## Description

**sawc2's member lookup ignores a bounded extension's bounds.** A member declared in `extension Cell<T: Equatable> { … }`, or in a bounded conformance `extension Cell<T: Equatable>: Equatable { … }`, resolves on an instantiation whose arguments don't meet the bound. The generic body is then instantiated at a type it was never checked for. Found reviewing SL-456.p2 (U5b2). It predates U5b2: sawc2 accepts these under both `sawc/std` and `std/`.

**Repro** (with `Token` a NoCopy struct, so not `Equatable`; probes in `.build/scratch/air-review/sl456p2/` on the Air):

```saw
struct Cell<T> { v: T }
extension Cell<T: Equatable> {
    func same(&self, other: &Cell<T>) -> Bool { self.v == other.v }
    static func twin(a: &Cell<T>, b: &Cell<T>) -> Bool { a.v == b.v }
}
extension Cell<T: Equatable>: Equatable {
    func equals(&self, other: &Cell<T>) -> Bool { self.v == other.v }
}
func generic_eq<E: Equatable>(a: &E, b: &E) -> Bool { a == b }
// with a = Cell(v: Token(id: 3)), b = Cell(v: Token(id: 4)):
```

| position | sawc2 | Stage 0 |
|---|---|---|
| `a.same(&b)` (bounded extension method) | **accepts** | refuses: "has no method `same`: requires `T: Equatable`" |
| `a.equals(&b)` (bounded conformance method) | **accepts** | refuses |
| `Vector<Token>.copy()` (std's bounded ExplicitCopy) | **accepts** | refuses: "requires `T: ExplicitCopy`" |
| `Cell<Token>.twin(&a, &b)` (bounded static) | **accepts** | accepts (a Stage 0 gap too) |
| `a == b` (operator through a bounded conformance) | **accepts** | accepts (a Stage 0 gap too) |
| `generic_eq(&a, &b)` (the conformance as a generic bound) | refuses, `type.bound` | — |

**Mechanism:** the conformance check honours the bounds (the last row), but member resolution doesn't. Lookup finds the member in the extension without checking the receiver's type arguments against that extension's bounds. That one lookup serves methods, statics, conformance requirements and the operators that resolve to them, so they all share the gap.

**Fix:** one funnel, the member lookup, that checks the declaring extension's bounds against the receiver's arguments and refuses with a message naming the bound (Stage 0's wording is a good model). Pin every row above. In a generic body, the bound must be proven from the body's own bounds, which is the same question `type.bound` already answers.

**Why it matters:** the generic body (`self.v == other.v`, `buf[i].copy()`) is instantiated at a type lacking the required conformance. Today that surfaces at best as a later failure in mono or codegen, and at worst as a call to a member that doesn't exist. Stage 0's gap on statics and operators belongs in SL:hazards as a "silent" entry.

## Items
1. **SL-463: member lookup ignores a bounded extension's bounds.**
   - **The fix:** one funnel, the member lookup. It checks the declaring extension's bounds against the receiver's type arguments, and refuses with a message naming the bound (Stage 0's "has no method `same`: requires `T: Equatable`" is the model). In a generic body, the bound is proven from the body's own bounds, the question `type.bound` already answers.
   - **Which lookups it covers:** methods, statics, conformance members, and the operators that resolve to them.
   - **Pins:** every row of the issue's table, including the two Stage 0 also misses (a bounded static, and `a == b` through a bounded conformance), plus V11, V22 and V43 remapped from typecheck-gap.
   - **Hazards:** Stage 0's gap on statics and operators becomes an SL:hazards "silent" entry. Sweep compiler/ and std/ for any site relying on it.
2. **SL-467: ten rows nothing refuses.** Name the mechanism for each group first, then sweep it for siblings:
   - **R29, the cast funnel:** `(&x) as Int`. The only crossing the spec allows is to a pointer.
   - **R43/R44, `capture.escaping-borrow`'s positions:** a borrow-capturing closure stored through a `&var` parameter, or into a local container. Fix the migrated fixtures' `result.discarded` artifact too.
   - **V24:** a manual `deinit()` call.
   - **V45/V46/P12, a generic body's inferred bounds against its declared bounds (design 219):** V45 is a public generic exceeding move-only without declaring its bound. V46 is a declared bound the body exceeds. P12 is a place read by value in a generic body without a `Copy` bound.
   - **V53/V58/V59, the NoMove tier the transfer funnel doesn't consult:** NoMove at a consuming receiver, a placement after a borrow, and a bound NoMove value moved into an argument.
   - Each row is remapped in CONFORMANCE.md from typecheck-gap to its rule id and fixture.
3. **SL-470: an exclusive-only borrows accessor isn't enforced at its use sites.**
   - **The fact:** an accessor whose body writes its receiver (SL-333 R4) must force every caller to borrow exclusively, so a read through it on a `let` root is refused.
   - **The work:** find where sawc2 records an accessor's exclusive-only-ness (or add it beside the accessor's mode). Make every window-opening use site consult it, through `place_verdict` as an exclusive entry: a subscript read, a get-shaped call, `borrow let`/`borrow var`, a `for` head, a forwarded `lend`, a nested window, and a method-call receiver.
   - **Pins:** the examples/errors rows of the exclusive-only family remapped (about 10), and the K123–K131 conformance rows.
   - **Agreement with borrowck:** U6d2's window charge (SL-460.p2, in review, not yet on main) already charges such a window exclusively when the accessor takes `&var self` or lends `&var` with no `@synthesize(shared)` twin. Read it in `/Users/shawn/Projects/sawlang/.claude/worktrees/agent-a8b332d8ac957cc88/compiler/borrowck/src/loans.saw`. Typecheck's exclusive-only fact must agree with it: derive it from the accessor's declaration the same way. Report the predicate so the lead can confirm the two match once both land.
4. **SL-474: a reference binding read into an aggregate builds a reference type.**
   - **The symptom:** `let t = (p, 1)` over `p: &Int` must be `(Int, Int)`, since reading a reference binding yields its value, as `let n = p` already does.
   - **Find where auto-deref-on-read is applied, and sweep every value-building position over a reference binding:**
     - a tuple element, an array or collection literal element;
     - a struct constructor argument, an enum payload, `Some(p)` and auto-wrap;
     - an interpolation segment, a format argument;
     - a `return`/tail of a non-reference result, a by-value call argument.
   - **Each reads the value,** with the copy tier's rules (a NoCopy referent refuses a by-value read, as today).
   - **Pins:** an accepted fixture per position. Reword the "stricter than Stage 0" reading in the typecheck README, and correct SL:hazards S24 if it mentions this.
