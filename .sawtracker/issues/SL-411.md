## Description

GRAMMAR.md does not say which name a parser reports when two §13 rules each refuse a different reading of the same text.

**Examples** (from SL-406.p4 and its review):
- head-restriction's own example, `if v.any { $0 } { }`: one reading is refused by `syntax.rule.trailing-closure` (at 2:21, the reading that got furthest), the other by `syntax.rule.head-restriction`;
- `while f { a } {`, `if let x = f { a } {`, and `if match m { case _ -> v }.any { $0 } {`.

**Consequences today:**
- None of these is recorded in the negative corpus.
- The N cells `trailing-call iter`, `trailing-call bhead` and `range-from bhead` are waived.
- No `if`, `else if`, `while`, `if let` or `for` head has a refusing head-restriction case at all. Only guard, scrutinee and arm-guard heads do.

**To decide:** a precedence among the rules, or the reading that gets furthest, or an expectation that accepts either name. The first two make the diagnostic id deterministic for the parser units. The third weakens the contract only for these texts. The decision then goes into GRAMMAR.md §13 and the corpus README's Refusals section, and the waived cases get recorded.


## Comments

User ruling (relayed by the lead, Sep 26): option (a). Where one reading of a text is refused by syntax.rule.head-restriction and another by a different rule (in practice syntax.rule.trailing-closure), the parser reports head-restriction. Its message names the fix (`if v.any({ $0 }) { }`), and GRAMMAR.md uses this exact text as the rule's example. The work: GRAMMAR.md §13 states the precedence. The corpus classifier applies it, so `if v.any { $0 } { }`, `while f { a } {`, `if let x = f { a } {` and the other head forms record head-restriction. The waived cells `trailing-call iter` and `trailing-call bhead` are recorded if this settles them. A two-rule conflict that does not involve head-restriction (check `range-from bhead`) is still undecided: report it, and do not choose.
