An interface parse for std and builtin modules: signatures parsed, bodies skipped (epic SL-398; the Air's option (e), chat m289).

**Why.** Resolve and typecheck read `sawc/std` modules as interfaces: declarations and signatures, never bodies. The parser still parses every body, so one refusal inside a body loses the whole module. `std/data.saw` is refused at 189:12 (`if #lend_var { … }` inside `Data.[]`, `syntax.expr.refused-lend-var`), and the parser gives no tree. The costs:
- U6b1's 29 std-cone gaps: every one is `data.saw`'s;
- U6b2's two `slice.not-yet` uses in `compiler/`: `File.read()` returns `Result<Data, IoError>`, in `driver/src/main.saw` and `resolve/src/loader.saw`, and they sit in the typecheck lane's allowlist.

SL:architecture §3.12's module interfaces want the same shape.

**The change:**
1. **The parser gains an interface mode.** It is an entry point beside `parse`, for example `parse_interface`, sharing the one parser.
   - In this mode, each function, method, `init`, accessor and closure-free body is skipped as a balanced `{ … }` token range from the lexer's tokens. The lexer already delimits strings and interpolations, so a brace inside a string can't unbalance it.
   - What gets skipped: bodies, static initializers, and parameter default expressions.
   - What is parsed exactly as the full parse would: every declaration head, signature, generic list, field, case, extension head, conformance and attribute.
   - A skipped body is a node of its own kind (`SkippedBody`, with its token range) where the body would stand. No later stage can mistake it for an empty body, and the verifier refuses a `SkippedBody` in any module that isn't an interface.
   - An unbalanced skip is a parse refusal like any other.
2. **Resolve's loader uses the interface mode for std and builtin modules only.** User modules parse fully. So `data.saw` loads, and `Data`, `File.read`'s signature and `to_string` resolve.

**Tests:**
- A unit program in `compiler/parse/tests/`: signatures that match the full parse's, for a file whose bodies are valid; a file with a refused body loading in interface mode; a brace inside a string or interpolation inside a skipped body; an unbalanced body refused; and the verifier's `SkippedBody` check.
- **Every `sawc/std` file,** parsed both ways where the full parse accepts it: identical declarations and signatures. The only difference allowed is `SkippedBody` in place of a body. This is the equivalence pin.
- `compiler/tests/typecheck/cone_coverage.py` reports the new coverage, 250 of 250 or a named remainder.
- **Merge order with SL-447.p2 (U6b2), whichever lands second:** if this lands first, U6b2 rebases and its two allowlist entries go stale and are removed. If U6b2 lands first, this unit removes them. The lane's stale-entry check says which.

**Where to work:** `compiler/parse/` (the parser and its unit programs), `compiler/resolve/src/loader.saw` and `compiler/tests/resolve/`. Don't touch `compiler/typecheck/`, `compiler/tests/typecheck/` (except `cone_coverage.py`'s expected count) or `compiler/driver/`: U6b2 works there at the same time. The parse lane, the depth funnel, the comma funnel and the grammar tables must stay green and unchanged. The interface mode is a skip over the same parser, not a second grammar.

**Gates:** `compiler/tests/run.py` per commit; before reporting, `battery.sh compiler citations grammarcorpus` under the suite lock; `git diff --check`.

Comments on the brief before the agent gets far. The balanced-brace skip is right for bodies. Two of the other skipped things need more than that, and one phrase is unclear.

1. **A skipped parameter default must leave a marker.** The very call this issue exists for depends on it: `File.read` is `read(&var self, size: Int = 0)`, and `compiler/` calls `file.read()` with no argument. Typecheck has to know `size` has a default, or the call is short an argument.
   - **Keep a `SkippedDefault`,** with its token range, where the default expression stood, just as `SkippedBody` stands for a body. Don't drop it.
   - **Also check whether any std signature depends on its default's type.** Design 108's default values drive inference, so a generic parameter could be inferred from a default. If one does, parse that default in full rather than skipping it.
2. **A static initializer isn't brace-delimited.**
   - **The skip needs its own rule:** the initializer ends where the statement ends, at bracket depth 0, not at a balanced `}`.
   - **It is safe only when the static's type is written.** If the grammar allows `static X = …` with no type, parse such an initializer in full, since its type comes from the expression.
3. **"closure-free body"** in item 1. I can't tell what it excludes. If it means every body, whatever closures it holds, since they sit inside its braces, say that.

Worth stating too: what an interface parse does with a refusal inside a signature. Today no std signature is refused, but if one is, the parser's lack of recovery would lose the whole module again. That is the failure this issue fixes, one level up. Recovering to the next declaration, with a note, matches SL-445 decision 2's "reports any declaration it can't take".

SL-448.p1 is up: the interface parse. 1 commit, 17 files, +1041/−53, on main afb18c7b.

**The mode.** `parse_interface` runs the same parser with an `interface` flag. There is no second grammar. Each rule below is a skip over tokens the lexer has already delimited, so a string, interpolations included, is one token and a brace inside it never counts.
- **Bodies** (function, method, `init`, accessor, a requirement's default) are skipped from `{` to its matching `}` with an opener stack. A mismatched closer is `syntax.lex.unclosed-bracket`.
- **Parameter defaults** end before the `,` or `)` at their own depth.
- **Static initializers,** whose type the grammar always writes, end at a depth-0 statement end. A line break counts only after a token that can end an operand, and not before `{`, `else` or `catch`.
- **Parsed in full instead of skipped:** an expression with a `<`/`>` at its depth (a generic list could hold commas); an initializer with control-flow words; a token that can't begin an expression (so the refusal is the same); and any default in a generic signature (design 108). No std default drives inference: all 14 are literals on non-generic `Int`/`Bool` parameters.

**The skipped nodes** are three new leaf shapes: `SkippedBody`, `SkippedDefault` (c2's refinement, so `file.read()` knows `size` has a default) and `SkippedInitializer`.
- `AstTree.interface` marks an interface's tree. The parser's `tree_problem` and resolve's `verify_unskipped` each refuse a skipped node anywhere else.
- **Body presence** goes through one helper, `is_body_node`, per the lead's (a) in chat m296–298. A Stmt_Block wrapper was rejected, because a stage could read it as an empty body.
- **The sweep:** typecheck's `build_function` (`TC_FLAG_DEFAULT_BODY`) was the only site that decided presence from `Stmt_Block`, and it now calls the helper. That is one line in `declarations.saw`, which SL-447.p2 (U6b2) also edits, and the lead merges it at integration.

**A refusal inside a signature** (c2 item 4) drops that declaration, or that member, and the parse continues.
- The loader keeps the module when every diagnostic belongs to a dropped declaration. It writes one `resolve.parse-refused` note per drop, naming the declaration (SL-445 decision 2's "reports any declaration it can't take").
- A whole-file diagnostic still makes the module unavailable.
- User modules parse fully.

**Pins:**
- The unit program `compiler/parse/tests/interface.saw` covers:
  - signatures equal to the full parse for every body kind, default and initializer, including the parse-in-full cases;
  - a body the full parse refuses, and a stray `///` in a body;
  - braces in strings and interpolations;
  - unclosed versus stray brackets;
  - dropped declarations and members;
  - a skipped node outside an interface.
- `compiler/tests/resolve/interface_pin.py` runs in every resolve-lane run:
  - **the equivalence pin:** all 33 files (`builtin.saw` plus 32 std files) are identical to the full parse apart from skipped nodes;
  - a bad signature in a copied std module gives its note, and its neighbours resolve;
  - a whole-file-refused std copy gives `import.unavailable`. The old tracked fixture moved here, because `data.saw` now loads;
  - a std default body completes a user conformance in `sawc2 typecheck`, and a requirement with no default gives `conformance.incomplete`.
