## Description

**An unsuffixed integer literal above `Int.max` with no expected type is accepted, and wraps silently** (SL:hazards S7; found by the SL-425 sweep, c7, on sawc2 at main and on the seed alike, at -O0 and -O2).

- `print(18446744073709551615)` prints `-1`.
- `let x = 9223372036854775808` binds `-9223372036854775808`.
- The same literal is refused at `let x: Int =` and beside an `Int` operand (`type.mismatch ... does not fit in Int`), and keeps its value at a `UInt64` slot.

"Never hide errors": a literal whose value its default type can't hold must be refused.

**Mechanism (UNVERIFIED, from the sweep):** the range check runs against an expected type, and the default-to-`Int` path skips it.

**Obligation 4:** every position where a literal takes its DEFAULT type rather than an expected one:
- `let` without an annotation;
- a generic argument inferred from the literal;
- an interpolation segment;
- a format argument;
- a `print` argument;
- a tuple element;
- a collection literal element with no annotation;
- an operand beside another default literal.

Pin each.

**Retires:** the subset checker's `int-literal-range` rule (it stays until this lands).

**Air: SL-822.p1 approved.** Reviewed r1 on origin/main cb8fcbad3. r2 is the server's rebase onto SL-810.p1, content-identical (diff of diffs empty), so this covers it.

**Legal boundaries keep their values** (`a1`, -O0 and -O2 identical):
- `UInt64` 2^64−1, written as a literal, as hex and with a `u64` suffix;
- `Int.min`, written as a literal and at `Int64`;
- `-128` and `-128_i8`, and a `static MIN8: Int8 = -128_i8`;
- `widest<UInt64>()`, `half<UInt64>()`, `below<Int64>()`, `sum<Int>()` = 18446744073709551615, 9223372036854775808, -1, 300;
- a `UInt64`-backed enum's `Top = 2^64−1` and `Hi = 1 << 63`;
- a value-`if` arm and a closure tail at `UInt64`.

`-(9223372036854775808)`, which the golden accepts, is exactly `Int.min` at both levels (`a2`), not a wrap or a negation panic.

**Faces the golden doesn't list** (`r1`, one diagnostic per marked line, under Stage 2):
- the signed suffix at a `static`, a return, an argument, an assignment, an array element, a binary operand and a pattern (`case 200_i8`), plus `-129_i8` and `-(129_i8)`;
- `-1` at `UInt64`;
- `0x100` at `UInt8`;
- `2_147_483_648` and `-2_147_483_649` at `Int32`;
- **`0xFFFF_FFFF_FFFF_FFFF` with no type**, which the pre-patch seed accepts silently. This patch adds that refusal.

Literals past `UInt64.max`, decimal and hex, and `256u8` are the lexer's (`syntax.lex.int-range`).

**Retiring `int-literal-range` is safe** even though the seed predates this check: a literal like `r1`'s line 22 in compiler source would pass the seed, but Stage 1 is built from the patched source and refuses it while building Stage 2. So the failure is a loud build failure, never a silent wrap.

**Out of scope, loud, no change:** a constant EXPRESSION past `Int.max` with no type (`let q = 9_223_372_036_854_775_807 + 1`) isn't folded. It panics `integer overflow` at run time under both compilers, while a typed slot or a `static` refuses it at compile time (`constant.overflow`). Not a wrap, so not S7. Noting it only in case the asymmetry is unintended.

**The run probe** `literal_default_range_accepted` matches its 23 `prints` at -O0 and -O2.
