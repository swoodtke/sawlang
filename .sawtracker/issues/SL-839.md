## Description

**Lift the intersection rule: the compiler's source no longer has to be Stage-0-compilable** (user ruling, Oct 23). SL:architecture §4 "Stage 0 moves after self-hosting" (Ruled) says that once the new compiler builds itself, a pinned release of it replaces Stage 0, "the compiler and its std may use the full new language, and the intersection rule lifts". The bootstrap is now seed → Stage 1 → Stage 2, with no `sawc/` involved, so the condition is met.

**What changes:**
- **The subset checker's compiler profile.** The rules that exist only to keep the source Stage-0-acceptable retire: `lex`, `parse` and `compile` (Stage 0's own lexer, parser and code generator run over `compiler/`), plus every remaining rule whose reason is a Stage 0 hazard or a §4 intersection exclusion. The constraint becomes "what the pinned seed compiles", which the bootstrap build already enforces.
  - The step-1 census: list every rule with its reason, classified as Stage-0-only (retire), a §4 language choice still wanted (keep; for example a lint the project wants regardless), or a hygiene rule (`workaround-marker`, `std-api`, `redundant-visibility`; keep, or say why not).
- **The std profile.** §4 also lifts it ("the compiler and its std may use the full new language"); its named-feature list becomes unnecessary. Same census.
- **Workaround markers:** those whose hazard sawc2 and the seed handle can be re-canonicalized. Not S23's (SL-825, a sawc2 leak) or S28's (needs std design). S4's are in SL-839.
- **Docs:** SL:architecture §4 records that the lift happened (Oct 23), and CLAUDE.md and `compiler/README.md` "The subset" are updated.
- **Gates:** `run.py`'s `subset` step, and the server's gate (it must not run Stage 0 over `compiler/` any more).

**Scheduled:** before SL-839 (S4's markers), which builds on it.
