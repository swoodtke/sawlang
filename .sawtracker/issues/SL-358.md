## Description

FOUND by an SL-357 wave-2 agent on Sep 23, while it was compile-checking the std doc examples. Reproduced on main fd2520e9.

## Repro
Program (`.build/scratch/fixedbuf_qual.saw`):
```saw
import std.fixedbuf
func main() {
    var fb = fixedbuf.FixedStringBuilder<32>()
    fb.append("hi")
    print(fb.as_string())
}
```
Output: `internal compiler error at 4:22 (MethodCall): Undefined struct: FixedStringBuilder`.

## Probed positions
| Position | Result |
|---|---|
| `var x = mod.T<N>()`, no annotation | ICE |
| `mod.T<N>().method()`, as a receiver | ICE (q6) |
| `var x: mod.T<N> = mod.T<N>()`, annotated | compiles |
| `return mod.T<N>()` in `-> mod.T<N>` | compiles (q2) |
| `import std.fixedbuf.{FixedStringBuilder}` + bare `FixedStringBuilder<64>()` | compiles and runs |
| non-const generic `once.Once<Int>()`, qualified | clean diagnostic, no ICE (q5) |

## Mechanism (not yet named precisely)
- The qualified `mod.T<const N>()` construction is parsed as a MethodCall on the module qualifier.
- With no expected type to steer it, the typechecker accepts the call. It never records or monomorphizes the const-generic instantiation under a name codegen can find, so codegen's struct lookup misses.
- An expected type supplies the instantiation, which is why the annotated and return positions work.

## Sweep owed before the fix (obligation 4)
- The other qualified-construction positions: argument, field initializer, collection element, interpolation.
- A user-module const-generic struct via `--module-path`.
- A qualified type with both const and type parameters.
