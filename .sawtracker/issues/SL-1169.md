## Description

**`@align` on a coroutine-frame-resident local is refused for a reason that SL-1167 removes.** `tests/corpus/conformance/N11_align_refuses_frame_resident_local.saw` (rule `coro.align-frame-resident`) refuses `@align(N)` on a local that lives in a suspending function's frame. Its stated reason is that the frame is allocated through a seam "whose `align` argument is documented as ignored", so honouring the request was "a later design". Since SL-1167, `__saw_rt_alloc` MUST honour `align`, and the hosted default does.

**To decide:**
- whether the frame now honours a field's `@align` (the frame's alignment becomes the largest it holds; `coro_lay_out_frame` places the field at that alignment; the task box allocates at the frame's alignment), or whether the refusal stays for another reason;
- in either case, N11's comment is rewritten. Rewording it detaches its corpusdiff row, so the baseline is recorded in the same patch.

Related: SL-1167, DF-300b, DF-306a, `N08_align_local_is_honored.saw`.
