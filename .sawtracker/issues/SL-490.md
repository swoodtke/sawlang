**Found by:** batch B2 (tcb2), confirmed by the lead on main 591942d1 and on B2's tip. **Area:** typecheck `settle_places`, the root charge it gives a nested accessor chain, and borrowck's `loan.window-root`.

**The defect:** an exclusive window opened through two accessor hops, `borrow var c = g[0][0] { … }`, charges the root `g` shared, not exclusive. So the body can read `g` while a `&var` into `g`'s storage is live. One hop is refused correctly.

```saw
struct P { n: Int }

func nested() {
    var g = Vector<Vector<P>>()
    var row = Vector<P>()
    try! row.push(P(n: 1))
    try! g.push(move row)
    borrow var c = g[0][0] {
        c.n = g.len()                 // accepted: should be loan.window-root
    }
    borrow var g[0][0].n += g.len()   // accepted: should be refused (an RHS overlap with the open window)
}

func single() {
    var v = Vector<P>()
    try! v.push(P(n: 1))
    borrow var c = v[0] {
        c.n = v.len()                 // refused: loan.window-root, correct
    }
}
```

`borrow var r = g[0] { try! r.push(P(n: g.len())) }` is also refused correctly. Only the two-hop chain under-charges.

**The rule:** SL:borrowing §3 says "A root is held EXCLUSIVELY for the whole borrow if the accessor takes `&var self` or lends `&var T`", and under an exclusive root "the body cannot touch the root at all". Every hop of `g[0][0]` under `borrow var` picks the exclusive `[]`, so the root's charge must be exclusive.

**Mutability is right:** the writability walk reaches the root, so a `let g` is refused. Only the loan side's charge is too weak.

**Sweep (obligation 4):**
- the other chain shapes: field hop then subscript (`s.rows[0].n`), subscript then field then subscript, and a method accessor in the middle (`g.at(0)[0]`);
- the statement form, the block form, the `for` head and `lend` forwarding;
- the `&self` cell-carrying middle hop, which per §3 also charges exclusive.

Repro: `.build/scratch/probe_nested_root_charge.saw` (lead's machine).
