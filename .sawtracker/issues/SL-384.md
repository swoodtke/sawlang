## Description

Found by the SL-340 implementer (Sep 24), while building K175. Reproduces on main.

Reading a field of an ALIAS-typed local that is held across a suspension fails to compile in the driven lowering. The borrow window the coroutine transform builds for the read is typed `(&Tag) -> Void`, and the print then reports "`Tag` is not Printable". The sync twin reads the field fine.

Shape (the implementer's cell; a minimal version):

```saw
import std.task.{yield_now}
struct Noisy { name: String }
extension Noisy: NoCopy {}
type Tag = Noisy

func work() -> Int {
    let t = Tag(Noisy(name: "four"))
    yield_now()
    print("{}", t.name)
    t.name.len()
}

func main() { print("{}", __saw_drive(work())) }
```

Expected output: `four`, then `4`. SL-340's K175 only counts drops for its alias cells because of this.

Probably the same mechanism as the alias-payload `match` finding filed beside it: a position that resolves the alias's underlying struct for member access, reached through the transform's synthesized window. Confirm, and sweep the positions the transform synthesizes (member reads, method calls, and borrow windows over alias-typed frame fields).
