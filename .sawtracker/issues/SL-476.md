## Description

**sawc2 types a closure with no expected type whose every path `return`s as `() -> Void`.** For example, `let f = { return 5 }; f()` fails with `type.mismatch`. The spec says a closure's result is what it returns, and Stage 0 accepts it. Found by typecheck batch A (SL-472/SL-469); its probe is `.build/scratch/pret.saw` in that worktree.

**Mechanism to name first (obligation 4):** closure result inference seems to read only the tail expression, so an explicit `return` doesn't contribute. Sweep:
- all-`return` bodies;
- a mix of `return` and a tail;
- a `return` inside `if`/`match`/loop arms;
- `return` in a closure passed to a generic parameter (does inference see it?);
- `return` with no value;
- a nested closure's `return` (it must not leak to the outer).

**Pins:** an accepted fixture per row, plus the batch A fixture `capture.escaping-consume.bound-return`, whose `let` annotation works around this and should be removed in the same landing.

Typecheck; it goes with batch B.
