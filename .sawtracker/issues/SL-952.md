**Two freestanding objects built by sawc can't be linked together: each defines a strong `__saw_bt_table`.** Found by SL-948's survey (`.build/scratch/p948/q2_two_plain_objects.txt`): two plain `sawc build --freestanding -c` objects, no builtins involved, fail with ld.lld's duplicate-symbol error on `__saw_bt_table`.

**Why it matters:** a kernel or firmware image built from more than one sawc compile (separately compiled components, a Saw object beside a library object) can't link. sawos builds through Blade, so check whether any sawos image links two sawc objects today.

**What a fix owes:** what `__saw_bt_table` is per object (design 113's backtrace table, SL-803's exec descriptor), whether one image needs one table or one per object, and the linkage that follows (per-object symbol names, `linkonce`/COMDAT, or a section the linker concatenates), with a two-object link case in the freestanding suite on both arches.

Requested changes on patch SL-952.p1 (revision 1) (its test run was cancelled)

**Air: SL-952.p1, changes requested.** Wording only. The pin works, but both doc sentences overclaim, and documenting the limit is what this patch is for. Reviewed r1 on 93ca383ab.

**What overclaims:**
- **The spec,** Profiles: "An image, hosted or freestanding, holds at most one object built by `sawc`." Every hosted image holds **16** objects that sawc builds: the runtime's, which `sawc runtime` compiles from `runtime/*.saw` and `build.py` lists in `.build/sawc-runtime.txt`. They sit beside the one program object.
- **runtime/ABI.md:** "Every object `sawc` builds defines `__saw_bt_table` as an external symbol". `llvm-nm` over those runtime objects finds **no** `__saw_bt_table` in any of them (`.build/rt2/*/{mem,offload,reactor,shim,…}.o`).

What's true, and what I measured, is one object from `sawc build` (the program) per image, plus whatever runtime objects come with it:
- **Hosted:** two `sawc build -c` objects (`sl952p/h_a.saw` with `main`, `h_b.saw` with one export), linked by clang with the manifest's 16 runtime objects, fail with exactly one duplicate: `duplicate symbol '___saw_bt_table' in: h_b.o h_a.o … ld: 1 duplicate symbols`. `h_a.o` alone with the same 16 links and runs (`a`).
- **Freestanding:** your `link_two_objects` case does the same under ld.lld.

So the spec's "fails with a duplicate-symbol error naming `__saw_bt_table`" holds on both. Only the count and "every object" are wrong.

**Suggested wording:**
- **Spec:** "An image, hosted or freestanding, holds at most one *program* object, the one `sawc build` writes; the runtime objects `sawc runtime` builds beside it are not program objects and carry no std of their own."
- **ABI.md:** "Every program object `sawc build` writes defines `__saw_bt_table`…"

**The pin:**
- The runner's LINK-REFUSAL kind compiles the second object with no runtime and no suite module, and matches ld.lld's error lines in order.
- `freestanding_runner.py link_two_objects` passes on both arches.
- `battery.sh freestanding patchgate docverify citations`: `exit=0` (freestanding 62/0/0).
