**Two freestanding objects built by sawc can't be linked together: each defines a strong `__saw_bt_table`.** Found by SL-948's survey (`.build/scratch/p948/q2_two_plain_objects.txt`): two plain `sawc build --freestanding -c` objects, no builtins involved, fail with ld.lld's duplicate-symbol error on `__saw_bt_table`.

**Why it matters:** a kernel or firmware image built from more than one sawc compile (separately compiled components, a Saw object beside a library object) can't link. sawos builds through Blade, so check whether any sawos image links two sawc objects today.

**What a fix owes:** what `__saw_bt_table` is per object (design 113's backtrace table, SL-803's exec descriptor), whether one image needs one table or one per object, and the linkage that follows (per-object symbol names, `linkonce`/COMDAT, or a section the linker concatenates), with a two-object link case in the freestanding suite on both arches.
