**A wholly constant sub-expression that faults, inside a run-time expression, is accepted and panics at run time** (`x + (Int.max + 1)`). Found by sl543 (SL-543), outside its scope.

**Probe** (`.build/scratch/probe_overflow_fold.saw`): `let y = id(1) + (Int.max + 1)`. Both Stage 0 and sawc2 Stage 2 accept it, and both panic at run time with `panic at probe_overflow_fold.saw:7: integer overflow` (rc 134). It is not silently wrong: the overflow check fires. But the fault is certain, and the spec's rule, "the faults a run-time operation would panic with are compile errors in a constant", with SL-543's extension, implies the sub-expression should be refused at compile time.

**Mechanism.** sawc2 folds a constant chain at an integer slot, and with SL-543 also a shift count or divisor, along with any wholly constant chain that has no integer slot (`let w = 1 << 64`). It does not fold a constant SUB-expression that is an operand of a run-time operation. So `Int.max + 1`'s overflow, `Int.min / -1`, a negation of `Int.min`, and a constant narrowing that faults all survive to run time when they sit beside a run-time operand.

**Fix.** Route every maximal constant sub-expression, in any operand position, through the fold that `check_certain_fault` and the constant positions already use. A fault there is the existing constant-position error. Pins: overflow `+`, `-`, `*`, negation, `Int.min / -1`, and a faulting conversion, each as an operand beside a run-time value, plus controls whose constant sub-expressions don't fault. Run the corpus recount under both std roots.

**Spec:** check whether the paragraph SL-543 extends already covers it ("an operation whose operands are constant before instantiation"). If not, extend it in the same sentence.
