**B3. The verifier's no-intersecting-lifetimes check.**
- **Scope:**
  - **The static check:** recompute storage lifetimes *from the lowered MIR's frame-slot accesses*, not from B1's sets, over parked states and the resume transitions. Then check that no two values sharing bytes intersect.
  - **Its dynamic twin** (t10, risk R2): a sawc2 sanitize flag that stamps `sanitize_address` on every function, plus, under it, `__asan_unpoison_memory_region` / `__asan_poison_memory_region` on each frame value's slot where its storage lifetime starts and ends. The run lane builds the coroutine programs once with it.
- **Depends on:** B2.
- **Files:** `compiler/coro/src/{verify,lower}.saw`, `compiler/llvm/src/module.saw` and `compiler/driver/src/main.saw` (the flag), `compiler/tests/coro/inject/`, `compiler/tests/run/`.
- **Pins:**
  - an injection that forces two interfering values onto one offset fails, naming both, the point and the state;
  - another that moves a drop past the end of its lifetime fails;
  - the same overlap injected at run time is reported by ASan at the access, and the clean corpus reports nothing.
- **Done when:** all three fail as described, and the corpus is clean both ways.
- **Estimate:** 1.5.

**Plan:** SL:coroutines §4, unit B3 (approved by the user, Oct 12). The plan text is authoritative; this issue is its tracker entry. Dependencies are named by unit id; see the epic's child list for their issues.

**Rule 5, "lifetimes disjoint"** (`coro_verify_lifetimes`, `compiler/coro/src/verify.saw`, run by `coro_verify_body` on every lowered frame). It recomputes every frame value's lifetime from the LOWERED body, independently of `lifetimes.saw` but under its definition:
- **Locals:** maybe-initialised, plus each assignment into them not through a dereference (a destination is live at its defining statement, and a scope-end drop reads the value).
- **Window records:** while their window may be open (rule 3's dataflow, factored out and shared).
- **Child slots:** from the first parameter write through the drive, its state, and the resume and move-out.
- **Offload storage:** start through take.
- **State word and budget:** everywhere.

Any two values with overlapping bytes and a common live point are reported, naming both, the shared bytes, the point and the state.

**Pins** (`compiler/coro/tests/verify_lifetimes.saw` over `inject/lifetimes.saw`):
- **an injected overlap:** "verify rule 5 (lifetimes disjoint): … _2 `both` … and _3 `extra` … share bytes [80, 88) …, and both are live at bb0.1, in state 0";

**B3b stopped at step 4, and the dynamic twin found a gap (agent p583asan; lead call, reversible).** The sanitized run lane gives 8 of 37 programs an ASan `use-after-poison`, every report a WRITE. Each failing program has a call or `window_open` terminator whose destination is a frame slot. **The mechanism (UNVERIFIED until the agent's step A):** a terminator writes its destination during the terminator. But B1's `lifetimes.saw` and rule 5 both start that destination's lifetime at the return block's first point. This is the class of B2's amendment (a destination is live at its defining statement), which covered assignment statements only.

**The amendment, pending its evidence: a terminator's destination is live AT its terminator.** It goes in both independent computations, the packer's `lifetimes.saw` and rule 5. <!-- sawtracker:comment {"author":"agent:claude-air-reviewer","body_bytes":2223,"created":"1792243418","id":"c9"} -->
**Air: evidence for step A (main with B2 and T3b). The 8 ASan hits are benign by construction, and the dangerous case is invisible to the poison twin.**

**Why ASan can't see it:** a use-after-poison WRITE means NO live value held the destination's bytes at the terminator, or rule 5's live set would have unpoisoned them. So every hit is a write into bytes nobody owns at that point. That's a mismatch with the definition, not a clobber. The real miscompile is a destination that shares bytes with a value LIVE at its terminator. Those bytes are unpoisoned (that value is live), so the dynamic twin is silent there by design. Only rule 5 with the amendment finds it, which makes step A the right instrument and a necessary one.

**Shapes I tried (`air-review/sl583p/` on the Air). Both share bytes on main, both run correctly, and the lowering is why:**
- `term_dest.saw`, a large operand moved into a plain call: `--layouts` puts `x` (the moved operand) and `y` (the destination) both at `[8: Big]`, 48 bytes. But the call's destination is a stack temp (`_4 = call reversed(move (*_15).[8: Big])`, then the statement `(*_15).[8: Big] = move _4`). Output is 654321 at -O0 and -O2.
- `child_dest.saw`, a suspending call returning a large value: `y` at [8, 56) overlaps its own child `make` frame at [8, 120), whose result sits at [16, 64). The move-out goes through a temp (`_2 = move (*_13).[16: Big]`, then `(*_13).[8: Big] = move _2` as a statement), so it never copies between overlapping ranges. `outer` prints 654321 and `two` 15005, at both levels.
- A scalar destination written straight into the frame (the stop report's `fetch_add`) is stored after the call returns, when no operand is read any more.

So the clobber needs a terminator that writes a frame place DURING its own execution while reading a co-located operand, for example an sret pointer into the frame, or a window record written while the accessor still reads its operands. I found no such shape, but that's a search, not a proof. The amendment is right regardless, since the definition must cover the terminator's write. Step A's refusals answer the question: an operand of the same terminator sharing the destination's bytes is the decisive case.

**SL-583.p2 submitted: B3b, the ASan twin, plus the plan amendment (one commit 169dcec03; agent p583asan).**

**The amendment: a terminator's destination is live AT its terminator.** A non-suspending call (sret return slot, `window_open`, a result) writes its destination before control leaves the terminator; a suspending call writes it at its return edge. The definition is fixed in both independent computations: `coro_mark_written` in `lifetimes.saw` (the packer) and rule 5's `coro_verify_local_lifetimes`. It is stated once at each site.
- **Hazard measured first (rule 5 alone amended, over today's packing):** `run.py --only coro,programs` ok, and `corpusdiff.py run` reports "No program moved". So no layout B2 packs today puts a destination on bytes a live value holds at its terminator, and there is no same-call operand case: **no live miscompile**. The 8 ASan hits were all benign (no live value held the bytes), as the Air's c9 said.
- **Goldens:** exactly four `.coro` lines, each a destination gaining its writing terminator's point (`windows.coro` ×2, `lifetimes.coro`, `chains.coro`). No `.layouts` or `.lowered` file moved.

**The twin:**
- `sawc2 build --sanitize address` (any other value exits 2). Flag-off IR is byte-identical to the base.
- `sanitize_address` through `ll_function_attribute_group` (entry point `llvm_emit_program`).
- **The lowered-lifetime funnel** `coro_lowered_lifetimes` (entry point `coro_verify_body`) has two consumers, rule 5 and `coro_poison_lists`. So the run-time check cross-checks the packer (the Air's c5).
- The frame is poisoned at creation, then each live value unpoisoned. The state word, the budget and offload storage are never poisoned while in use, and the whole frame is unpoisoned before `Ready`.
- **The `sanitize` step in `run.py`:** 37 programs (22 `coro_*`, 3 offload pins, 12 thread probes) built plain and sanitized must agree, with no ASan report (18 s in the gate). Darwin only for now; the aarch64 VM's clang-19 links ASan, but the lane hasn't run there.
