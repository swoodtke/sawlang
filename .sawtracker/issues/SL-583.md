**B3. The verifier's no-intersecting-lifetimes check.**
- **Scope:**
  - **The static check:** recompute storage lifetimes *from the lowered MIR's frame-slot accesses*, not from B1's sets, over parked states and the resume transitions. Then check that no two values sharing bytes intersect.
  - **Its dynamic twin** (t10, risk R2): a sawc2 sanitize flag that stamps `sanitize_address` on every function, plus, under it, `__asan_unpoison_memory_region` / `__asan_poison_memory_region` on each frame value's slot where its storage lifetime starts and ends. The run lane builds the coroutine programs once with it.
- **Depends on:** B2.
- **Files:** `compiler/coro/src/{verify,lower}.saw`, `compiler/llvm/src/module.saw` and `compiler/driver/src/main.saw` (the flag), `compiler/tests/coro/inject/`, `compiler/tests/run/`.
- **Pins:**
  - an injection that forces two interfering values onto one offset fails, naming both, the point and the state;
  - another that moves a drop past the end of its lifetime fails;
  - the same overlap injected at run time is reported by ASan at the access, and the clean corpus reports nothing.
- **Done when:** all three fail as described, and the corpus is clean both ways.
- **Estimate:** 1.5.

**Plan:** SL:coroutines §4, unit B3 (approved by the user, Oct 12). The plan text is authoritative; this issue is its tracker entry. Dependencies are named by unit id; see the epic's child list for their issues.

**SL-583.p1 submitted: B3's STATIC half (one commit; agent p583).** The ASan twin is B3b, a second patch on this issue after SL-765 T3b merges; its design notes are below. This restores the verifier's policing of B2's packing (the Air, on B2's merge).

**Rule 5, "lifetimes disjoint"** (`coro_verify_lifetimes`, `compiler/coro/src/verify.saw`, run by `coro_verify_body` on every lowered frame). It recomputes every frame value's lifetime from the LOWERED body, independently of `lifetimes.saw` but under its definition:
- **Locals:** maybe-initialised, plus each assignment into them not through a dereference (a destination is live at its defining statement, and a scope-end drop reads the value).
- **Window records:** while their window may be open (rule 3's dataflow, factored out and shared).
- **Child slots:** from the first parameter write through the drive, its state, and the resume and move-out.
- **Offload storage:** start through take.
- **State word and budget:** everywhere.

Any two values with overlapping bytes and a common live point are reported, naming both, the shared bytes, the point and the state.

**Pins** (`compiler/coro/tests/verify_lifetimes.saw` over `inject/lifetimes.saw`):
- **an injected overlap:** "verify rule 5 (lifetimes disjoint): … _2 `both` … and _3 `extra` … share bytes [80, 88) …, and both are live at bb0.1, in state 0";
- **a drop moved past a lifetime's end:** caught where rule 2 can't see it.

**On real code rule 5 fires nowhere:** 267 run programs match Stage 0, 38 unit programs pass, 2661 corpus programs hold. So no B2 bug.

**Gate (agent):**
- `run.py --only subset,coro,programs,units,std,std_cone`: green.
- `corpusdiff.py gate`: green.
- `battery.sh citations gmgate`: green.
- After the rebase, `run.py --only coro,units`: green.

**B3b, for its brief (from the agent):**
- **The flag:** `sawc2 build --sanitize address`, a valued flag. The driver adds `-fsanitize=address` at the link; the pinned clang's ASan runtime is untested.
- **The llvm files:** `llvm/src/{api,program,attributes}.saw` stamp `sanitize_address` through `#0`. `bodies.saw` (or `calls.saw`) emits `__asan_poison`/`unpoison_memory_region` from per-point lists that coro's lowering computes and `ll_lowering` carries.
- **The run lane:** one sanitized build of the coroutine programs, expected clean.
- **The pins:** an injected overlap is reported by ASan at the access.
- **To settle:** whether the dynamic poison lists come from rule 5's recomputation or from `lifetimes.saw` (which one the dynamic check cross-checks).
