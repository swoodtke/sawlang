Found by U6e (SL-468.p1's findings). Conformance row V49 (an escaping closure consuming its move capture frees it once) fails in sawc2's MIR: the closure body does `move (*_1).0` through its shared &-environment, and the environment's own drop later frees the same capture again, which is a double free. Drop elaboration can't fix it, because the move goes through a reference, so no initialisation state on the environment records it. This is DF-255a's shape in Stage 0. Per obligation 4, name the mechanism first: a closure body's access to a by-move capture lowers as a place through the environment REFERENCE, so a consuming use becomes a move out of a borrowed place. Sweep the siblings: every closure kind (escaping, non-escaping, let-bound), every consuming use (a move argument, return, a consuming method call, a destructure), and FnOnce-like single-call versus repeat-callable closures. The fix decides what the spec gives: either a closure that consumes a capture is called at most once and takes its environment by value (moved out at the call, so the environment drop is elided after it), or the consuming use is refused. Check LANGUAGE_SPEC's closure section and Stage 0's verdict. Pins: V49 remapped here, a MIR golden, and the drops verifier clean (one free).

Context for the fix: this is an open language question as well as a lowering bug, so it likely wants a ruling before code.

- **Stage 0 has the same open finding:** `examples/conformance/INDEX.md` row V49 is "DF-255a — OPEN, XFAIL": "an escaping env OWNS its captures and its destructor releases them, and nothing records that the body already moved one out … V48's answer does not port". So no reference behaviour exists to match.
- **The spec's model sets the constraint.** An escaping closure "is a `Copy` value": the env is "immutable and shared", copies are refcount bumps, and "at body entry every plain / `move` / `copy` capture is loaded out of it into a per-call local". A body that *consumes* an owned capture is therefore taking something from storage that other copies, and later calls, still see. That's why the per-call load turns `move o` into a double free.
- **The non-escaping rule is defined:** "the body takes the value as it starts … Running one such body twice panics rather than taking a value that has already left".

Two answers fit that model; the user's choice:
1. **Take with a runtime once-flag, mirroring the non-escaping rule.**
   - The env holds each consumable `move` capture with a taken flag. A call that consumes it takes it with an atomic swap, since the env can cross threads via `spawn`; a second consuming call panics; and the env's destructor releases only a capture not taken.
   - This keeps the spec's `run_owned({ [move o] in move o })` compiling for escaping closures too, at the cost of a flag word, an atomic op per consuming call, and a runtime panic as the failure.
2. **Refuse it at compile time:** a consuming use of a `move` capture in an *escaping* body is an error, with a hint to the spellings that work:
   - `[move o]` of an `Optional` and `o.take()`, which is the same flag made explicit;
   - pass the value as a parameter;
   - use a non-escaping closure.

   It's simpler and has no runtime cost, but it removes a case the spec's prose currently allows, if `run_owned`'s parameter is escaping.

Either way, the sweep the issue asks for is the test matrix: every closure kind × every consuming use. And V49 flips from XFAIL in the same landing, because Stage 0's pin and sawc2's row should not disagree.

The user's ruling (Oct 9, answering the lead's question in the session; quoted, since agents can't post kind=ruling): 'Compile error'. A consuming use of a move capture inside an ESCAPING closure body is refused at compile time. The hint names the spellings that work: capture an Optional and take() it, pass the value as a parameter, or use a non-escaping closure. Non-escaping closures keep the existing take-once rule. No runtime once-flag. The scope that follows: (1) a typecheck rule (an id beside capture.*) with the sweep matrix, every escaping closure kind (returned, stored, let-bound, passed to an escaping parameter) x every consuming use (a move argument, return/tail, a consuming method call, a destructure, a move into a field); (2) LANGUAGE_SPEC's closure section states the rule, and run_owned's example names its non-escaping parameter; (3) V49 flips in the same landing: Stage 0's XFAIL pin becomes a refusal row (the expected diagnostic), and sawc2's CONFORMANCE row maps to the new rule; (4) MIR keeps no consuming path through the env reference, and an invariant marks the now-unreachable lowering.
