## Description

Found by SL-260's same-source differential at base 6f307c11, independently reproduced at 6a6d57bd. Python sawc produces an internal compiler error when a String? argument reaches a String?? parameter.

Minimal repro:

```saw
func echo(value: String??) {}
func main() {
    let inner: String? = None
    echo(inner)
}
```

Actual: compiler exit 1, `internal compiler error ... (FunctionCall): Type of #1 arg mismatch: {i1, {i1, i8*}} != {i1, i8*}`. Existing full fixture: prototypes/minivm/examples/optionals/review_nested_context.saw:15.

Expected: a clean type diagnostic under LANGUAGE_SPEC.md's Call-site optional auto-wrap rule: an already-optional argument is passed through, never rewrapped. This report does not ask Python to imitate the prototype's broader recursive Optional wrapping (M10 deliberately permits that); the compiler must not pass incompatible layouts to codegen.

Mechanism: expressions.py::_arg_type_ok deliberately takes the ordinary compatibility path without setting an optional-wrap annotation when the argument is already Optional. types.py::_types_compatible recursively compares Optional inner types and permits an implicit String-to-String? match one level down. It therefore reports the outer String?/String?? pair compatible although the argument has no matching representation conversion. The call reaches LLVM with different aggregate layouts.

Sweep the shared compatibility/argument funnel across free/method/constructor/default/collection positions and Optional nesting depths. An independently observed annotated local `let outer: String?? = inner` also reaches an internal error (`Can't index at [0] in i8*`), so inspect storage positions too rather than patching the one call emitter. Preserve exact-depth Optional calls and the specified bare-value one-level wrap. SL-264 concerns outer-None value-branch semantics and is adjacent but distinct.
