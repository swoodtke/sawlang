## Description

**`sawc` can't build a freestanding object yet: sawos's command line (`-c --freestanding --no-hidden-alloc --target … --target-features …`) is Stage-0-only** (the Air, SL-667 c12, Oct 23).

sawos's `tools/sos_runner.py` compiles the kernel with Stage 0's flags: `--freestanding --no-hidden-alloc --target <triple> --module-path kcore=… hal=…` to an object (`-c`). The self-hosted `sawc build` has no `-c`, no `--no-hidden-alloc` and no `--target-features`, and `sawc build --freestanding` checks the profile but doesn't build. So the self-hosted compiler can't build the kernel, whatever the resolver does. "Kernels and embedded are first-class targets" (design doctrine), and sawos resumes only once `sawc` is ready (the user, Oct 9).

The corpus records the same gap: `refused driver.usage: sawc build takes no --no-hidden-alloc` (the fixedbuf rows and others).

**Scope** (an epic-sized ask; step 1 is a plan):
- object output (`-c`);
- `--freestanding` building, not just checking (the runtime-provider path, no hosted runtime linked);
- `--no-hidden-alloc` (design 135's three refusals);
- `--target` with `--target-features`;
- the `--runtime-build` and `--runtime-provider` modes Stage 0 has;
- port the freestanding suite (`tests/freestanding/`, frozen by SL-667) onto `sawc` as its gate.

Until this lands, sawos builds through a pin at or before v0.18.0 (SL-667's landing note says so).

**`-c`** (`u1_prog.saw`: recursion, a Vector, a Map, formatting):
- `sawc build -c -O2 … -o u1.o` writes a Mach-O arm64 object.
- Per Q1 it keeps the executable's linkage: `T _main`, `T ___saw_rt_get_argc`/`_argv` with their `b ___saw_argc`/`_argv`, and `S ___saw_bt_table`. The seams it reaches are left undefined: `___saw_rt_alloc`, `_dealloc`, `_panic`, `_last_raw_code`.
- Linked by hand with `/usr/bin/clang u1.o <the objects sawc-runtime.txt names>`, it runs: `fib 6765 a 3 b 2 c 1`, exit 0.

**The size levels, on the same program:**

| level | attributes in the IR | `__text` | output |
|---|---|---|---|
| -O2 | none | 27,684 | `fib 6765 a 3 b 2 c 1` |
| -Os | `optsize` | 26,276 | same |
| -Oz | `optsize` + `minsize` | 25,124 | same |

**`--target-features`:**
- `+crc,+lse` reaches every function as `"target-features"="+crc,+lse"`;
- an empty value is a usage error.

**The follow-up: an unknown feature is ignored, not refused.** `--target-features +nonsense` prints LLVM's "'+nonsense' is not a recognized feature for this target (ignoring feature)" twice and exits **0**, with an object built without it. For sawos a feature is a correctness input (`+strict-align`, or `-fp-armv8` in a kernel that must not touch FP registers), so a misspelling becomes silently wrong code. That conflicts with "never hide errors". It isn't a U1 regression, since Stage 0 hands features to LLVM the same way. I'd file it to be refused with the target's valid set named, e.g. by checking each `±feature` against the target's list before compiling, or by failing on clang's "not a recognized feature". It's worth landing before U2's per-target record, since U2 is where kernels start passing features.
