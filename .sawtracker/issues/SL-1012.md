Found by the SL-1011 spec review (F10 and F11).

LANGUAGE_SPEC "Type Definitions" makes `type UserId = Int` a DISTINCT type:
- `let order: OrderId = user` is an error;
- `42 as UserId` is an error;
- a sibling-alias cast is rejected;
- `let m: Byte = 45` is not legal;
- an annotated `let` takes an underlying-typed initializer only for the four primitive kinds.

It also refuses an alias whose underlying type is an enum, whether written directly, through an alias chain, raw-backed or module-qualified. That includes `type Outcome = Result<Int, ParseErr>`.

sawc accepts all of these. `/Users/shawn/Projects/sawlang/.build/scratch/p1000e/F29_alias_distinct.saw` builds and runs. `/Users/shawn/Projects/sawlang/.build/scratch/p1000e/F28_alias_refusals.saw` reports none of m1–m5 or m11. `/Users/shawn/Projects/sawlang/.build/scratch/p1000e/F30_alias_enum.saw` is accepted.

sawc does refuse wrong construction arity, a wrong construction type and `Byte(300)`.

Related: SL-48 (literal adoption) and SL-744 (alias construction). The fix brief owes a position matrix: every transfer position, casts, statics and constructions.
