## Description

**An unwritable front-cache directory prints the same warning up to eight times in one build.** Found by the lead on Nov 12, building scratch programs from a sandboxed shell where `~/.cache/sawc/front` can't be read or written.

One `sawc build` of a ten-line program prints, before its own output:

```
sawc build: warning: cannot list the front cache's generations in /Users/shawn/.cache/sawc/front: opendir "/Users/shawn/.cache/sawc/front" failed (permission denied)
sawc build: warning: cannot list the front cache's generations in … (again)
sawc build: warning: the front cache stores nothing: cannot create /Users/shawn/.cache/sawc/front/g1: mkdir … failed (permission denied)
sawc build: warning: cannot list the front cache's generations in … (again, and so on: five to eight lines)
```

The build itself is right (the cache is an optimization, and the warning is the never-hide-errors answer). The repetition is the defect: each cache operation re-discovers the same failure and reports it again, so the real diagnostics scroll under it.

**Expected:** one warning per cache per build, naming the directory and the cause once, and saying the cache is off for this build. Mechanism (UNVERIFIED): `driver_cache_warning` in `compiler/driver/src/main.saw` is called at each failing step with no record that the cache already reported. Check the object cache for the same shape.

Low priority; a small driver unit with a run-lane check beside `check_front_cache` (a cache directory made unreadable for the check).
