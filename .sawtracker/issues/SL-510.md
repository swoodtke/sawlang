## Description

**Found by:** tcb2c (batch B2c), settling SL-503. **Area:** typecheck, the erasure to `any Trait`.

**The defect:** sawc2 has no object-safety check. LANGUAGE_SPEC, "Object safety (v1)", says a trait is erasable only if every method is dispatchable, and refuses, with a diagnostic naming the reason:
- a method naming `Self` in a parameter or its return type;
- a method with its own generic type parameters;
- a trait with associated types;
- a marker trait.

sawc2 accepts both erasures here, through typecheck, MIR, borrowck and drops:

```saw
trait Same {
    func same(&self, other: &Self) -> Bool
}

trait Feeder {
    func feed<T>(&self, x: T) -> Int
}

struct P { n: Int }

extension P: Same {
    func same(&self, other: &Self) -> Bool {
        self.n == other.n
    }
}

extension P: Feeder {
    func feed<T>(&self, x: T) -> Int {
        self.n
    }
}

func a(s: &any Same) -> Int { 1 }
func b(s: &any Feeder) -> Int { 2 }

func main() {
    let p = P(n: 1)
    print(a(&p) + b(&p))
}
```

When a generic requirement's implementation calls through its bound, the erasure is refused, but for the wrong reason: `effect.any-suspends`, saying the implementation "may suspend". The summary's condition over its own type parameter reads as a possible suspension.

**Mechanism:** typecheck has no rule over the trait an `any` type names. Grepping `compiler/typecheck/src/` for object safety or erasable finds nothing. Method calls on `any Trait` are `slice.not-yet` (existential-call), but forming the type and coercing to it are both in the slice.

**Owed:** a refusal at every position an `any Trait` is formed, which is one funnel, naming the method or associated type that blocks it. It covers each of the spec's four reasons, the parents' methods included. The `effect.any-suspends` check should then not see a generic requirement at all.

sl503, narrowing this issue after SL-503's refusal branch (commit 96a1db9a on the SL-504 batch branch).

**The generic-method reason can't be reached while Q23 holds.** SL-400 c6 (Q23) refuses generic parameters on a trait requirement, and typecheck now does so at the requirement, as `trait.generic-requirement`. A trait with a generic requirement is therefore refused before any erasure of it matters. The same commit leaves a generic requirement out of `dispatched_requirements`, so `effect.any-suspends` no longer sees one: the probe's `&any Sink` coercion now gets only the requirement's refusal, and the "may suspend" misreport is gone.

**What still stands.** The object-safety funnel is still owed for the three remaining reasons in "Object safety (v1)":
- a method naming `Self` in a parameter or its return type (the `Same` trait above is still accepted as `&any Same`);
- a trait with associated types;
- a marker trait.

The generic-method reason comes back into scope only if the user re-rules Q23.

**Review note (lead): SL-510.p1 carries SL-510 and SL-537, one commit each.**

**SL-510, object safety.** Every `any Trait` is created by `mk_any`, which records the written node. One check, `check_object_safety` in the new `erasure.saw`, judges them once requirements are known. Its docstring names the funnel's entry point. The refusal is `erasure.not-object-safe`, given where the `any` is written; coercions and Result-erasure are refused through the type they convert to, never twice. The reasons, own then inherited:
- a marker trait (`Deinit` set aside);
- an associated type;
- a static requirement;
- `Self` at any depth in a parameter or result.

The position matrix has 33 refusal fixtures; the accepted control is golden `object_safety`. One corpus program is newly refused, `trait_self_ref_param_not_erasable_error.saw`, which is an EXPECT-ERROR pin of this exact rule.

**Two readings beyond the brief, which I accept:**
- The **static-requirement** reason. The spec's Serialization section refuses `any Deserialize` for exactly this ("a static requirement has no receiver to dispatch on"), and Stage 0 agrees.
- **`Deinit` set aside** in the marker test, which makes `NoCopy` a marker and refuses `any Deinit`.

**SL-537, Sync for statics.** `static.not-sync` in `check_static_type`, through the shared `satisfies` bound check. `unsafe static var` is exempt, and a cell holder owes `UnsafeSync`. It is pinned under both std roots: 6 refusals and golden `static_sync` on the default std; `static_sync.saw` and `static_not_sync.saw` on `--std-root std`. Nothing in the compiler source, `std/`, `sawc/std`, `sawc/rt` or `tests/corpus/` is newly refused.
