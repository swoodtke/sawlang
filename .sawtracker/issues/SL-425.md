## Description

**User direction (Sep 29):** Stage 0 workarounds must be tracked, so they can be removed once the self-hosted compiler runs, and so nobody copies them as Saw idioms without knowing why.

**The mechanism** (landing with SL-422):
- Every site in `compiler/` shaped only by a Stage 0 hazard carries `// Stage 0 workaround (SL:hazards <id>): canonical: <original spelling>`, with ` — <why>` optional (c1, user-confirmed). The canonical payload is the natural Saw spelling the workaround replaced. sawtracker uses the same marker (ST-66).
- A check validates each marker's hazard id against SL:hazards and prints the inventory, per hazard, with file, line and canonical text.
- The subset checker's refusal messages tell the author to add the marker.

The bootstrap std cone (epic unit 5) follows the same convention when it is written.

**This issue: removal after self-hosting.** Once the Stage 1 = Stage 2 fixpoint holds, and Stage 0 no longer builds the compiler:
1. Re-canonicalize: replace every marked site with its `canonical:` text, a mechanical step driven by the inventory. Then re-run the tests under Stage 1.
2. Retire the subset-checker rules that exist only for Stage 0 hazards. Keep the rules that enforce the subset for other reasons.
3. Make the marker check fail on any remaining marker, so none survive.
4. Update `compiler/README.md` and SL:hazards: the hazards remain as a record of the frozen compiler, but they no longer shape `compiler/`.

Tracked by SL-398's acceptance item "Every Stage 0 workaround marker is removed after self-hosting".

**Air on unit 1's evidence rule: each repro at BOTH -O0 and -O2, and the memory-class ones under ASan too.** "Compiled AND run" should name the levels. Several hazards were optimisation-dependent (folds, inlining, a drop placed differently at -O2), and sawc2's own record has level-split bugs: SL-805's fault read as `stack-use-after-return` at -O0 and `stack-use-after-scope` at -O2; SL-577's dump probes; the `-O2` busy-loop folds. So a repro that passes at -O0 alone proves nothing for the compiler source the seed builds at its own level.

A verdict of **fixed** should require, for each entry's repro:
1. -O0 and -O2, with sawc2 at main AND with the pinned seed (the issue already names both compilers);
2. for the S-family (soundness) entries that involve ownership, drops or lifetimes, an ASan run (`--sanitize address`, `ASAN_OPTIONS=detect_stack_use_after_return=1`) besides the plain one, since a plain run that prints the right line can still read freed memory;
3. the repro's EXPECT checked, not just exit 0. Some hazards were silent wrong answers, the `joined 60000000001` kind.

The sweep's table then has one row per entry and four cells (seed or main, by -O0 or -O2), plus an ASan column where it applies, and "fixed in both" means every cell. It's cheap to state now and saves re-running the sweep when a single-level "fixed" turns out to hold at only one level.
