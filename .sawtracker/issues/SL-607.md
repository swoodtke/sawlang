**A1. One capture lowering, and one "is it a reference" predicate** (SL-606, bucket A). Findings: Borrowck 1 (a use-after-free from safe code), Typecheck-body 1 and 1b, and M2.

- **Mechanism:**
  - MIR lowers an explicit `[&var v]`/`[&v]` capture of a REFERENCE PARAMETER as a reference to the reference. Borrowck's overlap rule then reads it as naming the reference, not its referent, so no loan check sees it. `self` and an implicit capture are lowered as reborrows and are checked.
  - Separately, typecheck asks "is this a reference?" with `kind == Ref` alone at a dozen sites (`add_capture`, `referent()`, `closure_result_value`, `open_return`, `ref_expr`'s reborrow, `adjust.saw`'s `convert`, `infer.saw`), so a `&[T]` slice is never a borrow.
  - `add_capture` also tests the `[move]`/`[copy]` branches before the frame-borrow test.
- **Fix:**
  - one capture lowering: an explicit capture of a reference is a reborrow of its referent, the way `self` is;
  - one predicate covering Ref and Slice, used at every site;
  - a capture word never skips the frame-borrow or move-from-borrow rules.
- **Pins first** (obligation 3): conformance rows for an explicit capture of a reference parameter under a window, a slice capture in an escaping closure, and `[move r]`/`[copy r]` of a reference. Use the review's probes (`review_bc_capture_*`, `review_tcsig_slice*`, `review_tcbody_capture_*`) as fixtures, each refused.
- **Sweep:** list every `kind == Ref`/`kind_of(t) == Ref` site in `compiler/typecheck` and `compiler/borrowck`, and route each through the predicate, or record why a slice can't reach it.
- **Done when:** every probe is refused with the right rule id, the matching local-root and implicit-capture controls are unchanged, and borrowck agrees with Stage 0 wherever Stage 0 can parse the form.

Requested changes on patch SL-607.p1 (revision 1)

Requesting changes on SL-607.p1. The explicit-capture fix is right and closes more than its own probe. But the same use-after-free survives with the capture list left off, and decision 3 is unsound by the same mechanism, with a different answer at -O2. Both are fixed by applying the patch's "one capture lowering" to the capture's copy use too.

I built Stage 1 and Stage 2 at the base 0afb91189 and with the patch (exact tree a5a54147). Probes are in `.build/scratch/air-review/sl607/` on the Air, each checked with `borrowck --check --std-root std`.

**What the patch closes** (base accepts, patch refuses):
- the original probe (`fable/capture_uaf.saw`): `loan.window-root` at the capture. The base printed `v[0] = 1 (expected 101)`.
- a nested closure re-capturing `[&var v]` from its outer closure's environment, under a window inside the outer closure (`cap_nested.saw`). See note 3 for its message.
- a borrow binding captured with its root, `[&var first, &var v]` (`cap_binding_and_root.saw`).

The controls are unchanged: `[&var self]` and an implicit `self` capture under a window are refused by both; an implicit slice capture under an element window is refused by both (`loan.read-while-exclusive`).

**1. Blocking: the implicit capture of a reference parameter is the same use-after-free, still accepted.** `cap_implicit_uaf.saw` is the original probe with `{ [&var v] in … }` written `{ … }`. Both base and patch accept it, and the patched binary prints `v[0] = 1 (expected 101)` at -O0 and at -O2.
- c1 assumed an implicit capture is "lowered as a reborrow and checked". It isn't. The MIR is `_5 = closure#0 of …through_param(…) [copy _1]`, a copy of the reference, made inside the open exclusive window `w0` on `*_1`.
- **The mechanism:** `capture_loans` does add a loan on the referent for a copied reference, but it isn't checked against the loans already live. Conflicts are found at accesses, and copying `_1` reads `_1`, which doesn't overlap a loan on `(*_1)`. The explicit capture is caught only because it now lowers as `ref (*_1)`, an access of the referent. `self` escapes the hole because it's always reborrowed. A slice escapes it because reading `s` overlaps its element loans. A plain `let r2 = r` copies the referent's value, so closures are the only place a reference itself is copied.

**2. Blocking: decision 3 (`[copy r]` copies the reference) aliases two exclusive references, and -O2 drops a write.** `cap_copy_exclusive.saw`: `both(&var r, { [copy r] in r += 10 })` with `both(a: &var Int, body:)` doing `a += 1; body(); a += 1`. Base and patch both accept it. It prints **12 at -O0 and 2 at -O2**: `a` is a `noalias` `&var` parameter, so the optimizer keeps it in a register across `body()` and loses the closure's `+= 10`. Stage 0 also accepts it and prints 2, so 'as Stage 0 does' copies a Stage 0 bug; the SL:hazards follow-up should cover this non-escaping case as well as the escaping one. It's mechanism 1 again: the copy's loan is never checked against the argument's reborrow.

**The fix for both:** make `reborrow_capture` cover the copy use. A capture of a reference binding whose use is `Copy`, implicit or `[copy r]`, lowers as `ref (*p)` in the reference's own mode (shared for `&T`, exclusive for `&var T`), exactly as Borrow and BorrowVar now do. The loan checks then see the window and the argument. I'd also refuse `[copy r]` of an exclusive reference outright, with the fix-it `[&var r]`, since a copy of an exclusive reference is exactly what exclusivity forbids, and keep `[copy r]` of `&T` as a shared reborrow. The other route, checking a capture loan against live loans when it's created, also works, but it leaves two lowerings.

Pins, conformance rows first (obligation 3): `cap_implicit_uaf` and `cap_copy_exclusive` as refusals, plus an implicit capture of a shared `&T` parameter under an exclusive window. The run lane needs a program showing the implicit capture still works where it's legal.

**3. Note: `cap_nested`'s refusal names an internal place:** "`_1.0` is borrowed exclusively here while the window … holds `_1.0`". A path through a closure's environment tuple should be rendered as the capture's name (`v`).

**Decisions 1, 2 and 4: agreed,** each consistent with how references already behave:
- (1) A reference parameter forwards only with its sigil in both sawc2 and Stage 0: bare `g(r)` is `type.mismatch` ('forward the reference with its sigil'), and `two(r, r)` likewise. A slice now follows the same rule, where it used to be a copy with no loan (`fwd_*.saw`).
- (2) Narrowing `[&v]` of a `&var` to shared mirrors `[&self]`.
- (4) Neither references nor slices narrow `&var x` to a shared parameter at a call; both are refused with 'call sites mirror the parameter's reference' (`narrow_*.saw`).

**Corpus:** `borrowck --check` over all 1809 `tests/corpus` programs, base against patch, gives 0 verdict changes. The corpus is thin exactly where this patch acts: 4 programs use slice types (2 of them `slice.not-yet`), and 54 use explicit captures. So the probes above carry the weight.

**Gate:** pending; these findings don't depend on it.
