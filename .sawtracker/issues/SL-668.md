## Description

**Unit 7 of SL-661: terminology for the v0 compiler inside sawlang, after the tag.**

**The user (Oct 14):** "we should also use different terminology for the python stage 0 compiler so it isn't confused with the sawc2 compiler which will eventually become the sawc compiler. so SAWLANG_V0_ROOT or something like that in our scripts." Also: "we can leave it as is for the tag - and then change it post tag so the current users see a consistent build env. and then when they move to the new compiler, everything will continue to work as is w.r.t. the toolchain - they will still need to update to sawc2 saw."

**So:**
- **The tag (v0.13.0) is untouched.**
- **The resolver's public names don't change:** `SAWLANG_ROOT`, `SAWC`, `BLADE`, `sawc` on `PATH`, `sawlang.pin`. They mean "the sawlang toolchain", which after unit 6 is the self-hosted compiler. A consumer that bumps its pin past the tag keeps its toolchain setup and updates only its Saw source.
- **Inside sawlang, wherever a script or doc still needs the v0 compiler,** it uses the distinct names:
  - **sawc0, "the v0 compiler":** the Python compiler at v0.13.0;
  - **`SAWLANG_V0_ROOT`:** a checkout of the tag with its venv;
  - a v0 pin if one is needed.

  This covers the frozen sources' build recipes, snapshot regeneration (unit 4), and anything else that still invokes it.

**Owed:**
- The spellings fixed: sawc0, `SAWLANG_V0_ROOT`, and the pin name.
- One resolver entry point for "the v0 compiler", so no script computes its path.
- Every remaining v0 reference using it.
- A docs pass so "Stage 0", "sawc" and "sawc2" each mean one thing: "sawc" is the self-hosted compiler after unit 8, "sawc0" the v0 compiler, and "Stage 0" only the historical bootstrap stage.
- **Coordination:** sawtracker vendors `tools/toolchain.py` (ST-80) and sawos uses it. Their names don't change, but tell their leads in chat when this lands.

**Depends on:** unit 6.
