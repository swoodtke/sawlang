**Air on (c): sound as a backstop, and sufficient for r2, on three conditions; two things I'd add.**

**Why it is sound.** With the counter in the group, every path a handle has — `join`, `cancel`, and its drop — touches the group's storage, so a handle outstanding when the group dies is a future use of freed storage whatever the program does next, a bare late drop included (today a handle's drop touches nothing; under (c) it decrements, so "never used again" is no longer a safe case, which is right). The abort at teardown therefore precedes every such use and fires in no correct program. It is deterministic (at the group's death, not at the stale use), and it is the same shape as the provenance-keyed drop panic behind the fate rule. p4, p5 and p7 abort at the right place: the Box's replacement, `consume`'s drop, the holder's scope end — each runs the group's `deinit` before the storage goes.

**The conditions, each a pin:**
1. **A consumed handle's drop decrements nothing.** `join` and `cancel` go through `consume()`, and the handle is dropped after; if the drop decremented again the count goes negative, and one outstanding handle beside one double-decremented one nets to zero — the abort would be missed, silently. Pin: spawn two, join one, keep the other past the teardown, and require the abort to say `1`, not `0`.
2. **The check comes after the eager cancel-and-join and before any storage is released** (`release_slots` and the cells): handles held in the group's own task frames are dropped by that join and must count down first, and nothing freed before the check can be what a stale handle reads.
3. **The counter is the group's own storage**, written only through the group pointer the handle holds, so the handle's decrement is itself a use the abort pre-empts; under `threads: N` it is the atomic A17a names, read after the workers are joined.

**What I'd add:**
- **A conformance row and a spec sentence that say "enforced at runtime for a handle minted through a borrow window"**, beside K161–K166's compile-time rows, so the ruling's "compile-time error naming the group's end" stays exact about which routes it covers. The static rules keep every route they see; (c) is the backstop for the window route and any route they miss. A later (a) can still be added without changing any program's meaning, since the abort then never fires.
- **The message should name what the user can act on.** `panic at taskgroup.saw:N` points into std; "destroyed while N task handles still refer to it" names no site. The group has no declaration site at runtime, but each handle's spawn site is known at the form; recording it (a `#file`/`#line` pair in the handle, as the fate panic's provenance is) would let the abort say `the handle made at main.saw:12 is still live`. Not a condition — a request, if the handle has room for it.

On (a) for the record: `Box.value()` lends `&var` only (`std/box.saw`), so a kept handle would indeed block every further window on a boxed group until it is consumed; a shared `value` accessor pair (which SL-671 made nameable) would lift that, which is why (a) stays open as a later refinement rather than being wrong.
