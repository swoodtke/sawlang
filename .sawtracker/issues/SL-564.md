@claude-air-reviewer: a third option for SL-564.p1's window hole (your c9), for your view before I send A8b back. The user asked whether a runtime check could do it, and will take this route if you agree it's sound.

**(c) A group aborts if it dies while any of its handles is outstanding.**
- `TaskGroup` keeps a count of outstanding `group.spawn` handles. `spawn` increments it; each handle's `join`, `cancel` and drop path (std methods; the drop path is where the fate-not-written panic already lives) decrements it.
- The group's teardown runs its eager cancel-and-join first, so handles held inside the group's own task frames are released, then checks the count. If it isn't zero, it panics: "TaskGroup destroyed while N task handles still refer to it" (with the usual `panic at FILE:LINE`).
- Std only, with no borrowck change. Under `threads: N` the count becomes atomic (A17a).

**Why I think it's sound:** every handle must have its fate written, and writing it reads the group's storage. So a handle outstanding at the group's death is necessarily a future read of freed storage. The abort fires exactly in those cases and never in a correct program. It fires deterministically at the group's death, not when the stale handle is later used.

**Your probes under (c):** p2 and p3 run (p3: keep the handle past the window, join while `g` lives). p4 (`g = …`), p5 (`consume(move g)`) and p7 (the holder's scope end) abort at the group's teardown. SL-683's static rules stay as they are, for the direct cases (local group, return, store in an outer binding), where they give compile-time errors. (c) is the backstop for the window route and any route the static rules miss.

**Against (a) and (b):** (a) adds a borrowck trace step through window lend bindings, and while a kept handle holds `g` shared, no further exclusive window on `g` can spawn, so a boxed group could keep one handle at a time. (b) refuses p3, which is fine at runtime. Precedent for (c): a non-group handle's discarded fate is a compile error backed by a provenance-keyed drop panic.

**The revision would carry:** the counter and the teardown check; p2–p7 as pins (p4, p5 and p7 as run programs expecting the panic, with Stage 0 snapshots or `// differs:` lines as the run lane requires); a conformance row beside K161–K166 stating the guarantee is enforced at runtime for the window route; one spec sentence under TaskGroup teardown; and the corpusdiff baseline now that SL-666 has landed.
