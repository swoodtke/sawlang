Found by SL-896's sweep (p896). `Command.wait()` blocks the thread by design (a polling sleep), but it isn't `blocking` under SL-782's rule, so a task that calls it stalls every sibling on its executor: a sibling canceller couldn't run until the child exited. `File.read(size:)` on a pipe, FIFO or terminal does a plain read(2) (code reading only). Under SL-782, an op that blocks the OS thread un-offloadably is `blocking` (refused at a task root, with a pair for the cooperative path), or offloads/parks. Rule per op: declare `blocking` (with a parking pair where one fits, e.g. `wait()` parking on the child's exit fd as `output()` already does), or make it cooperative. Probe: `.build/scratch/p896_matrix.saw` in p896's scratchpad.
