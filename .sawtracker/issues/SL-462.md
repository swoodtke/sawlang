# SL-462: mutability, reference positions and field move-out in sawc2's typecheck (plus SL-466)

- **Epic:** SL-398. SL-462's description and comments have the three families and their history. U6d1's conformance census (chat m347) found that no sawc2 stage refuses them.
- **Why it matters:** family 2 is the soundness premise of SL-460's U6d2. The borrow check is per-function only because a reference can never escape a function. This lands before U6d2 is relied on.
- **Design:**
  - LANGUAGE_SPEC: "Variables and Mutability" ("Bindings always initialize"), "References" (parameters only), "moving a field out", and `consumes`;
  - SL:borrowing §2 and §4 (lends, `borrows -> T?`, borrowing structs);
  - `examples/conformance/INDEX.md`'s Mutability, References and Moves sections (the M, R and V rows);
  - Stage 0's rules, as the behaviour to match: `sawc/parser/types.py` (references in types), `sawc/typechecker/types.py` and `expressions.py` (the "PARAMETERS ONLY" diagnostics, mutability and partial moves).

## Decisions (the lead)
1. **Mutability is a typecheck rule family, `mutability.*`.** Every binding has an initializer, so ANY assignment to a `let` is an error. No flow analysis is needed, and no MIR change. The facts are the binding's `let`/`var` and the reference type along the place path (`&T` vs `&var T`, `&self` vs `&var self`).
   - **The rows (a matrix, obligation 1):**
     - assigning or compound-assigning a `let` local, or a field or element of one;
     - `&var` of a place rooted in a `let`;
     - a write through `&T` or `&self`, a field of it, or an element through a `borrows` accessor reached shared;
     - a `&var self` method called on a `let` receiver, or through `&T`;
     - a `let` declared inside a loop body, accepted on every iteration, while a real `x = …` to it inside the loop is refused (the Air, m352);
     - writing a captured `let` from a closure;
     - `var` parameters, if the slice has them.
   - **What decides each row** is one funnel, "is this place writable", with its entry points named. Every write-shaped position routes through it: assignment, compound assignment, `&var`, a `&var self` receiver, a `&var` argument, and a `borrows` window opened exclusive.
2. **References are parameters only: `type.reference-position`** (or a family under one prefix). Each position where a type is written or inferred gets a row.
   - **Refused:** a return type, a struct or enum field, a local or static binding's annotation, a tuple element, a type argument (`Vector<&Int>`), an Optional payload outside a lend, a closure's return, a binding INFERRED from a reference-producing expression, and a generic instantiated at a reference.
   - **Allowed, each with its reason pinned:** parameters, `borrows -> &T` and `borrows -> &T?` lends (SL:borrowing), borrowing-struct fields under `borrowing.containment`, and what Stage 0 allows besides (find it in Stage 0's rules, don't guess).
   - One funnel over type positions; that's the type-position matrix.
3. **Field move-out.** A spelled `move p.x` (a struct field, tuple element, enum payload, or a nested path) is refused.
   - **The exceptions:** `move self.f` inside a `consumes` body, and `move o!`, plus any other the spec names.
   - **Its rule id** sits beside `transfer.*`, or is its own.
   - **"Every path or none" for `consumes` fields is NOT yours.** U6d1 (SL-460) owns it in the borrow check, from the shared init analysis. Don't build a copy of it.
4. **SL-466, in its own commit** (decided as D24 in SL:open-questions):
   - the builtin module gains `__saw_atomic_load_i64_relaxed`, typed like D23's three and visible only to new-std modules;
   - `std/string.saw`'s `copy()` and `deinit` read the refcount through it;
   - LANGUAGE_SPEC's String section says "relaxed atomic load", with the `docverify` lane run;
   - the std lane's MIR pin of the hooks asserts the relaxed load comes before any atomic RMW.

Pre-review of the SL-462 brief (c4). The shape is right: one funnel per family, with a row matrix. One row would break `std/` if missed, a few positions are absent from the matrices, and one existing rule should be mapped rather than rebuilt.

**1. A write through a raw pointer stored in a `let` must stay legal, or `std/` fails the std lane.** `std/string.saw` does exactly that:

```saw
let words = block as UnsafePointer<Int>
words[0] = 1                         // string_from_bytes
words[1] = count
let bytes = (&block[header_bytes]) as UnsafePointer<Int8>
bytes[i] = source[i]
```

A funnel that reads `words[0] = …` as "an element of a `let`" refuses it. The pointer is never written; the pointee is. So the "is this place writable" funnel needs a row: a subscript or deref through `UnsafePointer`/`UnsafeMemory` writes the pointee, and is allowed whatever the binding (it's already `unsafe` by the trigger rule). The same goes for interior-mutability cells: a `&self` method on a `let` Mutex, Atomic or SpinLock is legal by design, so the funnel must not see their `&self` writes.

**2. Mutability rows missing from the matrix** (each refused or allowed, as Stage 0 has it):
- assigning a non-`var` `static`; an `unsafe static var` is allowed;
- a `for` loop's binding;
- pattern bindings: `if let`, `guard let`, `match` arm bindings and tuple destructuring are `let`, while `if var`/`guard var` are `var`;
- optional-chained assignment `x?.y = v` with a `let` root;
- `self = v`: allowed in a `&var self` body, refused in a `&self` body;
- whole-referent replacement `r = v` through a `&var` parameter: allowed (design 110);
- writes to `self.f` in a `consumes` body: check the spec's rule and pin it either way.

**3. Reference positions missing from the matrix:**
- a function *type*'s return, `() -> &Int` (its parameters stay allowed);
- a trait requirement's return type;
- `extern` signatures (find Stage 0's rule);
- a type alias to a reference;
- `&any Trait` as a parameter (allowed), and a bare `&Trait` (refused, as the spec's unsized rule).

**4. Map the capture rows; don't rebuild them.** The spec's other escape route is "captured by an escaping closure". sawc2 already refuses it as `capture.escaping-borrow`, for all three spellings (on main plus U5b2):
- `return { self.n + 3 }`;
- `return { r.x + 1 }`;
- `let f = { r.x + 2 }` (a `let`-bound closure counts as escaping).

So the R rows about captures map to that existing rule in the conformance table, and family 2's funnel covers type positions only. The spawn forms are `slice.not-yet` in sawc2 today; Stage 0 refuses a reference passed into `Task.spawn`/`Thread.spawn` (the `Send` check, and "captures nothing implicitly"). Mark that row "due when spawn enters the slice" so it can't land silently.

**5. Field move-out rows to add:**
- an element: `move v[i]` on an array or Vector (the std ops are `swap_out`/`take`);
- a move out through a reference: `move r.f` with `r: &var S`, refused even in a `consumes` body, which owns only `self`'s fields;
- a nested path: `move p.a.b`.

Probes for points 1 and 4 are on the Air (`.build/scratch/air-review/sl456p2/probe_escaping_capture.saw`, `probe_spawn_ref.saw`).
