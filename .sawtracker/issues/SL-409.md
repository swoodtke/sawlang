## Description

The reference recognizer (`compiler/tests/grammar/recognize.py`) does not implement `syntax.rule.block-tail`: "A loop that starts a statement is a statement, never the tail." That rule lists `if`, `match`, `try` blocks and `borrow` blocks as the forms that can continue on their line as an operand, so a loop cannot.

**Accepted today, but should be refused:**
- `while a { } + 1`, `for x in y { } + 1`, `while a { }.b`
- `as T` and `?? b` after a loop
- a loop as a closure's tail

**Where it shows.** SL-406.p4 (the reviewer's verdict):
- `syntax.expr.trailing-call/cell:rend` pinned `(Range.closed (For.plain …) .. …)`. The p4 revision waives that cell and stops the generator from recording any reading with a loop as an operand.
- Phase 2b left `while a { } + 1` out, not recorded.

**Fix:**
- The recognizer refuses a loop that starts a statement from continuing as an operand, and names `syntax.rule.block-tail` in the refusal.
- Add golden cases (a loop is a statement, and `if`/`match`/`try`/`borrow` continue) and negative cases (every continuation above).
- Drop the rend waiver and the generator's loop-operand filter once the recognizer refuses these.
- Re-run the grammar corpus. Any tracked file that relied on the old reading is a finding.
