## Description

Four units, all ruled as the lead recommended: (1) ONE DISCOVERY LEDGER — a single pass computes the closed frame table (key, declaration, really-suspends, buildable, reason) before any body is lowered; classifier, closure walk, generic promotion, rejectors and drive-site rewriting READ it and derive nothing; a battery lane fails on any transform site that reads the raw suspension bit or a symbol name directly (the producer-taxonomy / astgraft precedent). (3) COVERAGE UNITS INSIDE THE EPIC — SL-215 (inline try/catch split) and SL-317 (iterator state in the frame for a collection for) are epic units, NOT standalone point fixes; sawtracker's build (currently stopped at those two) is the epic's acceptance test and WAITS for it — the user ruled a point fix is a waste of time. Census (Sep 18): coro_transform.py 12,224 lines, a 212-method _FrameBuilder, a 1,032-line transform_program with nine nested closures, ~20 distinct suspension/frame-key predicates, 7 split shapes (if, if-let, guard-let, while, RANGE for, match, BLOCK try-catch), 21 scattered refusals, 17 governing designs (44..224). The lowering is stable; every finding this week (SL-280, SL-274 keying sites, SL-306 + its review, SL-215, SL-317, SL-287, SL-316) was a discovery seam. Brief: designs/275-coro-discovery-uniformity.md (lead, next). Sequenced after SL-306.p1 r2 + SL-274.p1 r2 land and the small-fixes batch; ledger unit first.
