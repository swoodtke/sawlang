## Description

**Found by:** tcb2c (batch B2c), while writing SL-493's funnel. **Area:** MIR lowering of `&&`/`||`, the scope of an owned temporary made on the right side; or the MIR verifier's double-drop check.

**The defect:** an owned temporary created on the right side of `&&` inside a loop body trips the MIR verifier's double-drop invariant. On main's sawc2 (bd6d5713):

```saw
func name(k: Int) -> String {
    if k > 1 {
        return "long"
    }
    "s"
}

func count(n: Int) -> Int {
    var found = -1
    var k = 0
    while k < n {
        let at = k
        k = k + 1
        if at > 0 && name(at).starts_with("l") {
            found = at
        }
    }
    found
}

func main() {
    print(count(3))
}
```

`sawc2 mir --check` prints `INVARIANT dd 8:27 dd.count(n: Int): local _10 may be dropped twice in bb5: a path drops it before, and nothing assigns it between`.

**Mechanism (from the dump of the loop-free twin, which is clean):** the temporary `name(at)` is assigned only on the right side's path, but its drop sits at the join after the `&&`, in the condition's statement scope. So on the short-circuit path the drop sees a local that was never assigned in this iteration. Outside a loop that is a maybe-initialised drop. Inside a loop, the previous iteration's drop reaches it, so the verifier calls it a second drop. Either the right side's temporaries belong in a scope that closes on the right side's own path, before the join, or the verifier's check should treat a drop reached only through the short-circuit edge as a flagged maybe-drop.

**Sweep owed:** `||`, a value `if`/`match` arm, and `??`'s right side, each in a loop, at an owned temporary.

**Impact:** the compiler's own source can't use the shape: SL-493's `check_static_assert` binds the text to a `let` first instead.

Requested changes on patch SL-508.p1 (revision 1)

Changes requested on SL-508.p1, for two small items: the new spec text and the new subset rule each leave out one face of the same rule. Everything else holds up:
- D42's lowering is right on every shape I tried;
- the `cand_param_count` fix and its marker are in;
- the subset rule catches the site it was written for.

**1. The spec's new temporary rule says statement end for a bare `match` arm. sawc2 does arm end, and Stage 0 statement end.** The added text in "The Deinit trait": "A temporary … is destroyed at the end of its statement …; a condition of `if`, `while` or `guard`, and a `match` guard, ends before the branch it decides. The exception is a temporary made on an operand that only some paths evaluate: the right side of `&&` or `||`, …, and every operand of `??` after the first." A bare arm is also an operand only some paths evaluate, and it isn't in the list. Probed (`sl508/arm_scope.saw`):

```
let total = match k { case 0 -> 0, case _ -> mk(1).val() } + mk(2).val()
```

| compiler | output |
|---|---|
| Stage 2 (sawc2) | `drop 1; drop 2` (the arm's temporary dies at the end of the arm) |
| Stage 0 | `drop 2; drop 1` (statement end, reverse order) |

Read literally, the new text prescribes Stage 0's order. For an arm that may not run, that would need exactly the run-time flag D42 exists to avoid. sawc2 gives an arm's temporary no flag (`sawc2 drops --dump`), so arm end is its actual rule.

Braced arms agree on both compilers (`sl508/block_scope.saw`):
- `(if c { mk(3).val() } else { 0 }) + mk(4).val()` prints `drop 3; drop 4`;
- a block arm `{ mk(5).val() }` beside `+ mk(6).val()` prints `drop 5; drop 6`.

So a block's tail temporary dies at the end of the block, and the text doesn't say that either. Suggested addition:
- a block ends its own temporaries, its tail's included;
- a bare `match` arm is a temporary scope of its own, as a braced arm is, with the example above (`drop 1, drop 2`).

S29 should gain the taken-path face too: Stage 0 drops a bare arm's temporary at statement END even when the arm ran, so drop ORDER differs as well as the garbage drop. If you'd rather record the arm rule as a D-entry first, that works too. The spec just shouldn't land saying the opposite of the compiler.

**2. The `conditional-temporary` rule misses an index into a call's result. Stage 0 ABORTS on that shape.** The rule fires only when a `MethodCall`/`MemberAccess` has a call as its receiver, so `case Made -> fields(k)[1]` (a `Vector<Int>` temporary, `struct_fields(d)[i]`'s shape) is not flagged. On Stage 0 (`sl508/gaps.saw`), the pass that takes the OTHER arm exits 134 (SIGABRT) with no output, the garbage `Vector` drop. Stage 2 prints `7`, then `10`. The patch's rule reports 0 diagnostics on it.

The fix is two lines: also match `ArrayIndex.array_expr` and `TupleIndex.tuple_expr` in `CALLS` (an `f().0` tuple temporary is the same face), plus fixture rows. I ran that extended matcher over the compiler source and the new std (`sl508/index_census.py`): 0 sites, so it lands clean. `&f(..)` needs nothing: Stage 0 refuses a reference to a call result outright.
