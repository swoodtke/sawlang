## Description

**Found by:** tcb2c (batch B2c), while writing SL-493's funnel. **Area:** MIR lowering of `&&`/`||`, the scope of an owned temporary made on the right side; or the MIR verifier's double-drop check.

**The defect:** an owned temporary created on the right side of `&&` inside a loop body trips the MIR verifier's double-drop invariant. On main's sawc2 (bd6d5713):

```saw
func name(k: Int) -> String {
    if k > 1 {
        return "long"
    }
    "s"
}

func count(n: Int) -> Int {
    var found = -1
    var k = 0
    while k < n {
        let at = k
        k = k + 1
        if at > 0 && name(at).starts_with("l") {
            found = at
        }
    }
    found
}

func main() {
    print(count(3))
}
```

`sawc2 mir --check` prints `INVARIANT dd 8:27 dd.count(n: Int): local _10 may be dropped twice in bb5: a path drops it before, and nothing assigns it between`.

**Mechanism (from the dump of the loop-free twin, which is clean):** the temporary `name(at)` is assigned only on the right side's path, but its drop sits at the join after the `&&`, in the condition's statement scope. So on the short-circuit path the drop sees a local that was never assigned in this iteration. Outside a loop that is a maybe-initialised drop. Inside a loop, the previous iteration's drop reaches it, so the verifier calls it a second drop. Either the right side's temporaries belong in a scope that closes on the right side's own path, before the join, or the verifier's check should treat a drop reached only through the short-circuit edge as a flagged maybe-drop.

**Sweep owed:** `||`, a value `if`/`match` arm, and `??`'s right side, each in a loop, at an owned temporary.

**Impact:** the compiler's own source can't use the shape: SL-493's `check_static_assert` binds the text to a `let` first instead.
