## Description

**Release v0.24.0.** User instruction (Nov 14, typed): "tag now". Main carries two memory-safety fixes no release has, and the sawos project needs a tag to move its pin.

**The patch:** `.sawtracker/version` becomes `v0.24.0` and `driver_version()` in `compiler/driver/src/main.saw` becomes `"0.24.0"`, which run.py's `version` step holds equal. The server creates the annotated tag at the patch's merge commit (ST-46). The release holds whatever is on main when this patch merges; SL-1119.p1 is approved and at the head of the merge queue, so it is expected to be in.

**Why 0.24 and not 0.23.1:** main has new refusals since v0.23.0 that can reject a program v0.23.0 built (SL-1115; SL-457's per-instance checks; SL-925; Blade's unknown flags), one changed meaning (SL-1090), a changed default (SL-1084) and new Blade flags (SL-1098).

**What v0.24.0 holds beyond v0.23.0** (each merged; ancestors of the tag are verified at landing):
- **Memory safety, both in safe code:**
  - **SL-1109:** the std executor's scheduler walk read a `TaskGroup` its owner had dropped during a handed-off turn (a use-after-free on every target, in v0.21.0 to v0.23.0).
  - **SL-1115:** an array literal was accepted for `[T; N]` with `N` a const parameter whatever `N` was, so safe code read uninitialized stack. A list literal against a length that is not a known constant is now refused.
- **Constants (SL-457, units U1 to U4b; SL-511 and SL-1107 with it):** `sizeof` and `alignof` of a target-fixed type fold in a constant; a repeat count, an array length and a const generic argument are constant positions folded by one fold at the target's width; arithmetic over a const parameter is carried symbolically and folded when the parameter has a value; a const value that faults, is negative or does not fit at an instance is refused there by the fault's own rule, with the instance named (SL-1111's wrong sizes and backend failures are now errors); a raw case whose value names itself is an error, not a crash.
- **SL-1090:** a lone raw-backed error enum's case in a `Result` slot whose error is erased is `Err` (it was `Ok(raw value)`).
- **SL-925:** `@synthesize` checks each field meets the derived trait, for every derivable trait.
- **SL-1010:** `#file`, `#line` and `#function` build. **SL-1037:** `sawc build` prints the parser's own message. **SL-1052:** the default `-o` path works when `.build/` does not exist.
- **SL-1084:** riscv32 with no `--target-features` states `+m,+a,+c` (what the clang default built), and the front end agrees with it; a written list replaces it.
- **SL-900 unit 1:** the driver's file and process waits are declared `blocking`.
- **Blade (SL-1098):** `blade build --linker-script FILE --out-dir DIR --module-path NAME=DIR`; every subcommand refuses an unknown flag, a missing value and a stray word; the up-to-date check covers the target, the linker script and the module paths.
- **Driver (SL-1103):** a build's scratch files are named per process, so two `-c` or cross builds to one output do not collide.
- **SL-1119** (if merged before this patch): an optional chain that moves an owning field out of a temporary builds (`units.get(0)?.object ?? ""` was an internal error).
- **Linux (SL-1113, SL-1117):** a split `-c` object links as PIE on Linux; the whole Linux lane is green on aarch64 and x86_64.
- **Freestanding and tooling:** SL-1078 (an `@section` walk case on every row), SL-1086 (`--dump-skip-std`), SL-1068, SL-1070, SL-1105, SL-1088's three tooling patches.

**Known in this release, NOT fixed:**
- **SL-1124 (memory safety, safe code, every release so far):** `s == want` or `s != want` with `s` an Optional whose payload owns something (`String?`) and a right side that is not a literal wraps a reference as the payload: a wrong answer, a crash or an out-of-bounds read. A literal right side and a trivially copied payload (`Int?`) are right. Ways round: `if let x = s { x == want }`, or `let w: String? = want` and then `s == w`. The fix is scheduled next and wants a v0.24.1 or v0.25.0 when it lands.
- SL-1123: two builds that link one executable on macOS collide on `OUT.o` and the `.dSYM`.
- SL-457's follow-up (p7, in review): an internal `INVARIANT` line after the correct errors when a faulting const value reaches a callee by inference; the build fails with the right errors either way.

**For a project moving its pin from v0.23.0** (sawos): SL-1115, SL-925 and SL-457's instance checks can refuse code that built; SL-1090 changes `Ok(raw)` to `Err` at the affected sites with no source change; riscv32 builds with no feature list are unchanged in their objects (the stated default is what clang used); Blade refuses a flag or word it does not know.

**Landing:** `git rev-parse v0.24.0^{commit}`; check each commit above is an ancestor; post the version and sha to the sawos lead in chat.
