Found by SL-642's sweep (agent b642borrow, reversible decision 4); not yet reproduced as a wrong program.

**Mechanism:** MIR's `getitem` (`compiler/mir/src/lower.saw`) labels the window it opens `shared` whatever the accessor declares. Through an accessor whose only lending form is `&var self` (exclusive), a plain getitem read therefore records a shared window over storage the accessor lends exclusively. Since SL-642, a `borrow` subscript settles as a place and opens an exclusive window there, as the declaration says (mir golden `windows`, `let copied = borrow r[2]`). So the two paths now label the same accessor's window differently.

**Why it's not a wrong program today:** b642borrow's probes show typecheck and the borrow check still refuse the uses an exclusive window must forbid, so nothing unsafe compiles. The mislabelled window is MIR-internal.

**Why it matters:** A5's post-lowering verifier (SL-558) and anything that later reads a window's mode from MIR would trust the label. A window's mode should have one source, the accessor's declared lending mode as the use site resolves it (SL:borrowing), whichever path opens the window.

**Fix shape:** `getitem` takes the window's mode from the same answer the place path uses, through one funnel. Pin: a MIR golden over an exclusive-only accessor, read both ways, showing one mode.
