## Description

**A `Command.output()` whose stdout drain FAILS still leaves its child unreaped** (the remainder of SL-799). SL-799's orphan list covers the two cancel paths. On drain failure, std must close the job's stdout read end, so a child that's still writing gets SIGPIPE instead of blocking forever on a full pipe, and must still reap the child later. No seam lets std close only the read end: `__saw_rt_proc_read_stdout` takes the job, and none returns the descriptor. So the drain-failure path keeps plain `__saw_rt_proc_release` (one `waitpid(WNOHANG)`, then free), and a child still alive exits into a zombie.

**Fix:** a seam, e.g. `__saw_rt_proc_close_stdout(job) -> word (0/-tag)` (both runtime trees, `ABI.md`, `runtime_table`), then the drain-failure path closes the read end and orphans the job like the cancel paths. No portable probe can cause a drain failure (a `read` error on a pipe, or a capture allocation refusal); an `alloc_deny_after`-style injection for the capture's allocation is the likely pin. Small; it can ride with SL-798 (which changes the spawn seam too).
