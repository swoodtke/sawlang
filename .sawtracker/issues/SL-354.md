## Description

Found by the SL-353 sweep (Sep 23; SL-353's sweep-report comment, 'secondary finding'). The registration funnel `__saw_exec_io_register` (sawc/std/taskgroup.saw:566-568) → `rt_reactor_register` (sawc/rt/host_macos/reactor.saw:111-119) ignores `kevent`'s return at reactor.saw:105, 118, 142, 150 and returns `Void`, so a failed arm (bad fd, EBADF, ENOMEM) leaves the task parked forever with the same signature as SL-353's race — the investigation had to spend a probe (abort on any kevent < 0) to rule it out. Doctrine: never hide errors. Fix shape (folded into the SL-353 fix brief as R6): the funnel reports a failed arm and the executor panics naming the fd and errno — a failed registration is an invariant violation, not a recoverable condition; a pin injects a closed fd and expects the panic. Linux host_linux/reactor.saw to be checked for the same pattern.

**Verdict: FIXED.**

- **The rule:** design doctrine "never hide errors" (CLAUDE.md); the issue's oracle: a failed registration panics naming the fd and errno
- **What `sawc` does:** SL-354.saw calls the executor arm funnel `__saw_exec_io_register(999, 0, token)` with a closed fd and a valid park word, -O0: "arming closed fd 999 for read / panic at taskgroup.saw:3432: reactor: arming fd 999 for read readiness failed (errno 9)" (rc -6). Source: runtime/host_macos/reactor.saw:126-137 `rt_reactor_register` returns `0 - __saw_rt_last_syserror()` when kevent < 0, and :107 checks the create-time wake-event arm; std/taskgroup.saw:3429-3434 turns a nonzero status into the panic. Linux twin: runtime/host_linux/reactor.saw:164,172 check both epoll_ctl calls (r0/r1), :134 checks the create-time arm. Still unchecked on both hosts: the wake TRIGGER (macOS reactor.saw:166 `kevent(...)`, Linux :200 `write(efd,...)`) and unregister (macOS :159, deliberately ignored, documented :149-151), which are SL-376's.
- **Note:** The issue's named sites 105 and 118 (create arm, register) are checked; 142 (unregister) is ignored by design with a comment; 150 (trigger) is still unchecked - tracked by SL-376. Probe called the funnel directly (it is `public` in std.taskgroup).
