## Description

Found by the SL-353 sweep (Sep 23; SL-353's sweep-report comment, 'secondary finding'). The registration funnel `__saw_exec_io_register` (sawc/std/taskgroup.saw:566-568) → `rt_reactor_register` (sawc/rt/host_macos/reactor.saw:111-119) ignores `kevent`'s return at reactor.saw:105, 118, 142, 150 and returns `Void`, so a failed arm (bad fd, EBADF, ENOMEM) leaves the task parked forever with the same signature as SL-353's race — the investigation had to spend a probe (abort on any kevent < 0) to rule it out. Doctrine: never hide errors. Fix shape (folded into the SL-353 fix brief as R6): the funnel reports a failed arm and the executor panics naming the fd and errno — a failed registration is an invariant violation, not a recoverable condition; a pin injects a closed fd and expects the panic. Linux host_linux/reactor.saw to be checked for the same pattern.
