**Found by:** sl518 (SL-518), then reproduced by the lead on main. **Area:** `tools/astdiff.py`, the `astdiff` battery lane (which parses every tracked `.saw` with both parsers and compares the trees).

The lane exits 1 on main, for two independent reasons:
1. **A RecursionError on `compiler/tests/grammar/fixtures/refusals/nesting_past_the_depth_limit.saw`** (SL-412). The fixture is deliberately nested past the grammar's depth limit, and the dumper recurses once per level. The fix: the lane treats a file the grammar refuses for depth as out of scope (it is already a refusal fixture), or the dumper walks iteratively, or the lane raises the recursion limit with a bound. Choose the one that keeps `astdiff` checking every file it can, and say which files it skips.
2. **A `summary:TupleLiteral` dispatcher fallback** in `compiler/tests/typecheck/golden/constant_refusals.saw` and `compiler/tests/typecheck/refuse/static.not-constant.tuple.saw` (SL-504's B2c fixtures). A tuple literal in a static initializer reaches a summary position the dumper has no case for. Add the case, so both parsers' trees are compared there.

**Process note:** neither patch ran `astdiff`. Per CLAUDE.md's gate policy it is owed for a parser change, and these were fixture additions, so the lane went red without anyone seeing it. Consider whether `astdiff` belongs in the per-patch gate when a `.saw` fixture is added, or in the lead's per-merge checks.

The fixture is now dumped and checked, not skipped. **Please weigh:** a Python limit that high trades a `RecursionError` for a possible C-stack overflow on a far deeper input.
