## Description

**A generic trait can be declared but never conformed to: `extension S: Maker<Int>` is a parse error.** Found by SL-987's census.

- **What's refused:** GRAMMAR.md's `conformance-list ::= ":" path ( "," path )*` takes a bare path, so a conformance can't name a generic trait's arguments. `trait Maker<U> { … }` declares, and every conformance to it is refused at parse.
- **What the spec relies on:** LANGUAGE_SPEC's `m[k, default: e]` section names a generic trait, `trait KeyedPlace<K, V>`, as the operations the default subscript uses ("`Map` has one"). No std file declares or conforms to `KeyedPlace` today.

**Census first (obligation 4):** generic traits at every position, with compile-and-run evidence:
- declaration;
- conformance, both concrete (`S: Maker<Int>`) and generic (`extension W<T>: Maker<T>`);
- a bound (`<T: Maker<Int>>`);
- `any Maker<Int>`;
- default bodies;
- static requirements;
- a requirement whose type uses the trait's parameters.

Then decide with the user whether generic traits are part of the language now: the grammar, the spec's Traits section, and the `KeyedPlace` text. If not, the declaration should be refused with a reason, rather than parsing a trait nothing can conform to.
