## Description

**A plain member and a `borrows` member of one name and parameters are accepted as declarations, but no call can reach the `borrows` one** (found by m671accessor while sweeping SL-671).

Typecheck's redeclaration check (`indistinguishable` in `compiler/typecheck/src/overloads.saw`) accepts the pair on the premise that "a `borrows` member is called only as a `borrow` head, so it never meets a plain one". Call resolution doesn't honour that premise: it never separates the two by the call's position.

Probes (`sawc2 build --std-root std`, main at 06a5c6fc2; scratch copies in the m671accessor worktree's `.build/scratch/m671/`):

```saw
struct Grid { a: Int, b: Int }
extension Grid {
    public func at(&self, i: Int) -> Int { if i == 0 { self.a * 10 } else { self.b * 10 } }
    public func at(&self, i: Int) borrows -> &Int { if i == 0 { lend self.a } else { lend self.b } }
}
func main() {
    let g = Grid(a: 1, b: 2)
    borrow let x = g.at(0) { print(x) }   // call.ambiguous
    print(g.at(1))                        // call.ambiguous
}
```

- With the plain `at(&self)` and a `borrows` `at(&var self)`, `borrow var x = g.at(0)` resolves to the plain one and is refused as `type.not-a-place`.
- The subscript form, a getitem `func [](&self, i: Int) -> Int` beside a place accessor `func [](&var self, i: Int) borrows -> &var Int`, is refused at `borrow var x = g[0]` as `subscript.role` ("`Grid` declares or derives no such role"), in either declaration order. SL:borrowing §5.1 says the spelling at the call site picks the role, and `Map` declares a getitem beside its place accessor.

**Mechanism:** the overload filter for a call (and the subscript role lookup) doesn't restrict its candidates to `borrows` members at a `borrow` head, nor to plain members at a value use. Since the redeclaration rule assumes both, every such pair is declarable and uncallable.

**Fix:** partition the candidates by position before ranking them, in the one overload funnel (a `borrow` head and a `for` head take `borrows` members; every other use takes plain ones), and do the same in the subscript role lookup. Pins: the three probes above as run programs. Stage 0 has no `borrow` block, so these are stated probes.

Related: SL-602 (a getitem's value-borrow positions refused as place uses) is a different position of the subscript role check.
