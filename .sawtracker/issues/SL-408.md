## Description

Both lexers accept numeric-literal spellings that GRAMMAR.md §2.1 does not allow: `sawc/lexer.py` and `compiler/lex` (sawc2), with identical tokens. GRAMMAR.md is authoritative for spelling, so this is a lexer defect.

SL-406.p3 records the first three rows in a §16 row (construct `syntax.expr.int, syntax.expr.float`, kind `defect`) and prints leaves as written. It changes neither lexer, because p3 rests on the two lexers giving identical tokens.

| source | lexed as | §2.1 |
|---|---|---|
| `2__u8`, `2___u8` | INT 2, suffix u8 | allows one optional `_` before the suffix |
| `1_`, `0xFF_`, `1_000_` | INT 1, 0xFF, 1000 | a trailing `_` separates nothing |
| `1.0_` | FLOAT 1.0 | FLOAT is digits, `.`, digits |
| `1_0.5` → 10.5, `1_.5` → 1.5, `1.0__5` → 1.05 | FLOAT | FLOAT has no `_` |
| `0x_FF` | INT 0xFF | `_` right after the base prefix |
| `1__000`, `0b1__0` | INT 1000, 0b10 | doubled separator |

`2u8_` lexes as INT `2` then IDENT `u8_`, so it is not accepted.

**To decide first.** The last three rows are not in the §16 row. For each, decide whether §2.1 refuses it, or whether §2.1's wording should allow it (a `_` inside a float, after a base prefix, doubled). This is a spelling ruling for the user.

**Then:**
- `compiler/lex` follows §2.1, and its golden token fixtures and the lexer-equivalence note change with it.
- `sawc/lexer.py` is frozen (python-compiler-frozen), so its behavior is recorded as a known disagreement, not fixed. Check the corpus for any tracked `.saw` file that uses one of these spellings.
- When sawc2's lexer changes, the §16 row goes.
