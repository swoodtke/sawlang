## Description

Both lexers accept numeric-literal spellings that GRAMMAR.md §2.1 does not allow: `sawc/lexer.py` and `compiler/lex` (sawc2), with identical tokens. GRAMMAR.md is authoritative for spelling, so this is a lexer defect.

SL-406.p3 records the first three rows in a §16 row (construct `syntax.expr.int, syntax.expr.float`, kind `defect`) and prints leaves as written. It changes neither lexer, because p3 rests on the two lexers giving identical tokens.

| source | lexed as | §2.1 |
|---|---|---|
| `2__u8`, `2___u8` | INT 2, suffix u8 | allows one optional `_` before the suffix |
| `1_`, `0xFF_`, `1_000_` | INT 1, 0xFF, 1000 | a trailing `_` separates nothing |
| `1.0_` | FLOAT 1.0 | FLOAT is digits, `.`, digits |
| `1_0.5` → 10.5, `1_.5` → 1.5, `1.0__5` → 1.05 | FLOAT | FLOAT has no `_` |
| `0x_FF` | INT 0xFF | `_` right after the base prefix |
| `1__000`, `0b1__0` | INT 1000, 0b10 | doubled separator |

`2u8_` lexes as INT `2` then IDENT `u8_`, so it is not accepted.

**To decide first.** The last three rows are not in the §16 row. For each, decide whether §2.1 refuses it, or whether §2.1's wording should allow it (a `_` inside a float, after a base prefix, doubled). This is a spelling ruling for the user.

**Then:**
- `compiler/lex` follows §2.1, and its golden token fixtures and the lexer-equivalence note change with it.
- `sawc/lexer.py` is frozen (python-compiler-frozen), so its behavior is recorded as a known disagreement, not fixed. Check the corpus for any tracked `.saw` file that uses one of these spellings.
- When sawc2's lexer changes, the §16 row goes.

User ruling (relayed by the lead, Sep 26): `1__000` and `0x_FF` are refused, and `1_0.5` is fine. The lead reads this as one rule: a `_` is a single separator between two digits, including inside a float's digit runs. §2.1's one optional `_` before a type suffix (`2_u8`) is unchanged. So `1_0.5` is accepted. Refused: `1__000`, `0b1__0`, `1.0__5` (doubled); `0x_FF` (after a base prefix); `1_`, `0xFF_`, `1_000_`, `1.0_`, `1_.5` (trailing, or beside the `.`); and `2__u8` (doubled before the suffix). This has two consequences. GRAMMAR.md §2.1 gets the wording for a separator inside a float. compiler/lex refuses the rest, and the frozen sawc/lexer.py keeps its §16 row.

## Lexer batch: the `compiler/lex` halves of SL-408 and SL-413 (brief)

One patch, filed on SL-408, closes SL-408's lexer half and SL-413. GRAMMAR.md is the authority. Its §2.1 and §2.7 text already carry both rulings (SL-416). This batch makes the self-hosted lexer (`compiler/lex`, package sawlex) follow them, and removes the §16 rows that record the disagreement.

`sawc/lexer.py` is frozen: do not touch it. Where sawc2 changes and sawc does not, the disagreement stays recorded for the Python lexer alone. Keep that row, but narrowed to `sawc/lexer.py`.

### Unit A: numbers (SL-408 c1, c3; GRAMMAR.md §2.1)
1. **A `_` is a single separator between two digits,** in an integer and in each digit run of a float.
   - **Refused:**
     - doubled: `1__000`, `0b1__0`, `1.0__5`;
     - right after a base prefix: `0x_FF`;
     - at the end: `1_`, `0xFF_`, `1_000_`, `1.0_`;
     - beside the point: `1_.5`;
     - more than one `_` before a width suffix: `2__u8`.
   - **Accepted:** `1_000`, `0xFF_FF`, `1_0.5` and `2_u8`.
2. **A base prefix is lowercase only:** `0XFF`, `0B1` and `0O7` are refused. The digits after a prefix are either case.
3. **The refusal is one lexical diagnostic at the offending character,** worded for the reader, with a hint where one is obvious (`1__000` → `1_000`, `0XFF` → `0xFF`).
   - Use the diagnostic id §2.1/§2.7 gives for it. If none fits, report which one you used and why, as a reversible reading.
4. **The tests that pin the old behaviour flip in this patch** (SL-408 c4):
   - `compiler/tests/lex/literals.saw`, the golden token fixture with `0XFf`;
   - `compiler/lex/tests/literals.saw`, with `lexed("42 0XFf …")`.
   - Keep a lowercase-prefix, mixed-case-digit spelling such as `0xFf` in their place.
5. **The parse corpus** (SL-408 c2):
   - `compiler/tests/parse/dump/leaves.saw` keeps `2_u8` and `1_0.5`, and drops `1_`, `0xFF_`, `2__u8` and `1.0_`. Regenerate its `.dump`.
   - `compiler/tests/parse/README.md`: its "Leaves" sentence about spellings "which the lexers accept" goes. Every spelling in the "owed a negative case" list (all 13) becomes a lexical negative case, and the list goes.
   - Record the expectations with the corpus tools (`cases.py --write`). Never write an expectation by hand.
6. **GRAMMAR.md §16:** the `syntax.expr.int, syntax.expr.float` row narrows to `sawc/lexer.py`, or goes if the table's convention is that sawc-only rows are not kept. Follow the table's existing practice for other rows with a sawc-only side, and say which it was.
7. **Corpus check:** grep the tracked `.saw` files for any of the now-refused spellings. The grammar corpus (`corpus_expected.tsv`) must not change verdicts silently. If a tracked file uses one, report it.

### Unit B: lexical diagnostics (SL-413; GRAMMAR.md §2.7)
1. **`syntax.lex.unterminated-string`** is reported at the opening quote, not at the end of input.
   - It is at the stray `{` instead when an interpolation inside the string holds an odd number of unescaped quotes outside comments.
   - Pin the C3 shape (SL-413 c1; SL:hazards C3) at the position §2.7 gives: `func main() { let s = "a {1 // comment: "`. Work out that position from §2.7's text and state it. Today sawlex says 1:26 and the §2.7 quote rule says 1:23; if the text does not decide between them, stop and report it.
2. **`syntax.lex.unclosed-bracket`** is reported at the opener for `(`, `[` and `{`, including a `{` whose function is followed by another `func`.
   - If bracket balance is not a lexer concern in sawlex today, say where the parser (`compiler/parse`) reports it, and keep this unit's change inside `compiler/lex`.
   - If the fix has to be in the parser, stop that item and report it: U4e is working in `compiler/parse` concurrently.
3. **`syntax.lex.float-point`:** `.5` is refused with a hint naming `0.5`, as `7.` is with `7.0`.
4. **Remove the three §16 `defect` rows** (unterminated-string, unclosed-bracket, float-point), or narrow each to `sawc/lexer.py` as in A6.
5. **The parse corpus's cases for these dropped their position** (SL-406.p4). Restore the position where the contract allows a lexical refusal to carry one, and say what the contract says.
