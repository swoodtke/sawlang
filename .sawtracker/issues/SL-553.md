Two findings from reviewing SL-553.p1 (Air). Neither blocks A2; both are about what happens when later units remove refusals.

**1. The copy-hook rule catches only an UNCONDITIONAL suspension.** It needs a per-instantiation half before A3b lowers frames. `check_copy_hooks` reads the summary's unconditional `suspends`. A generic `copy()` that suspends only at some instantiations, through a bound method rather than the type argument's own `copy()`, passes it:
```saw
struct Wrap<T: Worker> { n: Int, w: T }
extension Wrap<T: Worker>: ExplicitCopy {
    func copy(&self) -> Wrap<T> {
        let bump = self.w.step()          // Slow.step calls a blocking extern
        Wrap(n: self.n + bump, w: self.w)
    }
}
// main: let a = Wrap(n: 1, w: Slow(n: 2)); let b = a.copy()
```
- **Stage 0** refuses at the conformance, per instantiation: `cannot suspend in the \`ExplicitCopy\` \`copy()\` of \`Wrap\`: method \`Wrap.copy\` calls \`Slow.step\` → blocking extern \`usleep\``.
- **sawc2 with A2** reaches only A1's `coro.not-yet` (`Wrap.copy -> Slow.step -> usleep`).

That's a refusal today, but it stops being one when A3b gives ordinary items frames. Then a suspending copy hook builds, which is exactly what the rule exists to stop: an implicit copy in a `sync` body would suspend with nothing on the page. A1's solver already has the per-instantiation answer, so the natural home is coro, refusing a copy-policy `copy()` item that suspends with Stage 0's message. It should land before A3b, with this program as its pin. Probe: `.build/scratch/air-review/sl553/probe/cond_copy.saw` on the Air.

**2. For A3c, which settles the park operands (the lead's note):** `__saw_park_timer(nanos: Int)`, with `timer_nanos` saturating at `Int.max`, is unobservable only on a 64-bit target. On a 32-bit one, `Int.max` ns is about 2.1 s, so `sleep(Duration.seconds(5))` would silently return after 2.1 s. That's silent degradation, and kernels and embedded are first-class targets. Stage 0 has the same `Int` (`__saw_exec_sleep_ns(ns: Int)`), but the runtime seam under it is `__saw_rt_sleep_ns(ns: UInt64)`, so a `UInt64` operand costs nothing on 64-bit and closes it. sawc2 has no 32-bit target yet, so it's an A3c choice, not an A2 fix. The comment's 'no observer can tell the two apart' should say 64-bit either way.
