## Description

**`__saw_rt_pthread_mutex_init_default` / `_cond_init_default` classify `EAGAIN` as `WouldBlock`; it should be `Exhausted`** (the Air, SL-777 c5).

POSIX's `EAGAIN` from `pthread_mutex_init`/`pthread_cond_init` means "the system lacked the necessary resources (other than memory)". `pthread_status` (`runtime/common/pthread.saw`) classifies it through the shared, context-free classifier, so `Channel.recv`'s `Err(System(e))` reads `pthread_cond_init failed (would block)`. That is the misreport the lead's SL-768 c7 rule fixed for the spawn family: a seam classifies its errno in its OWN context, and `WouldBlock` invites a retry loop.

**Fix (body-only, both runtime trees byte for byte, no signature change):** the two init seams map `EAGAIN` to `Exhausted`, with the raw code still stamped (`SystemError.code` keeps 35/11). `runtime_table.py` must stay ok.

**Repro:** the Air's DYLD interposer (`air-review/sl777p/failinit.c`, `recv_system.saw`, `run_injected.py` on the Air) with `SAW_FAIL_ERRNO=35`. It can't be a gated pin unless the run lane gains an interposer facility, so the pin is the Air's repro run at review, or a std-lane program if `alloc_deny_after`-style injection reaches these seams.

Small and Sonnet-suitable. It may fold into SL-768 c2, which edits both runtime trees anyway.
