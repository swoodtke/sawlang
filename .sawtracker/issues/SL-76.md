## DF‑286b — A3's instance-check residue was measured on ONE program; the
## CORPUS's population is larger and different in kind (filed Sep 1 by design
## 218 unit 1.5 stage 3c's agent, STAGE 3c-2's BLOCKER)

MECHANISM (obligation 4). A3 ran `.build/scratch/probe_std_instance_check.py`
on `examples/hello.saw`, whose registry is std's TYPE CLOSURE and nothing
else — 295 (type instance, method) pairs, no entry-module generic at all.
Splice-all checks every registered instance of every program, so the
population that decides whether 3c-2 is green is the corpus's OWN generic
bodies plus std's closure at every type argument the corpus instantiates. That
population had never been measured. The instrument that could have measured it
(`SAWC_MONO_MEASURE=splice-all`) reports through a THROWAWAY reporter by
construction, which is what let a green suite coexist with unruled
diagnostics — the same property that hid this.

MEASURED (`.build/scratch/probe_corpus_instance_check.py`, the A3 probe with a
file glob; same materialization, LIVE reporter):

    files probed 122 (examples/*generic*.saw)
    files whose own compile needs a --module-path and was skipped   23
    files with instance diagnostics                                 14
    (type instance, method) pairs materialized                   36276
    diagnostics                                                    115

SIX classes, of which the stage-3c-1 sign-off covers TWO:

  1. `undefined variable N` (54, plus its "body has no value" cascades) — a
     CONST-generic parameter. See DF‑286c face 1.
  2. `method `Vector.len` is not declared `unsafe`, but its body names a value
     of unsafe type (`UnsafePointer<Int8>`)` and six siblings — design 130's
     trigger rule, run per instance over std's own safe methods because the
     TYPE ARGUMENT is unsafe. §1c says the trigger rule RUNS on instances;
     this is what that costs, and it is a RULING (either the rule reads the
     authored signature only, or std's containers owe an `unsafe` declaration
     at every method).
  3. `type `MapSlot<String, Cell>` is not Copy` — family 1's shape at a tier
     skip 3 does NOT cover (it covers the silent 'implicit' tier; this is a
     struct with no copy policy at all, reached through `Vector<MapSlot<…>>`).
  4. `type `Map<…>` has no method `_key_ref`: requires `V: ExplicitCopy`` —
     the conditional-conformance bounds filter. See DF‑286c face 3.
  5. `ambiguous Result auto-wrap: … `Result<Int, Int>` has the same Ok and Err
     type` — an authored form that is unambiguous abstractly and ambiguous at
     one instantiation. The §1c family design 151's and design 132's rows are
     in; a rule, not an artifact.
  6. `cannot return NoCopy type `Res` without `move` in function
     `run_and_return$1$Res`` — skip 4's mechanism at a position skip 4 does
     not reach: a RETURN, not a by-value parameter. Conformance row V47 pins
     this program as legal.

Classes 1 and 4 are DEFECTS and are DF‑286c's; 2, 3, 5 and 6 are §1c rulings
the lead's stage-3c sign-off does not cover ("exactly these three families
over exactly these 24"). The fence in the 3c dispatch fired here, which is
what it is for.

NOT COUNTED, so the real number is larger: method-GENERIC instances, which
`measure_splice_all` (and therefore this probe) does not materialize at all;
`examples/` outside the `*generic*` glob; `blade/`, `libs/`, `devtools/` and
`selfhost/`.

WHAT IT BLOCKS: stage 3c-2 in the shape A4 and the A5(b) OUTCOME give it.
Under splice-all every compile checks all of these, so each class has to be
FIXED or ruled before the cutover can be green anywhere. [218c A3, A4, A5(b)]
