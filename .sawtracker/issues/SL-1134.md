## Description

**A capturing closure called in place leaks its environment at `-O2`.** Found by the reviewer while probing SL-1124.p2 (Nov 14); not that patch's: main's compiler and the patched one alike. Reproduced by the lead on main (`.build/scratch/p1124u/leak/closure_in_place.saw` in the lead's checkout):

```saw
func make() -> String {
    var b = StringBuilder()
    try! b.append("a string long enough to live on the heap, not inline")
    b.build()
}

func main() {
    let w = make()
    let r = { [w] in w }()
    print(r.len())
}
```

`leaks --atExit` on the built program: **0 leaks at `-O0`; 2 leaks for 112 total leaked bytes at `-O2`.** It prints 52 at both. The reviewer's form (`let r = { [w] in w }()` with `w` a `String`) reported 2 leaks of 32 bytes.

**Not known yet (the sweep the fix owes, obligation 4):** which two allocations (the environment and the captured `String`'s buffer, or the returned copy); whether `-O1`, `-Os` leak; whether it is the in-place call (a closure literal as a callee, never bound) or any capturing closure whose only use is one call; whether a closure bound first (`let f = { [w] in w }; f()`) leaks; other captured types (a `Vector`, a `Box`, a `NoCopy` value moved in); a closure that does not return its capture; and what differs between the `-O0` and `-O2` paths (a release the optimizer's pipeline loses, or a different lowering chosen by the driver at `-O2`, such as an environment the compiler keeps on the stack at one level and the heap at the other). The ownership oracle (`tools/gmgate.py`) runs programs at one setting: say which, and why it does not see this.

**Why it matters:** a leak in safe code that only an optimized build has, so no `-O0` test or oracle run catches it.

Related: SL-1124 (found during its review).

**The sweep is done, and the defect is wider than the title (lead, Nov 14; a read-only Sonnet sweep, condensed by the lead; every figure has a file under `.build/scratch/p1134s/` in the lead's checkout). Then the implementation detail.**

**What it is.** Every capturing closure LITERAL used as the callee of a call (`{ [w] in ... }()`, never bound) leaks its heap environment and never releases its captures, **at every optimization level**. A `NoCopy` capture's `deinit` never runs. sawc 0.24.1 at 4b7873728.
- **Not the optimizer.** sawc's own IR (`--emit-ll`) is the same at `-O0` and `-O2` but for the speed line and debug flags; `sawc mir --dump` already lacks the drop: `_6 = closure#0 of main() [move _5]; _7 = call value move _6 [] -> ...`, and the scope's exit drops `_3` and `_1` only.
- **`-O0` leaks too:** a one-shot run under `leaks` shows 0 there (why is not established: something keeps the block reachable), but a loop of 1,000 calls leaks 2,000 blocks (112,000 bytes) at `-O0` and `-O2` alike, and a `NoCopy` capture with a printing `deinit` prints nothing at either.
- **What leaks:** the environment block (16 bytes asked, refcount 1), and with it whatever it holds: a `String`'s or `Vector`'s buffer, a `Box`, a `NoCopy` value held inline (never destroyed). Per call: 1 block for `Int` captures, 2 for a `String`, 3 for two.
- **Every in-place form leaks:** returning the capture, computing from it, a void body, a body that never mentions the capture, with arguments (`{ [n] x: Int in x + n }(4)`), in parentheses (`({..})()`), `[w]`, `[move w]`, an implicit capture (`{ w.len() }()`), nested in another in-place call (3 blocks), and inside a bound outer closure's body.
- **These do not leak (controls):** a closure bound first (`let f = {..}; f()`), called twice, passed to a function, stored in a struct field; a call's result called (`mk()()`); `(if c {..} else {..})()`; a closure taken out of a `Vector`; a non-capturing literal called in place; a capturing closure never called; `Thread.spawn { [w] in .. }`; `Task.spawn(work(w))`.
- **Why nothing saw it:** no tracked `.saw` calls a capturing closure literal in place. The ownership oracle (`tools/gmgate.py`) sees faults and output, never leaks; the run lane's `// leaks: none` probes run at `-O0` and `-O2` and none has this shape.

**The mechanism (from the dumps and the code; UNVERIFIED by a patched build, which the sweep could not make).**
1. Typecheck gives every value-call's callee the use `Borrow` (`compiler/typecheck/src/bodies.saw`, where a call's head is typed).
2. A closure literal lowers to an OPERAND, `move _6` of a fresh temporary (`closure()` in `compiler/mir/src/lower.saw`).
3. `transfer` (same file) has a rule for exactly this, "a position that borrows takes no ownership, so an owned temporary it reads is the statement's to drop": `u == Borrow && self.borrows_owned_temporary(v.operand)`. But `borrows_owned_temporary` excludes a function value (`kind != TcKind.Func`), so the operand goes through as the move.
4. `emit_call` (`compiler/mir/src/build.saw`) relinquishes a moved operand's hand-off entry ("the instruction owns the value now"), and a value call does not own its callee (`compiler/llvm/src/calls.saw`: "the callee is read where it lives, never copied"). So nothing ever drops the temporary.
- The forms that work reach the callee as a PLACE (a binding; a call's result, which `transfer` owns with `own_temp` and reads with `borrowed_value`: `call value copy _2` and `drop(_2)`).

**The fix (the candidate; step 1 of the unit proves or refutes it).** A function value with an environment IS an owning value, so `borrows_owned_temporary` must not exclude it: a fresh closure temporary read under `Borrow` becomes the statement's to drop and the call reads it in place, as `mk()()` does today. Expected MIR after: `_7 = call value copy _6 [] -> ...` with `drop(_6)` at the statement's end.
- **First find out why the exclusion is there** (`git log -S'TcKind.Func' -- compiler/mir/src/lower.saw`, the commit's message and the test it added; and the sibling exclusion in `borrowed_value`'s comment, "a function value is copied"). If it guards a case (a plain function's name as a value, which owns nothing; a function value under a builtin operator or a format argument), the fix keeps that case: the rule is "a function value that owns" (`self.owns(ty)` already says whether a type owns: check what it answers for a function type with and without `sendable`, and for a function reference), not "any function value".
- If removing the exclusion double-drops, or changes any existing MIR golden beyond adding the missing drop, STOP with the diff: the mechanism is then not this, or not only this.

**Obligation 4, the class: an owned temporary read by a position that borrows.** The sweep covered the callee. The unit's matrix covers every position that gives `Borrow` (or `want_ref`) to an expression that can be a fresh closure literal or another owning function-typed temporary, each as a program under `leaks` in a 1,000-iteration loop AND with a `NoCopy` capture's printing `deinit`:
- the callee (the forms above);
- an argument to a `&` parameter of function type (`apply(&{ [w] in w.len() })`) and to a by-value one (a control);
- a method call's receiver where the receiver is a closure-typed temporary, if the language has any such method (say if none);
- the operand of `==`/`!=` or any builtin operator that admits a function value (say if none does);
