## Description

**Typecheck, borrowck and the MIR and drops verifiers are superlinear in the size of one constructor call or one function.** Found by SL-955 unit 4b's diagnosis (`.build/scratch/p955j/probe_long_function.py`). Generated code with a 454-field struct took sawmono's layer from 169 ms to 2848 ms.

**Evidence** (both main's compiler and unit 4b's):
- **Typecheck** of one constructor call with N arguments: 52, 131, 700 and 4871 ms at N = 100, 200, 400 and 800, roughly N^2.8.
- **A function of N statements** costs about 2.5× more per doubling of N in borrowck, verify mir and verify drops. At N = 800, borrowck alone takes 206 ms.

**Direction (obligation 4):** for each stage, find the per-argument or per-statement work that rescans the whole call or function: a linear search over arguments or labels, a per-statement walk of all locals, a verifier that re-checks every earlier statement. Fix it to near-linear. Pin it with a timing-free complexity check: a work counter, or a ratio test between N and 2N in a lane that tolerates load.

**Air: SL-970.p1, changes requested, for one row of the complexity lane: `ctor` fails at random on about half the runs here.** The state store itself is right, and I'd approve it as it stands.

**The change: the `ctor` row is flaky.**
- **20 runs of the lane** on the patched compiler, on the Air (macOS 27.2, toolchain rebuilt today): **9 fail, every one on `ctor`**. Its r ranges over 6.720–7.024, median 6.854, and the row allows 6.80 + 0.1 = 6.90. On main's compiler, `ctor` measures 6.840–6.846 over 3 runs.
  - The other rows are steady: spreads 0.005–0.019, and 0.068 for `yields`.
- **Where the noise is:** the build at N = 200, the denominator. Over six sequential runs with nothing else running, the patched binary's `ctor_200` build varies by 1.09% in instructions retired; main's varies by 0.21%. It isn't the new analysis doing variable work: `sawc typecheck --check` alone, which runs before any of the code this patch touches, varies 1.22% on the patched binary and 0.06% on main's. So the build's instruction count moves with the binary, and at N = 200, where typecheck's cubic binding dominates, a 1% move in I(N) is about ±0.15 in r. That's well past `NOISE` (0.03) and `SLACK` (0.1).
- **Taking the minimum doesn't fix it:** the minimum of 3 builds per size gives r = 6.73–6.93 over 5 trials, so the noise isn't one-sided.
- **What I'd do:** take `ctor`'s ceiling from the worst of several runs rather than one, or leave the row out until T1 makes the shape near-linear and the noise small next to it. Either way, the lane's NOISE should be measured per row (or `--write` should run K times), not assumed. run.py runs this step on every patch, so a coin-flip row would fail unrelated gates.
