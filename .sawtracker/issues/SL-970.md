## Description

**Typecheck, borrowck and the MIR and drops verifiers are superlinear in the size of one constructor call or one function.** Found by SL-955 unit 4b's diagnosis (`.build/scratch/p955j/probe_long_function.py`). Generated code with a 454-field struct took sawmono's layer from 169 ms to 2848 ms.

**Evidence** (both main's compiler and unit 4b's):
- **Typecheck** of one constructor call with N arguments: 52, 131, 700 and 4871 ms at N = 100, 200, 400 and 800, roughly N^2.8.
- **A function of N statements** costs about 2.5× more per doubling of N in borrowck, verify mir and verify drops. At N = 800, borrowck alone takes 206 ms.

**Direction (obligation 4):** for each stage, find the per-argument or per-statement work that rescans the whole call or function: a linear search over arguments or labels, a per-statement walk of all locals, a verifier that re-checks every earlier statement. Fix it to near-linear. Pin it with a timing-free complexity check: a work counter, or a ratio test between N and 2N in a lane that tolerates load.

**SL-970 step 1 (census, read-only).** Evidence is in `.build/scratch/p970/`: `table.md`, the curves, the samples, and `prototype.diff`, 25 files uncommitted in `.claude/worktrees/p970`. **The worst cells** (N = 1,600, before → after):

| shape | stage | before | after |
|---|---|---:|---:|
| constructor with N labelled arguments | typecheck | N^2.91, 42,227 ms | N^0.78, 10 ms |
| N calls | the borrowck and verifier steps | N^1.8–2.0 | about N^1 |
| N calls | total | 2,054 ms | 117 ms |
| N suspension points | coro lower | N^2.85, 4,628 ms | N^2.02, 110 ms |
| N suspension points | verify coro | N^2.72, 7,388 ms | N^1.97, 280 ms |
| `match` with N literal arms | mir | N^1.99 | N^1.85 |

**Mechanisms**, each with file:function and its prototype fix in the evidence:
- **A list rebuilt or searched per element:**
  - T1 `bind_args` rebuilds `struct_fields` per label (N³);
  - L1 `place_prefix_addr` rebuilds the field list per projection;
  - R1 `find_local` and `find_value_here` scan the live locals;
  - M2 `relinquish_operands`/`newest_entry`;
  - B1 `instruction_stmt`/`instruction_count`;
  - C3 `coro_verify_places` dedupes linearly.
- **Whole-function scans per element:**
  - B2 `step_forward`;
  - B3 `check_access`;
  - B4 `loan_holders`, `used_by_closure`, `passed_to_call`, `loan_ties`, `receiver_open`;
  - B6 `check_call_sets` pairwise;
  - B7 `check_assignment` walks the function twice;
  - M3 `call_arguments` asks `is_pure` of each later argument.
- **M1, a dense blocks × paths table** in `init_analysis`, used by five clients: MIR verify, borrowck check, borrowck verify, drops elaborate and drops verify. `refined_entries` keeps a second copy, and B5 keeps loan bitsets per block and per instruction. Prototype: persistent arena trees with structural sharing (a new `mir/src/states.saw`) and a `MirCursor`.
- **Pairwise:**
  - T2 `check_duplicate_arms`;
  - M4 `compile_rows`/`split_test`, still quadratic after the prototype;
  - C1 `coro_interference` (cubic) and `coro_first_fit`;
  - C2 `coro_verify_lifetimes` (cubic).
- **Hashing and text positions:**
  - L2: debug-location keys put the line in bits 20–39, which std's `Hasher` (FNV with an xor-fold) spreads badly;
  - L3: `position_text` walks from the line start for the column.

**Other findings:**
- **Crash on main:** a `match` with 6,400 literal arms segfaults `sawc mir`, because the decision tree recurses one frame per arm. The prototype loops instead.
- **std's `Hasher`:** `Int` keys that differ only in high bits probe in long runs. The spec says iteration order is unspecified, but a hasher change reorders iteration and moves corpus verdicts. That decision is the user's.
- **Small programs:** the prototype costs a trivial program about +5%, because std's small functions pay the new setup. The plan keeps a dense path for small functions.

**Plan (lead), one patch per unit:**
1. M1 shared states plus the complexity lane: a per-shape ceiling on the instruction-count ratio between 2N and N, lowered by each later unit.
2. borrowck B1–B7.
3. MIR lowering M2–M4, which fixes the crash.
4. coro C1–C3 and sparse lifetimes.
5. llvm L1–L3, resolve R1 and typecheck T1/T2, after SL-955 4b, which edits the same program structs.
