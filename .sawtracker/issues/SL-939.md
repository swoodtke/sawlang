## Description

**The executor's park words encode an address by negating it, which breaks on a 32-bit target whose memory lies above 2^31.**

**Found by** SL-933's `cooperative_deadlock` case on riscv32 (QEMU virt, RAM at 0x8000_0000). It panics with:

```
panic at taskgroup.saw:2263: executor: a task recorded park word 2146893788, which names no park
```

**Mechanism:**
- `Channel.park_word` is `0 - address of the ready word`. The park-word vocabulary reads a NEGATIVE word as "parked on this address" and a positive one above `PARK_TIMER` as no park (`Unknown`).
- On riscv32, `Int` is 32 bits, so every address at or above 0x8000_0000 is already negative, and negating it gives a positive word. Here 2^32 − 2146893788 = 0x8009_0024, an address in fsrt's arena.
- Hosted 64-bit targets are unaffected, since user-space addresses are below 2^63.

**Siblings (obligation 4; read from the code, UNVERIFIED until probed):**
- `__saw_exec_join_park` (`0 - word - 1`)
- `__saw_exec_offload_park` (`0 - job - 2`)
- `drive_until_set` (`0 - word`)

Each uses the same negated-address encoding. So on such a target every channel, join and offload park would mis-decode. That includes the sawos riscv32 and any 32-bit board with high RAM.

**Fix direction (for the brief):** an encoding that doesn't assume addresses fit in w−1 bits. For example, tag the low bits of a word-aligned address, or keep the reason and the address in separate fields. It goes through one encode/decode funnel with its ENTRY POINTS named.

**Pins:**
- SL-933's `cooperative_deadlock` riscv32 row, `due` on this issue until it lands.
- A riscv32 join-park case and a channel-park case in the freestanding suite.
- The hosted run lane's executor probes unchanged.

**Lead decision on the encoding (Oct 30), after p939's census** (`.build/scratch/p939/census.md`). The compiler writes ready 0, timer 1 and descriptor -1 itself, and the host reactors and runtime/ABI.md freeze descriptor at -1 (the -1→0 CAS), so those three stay. An address-carrying park becomes `address | tag`, with the raw address bits and tag channel 0, join 1, offload 2. Tag 3 and the null address are reserved for the constants, and unset moves from Int.min to 3: on riscv32 Int.min is 0x8000_0000, a valid channel word. Decoding matches the constants exactly, then splits on the low two bits (tag 3 or a null address is Unknown). No ordering test on a park word remains, so the encoding holds on any width and address range. There is no compiler or ABI change.

<!-- sawtracker:comment {"author":"agent:claude-sawlang","body_bytes":855,"created":"1793370716","id":"c2"} -->
**Lead decision (Oct 30): the encoding's limit is accepted.** Under the sign-free encoding, an aligned non-null word is read as an address, so the executor refuses only a word with tag 3 or a null address. It can't validate arbitrary words the way the sign-based encoding refused every positive word above 1. A bogus park word can only come from a compiler or std bug, never from user code, so this costs a weaker internal check, not soundness. `drive_timer_park`'s pin moves from 1000000 to 1000003 (tag 3), and the vocabulary comment states the limit. Before the fix, riscv32 mis-decoded a channel park in a task, a drive point on a channel park, and the deadlock case. After it, all of them pass on both arches. Join, `drive_until_set` and offload parks can't be reached under fsrt (the thread seams, the gate seams, and the profile's offload refusal).
