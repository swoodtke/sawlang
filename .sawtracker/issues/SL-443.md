## Description

These are design inputs for unit 5, the new std seeded in the bootstrap language. They come from U5a's std cone (SL-441; `compiler/tools/std_cone_review.md`). None is a defect in `sawc/std`, which is frozen. Each is a shape the new std should not carry into the bootstrap cone.

1. **The panic seam pulls in the task executor.** Every panic, bounds check or overflow check reaches `__saw_bt_panic`. That brings 44 `std.taskgroup` declarations into the cone of a sync-only compiler, plus `TaskGroup`, `VoidThread`, `Box<any Resumable>` and Atomic statics. At run time the backtrace walk finds no groups and falls straight through to `__saw_rt_panic`.
   - **Target:** the new std's panic path doesn't depend on the executor. Backtraces through tasks are an optional layer that only a program using tasks links in.
   - **How to see it:** `std_cone.py --why __saw_bt_panic`.
2. **`Data` writes through `Arc.with_unique`.** `File.read` returns `Data`, and each byte `push` goes through a closure passed to `Arc.with_unique`. SL:borrowing retires that in favour of the conditional lend `arc.unique()` (§2.4).
   - **Target:** the new std's `Data` uses `unique()`, or a representation that needs no Arc for a freshly read file.
3. **`std.net` comes along with `std.file`.** It arrives through `IoError`, and brings the runtime's errno table and a pthread-keyed slot with it.
   - **Target:** the file and path error types don't pull in the network module. Possibly they share a small error module.

**How to apply this:** each new-std module seeded for the cone is checked against this list. The cone lane (`std_cone.py`) then shows each input as a change in the recorded cone.

Also a small tooling nit from the Air's review of SL-441.p1. The cone lane's detail lines come from a set difference (diff_lines in std_cone.py). So a change to a line that repeats in the file, such as an instance line under every Vector method or extern memcpy under three modules, prints only the generic 'differs'. A positional diff (difflib) would name the declaration the change sits under. Do it whenever std_cone.py is next touched.

<!-- sawtracker:comment {"author":"agent:claude-sawlang","body_bytes":510,"created":"1790760000","id":"c2"} -->
A fourth new-std input, from U6a (SL-445.p1): Stage 0 lets imports reach std FUNCTIONS whatever their visibility, and hides only private types. sawc2 resolve applies design 204 and refuses them. Affected: std.net's net_buffer, tcp_close and others; std.slab's slab_alloc and slab_dealloc, which the saw-lang skill lists as importable; std.time's unix_timestamp (compare SL-397). The new std decides, per function, whether it is public API (then mark it public) or internal (then its callers stop importing it).

<!-- sawtracker:comment {"author":"agent:claude-sawlang","body_bytes":363,"created":"1790769485","id":"c3"} -->
A fifth new-std input, from U6b1 (SL-447.p1): resolve lets a sawc/std module see the gated std tier bare, because sawc/std is written for the frozen compiler's single std namespace (std/file.saw names Path and IoError without importing them). The new std writes its imports like any module, and resolve's ResModuleKind.Std exception in lookup.saw is then deleted.

<!-- sawtracker:comment {"author":"agent:claude-sawlang","body_bytes":638,"created":"1791656646","id":"c4"} -->
From U5b3 (SL-456.p3): inputs 1 (an executor-free panic path, U5b2), 2 (Data without `with_unique`: one refcounted block, no Arc) and 3 (file errors without `std.net`: `std.systemerror`) are met in the new std. The new-std cone of sawc2 has no `std.task*` or `std.net`. One residue, outside std: in a hosted link, the frozen runtime's `rt_fs_open` and `rt_fs_read` bodies call `rt_last_syserror`, which reads the errno table and stores into the pthread-keyed slot. So `net_os` still links, although std never reads the slot. Removing it needs a runtime change, which belongs to the runtime work once sawc2 builds its own runtime objects.


<!-- sawtracker:comment {"author":"agent:claude-sawlang","body_bytes":601,"created":"1791657895","id":"c5","kind":"landing"} -->
**All three inputs are met in the new std.** (1) The panic path doesn't reach the executor (U5b2's `std/panic.saw`). (2) `Data` is one refcounted block with no Arc and no `with_unique`. (3) File errors are `std.systemerror`, so `std.net` stays out. sawc2's new-std cone (`compiler/tests/std/cone/sawc2.cone`) has no `std.task*`, `std.net` or `rt.*`. The runtime residue (the frozen `rt_fs_*` bodies reach `rt_last_syserror`) is noted in c-latest and belongs to the runtime work.

Landed in SL-456.p3, merged as 8f47c495 after the Air approved it, with the gate passing on the applied commit 0e58a9b3.
