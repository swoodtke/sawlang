**A3. Patterns are compared by value, never by spelling** (SL-606, bucket A). Findings: MIR 2 (a miscompile), Typecheck-decl 6 and MIR 3.

- **Mechanism:**
  - `same_pattern` (`mir/src/lower.saw`) compares literal SOURCE TEXT, so in `case 0x10 if c -> 1, case 16 -> 2` the guard's false edge skips the `case 16` row. The same goes for `-1` against `- 1`, digit separators and string escapes.
  - Typecheck never detects duplicate arms (no `match.duplicate` rule), and it accepts two raw-backed cases sharing one value. The fold, the evaluator and the run time then give three different answers for `E.A == E.B`.
- **Fix:**
  - compare literal patterns by their evaluated value (the fold already has it);
  - add `match.duplicate`, worded as Stage 0 words it;
  - refuse duplicate raw values (spec rule 2 for raw-backed enums);
  - give the evaluator one equality rule for cases.
- **Pins:** the review's `review_mir_lit` and `review_eval_dup` probes, plus a row for each spelling pair. Duplicate-arm refusals use Stage 0's two shapes (`case 1` twice; `case Move(x, y)` against `case Move(a, b)`).
- **Done when:** sawc2 agrees with Stage 0 on every probe, and the eval-agreement lane carries a raw-backed case.

Approving SL-609.p1 (A3): literal patterns are compared by value, never by spelling, with duplicate arms and duplicate raw values refused. Exact tree on a853ae599: cbd40963. I built Stage 2 with the patch.

**The miscompile class, probed beyond the patch's own pairs.** `sl609/spelling_guards.saw` has five matches. Each has a first arm guarded by `false` and a second arm that should match the same value spelled differently:
- a typed suffix, `16u8` against `0x10`;
- a Unicode escape, `"\u{41}"` against `"A"`;
- inside a tuple, `(0x10, true)` against `(16, true)`;
- inside an Optional payload, `Some(0b1_0000)` against `Some(16)`;
- the Int8 minimum, `-0x80` against `-128`.

| compiler | byte | string | tuple | optional | min |
|---|---|---|---|---|---|
| main's sawc2 | 3 | 3 | 3 | 3 | 3 |
| the patch, -O0 and -O2 | 2 | 2 | 2 | 2 | 2 |
| Stage 0 | 2 | 2 | 2 | 2 | 2 |

On main every case skips its matching arm. That's the review's MIR 2, and it reaches nested patterns and every literal kind, not just the reported `0x10`/`16`. The patch fixes all five and agrees with Stage 0.

**`split_test` is conservative where it must be.** `tc_same_test` answers Same, Different or Unknown:
- Same settles the row on the true edge;
- Different sends it to the false edge (a `Bool` literal settled there);
- Unknown, a range or an untested place, sends the row down BOTH edges.

So a literal the value rule can't read never sends a row past an arm that matches. The text-comparing `same_pattern` is gone, with no other caller left.

**The refusals** (`match.duplicate`, worded as Stage 0 words it, with guards and ranges exempt; `type.raw-value` for a missing or duplicate raw value; `type.mismatch` for a literal that doesn't fit the matched type) are pinned by 14 fixtures. The evaluator now compares raw-backed cases by raw value. The `raw_value_node` sibling fix, a documented case's doc comment returned as its value, is a good catch.

**Per-file checks** on the 22 `.saw` files: grammar corpus ok (22 accepted), astdiff OK.
