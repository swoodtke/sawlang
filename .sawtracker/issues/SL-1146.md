## Description

**On windowed Xtensa a frame over 32,760 bytes still prologues with `movsp`, which raises the Alloca exception the freestanding suite's start-up does not handle.** Reported by the sawos lead (Nov 15, chat m1061, from SO-126): with SL-1133 (no frame pointer for windowed Xtensa) every ordinary function has no `movsp`, but `entry`'s immediate holds at most 32,760 bytes, so a larger frame is set up with `movsp`, as before. The sawos kernel handles the Alloca exception; the suite's `hal/xtensa-windowed/boot.S` treats it as fatal, and no case has a frame that large.

**To do (low; nothing reaches it yet):** a case in the windowed row with a frame over 32,760 bytes (a large local array) to show what happens; then either an Alloca handler in the suite's windowed start-up (the ISA's sequence, written as the window vectors were) or a refusal/diagnostic from sawc for such a frame on windowed Xtensa. Also from the same report: sawc emits only `callx8` on this target, so the 4- and 12-register window vectors are reached only by hand-written code (as the SL-1128 review found).

Related: SL-1133, SL-1128, SO-126.
