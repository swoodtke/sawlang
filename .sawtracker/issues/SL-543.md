**Ruled by the user (Oct 12): Q-shiftcount (b).** See SL:open-questions, "Q-shiftcount" under Resolved: a run-time fault that is CERTAIN because an operand is constant is a compile error.

**Scope:**
- **Shifts:** a count that is constant BEFORE generic instantiation (a literal, a `static`, a constant expression over those) and out of range for the shifted type is refused as `constant.shift-range`, beside a run-time left operand. This covers the binary shifts and the compound `<<=`/`>>=`.
- **Division:** a divisor that is constant zero in the same sense, for `/`, `%`, `/=` and `%=`, is refused as `constant.divide-by-zero`.
- **NOT refused:** a count or divisor that is constant only per instantiation of a const generic (the Air's `func top_bit<const N: Int>(x: Int, …) { if N > 0 { x << (N - 1) } else { x } }` stays ACCEPTED and runs, printing `1 8` for `[0; 0]` and `[0; 4]`).
- **Regardless of reachability:** `if false { x << 64 }` is refused (the lead's scope; no flow analysis).

**Work:**
1. **Spec:** extend the paragraph "The faults a run-time operation would panic with are compile errors in a constant" to say that such an operation is also a compile error when the operand that makes it fault is constant before instantiation, whatever the other operand is. Name the generic exception, with the guarded example as a compiled block that runs. `docverify` applies.
2. **Typecheck:** fe3's first SL-514 attempt had the refusal for shifts (`shift_count` folding a constant count wherever the whole shift isn't constant); it was removed pending this ruling. Restore that shape, extend it to divisors, and exclude const-generic dependence. The test is whether the folded operand mentions a type or const parameter.
3. **Pins:**
   - refusals for a binary shift, a compound shift, `x / 0`, `x % 0`, `x /= 0`, `if false { x << 64 }`, a `static` count, and a constant-expression count;
   - ACCEPTED controls: the guarded const-generic shift (a run-lane program, matching Stage 0's `1 8`), a run-time count, and a run-time divisor;
