Found by the Air (SL-596 c20). `compiler/resolve/src/prelude.saw` lists `Serialize`, `Deserialize`, `Encoder`, `Decoder`, `DecodeError`, `DecodeFault`, `EncodeError` and `EncodeFault` as prelude names of `std.serde`. That module doesn't exist, so resolve drops the entries: a program gets `name.undefined` / `name.not-in-prelude` / `import.unknown-module`. But SL-878's `prelude_doc` step reads the prelude's TEXT, so it counts them as prelude and agrees with the spec's 'yes' row. **Guard:** the step requires each non-`builtin` prelude module to exist as a file under `std/`. A module that is absent on purpose (pending a port) is allowed only when the spec's row carries a pending mark citing an OPEN issue (SL-886's `pending SL-596`), and the step checks that the issue is open, as docverify's `saw-pending` does. Today that flags exactly `std.serde`. Run it as part of the `prelude_doc` step, with a fixture.
