**Downcasting an erased box, `b.is<T>()` and `b.take<T>()`, is refused as `slice.not-yet`** ("downcasting an erased box with `is` or `take` is not in the bootstrap slice yet"). After SL-721 it is the first refusal of 7 corpus programs: `erased_downcast_deinit_once`, `erased_downcast_error_retry`, `erased_downcast_generic`, `erased_downcast_is_take`, `erased_downcast_nonconforming_error`, `erased_downcast_use_after_take_error`, `erased_error_spawned_container_result` (gmgate's blocked twin).

**What SL-721 leaves in place:** the vtable header's `type_id` word is the concrete type's interned type (`compiler/llvm/src/erased.saw`, `vtable`), one per type in a program, so `is<T>()` is a compare of that word against `T`'s; a box's payload address is the fat pointer's first word, its size and alignment the vtable's, and its allocator's `dealloc` is mono's `erased_dealloc` item.

**The spec** (`any Trait` existentials, "Downcasting (v1)"): `is<T>()` borrows; `take<T>()` consumes the box either way, moving the payload out on a match (freeing the shell without its deinit) and dropping it on a miss; `T` explicit, concrete and conforming.

**Pins:** the corpus programs above, a run program per outcome (hit, miss, the payload's deinit once on each path), the nonconforming and use-after-take refusals, and the corpusdiff baseline; gmgate's twin moves when it builds.

**Implementation detail (lead, Nov 12; a stretch item this week): a design pass (Opus) first, because the type-identity mechanism is a representation choice that SL-680's error union shares.**

**The gap.** `b.is<T>()` and `b.take<T>()` on an erased box are refused in typecheck (`compiler/typecheck/src/bodies.saw`, `self.not_yet(e, "downcasting an erased box with `is` or `take`")`); seven corpus programs are refused on it. This is how a caller recovers a concrete error from `Result<T, Box<any Error>>`, the erased-error idiom the README advertises.

**What is ruled already.**
- Erased-error downcasting exists in the language with a type-id mechanism (SL-200: "Erased-error downcasting is already implemented. Only the deferred catch-side syntax remains; preserve the existing type-id mechanism", written of Stage 0).
- The user's Oct 16 rulings on SL-680 (the closed error union): a caught union erased into `Box<any Error>` is erased as its ACTIVE MEMBER, so after `return error` the caller's `err.is<ParseError>()` answers true when a `ParseError` was raised. Whichever of SL-680 and this issue lands second owes that pin (the Air's c2 here).
- The user's Oct 16 ruling on SL-721 / SL-764: no method forwarding through any `Box`, an erased one included.

**The design must settle:**
1. **Type identity at run time:** what an erased box carries that names its concrete type (a pointer to a per-type descriptor in the vtable, the vtable's own address, a hash), given that type identity is (defining module, name) plus generic arguments; what guarantees two instantiations of one type compare equal across modules and codegen units (the split's `linkonce_odr hidden` copies: one address per program or not?), and under the front cache's layers.
2. **`is<T>()`:** the comparison; `T` must be a concrete type that conforms to the box's trait (refused otherwise: which rule); a generic `T` inside a generic function (per instantiation).
3. **`take<T>()`:** its signature per the spec (consumes the box and gives `T?`, or a `Result` handing the box back on a miss? quote the spec), the ownership on each path (hit: the payload moves out and the allocation is freed with the box's allocator; miss: the box survives), `NoCopy` payloads, a payload with a `deinit`, zero-size payloads, allocator-parameterized boxes.
4. **Stages:** typecheck's typing of the two calls; MIR's representation (a new rvalue or a call to a lang item in `std/box.saw`); mono's instantiation of the descriptor; the backend's emission; freestanding (no allocation beyond the box's own free).
5. **What Stage 0's seven programs expect**, as the acceptance set, each with the cells it covers.

**Census first** (`.build/scratch/p745d/` of the main checkout): the seven programs; `std/box.saw`'s erased-box surface today; how the vtable of an `any Trait` is emitted (`compiler/llvm/src/`, `compiler/mono/src/`) and whether anything in it is already unique per concrete type.

**Deliverable:** one comment here with the mechanism, the position and ownership matrix with fixtures and run pins (each run under `--sanitize address` and in gmgate, since `take` moves ownership), the SL-680 cross-pin, the open questions for the user, and the cut into Sonnet units.
