## Description

Found by the SL-357 comment-review agent on Sep 24 while reading std/taskgroup.saw and the reactors against the code. These are SOURCE-READING candidates: none has been reproduced. Under the Python-compiler freeze they're recorded for the hazards ledger. Note that std/rt are Saw code the self-hosted compiler will reuse, so they matter beyond the freeze.

1. **Unlocked generation read (handle aliasing):** the synthesized spawn helper reads `__gen_at` right after `__enqueue`, without the run-queue lock. In an MT group a worker can finish and recycle a Void task's slot in that window, so the handle may carry the retired generation and later name a successor task that reuses the slot. Check: does handle validation then accept the wrong task?
2. **Missed cancel:** a `cancel_addr` write from another thread isn't seen by an ambient sweep that is already blocked in `poll(-1)`. Nothing wakes the poll for a cancel.
3. **Quiescence, false deadlock:** a detached thread stops counting toward the quiescent report, so a detached thread that will still send on a channel can make a live program be reported as deadlocked. Groups beyond `BT_MAX_GROUPS` aren't walked by the report either.
4. **Ambient list:** it is linked and unlinked without synchronization, assuming one owner thread. Check whether any path (a Thread.spawn body running ambient tasks?) breaks that.

Each item needs a reproduction (for the concurrency ones, an oversubscribed or instrumented program in the SL-353 style) before it's classified as a real hazard, a fix candidate, or not reachable.

Additional SOURCE-ONLY candidate from the SL-357.p4 review (not reproduced; no unsafe pointer access performed): cancel_addr after slot recycling.

Exact reviewed tree a74c8f4ff577f26359bcab5928979b8c8d65cd4c. std/taskgroup.saw:1042-1046 __pin silently returns for a stale generation. Task.cancel_addr:1873-1875 and VoidTask.cancel_addr:1976-1978 nevertheless return the handle's stored cancel_ptr. Task.join:1800-1802 recycles the slot after taking the result; __recycle:1028-1037 advances the generation and drops an unpinned cell. Because join takes &self, the stale handle is still callable. A later cancel_addr therefore appears able to return a pointer to the released cell without establishing a pin. Void completion can also recycle its slot.

This is distinct from the four existing SL-392 candidates. The public group-lifetime/address-pinning promise needs a live-generation precondition or explicit hazard qualification in the allowed documentation wave. No runtime change requested under the freeze. A safe later discriminator could observe count before/after calling cancel_addr on a joined handle WITHOUT dereferencing the returned pointer; a stale-pointer write or crash is unnecessary. This report is source evidence, not a claimed reproduced UAF.
