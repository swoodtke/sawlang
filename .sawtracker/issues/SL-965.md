## Description

**Move OS threads out of `std.task` into a module of their own, so a thread doesn't depend on the task executor.** USER DIRECTION (Nov 4): task != thread, and the stdlib should reflect that.

**Why:** design 242 split the engines by namespace, `Thread.spawn { }` (OS threads, blocking, sync bodies) and `Task.spawn(call())` (the cooperative executor), but both live in `std.task`. `Thread`'s implementation also imports `std.taskgroup`'s thread-control blocks and executor hooks: `ThreadControlBlock`, `alloc_thread_block`, `__saw_exec_join_park`, `__saw_exec_thread_exiting`, `__saw_exec_thread_finished` and others. So a program that only starts OS threads links the executor's bookkeeping.

SL-955 unit 4b hit this. Its background front-cache store uses `Thread.spawn`, which pulls `std.task` and `std.taskgroup` into sawc's std cone, and SL-443's rule keeps both out (`DRIVER_CONE_EXCLUDED`, `compiler/tests/std/std_lane.py`).

**The direction:** the executor is built on threads (a `TaskGroup(threads: N)`), not threads on the executor.
- A thread module holds the raw primitive: spawn, join, detach, the fate rule and its drop panic.
- The executor adds what it needs as a hook, such as parking a task that joins a thread and waking it when the thread finishes. The thread module imports nothing from `std.task` or `std.taskgroup`.

**Unit 1, a census (read-only):** it ends in a size estimate and a draft design for the user's approval.
- what `Thread` uses from the executor, and why;
- the module's surface;
- the hook the executor needs;
- every site that names `std.task`'s `Thread` or `VoidThread`: std, the compiler's `Thread.spawn` form, the spec, the saw-lang skill, docs, tests, corpus, Blade and libs.

**Blocks** SL-955 unit 4b's background store, and with it the v0.20.0 release.

**SL-965: rulings on the thread module** (census and draft: `.build/scratch/p965/census.md`, `design.md`)

**Ruled (user, Nov 4), all as the census recommended, with one change to 3:**
1. **The module is `std.thread`.** A sawos file that whole-imports both it and `sos.thread` renames one with `as`.
2. **`Thread` stays import-gated** (`import std.thread.{Thread}`), as design 255 chose. `Thread.spawn { }` needs no import.
3. **No alias, and no special error.** `import std.task.{Thread}` gets the ordinary error that `std.task` has no `Thread`. There is no teaching error naming `std.thread`, so unit 3 drops the census's `lookup.saw` teaching error.
4. **A plain `func main()` that joins a thread stays a task root** (SL-782). The docs give `func main() blocking` as the executor-free spelling.
5. **`std.channel`'s coupling to the executor gets its own issue.**
6. **The order:** unit 2 (the compiler learns `std.thread`, with a fallback to `std.task`), then the seed bump, then unit 3 (the move). A backlog issue covers having the std root list its own modules.

**Internal shapes (lead):**
- one observer with an event enum;
- the count raise folded into the control-block allocation;
- the join tag owned by `std.thread`;
- the observer installed beside `install_panic_report`.

The census proposed these, and they are reversible and std-internal.
