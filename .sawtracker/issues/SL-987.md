## Description

**`Self` in a trait's default body: `Self()` gives only an internal INVARIANT, and `Self.make()` can't see the trait's own static requirement.** Found by SL-966's census (`.build/scratch/p966/extras/self_default_{empty,fields,unused,static}.saw`).

- **`Self()` in a default body:** typecheck exits 1 with only `INVARIANT … an expression's type is unresolved, but the module has no refusal` and `a call has no target`. There is no user diagnostic, even with no conformer at all.
- **`Self.make()` in a default body:** `member.unknown`: "`Fresh` has no method `make` this module can see", though the trait declares `static func make() -> Self`.

**Expected:**
- `Self.make()` resolves to the requirement, as `T.make()` does through a bound (spec 2699–2727).
- `Self()` follows whatever SL-966 rules for `T()` through a type parameter. Until then it gets a real refusal naming the construct, never an INVARIANT.

**Census first (obligation 4):** `Self` in default bodies across the positions it can appear: `Self()`, `Self(args)`, a static call, a static requirement, `Self` as a type annotation, a return, and generic traits. Also the same in extension bodies and protocol-like generic contexts, each with compile-and-run evidence.
