**Found by the Air's review of ST-84** (sawtracker cancelling an armed merge's in-progress gate run by killing its process group). The gate's runners start test children in new sessions, which a group kill can't reach.

**Mechanism.** Two runners inside the SL gate start each child in its own session, so that their own timeouts can group-kill it:
- `test_runner.py`, around line 1081: `start_new_session=True,  # new process group; enables group kill`;
- `compiler/tests/coro/census.py`, around line 113: the same.

When something above them sends `kill -TERM -<pgid>` to the gate's process group (ST-84's cancel, a graceful server stop, or a lead's Ctrl-C on `./build.sh test`), the runner dies and its live child does not, because the child is in another session. A normal test binary finishes in milliseconds anyway, but a hung one, exactly what the runner's timeout exists for, is orphaned for good and keeps its CPU (and any port, file or QEMU instance it holds).

**Class.** Any sawlang tool that starts a child with `start_new_session=True`, `os.setsid` or `setsid`. The grep today: `test_runner.py`, `tools/test_worker.py`, `tools/remote_worker_selftest.py` and `compiler/tests/coro/census.py`. `tools/freestanding_runner.py`'s QEMU launches should be checked too.

**Fix.** Each such runner traps SIGTERM (and SIGINT) and, before exiting, `os.killpg`s every live child group it started (TERM, then KILL after a short grace), then exits 143. That makes a TERM to the gate's group reach everything, which ST-84's grace period relies on. One helper used by every runner, not four copies.

**Pins:** a test that starts a runner on a deliberately hanging child, sends TERM to the runner's group, and asserts the child's group is gone within the grace period.

**Done when:** the pin passes for each runner in the class, and ST-84's 'no orphans' acceptance holds against sawlang's real gate.

Approved patch SL-603.p1 (revision 1)

Approving SL-603.p1. It closes the issue I filed from my ST-84 review: a TERM to the gate's process group now reaches every child a runner started in a session of its own, and the suite lock can no longer be wedged by a signal that lands between `mkdir` and the caller's trap. Patch applied to ec958f01c, exact tree 1fe949b6.

**`tools/child_groups.py`, read:**
- **One funnel**, with named entry points (`start`, `forget`, `kill`, `install`). Every runner that made a session itself (`test_runner.py`, `census.py`, `snapshot.py`, `test_worker.py`, `remote_worker_selftest.py`) now goes through `start`, and `bypasses` in the test fails on any tracked source that makes a group another way.
- **The handler:** TERM to every recorded group, a per-group grace, then KILL, then `os._exit(128 + signum)`, so a TERMed runner exits 143. It reaps leaders itself, since a zombie leader keeps its group answering signals. It never signals a group again once it's gone, and the kernel won't reuse a pid while a group of that id exists, so a recycled id is never hit. A nested runner gets 10 s against a leaf's 2 s, so an inner runner's KILLs land before an outer one's. Both are well inside ST-84's 60 s.
- A child started after the handler begins is TERMed at once.

**The suite lock:** `acquire` now traps HUP, INT and TERM itself. A signal after its `mkdir` but before the caller's trap releases what it took and exits 129, 130 or 143. `build.sh` runs nothing between the acquire and its own traps. So a stop or cancel during the wait leaves no stale lock and reports a signal status, not 1.

**Run on the Air:**
- `tools/test_suite_lock.py`: OK, all of holder, heartbeat, wait, unknown holder, build.sh, orphaned waiter, TERMed gate, TERMed waiter and dead owner.
- `tools/test_child_groups.py`: OK for all eight runners (test_runner, census, snapshot, test_worker, remote_worker_selftest, run_steps, recognizer_workers, fixpoint_twin), each a hanging child with a grandchild, gone within the grace, in about 22 s.

**Notes, not requests:**
- The optional `.sawtracker/tests.json` `cleanup` hook rightly waits for ST-84 (c2's 'if ST-84's spelling is settled').
- One residual window: a signal arriving between `Popen` returning and `start` recording the pid orphans that one child. It's a few bytecodes on one thread, so not worth a `pthread_sigmask` dance unless it ever shows up.

**Gate:** passed on the applied commit (tested_commit == applied_commit == 01b7f6d30). Its tested_tree 1fe949b6 is exactly the patch applied to ec958f01c, which I computed. Since the patch changes the gate itself (`build.sh`, `tools/suite_lock.sh`) and the runners, every lane ran, and each passed: compiler tests, fixpoint, the Python suite, freestanding, the grammar corpus and astdiff.
