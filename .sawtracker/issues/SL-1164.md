## Description

**A stale toolchain record across worktrees (lead, Nov 18):** two agents today hit `cannot run llvm-objcopy: launch "/opt/homebrew/Cellar/llvm/23.1.5_1/bin/llvm-objcopy" failed (not found)` in the run lane's placed-link probe: Homebrew moved LLVM to 23.1.6, and a worktree's cached runtime manifest (built earlier) still names the old Cellar path. The tool records should be refreshed when the recorded path no longer exists (a freshness check on the recorded tool, re-running `choose_clang`/the record), or name the stable `/opt/homebrew/opt/llvm/bin/` path, not a versioned Cellar one. Low; it fails loudly. Related: `compiler/tools/build.py` `choose_clang`, `sawc tools`.

**Lead's note with p1 (Nov 25):** both guards, as ruled.

- **`build.py`:**
  - `recorded_tool_path` maps a realpath of `PREFIX/Cellar/F/V/rest` to `PREFIX/opt/F/rest`, only when that `opt` path exists and is the same file. Its entry points are `pick_clang` (clang and the Espressif clangs) and `choose_objcopy`.
  - `missing_recorded_tool` and `note_missing_tool`: `configure_bare_metal_targets` treats a record naming a gone tool as stale and rewrites it. Its cache key doesn't change when a tool disappears, the likely mechanism of the symptom. `build_runtime` already rewrote the host manifest each run, and now says why.
- **The driver:** `driver_tool_missing` at `driver_tool` and `driver_run_jobs`' two failure branches.
- **The test:** `compiler/tests/seed/test_tool_records.py`, in `run_seed`, covers 7 cases with a fake Cellar and an `opt` link. It is red on main (no `recorded_tool_path`).
- **One-time cost:** a clang chosen by its Cellar spelling changes `runtime_key`/`stage2_key` once, to the `opt` spelling, so the runtime and Stage 2 rebuild once. Machines on `/usr/bin/clang` are unaffected.
- **The lead's checks:**
  - The agent's driver edit didn't parse (`and` for `&&`, never compiled, because the agent wrongly thought a stage build needs the suite lock). Fixed.
  - The worktree builds through Stage 2.
  - The manifest records `objcopy /opt/homebrew/opt/llvm/bin/llvm-objcopy` (clang here is `/usr/bin/clang`).
  - With the clang record pointed at a missing path, `sawc build` prints "the clang the records beside this binary name, /nonexistent/…, does not exist; run compiler/tools/build.py (bin/sawc does) to record it again".
  - The new test, `tools/battery.sh toolchain citations` and the lint are green. The agent's `toolchain` failure was the missing Stage 2.
