## Description

REQUESTED by the user, Sep 23 2026, after a repo review found comments crowding out the code in `sawc/`: roughly 0.8 comment/docstring lines per code line overall, and more than 1.0 in `rt/shim.c` (1.48), `ast_nodes.py` (1.43), `std/vector.saw` (1.21), `typechecker/core.py` (1.15) and `coro_transform.py` (1.08).

A sampled breakdown of the comment lines:
- about 35% are real WHY/invariant comments;
- about 20% are history or changelog ("used to", "retired", "RULED by the user Aug 8");
- about 15% are design-brief essays pasted into docstrings;
- about 14% cite a design/DF number and cannot be read without `designs/` open;
- about 17% of lines contain ALLCAPS emphasis.

Stale comments already exist, for example:
- `coro_transform.py:180-213` cites `sawc.py:1950` and gives site counts that are wrong today;
- `coro_transform.py:19-25` lists landed work as "later";
- `std/vector.saw:161` says the signature carries nothing unsafe, but it is `unsafe`.

## Rules
Now in CLAUDE.md under "Code comments", landing with p1 of this issue.

## Method
- Each patch changes COMMENTS ONLY: no code, no identifiers, no behavior.
- `///` and `//!` in std `.saw` files are published API (`--emit-docs`) and follow the saw-docs skill. They are trimmed only where they narrate history.
- Before an essay or history block is deleted, check that its reasoning exists in `designs/` or the tracker. If it doesn't, move it there first; the only copy of a mechanism must never disappear.
- Funnel docstrings keep their ENTRY POINTS lists (brief obligation 1). The source-reading lanes (corodiscovery, corototality, windowseam, citations, astgraft, stdseed) run on every patch, because they parse docstrings and source text.
- Gate per patch: `tools/battery.sh --quick` plus `freestanding`. Removing comments cannot change IR, but a `.saw` doc comment feeds `--emit-docs` and the lexers.
