## Description

Document the sawtracker-gated development workflow (ruled Sep 8) and wire the patch test gate.

Three pieces, one patch:

1. CLAUDE.md — new "Sawtracker (issues + the merge gate)" section: server/CLI coordinates, the five-step patch path (issue -> worktree -> lead squashes to one diff -> `patch add` -> user reviews/merges -> fast-forward pull), GitHub downstream of sawtracker, pull-only deploy key, direct commits on local main retired (including the old lead docs-commit carve-out). WORKTREES + INTEGRATION rewritten for the flow: agents still build in isolated worktrees with linear branches; integration is squash + patch instead of cherry-pick; accumulator-file conflict rules and DF-range collision rules unchanged.

2. build.sh (new) — the patch gate's entry point: bootstraps .venv when absent, then runs the compiler's per-commit gate (full suite + freestanding feature suite, both arches — the host has qemu/lld) under the machine-wide suite lock so a server-side patch test never overlaps a local suite run.

3. .sawtracker/tests.json (new) — {"command": ["sh", "-c", "./build.sh test"]}, the one file in .sawtracker/ that is ours rather than the server's. Documented as such in the new section.

Smoke test of ./build.sh test recorded on the issue before submission.
