Two follow-ups from the Air's review of SL-716.p1 (SL-716 c-Air; neither blocked it).

**1. `Data.append_bytes(src:len:)` reads `src` after the old block may be freed.**
- **Mechanism:** `ready` (the separation and growth step) releases the old block before `place` copies from `src`. If this `Data` was the block's last holder, that release frees it. A `src` inside this `Data`'s own bytes, from `byte_ptr()` or a slice sharing the block, then reads freed memory.
- **Stage 0:** its Arc-based version has the same order, so this is no regression, but it is a use-after-free reachable from a call whose only unsafe-typed parameter is `src`.
- **Fix (the API doing the expected thing):** copy before the old block goes, or hold a retain across the copy. Documenting it is not enough.
- **Sweep (obligation 4):** every Data op that takes a raw pointer or a `Data` argument and runs `ready` first. `append(other:)` is safe, because its argument is a retain; check `append_bytes` and any later raw-pointer intake (`File.read` into a Data, `string_from_bytes`).
- **Pin:** a run program that appends a self-slice's `byte_ptr()` across a growth, checked under `leaks` / Guard Malloc (the gmgate lane).

**2. One allocation-failure convention per file (needs a ruling).**
`data_of_string` reports a refused allocation as the block's true size (header + bytes, align 16). The ops SL-716 ported report Stage 0's numbers (the bytes alone, align 1), and the `alloc_data_reports_oom` pin follows Stage 0. Changing the ported ops to the true size moves that pin's output against Stage 0, so this needs a ruling. The lead's lean is the true size (never hide errors: the message should name what was actually refused), recorded as a `stage0-wrong` annotation.

**SL-735.p1: part 1, the `append_bytes` use-after-free. Summary for review.**

- **The fix (std/data.saw):** `append_bytes` keeps the fast path when this `Data` solely owns its block at offset 0 with room. Otherwise it relocates into a fresh block, places `src` there, and only then does `self = fresh`, so the old block is still alive while `src` is read. The fast-path test is a private helper `has_room`, shared with `ready`. The error value (`AllocError(size: target, align: 1)`) and the growth policy are unchanged.
- **Pin:** `compiler/tests/run/probes/data_append_bytes_self_alias.saw` (a stated probe, -O0 and -O2; Stage 0 has the same defect, so its run is no oracle). Before the fix: a segfault under Guard Malloc, and sixteen `0`s for the second copy without it. After: 1..16 twice.
- **Sweep (obligation 4), each `ready` caller probed under Guard Malloc before and after:** `[]`/`set`/`reserve` read no caller memory; `push` takes a byte by value; `append(other:)` reads through a retained `Data` that keeps the old block alive; `append_bytes` with a slice's pointer is safe for the same reason (the slice retains the block). Only `append_bytes` from its own `byte_ptr()`, while sole owner, was broken. So there is no second fix.
- **Not in the gmgate list:** `tools/gmgate.py` takes only programs judged by a Stage 0 record, and this probe has none.
- **The agent's gate:** `run.py --only std,programs` ok; `corpusdiff.py gate` holds all 2661 (no verdict moved, so no baseline commit); `battery.sh citations gmgate` green.
- **Part 2** (which size a refused allocation reports in std/data.saw) waits for the user's ruling and is not in this patch.

Approved patch SL-735.p1 (revision 1)

**Air: SL-735.p1 r1 approved; arming it.** `append_bytes` now relocates into a fresh block, places `src` there, and assigns `self = fresh` last, so the old block outlives the read. The fast-path test is shared with `ready` through `has_room`.

**Read:** an empty `Data` never reaches `self.block!` in `has_room`, because `is_unique()` is false with no block. The error value is computed exactly as before (`grown(wanted)` ahead of any move). `wanted > length` here, so the slow path sizes the block as `ready` did. The new comments say why and are in the present tense.

**Probes** (`air-review/sl735/probe_paths.saw`, main's sawc2 with main's std and with the patch's std, at -O0 and -O2, natively and under Guard Malloc):
