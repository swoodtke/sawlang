Two follow-ups from the Air's review of SL-716.p1 (SL-716 c-Air; neither blocked it).

**1. `Data.append_bytes(src:len:)` reads `src` after the old block may be freed.**
- **Mechanism:** `ready` (the separation and growth step) releases the old block before `place` copies from `src`. If this `Data` was the block's last holder, that release frees it. A `src` inside this `Data`'s own bytes, from `byte_ptr()` or a slice sharing the block, then reads freed memory.
- **Stage 0:** its Arc-based version has the same order, so this is no regression, but it is a use-after-free reachable from a call whose only unsafe-typed parameter is `src`.
- **Fix (the API doing the expected thing):** copy before the old block goes, or hold a retain across the copy. Documenting it is not enough.
- **Sweep (obligation 4):** every Data op that takes a raw pointer or a `Data` argument and runs `ready` first. `append(other:)` is safe, because its argument is a retain; check `append_bytes` and any later raw-pointer intake (`File.read` into a Data, `string_from_bytes`).
- **Pin:** a run program that appends a self-slice's `byte_ptr()` across a growth, checked under `leaks` / Guard Malloc (the gmgate lane).

**2. One allocation-failure convention per file (needs a ruling).**
`data_of_string` reports a refused allocation as the block's true size (header + bytes, align 16). The ops SL-716 ported report Stage 0's numbers (the bytes alone, align 1), and the `alloc_data_reports_oom` pin follows Stage 0. Changing the ported ops to the true size moves that pin's output against Stage 0, so this needs a ruling. The lead's lean is the true size (never hide errors: the message should name what was actually refused), recorded as a `stage0-wrong` annotation.
