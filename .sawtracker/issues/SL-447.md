# U6b1: types and signatures (SL-447, the first of three typecheck units)

- **Epic:** SL-398, unit 6b. The issue's description gives the three-unit split and the stage's acceptance.
- **Design:**
  - SL:architecture §3.0 (shared), §3.4 (type checking: "Order", "Traits", "Copy tier", the accessor-signature reader), §4 (the subset and the cone) and §5;
  - the spec's rules for generics and defaults (designs 108, 109; SL-382's defaults filled at every depth);
  - designs 80 (member visibility), 128 (`@synthesize`), 130/136 (`unsafe` per declaration), 142 (import-scoped extensions), 144 (type identity), 219 (the Copy tier) and 229;
  - SL:borrowing §2.5 for `borrows` signatures.
- **Package:** `compiler/typecheck/`, package `sawtypecheck`. It depends on `sawresolve`, is registered in `STAGE_PACKAGES`, and is written in the bootstrap subset. The subset checker passes over it, and Stage 0 markers apply.
- **Input:** resolve's program: arenas plus side tables, unchanged. Typecheck never looks a name up by its spelling. Every name is one resolve bound.

## Decisions (the lead)
1. **One type interner per compilation, keyed by canonical form.** A key is:
   - the defining module and declaration path (design 144);
   - the canonical arguments, with defaults filled at every depth;
   - the structural types: optional, tuple (with labels), function (with effects), reference (`&`, `&var`), slice, raw pointer, and so on.

   Identity is key equality, and ids are handed out in a defined traversal order (modules in load order, declarations in source order). Output never prints an id. The dump renders every type by its canonical spelling, so goldens don't depend on interning order. Keys are symbolic, so §3.12's per-module serialized boundary can re-intern by key later. That is not this unit's work.
2. **The dump is an S-expression, one per module, specified in `compiler/tests/typecheck/README.md`.** It holds:
   - `declarations`: each signature in canonical types. That means generic parameters with bounds, defaults and const parameters, the receiver kind, labels, parameter passing, effects (`unsafe`, `sync`, `consumes`, `borrows`, with the conditional-lend classification) and the return type.
   - `members`: per nominal type, its fields (type, visibility), its methods and statics, and where each comes from (the declaration, an extension in module M, or a trait default).
   - `conformances`: (type, trait), where it is declared, and which requirements are defaulted, synthesized or written.
   - `copy-tier`: per nominal type, Copy, ExplicitCopy or NoCopy. For a generic type, the rule over its arguments.

   Invocation is `sawc2 typecheck (--dump | --check)`, with resolve's flags.
3. **Member tables are per (type, viewing module).** Extensions are import-scoped (design 142, resolve hands over each module's visible-extension set) and fields and methods are private by default (design 80). A module sees a type's members through those two filters. The table is built once per type, and the view is a filter, not a copy.

## Scope, for this unit
**Build:**
- the interner;
- every signature in `compiler/` and in the std cone (read as interface from `sawc/std`, as resolve reads it);
- trait requirements;
- the conformance table, with default bodies filling gaps;
- member tables;
- the Copy-tier classifier;
- the accessor-signature reader (§3.4).

**Check, each with a stable rule id and a refusal fixture:**
- type-argument arity;
- bounds for every type argument, primitives included (design 109);
- defaults filled at every depth;
- finite struct size (a cycle in by-value containment);
- conformance completeness and signature agreement;
- a declared empty derivation requires `@synthesize` (design 128);
- the signature half of `unsafe`: a signature naming an unsafe type is declared `unsafe`, and a function type carries `unsafe` only when its signature names one (designs 130, 136).

**Not this unit:** bodies (U6b2), and effects fixpoints and body-level checks (U6b3). A signature construct outside the slice is refused as `slice.not-yet`, naming it.

**The position matrix:** every type-position kind the subset and the cone use, with the golden case covering each row, in the tests README.

## Tests, test-first
- Golden dumps under `compiler/tests/typecheck/`, and a lane in `compiler/tests/run.py`.
- A refusal fixture for each rule id; the lane fails any rule without one, as resolve's lane does.
- **A verifier** on every output:
  - every type-position node has a type;
  - every nominal type has a member table and a Copy tier;
  - every conformance is complete;
  - no type is left unresolved or looked up by spelling.
- **Acceptance:** every declaration of `compiler/`'s own source (the sawc2 build and each unit program) and of the cone gets its signature, with no refusal and no invariant. Report `tests/corpus/` coverage as information only.
- **The frozen cross-check,** once, recorded as SL-445's `FROZEN_CHECK.md` was: over the sawc2 build, compare each struct's field types, each function's parameter and return types, and each nominal type's Copy tier with the frozen typechecker's view. It is observed the way `frozen_check.py` observes it, with `sawc/` never edited.

## Rules
- **Where to work:** stay inside `compiler/typecheck/`, `compiler/tests/typecheck/`, `compiler/driver/` (the `typecheck` subcommand), `compiler/tools/build.py`, `compiler/tests/run.py` and `compiler/README.md` (its layout and testing lists).
- **Resolve gaps:** if typecheck needs something resolve doesn't give, report it. Don't edit `compiler/resolve/` or `compiler/parse/`.
- **`sawc/` is frozen.** A Stage 0 bug that blocks you stops that item, and you report it with a minimal repro. Work around it only with a Stage 0 marker for a hazard SL:hazards names.
- **Decisions:** a reversible reading goes in the report. A change of meaning, or something the design leaves unsettled, stops that item and goes in the report.
- **Measured performance:** report the time to typecheck `compiler/`'s signatures.

Comments on U6b1 before the agent gets far. Two points.

1. **The interner's key hides its three hard forms behind "and so on".** Decision 1 lists the nominal key and the structural types. A signature also holds three types that are neither nominal nor structural, and each needs a defined key:
   - **A type parameter,** as in `Vector<T>.push(value: T)`. The cone needs this one. Key it by its declaring declaration's path and the parameter's index, so two `T`s of different declarations never meet.
   - **`Self` in a trait requirement:** a placeholder that each conformance substitutes.
   - **An associated-type projection:** `T`'s `Item` through its bound. My SL-445.p1 review (item 2) found that the language has no settled spelling for one yet: bare `Item` via the bound in Stage 0, while both compilers refuse `T.Item`.

   The brief should give the first two keys, and either give the third or state that projections are `slice.not-yet` until that D entry lands. The cone's builtins don't include `Iterator`, so the slice may not need projections.
2. **Sequencing with SL-445.** U6b1 builds on resolve, and resolve's revision changes two things typecheck reads:
   - `Optional` becomes an enum with a `Some` case, which changes the canonical form of `T?`;
   - D13's case candidates are scoped to the import closure.

   Say that U6b1 rebases onto the merged SL-445 revision before its interner fixes `Optional`'s key, so its goldens aren't built on the p1 shape.
