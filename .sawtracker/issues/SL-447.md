# U6b1: types and signatures (SL-447, the first of three typecheck units)

- **Epic:** SL-398, unit 6b. The issue's description gives the three-unit split and the stage's acceptance.
- **Design:**
  - SL:architecture §3.0 (shared), §3.4 (type checking: "Order", "Traits", "Copy tier", the accessor-signature reader), §4 (the subset and the cone) and §5;
  - the spec's rules for generics and defaults (designs 108, 109; SL-382's defaults filled at every depth);
  - designs 80 (member visibility), 128 (`@synthesize`), 130/136 (`unsafe` per declaration), 142 (import-scoped extensions), 144 (type identity), 219 (the Copy tier) and 229;
  - SL:borrowing §2.5 for `borrows` signatures.
- **Package:** `compiler/typecheck/`, package `sawtypecheck`. It depends on `sawresolve`, is registered in `STAGE_PACKAGES`, and is written in the bootstrap subset. The subset checker passes over it, and Stage 0 markers apply.
- **Input:** resolve's program: arenas plus side tables, unchanged. Typecheck never looks a name up by its spelling. Every name is one resolve bound.

## Decisions (the lead)
1. **One type interner per compilation, keyed by canonical form.** A key is:
   - the defining module and declaration path (design 144);
   - the canonical arguments, with defaults filled at every depth;
   - the structural types: optional, tuple (with labels), function (with effects), reference (`&`, `&var`), slice, raw pointer, and so on.

   Identity is key equality, and ids are handed out in a defined traversal order (modules in load order, declarations in source order). Output never prints an id. The dump renders every type by its canonical spelling, so goldens don't depend on interning order. Keys are symbolic, so §3.12's per-module serialized boundary can re-intern by key later. That is not this unit's work.
2. **The dump is an S-expression, one per module, specified in `compiler/tests/typecheck/README.md`.** It holds:
   - `declarations`: each signature in canonical types. That means generic parameters with bounds, defaults and const parameters, the receiver kind, labels, parameter passing, effects (`unsafe`, `sync`, `consumes`, `borrows`, with the conditional-lend classification) and the return type.
   - `members`: per nominal type, its fields (type, visibility), its methods and statics, and where each comes from (the declaration, an extension in module M, or a trait default).
   - `conformances`: (type, trait), where it is declared, and which requirements are defaulted, synthesized or written.
   - `copy-tier`: per nominal type, Copy, ExplicitCopy or NoCopy. For a generic type, the rule over its arguments.

   Invocation is `sawc2 typecheck (--dump | --check)`, with resolve's flags.
3. **Member tables are per (type, viewing module).** Extensions are import-scoped (design 142, resolve hands over each module's visible-extension set) and fields and methods are private by default (design 80). A module sees a type's members through those two filters. The table is built once per type, and the view is a filter, not a copy.

## Scope, for this unit
**Build:**
- the interner;
- every signature in `compiler/` and in the std cone (read as interface from `sawc/std`, as resolve reads it);
- trait requirements;
- the conformance table, with default bodies filling gaps;
- member tables;
- the Copy-tier classifier;
- the accessor-signature reader (§3.4).

**Check, each with a stable rule id and a refusal fixture:**
- type-argument arity;
- bounds for every type argument, primitives included (design 109);
- defaults filled at every depth;
- finite struct size (a cycle in by-value containment);
- conformance completeness and signature agreement;
- a declared empty derivation requires `@synthesize` (design 128);
- the signature half of `unsafe`: a signature naming an unsafe type is declared `unsafe`, and a function type carries `unsafe` only when its signature names one (designs 130, 136).

**Not this unit:** bodies (U6b2), and effects fixpoints and body-level checks (U6b3). A signature construct outside the slice is refused as `slice.not-yet`, naming it.

**The position matrix:** every type-position kind the subset and the cone use, with the golden case covering each row, in the tests README.

It is observed the way `frozen_check.py` observes it, with `sawc/` never edited.

# U6b2: bodies (SL-447, the second of three typecheck units)

- **Epic:** SL-398, unit 6b. The issue's description gives the split and the stage's acceptance.
- **Base:** main after SL-447.p1 (U6b1) merged. It builds on `sawtypecheck`'s interner, signatures, member tables, conformance table and Copy tiers.
- **Design:**
  - SL:architecture §3.4: the Out list, "Type inference is local and bidirectional", the expected-type funnel with its peeling, implicit members, call-site inference and "Overloads";
  - the spec's literal adoption (Primitive Types, design 87), auto-wrap, optional chaining (design 111), the Copy family's transfer rules and payload reads (design 131), and overloading with labeled arguments (designs 93, 105);
  - SL:borrowing §5 (the three subscript roles) and §2 (`borrow` bindings);
  - SL:open-questions D13, whose typecheck half this unit owes.
- **Package:** `compiler/typecheck/`, the same package, with the same subset, checker and markers.

## Decisions (the lead)
1. **Output is side tables keyed by the AST's expression ids** (§3.0). The tree is never touched. Per expression:
   - its type;
   - its adjustments, as an ordered list of explicit conversion records: auto-wrap into Optional or Result, literal adoption, `&v` to `&[T]`, `Never` to any type;
   - place or value;
   - for a value use, its transfer kind: a spelled `move`, an implicit copy, or the hand-off of an owned temporary.

   Per call: the chosen target (a declaration identity, including a synthesized member) and its instantiation, the type arguments in canonical form. Per operator, subscript, `for` and `default:`: the declaration it calls, with a subscript's role (getitem, setitem or place accessor, SL:borrowing §5).
2. **The dump grows a `bodies` section per module,** specified in the tests README. It lists one line per expression, in source order: span, canonical type, adjustments, place/value with the transfer, and call target with instantiation. Goldens stay readable, because each golden case is small and aimed at one aspect.
3. **The expected-type funnel is ONE function** (brief obligation 1). Its docstring lists its entry points: §3.4's literal-adoption positions, which are each a row of the position matrix with its golden case. Peeling is the same for every client, as §3.4 states. An implicit member goes through the funnel and never selects an overload.
4. **The overload filter is ONE function.** It filters by labels, arity and types. A unique best candidate wins, and otherwise the call is refused naming every candidate. Call-site generic inference is local unification with the later-argument fixpoint and the unique-solution rule (designs 93, 105).

## Scope, for this unit
**Build:**
- typing for every expression, statement and pattern form in the bootstrap slice (the subset plus the new std's named low-level features);

- the overload filter and generic inference;

**Carried from U6b1:**

- an `init`'s result is the receiver or `Result<Receiver, E>`;

**Checks, each with a stable rule id and a refusal fixture:**
- type mismatch at each funnel position;

- the implicit member with no expected type (with the `Enum.Case` fix-it);

**Not this unit (U6b3):** the effect and Copy-requirement fixpoints, the `sync` check, exhaustiveness, discarded `Result`, literal ranges, borrowing-struct containment, and the body half of `unsafe`, `consumes` and `borrows`. Nor use-after-move or exclusivity, which belong to MIR and the borrow check. A body construct outside the slice is refused as `slice.not-yet`, naming it.

**Finding, non-blocking (a follow-up, or U6b2's brief)**
- **Extension heads get one message for three different cases.** `type.arity`'s "an extension of `Vector` renames its 2 type parameters, and 1 are written" covers all of these:
  1. **A rename missing a parameter that has no default.** `extension Pair<A>` over `Pair<A, B>` is a real arity error, and `type.arity.extension.saw` pins it.
  2. **A head that omits a defaulted parameter:** `extension Vector<T> { … }`. Stage 0 accepts it. It is also ambiguous: filling the default makes it a specialization on `A = GlobalAllocator`, while reading it as a rename makes it generic over `A`. std always writes the defaulted parameter out, as `Box<T, A: Allocator = GlobalAllocator>` shows, so this needs a D entry, not a guess.
  3. **A specialization:** `extension Vector<String>`, which std uses (`string.saw:747`, `join`, outside the cone), as does one corpus program. It isn't a rename at all. The spec says specialized extensions "beyond what monomorphization already supports" are planned, so the basic form is supported.
