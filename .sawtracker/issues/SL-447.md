Unit 6b of epic SL-398, the bootstrap slice's second semantic stage: type checking (SL:architecture §3.4). The user gave the go on Sep 30. The package is `compiler/typecheck/`, package `sawtypecheck`. It depends on `sawresolve` and reads resolve's side tables unchanged. Its output is side tables keyed by arena ids (§3.0).

**Three units, landing in order.** Each is briefed as a comment here when the one before it lands, and each is a patch on this issue.
1. **U6b1, types and signatures.** The type interner. Every declaration's signature program-wide. Member tables and the conformance table. The Copy tier. Finite struct size and the other signature-only checks. `sawc2 typecheck --dump`.
2. **U6b2, bodies.** Local bidirectional inference, including:
   - the expected-type funnel with its peeling, and implicit members;
   - literal adoption, auto-wrap and the other explicit conversion nodes;
   - overload filtering and call-site generic inference (designs 93, 105);
   - operator and subscript-role targets;
   - place and value marking, and transfer kinds;
   - D13's check: a name pattern taken for a case whose candidates include none of the scrutinee's enum is refused, naming the case and suggesting the rename.
3. **U6b3, summaries and checks.** Phase 2's fixpoints: may-suspend, sync-callable, and the inferred Copy requirement (design 219). Phase 3's consuming checks. Then exhaustiveness, discarded `Result` (design 151), literal ranges, borrowing-struct containment, and the body half of `unsafe`, `consumes` and the `borrows` contracts.

**Acceptance, for the stage:**
- `compiler/`'s own source typechecks whole, with no refusal and no not-in-slice diagnostic.
- A typed-IR verifier passes on every output.
- The frozen cross-check agrees on what both compilers decide, and records it once, as SL-445's did.
- `tests/corpus/` coverage is reported, for information only.

**Scope:** the bootstrap slice, as for U6a. That means what `compiler/` uses, the std cone (`compiler/tools/std_cone.txt`), and the new std's named low-level features: `unsafe`, raw pointers, extern seams, allocator parameters, and `borrows` with `lend`. Anything else is refused as `slice.not-yet`, and never mis-typed.
