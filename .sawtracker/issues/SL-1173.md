## Description

**A `borrows` accessor that forwards a lend to an accessor declared later fails MIR: "a window call does not name its accessor's half".** Reported by sawos (chat m1356, Nov 18, from `sosmain` on v0.24.3; their repro is f403, unpacked at `.build/scratch/sl_lendorder/x/` in the lead's checkout). Reduced by the lead on main (f96b2000b's tree) to `.build/scratch/sl_lendorder/order.saw`:

```saw
extension Outer {
    func outer_view(&self) borrows -> &Inner {
        lend self.inner_view()      // INVARIANT 10:46 prologue/epilogue: a window call does not name its accessor's half
    }
    func inner_view(&self) borrows -> &Inner {
        lend self.inner
    }
}
```

The same program with `inner_view` declared first (`order_first.saw`) builds and prints `7`. Declaration order must not change meaning, and an accepted program must never reach an internal check.

**To do (brief obligation 4: a class until a sweep says otherwise):**
- Name the mechanism. The suspicion (UNVERIFIED) is that an accessor's prologue and epilogue halves are made in declaration order, so a window call lowered before its callee is split finds no half.
- Probe the other positions with build evidence:
  - a forward lend to a later accessor in another extension or another file of the module;
  - one in another module;
  - a plain (non-lending) window call to a later accessor (`let x = self.inner_view()` inside a method body);
  - `&var self`, `borrows(sync)`, a conditional lend `-> &T?`, a generic accessor, a suspending body;
  - mutual forwarding (a cycle, which must be a clean refusal, not a hang).
- The fix targets the mechanism, with the matrix as its pins (each red on main).

Related: SL-1155 (receiver-less windows), SL-1156 (forwarding through a declared root).

**Lead's note with p1 (Nov 18).** The sweep evidence is in `.build/scratch/p1173/sweep/` in the lead's checkout.

- **The mechanism:** `lower_program` lowered accessor roots in source order and split each right after lowering it. So an accessor whose body calls a window on an accessor later in that order was lowered before its callee had halves (`accessor_of == -1`), and `verify_window_call` then reported the invariant.
  - It is a class: any accessor calling a later accessor triggers it, with or without a `lend`.
  - Across modules too: the imported callee's case failed on main.
- **The fix** (`compiler/mir/src/lower.saw`): accessors are lowered callee-first through one funnel, `accessor_order` (ENTRY POINTS: `lower_roots`). It is a depth-first order over `accessors_called` (each accessor body's calls to accessor roots, closures included). The original index is kept, so the dump and verify order are unchanged.
- **The sweep, main → after:** each was an INVARIANT on main and now builds and runs:
  - the same extension;
  - a later extension;
  - a plain window call in an accessor body;
  - `&var self`;
  - `borrows(sync)`;
  - a generic receiver;
  - a suspending callee;
  - a subscript forwarding to a later accessor;
  - another module's accessor.

  Pinned by ten run-lane probes `lend_forward_*`.
- **A cycle** (a forwards to b forwards to a, and self-forwarding) was an INVARIANT in every order on main. It is now a clean `slice.not-yet` refusal ("an accessor that forwards a lend to itself, through other accessors or directly"), pinned by `compiler/tests/mir/refuse/forwarding-lend-{cycle,self}.saw`.
  - The lead accepts `slice.not-yet` as the honest verdict: a recursive accessor that descends through different receivers (a tree's leftmost node) is plausibly a legal program not yet lowered, not a language refusal. Nothing that ran before is refused.
- **Unchanged:** a conditional lend's place read other than through `!` (a separate pending feature, order-independent).

Approved patch SL-1173.p1 (revision 1)

**Approved. The callee-first order covers every way an accessor reaches another today, and the cycle is a clean refusal.**

- **The order.** `accessor_order` puts each accessor after every accessor its body calls. The calls come from the typechecked call targets, closures included. The original index is kept for dump and verify. Plain bodies are still lowered after every accessor (`lower_roots(…, false, …)`), so a plain function calling a window on any accessor was never at risk. Your ten `lend_forward_*` probes are each an INVARIANT on main and pin the positions: same or later extension, plain window, `&var self`, `borrows(sync)`, generic receiver, suspending, subscript, another module.
- **The one position the order cannot see** is a call through a trait requirement, whose target is the requirement and not the accessor. A call through a bound or an `any Trait` to a `borrows` requirement isn't built in sawc yet (spec, "`borrows` reaches suspensions, function types and traits": "not built in `sawc` yet, SL-1024"), so nothing reaches it now. When SL-1024 builds that call, it has to give `accessor_order` the implementation's edge.
- **Cycles.** The walk marks the accessor whose call closes a cycle, and that accessor is refused as `slice.not-yet`. The two fixtures (`forwarding-lend-cycle`, `forwarding-lend-self`) pin that a cycle in either shape refuses cleanly instead of tripping the invariant. Your reading of `slice.not-yet` as the honest verdict (a recursive descent through different receivers could be a legal program not yet lowered) is right.

The gate passed on this revision. I didn't rebuild it: the server ran run.py with the stage, borrowck, drops and coro steps, and the fix is pinned at each position above.
