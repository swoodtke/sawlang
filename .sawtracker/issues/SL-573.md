**A14a. Offload, the compiler half** (back track).
- **Scope:**
  - A `blocking` extern called in a framed body lowers to the offload sequence: `__saw_rt_offload_start`, then `park(offload)` on the job's pipe (A3c), then `take`, the join, on every exit, cancel included.
  - One C-ABI `word(word)` thunk is synthesized per offloaded extern, reading its frame-resident argument slots.
  - Not offloaded: in a `Thread.spawn` body a `blocking` extern is a plain call. In the freestanding profile it is refused.
- **Depends on:** A3c.
- **Files:** `compiler/coro/src/lower.saw`, `compiler/llvm/src/calls.saw`.
- **Pins:** lowered-MIR goldens for the sequence on its completion and cancel exits. The run pins come with A14b.
- **Done when:** the goldens are stable.
- **Estimate:** 1.

**Plan:** SL:coroutines §4, unit A14a (approved by the user, Oct 12). The plan text is authoritative; this issue is its tracker entry. Dependencies are named by unit id; see the epic's child list for their issues.

**Why the files are incomplete.** The plan names `compiler/coro/src/lower.saw` and `compiler/llvm/src/calls.saw`, plus `program.saw`/`dump.saw` for a new point or thunk kind. The sequence needs four more things, each checked in the source:

1. **The job handle has no frame storage.** `__saw_rt_offload_start`'s job word is `take`'s operand after the park, so it must live in the frame. The plan's frame-resident argument slots need storage there too. A frame holds only the state word, the budget counter, the result, the parameters, resident body locals and child slots (`coro_find_frame`, frames.saw). `coro_lower_for` lays frames out (`coro_lay_out_frames`) before `coro_lower_frames` runs, and a caller embeds a child by its laid-out size, so lowering cannot add a slot. This needs `compiler/coro/src/frames.saw`: a value per blocking-extern suspension, live from the call through its suspension point. It also needs a new `CoroValueKind` (program.saw), its `--layouts` label (dump.saw), and possibly layout.saw if the argument slots are one aggregate value.
2. **Mono never roots the offload park's executor calls for a real program.** `resolve_park` (`compiler/mono/src/worklist.saw`) roots `__saw_exec_io_register` and `__saw_exec_offload_pipe` only from a call of `__saw_park_offload`. Only the lane's `parks/task_tail.saw` makes such a call; a blocking extern call is not one. So `coro_exec_call` would report "a park reached coroutine lowering without the executor function its lowering calls" for every corpus row above. This needs `compiler/mono/src/worklist.saw`, to root both from a blocking-extern call.
3. **The verifier refuses the shape.** Rule 2 (`coro_verify_transfers`, verify.saw) lets only a drive, a park, a spawn site or a drive site lose its arguments or destination. It also requires each operand the call passed to be used exactly once afterwards. The offload's per-argument widening writes, and its `dest = narrow(take(job))`, are a new shape. Rule 4 sees an offload park whose JOB operand is a value lowering made. This needs `compiler/coro/src/verify.saw`, and the "Lowering" and "The verifier" text in `compiler/tests/coro/README.md`.
4. **The thunk's address needs the backend's point emission.** No MIR operand names an item (the A7a amendment), so the start's `fn` word is written by the backend, as a spawn's `_D` is. The resume function's points are emitted in `compiler/llvm/src/bodies.saw`, A3c's file, so an offload-start point needs bodies.saw beside calls.saw.

**A shape that fits (UNVERIFIED, for the lead to rule on; nothing here is built):**
- frames.saw reserves, per blocking-extern suspension, one word for the job plus one word per argument.
- lower.saw rewrites `dest = ext(args)`:
  1. the block writes each widened argument into its slot;
  2. an offload-start point: the backend calls `__saw_rt_offload_start(thunk$ext, &slots, argc)` and stores the job into its slot (the SL-768 comment goes here);
  3. A3c's offload park, with JOB copied from the job slot;
  4. on resume, `_w = __saw_rt_offload_take(job)`, then `dest = narrow(_w)`. This is straight-line after the park, so the cancel exit is the same edge. The park returns nothing, and the cancel word is read afterwards, so `take` runs on every exit.
- mono roots the two executor entries from the extern call.
- verify.saw learns the start, the slots and the take.

Files that adds: `compiler/coro/src/{frames,program,dump,verify}.saw` (layout.saw maybe), `compiler/mono/src/worklist.saw`, `compiler/llvm/src/bodies.saw`, and `compiler/tests/coro/README.md`.

One ruling this also needs: Stage 0 checks `done` before it parks, and re-parks on a wake that is neither a cancel nor completion (`_emit_blk_call`). The plan parks once, then takes. A cancel wake then makes `take` block the executor thread until the C call returns, which the spec allows (offload "Cancellation"). A wake for any other reason would also go straight to `take`.

**The other two cases, as far as they can be decided today:**
- **Freestanding:** sawc2 has no freestanding profile (`sawc2 build takes no --freestanding`), so no refusal fixture can be written. The rule would key on the build's profile, at the blocking extern call in a framed body.
- **`Thread.spawn`:** the form is refused in resolve (`slice.not-yet`, SL-765). The rule is that a thread body is a sync item with no frame (§3.8), so coro never reaches its calls. A blocking extern there must then not be a suspension source in `suspends.saw` (`coro_call_is_source`). That decision is SL-765's, not lower.saw's.

**Air on the stop's ruling question (park once, then take).**

**Equivalent today:** in sawc2 an offload park can wake only on completion or cancel. `coro_lower_park`'s `ParkOffload` records deadline 0, so `park_wakes`' `PARK_FD` arm never fires on the clock. The word reads `PARK_READY` only through a reactor CAS from -1, which happens only for a registration carrying this park word's address. The completion pipe's registration is the only live one, because SL-569's `io_wait` withdraws every non-Ready registration, and a Ready one-shot is consumed. So "a wake for any other reason" can't happen yet, and park-once behaves like Stage 0's loop.

**Still, I'd keep Stage 0's loop shape:** check `__saw_rt_offload_done` before parking, and after a wake re-park unless it's done or cancelled. It costs one load per wake. Without it, any future path that latches the word while the C call runs turns into a blocking `take` on the executor thread, stalling every sibling for as long as the C call takes. It's also the oracle's shape, so the corpus compares like with like.

**A question for the lead or the user, not a stop:** the spec's Cancellation paragraph has the cancelled task leave the park loop and then join, which is a blocking `take`, as Stage 0 does. With a C call that never returns (`offload_multi_arg_pipe_read`'s `read` with no writer), that stalls the whole executor. A cancel used for shutdown then can't unwind the other tasks on that thread either. The alternative keeps the spec's promise ("a cancelled task still waits for its C call to finish before it can return") cooperatively: after a cancel, stay parked on the completion pipe until `done`, then `take` (the join then returns at once). Siblings keep running, and only the cancelled task waits. That changes the spec's described mechanism, so it's a ruling, and A14b's `offload_cancel_*` rows are where it would show.
