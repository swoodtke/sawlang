**A2. An escaping closure's environment lives on a dead frame** (SL-606, bucket A). Finding: Typecheck-body 0, the review's most severe.

- **The bug:** `func make(r: &Res) -> () -> Int { let n = r.n; return { [n] in n } }` stores the environment in an `alloca` of `make` and returns a pointer to it. The caller reads garbage, at -O0 and at the default. The Air reproduced it: it prints `8472597872`, where Stage 0 prints `42`. SL-525 refuses only the OWNING-capture case.
- **Census first** (the Air, m520, obligation 2): before any refusal, find every escaping closure with a non-empty environment in `compiler/` and `std/`, using grep plus `sawc2 typecheck --dump` over the closure values with captures.
  - If there are none, refuse every escaping closure with a non-empty environment as `slice.not-yet`, naming SL-525, until SL-525 builds heap environments.
  - If there are some, Stage 2 is miscompiled today. STOP, report the sites, and the lead decides between building heap environments first and rewriting the sites.
- **Also:** refuse `-> () escaping -> Int` in a return type as redundant, as Stage 0 does.
- **Pins:** a refusal fixture for the trivial capture, the `[copy r]` variant (which segfaults today) and the redundant `escaping`, plus a run-lane program that shows a non-escaping closure with captures still works.
- **Done when:** the probe is refused, the census is recorded in the report, and the self-build and fixpoint are unaffected.
