tools/lima/sawlang-linux.yaml sets Rosetta with the top-level `rosetta:` key, which Lima 2.x deprecates in favour of `vmOpts.vz.rosetta`.

Creating the VM with Lima 2.3.0 (Nov 26) warns twice: "Both top-level 'rosetta' and 'vmOpts.vz.rosetta' are configured. Using vmOpts.vz.rosetta." Rosetta came up enabled this time (binfmt_misc `rosetta` enabled), so the x86_64 lane is unaffected today. But the file depends on Lima's default for `vmOpts.vz.rosetta` agreeing with it.

**Fix:** move the setting under `vmOpts.vz.rosetta` (`enabled: true`, `binfmt: true`), and drop the top-level key. Verify by recreating, or with `limactl validate`, and by the x86_64 lane.
