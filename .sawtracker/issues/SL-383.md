## Description

Found by the SL-340 implementer (Sep 24). Reproduces on main.

A `match` arm binding an enum payload whose type is a distinct ALIAS over a struct types the binding as `Void`, whether the enum is owned or borrowed. An alias over a primitive (`Count = Int`) is fine.

```saw
type Count = Int
struct Noisy { name: String }
extension Noisy: NoCopy {}
type Tag = Noisy

enum A { case Has(c: Count), case No }

enum B { case Has(t: Tag), case No }
extension B: NoCopy {}

func a_val(a: A) -> Int {
    match a {
        case Has(c) -> c as Int,
        case No -> 0
    }
}

func b_val(b: B) -> Int {
    match b {
        case Has(t) -> t.name.len(),     // `t` is typed Void here
        case No -> 0
    }
}

func main() {
    print("{}", a_val(A.Has(c: Count(3))))
    print("{}", b_val(B.Has(t: Tag(Noisy(name: "four")))))
}
```

Expected output: `3`, then `4`.

Mechanism to confirm (obligation 4): the pattern-binding type resolution for an enum payload does not resolve a distinct alias over a STRUCT. Sweep every position that reads an alias-typed payload or field:
- `if let` and `guard let` payloads;
- tuple destructuring;
- borrowing arms;
- the driven twin. A sibling is filed separately: an alias field read in a driven body.
