## Description

**Unit 4 of SL-661: every oracle reads Stage 0's recorded snapshots, never a live Stage 0.**

Today some lanes build each program with Stage 0 at test time and compare: the run lane (`compiler/tests/run/run_lane.py`: "built by sawc2 and by Stage 0, the two binaries' output and exit status compared"), the layouts check ("layouts matching Stage 0"), parts of the coro lane, the census and any other step that runs `sawc/sawc.py`. Once `sawc/` is gone, none of them may.

**Snapshots that exist:**
- SL-655's whole-corpus snapshot (`compiler/tests/corpusdiff/stage0/`, with the shared `compiler/tests/oracle.py`);
- A0b's coro snapshot (`compiler/tests/coro/stage0/`).

**Owed:**
- An inventory of every place in `compiler/tests/`, `compiler/tools/` and `tools/` that invokes Stage 0, with grep plus a run that fails if `sawc/sawc.py` is made unreadable.
- Each one switched to a recorded snapshot read through `oracle.py`: stdout, exit status, panic text, frame layouts, or whatever it compares.
- A regeneration path for each snapshot that uses the v0 compiler through the pinned toolchain, not the in-tree `sawc/`, so the records stay reproducible after the deletion.
- Each snapshot records the target triple, as A0b's already does.
- The lanes' READMEs updated.

**Done when:** `compiler/tests/run.py` passes in full with `sawc/` moved aside, apart from what unit 3 owns.

**Depends on:** SL-655 (the snapshot module), which is in the gate.
