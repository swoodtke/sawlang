**A pool whose every worker waits in place can starve an unbound runnable task that would unblock them.**

**The probe:** the reviewer's `allinplace_unbound_t2.saw` (SL-1161.p1 r5 review). Both workers of a two-worker pool wait in place for a `Task.spawn` child. The child's only sender is a third pool task, not bound to any worker, which never gets a worker.
- It times out 20/20 on SL-1161 r4, 20/20 on r3, and 10/10 on v0.24.3, so it predates SL-1161.
- It completes with a third worker.

**Not SL-1179:** a runnable frame exists here, so this is starvation, not a deadlock.

**The direction** (unruled): an in-place wait on a worker also runs ready UNBOUND slots of its pool, not only the ones bound to it. That is SL-1161's `resume_bound` widened, subject to SL-1161 r6's lock-window rule.
