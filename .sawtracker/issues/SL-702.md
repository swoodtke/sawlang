**S3. Vector's missing methods in the new std** (unit of SL-596; Sonnet tier, user Oct 15).

- **Plain methods**, ported from `sawc/std/vector.saw` under the current API rules (checked accessors panic out of range; allocating calls return `Result<_, AllocError>`; design 234's `try_` means non-blocking only): `sort` (on `T: Comparable + Copy`), `swap`, `swap_out`, `try_copy`, and anything else the corpus reports missing from `Vector` (`awk` over `corpus_diff.tsv`'s "has no method" rows), except `iter`/`enumerated` (S4).
- **Closure methods:** `each`, `map`, `fold` and `each_indexed`, which take closure parameters. A closure capturing an owning value isn't in sawc2's backend yet (SL-525). Port them, and pin them with callers that capture nothing or capture by reference; a caller that needs an owning capture stays refused, named in the report.
- **Blocks:** `sort` 7 programs, `each` 4, `swap`/`swap_out` 3 each, `try_copy` 2 (main's baseline, Oct 15).
- **Pins:** run programs for each method, matching Stage 0, plus the out-of-range panics; and the re-measured corpusdiff baseline (SL-666).
- **Later batch, same unit or S3b:** the small `String` (`scalars`, `bytes`, `to_uppercase`, `to_int`) and `Data` (`len`) methods the baseline reports missing.
