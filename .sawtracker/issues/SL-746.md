## Description

**gmgate fails on main: seven programs it lists as `Blocked` now build** (found by SL-712's gate; confirmed by the lead on main 5a2c99f5e).

`tools/gmgate.py` lists them as blocked, but main's `corpus_diff.tsv` has each one at `pass`. They are `df139a_copy_then_overwrite`, `repeat_literal_implicit_copy`, `set_algebra_owning_balance`, and four `df151*` programs. SL-710 (collection literals) and SL-711 (scalar hooks) unblocked them. gmgate fails a blocked entry that builds, so the lane is red on main. The server's per-patch gate doesn't run gmgate, so nothing caught it.

**Fix (mechanical):** move each one from `Blocked` into gmgate's guarded twins, run under Guard Malloc. If any faults there, that is a real finding: stop and file it rather than keep it blocked. Gate: `battery.sh gmgate citations`.

**Structural note:** a patch that moves a corpus verdict to `pass` can leave a gmgate entry stale. If moves like this keep recurring, the corpusdiff gate (or `patch_gate.py`'s SUITE_INPUTS) could cross-check gmgate's `Blocked` list against the baseline cheaply.
