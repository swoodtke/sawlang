## Description

**sawc2 accepts a plain getitem of a NoCopy or ExplicitCopy element in a rendering or comparison position, which SL:borrowing refuses (D29).** Found by the Air (chat, re m417) with probes on batch B1's build.

**The rule (D29):** a plain `v[0]` is a value read in every position, getitem per §5.1, because anything that looks like a copy is a copy (§1). The in-place read is spelled `borrow` (§2.2): `print(borrow v[0])`, `"{borrow v[0]}"`, `borrow v[0] == borrow w[0]`. sawc2 already parses and typechecks all four `borrow` forms.

**Today:** with `Res: NoCopy, Printable, Equatable` in a `Vector<Res>`, sawc2 accepts all of these, treating each as a borrow where it sits:
- `print("{v[0]}")`, `print(v[0])` and `print("{}", v[0])`;
- `v[0] == w[0]`.

Stage 0 accepts them too.

**Owed:**
1. **Name the mechanism:** the "a position that keeps nothing is a borrow" classification in typecheck. Route every rendering and comparison position through the getitem rule:
   - interpolation holes;
   - `print`/`panic`/`assert` arguments and `{}` format arguments;
   - `==`/`!=`/`<` and the other comparison operands;
   - `match` literal comparisons, if they read a place.
2. **Refuse** a plain getitem of a NoCopy element, and an ExplicitCopy one without `.copy()`, in those positions. The fix-it names the `borrow` form.
3. **Copy-tier elements are unchanged.**
4. **Differential:** put any Stage 0-accepted tests/corpus program it refuses in the differential, classed as "language changed".
5. **Pins:** one refusal fixture per position, plus the accepted `borrow` forms.

Typecheck, batch B2 beside SL-483.

One more position for this issue, found reviewing SL-482.p1. It's the same mechanism with a wider scope: **a member hop off a plain subscript is read in place.**

SL:borrowing §5.2's Ruled "Field reads of a derived getitem" says `PROCESSES[p].state` is "a getitem of the whole element followed by a field read". The field-only lowering is allowed only when copying the element runs no code. SL-482's "Value reads" table lists `v[i].field` as a value read: an error for ExplicitCopy and NoCopy.

**sawc2 on main** b163513d (`.build/scratch/air-review/sl482/agent/p14b_value_reads_more.saw`, `--std-root std`):
- **accepted:**
  - `v[0].id` and `v[0].m()` on a `Vector<Res>` with `Res: NoCopy`;
  - `v[0].len()` on a `Vector<Vector<Int>>` (ExplicitCopy);
- **refused:** only `let e = v[0]` (`transfer.implicit-copy`).

So besides rendering and comparison, the fix needs the member positions: a field read, a method call (`&self` included, since §1 makes the spelling, not the callee, decide), and a chained hop (`v[0].a.b`). The spelled form `borrow v[0].id` stays the in-place read. The Copy-tier and trivial rows are unchanged, with the field-only lowering when the element's copy runs no code.
