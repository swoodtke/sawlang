## Description

Unit 1 of the self-hosted compiler epic. Read the epic, SL:architecture (§3.0, §3.1 and §4) and SL:hazards first.

## Goal

The `compiler/` directory exists and builds with the frozen compiler (Stage 0). It holds the lexer, with a driver binary that dumps tokens, golden token fixtures, a test runner, and the subset checker. `./build.sh test` is path-aware. The syntax diff lanes that the golden fixtures replace are retired.

## Rulings this unit implements (user, Sep 25)

- `compiler/` at the top level, one directory per stage.
- The lexer moves in from `selfhost/lexer`. `prototypes/minivm` stays where it is, paused.
- Internal tests until self-hosting: golden dumps, plus small subset programs the frozen compiler builds.
- The per-patch gate is path-aware.
- The syntax diff lanes retire into a one-time golden snapshot.

## Work

### A. Layout and build
- `git mv selfhost/lexer compiler/lex`, so its history follows. It stays a package the other stages import through `--module-path`. Keep its package name unless a rename is clearly better, and say which you chose. Re-point `prototypes/minivm`'s `--module-path sawlex=selfhost/lexer` (its README and the battery `minivm` lane) so it still builds.
- `compiler/driver/`: the compiler binary, named `sawc2` for now (provisional). Its first subcommand is `sawc2 lex [--docs] <file>`, which emits the lexer's existing canonical dump format. It absorbs `sawlex`'s CLI, so there is one entry point, not two.
- One build entry (a small script, or a `build.sh` subcommand) that builds `sawc2` with the frozen compiler and the right `--module-path` flags. Output goes to `.build/`.

### B. Tests
- **Unit programs:** the lexer's `tests/*.saw` move with it. Each is built by the frozen compiler and passes by exiting 0.
- **Golden token fixtures** in `compiler/tests/lex/`: an input `.saw`, its expected `.tokens`, and a `.docs` expectation where doc trivia matter.
  - Choose the fixture set so that every token kind and every lex-error kind appears at least once. Take the fixtures from existing tracked `.saw` files and the lexer tests' inputs.
  - Snapshot procedure: generate each expectation with `sawc2 lex`, confirm it is byte-identical to the Python lexer's dump (the machinery `tools/lexdiff.py` uses), then commit.
  - Before retiring lexdiff, run its full sweep over every tracked `.saw` once, and record the result (it should be zero mismatches) in your report.
- **Coverage check:** the runner fails if some token kind appears in no fixture. Get the list of kinds from the lexer itself (for example a `sawc2 lex --kinds` subcommand), not from a hand-kept copy.
- **The runner**, `compiler/tests/run.py` (Python is fine for now):
  - it builds `sawc2` and the unit programs with the frozen compiler;
  - it runs the unit programs, the golden fixtures and the subset checker;
  - its output is deterministic, it prints one summary line, and it exits nonzero on any failure.

### C. The subset checker
- A tool under `compiler/` that refuses subset violations in the compiler's own source. It covers every `compiler/**/*.saw` except test fixtures (`compiler/tests/**`, which hold arbitrary Saw) and `*.test.saw`.
- Implement the syntactic rules from SL:architecture §4's blanket list, plus the SL:hazards entries whose Checker line says `yes` and whose check is cheap. Add an **import allowlist**: the std modules the compiler may import, starting with what the lexer and driver need. The allowlist keeps the compiler's std cone small for the bootstrap std unit.
- Parsing the source with the frozen compiler's own front end (for example `--emit-ast`) is fine, and it is more robust than regexes. Each diagnostic gives `file:line`, the rule's name, and the SL:hazards entry or §4 rule it enforces.
- **Self-test:** a fixture per rule that the checker must refuse, and a clean fixture it must accept.
- If the moved lexer violates a rule, bring the lexer into the subset. List every change in your report. Never weaken a rule to fit the code.

### D. The path-aware gate
- `.sawtracker/tests.json` runs `./build.sh test --changed-since HEAD^`. The server tests the applied commit, whose parent is the patch's base. Without the flag, `./build.sh test` runs everything.
- It always builds and runs the compiler tests. It runs the Python suite (`test_runner.py`) and `tools/freestanding_runner.py` only when a changed path is one those suites depend on. Derive that set from the two runners (for example `sawc/`, `examples/`, `libs/`, the runners themselves, `build.sh` and `.sawtracker/`), and list it with a comment saying why. If the changed paths cannot be determined, run everything.
- Keep the suite lock around everything the gate runs. Print which parts ran and why.
- Add a dry-run flag that prints the decision for a given diff. Use it to show a compiler-only diff skipping the Python suite, and a `sawc/` diff running it.

### E. Battery
- Remove the `lexdiff` and `selfhostlex` lanes. The compiler tests replace them.
- Add a `compiler` lane that runs `compiler/tests/run.py`, and keep `minivm` building from the new path.
- Delete `tools/lexdiff.py` after the snapshot. Delete `tools/dump_tokens.py` too, unless something else still uses it; check `astdiff` and the rest of `tools/`.

### F. Docs
- `compiler/README.md`: the layout, how to build and test, the subset and its checker, and pointers to the SL docs.
- `CLAUDE.md`: the repo map entry, the gate policy, and the retired lanes.
- `TESTING.md`: the compiler tests.
- Follow CLAUDE.md's rules for code comments.

Why SL-399.p1's server gate failed (claude-air-sawlang, reviewing). The patch's code is not at fault. The Python suite (2,661 passed) and freestanding (36) are green, and the 18 compiler-test failures are one whitespace problem.

**What fails.** Every failure is the last record of a golden file:
- `sawc2 lex` prints `EOF\t6:1\t`, with a trailing tab for the empty text field;
- the server's copy of the fixture ends `EOF\t6:1`, with no tab.

The `--docs` case is the same thing for a doc record with empty text (`DOC\t8:1\tdoc\t`).

**Why.** The submitted diff has the tab (`+EOF\t6:1\t`). The server applies patches with `git apply --3way --index` (sawtracker `store.saw`, `apply_in_worktree`) and no `--whitespace` flag, so git's config decides. The global git config on the Air has `apply.whitespace = fix`, and very likely the Studio's does too: same user, same setup. I reproduced it locally:
- `git apply --3way --index` of this exact diff onto origin/main strips the tab, and `comments.tokens` ends `EOF\t6:1\n`;
- the same diff applied with `--whitespace=nowarn` keeps it, and `compiler/tests/run.py` is then green. My review run gave `compiler tests: ok`, and the battery's `compiler`, `minivm` (446 cases) and `citations` lanes all pass.

**Fixes.**
1. **In this patch (suggested):** make the canonical dump never end a record in whitespace, and regenerate the affected expectations. A record whose last field is empty (EOF's text, an empty doc line) should omit the trailing separator, or the empty field should be escaped. A fixture format with significant trailing whitespace is fragile in general: editors that trim on save, `git apply --whitespace=fix`, and review tools all remove it silently.
2. **In sawtracker (worth an ST issue):** apply with an explicit `--whitespace=nowarn`, so the tested and merged tree is byte-for-byte the reviewed diff. Today, any added line ending in whitespace is merged differently from how it was reviewed. That includes Markdown hard line breaks (two trailing spaces), and expected-output lines with trailing spaces.
