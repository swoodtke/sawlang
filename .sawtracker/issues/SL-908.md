Found by SL-906's sweep (p906; probes `synth_writes_self.saw`, `synth_writes_self_uaf.saw` and `for_grow_alias__A` in its scratchpad). SL:borrowing §4: `@synthesize(shared)` derives the `(&self) borrows -> &T` twin by TYPECHECKING THE SAME BODY AGAIN under the shared signature, so a body that writes `self` is refused. sawc never does: it emits only the `receiver exclusive` instance and calls it from shared positions.
- An accessor whose prologue writes `self` is accepted; a read through a `&H` parameter mutates a `let h`.
- Two shared windows of an accessor whose prologue pushes onto `self.v` give a heap use-after-free on a `let` root.
- A synthesized `func cur(&var self) borrows -> CurX` with a `&var` field passes (the hand-written `&self` twin is refused `lends.origin`); under a `for` head it charges the root shared while `next` writes, and faults under ASan.

**The fix:** really derive and typecheck the shared twin (the §4 rule), and emit and call it from shared positions. std's `borrow var` arms in synthesized bodies (`map.saw` `find`/`[]`, `json.saw` `as_array`/`as_object`) must read as the lent type there (§2.7). **Obligation 4:** every `@synthesize(shared)` in std and the tests, plus probes of a prologue/epilogue write, a nested lend, and a borrowing-struct return. Conformance row first.

**Air, IR evidence for SL-908 (main d13e8e6e8), and a check for its fix.** `n1_two_shared_lends.saw` has `borrow let a = v[0] { borrow let b = v[1] { print(a, b) } }`, two legal shared lends of `Vector.[]` open at once. At -O0 both calls are to the one instance:

```
call ptr @"saw prologue std.vector.Vector.[](index: Int) receiver exclusive args Int std.alloc.GlobalAllocator"(ptr %t10, i64 0)
call ptr @"saw prologue std.vector.Vector.[](index: Int) receiver exclusive args Int std.alloc.GlobalAllocator"(ptr %t13, i64 1)
define internal ptr @"saw prologue std.vector.Vector.[](...) receiver exclusive ..."(ptr noalias %p1, i64 %p2)
```

No shared instance exists. Vector's prologue only reads `self` and LLVM's `noalias` scope is the call, so this is harmless today. But it's the same path SL-908's writing prologues take: an exclusive instance, `noalias`, run from a position whose root holds other live lends.

A cheap pin for the fix: shared positions call a `receiver shared` instance, and the shared instance's `self` is not `noalias`. That pin answers "is the shared twin really emitted and called" without needing a fault to show it.

This also narrows my SL-903 c2 remark that "`noalias` is correct for it". That holds for SL-903's accessors, which have no shared form and are charged exclusively, not for a `@synthesize(shared)` one.
