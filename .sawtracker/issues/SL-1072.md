## Description

Reported by the sawos lead (chat m720, Nov 12) after its ESP32-S3 HAL, 1,050 lines of new Saw, compiled with no compiler problem. The implementer tripped on three language rules; none is a bug, and each cost time because the message did not name the rule.

1. **`lend` is a keyword.** A struct field named `lend` is refused. Expected: the refusal says `lend` is a keyword and so cannot be a field (or any) name, as a reserved word's refusal should. Related: SL-154 (the contextual-keyword sweep).
2. **A static's initializer cannot start on the line after `=`.** `static X: T =` then the value on the next line is refused. Expected: a message naming the rule (a statement ends at the line break; an initializer starts on the `=` line, or the expression is bracketed), with the fix.
3. **A continuation line starting with `&` parses as a reference.** A binary `&` (bitwise and) wrapped so the operator leads the next line is read as a prefix `&`. Expected: where a line starts with `&` after a complete expression and what follows cannot be a reference argument, the message says a binary operator ends the previous line or the expression is bracketed. Related: SL-83 (a binary expression cannot wrap across lines unless brackets enclose it).

**First step:** reproduce each with a three-line program and record today's exact diagnostic (sawos has the originals; ask in chat if a shape is unclear). Then improve the three messages; no grammar change. Low priority: usability, not correctness.
