**sawc2 typecheck accepts a repeat count or an array length that folds negative, and a constant index outside a fixed array's length.** Found by SL-710's sweep: once the backend lowers fixed arrays, these reach it.

**The spec and Stage 0.** LANGUAGE_SPEC (Composite Types): "A length that folds to a negative number is a compile error". Stage 0 refuses `[0; 3 - 5]` (`repeat count is negative (`-2`)`), `struct Bad { bytes: [UInt8; 2 - 3] }` (`array length is negative (`-1`)`) and a constant index past the end of a fixed array (`array index 5 out of range for array with 3 elements`).

**sawc2, probed at SL-710's branch** (worktree agent-a6f098c61bce625db):
- `tests/corpus/repeat_literal_negative_error.saw` (`let xs = [0; 3 - 5]`) typechecks, and the backend lays out `[Int; -2]` as `alloca [-16 x i8]`, which clang rejects (`expected number in address space`): corpusdiff bucket `link`.
- `struct Bad { bytes: [UInt8; 2 - 3] }` in a program that never builds a `Bad` compiles and runs.
- `tests/corpus/array_const_index_out_of_bounds.saw` (`print(arr[5])` on a 3-element array) builds; its run panics `array: index out of range: 5 (len 3)` (safe, but a refusal test accepted): corpusdiff `wrong / accepts a refusal test`.

**Mechanism (UNVERIFIED which funnel):** typecheck folds array lengths and repeat counts (design 148) but checks neither the folded value's sign nor a constant index against the folded length; `grep "is negative\|out of range for array" compiler/typecheck/src` finds nothing. The positions to sweep: an array type's length at every position a type is written, a repeat count, a const generic argument used as a length, and a constant index (read, write, compound, `&`/`&var` of an element, `swap`).

**Pins:** the two corpus programs above, which move to `pass`, and the corpusdiff baseline.
