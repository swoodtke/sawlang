## Description

# U5a: the std cone of the self-hosted compiler: a tool, a lane, and the cone's hazard review

- **Epic:** SL-398, unit 5, the bootstrap std.
- **Design:** SL:architecture §4, "The bootstrap std". Read it before starting.

The cone is the **resolved transitive dependency set** of the compiler's build, not its import list. It includes:
- the std modules the source imports;
- the prelude and builtins the source uses without importing (`Vector`, `String`, `Optional`, `Result`, `Map`, `StringBuilder`…);
- what those modules import in turn;
- the calls the compiler synthesizes: interpolation's builder, the panic and bounds-check seams, drop and copy glue, and the `Result`/`Optional` machinery.

This unit makes the cone a measured, reviewed fact. It is the input to the new std, unit 5 proper, and it scopes the bootstrap slice (unit 6).

## 1. The tool (`compiler/tools/std_cone.py`)

- **Compute the cone from a real Stage 0 build of sawc2:** the frozen compiler building `compiler/driver` as `compiler/tools/build.py` does. The output is **declarations**, not files: every std type, function, method, extension member, trait and static that the build reaches, keyed by `(module, qualified name)`.
- **Choose the method that sees everything the backend emits.** Instrumenting the frozen compiler in-process, as `compiler/tools/migrate` does for sawc's front end, is allowed. So is walking the typechecked, monomorphized program, or reading the IR's defined symbols back to std declarations. Editing `sawc/` is not allowed.
- **State which method you used and what it can't see.** Synthesized calls must be in the cone. Show, with a probe, that interpolation, a bounds check, a drop and `?` each add their std declarations.
- **Write `compiler/tools/std_cone.txt`:** one line per declaration, sorted and deterministic, run to run and hash seed to hash seed. Group the lines by module, with a count per module.

## 2. The lane

`compiler/tests/run.py`, or a battery lane if the build is too slow for `run.py`, recomputes the cone and fails when it differs from `std_cone.txt`.
- **It fails in either direction:** a declaration the build reaches that the file doesn't list, or one the file lists that the build no longer reaches.
- **The failure message** tells the author to review the change, rerun with `--write`, and commit the file.
- **Report the lane's time.** If it can't run per commit, say where it runs instead.

## 3. The hazard review

- **Review the cone's `sawc/std` bodies once against SL:hazards** (`~/bin/sawtracker doc show SL:hazards`), as §4 requires. These are the bodies Stage 0 compiles into sawc2.
- **For each declaration**, record which hazard shapes its body contains.
- **Then run the subset checker's rules over those bodies.** Each rule that fires gets a listed exception naming the declaration and why it is safe here. That list is a **trust obligation** register.
- **Write it to `compiler/tools/std_cone_review.md`:** the method, the table, and each obligation.
- **Don't fix `sawc/std`.** It is frozen, and a real defect found here becomes an SL issue for the new std.

## Rules
- **Allowed files:** `compiler/tools/`, `compiler/tests/`, and `compiler/README.md` for the tool line. Don't touch `compiler/parse/` or `compiler/tests/grammar/` or `compiler/tests/parse/`; SL-440 is working there.
- **`sawc/` is frozen.**
- **The tool is Python test tooling** (the second tier, SL:architecture §5).

## Gates
- `compiler/tests/run.py` per commit.
- Before reporting, `battery.sh compiler citations` under the suite lock.
- `git diff --check`.

## Report
- the commits and tip;
- the method, and what it can't see;
- the cone's size, by module;
- the synthesized-call probes;
- the lane and its time;
- the review's summary, with obligations by hazard;
- anything in the cone that surprised you, such as a module you wouldn't expect a sync compiler to reach;
- the diff size.

Comments on the U5a brief before the agent gets far. The shape is right. Four points.

1. **The runtime is compiled into sawc2 too.** Every hosted build links the Saw-authored runtime objects that Stage 0 builds from `sawc/rt/common/*.saw` and `sawc/rt/host_macos/*.saw` (`--runtime-build`, cached under `.build/rt/`). They are linked whole, as separate objects.
   - **What that means for the cone.** A method that reads sawc2's own module never sees their bodies. That includes the ends of the panic and bounds-check seams the brief lists as synthesized calls.
   - **Why it matters.** §4 reviews "the bodies Stage 0 compiles into the Stage 1 executable", and that description fits these objects as well.
   - **What to ask for.** Either the cone covers them (by object, or by the seams sawc2 calls), or the report names them as a stated gap.
2. **Several hazard faces depend on the instance, not the body alone.**
   - **Examples:** S3's leaked error under `try?` exists only when the error type owns memory, and S23's owned-operand leak only when the operand's type does.
   - **The gap:** a cone keyed by `(module, qualified name)` drops the type arguments.
   - **The fix:** for each generic declaration, record the type-argument tuples sawc2's build instantiates it with. Walking the monomorphized program gives them for free. The review can then judge each such face against the instances that actually exist.
3. **If the tool reads IR symbols, read the unoptimized module.** Once O1 inlines a small std function, it can leave no defined symbol, even though its body is compiled into sawc2. So a symbol-based cone taken after optimization undercounts.
4. **Keep the hazard rules apart from the discipline rules.** In `RULES`, some rules cite an SL:hazards entry (`raw-pointer` cites C1, `cell-type` S11 and S15, `owned-operand` S23, and so on). Others cite only SL:architecture: `import-allowlist`, `std-api`, `borrows-accessor`, `borrow-syntax`, `test-directive` and `closure-capture`.
   - **Why they differ.** The architecture-only rules encode the compiler source's own discipline. Over std they fire by design and say nothing about a Stage 0 defect.
   - **The risk.** If the register lists both kinds alike, the obligations that matter get lost.
   - **The suggestion.** Give each hazard-rule firing its per-declaration reason, and summarize the discipline firings by rule.
   - **One exception.** `sync-only` belongs with the hazard rules here, because a suspending std body in the cone would bring the coroutine transform into sawc2.

SL-441.p1 is up: U5a, the std cone of sawc2 (brief, with c1). It has 3 commits and touches 6 files (+1910/−4). The review found no defect in any cone body.

**Method.** `compiler/tools/std_cone.py` runs the frozen compiler in a child process, on exactly `build.py`'s build of sawc2. It does the same for each of the 13 runtime sources a hosted link adds (`rt/common`, `rt/host_macos`, `--runtime-build`), so c1's point 1 is covered.
- **Hooks.** Only in that process, it wraps codegen's body generators and static emission. It stops once the **unoptimized** module exists (c1's point 3). `sawc/` is never edited.
- **Tracing bodies to declarations:**
  - by source position (an instance keeps its template's);
  - trait defaults through the conformance;
  - synthesized methods by owner and name;
  - closures by symbol prefix.
- **Reach:** a declaration is in the cone when `main` reaches it in the unoptimized symbol graph, crossing into the runtime through the seams it exports. The set is then closed over the std types and traits the reached bodies name.
- **Instances** (c1's point 2): each generic declaration records its type-argument tuples. A compiler-source type is written as `(owning)` or `(plain)`; `--instances` prints full tuples.
- **Determinism:** identical output across three hash seeds and with `SAW_NO_STDCACHE=1`.
- **Other modes:** `--why TEXT` prints the reach path, `--entry FILE` gives another program's cone, and `--rules` runs the subset rules over the cone.
- **Blind spots, stated:**
  - Code the compiler emits inline is listed by helper symbol: Optional/Result, `?.`, `??`, `try`, interpolation, print and bounds checks.
  - `shim.c` and libc are listed but not reviewed.
  - `host_linux` is not covered, since the target is pinned to `arm64-apple-darwin`.
  - Declarations used only at compile time appear only when an emitted body names them.
  - Reached doesn't mean executed.

**The cone: 250 declarations in 19 modules.**
- builtin: 13.
- runtime: 51 (`mem` 6, `os_ops` 8, `net_os` 37).
- std: 186 (taskgroup 44, data 27, stringbuilder 26, string 18, file 13, vector 10, arc 9, net 9, alloc 8, env 8, scalar 8, path 3, box, compiler.frame and task 1 each).
- Also 15 compiler-emitted helpers, and 19 external C symbols (3 of them `shim.c`).

**Synthesized-call probes** (with and without, via `--entry`):

| construct | adds |
|---|---|
| interpolation | +20: the compiler's string helpers, `rt_alloc`/`rt_dealloc`, `snprintf`/`strcat`. Stage 0 doesn't use std's StringBuilder for it. |
| bounds check | +75: `__saw_bt_panic` and the whole backtrace walk in `std.taskgroup` |
| drop | +82: `Vector.deinit` and `GlobalAllocator.dealloc`, which no source line names |
| `try`, `?.`, `??` | +0: Result and Optional are built into Stage 0 |

**The lane.** `run.py` calls `std_cone.check()`, which fails in either direction and tells the author to review, `--write` and commit. It takes about 7 s (14 observers in parallel), so it runs per commit.

**The hazard review** is `compiler/tools/std_cone_review.md`. Hazard rules get a per-declaration reason, and discipline rules are summarized (c1's point 4).
- **Owned temporaries and coroutines:** `owned-operand` finds 0 sites in sawc2's build. The frame ledger shows 0 frames and 0 suspension sites.
- **C1, raw pointers (96 declarations):** each is kept sound by its owner's invariant: Vector's bounds, StringBuilder's `_reserve`, Data's `_make_ready`, `String.byte_at`, Arc's control block and the backtrace table. No `move *p`.
- **S1:** `Vector.init()` takes no parameter. `Arc.init(value:)` places its argument, and a probe showed a NoCopy payload dropped exactly once.
- **S3:** only `try` over `AllocError`, which owns nothing. There is no `try?` and no `catch`.
- **S2, S4, S5 firings:** each is explained: owned call results, Int or Byte arguments read before the borrow, and a misread `&var` closure parameter.
- **S10, S12, S13, L8:** only TaskGroup's field types, and no TaskGroup is ever constructed.
- **S11/S15:** Arc drops its payload (probe). The Atomic statics are used only by name.
- **S18, sync-only, the 5 `deinit`s and the loud entries** are each explained.
- **Discipline rules** (`std-api` 59, `closure-capture` 4, `borrows-accessor` 2) are summarized by rule.

**Findings for the new std** (unit 5 proper). These are design inputs, not defects:
1. **The panic seam pulls in the task executor's backtrace code.** Every panic or bounds check reaches `__saw_bt_panic`, which brings in 44 `std.taskgroup` declarations, `TaskGroup`, `VoidThread`, `Box<any Resumable>` and Atomic statics. At run time the walk finds no groups. A sync compiler's panic path shouldn't need the executor.
2. **`Data` writes through `Arc.with_unique`,** which SL:borrowing retired in favour of `arc.unique()`. `File.read` returns Data, so the new std's Data needs the unique lend.
3. **`std.net` comes along with `std.file`** through `IoError`, bringing the errno table and a pthread-keyed slot.

**Readings (reversible):**
- The target is pinned to `arm64-apple-darwin`, so the file is host-independent. The Linux runtime is out of the cone.
- Compiler-source types appear as `(owning)`/`(plain)` classes.
- `--rules` attributes each firing to a cone declaration or to an extension head of a cone type.
- The runtime is covered through the seams reached. `owned-operand` doesn't run over runtime bodies; they were read by hand.
