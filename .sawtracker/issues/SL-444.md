## Description

These are two small items from the Air's review of SL-442.p1 (non-blocking), both low priority.

**1. `cases.py`'s double-refusal check needs a whole-file tree** (`Expectations.refused_once`). So any second error anywhere in the file makes a doubly-refused text recordable again. Three examples, where sawc2 names block-tail each time:
- `while { a } + (while { b } { }) { }` followed by a line `let = 1`: the check records infinite-loop at 2:17;
- the same text with a juxtaposed `9` on its line: infinite-loop at 2:17;
- the cast shape with a `9`: cast-target-question at 2:28.

A negative case holds only one error, so the corpus is safe today.
- **Fix:** look at the tree of the statement or item that holds the deciding token, instead of the whole file.
- **Pin:** the three texts raise Problem.
- The Air's probe is in `.build/scratch/air-review/sl442/cases_gap/`.

**2. A doc run placed between an attribute and its declaration** keeps "documents no declaration" with the hint "move it before a declaration". Two examples:
- `@synthesize`, then `/// two`, then `extension P: Equatable {}`;
- the third run of `/// one`, `@test`, `/// two`, `@export("f")`, `/// three`, `func f() {}`.

The recognizer, the frozen parser and `test_parse.py`'s existing `@export`/`/// d` pin all agree that such a run documents nothing. But the hint points the wrong way, since the run already sits just above the keyword.
- **Fix:** the hint says "move it above the attributes". §2.6 also states outright that a doc comment placed after an attribute documents nothing. §2.6 already says attributes between a comment and its declaration don't matter.
- Update sawc2's hint and the recognizer's detail together, with pins.

One implementation note for item 1.

Take the statement's derivations from the whole file's chart, with every removed production enabled: the complete `statement` or item derivations whose span holds the deciding token. Don't re-lex and re-parse the statement's text on its own. A statement cut out of its file loses what surrounds it:
- the closure or accessor body it stands in (`lend` is legal only in one);
- a head it sits inside;
- its positions, which the step-1 `at` check compares.

With the deciding token inside a closure body, as in `let g = { while { a } + (while { b } { }) { } }`, the innermost statement holding the token is the inner `while`. Its derivation already contains the whole doubly refused reading, whatever else in the file fails to parse.
