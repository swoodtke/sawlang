## Description

**A freestanding runtime owns the background group, so `Task.spawn` works freestanding.** Ruled by the project owner (Nov 16, in the lead's session, on SL-1143's Q1): design it with the sawos lead; once the runtime contract exists, `Task.spawn` is allowed freestanding.

**Today:** `Task.spawn` spawns into the calling thread's background group, built lazily by `__saw_exec_background()` and closed by `__saw_exec_close_background()` (`std/taskgroup.saw`; ABI.md's executor entry-point table), which hosted code calls at `main`'s return and at the end of each `Thread.spawn` body. Freestanding, `Task.spawn` is refused (SL-1143 keeps it refused, with a reworded message), because an `@export` can run outside `main` (an interrupt handler, a callback after `__saw_main` returned), where nothing would close the group.

**To design:**
- The runtime's contract in `runtime/ABI.md`: a close entry the runtime calls when a process/thread ends (and a C-ABI name for a C crt.o), and a **drive** entry: a task spawned from an export sits in the queue until something runs the executor, and closing alone cancels it before it ran, so its work is silently lost (never hide errors). When the runtime may call drive (idle loop, scheduler tick; never from an interrupt handler), and what a runtime that provides neither gets (refused at compile time by a declaration, or a link error naming the entry).
- How a runtime declares that it provides the group, and `Task.spawn`'s refusal keyed on that rather than on the profile.
- sosrt's side (SO-124's neighbour): what it calls and when; the suite's `fsrt`/`fsentry` doing the same, with cases (spawn from `main`, from an export then driven, closed at the end).

Lands after SL-1143 U1. Related: SL-1143, SO-124.

**The design pass is done (Nov 17; Opus, with a prototype): `.build/scratch/p1150d/design.md` and `proto.diff`, in the lead's checkout.** The sawos lead's answers on sosrt (chat m1236) are folded in.

- **Two compiler-defined entries** (like `__saw_main`; not `__saw_rt_*` seams; the runtime calls them), in a new `runtime/ABI.md` section "The background group":
  - `__saw_background_drive() -> Int64`: one bounded turn over the calling thread's cooperative tasks, never waiting (the reactor polled once with a zero timeout); at most one resume per task that can run, no more than were live at the start; answers -1 (nothing live), 0 (a task can run now), `INT64_MAX` (live tasks wait with no deadline), else the earliest deadline in monotonic nanoseconds. Allowed inside a task's turn (a nested sweep).
  - `__saw_background_close()`: cancel, join and release the calling thread's background group, as the hosted close; panics inside a task's turn or a drive.
  - Never from an interrupt or exception handler (the ABI says so; the compiler cannot check it). `__saw_main` still closes the group at `main`'s return.
- **How a runtime declares it owns the group (recommended):** a module compiled into the program declares both entries in an `extern "C"` block (the `__saw_main` pattern). Without both, `Task.spawn` is refused (`spawn.freestanding`, the message naming the two entries); a disagreeing signature is `extern.signature-disagree`; a hosted declaration is `extern.entry-hosted`; one entry alone `extern.background-incomplete` (designed, not prototyped). Weighed and set aside: a manifest key plus a sawc flag; a link-time marker (needs a new seam).
- **Prototype:** nine new freestanding cases (a start-up module `fsgroup` that runs `__saw_main`, an export, drives until idle, closes) pass on riscv32, arm64, xtensa and xtensa-windowed (36/36); the whole riscv32 row 63/63; run.py `typechecker,mono,programs` green; hosted programs' output, status and symbols unchanged; no new seam.
- **sosrt (m1236):** no idle loop or tick, so it drives before each blocking call (in its wrappers) and closes at each thread's end (SO-124's `_start` and thread entries). sosrt exports none of the freestanding executor set today, so any spawn in a sawos image already fails at link. Six questions for the sawos lead are relayed in chat.
- **Units:** U1 one patch (conformance K223 first, K87 extended; std, typecheck, mono, llvm; the ABI section; fixtures, a run-lane probe; the suite); U2 the spec; U3 the skill. Then sawos: the executor set in sosrt, SO-124's entries and declarations, the drive in the wrappers.
- **Owner questions** (asked in the lead's session): Q1 how strong the declaration is; Q2 whether `main`'s return still closes the group under an owning runtime.

**The owner's rulings on the design's questions (Nov 17, in the lead's session):** Q1 = **the declaration is enough** (both entries declared in an `extern "C"` block in a module compiled into the program; works for a Saw start-up and a C crt.o; the "declared, never driven" gap is the runtime's documented obligation in ABI.md). Q2 = **yes, as hosted**: `main`'s return still closes the group under an owning runtime; tasks spawned later from exports live until the runtime's close. U1 proceeds on the design as written; the sawos lead's answers to the six sosrt questions shape only the sawos side.

**sawos's answers to the design's six questions (chat m1241; their side is SO-141):** (1) drive in `sos`'s blocking wrappers: yes; (2) a Timer attached to the Waiter bounds the wait by the drive's deadline, an Event signalled by `reactor_wake` ends it: yes; (3) the declaration on the process side only, the kernel image keeps `Task.spawn` refused: yes; (4) the per-thread executor word is the architecture's thread register (riscv32 `tp`, the S3's `THREADPTR`; arm64's `TPIDR_EL0` joins the trap frame in SO-141); (5) SO-141 implements the freestanding executor set in sosrt, after SO-124 and after the sawlang release carrying SL-1150; (6) every thread returns through sosrt's entry, which calls the close; `Process.exit` not closing the group is acceptable. Nothing here changes sawlang's U1.
