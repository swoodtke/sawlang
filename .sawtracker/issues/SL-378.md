## Description

Found by the SL-340 implementer (Sep 24). The cell is `c14`, in `.claude/worktrees/sl340/.build/scratch/`.

A placement write of a by-value parameter through a pointer drops the value TWICE when the pointer is not a plain identifier:
- `(p + 0)[0] = value`, in a generic body, prints `drop placed-expr` twice. That is a double free for a heap-owning `T`.
- The `p[0] = value` form drops once, which is correct.

Mechanism (obligation 4, named by the implementer; verify in code): the placement bookkeeping in `codegen/statements.py` `_generate_assignment` clears the source binding's drop flag only when `stmt.target.array_expr` is an `Identifier`. Every other pointer spelling leaves the flag set, so the source is released at scope exit after its bytes were placed.

Positions to sweep, one row each, with a printing deinit counting exactly one drop:
- a method-call pointer: `self.cell.ptr()[0] = value`, which is exactly `Once.set`'s shape. `Once` itself is unreachable with an owning `T` today, because it is static-only and statics refuse Deinit payloads. A user cell-carrying type is reachable.
- pointer arithmetic: `(p + i)[0]`;
- a field pointer: `self.buf[0]`;
- an indexed pointer inside a struct;
- the non-generic twin of each;
- a moved local as the source, as well as a parameter.

The fix belongs in the one place that decides whether a placement write consumed its source, keyed on the SOURCE rather than on the target's spelling. Unsafe-domain code, but correct-looking code double-frees.
