## Description

**A `blocking` extern reached through a GENERIC BOUND inside a `Thread.spawn` body is refused** at the call by typecheck's `effect.closure-suspends` ("a closure body cannot suspend"), though a direct `blocking` call there is a plain call (SL-765 T3b's thread-body rule). Confirmed by T3b's agent (SL-765 T3 note 5).

UNVERIFIED: the fix needs the cause-carrying summary (SL-765 T1) to see through the bound at instantiation, plus mono's thread keying (`MONO_KEY_THREAD`, T3b) for calls through a bound.

Pin: a generic helper `<T: Blocker>` whose method is a `blocking` extern, called from a thread body: it runs as a plain call; the same helper from a task body is offloaded.

**What the IR shows, in g5:**
- `napped` gets its thread item, `saw …napped(ms: Int) thread`.
- That item calls `saw …nap_through(who: T, ms: Int) inst …Sleeper`, the plain name with no thread key.
- The only item emitted for that instance is `saw resume …nap_through(…) inst …Sleeper`. In an ordinary context its call offloads, so it's a frame.
- No `… inst …Sleeper thread` item exists, and no `Sleeper.nap … thread` either.
- Compare g8: there, `nap_generic … inst Bool thread` is both defined and called.

**So the description's premise has moved:**
- **Typecheck already sees through the bound.** g11 and g12 are refused when the implementation really suspends. g1 and g5 pass the thread-body check because the cause is a blocking extern. Nothing is refused at `effect.closure-suspends`.
- **The gap is mono's thread keying (`MONO_KEY_THREAD`).** My reading, unverified: the keying decision for a call to a generic instance comes from the generic's shape before instantiation, which suspends only through its bound. The resolved instance is a frame. The fix should key a thread-context call by the instance's resolved summary, and emit the instance's `thread` item along with the bound method it reaches (`Sleeper.nap … thread`).
- **This is worse than a refusal.** A program the checks accept ends in a clang error the user can't act on. The pin should be g5's shape at both levels, with g4 as the task-side control.

g3 (dynamic dispatch) and g7 (a function value) refuse cleanly under their own rules, so they're outside this class.

**SL-776.p1 submitted (agent p776, Opus; one commit, 639c1f604).** Both mechanisms from the sweep (c3) are fixed through one funnel, and a plain call to a frame-only item can no longer reach clang.

- **THE THREAD KEY FUNNEL, `callee_key`** (`compiler/mono/src/worklist.saw`), with ENTRY POINTS `resolve_call` (the Function and Default arms) and `resolve_window` (open and close). It decides from the resolved instance's causes through the new `instance_effect`: typecheck's call evaluation at the source, with each condition over the caller's type parameters answered at the item's concrete type by the public `eval_condition`. `compiler/typecheck/` is untouched. The same helper feeds `thread_plain_copy`, so a `When` call that is blocking-only at the instance is made plain, as `Always` already was. `substituted` is split out of `concrete_type` (no refusal, for a question-only type).
- **THE PLAIN-CALL FUNNEL, `LlEmitter.plain_symbol`** (`compiler/llvm/src/module.saw`), with entry points `call_term`, `call_item_direct`, `closure_into`, `string_comparison`, `string_bytes_of`, `string_length`, `thread_trampoline` and `vtable`. Naming an item that has a lowered frame becomes a `mono.problems` entry. It absorbs the old inline vtable check.
- **Pins (run lane, -O0/-O2, with `ll defines` lines):**
  - `thread_blocking_through_bound` covers g1, g5, s1, s2, s2b, s3, s5b and s7, with the s9 control and the task control, offloaded;
  - `thread_blocking_default_and_window` covers s8, s8b, s6 and s6b.
- **Refusal fixtures:** `effect.thread-body.bound` (g11), `effect.thread-body.dispatch` (g3), `effect.thread-body.closure-blocking` (s4) and `effect.sync.thread-closure` (s4b). g7 and s4c were already covered.
- **Filed SL-781:** interpolating a value whose `Printable.format` blocks fails in clang from a task as well as from a thread, a separate class. The guard now turns it into `INVARIANT mono a plain call names …format…`. It needs a ruling (refuse a suspending `format`, or render it through a frame).
- **Outside the brief's list:** one ENTRY POINTS line in `compiler/mir/src/build.saw` (`thread_plain_call` gains `callee_key`). Accepted.
