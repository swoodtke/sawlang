## Description

**`T()` through a type parameter is refused by mono when `T` is an allocator with fields or an `init`.** Found by SL-964's sweep while it was looking for an owned trigger for a refusal reached inside std.

**What happens:** `check_empty_construction` (`compiler/mono/src/worklist.saw`) refuses a `T()` construction through a type parameter unless `T` is an empty type. A generic std routine that builds its allocator this way is refused at mono when it's instantiated with an allocator that has fields or an `init`, for example `Vector<Int, A>` with such an `A`. Typecheck accepts the program.

**Expected:** decide whether `T()` through a type parameter is part of the language for non-empty types:
- **If it is**, mono constructs it: the default `init`, or a memberwise one with defaults.
- **If not**, typecheck refuses it at the bound, with a reason the reader can act on.

Either way, mono shouldn't refuse late what typecheck accepted.

**First step, per obligation 4:** census every position where a type parameter is constructed (`T()`, `T(...)`, a static on `T`) against the allocator and non-allocator types that reach it, with compile-and-run evidence.

SL-964 points its std-position refusal fixture at this gap as its owner until it closes.

# SL-966 census: `T()` through a type parameter (sweep agent, Nov 6; raw results in results.json, cells/, extras/)

**The headline:** typecheck accepts a zero-argument `T()` through a type parameter, checking no bound. Mono then refuses every instance that isn't a fieldless struct with no `init` (`mono.not-yet`, `compiler/mono/src/worklist.saw:2022–2054`). The spelling that works for every shape is a static requirement, `<T: Make>` with `T.make()`.

Edge shapes:
- `struct S { e: E }` with zero-sized E, and `enum S {}`: refused by mono, so an uninhabited value is never fabricated.
- Fieldless NoCopy with a `deinit`: OK.
- A generic with `T()` that is never instantiated at a non-empty type: OK. The refusal is instantiation-driven, against spec 12734–12738's "a generic body is type-checked once, abstractly, against its bounds".
- IR: `make<S>` is `alloca [0 x i8]` then `ret void`. Nothing is constructed.

## Spec and designs
- Nothing states whether `T()` on a type parameter is allowed. The spec's only `A()` is the allocator idiom:
  - 15935–15937: `GlobalAllocator` is a zero-field unit struct;
  - 15944–15956: "a custom allocator is written as a zero-field unit struct conforming to `Allocator`", and `A().alloc` is a direct static call.
- Design 19 (designs/19-freestanding-profile.md:82–114) decided on zero-sized, static-backed allocators and rejected stored allocator values. Design 37:32–34 calls `A()` a "zero-sized construction".
- Static requirements on a type parameter work: spec 2699–2727 and 8379–8385, and `std/serialize.saw:431,460`. SKILL.md:2198–2200 says they don't (DF-169e), which is stale.

## Std sites
There are 9 `A()` sites, all `A().alloc` or `A().dealloc`:
- `box.saw:23`, `42`

`Set` reaches them through Map. The erased-box glue builds `A()` with no source site (`mono/src/worklist.saw:2569–2585`). Std instantiates them only with `GlobalAllocator`. Every tracked `Allocator` conformer is fieldless with no `init`, except SL-964's fixture.

Non-allocator `T()` users:

- `tests/corpus/generic_instance_constructs_type_param.saw:45` (`M: Maker`);

## The mono check
`worklist.saw:2022–2054` passes only a `Struct` with no fields and no `init` of any arity. It is reached from `resolve_call` for a builtin `"init"`. Typecheck's `type_param_call` (`bodies.saw:7666–7692`) types `T()` as `T` with no bound check. LLVM emits nothing for it (`llvm/src/calls.saw:1461`). So the mono check is the only thing that stops a value with storage, or an `init` body, from being silently skipped.
