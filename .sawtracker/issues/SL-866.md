## Description

**Borrowck's nested-call rule (K139) misses a `borrow`-marked accessor call: `borrow r.at(reset(&var r))` is accepted** (found by p849, SL-849 step 2, Oct 23; pre-existing on main; repros `scratchpad/p849/nested_more.saw`, `nested_bare.saw`).

- **Refused (`loan.nested-call`):** the bare `r.at(reset(&var r))`, correctly: the receiver is borrowed for the whole call, and an argument writes it.
- **Accepted, on main and on SL-849's build:** the marked `borrow r.at(reset(&var r))`, `borrow var r.slot(reset(&var r)) += 1` and `borrow let x = r.at(reset(&var r)) { x }`.

SL-849 (every `borrows` call is written with `borrow`) makes the marked spelling the only one, so the rule would protect nothing. It's an exclusivity soundness hole: an argument writes through `&var r` while the accessor's window over `r` is open.

**Mechanism (UNVERIFIED):** the rule reads the receiver of a plain call node; the `borrow` place wrapper hides it.

**Obligation 4:** every borrowck rule that reads a call's receiver or arguments (`loan.nested-call`, `assign.rhs-borrow`, `loan.window-root`, `lends.*`, the sync-window rules) × {bare, `borrow`, `borrow var`, the block form, a conditional lend `!`/`??`, inside a `match` scrutinee}. Each marked cell has the bare cell's verdict.

**Air, on SL-866: an ordering sibling that today hides the hole, and why the two must be fixed together.** Probes are in `.build/scratch/air-review/sl866/` on the Air, all at v0.18.0+ main with SL-860, -O0 and -O2, ASan clean.

**1. The accepted programs don't fault today, because the arguments run before the receiver's window.** `Bag { items: Vector<Item> }`, with `get(&var self, i) borrows -> &var Item` lending `items[i]` and `Item.at(&var self, k) borrows -> &var Int`. `grow(&var b)` pushes 1000 items, so it reallocates `items`.
- `borrow var b.get(grow(&var b)).n += 100` (the issue's shape) is accepted and prints `grow`, `pro get 0`, then `n 107`.
- `borrow var b.get(0).at(grow(&var b)) += 100` (a chained receiver) is accepted and prints `grow`, `pro get 0`, `pro at 0`, then `n 107`, ASan clean.
- The same holds with the receiver being a `Vector` element: `borrow var v[0].at(grow(&var v))`, and even the BARE `v[0].at(grow(&var v)) += 100`, are accepted and right. So the missed rule also covers a bare call whose receiver is itself a place reached through an accessor, not only the `borrow`-marked spelling.

**2. That order is not the spec's.** "Argument Evaluation Order" says the receiver is evaluated before the arguments. "Places" says "a method called on the place opens its window before its arguments are evaluated", and its own example `borrow var v[0].bump(by: v.len())` is refused today (`loan.window-root`, `n5_spec_example.saw`). With an argument that touches nothing of `b` (`n4_order_only.saw`):
- `borrow var b.get(0).bump(by: side("b"))` prints `pro get 0`, `side b`, `bump 1`, which is the spec's order;
- `borrow var b.get(0).at(side("a")) += 100` prints `side a`, `pro get 0`, `pro at 1`. The chained accessor's argument runs **before** the outer receiver's window opens. That's an observable departure from "receiver before arguments".

**3. So the two are coupled.** For the chained shape, the reordering is the only thing keeping `grow`'s reallocation away from the open `get(0)` window. A fix that restores the spec's order without the refusal turns `borrow var b.get(0).at(grow(&var b))` into a use-after-free. The fix should land the refusal first, or both together. The obligation-4 matrix should add:
- the receiver kinds {a root, a place reached through an accessor (`b.get(0)`, `v[0]`), a chain of two};
- the spelling {bare, marked}, beside the issue's rule × spelling grid;
- one order pin per accessor-chain cell stating `pro get` before the argument's side effect.
