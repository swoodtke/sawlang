## Description

Found by the SL-340 implementer (Sep 24). Reproduces on main.

A bounded extension's method is instantiated for a type argument that does NOT meet the bound. `Vector<T>` is `ExplicitCopy` only when its element is, but `extension Box1<T: ExplicitCopy>`'s method is materialized for `T = Vector<Noisy>` where `Noisy` is `NoCopy`, and compilation fails inside the method body. So `Mutex<Vector<Noisy>>` does not compile: the failure surfaces from `Mutex`'s bounded `get`. SL-340's K170 had to use a NoCopy struct instead of a `Vector` of one.

```saw
struct Noisy { name: String }
extension Noisy: NoCopy {}

struct Box1<T> { v: T }
extension Box1<T>: NoCopy {}
extension Box1<T: ExplicitCopy> {
    func dup(&self) -> T { self.v.copy() }
}

func main() {
    var v: Vector<Noisy> = []
    let b = Box1(v: move v)
    print("ok")
}
```

Expected: `ok`. The bounded extension simply does not apply to `Box1<Vector<Noisy>>`.

Mechanism to confirm (obligation 4): the bound check behind extension applicability or instantiation answers from the type constructor's DECLARED conformance (`Vector: ExplicitCopy`) rather than the CONDITIONAL one (`Vector<T>: ExplicitCopy where T: ExplicitCopy`). Sweep:
- every conditional conformance in std (Vector, Map, Set, Optional, Result, Box, tuples, fixed arrays);
- every bounded-extension position: methods, statics, trait conformances;
- whether eager instantiation happens even when no method is called, as here.
