**sosimg: carry the four realtime bands' levels in the header (`reserved0` → `rt_map`), with `[sos] priorities` keys `rt0`–`rt3`.**

**Why.** sawos's scheduler has eight bands: Background, Low, Normal, High and Rt0 to Rt3. The sosimg header's `prio_map` holds only the first four, one byte each. A root image therefore can't put a thread above `High`'s level: the kernel maps Rt0 to Rt3 to `High`'s level when the header names none.

sawos's stock root needs a thread at Rt1 (level 5), above its console driver at Rt0 (level 4). That thread is a watchdog that takes the console back from a stalled driver (sawos design `SO:s3-uart`, rev 3.1).

**Asked:**
- `libs/imgformat`: `SosimgHeader.reserved0: UInt32` becomes `rt_map: UInt32`, one byte per band: Rt0 in the low byte, then Rt1, Rt2, Rt3. Zero means "no realtime levels named", which is exactly today's bytes, so existing images are unchanged. Whether that needs a `SOSIMG_VERSION` bump is yours to say. The word is padding today, so v3 readers ignore it.
- Blade's sosimg emitter: `[sos] priorities` accepts `rt0`, `rt1`, `rt2` and `rt3`, each checked against `0..PRIORITY_LEVEL_MAX` as the four existing bands are, and writes them to `rt_map`. Naming none writes 0.
- sawos's loader does the reading, on its side.

**Not urgent:** sawos's unit that needs it comes after the S3 UART driver's first units. Riding v0.24.5 or the release after is fine.

**Lead's ruling and brief (Nov 26).** Accepted as asked, with two points settled.

1. **No `SOSIMG_VERSION` bump.** An image that names no realtime level is byte-identical to today's (`rt_map` = 0). An image that names some, loaded by a v3 loader that ignores the word, gets today's behaviour (Rt0 to Rt3 at High's level). Nothing reads differently from what it read before.
2. **Partial naming.** When `[sos] priorities` names at least one of `rt0`..`rt3`, Blade writes all four bytes, and a band it doesn't name gets the `high` band's level (the level the kernel already gives it when the word is zero). So each byte means exactly one level, and a loader never has to tell "unnamed" from "level 0". When none is named, the word is 0.

**The work (one patch):**
- `libs/imgformat/src/lib.saw`: `SosimgHeader.reserved0: UInt32` becomes `rt_map: UInt32`, documented as `prio_map` is: one byte per band, low byte first, Rt0, Rt1, Rt2, Rt3; zero means none named and a loader gives each Rt band High's level. Rewrite the struct comment that calls `reserved0` the padding: the field still puts `entry` on an 8-byte boundary, and it now carries data. Its tests follow.
- `blade/src/sosimg.saw`: `priorities_from` reads `rt0`..`rt3` with `band_level` (same range check, same error spelling); one packing funnel produces the `rt_map` word under rule 2; it travels to the header where `prio_map` does (`elf_to_sosimg`, `write_sosimg` and their callers). The `[sos]` docstring that lists the priorities keys names the four new ones.
- Pins (`blade/tests/sosimg_wire.saw` and imgformat's tests): no rt key gives a header byte-identical to today's (offset 12 is 0); all four named; one named (the other three take `high`'s level, including a manifest whose `high` is itself set); an out-of-range `rt2` refused with the same message shape as the existing bands; the inline and `[sos.priorities]` spellings agree.
- Any user doc listing the `[sos] priorities` keys (grep `priorities` under `blade/` and `libs/imgformat/`) names the new ones.

**Gate:** `blade test` in `blade/` and `libs/imgformat`, plus run.py's `comments` step. The server runs the blade lane.

**Reviewer's note on c2's point 1, before the patch: an image that names a realtime level degrades silently on a v3 loader. A version written only then avoids it.**

- **The format's own contract.** imgformat's doc for `reserved0` says "Zero. Present so `entry` lands 8-aligned; a later version can spend it without moving anything" (`libs/imgformat/src/lib.saw`). `SOSIMG_VERSION`'s doc calls every bump a refusal boundary, and "A loader refuses anything it does not know".
- **The sawos loader checks the magic, the version (`has_known_version`) and the arch, and never reads `reserved0`** (`kernel/core/loader.saw` around the header checks). So an image whose `rt_map` puts the console watchdog at Rt1, above the driver's Rt0 (SO:s3-uart 3.1), boots on a v3 kernel with Rt0 to Rt3 all at High's level. The watchdog then no longer sits above the driver, which is the whole reason it is at Rt1, and nothing says so. That is a silent degradation of a stated guarantee.

**Suggested, keeping your point 1's byte-identity:** write `version` 4 only when `rt_map` is nonzero. An image that names no rt level stays byte-identical v3. A v3 loader refuses an image it would misread. A v4 loader accepts 3 and 4, reading `rt_map` as 0 under 3. One more pin: a manifest naming `rt1` writes version 4, and none named writes 3.

If the drop is meant to be acceptable, then say it in imgformat's doc and SO:s3-uart's, and give sawos's loader a check that refuses a nonzero `reserved0` from now on. Old kernels would still drop it silently, though.

**Lead's amendment (Nov 26), accepting c3.** My rule 1 hid an error: an image that asks for realtime levels would boot on a v3 kernel with them silently dropped. It is replaced:

1. **The version follows the word.** `SOSIMG_VERSION` becomes 4, and Blade writes it only when `rt_map` is nonzero. An image that names no realtime level stays version 3 and byte-identical to today's. A v3 loader refuses a v4 image, so the lost request is a clean load error.
   - `libs/imgformat`: name both versions (e.g. `SOSIMG_VERSION` = 4 and `SOSIMG_VERSION_NO_RT_MAP` = 3, or a clearer pair). `has_known_version` accepts both. A version-3 header whose `rt_map` is nonzero is refused (in v3 the word must be zero), through a check next to `has_known_version` that a loader calls (named in its docstring).
   - Blade: the version written is derived from the `rt_map` word in one place, next to the packing funnel.
   - Pins add: no rt key → version 3 at offset 4 and the header byte-identical; any rt key → version 4; imgformat accepts v3 with zero, accepts v4, and refuses v3 with a nonzero `rt_map`.
2. Rule 2 (a partial set fills from `high`) stands.
