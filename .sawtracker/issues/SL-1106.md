## Description

Found by SL-1037's agent (Nov 14) while trying to pin `note_dropped`'s message. **Evidence:** a hand-made std root with the old layout (a root holding `builtin.saw` plus `std/`, and no `prelude.saw`) makes `sawc resolve --std-root ROOT ...` panic: `vector.saw:89: Vector.[]: index out of range: -1 (len 13)`. Main's compiler panics the same way, with a clean `builtin.saw` too. A wrong std root is a user's mistake to report ("this is not a std root: no prelude.saw"), never a panic. **The second half:** `note_dropped` in `compiler/resolve/src/loader.saw` handles a declaration an INTERFACE parse dropped. The agent could produce an interface-only module only under that old layout; appending refused declarations to a new-layout std file refuses the whole file instead. So: is the interface-only path reachable with today's std layout at all? If not, it and `note_dropped` are dead and go (with the lane's built case that names it); if it is, name the construction and pin `note_dropped`'s message, which SL-1037 left unchanged for want of a test. Probes: `.build/scratch/p1037/` in the lead's checkout.
