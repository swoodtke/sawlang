## Description

Found by design 275 U4's ADVERSARIAL probe set (the lead's two-module /
same-name / generic-via-helper / closure-caller sweep), probed on main at
46d6db9c and unchanged by U4, which is behaviour-preserving.

A suspending GENERIC free call in an EXPRESSION position inside a driven body is
neither promoted nor refused — it is left as a plain call to a suspending
instance inside the synthesized resume, and the author is handed a diagnostic
about a `sync` region and two frames they never wrote:

    error: cannot suspend in `sync func` method: method `__Frame_main.resume`
           calls `warp$1$Int` → yield_now (`warp$1$Int` suspends at line 6)
    hint: a `sync` context must be transitively suspension-free ...

REPRO (main, 46d6db9c — `.build/scratch/probe_adv_entry_generic.saw` and
`probe_adv_generic_positions.saw` in the sl318u4 worktree):

    import std.task.{yield_now}

    func warp<T>(x: T, n: Int) -> Int { yield_now()  n + 10 }

    func main() {
        print("entry {warp<Int>(1, 0)}")   // REFUSED, as above
        yield_now()
    }

THE CONTROL, one line different, compiles and prints 10 (`probe_adv_entry_
generic_let.saw`):

        let r = warp<Int>(1, 0)
        print("entry {r}")

POSITION MATRIX probed so far — the statement-level `let` is the only cell that
works; an INTERPOLATION operand, a call ARGUMENT and a binary OPERAND all fail,
entry-module and imported alike, through the qualifier spelling
(`mod.warp<Int>(..)`) and the selective-import spelling (`warp<Int>(..)`) alike,
and with `main` or an explicit `__saw_drive` as the root. Two modules declaring
the same generic name fail the same way (the original probe), which is how this
was found.

MECHANISM (obligation 4): two position sets that do not agree.
`coro_transform._promote_nested_generic_calls` walks a driven body for a nested
generic call "in a drivable position — a top-level or control-flow-body
`let x = g<Args>(...)` / bare `g<Args>(...)`", which is the position set design
74 shape 3 was written against. Design 120 then gave every EXPRESSION position an
ANF hoist, and design 224 widened it again to container heads — so a generic call
in one of those is lifted into a temporary by the hoist, but the INSTANTIATION it
names was never adopted, and the call the hoist lifted is a plain call to a body
the transform never framed. The promotion walk is discovery; the hoist is
lowering; nothing reconciles their position sets.

This is design 275's own diagnosis one site over: a decision (which instances are
promoted) re-derived against a position list that another pass has since widened.
It belongs to the TOTALITY unit (SL-318 U2), whose shape table is exactly the
artifact that would have caught it — the table says every shape SPLITs, HOISTs or
REFUSEs, and this cell hoists while its callee is left unbuilt, which is the
fourth outcome the unit exists to delete.

FIX DIRECTION: the promotion walk visits the same positions the hoist does (or,
better under U1, the ledger is populated from the effect graph's edges rather
than from a positional walk of bodies — an edge to a generic instance is a demand
whatever position the call sits in). Until then the workaround is the control
above: bind the call to a `let` at statement level.
