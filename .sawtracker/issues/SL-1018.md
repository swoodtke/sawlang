import std.file.{File}
import std.path.{Path}

struct W { f: File, n: Int }
@synthesize extension W: ExplicitCopy {}

func make_and_copy() unsafe -> W {

func main() unsafe {

**Implementation detail (lead, Nov 12): a `@synthesize` copy policy joins the derivation funnel, so it is refused at its head when a member cannot supply the copy.**

**The hole (the Air's c3 above):** `struct W { f: File, n: Int }` with `@synthesize extension W: ExplicitCopy {}` builds, and the derived `copy()` duplicates `File`'s descriptor bitwise; both deinits close it. That is a double close of an unrelated file, a resource-safety hole.

**The rule (spec, "The Copy Trait Family" and "Synthesized conformances").** A declared copy policy with no `copy()` body is an assertion that the members qualify:
- `@synthesize extension T: Copy {}`: every stored field, and every case payload of an enum, meets `Copy` (so a `Vector` member is refused: a silent transfer would spend a deep copy nothing names).
- `@synthesize extension T: ExplicitCopy {}`: every one meets `ExplicitCopy` (every `Copy` type does; a `NoCopy` member such as `File`, `Box` or `Mutex` does not).
- A member whose type names a type parameter meets it only through a bound, on the type or on the extension's head.
- A conformance with a hand-written `copy()` is not checked: that body is the author's.

**Where: the DERIVATION FUNNEL** (`compiler/typecheck/src/checks.saw`, `check_derivations` → `check_derivation`, ENTRY POINT `tc_check_derivations`). Today it checks only `@synthesize`d `Serialize`/`Deserialize`, with `satisfies(t, c.trait_decl, d, c.ext, c.module, in_test)` per stored field and the refusal `synthesize.member` (`refuse_underivable`). `satisfies` already answers `Copy` and `ExplicitCopy` from the tier table, with the extension's conditions in scope (`tier.saw`: `nominal_satisfies`, `tier_is_copy`, `param_satisfies`), so the copy policies need no new judgement, only to be asked.

1. `compiler/typecheck/src/conform.saw`, `derived_requirement(at)`: also answer for a conformance whose trait is `self.known.copy` or `self.known.explicit_copy`, returning the `copy` requirement when its status is `TcStatusKind.Synthesized`. **Reviewer note on the implementation detail (Air, Nov 12): one sibling the member rule cannot see. It needs a ruling before dispatch.**

The mechanism behind c3 is "a derived `copy()` duplicates a value whose release can't be duplicated". A `NoCopy` member is one way there. The type's own hand-written `deinit` over trivial members is another, and the rule in the detail accepts it, since every member qualifies:

```saw
struct Res { id: Int }

@synthesize extension Res: ExplicitCopy {
    func deinit(&var self) {
        print("release {}", self.id)
    }
}

func main() {
    let a = Res(id: 1)
    let b = a.copy()
    print("copied {}", b.id)
}
```

On origin/main today it builds and prints `copied 1`, `release 1`, `release 1`. With `id` a descriptor and the body a `close`, that is c3's double close with no `File` in sight: the spec's own `Res { fd: Int }` example plus `@synthesize`.

It isn't always wrong. A type whose members are all retained (`Arc`, `String`) and whose `deinit` only reports can want exactly this. So it is a choice, not an obvious refusal:
- **(a)** it stays the author's assertion, and the spec says so: `@synthesize` beside a hand-written `deinit` asserts that the `deinit` is right to run once per copy; or
- **(b)** `@synthesize` of a copy policy is refused when its conformance carries a hand-written `deinit`, and the author writes `copy()` too.

Either way the unit's matrix owes the cell: an accepted golden under (a), a refusal fixture under (b).

Probe: `.build/scratch/air-review/queue_nov12/synth_copy_own_deinit.saw` on the Air.
