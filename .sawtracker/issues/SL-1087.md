## Description

**A raw-backed enum case written where a `Result` is expected becomes `Ok(its raw value)` when the Ok payload is an integer and the Err payload is that enum. An error is silently a success.** Reported by the sawos lead (chat m751, Nov 13) at v0.22.0; reproduced by the lead on main.

```saw
enum Why: UInt8 { case Fine = 0, case Bad = 11 }

func by_return(fail: Bool) -> Result<UInt, Why> {
    if fail {
        return Why.Bad      // builds; the caller gets Ok(11)
    }
    return 5
}
```
Nothing is diagnosed. In sawos it made the kernel's address translation answer `Ok(11)` for every address that named nothing, and the kernel dereferenced address 11.

**Cells, measured on main** (the lead's checkout, `.build/scratch/presult/cells.saw` and `plain.saw`):
| slot | written | result |
|---|---|---|
| `Result<UInt, Why>`, `Result<UInt8, Why>`, `Result<Int, Why>` | `return Why.Bad`, or `Why.Bad` as the tail | **`Ok(11)`** |
| `Result<Bool, Why>` | `return Why.Bad` | `Err` |
| `Result<UInt, Plain>` (no raw backing) | `return Plain.B` | `Err` |
| `Result<UInt, Why>` | `return w` for a local or parameter `w: Why` | `Err` |
| `let a: UInt = Why.Bad`, `let b: UInt? = Why.Bad`, `takes(Why.Bad)` for `n: UInt` | | accepted: the value is 11 |
| `let d: UInt = w` | | `type.mismatch` |

**Mechanism (read from the source).** `expect` in `compiler/typecheck/src/bodies.saw`, before anything else: when the expression is a lone raw-backed case (`raw_case_named(e) >= 0`) in a position `adopts_lone_case` allows, it peels the slot for an INTEGER (`self.peel(slot, TcClient.Integer, -1, -1)`), and if one is found the case adopts it (`TcAdjustKind.Adopt`). `peel` goes through an Optional's payload and a Result's unique payload that takes the client. For `Result<UInt, Why>` and an integer client that is `UInt`. The question "does this slot take the case as what it IS, a `Why`?" is never asked, so the fold wins over the value's own type.

The fold itself is a rule, and stays: the spec's Flag enums section (a user ruling, amended Aug 21 and Aug 31 2026) says "Where a declared integer type is in force — an annotated `let`, a field, an argument, a `return`, a `static`, an arm — ... A LONE case folds there too". It speaks of a declared INTEGER type. It does not say a case stops being its enum where the slot also takes the enum.

**The rule this issue implements (lead's decision; it narrows nothing the spec states):** a lone raw-backed case is its enum wherever the slot takes that enum, at the slot itself or at any layer the peel reaches (an Optional's payload, either payload of a Result). The fold into an integer applies only where no layer takes the enum. So:
- `Result<UInt, Why>` ← `Why.Bad` is `Err(Why.Bad)`.
- `Result<Why, UInt>` ← `Why.Bad` is `Ok(Why.Bad)`.
- `Result<Why, Why>` ← `Why.Bad` is the existing ambiguity error.
- `UInt` ← `Why.Bad`, `UInt?` ← `Why.Bad`, `Result<UInt, Other>` ← `Why.Bad`: unchanged (the fold; no layer takes `Why`).
- A COMBINATION (`Perm.Read | Perm.Write`) is unchanged everywhere: it is the backing integer, never the enum.

**Implementation.**
1. **Conformance row first** (obligation 3; this is a "never hide errors" guarantee): a row in `tests/corpus/conformance/INDEX.md` for "an error enum's case returned from a `Result` function is `Err`, whatever the Ok payload", with its program under `tests/corpus/conformance/` (runs, prints `Err` for each of the three integer payloads, by `return` and by tail). Read how V170 and V171 were added (SL-1018): the row, the count line, and the TWIN row in `compiler/tests/borrowck/CONFORMANCE.md` (owner `typecheck`) that the `borrowck` step requires.
2. **Step 0, the census, before the fix** (obligation 4: one funnel, every position). A cell per position `expect`'s ENTRY POINTS list names where a Result-typed slot can stand: `return`, body tail, closure tail, an annotated `let`, a field in a construction, an argument, a default value, a branch of a value `if`/`match`, an element of a collection literal, an assignment to a `Result`-typed place, a `??` right side if a Result can be there. Each with `Why.Bad` spelled three ways (qualified `Why.Bad`; implicit `.Bad`; through a local). Plus the slot shapes: `Result<UInt, Why>`, `Result<Why, UInt>`, `Result<Why, Why>`, `Result<UInt?, Why>`, `Result<UInt, Why>?`, `Result<UInt, Other>`, and the plain `UInt`, `UInt?`. Record what each builds to and prints. One file per cell or a generator script in the evidence directory; the table goes in the report.
3. **The fix, in `expect`, at that one place:** before the Integer peel adopts, ask whether the slot takes the case's own enum: a peel for the enum's nominal type through the same layers (`TcClient.Construct` with the enum's declaration, or the client that fits; read `takes` in `adjust.saw`). If that peel finds the enum, or is ambiguous, the fold is skipped and the expression goes down the ordinary path, where `convert` wraps it as the payload it is or reports the ambiguity. Nothing else changes. Update the comment at the site and `adopts_lone_case`'s to state the rule.
4. **The census again.** Expected: every cell whose slot takes `Why` at some layer now yields the enum (`Err`, `Ok(Why)`, or the ambiguity error); every other cell identical.
5. **A sweep of existing code for programs that relied on the old reading:** build `std/`, `compiler/` (the stages build themselves), `blade/`, `libs/` and the corpus (the gate does this); any program whose behaviour changes is listed with its line. Expected: none in std, the compiler or Blade. **A site that changes is a stop: report it, don't rewrite it.**
6. **Pins:** the conformance program; typecheck golden cells for each slot shape (`compiler/tests/typecheck/`: read the README for where accepted cells and refusal fixtures go); a refusal fixture for `Result<Why, Why>`; a run probe if the lane has a place for one that prints the variant.
7. **Spec** (saw-docs skill first): the Flag enums paragraph "A LONE case folds there too" gains the sentence that states the rule above, with the `Result<UInt, Why>` example. Nothing else.

**Open for the user, NOT decided here (leave as it is and list in the report):** whether a lone case should fold THROUGH a wrapper at all when no layer takes the enum (`UInt?` ← `Why.Bad`, `Result<UInt, Other>` ← `Why.Bad`). The spec says "a declared integer type is in force", which reads as the slot's own type.
