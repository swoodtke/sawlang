## Description

**A `borrows` function may lend `Result<&T, E>` or `Result<&var T, E>`.** This extends the conditional lend (`borrows -> &T?`, spec "Conditional lends"): the absent path carries an owned error instead of `None`. Queued by the user on Oct 22, after design conversation ("an extension to the existing optional path makes sense to me"). Today sawc2 refuses the shape with `borrows.result` (`compiler/typecheck/src/bodychecks.saw`, `check_function_containment`).

**Why:** a lend that can fail has no way to say why. Two documented panic boundaries exist only for that reason:
- `Map`'s `default:` place form, which inserts and then lends, panics if the allocator refuses;
- `Data`'s copy-on-write subscript does the same.

`String.c_string` (SL-813) needs it once String slices make it copy. A non-blocking `try_lock` (`Result<&var T, WouldBlock>`) is the same shape.

**Semantics (ruled with the user, Oct 22):**
- **In the accessor body,** every path either `lend`s real storage (the Ok path: the window opens), or returns an error value (auto-wrapped; no window, no epilogue), or diverges. `try` in the prologue propagates the error before any lend. Otherwise the rules are the conditional lend's: no `lend` in a loop, the root charge follows the receiver, `borrows(sync)` and `unsafe` combine as they do today, and `@synthesize(shared)` derives the shared version.
- **The borrow check is path-sensitive,** as for `None`: an `Err` arm holds no borrow, so it may touch the root.

**Call-site forms:**
1. **The binding carries the Result, and the body matches on it** (the Sep 24 ruling: no `else` on the construct). `borrow let r = s.c_string() { match r { case Ok(borrow let p) -> …, case Err(e) -> … } }`. `case Ok(borrow let p)` is the existing payload-pattern rule; `case Err(e)` binds the owned error.
2. **`try` / `try!` in the head:** `borrow let p = try s.c_string() { … }`. The operator acts on the accessor's result before any window opens: `try` returns from the enclosing function with the usual conversion, and `try!` panics. The same goes for the one-statement prefix (`borrow try! s.c_string()`), the Result counterpart of `!` in `borrow g.at(4)!.weight`.
3. **`if borrow let p = try? s.c_string() { … } else { … }`:** `try?` (already in GRAMMAR.md) turns the Result into an optional place, and the existing unwrap applies.

**Refused, each diagnostic naming forms 1 and 2:**
- a bare `if borrow let p = s.c_string()` on a Result place: the `else` would discard the error (rule 151, a discarded Result);
- `try … catch` in a borrow head: there is no substitute place, and two brace blocks side by side read badly;
- `match borrow s.c_string() { … }`: the codex r11 ruling writes a borrowing scrutinee as a `borrow … = … { }` block.

**Brief obligations:**
- **(3, first unit)** conformance rows for the guarantees: no window on the Err path, the error dropped exactly once, the root free in an Err arm, a window spanning a suspension on the Ok path.
- **(1)** the lending shapes are one funnel (typecheck's `TcLend`), its docstring naming the entry points: typecheck, the borrow check's window, MIR lowering, drops for the owned error, the coroutine transform for a lend across a suspension.
- **A position matrix:** block, one-statement prefix, `if`/`while` head, `match` payload, `for` head (is a fallible iterator lend in scope? say so), a `lend` forwarding a Result lend, `@synthesize(shared)`.

**Spec and grammar:** a "Fallible lends" section beside "Conditional lends"; GRAMMAR.md rows for `try` in a borrow head and the three refusals.

**Migrations, in this unit or as follow-ups (the brief says which):**
- `Map`'s `default:` place form and `KeyedPlace.insert_and_lend` move to `Result<&var V, AllocError>`, with `try`. The "documented panic boundary" text shrinks, and the strict flag's list with it.
- `Data`'s copy-on-write subscript.
- `String.c_string`, which SL-813 ships as `borrows -> &UnsafePointer<Int8>?` (interior NUL is its only failure today).


## Comments

<!-- sawtracker:comment {"author":"agent:claude-air-reviewer","body_bytes":1278,"created":"1792716550","id":"c1"} -->
**Air, pre-design: the error type `E` must not be able to hold a borrow, or "an `Err` arm holds no borrow" fails.** The issue's path-sensitive rule (an `Err` arm may touch the root) is sound when the error is an owned value. But Saw has borrowing structs, types that hold a reference: SL-788's ruling names `VectorIterator<Int>` among them. A `borrows` function returning `Result<&T, E>` where `E` is, or contains, such a type could hand back an error that still points into the receiver. The `Err` arm would then hold a live borrow of the root while the borrow check treats the root as free.

**The brief should pick one rule and pin it:**
- (a) **refuse** a fallible lend whose `E` is a borrowing type, or contains one in a field, payload or element: `E` must be a type a `Result` could carry out of the function by value with no lend;
- (b) **track** the error's loans like the Ok window's, so an `Err(e)` arm holds whatever `e` borrows.

(a) is the smaller rule, keeps "the Err arm frees the root" unconditional, and matches every motivating case (`AllocError`, `WouldBlock`, an interior-NUL error), all owned. A row in the position matrix: `borrows -> Result<&T, VectorIterator<Int>>` refused (or tracked), and an owned `E` accepted with the root touched in the `Err` arm.
