**From A10 (SL-567): the cancel-during-sleep pins move here.** A10 builds the generic cancel wake: `park_wakes` in `std/taskgroup.saw` is the one predicate the sweep decides runnability by, a ready park or any park of a cancelled task. A10's own sleep pin, run lane `task_cancel_during_sleep`, cancels a task parked on a timer and never needs a deadline to pass. The pins that do need one are yours:
- **`taskgroup_cancel_during_sleep`**, the plan's A10 pin "with A11". Both tasks sleep, so the executor has to idle until the canceller's 50 ms deadline, and the sleeper must come back promptly instead of after its 10 s. It also needs `std.time`'s `Instant` (yours), `group.spawn` (A8b, SL-564) and `Task.cancel_addr()` (A17a's scope: "`cancel_addr` pinning a slot"). Until those land, a `Task.spawn` form that cancels through the handle would pin the same idle-wait wake.
- **Two obligations for the timer executor half:**
  - put your wake conditions (deadline expired) in `park_wakes` beside the cancel one, so the wake stays one funnel;
  - the idle wait must not sleep past a cancel. On one thread a cancel is always written by running code before the sweep idles, so the sweep sees it. A cross-thread cancel (A17a) has to rouse the reactor poll.
- **The outcome:** A10 reads a park's cancelled outcome as the cancel word, read by the parking frame after its park through `__saw_cancel_requested()` (A9's read through `cx`). No role return type or context field was added. The spec says a timed park "reports cancellation rather than a timeout", so read the cancel word first.

**a11timers: `Instant` (`std/time.saw`) needs a file outside A11's list, so it is held back; the rest of A11 is built.**

The new std's modules are enumerated, not discovered: `compiler/resolve/src/loader.saw`'s `load_new_std_modules` loads each `std.X` by a `self.std_module("X")` line, and `time` is not among them. So a `std/time.saw` alone is unreachable:

```
$ .build/sawc2-stage2 build --std-root std .build/scratch/probe_time.saw   # import std.time.{Instant}
ERROR	import.unknown-module	.build/scratch/probe_time.saw:1:8	no module `std.time`
```

Porting `Instant` therefore needs one line in `compiler/resolve/src/loader.saw` (front track, not in A11's files), `self.std_module("time")`, besides the new `std/time.saw` (a port of `sawc/std/time.saw`'s `Instant`). No seed bump: the line uses nothing the seed lacks. Per the brief I have not touched the loader. None of A11's three plan pins uses `Instant`; the one moved pin that does, `taskgroup_cancel_during_sleep`, also waits on A8b's `group.spawn` and A17a's `cancel_addr`, and its idle-wait wake is pinned meanwhile by the run lane's `task_cancel_idle_sleep` (a ten-minute sleep the cancel must cut short, so a missed wake is a hang).

Ruling wanted: take the loader line into A11 (or a follow-up), or leave `Instant` to whichever unit first needs it.

SL-568.p1 (A11) submitted. It also closes **SL-645**.

- **The wake:** `park_wakes(cx)` stays the one runnability test. It wakes a ready park, any park of a cancelled task (checked first, so a cancelled sleeper wakes at once), or a timer whose deadline has passed.
- **The idle wait:** when a sweep pass resumes nothing, `idle` finds the earliest deadline among the timer parks off this thread's stack, plus a waiting drive point's own deadline. It re-checks each with `park_wakes` (the clock may have moved), then blocks in the reactor poll until that deadline: rounded up to whole milliseconds, capped at 60 s a poll so epoll's `int` timeout can't overflow. With no timer left, it returns and cedes to the sweep above. The process-wide reactor is created on first use. The wait uses the reactor poll, not a sleep, so A17a can rouse it.
- **SL-645:** a drive point's non-ready park goes to the same shared sweep (`sweep(..., waiter)`), so other tasks run until the drive's park wakes. `drive_timer_park` and `main_timer_park` are plain run programs now, matching Stage 0. A channel park still panics naming A13a, a descriptor park panics at its arm (A12a), and an unknown park word is refused.
- **`std/time.saw`:** `Instant` (`now`, `elapsed`, `duration_since`) and `unix_timestamp`, ported from Stage 0's with the same docs, loaded by one line in `compiler/resolve/src/loader.saw` (the lead's ruling, c4). No resolve or typecheck golden moved.
- **Pins:** `async_main_sleep_yield` (verbatim), `task_sleep_ordering` and `task_suspending_parent_sleep` (the plan's two TaskGroup programs with `Task.spawn`, since `group.spawn` waits on A8b; each keeps its meaning), `task_cancel_idle_sleep` (the idle wait must wake a 600 s sleeper on a cancel; a missed wake hangs), and `instant_after_sleep`. All are recorded against Stage 0 on macOS and Linux and match at -O0 and -O2. `taskgroup_cancel_during_sleep` stays pending on A8b and A17a.
- **Coro goldens:** 16 regenerated, no `INVARIANT`. Besides new and removed std items and renumbering, about 58 existing std items newly appear in the drive-only programs (`cancel_read`, `drive_site`, `index_reads`, `op_budget`, `windows`), because a drive point now reaches the shared sweep's run-queue code. That is SL-645's change itself.
- **Corpusdiff, 25 rows, committed:** 9 move wrong → pass (they panicked "parked on a timer"; for example `async_main_nested_sleep` and the `coro_match_arm_*` family), 1 refused → pass, 1 stays stage0-wrong with a new detail (SL-283's program now exits 0), and 14 stay refused but at the next missing piece once `std.time` exists (`Arc`, `std.net`, `TaskGroup.spawn`, `Vector.iter`, `Command`, `Data`, a Bool format, Duration `Comparable`).
- **Gate in the worktree:** `run.py --only resolver,typechecker,mir,eval,std,borrowck,drops,mono,coro,programs,std_cone,std_suspension` ok; `battery.sh citations` green; `corpusdiff.py gate` ok. The diff applies cleanly to current main.

The drive point's park is the shared sweep's `waiter`, which is t8 and closes SL-645.
