## Description

**New-std API gaps found by the sawtracker port measure** (Oct 23, read-only measure of sawtracker a0d7b57a6 under sawc2 at 890686a46; evidence in the lead's session scratchpad `st_measure/`). Each was in the frozen `sawc/std`; sawtracker uses it; the new std lacks it.

1. **`File.read(&var self, size: Int)`, a bounded read.** The new `read()` reads to the length `lseek` reports and documents a pipe as an Err, so nothing reads a tty or a pipe incrementally (sawtracker reads `/dev/tty` for its token prompt, and reads regular files with a size).
2. **`Command.env(name:value:)`.** The LANGUAGE_SPEC still documents it as shipped (Process section). "Never hide errors": either std gains it or the spec drops it, never a silent mismatch.
3. **A writable Map element place:** `[](&var self) borrows -> &var V?`. The new `Map.[]` lends read-only (`subscript.role`), so updating a value in place takes a remove, a change and a put back. The std comment beside it cites SL-600, which is closed and unrelated, so that pointer is wrong.
4. **`Directory.current() -> Path?`.** The new std has `Env.cwd()`; the saw-lang skill still documents `Directory.current`. Decide: add it, or fix the skill.

**Scope:** for each, rule add or retire (with its docs); then the API, its doc comment, and its pins. Items 1-3 add std surface, so obligation 4 applies to item 3 (every keyed-collection place: Map, Set if relevant).
