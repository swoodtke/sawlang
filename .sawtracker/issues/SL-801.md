## Description

**`@align` is not in sawc2's backend slice** (found by A18's census, SL-580 c7). `compiler/llvm/src/` `ll_refuse_placement` refuses every `@align` ("`@align` is not in the backend slice yet: a static or a local is aligned only as its type asks"), so a program that aligns a static or a local doesn't build. The spec defines `@align` on statics and locals (design 149 runtime authoring, the freestanding toolkit), and corpus/coro rows use it.

**Owed rows:**
- N11, `@align` on a frame-resident local, must be REFUSED, since a coroutine frame can't honour an over-alignment (Stage 0's refusal; the rule sits in coro beside `coro_check_frame_send`, where frame residency is known);
- N08 and the corpus programs that align a static or a non-resident local must BUILD and honour the alignment;
- the two `@align` rows from the coroutine corpus tally (`'@align' is not in the backend slice yet`).

**Scope:** the LLVM emission of `align N` on globals and allocas (the IR's `align` attribute), the frame-residency refusal (N11), and the spec check. Kernels and freestanding are first class, and `@align` is a freestanding-toolkit feature.
