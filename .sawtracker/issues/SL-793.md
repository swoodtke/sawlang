## Description

**A cooperative task that joins a `threads: N` group's task blocks its executor thread** (found by SL-782 1b-ii's design census, agent p782b2). A pool group's `await_task` (`std/taskgroup.saw`) waits on a condition variable on the OWNING thread. When the joiner is a cooperative task (on main's executor, or on another single-threaded group), `join()` on a pool task blocks that executor thread, and every sibling task on it stops until the pool task finishes. That is the `recv`/`Thread.join` hazard class SL-782 removes elsewhere.

Per `Task.join`'s docstring ("on a pool … this thread only waits"), a join from a NON-task context is fine. A join from a task should park the task until the pool task completes (a word park, as 1b-ii's `Thread.join()` default does, woken by the pool task's completion).

**Obligation 4, a class:** "a std wait that blocks the calling thread with no task-side body". Sweep std's other waits (pool `join`, `TaskGroup.join`/`Deinit` waits on pool tasks, `Mutex.lock` contention? `Once`?) and measure each with the Air's sibling-ticks probe (a sibling ticking every 5 ms while the call waits; 0 ticks means blocked). The fix likely makes each a pair (SL-782's mechanism) or gives it a park.

`Mutex` (w3) is documented as blocking the calling thread, so it may be ruled acceptable. It's still the same class, and the brief should rule on it explicitly. **Air on c8's record design: "never freed" needs "recycled" beside it, or the registry grows with every thread that ever drove.** Never-freed is the right call for the walk: the deadlock walk and A16b's dump can read a record without a lock while its thread exits. But if a record is created on a thread's first drive and never handed to another thread, the registry's size is the number of threads that ever drove a cooperative group. In a thread-per-connection server whose handler drives a `TaskGroup()`, each `Thread.spawn` per request, that's one record per connection served, forever. It would also make the walk iterate every dead thread's record.

**The suggestion, keeping never-freed:** when a thread's outermost drive returns with its record empty (no registered group, depth 0), or at the thread's exit, the record goes on a free list, and the next thread to need one takes it from there. Then the registry is bounded by the peak number of threads driving at once. A record on the free list reads as empty to the walk, so it adds nothing to a report. The reuse has to publish "empty" before the free-list push, the same release order as the exit word before `LIVE_THREADS` (my SL-782 c8).

**A pin for it:** spawn and join a few thousand short threads that each drive a one-task `TaskGroup()`. The registry's record count should stay at the concurrency level, read through whatever count A16b's dump exposes, or a debug counter.
