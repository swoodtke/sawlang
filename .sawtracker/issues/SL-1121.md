## Description

**Filed by the sawos lead for the sawlang lead.** Found by the sawos reviewer while reviewing sawos's image builder (SO-104), which reads its inputs with `std.json`. sawlang 0.23.0.

- **Tried (reproduced by the reviewer).** A description `{..., "version": 1, ..., "version": 2}` given to the builder, which reads it with `JsonValue.parse` and takes each key out of the object's map.
- **What happened.** It is read as version 2: an object with a repeated key parses, and the last value wins, with no error and no way for the caller to see that a key was repeated.
- **Expected.** A way to refuse it: either `JsonValue.parse` refusing a repeated key in an object (by default, or by an option), or the parsed object keeping enough to let the caller ask.
- **Why sawos needs it.** The builder promises that a description it half-understood is refused (an unknown key, a wrong type, a wrong version are each an error naming the key). A repeated key is the one way left to half-understand one, and it matters most for descriptions people will write by hand. The same holds for `libs/toml`, where a repeated key or table should be an error (SL-1092).
- **How badly.** Nice to have for now: the test runner writes these files and cannot repeat a key. It becomes real with hand-written descriptions.
