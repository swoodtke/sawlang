## Description

**Typecheck admits a store to, or a reference of, a `borrow` block's conditional-lend binding, for which no storage exists** (found by p686, SL-686 step 1, Oct 23). In `borrow var e = m.find(&k) { … }` (`e: &var V?`, an optional PLACE), typecheck accepts:
- `e = None`
- `look(&e)`
- `let w = e`

The binding names an optional place, not an `Optional` value in storage: there is no `T?` slot to write `None` into or to take a reference of. SL-686 refuses all three in MIR as `slice.not-yet`.

**The question for the spec:** what each one means.
- `e = None`: is it refused, or does it mean "remove the entry"? It can't mean the latter for a generic accessor.
- `&e`: a reference to an optional place?
- `let w = e`: a copy of the payload (the Copy tier), or refused?

The spec's "Unwrapping an optional place says `borrow`" section covers `if borrow var x = e` and `if let x = e` (a copy), but not these.

**Scope:** rule each, then make typecheck refuse what has no meaning (with a teaching message naming `if borrow var x = e`), and pin it.
