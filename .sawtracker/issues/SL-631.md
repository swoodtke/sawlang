## Description

Found by SL-626's sweep (agent e1over). The mechanism differs from E1's.

**Mechanism:** a declaration written directly after `@test` records the TestOnly item as its `outer` (`collect_item` passes the item as `holder`, so `ResDecl.outer` is that item; `model.saw` documents this). The attributes are children of the inner Declaration, not of the item. Every attribute reader looks at `decl.outer`'s children, so it finds none. Visibility is read from the Declaration (`visibility_of(outer)` in `collect_declaration`), so `@test public func` keeps its tier; only attributes are lost. Declarations inside a `@test { ... }` group are collected with their own Declaration as `outer`, so this happens only to a declaration written directly after `@test`.

**Readers** (each reads `decl.outer`):
- `declarations.saw`: `has_attribute(info.outer, Attr_Attribute_Synthesize)`, for `@synthesize`;
- `exports.saw`: `export_attribute`, for `@export`;
- `bodies.saw`: `check_align_attribute`, for `@align`;
- `mir/src/lower.saw`: `is_align_argument`;
- `declarations.saw`: the synthesized-method check, `has_alt(info.outer, Decl_ExtensionMember_SynthesizedMethod)`. Check whether this one can reach a TestOnly item.

**Evidence** (`sawc2 typecheck --check` at SL-626's tree): the `@synthesize` is lost, and the derivation is refused.

```saw
struct Money {
    cents: Int
}

@test
@synthesize extension Money: Equatable {}
```

`ERROR synthesize.required 6:30 ... mark the extension @synthesize to derive it`

**Fix shape:** one place answers "the node holding a declaration's attributes": record the Declaration node, or give the readers one accessor that steps through a TestOnly item. Each reader above goes through it. The pins: one fixture per attribute under `@test`.

**c631attr: fixed in commit 90df4a491 in the worktree, not submitted.** All three attributes reproduced on main (`sawc2 typecheck --check`): `@test @synthesize` was refused `synthesize.required`, a `@test @export` duplicate symbol and a `@test @align(true)` were both accepted, and MIR lowered no align body for `@test @align(64) static`. Each one's `@test { }` group control was right.

- **The record:** collect now records the Declaration node as `outer` under `@test`, never the TestOnly item. Resolve's verifier refuses a declaration whose `outer` is a TestOnly item.
- **The funnel:** `ResProgram.decl_attribute(d, alt)` in `resolve/src/program.saw`, with its entry points named. All four readers go through it: `build_extension` (`@synthesize`), `export_attribute` (`@export`), `check_align_attribute` and MIR's `is_align_argument` (`@align`). Typecheck's `has_attribute` is gone.
- **The synthesized-method check is ruled out:** a method's `outer` is always its ExtensionMember node, and `@test` can't stand inside an extension. The parser refuses it with `syntax.rule.test-form`, so the check can't reach a TestOnly item.
- **Pins:** the typecheck golden `test_only_attributes` (each attribute after `@test`, beside its group control); the refusal fixtures `synthesize.inert.test-only`, `export.generic.test-only` and `type.mismatch.test-only-align`; the MIR golden `test_only_attributes`; and a matrix in the typecheck README.

**The run-program pin is blocked; filed as SL-644.** In a normal build, an attribute on test-only code can only change behaviour through `@export`. It can't happen through a test case either, since sawc2 has no test build. But that observable effect is itself a defect: a test-only export is emitted and linked into an ordinary binary, so production code can call it through `extern "C"`. SL:testing says such code is "typechecked, not emitted". The group form already did this on main. This fix makes the `@test` form do the same. A run program would pin a leak, so I didn't write one. The MIR golden is the behaviour pin.
