## Description

Found by SL-626's sweep (agent e1over). The mechanism differs from E1's.

**Mechanism:** a declaration written directly after `@test` records the TestOnly item as its `outer` (`collect_item` passes the item as `holder`, so `ResDecl.outer` is that item; `model.saw` documents this). The attributes are children of the inner Declaration, not of the item. Every attribute reader looks at `decl.outer`'s children, so it finds none. Visibility is read from the Declaration (`visibility_of(outer)` in `collect_declaration`), so `@test public func` keeps its tier; only attributes are lost. Declarations inside a `@test { ... }` group are collected with their own Declaration as `outer`, so this happens only to a declaration written directly after `@test`.

**Readers** (each reads `decl.outer`):
- `declarations.saw`: `has_attribute(info.outer, Attr_Attribute_Synthesize)`, for `@synthesize`;
- `exports.saw`: `export_attribute`, for `@export`;
- `bodies.saw`: `check_align_attribute`, for `@align`;
- `mir/src/lower.saw`: `is_align_argument`;
- `declarations.saw`: the synthesized-method check, `has_alt(info.outer, Decl_ExtensionMember_SynthesizedMethod)`. Check whether this one can reach a TestOnly item.

**Evidence** (`sawc2 typecheck --check` at SL-626's tree): the `@synthesize` is lost, and the derivation is refused.

```saw
struct Money {
    cents: Int
}

@test
@synthesize extension Money: Equatable {}
```

`ERROR synthesize.required 6:30 ... mark the extension @synthesize to derive it`

**Fix shape:** one place answers "the node holding a declaration's attributes": record the Declaration node, or give the readers one accessor that steps through a TestOnly item. Each reader above goes through it. The pins: one fixture per attribute under `@test`.
