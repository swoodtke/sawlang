**Ruling 2 (the user, Oct 13): a refusal case's body is opaque text, ended by `@test(end: refuses)`** (SL-606; replaces the review's Lex/parse 5 and folds in Lex/parse 1).

The user's words: "let's make this ruling 2", on making the body's extent independent of its contents, and on the spelling, "let's go with end: refuses".

```saw
@test(refuses: "type.mismatch") "a String is not an Int"
let x: Int = "a"
@test(end: refuses)
```

- **The rule:**
  - After a `@test(refuses: …)` header line, the lexer takes raw bytes up to the first line that starts with `@test(end: refuses)`, and makes them one refusal-text token.
  - Every whole-file pass sees that one token: bracket matching (`check_brackets`), newline significance (`parse/src/tokens.saw`), the recognizer, the grammar corpus and astdiff.
  - A test build lexes and parses the body on its own as `refusal-unit`, so any error is testable in a case, unbalanced braces and lexer errors included.
- **Edge rules:**
  - a header with no end marker is refused at the header (a new `syntax.test.*` id);
  - an end marker outside a refusal body is refused;
  - the marker must start a line, so it can't appear inside a body.
- **Only refusal cases change.** Ordinary `@test` bodies keep their braces.
- **Grammar and spec:** GRAMMAR.md's `syntax.test.case.refuses` and §4 change, and `refusal-body`/`refusal-token` go away. The §2.4/§2.7 notes say a refusal body is one token. SL:testing §2, §4 and §5 are rewritten to match, and so is LANGUAGE_SPEC.md's Attributes section where it shows the form.
- **Code:**
  - sawc2's lexer gets the raw mode, with the header recognized at token level;
  - the parser drops `parse_refusal_body`'s brace counting;
  - `--unit` mode no longer hangs or panics on a stray `}` (Lex/parse 1): add pins for both probes;
  - the reference recognizer (`compiler/tests/grammar/recognize.py`) gets the same rule.
- **Migration:** the 7 cases in 5 files under `compiler/tests/`, plus the doc examples. Stage 0 is frozen and can't read the form: add the one tracked file outside `compiler/tests/parse/` (`compiler/tests/resolve/golden`) to astdiff's exclusions, and record it in `corpus_expected.tsv`.
- **Pins:** an unclosed `(` and an unbalanced `}` inside a body, each refused as that case's own refusal; an unterminated string inside a body; a missing end marker; a stray end marker; and the two Lex/parse 1 probes.
- **Done when:** the pins pass, the grammar lint, recognizer and corpus lanes are green, and docverify passes.
