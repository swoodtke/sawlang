## Description

Found by SL-626's sweep (agent e1over), a sibling of E1 with its own mechanism.

**Mechanism:** typecheck's conformance table has no test-only filter. A conformance declared by a `@test` extension is in the table every body reads, so ordinary code's generic-bound satisfaction (`satisfies`) and the operators that go through a conformance (`resolve_comparison`'s `==`) see it. SL:testing ("Test code cannot change what production code means") requires that ordinary code's overload resolution, generic-bound satisfaction and copy-tier classification never see test-only conformances. SL-626 filtered what a test-only extension declares or brings in the member tables (methods, statics, inits, conformance defaults), but the conformance itself stays visible.

**Evidence** (`sawc2 typecheck --check`, at SL-626's tree): rc=0, where the spec refuses both uses in `main`:

```saw
struct Money {
    cents: Int
}

@test
extension Money: Equatable {
    func equals(&self, other: &Money) -> Bool {
        self.cents == other.cents
    }
}

func same<T: Equatable>(a: &T, b: &T) -> Bool {
    a == b
}

func main() {
    let a = Money(cents: 1)
    let b = Money(cents: 1)
    print("{}", same(&a, &b))
    print("{}", a == b)
}
```

**Positions to sweep:** a bound at a call (inferred and explicit), at a generic struct's arguments, a conditional conformance's condition, `==`/`!=`/`<` through `equals`/`compare`, `for` over a test-only `Iterator` conformance, a `Printable` conformance used by `print("{}", x)`, an erasure to `any Trait`, and the copy tier (a test-only copy-family conformance on a production type, which SL:testing refuses outright).

**Fix shape:** the conformance lookup takes the viewer and whether it is test code (`current_test`, which SL-626 added) and applies resolve's `may_use` to the conformance's extension, so ordinary code is checked as if the conformance did not exist. Mono and later stages read typecheck's decisions, so a conformance ordinary code cannot see is never chosen for it.
