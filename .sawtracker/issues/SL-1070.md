## Description

**`tools/gate_status.py` exits 1 on an exception it doesn't catch, and 1 is its "busy" answer, so `suite_lock.sh acquire --yield-to-gate` waits forever instead of falling back to the plain acquire.** Found by the Air reviewer on Nov 12 (chat m707), reproduced there.

**Evidence (the Air's).**
- In a session where `sawtracker` isn't on PATH and one PATH directory is unreadable in the sandbox, `subprocess.run(["sawtracker", …])` raises `PermissionError: [Errno 1] Operation not permitted: 'sawtracker'`, not `FileNotFoundError`. `query` catches only `FileNotFoundError` and `TimeoutExpired`.
- `python tools/gate_status.py SL` prints the traceback and exits 1.
- The acquire then printed "yielding to the server's SL gate (Traceback …)" at each heartbeat for 15 minutes with the lock free.
- With `SAW_GATE_STATUS_CMD="$HOME/bin/sawtracker gate --project SL --json"` it answers correctly (the workaround).

**The contract** (CLAUDE.md, "THE SUITE LOCK"): `--yield-to-gate` "falls back to the plain acquire, saying so, when the tracker cannot be read". An uncaught exception is the tracker not being readable, so it must give the cannot-tell answer (exit 2), never the busy one.

**Fix.** In `tools/gate_status.py`: `query` catches `OSError` (which covers `FileNotFoundError` and `PermissionError`) and `subprocess.TimeoutExpired`; and the top level turns any other exception into the cannot-tell exit with one line naming the exception, so no failure mode can read as "busy". Sweep (obligation 4): every other exit path of the script, and `suite_lock.sh`'s reading of each exit code, as a table (exit code, meaning, what `acquire --yield-to-gate` does).

**Pins.** `tools/test_suite_lock.py` (the `suitelock` lane) has the yield cases against stub status commands: add one whose status command raises `PermissionError` when run (a PATH directory made unreadable, or a stub that exits the way the uncaught traceback does), expecting the fallback line and an acquire, and one for an arbitrary exception.

**Gate:** `tools/battery.sh suitelock patchgate`, `compiler/tests/run.py --only comments`. Files: `tools/gate_status.py`, `tools/test_suite_lock.py`. A small Sonnet unit.

**Part 2 (lead, Nov 13), asked for by the Air in its approval of p1: "busy" gets an exit code of its own, so no failure of the interpreter can read as busy.**

**Why.** Python answers exit 1 for every failure of its own: a syntax error in `gate_status.py` after an edit, a failed import, a broken venv. While 1 means busy, the default failure of the tool that runs the script is a wait that never ends. p1 closed the paths inside the script; this closes the ones outside it, by the code and not by matching output.

**The change.**
- `tools/gate_status.py`: busy exits **3**. Idle stays 0, cannot-tell stays 2. The module docstring's table of exit codes says so, and says why 1 is not used (it is what the interpreter answers for its own failures).
- `tools/suite_lock.sh`, `gate_clear`: 0 is clear, 3 is busy, EVERY other code is cannot-tell (the fallback line, then the plain acquire). The header comment that describes the yield says the same.
- Sweep (obligation 2, a contract flip): every reader and writer of the old code. Known: `suite_lock.sh` line calling `gate_status.py`, and `tools/test_suite_lock.py`, whose stub status commands signal busy. NOTE the two layers: `SAW_GATE_STATUS_CMD` replaces the TRACKER command `gate_status.py` runs (its output is JSON, its exit code is the tracker's), which is not the script's own exit code; find how each existing yield case makes "busy" (a stub tracker command printing a busy report, or a stub in place of the script) and change only what speaks the script's exit code. `git grep -n "gate_status"` and `git grep -n "gate_clear"` over the tree; CLAUDE.md's "THE SUITE LOCK" does not state the codes (check; if it does, it changes with them).

**Pins** (`tools/test_suite_lock.py`):
- a status script that is a syntax error (the interpreter exits 1): the acquire falls back and takes the lock, with the fallback line, and never prints "yielding". Red before the change (it yields for the case's whole deadline), green after.
- the existing busy cases still yield (now through exit 3), and the existing idle and cannot-tell cases are unchanged.
- a direct case on `gate_status.py`: a busy report gives exit 3.

**Gate.** `tools/battery.sh suitelock patchgate`; `compiler/tests/run.py --only comments`.

**Files:** `tools/gate_status.py`, `tools/suite_lock.sh`, `tools/test_suite_lock.py` (CLAUDE.md only if it states the codes).
