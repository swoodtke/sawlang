## Description

**`sawc --build-id` on an installed toolchain: check what its runtime records name.** From SL-1102 (landed Nov 15). On a development checkout, the host's runtime record beside the compiler names its runtime objects by absolute path under the checkout's `.build/rt2/`, and `--build-id` reads each of them. Not examined: how an installed toolchain (`make install`, a release fetched through `tools/toolchain.py`) lays those files out. If a record there names an object path that does not exist where the toolchain is installed, `--build-id` exits 1 and Blade treats the build as never up to date: every `blade build` rebuilds (slow, never wrong).

**To do:** install a toolchain the ways the project supports (`make install`; the resolver's cached fetch of a tagged release), run `sawc --build-id` from the installed location, and confirm it prints the identity. If a record names an unreadable object, decide with the lead whether the record should name objects relative to itself or the identity should hash the record's text only for objects it cannot reach.

Related: SL-1102, design 238 (the toolchain resolver).
