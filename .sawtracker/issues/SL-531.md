## Description

Found while doing SL-519 (a package's module root is its `src/`). Stage 0 is frozen, so this is a hazard to record, not a fix to make. Both are loud.

**1. A bare import is resolved against the ENTRY file, not the importing file.** `_prepare_codegen` in `sawc/sawc.py` calls `resolver.resolve_module(list(module_path), source_path)` for every pending import, from any module, with `source_path` set to the entry file. `ModuleResolver._file_relative_dirs` then searches the entry's directory and the entry's `Saw.toml` directory. The importing module's own directory is never searched. So the in-package bare spelling the ruling allows (`import layout`, found "through the importing file's own directory") resolves only when the importing file sits beside the entry.

Repro: change `blade/src/resolver.saw`'s `import src.manifest.*` to `import manifest.*`, then build any Blade test:
```
./.venv/bin/python sawc/sawc.py blade/tests/dep_build.saw -o .build/scratch/dep_build \
    --module-path blade=blade/src --module-path toml=libs/toml/src \
    --module-path semver=libs/semver/src --module-path imgformat=libs/imgformat/src
error: module `manifest` not found
```
Building `blade/src/main.saw` works, because the importer and the entry share `blade/src/`. Module identity is also keyed by the import path's text (`_cache`, `module_map`), so a bare `import layout` and a self-named `import blade.layout` would load one file as two modules, which makes two `BuildLayout` types. SL-519 therefore writes Blade's in-package imports self-named (`import blade.layout`) everywhere, the ruling's other spelling. sawc2's resolver gives both spellings one module.

**2. A test that imports its package by name is in a different package for `public(package)`.** `Namespace.package_identity` puts every module under a `--module-path` name in `package:NAME`, and the entry (a test in `tests/`) in `manifest:<Saw.toml dir>`. With the ruled spelling `import NAME.x`, a test loses `public(package)` reach into its own package's modules. The old `import src.x` spelling kept both in `manifest:`. Repro (a scratch package with `Saw.toml`, `src/lib.saw` declaring `public(package) func pkg_only() -> Int { 7 }`, and `tests/reach.saw` doing `import pkgprobe.{pkg_only}`):
```
sawc tests/reach.saw --module-path pkgprobe=src
error: `pkg_only` is public(package) in `pkgprobe`
```
The same file with `import src.lib.{pkg_only}` compiles. No Blade or `libs/` module uses `public(package)`, so SL-519 is not blocked. Whether a package's tests are inside the package for `public(package)` is not settled by the ruling: the Rust analogy it cites (`use mycrate::layout`) puts integration tests outside the crate. sawc2 currently treats a test entry as outside every package (package ""), and an entry inside a mapped `src/` as inside it.

**Suggested:** two SL:hazards entries (the import search, and the package identity of a mapped package against its own tests), plus an open question for the second.

**Ruled by the user (Oct 11): a package's tests in `tests/` are OUTSIDE the package.** They reach its `public` members only. White-box tests use `@test` or a sidecar `x.test.saw` (SL:testing), which are part of their module, with private access. Logged in SL:open-questions (Resolved, "SL-531").
