**Found by U7b (SL-398, the backend over `compiler/`), fixed on its branch.** The new std's `StringBuilder` lacked `append(b: Byte)`, which Stage 0's std has and the compiler's own source calls (`compiler/lex/src/lib.saw` `char_str`, `escape_text`: `try! sb.append(to_byte(u))`).

**The mechanism.** Against `std/`, sawc2's typecheck resolves `sb.append(byte)` to the one remaining candidate, `append(value: Int)`, through a lossless `Byte` → `Int` widening. Stage 0 resolves the same call to the exact `append(b: Byte)`. So the program types under both stds and means two things: the Stage 1 compiler's `sawc2 lex` printed every token's text as decimal byte values (`(` as `40`), and keyword lookup then failed (`func` lexed as `IDENT`).

**Why nothing caught it.** The API-equivalence lane (`compiler/tests/std/equivalence.tsv`) compares the rows it lists, one declaration per row; nothing compares an overload *set*, so a member present in Stage 0's set and absent from the new std's is invisible unless a row names it.

**The class sweep.** Every method/init name both stds declare on one owner, through the lane's own `--interfaces` dumps: the new std lacks `File.read(size:)`, `StringBuilder.append(value: UInt)` and `StringBuilder.init(capacity:)` besides `append(b:)`. None of the three has a silent path: a `UInt` argument does not widen into `Int` (refused), and the other two are told apart by their labels, so a call is refused rather than retargeted. `append(b:)` was the one whose absence a widening reaches.

**The fix (U7b branch):** `std/stringbuilder.saw` gains `append(&var self, b: Byte)`, the raw byte, truncating in fixed mode as Stage 0's does; `equivalence.tsv` gains its row (`b:UInt8`, unit U5b2), which the lane now holds equal to Stage 0's; the three std cones move by `append_byte`; the run lane pins it (`compiler/tests/run/byte_append.saw`).

**Open:** whether the equivalence lane should compare overload sets per name, so the next partial set is a failure rather than a sweep. Left for the std's owner.
