## Description

Found by SL-275's obligation-4 census (the mechanism sweep for "a codegen site
answering an ownership question from an inline isinstance node-type list").
NOT fixed there: SL-275's four sites are all "does this transfer owe a RETAIN",
answered by routing to the shared transfer funnel. This one asks the OPPOSITE
question — "did the receiver's ownership LEAVE, so suppress its drop" — and the
funnel has no answer for it. Filed rather than fixed, per the no-workarounds
rule: the fix needs a ruling (see DISPOSITION).

## Symptom

`b.take<T>()` on an erased `Box<any Trait>` CONSUMES the box: it moves the
payload out on a hit, drops it on a miss, and frees the box shell inside the
call. Codegen suppresses the receiver's later drop only when the receiver is a
bare `Identifier`. Every PROJECTION receiver — a struct field, a tuple element,
an indexed element — therefore leaves the CONTAINER holding a shell the call
already freed, and the container's own scope-exit drop frees it a second time.

Measured, with a `NoCopy` payload whose `deinit` prints its id (a second deinit
reading freed memory is the tell; the box shell is heap, not immortal):

| receiver | spelling | result |
|---|---|---|
| bare binding (CONTROL) | `let b = Box<any Shape>.make(Res(id: 42))`, `b.take<Res>()` | correct — exactly one `gone 42`, exit 0 |
| struct FIELD | `struct W { b: Box<any Shape> }`, `w.b.take<Res>()` | `gone 42` then a SPURIOUS `gone 1` after main — id read from freed memory, **exit 0, silent** |
| TUPLE element | `let t = (Box<any Shape>.make(Res(id: 7)), 1)`, `t.0.take<Res>()` | `gone 7` then `gone 2`, then `Trace/BPT trap: 5`, **exit 133** |
| ARRAY element | `let arr: [Box<any Shape>; 1] = [...]`, `arr[0].take<Res>()` | `gone 5` then `gone 1`, **exit 0, silent use-after-free** |
| DRIVEN twin (field) | same field shape inside `Task.spawn(work())`, `yield_now()` either side | reproduces — `gone 42` then `gone 1`, exit 0 |

The field row is identical under `MallocScribble=1 MallocPreScribble=1`.

## Mechanism

`sawc/codegen/calls.py:1848-1854`, in `_generate_method_call`'s erased-downcast
arm:

    if (expr.erased_downcast['op'] == "take"
            and isinstance(expr.object, Identifier)):
        flag = self.drop_flags.get(name)
        ...
        self.moved_variables.add(name)

The drop-flag clear and the moved-variable mark are the whole suppression, and
both are gated on the receiver being a bare `Identifier`. A projection has no
drop flag of its own — the CONTAINER owns the storage — so there is nothing at
this site to clear, which is why this is not the one-line routing SL-275's four
sites took.

## Why it is a class and not this one spelling

Every receiver spelling that reaches storage a container keeps is affected: the
three probed above, and (unprobed) `self.field.take<T>()` inside a method, a
receiver reached through a `&`/`&var` parameter, and an optional-chain hop. The
MISS path (where the call drops the payload rather than moving it out) is
unprobed and frees the same shell, so it is presumed to have the same two
frees.

## The adjacent checker fact that scopes the ruling

The same field consume spelled with `move` is REFUSED, and its hint points at a
`take` spelling:

    error: (cannot move out of a field)
     14 |     let moved = move w.b
    hint: move the whole value (`move w`) or restructure so the piece is its own
          binding; a field moves out with `w.b.take()`, which leaves a valid
          value behind

That hint is about `Optional.take(&var self)`, which writes `None` back into the
place and so really does leave a valid value behind. The erased-Box `take<T>()`
is a DIFFERENT member with the same name and it leaves nothing behind — it frees
the shell. So `move w.b` is a partial-move error while `w.b.take<Res>()`, which
consumes the same field, is admitted and miscompiled.

## Disposition (needs a ruling — not taken here)

Two shapes, and they are not equivalent:

1. **REFUSE the form in the checker.** `take<T>()` on a projection receiver is a
   partial move by any other name, so it takes the no-partial-moves error, with
   a fixit naming the outs (`move` the whole container, or bind the box first).
   Consistent with `move w.b`, and it closes the class by construction.
2. **Make the consume write back a husk**, the way `Optional.take` does — so a
   projection receiver leaves a valid empty `Box` behind. That is a language
   question (is there an empty `Box<any Trait>`?), not a codegen one.

Option 1 looks right and is small; option 2 would need a design brief. Either
way the current state — admitted, then two frees — is the one thing it must not
stay.
