## Description

**`String` range subscripts (`s[a..b]`): §6's O(1) window conflicts with String's representation, so this needs a design ruling.** Found by SL-988 unit 2's census (`.build/scratch/p988/census_u2.md`).

- **What SL:borrowing §6 says:** a Copy-tier refcounted parent (`Data`, `String`) copies a range in O(1), as a window sharing the parent's storage. Strings are byte-indexed, and a cut inside a UTF-8 character panics.
- **What String is:** `struct String { private bytes: UnsafePointer<Int8> }`, one pointer to a `{ refcount, len, bytes…, NUL }` block. The spec calls it "a single pointer" that "stays NUL-terminated for zero-copy C FFI". There's no offset or length to narrow, and a window couldn't stay NUL-terminated.
- **Unstated:** what a named view (`borrow let t = s[1..3]`) lends, a `&[UInt8]`/`&[Byte]` or a string view type, and whether `borrow var` on a String is refused.

**Options for the user:**
- **(a) Change String's representation** (pointer, offset, length) so a slice is an O(1) window. It touches the string lang-item roles, literal emission, `c_string`'s NUL guarantee and the FFI.
- **(b) A separate string-slice view type** that borrows a String's bytes. `s[a..b]` gives a view, and an owned copy is O(n) (`substring`).
- **(c) No range subscripts on String;** `substring` remains the way.

**Today (SL-988 unit 2):** `s[a..b]` is refused with a reason naming `substring`.
