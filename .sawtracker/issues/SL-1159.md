## Description

**`std.spinlock.SpinLock`: spin, then yield the thread.** Requested by the sawos owner (chat m1275 and m1276, Nov 17): after N failed attempts to take the lock, call a runtime seam that yields the OS thread and retry, instead of spinning for the rest of the time slice. Why: on a single-core, preemptively scheduled target (the ESP32-S3; sawos on every board today), a waiter that spins while the holder is preempted burns its whole slice (a 10 ms tick there) before the holder can run and release; a yield hands the core to the holder at once.

**The seam:** a weak, do-nothing default, so a runtime with nothing to yield to writes no code, and a runtime that can yield overrides it with a strong definition (sawos's sosrt answers with the kernel's thread-yield op, in SO-142; it also answers `__saw_rt_lock_owner` with a per-thread identity). Hosted: the host's thread yield (`sched_yield`).

**To settle in the detail (with evidence):**
- The name, in `runtime/ABI.md`'s style and the no-abbreviation rule: a thread yield, distinct from the cooperative `yield_now` (std.task): e.g. `__saw_rt_thread_yield()`. Where the weak default lives (std or the runtime, per how the existing weak helpers are supplied) and that `tools/test_runtime_abi_doc.py`'s frozen set is updated.
- N: a named constant in `std/spinlock.saw` (stated why that value; perf work is by measurement, so the first value is a documented default, not a tuned one), or a runtime answer; the lead's default is the std constant.
- The lock's `sync`-enforced body: the seam call must be legal there (a `sync` extern, no suspension).
- Tests: a hosted program where two threads contend (the yield path taken, counted), and a freestanding suite case on a single-core row where a holder is preempted (if the suite's runtime can preempt; else a case that the seam is reached and the weak default links).

Related: SO-142 (sawos), the SpinLock design (std.spinlock).

**The implementer's stop (Nov 19): no weak-symbol mechanism a seam can use.**
- sawc has no `@weak`.
- Its only weak definitions are std's freestanding builtins (`ll_builtin_export` → `define weak`, for `std.builtins.*` modules or LLVM libcall names).
- `export_name_ok` refuses any `__saw_*` export outside a runtime compile.
- `runtime/shim.c` has no weak C definitions and is hosted-only.
- In a `--freestanding --runtime` build, the runtime package and std's builtins share one LLVM module, so a weak default and a strong override would be two definitions in one module, with no dedupe today.

**Owner ruling (Nov 19): a `@weak` attribute.** It is new language surface, so an Opus design pass comes before any implementation. It settles:
- the spelling (`@weak` beside `@export`? a standalone attribute? on which declarations: functions only, or statics too);
- the semantics per object format (ELF weak and Mach-O weak definitions differ; what `ld.lld`, `ld64` and Espressif's linker do with two weak or one weak plus one strong);
- the same-module duplicate rule (a weak and a strong definition of one symbol in one compile: the strong one wins, or a compile error?);
- how it composes with `@export`'s reserved-name rule (a `__saw_rt_*` weak default from std);
- hosted vs freestanding;
- the spec, GRAMMAR.md, the conformance impact (if any), and the units.

SL-1159's SpinLock change then uses it: a weak do-nothing `__saw_rt_thread_yield` default, overridden by sawos's sosrt, with `sched_yield` hosted.
