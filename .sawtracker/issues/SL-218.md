## Description

SOUNDNESS. A `self` RECEIVER READ is not an aliasing expression, so every
transfer of `self` by value is judged a FRESH TEMPORARY and duplicates a value
the CALLER still owns. Double free at exit 0 on NoCopy, SIGABRT on
ExplicitCopy. Found Sep 9 by SL-210 (design 267 unit A) while inventorying the
ownership boundaries; NOT introduced by that unit, and deliberately NOT fixed
there — SL-210 is behavior-preserving, and the fix changes which programs the
compiler accepts.

## The mechanism (obligation 4 — this is a CLASS)

`_is_aliasing_expr` (`sawc/typechecker/types.py:3440`) decides the whole
producer question — "does this expression read out of storage somebody else
keeps?" — as a NODE-TYPE TEST over exactly four classes:

    _ALIASING_EXPR_TYPES = (Identifier, MemberAccess, ArrayIndex, TupleIndex)

plus two hand-added transparencies (`ForceUnwrap`, design 131; a forwarding
`CastExpr`, DF-299a) and one hand-added exclusion (`enum_variant_literal`,
design 139). Any node that reads out of existing storage and is not on that
list answers False, and every tier arm of `_check_value_transfer` is gated on
it — so NoCopy and ExplicitCopy skip their refusal and the Copy tier skips its
`needs_copy` stamp.

`SelfExpr` is on none of the lists. This is the SAME mechanism as DF-216a (the
compiler-synthesized call constructions that skipped `_check_value_transfer`)
and DF-299a (`CastExpr`), which is why it is filed as a class rather than as
one symptom: the enumeration below is the whole `Expression` subclass set
checked against the question, and the ONE remaining member is the auto-wrap
family, already filed as SL-79.

## Measured evidence

All programs compile clean and exit 0. `Res` is `NoCopy` with a printing
`deinit`; one value, two `drop` lines.

    struct Res { w: Int }
    extension Res: NoCopy { func deinit(&var self) { print("drop {self.w}") } }
    extension Res { func clone_me(&self) -> Res { self } }
    func main() { let a = Res(w: 7)  let b = a.clone_me()  print(b.w) }
    // prints: 7 / drop 7 / drop 7   — exit 0

SIX FACES, each measured, each double-freeing:

  1. RETURN — `func clone_me(&self) -> Res { self }`
  2. BY-VALUE ARGUMENT — `func hand_on(&self) -> Int { sink(self) }`
  3. LET BINDING — `func to_local(&self) -> Int { let b = self  b.w }`
  4. STRUCT FIELD — `func to_field(&self) -> Int { let bx = Box2(r: self) ... }`
  5. TUPLE ELEMENT — `func to_tuple(&self) -> Int { let t = (self, 1) ... }`
  6. `&var self` RECEIVER — `func from_var(&var self) -> Res { self }`

  (one program, `drop 1 / drop 2 / drop 3 / drop 4` each printed twice)

TIER SPREAD:

  * NoCopy — double free, exit 0 (above).
  * ExplicitCopy — SIGABRT. `struct Bag { v: Vector<Int> }` with a
    `@synthesize ExplicitCopy`, `func out_return(&self) -> Bag { self }`:
    prints `3 / 3` then `Abort trap: 6` (the buffer is freed twice).
  * Copy — CORRECT, and that is the point. `Arc.strong_count()` reads
    1 before / 2 after, because codegen's `_transfer_needs_copy`
    (`sawc/codegen/resources.py:1603`) carries `SelfExpr` in its OWN isinstance
    list and retains there. That is the epic's "codegen sometimes compensates
    independently" (SL-209) visible in one program: codegen can mint the
    missing retain but cannot deliver the missing REFUSAL, so the hole is
    invisible on the tier that can be papered over and fatal on the two that
    cannot.

## Where it shows in the new record

SL-210's decision ledger (`sawc/typechecker/ownership.py`) makes the hole
legible without reading the checker: the `self` transfers above are recorded

    take / adopt-temporary / tier=nocopy / source=receiver 'self'

— a NoCopy-tier source correctly CLASSIFIED as a receiver and then actioned as
a fresh temporary. The source-identity walk already knows what `self` is; only
`_is_aliasing_expr` does not.

## Pin

`examples/conformance/V86_self_receiver_read_is_a_transfer.saw`, XFAIL citing
this issue, with EXPECT directives stating the intended refusal. Conformance
INDEX row V86.

## Fix shape (NOT this issue's scope to land unreviewed)

Adding `SelfExpr` to `_ALIASING_EXPR_TYPES` is one line and REJECTS PROGRAMS
THAT COMPILE TODAY, so it is a language-rule change owing a corpus sweep (std
and blade both have `&self` methods returning `self`-derived values) and the
tier-blindness rows V62/V65 teach: fence every tier, not only the owning ones.
Natural home is SL-211 (unit B, the forwarding taxonomy) or its own brief; the
`try`-family sibling filed beside this one shares the mechanism and should be
swept and fixed with it.

Fixed AS THE MECHANISM, which is what this issue asked for. `_is_aliasing_expr` stopped being a node-type list: the producer question is now a TOTAL classification over six kinds in `sawc/typechecker/producers.py`, and `tools/test_producer_taxonomy.py` fails the build when a value-position node is in no bucket. `SelfExpr` joining READS is one row of that table — the one-line fix this issue named, with the shape that made it necessary removed alongside it.

All six measured faces are refused now (return, by-value argument, `let`, struct field, tuple element, `&var self`), and the Copy tier still duplicates EXACTLY ONCE — conformance row V89 counts it with a hand-written `copy()` hook that prints, so implicit duplications are observed directly rather than inferred from a refcount. That row exists because of this issue's own finding: codegen's `_transfer_needs_copy` carries `SelfExpr` in a list of its own, so the risk the fix carried was a SECOND duplication beside the derived one, not a missing first.

THE FIXIT CHANGED, per V86's pin. The old "use `move` to transfer ownership instead" was a dead end — a borrowed receiver has nothing to move, because the value is the caller's. It now names the two real outs: declare the method `consumes` (design 260), or give the type a duplicable policy and spell `self.copy()`.

CORPUS COST: zero. No `self`-returning shape in std, blade, libs, devtools or the corpus relied on the hole.

SWEEP NOTE for the record: DF-288a's borrowed-scrutinee rule keeps its OWN `SelfExpr` arm ahead of the aliasing test, so `match self` is untouched. That arm's comment said a receiver "reaches neither the aliasing set below nor a scope lookup" — no longer true, and the arm stays as the narrower rule it is. The consuming-receiver funnel now asks for `(move self).finish()` where it used to treat `self` as a temporary receiver; correct, and unreached by the corpus.
