**Found by:** u7skel and u7b (U7a, SL-505, merged as 7e04eaa0). **Area:** mono's glue and the LLVM backend's closure lowering.

**Today:** a closure whose environment holds an owning capture is refused as `backend.not-yet`, since freeing the environment isn't built. Escaping closures are refcounted `Copy` (SL:open-questions, Oct 9), so the environment needs a release that drops each owned capture once.

**Not on the bootstrap path:** `compiler/` takes no closure captures (SL:architecture §4). Pin it with run-lane programs: a String capture, a NoCopy capture moved in, and a copied escaping closure released twice.

**Invariant for SL-525 (from SL-795, the Air's c1):** the heap environment of an escaping closure KEEPS the spec's ATOMIC refcount word. SL-795 grants a closure type `Send + Sync` when its captures are, which is sound only if copies on two threads can retain and release the environment concurrently. Pin: a closure copied into two threads and dropped on both, run many times under the gmgate lane. Also registered here: SL-795's capture-proven run pins (a closure capturing only `Send + Sync` values crossing into a `threads:` task; one capturing a non-`Sync` value refused, naming the capture), which need SL-525's heap environments to build.
