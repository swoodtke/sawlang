## Description

**A const generic value may exceed the target's `Int`: SL-457's unit U4c, ruled yes by the project owner (Nov 14: "for the blocking work, i agree with the recommendations", on the lead's list, where this was Q-W with the recommendation "yes, as one more unit").**

**The question that was open.** The spec says a const parameter's type may be any primitive integer type and states no limit, but the fold carries a const generic value at the target's `Int`, so a `const M: UInt32` cannot take `0x8000_0000` at riscv32 and a `UInt64` parameter cannot take 2^63 and up anywhere. Register masks and addresses on 32-bit targets are the use.

**The ruling: widen.** A const generic value is held at its parameter's own type's width, whatever the target's `Int` is.

**Where the design is.** SL-457's U4 detail (`.build/scratch/p457u4/detail.md` in the lead's checkout, also a comment on SL-457): its question Q-W, option (A), and the conditional unit "U4c". The lead's review of it is `.build/scratch/briefs/q457u4_lead_review.md`. Before dispatch the lead writes this issue's implementation detail from that section against main as it is now (U4a, U4b and the p7 follow-up have landed since): where a value is narrowed to `Int` today, what a length or a repeat count does with a value its position cannot hold (an array length is still the target's word), the mangling of an instance, and the rows (a `UInt32` parameter at `0x8000_0000` and `0xFFFF_FFFF` on riscv32; a `UInt64` parameter at 2^63 and `UInt64.max` on every target; a negative value into an unsigned parameter still refused).

Related: SL-457 (closed), SL-1095 (a struct's `sizeof` as a constant), SL-1116 (layout overflow).

**The representation.** `ConstInt` keeps its key's shape: `a` holds the value's low 64 bits and `b` is 1 for a value at or above 2^63, so a constant's domain is [-2^63, 2^64) and a constant is a VALUE, not bits awaiting a type. One funnel makes constants (`mk_const_at(bits, ty)`), and three read them (`const_fits`, `const_negative`, `const_text`). Every constant main can make has `b == 0`, so no key, symbol or object changes: 47 of 48 builds (16 programs, IR on host and riscv32, objects on host) are byte for byte main's; the 48th is a program main refuses. Rejected, with reasons in the design: raw bits read by the parameter's type (`F<2^64-1>` and `F<-1>` would share a key once a value is forwarded), a constant carrying its type (splits identity: `Buf<4>` against `Buf<4u8>`, and changes mangling), a wider integer (Saw has none; it amounts to the flag).

**The change.** An argument is no longer converted to the target's `Int`: the parameter's existing fit check is the only judge of its value. A length or a repeat count stays an `Int`, and a value past it is refused at the instance by the funnel that already refuses a negative one, with one new message: "an array length `N` is V, which does not fit `Int`, at this instance".

**Proved by the prototype:** on riscv32 under QEMU, a `UInt32` at `0x8000_0000` and `0xFFFF_FFFF` reads back whole through a function's parameter, a struct's, a static, a forward into `UInt64` and `K + 1`; a `UInt64` at 2^63 and `UInt64.max` on both targets; a negative value into an unsigned parameter and `18446744073709551615u64` into an `Int64` still refused; two values differing only above 2^63 are two instances with two symbols. **The project owner's ruling on Q1 (Nov 15, in the lead's session, answering "should an unsuffixed literal argument take its parameter's type?"): "Yes, infer from the parameter".** So `Mask<0x8000_0000>` with `const M: UInt32` on riscv32, and `Big<18446744073709551615>` with `const N: UInt64`, are accepted: a literal written as a whole const generic argument takes its type from the parameter it fills, as a literal in a typed slot does (`let x: UInt32 = 0x8000_0000`). A literal that does not fit the parameter's type is refused with the existing fit diagnostic; a literal inside an expression argument (`Mask<0x8000_0000 + 1>`) is outside this ruling and keeps today's rule unless the unit's design says the parameter's type reaches it too (to be raised then, not decided by the unit).

**Units now:** U1 (the representation and its readers), U2 (the widening), then **U3** (the literal takes its parameter's type), which the design pass did not design: the pre-signature pass types an argument before a call's candidate is chosen, so U3 needs a short design of where the literal is typed once the parameter is known. U3 is written after U2 lands.

## What changes that the note does not name

| | host | riscv32 |
|---|---|---|
| refused before, builds after | 33 | 12 |
| refused by both, the rule moves | 6 | 3 |

- **Refused before, builds after.** Each is a `UInt64` expression over a const parameter (a `UInt` one on the host) whose intermediate value is 2^63 or more and whose result is below it: `[7u8; (K << 40) >> 60]` at `K = 8388608`, `v<(K + 1) - 1>` at `K = 2^63 - 1`. It builds in a repeat count, a length, an argument, a struct's field type, a return type, a method of a generic struct, and with one parameter still open (`((K << 40) + J) >> 60`). v0.24.2 says "constant expression -9223372036854775808 does not fit in `Int64`"; the old fold refused any result `Int64` cannot hold, and the new one keeps it as a high constant.
  - Every value printed is right: 2^63 / 3 is 3074457345618258602, 2^63 % 1000 is 808, `>> 63` is 1 (a logical shift), `(~K) >> 60` is 15. The riscv32 IR of the first holds `[8 x i8]`.
  - The spec has them build: a parameter's "arithmetic runs at" its type, and the fault is "an overflow at the parameter's type" (Const generics). The form with no parameter already builds on v0.24.2 (`[7u8; (1u64 << 63) >> 60]`).
- **The rule moves** where the old stop hid a later fault: `type.mismatch` becomes `constant.overflow` for `(K + 1) * 2`, `-(K << 40)` and `(K << 40) + (K << 40)`, and `constant.shift-range` for `1 >> (K << 40)`.
- **The message moves**: the fixture's own change in a length, a count and two levels of forwarding; a cast of 2^63 now names its target (`does not fit in `UInt32``); and a type is spelled with the part folded, `[UInt8; (9223372036854775808 + J) >> 60]` where it was `((8388608 << 40) + J) >> 60`.
- **For U2's rows:** one count and one argument with an intermediate of 2^63 or more, run on the host and checked for riscv32; the refusals whose rule moved; the folded spelling.
