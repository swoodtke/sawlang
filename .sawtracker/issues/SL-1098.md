## Description

**Filed by the sawos lead for the sawlang lead.** The user asked that sawos's build tools be written in Saw, not Python, and that the gaps be filed here. Each was hit while designing sawos's image builder (SO-95, tracker doc `SO:images-and-packaging`, section 11). Run against sawlang 0.23.0 (`sawc-stage2` and its `blade`), hosted on macOS arm64, by the design's author; "reproduced" means it was run, "read" that only the source was read.

- **Tried.** In a package that builds an sosimg, reproduced:
  `blade build --target riscv32-unknown-none-elf --linker-script /tmp/x.ld`,
  then the same with `--out-dir /tmp/o`, then with
  `--module-path imageplan=/tmp/p`.
- **What happened.** Each printed `Finished .build/riscv32-unknown-none-elf/
  hello-product.sosimg (up to date)` and exited 0. Each flag was ignored
  without a word. `blade/src/cli.saw` knows `--target` and `--force` for
  `build`.
- **Expected.**
  - `--linker-script PATH` overriding `[sos.<triple>] linker-script`;
  - `--out-dir DIR` replacing `.build/<triple>/`, with nothing written
    outside it;
  - `--module-path NAME=DIR`, repeatable, passed through to sawc;
  - and an error for any flag Blade does not know.
- **Why sawos needs it.**
  - On a board that does not translate, every image links each process at
    an address that image assigns, so one driver package is linked
    differently per image.
  - Two images, or two parallel test cases, must not overwrite one
    another's output.
  - The stock root and drivers take generated or product-supplied modules
    (`imageplan`, a pin table).
- **How badly.** Blocks generated link addresses, several children in
  place on the S3, the stock root and config modules. The ignored-flag
  behaviour is worth fixing on its own. The workaround I rejected: an
  `SOS_LD` wrapper that rewrites `-T`, which races on the shared output
  directory.

Related: SL-19 (out-of-tree Blade target plugins).

**Implementation detail (lead, Nov 13).** Filed by sawos for its first product; ahead of the queue.

**The mechanism (obligation 4), which is wider than the three flags.** `scan_args` (`blade/src/cli.saw`) takes a set of value flags and treats EVERY other `--word` as a boolean flag that is recorded and never asked about, every bare word as a positional nobody reads, and a value flag at the end of the line as the value `""`. So for every subcommand: an unknown flag, a misspelled one (`--targt x` builds for the host and treats `x` as a positional), a stray word, a missing value, and `--help` after a subcommand (`blade build --help` builds) are all accepted in silence. `test`, `tree`, `update` scan nothing at all. The fix is the scanner, once; the three flags are then rows of its table.

**1. The scanner.** One description per subcommand: each flag it takes, whether it takes a value, whether it may repeat, and how many positionals the subcommand takes. `scan_args` returns `Result<ScanResult, ParseError>` and refuses, naming the subcommand and the word:
- a flag the subcommand does not list (`blade build: unknown flag `--x``), a single-dash word included;
- a value flag with no value after it, or followed by another flag;
- a flag that does not repeat, given twice;
- a positional the subcommand does not take (`build`, `clean`, `update`, `test`, `tree` take none; `new` and `add` take one).
A value flag is also accepted as `--name=value`. `--help` or `-h` after any subcommand prints the help and exits 0. `run` is unchanged: everything after `run` is the program's own arguments. The table, per subcommand, is the test matrix (obligation 1): each row has an accept case and each refusal above has a case, for every subcommand.

**2. `--out-dir DIR`** (`build` only). The build's directory is DIR itself, in place of `.build/<target>/`: the artifact, the freshness stamp and every intermediate. `BuildLayout` carries the override and `dir()` answers it, so nothing else changes if every write already goes through the layout. **Sweep that:** every path Blade writes during `build` and `build_sos_image` (grep the literals `.build`, `.blade`, and every `File.create`/`-o` argument). A write that bypasses the layout is routed through it. Not build output, unchanged and said so in the help: `Saw.lock`, git dependency checkouts under `.blade/deps/`, and sawc's own caches. `clean`, `run` and `test` do not take the flag (a `clean --out-dir` would remove a directory the user names; not offered). DIR is relative to the working directory and is created.
Pins: a build with `--out-dir` in a package with no `.build` leaves no `.build` behind; two builds of one package with two out-dirs and two targets each report their own freshness; a second build with the same out-dir is "up to date".

**3. `--linker-script PATH`** (`build` only, image builds only). Overrides `linker-script` of the selected `[sos.<triple>]` section. Refused before anything is compiled when the build is not an image build (no `[sos]` for the target: "`--linker-script` applies to an image build") or the file does not exist.
**Freshness is the hazard.** Find what the image build's freshness hash covers (`build_hash`, and whatever `build_sos_image` adds). The script's CONTENT must be in it, whichever way the script is named, or a build after changing the script (or switching `--linker-script`) answers "up to date" with the old image. If the manifest-named script's content is not hashed today, that is an existing staleness bug of the same mechanism: fix it here and report it with a before/after (edit the script, rebuild, `Finished ... (up to date)` before; a relink after). Check the same for every other file the image build reads that is not a `.saw` under `src` (the HAL objects, the C sources, `SOS_*` variables): list what is and is not covered; fix only the linker script, report the rest.
Pin: two builds of one package into two out-dirs with two scripts that place `.text` at different addresses produce images whose entry or load address differs as the scripts say (read it from the linked ELF or the sosimg header, whichever the lane already reads).

**4. `--module-path NAME=DIR`** (`build` only, repeatable). Passed to every sawc invocation of the package's own compile exactly as sawc's flag of the same name, after the dependencies' own (read how Blade passes a dependency today and mirror it; DIR means what sawc's flag means). Refused: no `=`, an empty NAME or DIR, a NAME given twice, a NAME that a resolved dependency already has (name both sources), a DIR that does not exist. The freshness hash covers each NAME, DIR as written, and the `.saw` content under DIR.
Pin: a fixture package that imports a module it has no dependency for builds with the flag and is refused by sawc without it; changing a source under DIR rebuilds.

**5. The contract flip's consumers (obligation 2).** Unknown flags and stray words were accepted; now they are refused. Grep every Blade invocation in the repository (`tools/`, `bin/`, `Makefile`, `blade/tests`, `libs/`, `tests/freestanding/`, the docs' command lines) and list each with its flags; any that passes a flag or word Blade does not take is fixed and listed. sawos is told by the lead.

**6. Docs** (saw-docs skill first): `print_help` in `blade/src/main.saw`; README's Blade commands; LANGUAGE_SPEC.md "Image manifests (`[sos]`)": the flag beside `linker-script`. Quote what was added.

**Tests.** Blade's own tests (`blade test` in `blade/`) for the scanner's table. `tools/blade_lane.py`: a check for each pin above, built on the lane's existing image fixtures (`blade/tests/fixtures/sos*`, `tests/freestanding/bladepkg`) and tool discovery; a check that skips for a missing tool says which, as the lane's others do.

**Shape.** `BladeCommand.Build` carries the options as one value (a struct; `Builder` takes it), not four more enum fields.

**Stops.** Something the build writes cannot be moved under the out-dir (say what and why). The image build's freshness is computed somewhere this detail did not name and the fix would change a stamp format other tools read. A consumer in step 5 relies on an ignored flag in a way that is not a one-line fix.

**Gate.** `tools/blade_lane.py`; `compiler/tests/run.py --only docs,comments`; `tools/battery.sh citations`; `tools/freestanding_runner.py` only if `tests/freestanding/bladepkg` changes.

**Files expected:** `blade/src/cli.saw`, `main.saw`, `builder.saw`, `layout.saw`, `sosimg.saw` as needed; `blade/tests/`; new fixtures under `blade/tests/fixtures/`; `tools/blade_lane.py`; README.md; LANGUAGE_SPEC.md.
