## Description

**Lang-item binding takes a test-only std declaration, so a normal build emits test code.** Found by SL-698's sweep (agent m698main).

**Mechanism:** a role picked by name that doesn't filter test-only declarations. `bind_lang_items` binds each role through `std_top_decl` → `module_top_decl` (`compiler/resolve/src/lang.saw`), which returns the newest declaration of that name in the std module, test-only or not. SL-698 fixed the same lookup on the typecheck side (`TcProgram.top_decl`, which mono's `main` root, `exec_entry`, `resolve_spawn`, coro's `coro_context_shape` and `find_known` read). Resolve's copy wasn't in that unit's file area.

**Evidence** (Stage 2 at c4ea336a3 plus SL-698's fix): copy `std/` and make `__saw_exec_run_main` (the `ExecRunMainFunction` role) test-only: `@test public(package) func __saw_exec_run_main(...)` in `task.saw`. Then `sawc2 build --std-root COPY compiler/tests/run/background_task_spawn.saw` exits 0, the binary runs, and `nm` shows `t _saw std.task.__saw_exec_run_main(...)`. Expected: the role is missing in a normal build, so `lang.missing`, as for a std root that doesn't declare it.

**Reach:** today's std has no `@test` code, and sawc2 loads no sidecars (`*.test.saw`), so the tree as it stands can't hit this. It opens once std carries test code, or with any `--std-root` that does. A type role, or a function role that production std names, is already refused as `test.only-reference` (probed: `TaskContext` and `TaskProvenance` made test-only). The roles that only the compiler calls aren't: the entry executor, the panic sink, the String roles and the park points.

**Fix:** `module_top_decl` passes test-only declarations over. Better still, one resolve funnel that both it and typecheck's `top_decl` call, with its entry points named. Pin: a std-root fixture with a test-only compiler-called role, refused `lang.missing`.
