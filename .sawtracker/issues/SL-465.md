Found by U5b2 by reading the code (SL-456.p2 finding 2; the Air's review, note 3). In fixed mode (StringBuilder(bytes:capacity:)), appending a multi-byte scalar near capacity can write some of its bytes, leaving a String with invalid UTF-8. That breaks String's invariant rather than truncating on a boundary with the ellipsis. sawc/ is frozen: recorded as SL:hazards L25 (no compiler/ use of fixed mode today), and the new std truncates before the whole encoding. Needs a Stage 0 run probe to confirm, attached when the hazard is next touched.

Closed by the SL-1064 reconcile sweep (agent preconcile, Sonnet; Nov 12), re-probed against `sawc` at main eb43124e8.

**Verdict: FIXED.**

- **The rule:** LANGUAGE_SPEC.md:3336-3339 "content that does not fit is cut on a UTF-8 boundary and the marker `…` is stamped in its place, so a shortened result says it was shortened. `is_truncated()` reports it"; std/stringbuilder.saw:305-306 doc: "A fixed builder that cannot hold the whole encoding truncates before it, so no half of a scalar is written"
- **What `sawc` does:** SL-465.saw, capacity 8 (4 text bytes), -O0 and -O2: prefix "abc" + U+1F600 (4-byte): bytes "97 98 99 226 128 166" (abc + the `…` marker E2 80 A6), truncated=true; prefix abc + U+20AC and + U+E9: same bytes; prefix "ab" + U+1F600: "97 98 226 128 166"; prefix "a" + U+20AC fits exactly: "97 226 130 172", truncated=false; "ab" + U+20AC cut; "abcd" + U+41 cut. No lead byte without its continuation anywhere (source: std/stringbuilder.saw:320-327 reserves the whole encoding + NUL before placing any byte).
- **Note:** Matrix: 1-, 2-, 3- and 4-byte scalars at one-free-byte, exact-fit and over-capacity.
