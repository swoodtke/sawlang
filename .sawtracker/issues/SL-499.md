**Split from SL-459 item 10** (misc459). **Area:** resolve, `walk_trait` in `compiler/resolve/src/walk.saw`.

**The defect:** a bare `Item` inside a refining trait (`trait Pipe: Source { func pull(&var self) -> Item }`, where `Item` is declared by `Source`) is `name.undefined`; only `Self.Item` works. `walk_trait` binds only the trait's own associated types, not inherited ones.

**The rule:** W4 in SL:open-questions (user, Oct 9) says a bare `Item` names the associated type inside the trait. The spec doesn't cover refinement directly. The reading is that an inherited associated type is in scope in the refining trait the same way, but confirm it against the spec's trait-refinement text.

**Sweep:** two levels of refinement; a refining trait that also declares an associated type with the same name (decide: a conflict, or a shadow refused); use in a default body; use in a where-clause or bound.

SL-459 c13's item 9 fixed the conformance side: `assignment_for` falls back to the parent conformance.

Landed in SL-496.p1, approved by the Air.
- **The new std's `Vector`:**
  - `get(&self, index: Int) unsafe -> T?` is the optional copy, declared in `extension Vector<T: Copy, …>`. A move-only `T` is refused as `type.bound` at the call.
  - `find(&var self, index: Int) unsafe borrows -> &var T?` is the conditional lend, with a `@synthesize(shared)` twin.
- **Resolve (SL-499):** a refining trait names an inherited associated type bare. Redeclaring one is `name.duplicate-declaration` (D34).

Follow-ups filed: SL-501, SL-502 and SL-503.
