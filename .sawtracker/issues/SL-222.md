## Description

Building sawtracker against main 88fa56ba fails with: 'coroutine transform: move of a frame local in a nested tail-expression of driven open_store is not supported; move it in a return statement instead'.

The refusal is over-broad. parse_block (sawc/parser/statements.py:60) unconditionally promotes a block's final ExpressionStatement into Block.final_expr - including a DISCARDED void call at the end of a loop body - and _FrameBuilder._lower_block_body_in_place (sawc/coro_transform.py:7860-7875) then refuses any __saw_forget that tail owes. The with-a-value justification in the _lower_block_in_place docstring does not apply to a discarded tail, and _norm_block's DF-158b branch (coro_transform.py:4276-4286) already demotes a void FUNCTION-BODY tail for exactly this reason; the nested case never got the same treatment. Suggested fix: when the tail is void or the block's value is discarded, demote final_expr to an ExpressionStatement and append the forgets.

Three ingredients are each load-bearing (drop any one and it compiles): an ITERATOR for loop (range for desugars differently), an early return inside the block, and an &-borrow of the moved local (address-taken => legacy drop-flag encoding; slot-encoded locals move fine). Newly REACHED by SL-208's cross-module transform, but the defect predates it.

Reproducer: sawtracker repros/coro_tail_move.saw + repros/coro_tail_move_mod.saw (compile the entry file; two-file, module-qualified suspending call). Worked around in sawtracker ST-13 by prefixing the four open_store call sites with 'let _ =' (a LetStatement can host the forget).

Requested changes on patch SL-222.p1 (revision 1)

Review of SL-222.p1 revision 1 (applied commit 99305a0a, base f1794b07): requesting changes for one remaining case of SL-222. This is an incomplete fix of the reported discarded-tail class, not a claim that the patch introduced the original refusal.

[P2] Preserve discarded context through a tail conditional before rewriting its blocks.

Location: sawc/coro_transform.py:7346 (the new unconditional value_used=True for a Block reached through expression recursion), together with _lower_block_body_in_place's call to _rewrite_hosting before demotion.

The loop body is correctly entered with value_used=False, but its final expression is still sent through _rewrite_hosting as an expression. If that final expression is a void if, its branch Block reaches the generic Block arm and is unconditionally reclassified as value_used=True. A move in that branch's tail therefore raises the supposedly unreachable value-used refusal, even though neither the if nor the loop consumes a value.

Reproduced on the submitted patch with:

```saw
import std.task.{yield_now}
struct Res { name: String }
extension Res: NoCopy {}
func note(r: &Res) -> Int { r.name.len() }
func sink(r: Res) {}
func run(items: Vector<Int>) -> Int {
    yield_now()
    for i in items.iter() {
        var r = Res(name: "item")
        if note(&r) + i < 0 { return -1 }
        if i > 0 { sink(move r) }
    }
    1
}
func main() { print(__saw_drive(run([1, 2]))) }
```

Command: the project venv's Python running `sawc/sawc.py .build/scratch/nested_tail.saw -c -o .build/scratch/nested_tail`. Result: exit 1, "move of a frame local in a nested tail-expression of driven run whose value is used is not supported". Adding only `print(i)` after the final if makes the program compile, because the if then travels through statement lowering with discarded context. The direct sink tail in the patch's own fixture also compiles. Thus the three load-bearing ingredients remain the same; nesting the discarded call under a final conditional is enough to evade the fix.

Please lower a discarded final expression through the statement path, or propagate its discarded context through nested control-flow tails, before _rewrite_hosting can assign value_used=True. Add a regression for a final void conditional (and its nested control-flow siblings); the claim that no source shape reaches the remaining refusal is currently false.

Validation: isolated worktree at the exact patch base. The control and the patch's four successful same-/cross-module SL-222/223 fixtures compile to objects; the SL-224 fixture produces the expected defining-module diagnostic at sl224_anchor.saw:14:5. The forget-citation gate and git diff --check pass. The server reports all 2443 compiler tests passed, 12 expected failures, and all 36 freestanding tests passed for 99305a0a. Local runtime execution was not repeated; the finding is a compile-time refusal reproduced directly. No additional actionable finding from the SL-223/224 review.
