## Description

**`examples/conformance/INDEX.md` has two K53 rows.** One is "a driven `for` over a range runs exactly its sync twin's iterations" (`K53_driven_for_range_iteration_count.saw`), the other "an MT group's workers PERSIST across spawns" (`K53_mt_group_stays_live_across_spawns.saw`). Found by p808fix on Oct 22, while it checked the union merge of its rebase. It is on main today, so it predates SL-808.

CLAUDE.md says a duplicated row id fails the borrowck lane, but the lane passes with this duplicate. So the lane's duplicate check either doesn't read INDEX.md or doesn't run over it. Name the mechanism (obligation 4): which ledgers the check reads, and whether other duplicates exist.

**Scope:**
- renumber one K53 row (and its program's name and citations) to the next free id;
- make the duplicate-id check cover INDEX.md, with a fixture that fails on a duplicate;
- sweep the other two union-merged ledgers (`compiler/tests/borrowck/CONFORMANCE.md`, `compiler/tests/drops/conformance.tsv`) for duplicates.

Mechanical; Sonnet-sized.
