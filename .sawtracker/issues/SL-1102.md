## Description

**`blade build` answers "up to date" after a change to several things the build reads: a source in a subdirectory of `src`, a native C or assembly unit, a dependency's manifest, the compiler, the tool variables.** Found by SL-1098's agent (Nov 13) while adding the linker script to the freshness hash (which SL-1098 fixes; before it, editing the script also left the old image in place).

**The mechanism.** `Builder.build_hash` (`blade/src/builder.saw`) hashes `Saw.toml`, `Saw.lock`, a constant marker (`sawc-1`) and, through `append_dir_saw`, the `*.saw` files DIRECTLY inside `src` and each dependency's `src`. `is_up_to_date` compares that with the stamp. Anything the build reads that is not in the hash can change without a rebuild.

**Not covered** (the agent's list; the first is read from the code and SL-1098's `--module-path` walk, which had to recurse, and none is yet shown by a run):
- `*.saw` files below the top level of `src`, the package's or a dependency's. A package with `src/net/tcp.saw` that edits it gets `Finished ... (up to date)` and the old binary.
- the native C and assembly units an image's `native` key names;
- a dependency's `Saw.toml`;
- the compiler: a new sawc leaves every package "up to date" (the marker is a constant);
- `SOS_CLANG`, `SOS_LD` and `SAWC`, which choose the tools.

**To do first.** Show each by a run (build, change the one thing, build again, quote the `Finished` line), starting with the nested source, which is the one an ordinary package hits. Then name the rule: the hash covers every file the build reads and the identity of every tool it runs, gathered in ONE place the builder's readers go through (obligation 1), so a new input cannot be read without being hashed.

**Notes for the design.** sawc has its own caches keyed on content, so a rebuild that changes nothing is cheap; Blade's stamp only decides whether to ask. The compiler's identity can be `sawc --version` plus the binary's digest (as the front cache's key does). `Directory.exists` answers true for a regular file (SL-1094), so a tree walk uses `Directory.list` as the directory test until std has `is_dir`.

**Priority.** A silent stale build is the kind of error the doctrine says never to hide; the nested-source case is the one to confirm first.

**Implementation detail (lead, Nov 14), for after SL-1098 lands (same files).** Two units. U1 is everything Blade can know by itself and is specified here. U2 needs a way for `sawc` to state its own identity, which is new command-line surface and waits on the project owner's answer (question at the end).

**The mechanism (obligation 4).** `Builder.build_hash` (`blade/src/builder.saw`) is what `is_up_to_date` compares with the stamp. It covers `Saw.toml`, `Saw.lock`, a constant marker, the `*.saw` files directly inside `src` and each dependency's `src`, and since SL-1098 the target, the linker script and the `--module-path` entries. Anything else the build reads can change and leave `Finished ... (up to date)` with the old output. The class is "an input of the build that is not an input of the hash", so the fix is a rule with a matrix, not five patches.

**The rule.** The hash covers every file the build reads and every fact that chooses a tool or an argument. `build_hash` is the one place that states the inputs: its docstring lists each class of input, and each line of it is held by a pin that fails when the line is removed.

**Step 0: the matrix, before any change.** For the hosted build (`build`) and the image build (`build_sos_image`), list every argument Blade hands to `sawc`, to the C compiler and to the linker, and every file Blade itself reads; for each, where its value comes from and which line of the hash covers it today. Write it as a table in the evidence directory. Then show each uncovered row by a run: build, change the one thing, build again, quote the `Finished` line. **The change (U1).**
- Sources: the package's `src` and each dependency's `src` are hashed as trees (`append_tree_saw`, which the module paths already use); `append_dir_saw` goes if nothing else calls it. The entry file `find_source_file()` answers is hashed by path and content when it is not under `src`.
- Each resolved dependency's `Saw.toml`, by path and content.
- An image build: each unit of `cfg.native`, by path and content. **Stated limit, in the help text or README where the up-to-date check is described:** a header a native unit includes is not tracked; `--force` rebuilds.
- Tool choices, as facts: the value of `SAWC` (or that it is unset), and for an image build the C compiler and the linker Blade will run (the paths `SOS_CLANG`/`SOS_LD` or the target's record resolve to, as the build itself resolves them: call the same functions, never a second copy of the lookup).
- The compiler's version: the first line `<compiler> --version` prints, read once per build with the same command `compiler_command()` makes. **If it cannot be read (the command fails or prints nothing), the build is never up to date** and goes on to compile, where the real failure is reported. If std's `Command` cannot capture a child's standard output in Blade today (read how `blade test` or the lane's Blade code captures one), STOP: that is SL-1093's gap and the lead decides.
- Order: a directory's entries must reach the hash in one order on every run. Show whether `Directory.list` is ordered (two listings of a directory with ten files, on this machine, and what std's docs say); if it is not promised, sort the paths before hashing.
- The marker `sawc-1;` becomes `blade-hash-2;` so every stamp written before this change stops matching once.
- `build_hash`'s docstring lists the input classes, one line each, and its ENTRY POINTS (`build`, `build_sos_image`).
- Every other caller of `is_up_to_date` or reader of the stamp (`run`, `test`, `clean`: grep) is listed with what it does; none may answer "up to date" by another route.

**Pins (obligation 1: the matrix is the test plan).** In `tools/blade_lane.py`, one line per row: after an up-to-date build, change the one input, and the next build prints `Compiling` (or, for a tool that then fails, does not print `(up to date)`); then an unchanged rebuild is `(up to date)`. Hosted rows on the lane's hosted fixtures (a new fixture under `blade/tests/fixtures/` with a nested source and a path dependency that has a nested source and a manifest, if no existing one fits); image rows on the lane's copy of the image package (`image_package()`), needing the riscv32 record as the lane's other image checks do. The environment rows set the variable for the child only (`blade_environment(extra)`).

The lane's existing checks change their output. A file outside `blade/src/builder.saw`, `blade/src/sosimg.saw` (only if a tool lookup must be shared), `blade/src/main.saw` (help text), `blade/tests/`, `tools/blade_lane.py`, `README.md` and `LANGUAGE_SPEC.md`'s image-manifest paragraph changes.

**Gate.** `tools/blade_lane.py`; `compiler/tests/run.py --only docs,comments`; `tools/battery.sh citations`.

**U2, the project owner's question.** A development compiler rebuilt from new sources, or an edited `std/`, keeps its version, so U1 still answers "up to date" there. `sawc` already digests its own binary and std's files for its front cache key; Blade cannot do the same without knowing where `sawc` and its std are. Options: (a) `sawc` prints that identity on request (a new flag, for example `sawc --build-id`: one line, the digest of the binary and of the std root it would compile against), and Blade puts it in the hash; (b) Blade leaves it at the version and documents `--force` for a development compiler; (c) Blade always asks `sawc` to build when the compiler is not a released version, relying on sawc's own caches to make that cheap. Lead recommends (a).
