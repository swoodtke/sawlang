Approved patch SL-551.p1 (revision 1)

Approving SL-551.p1 (A0b). This snapshot becomes the oracle once `sawc/` is gone, so I tested that it is Stage 0's real behaviour, that its second triple is genuine, and that its one known Stage 0 failure can't penalise a correct sawc2.

**The records are real.** Three programs rebuilt and run by Stage 0 now, compared with `index.tsv` (exit status, stdout length and sha256 prefix):

| program | snapshot | fresh run |
|---|---|---|
| `D21_substituted_never_is_a_value` | `0`, `26:7cd7b6160abe` | identical |
| `align_nonresident_local_in_suspending_function` | `0`, `29:b0cac6ebd7a9` | identical |
| `taskgroup_nested_groups` | `0`, `4:ca2ebdf97d74` | identical |

**The x86_64 "same-as" is genuine equality, not an ignored flag.** `snapshot.py` runs Stage 0 with `--target <triple>` for the non-host triple, and writes `same-as` only when the layouts match line for line. I confirmed Stage 0 honours `--target` for layouts: on `D21`, the field sizes for `arm64-apple-darwin` and `x86_64-unknown-linux-gnu` are identical (8, 24, 16, 8, … 88), while `i686-unknown-linux-gnu` and `riscv32-unknown-none-elf` halve them (4, 12, 8, 4, … 44). The two 64-bit files differ only in their `triple` string. A future 32-bit row (freestanding) would therefore record real differences, not a `same-as`.

**The known Stage 0 failure is recorded, not trusted.** `V96_driven_capture_duplicates_once` is the only `meets_expect` other than `yes`: "no: output line 9 is 'copy 1', expected 'nonescaping 1'". The census judges sawc2 by each program's own EXPECT directives (`expect.py`), not by Stage 0's output, so a sawc2 that gets `V96` right passes it. The same applies to any later run-lane comparison against the snapshot: `V96` needs its "oracle known wrong" annotation there.

**Also sound:**
- the reader `load()` needs nothing from `sawc/`, which is the point of the unit;
- stdout and stderr lines are JSON-quoted, so whitespace fixing can't change them;
- the census reports plan-complete against gated (412 / 78), giving SL-545's exit condition its denominator.

**Gate:** passed on the applied commit (tested_commit == applied_commit == 4b2b600d8). Its tested_tree 0e1c15dd is exactly the patch applied to 0c3609b2, which I computed, and identical outside `.sawtracker` to the tree I probed.
