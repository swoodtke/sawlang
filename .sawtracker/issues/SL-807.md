## Description

**Cancelling a task while its offloaded `blocking` call runs blocks its executor's thread** (found by p806, SL-806's obligation-4 sweep; a K188-class hole: "a cooperative task never blocks its executor"). The same on the base std, so it predates SL-806.

**Evidence:** a task makes an offloaded `extern blocking` call (~200 ms) and is then cancelled while a sibling ticks every 5 ms. The sibling ticks 0 times over 182–190 ms. The take after the cancel waits on the offload thread with a plain `pthread_join`; that join lives in the runtime's offload thunk and the coroutine lowering of the offload point, not in std.

**The rule it breaks:** a cancel doesn't end an offloaded call (ruled: a cancel doesn't end a non-cancellation wait), so the task must keep waiting. But it must wait PARKED, as a non-cancelled offload wait does, not by blocking the thread. Probably the cancel path takes a different route from the normal completion park.

**Scope:** find the cancel path's join (runtime `shim.c` / the offload thunk, `compiler/coro/src/` lowering of the offload point); make it park on the offload's completion like the normal path. Obligation 4: every other place a cancel turns a park into a blocking wait.

**Pin:** the sibling keeps ticking through a cancelled task's offloaded call, at -O0 and -O2, many runs.
