## Description

**`Path.canonical` on a relative path costs about 240–300 µs a call, against 13–19 µs on an absolute one, and the resolver pays it per import.** Found by SL-955 unit 4b's diagnosis (`.build/scratch/p955j/probe_canonical_run.py`, `probe_scan_paths.py`).

**Evidence** (main's compiler, sawc's own sources, sawc -O2 split thin, front cache off):
- **Resolve:** 270 ms when the `--module-path` mappings are spelled absolute, 1254 ms when they are spelled relative.
- **`sawc resolve --check`:** 0.42 s absolute, 1.06 s relative.
- **The calls themselves:** 10,000 `Path.canonical` calls take about 240–300 µs each on a relative path and 13–19 µs on an absolute one, whatever the working directory.

**Theory (UNVERIFIED):** `realpath(3)` on a relative path resolves the working directory through `getcwd`, every call.

**Fix direction:** make the std root, the entry and each mapping absolute once, at the driver, and join each import onto an absolute base, with a per-directory real-path cache in the loader. Every relative spelling then costs what an absolute one does. Check `Path.canonical` itself too: if std's implementation re-reads the working directory per call, fix it there, so every caller gains.

**SL-969, step 1 (diagnosis, read-only; evidence in `.build/scratch/p969/`).**

**The cause:**
- **macOS, `realpath(3)` on a relative path:** libc doesn't use `getcwd`'s fast `F_GETPATH` route. It walks up from `.`, opening each ancestor's `..`, reading the directory and `fstatat`ing entries until it finds the child: 7 `getdirentries`, 64 `fstatat` and 21 `fstat` calls from the checkout's root.
- **The cost follows the working directory's ancestors,** not the path resolved: `realpath(".")` takes 1.7 µs at `/`, 185 µs in the checkout, 249 µs in `compiler/resolve/src`, and 942 µs under `.build/scratch` (4,053 entries).
- **For comparison:** `getcwd` is 8 µs, an absolute `realpath` 14 µs, and `getcwd` plus a join plus an absolute `realpath` 23 µs.
- **Linux (glibc):** no penalty; relative and absolute both cost about 6 µs.

**Calls:**
- A sawc self-compile makes 4,278 `realpath` calls for 189 distinct paths. Each import costs three: `load_import` once, and `stored_case` resolving the base directory again on every import.
- **All relative spellings:** about 0.8 s of `realpath`. **build.py's spellings** (mappings absolute): about 70 ms.

**Options** (`sawc resolve --check` on sawc's sources, median of 5, relative / absolute spellings):

| option | relative | absolute |
|---|---:|---:|
| base | 1.17 s | 0.44 s |
| (a) std: join onto `getcwd` per call | 0.48 s | 0.47 s |
| (c) loader: real-path memo, reuse in `stored_case` | a further 40–70 ms | — |

**Decided (lead):**
- **(a) now.** It is std-only, every caller gains, and output is byte-identical. The working directory is read per call, never cached, because a raw `chdir` or another thread would make a cache wrong. If `getcwd` fails, it falls back to today's call.
- **(c) folds into SL-955 unit 4b's loader rewrite.**
- **(b), absolute spellings at the driver, is not done:** diagnostics print paths as the user spelled them.
