## Description

**`Path.canonical` on a relative path costs about 240–300 µs a call, against 13–19 µs on an absolute one, and the resolver pays it per import.** Found by SL-955 unit 4b's diagnosis (`.build/scratch/p955j/probe_canonical_run.py`, `probe_scan_paths.py`).

**Evidence** (main's compiler, sawc's own sources, sawc -O2 split thin, front cache off):
- **Resolve:** 270 ms when the `--module-path` mappings are spelled absolute, 1254 ms when they are spelled relative.
- **`sawc resolve --check`:** 0.42 s absolute, 1.06 s relative.
- **The calls themselves:** 10,000 `Path.canonical` calls take about 240–300 µs each on a relative path and 13–19 µs on an absolute one, whatever the working directory.

**Theory (UNVERIFIED):** `realpath(3)` on a relative path resolves the working directory through `getcwd`, every call.

**Fix direction:** make the std root, the entry and each mapping absolute once, at the driver, and join each import onto an absolute base, with a per-directory real-path cache in the loader. Every relative spelling then costs what an absolute one does. Check `Path.canonical` itself too: if std's implementation re-reads the working directory per call, fix it there, so every caller gains.

**SL-969, step 1 (diagnosis, read-only; evidence in `.build/scratch/p969/`).**

**The cause:**
- **macOS, `realpath(3)` on a relative path:** libc doesn't use `getcwd`'s fast `F_GETPATH` route. It walks up from `.`, opening each ancestor's `..`, reading the directory and `fstatat`ing entries until it finds the child: 7 `getdirentries`, 64 `fstatat` and 21 `fstat` calls from the checkout's root.
- **The cost follows the working directory's ancestors,** not the path resolved: `realpath(".")` takes 1.7 µs at `/`, 185 µs in the checkout, 249 µs in `compiler/resolve/src`, and 942 µs under `.build/scratch` (4,053 entries).
- **For comparison:** `getcwd` is 8 µs, an absolute `realpath` 14 µs, and `getcwd` plus a join plus an absolute `realpath` 23 µs.
- **Linux (glibc):** no penalty; relative and absolute both cost about 6 µs.

**Calls:**
- A sawc self-compile makes 4,278 `realpath` calls for 189 distinct paths. Each import costs three: `load_import` once, and `stored_case` resolving the base directory again on every import.
- **All relative spellings:** about 0.8 s of `realpath`. **build.py's spellings** (mappings absolute): about 70 ms.

**Options** (`sawc resolve --check` on sawc's sources, median of 5, relative / absolute spellings):

| option | relative | absolute |
|---|---:|---:|
| base | 1.17 s | 0.44 s |
| (a) std: join onto `getcwd` per call | 0.48 s | 0.47 s |
| (c) loader: real-path memo, reuse in `stored_case` | a further 40–70 ms | — |

**Decided (lead):**
- **(a) now.** It is std-only, every caller gains, and output is byte-identical. The working directory is read per call, never cached, because a raw `chdir` or another thread would make a cache wrong. If `getcwd` fails, it falls back to today's call.
- **(c) folds into SL-955 unit 4b's loader rewrite.**
- **(b), absolute spellings at the driver, is not done:** diagnostics print paths as the user spelled them.

**SL-969.p1: `Path.canonical` resolves a relative path as an absolute one**

**The change** (`std/path.saw`): `canonical` hands realpath the text from `Path.realpath_text`, a module-private helper.
- **An empty or absolute path** passes unchanged.
- **A relative path** is joined onto the working directory. The working directory is read through `__saw_rt_fs_getcwd` on every call, never cached. That is `Env.cwd`'s seam, declared again here because `std.env` imports `std.path`.
- **If the working directory can't be read, or isn't UTF-8,** the relative text goes to realpath as before, so results and errors stay realpath's. The NUL check, the empty-path check and the error subject, the caller's own text, are unchanged.

**Pin:** `compiler/tests/run/probes/path_canonical_relative_matches_absolute.saw`.
- **Inputs:** relative, `./`, `..`, leaving and re-entering a directory, `.`, case-varied, missing and empty paths; `file.txt` and `..` from a symlinked working directory; and a removed working directory, which takes the fallback.
- **Checks:** its output is byte-identical against main's std and the new one, and it holds no leaks. It passes in the Linux VM too.

**Measured:**

| | relative, before | relative, after | absolute, before | absolute, after |
|---|---:|---:|---:|---:|
| `canonical` per call, macOS | ~214 µs | ~16 µs | ~7.0 µs | ~7.1 µs |
| `canonical` per call, Linux VM | ~0.8 µs | ~1.9 µs | ~1.6 µs | ~1.6 µs |
| `sawc resolve --check` on sawc, macOS | 1.296 s | 0.495 s | 0.474 s | 0.447 s |
| `sawc resolve --check` on sawc, Linux VM | 0.469 s | 0.464 s | 0.467 s | 0.462 s |

The added ~1 µs per relative call on Linux, for the `getcwd` and the join, is a few milliseconds per compile. It is accepted (lead) to keep one path for every platform.

**Cone:** sawc's `std.path` grows from 10 to 13 entries (`__saw_rt_fs_getcwd`, `Path.is_absolute`, `Path.realpath_text`), reaching no `rt.`, `std.task*` or `std.net`.

**Gate:** `run.py --only seed,units,golden,subset,fixture_whitespace,std,programs`: ok.

**Still open:** the loader's half of the 4,278 calls for 189 paths (a per-directory memo, plus `stored_case` reusing resolved paths) folds into SL-955 unit 4b.

Approved patch SL-969.p1 (revision 1)

**Air: SL-969.p1 approved.** It's the diagnosis's option (a): `canonical` hands realpath(3) `realpath_text()`.
- **An empty or absolute path** passes through as before.
- **A relative one** is joined onto `getcwd`, read on every call and never kept.
- **Unreadable or non-UTF-8 working directory:** the path's own text is used, which is today's call.
- **Errors still name the user's spelling** (`SystemError.of("realpath", status, self.text)`).

**The join can't change what `..` means.** `Path.join` is purely textual: it adds a `/` unless one is there, and never collapses `..`. So realpath still resolves every component physically, as it did for the relative spelling.

**Old std against new, same program, same working directory** (`canon_edges.saw`, built with main's Stage 2 against each std, outputs compared after masking the pid): **identical** on every line.
- `link/../x` with `link` pointing **outside** the working directory resolves to `…/b/x`, through the link and not lexically back to `a`.
- The rest: `link`, `file.txt/`, `file.txt`, `.//file.txt`, `..//b///x` and `./`.
- `nope/../file.txt` gives `realpath "nope/../file.txt" failed (not found)` on both, naming the user's spelling.
- `""` gives `realpath "" failed (not found)` on both. The empty-path guard keeps today's error rather than resolving the joined `cwd/`.

**The patch's own probe** (`path_canonical_relative_matches_absolute`) matches its 14 stated lines at -O0 and -O2. It covers a symlinked working directory, `..` from one, a removed working directory, case variation and a missing file.

**Gates:**
- The stages were rebuilt with the new std, since sawc itself calls `canonical`.
- `run.py --only programs,resolver,std,subset,units,golden`: `exit=0`, with the `sawc.cone` record moved for `__saw_rt_fs_getcwd`, `is_absolute` and `realpath_text`.

I haven't run the Linux VM: the diagnosis found no penalty there, and the change is the same textual join on both systems.
