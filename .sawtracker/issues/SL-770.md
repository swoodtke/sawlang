## Description

**Port the rest of `std.net` to the new std** (the owner A12b's deferred rows need; SL-570 c3/c4). A12b (SL-570) ported the minimal cooperative surface:
- `TcpStream.pair`, `read`, `write`;
- `TcpListener.listen`/`accept`, plus `local_port` and `connect` to an IPv4 literal;
- `IoError`/`IoErrorKind`.

**This issue owns the rest of Stage 0's `sawc/std/net.saw` public surface, per the spec's std.net section:**
- `Timed<T>` and the `timeout: Duration` twins of `accept`, `read`, `read_into` and `connect`;
- `read_into`;
- `set_no_delay` and `set_keepalive`;
- `IoError.from_errno`, if the spec keeps it public;
- host-name `connect` once A14b (SL-574) gives std the offload worker for the resolver. Until then, A12b's interim panic names A14b.

The raw layer stays private (the spec; SL-569 c4).

**Acceptance:** the corpus rows A12b records against this issue pass (registered on its checklist at A12b's landing).

**From the Air's SL-570 review:** `IoErrorKind.of(tag:)` and `IoError.of(syscall:tag:)`/`of(syscall:kind:)` are `public` (as Stage 0's are), but they build values over the private seam's tag space. If no module outside `std.net` builds an `IoError`, make them `public(package)` (with an `equivalence_exceptions.tsv` row). Decide this with this issue's port.

**Air on c-latest's first reason: `std.signal` doesn't block `public(package)`.** The spec's scoped visibility ("From inside the package, `public(package) func internal_api` answers to `m.internal_api()`, to `import m.{internal_api}` and to the glob…") admits every module of the declaring package. `std.signal`'s four `IoError.of(syscall:…)` calls are in `std`, so they'd still compile with the factories narrowed. My SL-570 note's "outside `std.net`" should have read "outside std".

So the one real reason is the corpus row `io_error_kind_and_raw_code`, a user program that builds an `IoError` through both factories. That's a surface question: the spec's `IoError` surface is `kind()`, `code()` and the rendering, and names no factory. Either the spec gains the two factories as public API, so user code can build an `IoError` (a test double, say), or the row is re-spelled to read an `IoError` std produced and the factories narrow. Either is fine, but the spec and std should end up saying the same thing.
