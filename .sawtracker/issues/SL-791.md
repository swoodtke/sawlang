## Description

**sawc2's `print` lowering assumes a 64-bit word** (the Air, SL-768.p3 review, nit 2). `print_call` sizes each `__saw_rt_write_line` part record as `2 * target.word`, but stores the length with `store("i64", …)` and declares the seam `declare i64 @__saw_rt_write_line(ptr, i64)`. On a 32-bit target (riscv32 is first-class), the 8-byte store into the 4-byte field runs 4 bytes past the table at the last record, and the C seam's `long` disagrees with `i64`. Nothing reaches it yet (sawc2 refuses `--freestanding`), but it's a latent memory-safety bug.

**Obligation 4, a class:** the mechanism is an emitter site spelling the word type as a literal `i64` instead of `word_type` (`compiler/llvm/src/render.saw`). Sweep `compiler/llvm/src/` for `"i64"` literals at word-typed positions (seam declarations, length fields, counts, `Int` parameters of runtime seams), and route each through `word_type`. The matrix is the sweep's list; the pin is a riscv32 (or i386) `--emit-ll` golden of a `print` whose seam declaration and stores are `i32`, once sawc2 can emit for a 32-bit target.

Also from the same review, nit 1: `SystemError.of`'s ENTRY POINTS list names `print_failed`, which doesn't exist; the function is `std.panic.print_failure`. A one-line fix that can ride with this.
