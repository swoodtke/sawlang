## Description

**sawc2's `print` lowering assumes a 64-bit word** (the Air, SL-768.p3 review, nit 2). `print_call` sizes each `__saw_rt_write_line` part record as `2 * target.word`, but stores the length with `store("i64", …)` and declares the seam `declare i64 @__saw_rt_write_line(ptr, i64)`. On a 32-bit target (riscv32 is first-class), the 8-byte store into the 4-byte field runs 4 bytes past the table at the last record, and the C seam's `long` disagrees with `i64`. Nothing reaches it yet (sawc2 refuses `--freestanding`), but it's a latent memory-safety bug.

**Obligation 4, a class:** the mechanism is an emitter site spelling the word type as a literal `i64` instead of `word_type` (`compiler/llvm/src/render.saw`). Sweep `compiler/llvm/src/` for `"i64"` literals at word-typed positions (seam declarations, length fields, counts, `Int` parameters of runtime seams), and route each through `word_type`. The matrix is the sweep's list; the pin is a riscv32 (or i386) `--emit-ll` golden of a `print` whose seam declaration and stores are `i32`, once sawc2 can emit for a 32-bit target.

Also from the same review, nit 1: `SystemError.of`'s ENTRY POINTS list names `print_failed`, which doesn't exist; the function is `std.panic.print_failure`. A one-line fix that can ride with this.

**p791's census (step 1):** the class is wider than `print`. Beyond the ~23 start-of-string `"i64` literals there are ~250 in appended IR text. WORD rows go to `word_type`: the `write_line` declaration and part-record length store (the overrun), the bool length select, the String-length role call, the print-failure status/cap/return, the offload seams' word parameters and status compare, the coroutine frame STATE word (`load/switch/store i64` into a word-sized slot, also an overrun on 32-bit), the frame descriptor struct's `Int` fields, the `sizeof`/`alignof`/`len()` stores, the ASan `size_t`, and array-index load/mul/gep/compare. All of these are identities on 64-bit; the pin is byte-identical goldens, since sawc2 has no 32-bit target (`target_triples()` lists three LP64 triples; `Target.init` hardcodes `word: 8`).

**Checklist before a 32-bit target is added (FIXED today, by design):**
- the offload thunk's 64-bit slots (`offload_signature` refuses `word != 8`);
- the `_i64_` atomic intrinsics (an `Atomic<Int>` on 32 bits needs `_i32` siblings, a std decision);
- the internal `i64` domains (tags via `tag_of`, render helpers, fail-part table, repeat-literal counter, pointer arithmetic), which are self-consistent but should be re-audited;
- `target_triples()` and `Target.init`'s `word: 8`.
