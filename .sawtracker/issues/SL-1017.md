**A `??` default deeper than the payload is accepted and widens the result** (found by the SL-1011 spec review, F3, and confirmed by the reviewer).

LANGUAGE_SPEC "Optionals": "`??` peels exactly one layer, and its default owes what is left." On a `Vector<Int?>`, `v.get(9) ?? v.get(0)` "is a type error: the default is another `Int??` where an `Int?` is owed. The error names both types." The rule refuses only a default DEEPER than the payload.

In sawc:
- `let r = v.get(9) ?? v.get(0)` over a `Vector<Int?>` builds, binds `r` to `Int??`, and prints 1;
- only a constrained slot refuses: `let r: Int? = …` gives a `type.mismatch` (expected `Int?`, found `Int??`).

So the coalesce's result is widened to the default's depth instead of the default being checked against the payload.

The probe is `.build/scratch/p1000e/F10_coalesce_layers.saw`.

**Expected:** a refusal at the default, naming the payload type it owes and the default's type, at every coalesce position: a `let` with and without an annotation, an argument, a return, an interpolation and a chain.
