Found by p920's SL-920 survey (Q8a); reproduced by the lead on main.

**A generic bound is not checked for a type argument written inside a function body.** `struct Keyed<T: Hashable>`; `let a: Keyed<Plain> = Keyed<Plain>(item: Plain(x: 1))`, where `Plain` declares no `Hashable`, typechecks, builds and runs (prints `1`). The same `Keyed<Plain>` as a struct FIELD's type is correctly refused. That breaks design 109's rule that bounds are checked for EVERY type argument.

Repro: `.build/scratch/probe_body_bounds.saw` (`bin/sawc .build/scratch/probe_body_bounds.saw -o …` builds and runs).

**Mechanism (obligation 4; UNVERIFIED reading from p920):** bound obligations are collected and checked once, before bodies are typed, so every type written in a body (a `let` annotation, a constructor's type arguments, a cast target, a closure's parameter or result, a generic call's explicit arguments, a nested argument) bypasses the check. The fix routes every type-argument application through one bound-checking funnel, with a body-position matrix as its test plan. Also probe what happens when a method of `Keyed` actually uses `T`'s Hashable (mono / backend behaviour) to size the impact.
