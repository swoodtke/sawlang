Child of SL-884: the first piece scheduled. **A constant argument named by a `static`** (`Slab<T, MAX>`, `[T; SLOTS]`, `FixedBuf<FRAME_VALUES>`) is typecheck `slice.not-yet` in sawc, and in a constructor call's type arguments it is mis-refused as `type.not-a-type` (SL-915, folded in here).

**Why now:** it blocks the sawos restart (SL-913's sweep: ~383 sites in 70 sawos files, 198 of 201 entries) and SL-865 U9 (the freestanding suite's shared `fsrt` module sizes its arena with a static). Corpus: K21, K22, K25, `coro_frame_over_65535_nonconstant_values`, `resolve_seam_offloads`.

**Obligation 1 (a funnel or a matrix):** route every position a constant argument can take through ONE funnel that resolves a static's value, with its entry points named. Position matrix, with a fixture per row: a type annotation, a constructor's type arguments (SL-915), a repeat count `[v; N]`, a generic function's explicit argument, an inferred `[T; N]` parameter, a field's type, a return type, an alias, a nested argument (`Ring<Slab<T, MAX>>`), and a static defined in another module (qualified and imported). The spec (const generics, design 148; statics) decides which statics qualify (a constant initializer only?) and what happens to a non-constant one.

Closes SL-915.

**Step 1 (p920):** plan at `.build/scratch/p920/plan.md` (matrix, twins, probes beside it).
- **Where it's refused:** one site, `refuse_static_constant` (signatures.saw), reached from `build_const` and `const_named_as_type`. Type positions already decide type vs value by the parameter filled (`apply_nominal`).
- **Two bypasses decide by spelling:** call heads (`explicit_type_args`, 10 callers; that's SL-915, and also the missing kind check behind `Pool<Int, Int>(…)`) and const-parameter defaults (`build_generic`).
- **Two more gaps:** a qualified static can't be read in `build_const`, and a plain local is mislabelled "a static".
- **Literal twins:** in 25 matrix rows the static is the only blocker, except SL-457 (`/`) and SL-548.
- **Design:** an argument classifier (by binding) plus a static-constant funnel (`static_constant`, on-demand initializer typing with a cycle guard, folded by `fold.saw`). Typecheck only; no seed bump.

**Lead decisions:**
- **Q1:** the spec's wording: "array length / repeat count is not a compile-time constant: the mutable static `X` is not allowed here", and the like per reason. Reuse `static.not-constant` if that's the existing rule id; the six error rows should then pass on their text.
- **Q2 CORRECTED:** the spec refuses "a static of a NON-INTEGER type", so EVERY integer type qualifies (`UInt8` included). The value must fit the parameter it fills; a value that doesn't fit is refused, naming both.
- **Q3:** a static with no initializer is refused (spec).
- **Q4/Q7:** on-demand typing is approved, behind the opening spike. Static → static references keep the spec's DECLARATION-ORDER rule: a forward reference is refused where written (SL-762's text). If SL-762's `saw-pending` block flips as a side effect, re-tag it and say so; don't chase it otherwise.
- **Q5/Q9:** `/ % << & |` and the 2^31 limit stay SL-457's.
- **Q6:** no GRAMMAR edit.
- **Q8:** (a) is filed as **SL-921** (high: a bound is unchecked for a type argument written in a body; reproduced). (b) is filed as **SL-922** (a negative length is accepted as a type). (c) `extension Pool<Int, SLOTS>` treating `SLOTS` as a new parameter is OUT of scope; noted here as a spec question for later.
- **Also fix:** the plain-local mislabel (a `let` local in a length gets the static text; the spec says a local wins and is the runtime value, so it is refused as not constant, naming the local).
