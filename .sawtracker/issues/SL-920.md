**1. A negative static as a length reaches clang instead of being refused.** This is a new route this patch opens.
- `static N: Int = 2 - 3` then `let x: [Int; N] = [0; N]` (s5) typechecks, and the backend emits `%l1 = alloca [-8 x i8]`. The build ends in clang's "error: expected number in address space" (`sawc build: clang exited 1`).
- On main, s5 is a clean `slice.not-yet`.
- The literal twin `[Int; 2 - 3]` (s8) already fails the same way on main (SL-922's family), so the root is older. But this patch makes the static route reachable, and its funnel is where a static's value meets the length.
- Asked: an array length (and a repeat count) below 0 is refused where the value is known, naming the static and its value, with a fixture. Doing it in the shared length check would close SL-922's literal case too.

**2. The "fits its parameter" check covers only `Int` and `UInt`, not the narrow widths.** Your fixtures pin `HIGH: UInt64 = 1 << 63` for an `Int` parameter and `BELOW = 0 - 1` for a `UInt` one, and both are refused. But a `const N: UInt8` given 300 is accepted at every position: a type position `&Small<BIG>` (s11), a constructor head `Small<BIG>(…)`, and a generic function's explicit `width<BIG>()` (s12). And `N` then HOLDS 300: `struct Buf8<const N: UInt8> { items: [Int; N] }` gives `sizeof<Buf8<BIG>>() == 2400`, i.e. 300 elements, not 44 (s13). The literal `Buf8<300>` is accepted on main too (s14), so that half is older. Still, the patch lists "a value that doesn't fit its parameter" among its refusals, and as built that holds only for the two full-width cases.
- Asked: check the value against the parameter's declared type for every integer width, signed and unsigned (`Int8`…`UInt64`). Literal and static arguments should go through the one check, with a fixture per width class (narrow unsigned, narrow signed).
