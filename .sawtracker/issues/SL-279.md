## Description

Taking a move-only payload out of `Timed<T>` (SL-204) — e.g. `Timed<TcpStream>` from `accept(timeout:)` or `Timed<Data>` from `read(timeout:)` — requires `match move outcome { case Value(v) -> ..., case TimedOut -> ... }`. A plain `match outcome` is refused:

    error: `self.outcome.value(…)` lends a place of type `Timed<TcpStream>`, which is move-only — reading it out as a value would alias storage the container still owns

The hint (`.value(…).method()` borrows through the window) targets a caller that wanted a borrow; a caller that wants the value needs `match move`, which is not mentioned. The asymmetry with `Result` — `match attempt { case Ok(v) -> ... }` needs no `move` on the scrutinee — makes this surprising, and sawlang's own suite has no example that moves a value out of a `Timed`. Suggest: extend the diagnostic hint to mention `match move`, and add a suite example. Found adopting design 272 in sawtracker (ST-25); analysis in SAW_NOTES ST-SAW-15. Against sawlang main 5755f60b.
