## Description

**sawc2 judges a `try` over a binding by the whole Result's copy tier, not the extracted payload's** (found by t670try on SL-670).

LANGUAGE_SPEC, "A `try` forwards its subject's storage": `try r` over a binding or field extracts the Ok payload, "so the extraction is a transfer and takes the checkpoint — in all four spellings (`try`, `try!`, `try?`, and `try … catch { }`)". The payload is what is transferred.

sawc2's `try_expr` (and SL-670's `try_catch_expr`, which follows it) calls `consume(operand)`, which reads the whole `Result` place by value. A `Result<Counted, Bad>` whose error type is NoCopy is NoCopy, so `try! r` with a Copy `Counted` payload is refused:

```
struct Counted { n: Int }
enum Bad { case Nope }
extension Bad: NoCopy {}
func made(n: Int) -> Result<Counted, Bad> { Counted(n: n) }
func forced() -> Int {
    let r = made(1)
    let got = try! r      // sawc2: transfer.implicit-copy on `Result<Counted, Bad>`; Stage 0 runs it
    got.n
}
```

The same for `try r catch { … }` (`.build/scratch/p11.saw` in the t670try worktree). It keeps the corpus conformance rows `V91_try_catch_copies_per_path` and `V92_merged_results_copy_once` refused.

**The class:** every spelling over a place subject: `try`, `try!`, `try?`, and the inline catch. The fix is one rule for the four (the checkpoint on the extracted payload, and on the error the catch or the propagation takes), not a change to one spelling. Not changed in SL-670, which kept the inline catch consistent with the other three.

**The design pass (Nov 18; `.build/scratch/p677d/design.md` in the lead's checkout, probes beside it).** Judging only the payload would be unsound. `try` and `try … catch` take the error out of the subject on Err. Stage 0 judged the payload only, and it accepts `try r` with a NoCopy owning error and runs that error's `deinit` twice.

**Rulings:**
- **D1 (lead, from the spec and design 269): a `try` over a place judges each part its spelling takes, on the path that takes it, never the whole `Result`.**
  - `try!` takes `T` on Ok and nothing on Err (it panics, rendering `E` by reference).
  - `try?` takes `T` on Ok and nothing on Err (`E` stays in the place).
  - `try` and `try … catch` take `T` on Ok and `E` on Err.
  - No `move` is needed when every part taken copies silently. Each copy is made inside its path (V91's discipline).
  - A place subject is never moved on one path only. `try move r` moves before the tag switch.
- **D2 (owner): a NoCopy or ExplicitCopy error taken out of a place is refused.** The fix-it names `try move r`, `try r.copy()`, or `try!`/`try?`, which take no error.
- **D3 (lead): a reference subject (`&Result`, `&var Result`) goes through the same funnel,** read through the reference as `o!` is.
- **D4 (owner): the inline catch's `error` over a place is an owned copy,** matching the block form. A NoCopy error falls under D2.
- **D5 (lead): `try?` on Err no longer runs the error's copy hook.** This is an observable change. The spec section says so.
- **D6 (lead): deferred.** `try!` as a place (`(try! h.r).n` borrowing) is not part of this issue.
- **D7 (lead): a generic body requires `Copy` only of the parts it duplicates.** The last-use `Move` promotion still reaches a `try` subject.

**Mechanism (obligation 1):** one funnel, `try_subject`, with ENTRY POINTS `try_expr` and `try_catch_expr`. It replaces their `consume(operand)`. It reaches the generic last-use pass and the requirement summaries. MIR's four lowerings gain the place path: switch on the tag in place and copy the part on its own path. The `consume` calls are the only bypass. The Optional constructs already follow the payload, and `match` keeps its own ruled rule.
