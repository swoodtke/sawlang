## Description

**sawc2 judges a `try` over a binding by the whole Result's copy tier, not the extracted payload's** (found by t670try on SL-670).

LANGUAGE_SPEC, "A `try` forwards its subject's storage": `try r` over a binding or field extracts the Ok payload, "so the extraction is a transfer and takes the checkpoint — in all four spellings (`try`, `try!`, `try?`, and `try … catch { }`)". The payload is what is transferred.

sawc2's `try_expr` (and SL-670's `try_catch_expr`, which follows it) calls `consume(operand)`, which reads the whole `Result` place by value. A `Result<Counted, Bad>` whose error type is NoCopy is NoCopy, so `try! r` with a Copy `Counted` payload is refused:

```
struct Counted { n: Int }
enum Bad { case Nope }
extension Bad: NoCopy {}
func made(n: Int) -> Result<Counted, Bad> { Counted(n: n) }
func forced() -> Int {
    let r = made(1)
    let got = try! r      // sawc2: transfer.implicit-copy on `Result<Counted, Bad>`; Stage 0 runs it
    got.n
}
```

The same for `try r catch { … }` (`.build/scratch/p11.saw` in the t670try worktree). It keeps the corpus conformance rows `V91_try_catch_copies_per_path` and `V92_merged_results_copy_once` refused.

**The class:** every spelling over a place subject: `try`, `try!`, `try?`, and the inline catch. The fix is one rule for the four (the checkpoint on the extracted payload, and on the error the catch or the propagation takes), not a change to one spelling. Not changed in SL-670, which kept the inline catch consistent with the other three.
