## Description

**The backend refuses `ExplicitCopy.copy()` on a non-trivial type** (`String`, `Arc<Int>`, a user Copy-tier struct): `mono.not-yet: a call of ExplicitCopy.copy() on String, which no conformance of it meets, is not in the backend slice yet`. Found by SL-703 phase 2: `Vector.iter`/`enumerated` yield `buf[idx].copy()`, so a `for` over a `Vector<String>` is refused at std/vector.saw's `next()`. Integers and other scalars work (SL-711's scalar hooks).

**Rows:** the corpus rows SL-703 moved to `mono.not-yet` on `.copy()`, and gmgate's `generic_for_loop_owning_balance` (Blocked on this).

**Scope:** the synthesized `copy()` hook for the copy tiers on aggregates and std types. That means the retaining copy of a `String`/`Arc`, and a struct's member-wise copy. Use SL-711's scalar funnel (`build_member_glue`) and its kind × hook table. Obligation 4: the sibling hooks (`equals`/`hash`/`format`) on the same kinds; check which already lower.
