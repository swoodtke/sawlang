## Description

**Three Blade manifest defects, found by SL-1092's design pass while sweeping Blade's TOML readers and writers (Nov 14). Each was READ in the source, not run; step 0 of any fix is a run of each.**

1. **`blade add` puts the dependency in the wrong table.** `add_dep` (`blade/src/builder.saw`) appends the new line at the end of the file whenever a `[dependencies]` table exists, so in a manifest whose last table is `[sos.<triple>]` (or any table after `[dependencies]`) the dependency lands in that table. Expected: the line goes inside `[dependencies]`.
2. **README's manifest example shows a form Blade refuses.** `README.md`'s `Saw.toml` example has `tiny = "0.3.1"  # bare = EXACT pin`; Blade refuses a bare version string ("no registry yet"). Expected: the example shows only what builds, or says what is refused.
3. **A manifest with no `name` or no `version` is accepted.** `Manifest.load` defaults a missing `name` to `"unknown"` and a missing `version` to `"0.0.0"` with no error. Expected (never hide errors): an error naming the missing key and the file.

Related: SL-1092 (the typed TOML reader; its unit U2 rewrites `Manifest.load`, so item 3 is cheapest there or straight after it; its unit U3 rewrites `add_dep`'s quoting, so item 1 is cheapest there).
