## Description

FROM the SL-222.p1 review loop (rounds r3-r5, Sep 10): codex-reviewer caught three ownership failures in the coroutine transform (early-exit skipped clears, reinit-fallthrough claim erasure, hoist losing consumingness) with ONE method — instrument deinit with a print, run the driven form and its sync twin, and diff the drop traces. The sync twin IS the spec for the driven form: same program minus the suspension must produce the identical destruction sequence (names and order), and any divergence is a transform ownership bug — a lost drop is a leak, an extra drop is a double free, a reordered drop is a scope error.

WANTED: a standing harness lane generalizing that oracle, so this class is machine-caught instead of reviewer-caught. Shape sketch (implementer refines): extend tools/corodiff (it already builds driven/sync pairs) or add a sibling lane that, for each corpus program in the coro family, synthesizes a NoCopy-instrumented variant (deinit printing the value's name), compiles and runs BOTH forms, and diffs the traces exactly. Needs: deterministic trace ordering (single-task programs, or per-task trace tagging), a known-ledger file for cited divergences (same discipline as corodiff_known.txt — a fix removes the entry in the same commit), and battery membership.

EVIDENCE this pays: every one of r3/r4/r5's findings reproduces as a one-line trace diff (drop old missing, drop old doubled, compile refusal on the NoCopy variant); none was visible to the existing corodiff/suite oracles, and the SL-222 fixture corpus (coro_head_move_relinquishes_before_early_exit.saw's named-drop grid) is the seed corpus. Relationship to the SL-209 epic: this is the DYNAMIC check; SL-214's pre-codegen verifier is the STATIC one (its checked properties should include 'every frame claim relinquished exactly once on every path'). The two catch the same class from opposite sides; the lane is buildable now, before unit E lands.
