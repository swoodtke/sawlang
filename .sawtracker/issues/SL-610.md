**A4. The accessor split's liveness runs to a fixpoint, and the verifier recomputes it** (SL-606, bucket A). Findings: MIR 1, and M6 in part.

- **The bug:** `split.saw`'s liveness stops after 1000 rounds. The state record then misses a live local, and the epilogue reads uninitialized memory: the probe with N=1100 `if`s prints `6095644912`, with no INVARIANT line. The verifier calls the same `liveness`, so it can't see the miscompile. `window_entries` and `verify_payloads` share the cap.
- **Fix:**
  - a worklist to the fixpoint, with no round cap (principle 6). Order the blocks so a join is processed after its arms, which also fixes the round count;
  - an independent recomputation in the verifier: a second implementation or a cross-check, never the lowering's own function;
  - the same for `window_entries` and `verify_payloads`.
- **Pins:** the review's generator `probe_gen_ifs.py` as a test at N=1100, with the right output and no INVARIANT, plus an injection that drops a live local from the record and requires the verifier to report it.
- **Done when:** both pins pass, and `mir --check` on the N=1100 program takes well under the 32 s it takes today.

Two notes before submission (Air), so the pins test the new code's riskiest part.
1. **The pins are acyclic.** N=1100 straight-line `if`s form a DAG, and a backward liveness swept in postorder converges there in ONE pass, so neither pin exercises the worklist's re-enqueue. That's the step a cap-to-worklist rewrite usually gets wrong: forgetting to re-add a block's predecessors when its live-in grows. A 1-pass test can't tell a correct worklist from a single sweep. Please add a pin where liveness has to flow around a backedge through the split:
   - a local defined before a `while`, used after it, with an accessor window inside the loop body, so the local is live across the split on every iteration;
   - the same with the use inside the next iteration (`x` written at the bottom, read at the top);
   - one nested loop.

   Each should build, run right, and pass the verifier. The injection (dropping a live local from the record) is worth running on the loop case too, so the verifier's own liveness is shown to handle backedges as well.
2. **Run the long-accessor check at -O2 as well as -O0.** The defect is an uninitialised read, and -O0 and -O2 diverge on exactly that kind of UB. `run_lane.py check_long_accessor` builds only -O0 today, so a second build at -O2 printing the same `42` and `5` makes the pin cover the optimised IR too.

The rest reads well: no cap, an independent verifier recomputation, the drops verifier's `refined_entries` swept too, and the 3066-file byte-identity, which is good evidence the cap was never reached elsewhere.
