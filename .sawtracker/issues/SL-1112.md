## Description

**Safe code can import and call the executor's internal entry points: `__saw_exec_close_background` rebuilds the background task group under a running program.** Found by SL-1109's design pass (Nov 14); evidence `.build/scratch/p1109d/logs/user_calls_close_background.log` in the lead's checkout.

- `std/taskgroup.saw`'s `__saw_exec_close_background` is `public` because the thread exit's observer (`std/thread.saw`) calls it. So `import std.taskgroup.{__saw_exec_close_background}` compiles in a user program, and a call from `main` cancels, joins and rebuilds the background group in place; the later `join` of a `Task.spawn` handle then panics "this task belongs to another thread's group".
- Called inside a turn while an outer walk stands on the background group, the walk reads a group rebuilt under it (its storage persists, so a wrong read or a panic, not a freed read; UNVERIFIED, no probe). SL-1109's fix moves the walk on in that case.

**The class:** every `public` `__saw_exec_*` / `__saw_*` function in `std/` that exists for the compiler or for another std file. A user program should not be able to name them. Sweep: list them, and for each whether a safe program can import and call it and what that breaks. The remedy is a visibility one (design 82 makes each std file its own module: is there a std-internal tier, or must the compiler refuse a user import of a `__saw_` name?), which is a design question before it is a fix.

**Sweep done (lead, Nov 17; Sonnet, read-only; probes and scratch std copies in `.build/scratch/s1112/` of the lead's checkout; the agent's full report is this issue's evidence, summarised):**
- **Census:** 32 public `__saw*` declarations in std: 19 already `public(package)` (refused to users), 13 plain `public`, all importable by a user program (selective, qualified or glob import): 7 callable from a plain `main`, 6 from any user `unsafe` helper. An `unsafe` callee gates nothing (a plain `main` calls `__saw_exec_close_background`).
- **Correction to the description:** `std/thread.saw` does not call `__saw_exec_close_background`; its callers are `std/taskgroup.saw` (the end of a `Thread.spawn` body; `__saw_exec_drive_main`) and the compiler (`resolve_spawn`).
- **What a safe call breaks:** `close_background` from `main` makes a later `join` panic with a wrong message and force-runs background tasks; from a background task's own body, a "frame released before its root returned Ready" panic. **Worse:** `__saw_exec_io_register(fd, dir, token)`, `__saw_exec_offload_done(job)` and `__saw_exec_offload_pipe(job)` take `Int`s the runtime treats as addresses: a plain `main` reads arbitrary memory through them and the reactor writes into a cell an `Int` names (memory-unsafe from safe code, against the rule that a function with all-safe parameters is sound for every input).
- **The tier that fits:** `public(package)` (the spec: "genuinely-shared std internals are marked `public(package)` (std is the package)"; 19 siblings use it). With the 13 marked so in a scratch std, std's callers and every compiler path tried (suspending `main`, `Task.spawn`/join, `group.spawn`, an offload, a `Thread.spawn`, a detached task; four build settings) build and run, and a user is refused with the standard message. The compiler's synthesized calls resolve by module and name with no visibility check (`module_named` + `top_decl`).
- **Cost:** 17 tracked test files (the hand-driven executor programs under `compiler/tests/std/exec/`, two park tests, one run probe) import these names from a user package and stop compiling.
- **Adjacent:** the test intrinsics `__saw_suspend`, `__saw_drive`, `__saw_drive_steps` resolve bare in every module (`compiler/resolve/src/prelude.saw`), and their lowering calls `__saw_exec_drive`/`__saw_exec_drive_steps`.

**Lead's ruling (Nov 17; the spec decides the tier, the doctrine the signatures):**
1. **The 13 become `public(package)`** (the spec's tier for shared std internals; 19 siblings use it). Not private: `__saw_exec_drive_main` needs the package tier for `std/task.saw`, and one rule for all 13 reads simply.
2. **The three `Int`-address entries take unsafe-typed parameters:** `__saw_exec_io_register`'s token, `__saw_exec_offload_done`'s and `__saw_exec_offload_pipe`'s job become the pointer types they are (the precondition spelled as an unsafe-typed parameter, per the unsafe-surface rule), and the compiler's lowering that builds those calls (`compiler/mono/src/worklist.saw`, `compiler/coro/src/lower.saw`) passes them so. Hiding alone is not enough: they are unsound for any std caller too.
3. **The 17 test files** reach the internals as std's own code does: from inside the std package. The existing precedent is `std_lane.py`'s `make_park_std` (a tail appended to a std copy's module); the implementer measures whether the hand-driven executor programs can be compiled that way (each program's body as a module of a test std copy, or the lane's tail mechanism extended), picks the smallest mechanism that keeps every one of them running unchanged in what it checks, and STOPS if none does.
4. **Documented:** the compiler's synthesized calls resolve std names with no visibility check (one sentence in `compiler/README.md`, where the lowering's std names are described), since the fix relies on it.
5. **Filed apart:** the bare test intrinsics (`__saw_suspend`, `__saw_drive`, `__saw_drive_steps`) visible to every module.
