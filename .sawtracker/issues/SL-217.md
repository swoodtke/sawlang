## Description

DF-320. A driven/spawned ROOT must be a call the entry module can spell BARE, so a suspending free function reached through a module qualifier cannot be a root at all — only a nested callee.

```saw
// dep.saw
import std.task.{yield_now}
public func posdef(a: Int = 7) -> Int { yield_now()  a }

// main.saw
import dep
func main() {
    print(__saw_drive(dep.posdef()))          // error
    var group = TaskGroup()
    let h = group.spawn(dep.posdef())         // error
    print(h.join())
}
```

Both refuse, cleanly, and identically on base 7467b1f2 and on the SL-208 branch (so this is neither introduced nor fixed by SL-208):

```
error: `__saw_drive(...)` on a method requires a concrete struct receiver
error: `group.spawn(...)` expects a direct call to a free function, e.g. `group.spawn(worker(n))`
```

MECHANISM. `mod.f(...)` parses as a `MethodCall` — the parser cannot tell a module qualifier from a receiver — and the two root VALIDATORS read the AST shape: the drive site's takes the `MethodCall` arm and asks for a concrete struct receiver it will never find, and the spawn site's wants a `FunctionCall` and stops. SL-208 taught the coroutine transform's classifiers to read `MethodCall.module_free_call` (the typechecker's "this qualified call resolved to a free function" stamp) so a cross-module free callee EMBEDS; the two root validators are the same question at the other end of the pipeline and were not taught it, because SL-208's faces were all nested calls.

IMPACT: the shape a caller would predict — `group.spawn(dep.handle(conn))`, spawning a dependency's suspending entry point directly — is unwritable. The workaround is an entry-module one-line wrapper (`func handler(c: TcpStream) -> Int { dep.handle(move c) }`, which is exactly what `examples/coro_cross_module_io_wake.saw` does), so nothing is blocked; the cost is a wrapper per spawned dependency entry point and a diagnostic that talks about struct receivers for a call with no receiver in it.

Not silent: both are refusals, so no miscompile and no wedge. Filed rather than folded into the SL-208 review revision because it is a separate mechanism (root-site validators, not the transform's classifiers) with its own position matrix — the drive site, `group.spawn`, `Task.spawn`, and each of those against a cross-module suspending METHOD as well as a free function.

Second face of the same validator family, worth the same sweep: a LABELED argument at a drive root is refused too, in ONE module with nothing imported.

```saw
func labdef(a: Int, b: Int = 5) -> Int { yield_now()  a * 100 + b }
func main() { print(__saw_drive(labdef(a: 1))) }
// error: `__saw_drive(...)` expects a direct call to a suspending function or
//        method, e.g. `__saw_drive(work())` or `__saw_drive(obj.step())`
```

Also identical on base and branch. `group.spawn(labdef(a: 1))` is ACCEPTED and correct (pinned by `examples/coro_omitted_default_arguments.saw`), so the two root validators disagree about labels and only the test-only `__saw_drive` refuses them.

Found while auditing the argument-binding mechanism for the SL-208.p1 review (finding 1's class sweep). The embedded and root DEFAULT-materialization halves of that mechanism are fixed in SL-208.p1 revision 2; these two are the shape-validator siblings that revision does not touch.
