## Description

A parameter whose DEFAULT VALUE suspends can be used, but not OMITTED, at a call the coroutine transform builds a frame for. Omitting it is a clean refusal; supplying the argument explicitly works.

```saw
import std.task.{yield_now}

func seed() -> Int {
    yield_now()
    7
}
func target(x: Int = seed()) -> Int {
    yield_now()
    x
}
func main() {
    print(__saw_drive(target(9)))   // 9 — fine, the default is never evaluated
    print(__saw_drive(target()))    // refused
}
```

```
error: coroutine transform: the default value of parameter `x` of `target`
       suspends, and a suspending default cannot be materialized at a call that
       omits it — the expression would need a coroutine frame of its own at
       every such call. Pass the argument explicitly, or give the parameter a
       non-suspending default
```

Anchored at the omitting call's own line, identical at every position that builds a frame (an embedded nested call, a `__saw_drive` root, a `group.spawn` / `Task.spawn` root) and identical same-module and cross-module.

MECHANISM. An omitted default is MATERIALIZED at the call site — the callee's declared expression is copied in where the author would have written the argument, and the frame is built from a full-arity list (`_arity_args`). A suspending expression cannot be materialized that way: it is not a value the site can compute, it is a suspension, so it would need its own embedded sub-frame at every call that omits it, with the caller's state split around it. That is a feature (a fourth embedding position, with its own evaluation-order and cancellation questions), not a gap in the materialization.

WHAT BASE DID, measured on 7467b1f2 — nothing that worked is lost:

- same-module, omitted, `__saw_drive` root: `function __saw_drive_target takes 1 argument(s), but 0 were given` (an arity error against a synthesized name).
- same-module, omitted, embedded: `IndexError: list index out of range` — a compiler traceback.
- CROSS-module, omitted: compiled and printed 7, but `__saw_drive_steps` reports **0** Pending resumes. That is the SL-208 / DF-300e wedge itself: the qualified call lowered as a plain call, so BOTH the callee's own `yield_now()` and the default's ran outside any frame, where the cooperative cede is a no-op. The right answer, with the suspension silently dropped.

So the three spellings were an arity error, a crash, and a miscompile. The refusal replaces all three with one sentence at the user's line, and the same-module and cross-module answers agree for the first time.

UNBLOCKED SPELLINGS: pass the argument explicitly (works, at every position, same-module and cross-module — that is what `examples/coro_omitted_default_arguments.saw` pins), or make the default a non-suspending expression (a literal, a constant, or a `sync` call — also pinned there, including a call to a helper PRIVATE to the callee's own module, which travels under design 210's embed contract).

Found while fixing the SL-208.p1 review-r2 regression, where the previous approach — copying the default onto the synthesized wrapper's parameter — made a suspending default break even the EXPLICIT-argument callers (`undefined function seed`). That regression is fixed in revision 3; this issue is the remaining limitation, which is a smaller surface than any of the three behaviors it replaces.
