## Description

**A rebound binding's release order: sawc2 follows the spec, Stage 0 releases the shadowed binding at the rebind.** Found by the Air reviewing SL-566 (A9).

`let s = …; let s = derive(s)` (shadowing that derives from the shadowed binding is legal, design 100/107):
- **sawc2:** releases both at scope end, the second binding first. This holds in sync code too (the Air's `b8_exposed`).
- **Stage 0:** releases the first `s` at the rebind.
- **The spec:** "The compiler inserts `deinit()` calls at every scope exit", and "Each scope releases its own bindings in reverse declaration order". That reads as sawc2's order.

**Corpus programs affected** (the differential shows them as `wrong`): `conformance/K70_driven_scope_end_release_matrix` and `coro_frame_local_released_at_scope_end`.

**Owed:**
- **Confirm the reading,** with the Air; a user ruling is needed only if the spec's text is judged ambiguous.
- **Annotate both programs** `stage0-wrong` in `compiler/tests/corpusdiff/annotations.tsv`, citing this issue, so SL-666's baseline gate doesn't freeze them as `wrong`.
- **Add an SL:hazards entry** (silent, a drop-order difference): Stage 0-built code that relies on the earlier release must not rebind an owned value.

**SL-682.p1: the spec's rule as settled in c1/c2. Summary for review.**

- **The mechanism:** drops never moves a drop; MIR places them. `lower_let` registers each new binding with its scope, and nothing removed the REPLACED binding's entry, so it fell to scope end.
- **The fix, in one funnel:** `release_replaced(bound, depth)` in `compiler/mir/src/build.saw`. ENTRY POINTS: `lower_let` (plain and destructuring) and `lower_guard_let`. For each new binding, the newest owned same-name binding in the joined scope is released right after the initializer and before the statement's temporaries drop (Stage 0's `_drop_redefined_same_scope` order, confirmed by probe), and its scope entry goes, so there is no double drop.
  - Borrowck labels the drop as usual: static (the initializer borrowed or copied the old binding), elided (it moved it), flagged (moved on some paths).
  - A new binding holding a reference into the old one keeps the old one to scope end.
- **Beyond the brief's wording, for review:** a closure's statements get their own MIR scope, as a function body's do. Without that, the fix would release a closure PARAMETER at a `let` that shadows it, which Stage 0 doesn't do; with it, the two match. No MIR golden changed.
- **Conformance:** K70 (cell SC8, sync and driven twins) is the existing row. The drops ledger gains K70 and S09 lines; the drop and flag counts are unchanged, since the drop moves rather than being added.
- **Pins:**

**Differential** (`air-review/sl682p/rebind.saw`, a NoCopy `Res` with a printing `deinit`; Stage 0 is the oracle here):
- **sync:** a borrowed rebind (`let a = derive(&a)`) drops the old value right after the initializer. A moved rebind drops it once inside the callee. A rebind moved on one path (`if flag { consume(move c) } else { make(4) }`) drops it inside the callee on the true path and at the redefinition on the false path. Two rebinds in a row drop each predecessor in turn.
- **driven** (`__saw_drive`, with `yield_now` between): the same two shapes across suspensions.

The output is byte-identical to Stage 0 at -O0 and -O2, both branches included, with every value dropped exactly once.
