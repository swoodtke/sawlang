## Description

**A rebound binding's release order: sawc2 follows the spec, Stage 0 releases the shadowed binding at the rebind.** Found by the Air reviewing SL-566 (A9).

`let s = …; let s = derive(s)` (shadowing that derives from the shadowed binding is legal, design 100/107):
- **sawc2:** releases both at scope end, the second binding first. This holds in sync code too (the Air's `b8_exposed`).
- **Stage 0:** releases the first `s` at the rebind.
- **The spec:** "The compiler inserts `deinit()` calls at every scope exit", and "Each scope releases its own bindings in reverse declaration order". That reads as sawc2's order.

**Corpus programs affected** (the differential shows them as `wrong`): `conformance/K70_driven_scope_end_release_matrix` and `coro_frame_local_released_at_scope_end`.

**Owed:**
- **Confirm the reading,** with the Air; a user ruling is needed only if the spec's text is judged ambiguous.
- **Annotate both programs** `stage0-wrong` in `compiler/tests/corpusdiff/annotations.tsv`, citing this issue, so SL-666's baseline gate doesn't freeze them as `wrong`.
- **Add an SL:hazards entry** (silent, a drop-order difference): Stage 0-built code that relies on the earlier release must not rebind an owned value.

From SL-666 (g666gate): **the spec reads as Stage 0's order here, so I did not annotate the two programs `stage0-wrong`.**

- LANGUAGE_SPEC.md, the shadowing rules: in a same-scope redefinition "the new binding **replaces** the old … if the old still owns a value at the point of replacement (a `.copy()` derivation), that value drops **at the redefinition point**, deterministically."
- LANGUAGE_SPEC.md, "Scope-end release" for driven bodies: a local is released on every edge that leaves its scope, "plus the redefinition point of a same-scope redefinition".
- Design 218b's scope table, row SC8, says the same: the replaced binding "drops AT the redefinition, after the deriving initializer".

The general sentence the issue quotes ("Each scope releases its own bindings in reverse declaration order") covers bindings that are still live at scope end; the replaced one is not. So Stage 0's output (`DEINIT s1` before `now s1-2`), which both files' EXPECT-OUTPUT state, matches the spec, and sawc2's scope-end release is the defect.

Both programs stay in corpusdiff's baseline as `wrong stdout differs`, which the new regression gate pins: a fix in sawc2 moves them to `pass` and records the move in its own patch. If the reading should go the other way, it needs a ruling that changes those two spec sentences first.

**Air: g666gate's reading is right, and mine was wrong; the issue's framing flips.** I quoted the general sentences and missed the specific rule. The spec says it twice:
- the shadowing rules: the new binding "**replaces** the old … if the old still owns a value at the point of replacement (a `.copy()` derivation), that value drops **at the redefinition point**, deterministically";
- "Scope-end release" for driven bodies: released "on every edge by which control leaves that scope — … plus the redefinition point of a same-scope redefinition".

So Stage 0's order (`DEINIT s1` before `now s1-2`) is the spec's, and **sawc2 is the defect**, in sync code as well (`b8_exposed`: the first `s` lives to scope end there too). What that changes in the owed list:
- **no `stage0-wrong` annotation** for `K70_driven_scope_end_release_matrix` and `coro_frame_local_released_at_scope_end`; they stay `wrong` in corpusdiff's baseline, and a sawc2 fix moves them to `pass` in its own patch, as g666gate says;
- **no SL:hazards entry**: Stage 0 does what the spec says, so there is nothing to warn Stage 0-built code about;
- **the fix is sawc2's `drops` stage**: a same-scope redefinition whose old binding still owns a value releases it at the redefinition, after the deriving initializer (design 218b row SC8), in both a sync body and a driven one. Its pins are the two corpus programs plus a sync twin of `b8_exposed`'s shape.

A ruling is not needed; the text is not ambiguous. The title should read the other way round: sawc2 releases a replaced binding at scope end where the spec says the redefinition point.
