## Description

Found while fixing SL-331 (design 275 U2, SL-318). PRE-EXISTING and identical on
main `50a21f4f` and on the U2 branch, so it is not U2's regression — it is the
METHOD half of the same DF-218e sweep, missing the guard the FREE half has.

A generic METHOD TEMPLATE whose body names a consumed callee is stripped from its
extension even when a surviving function still CALLS it, and the author is told
their type has no such method:

```saw
import std.task.{yield_now}

func leaf(x: Int) -> Int { yield_now()  x + 1000 }

struct Holder { n: Int }
extension Holder {
    func wrap<U>(&self, x: Int) -> Int { leaf(x) + self.n }
}

func via_method(h: &Holder) -> Int { h.wrap<Int>(1) }   // the surviving caller
func driven(n: Int) -> Int { leaf(n) }
func main() { print("{}", __saw_drive(driven(1))) }
```

```
error: type `Holder` has no method `wrap`
  --> probe.saw:16:39
   hint: no methods defined
error: function `via_method` should return `Int` but body has no value
```

MECHANISM (obligation 4, probed rather than inferred). Design 218b's consumption
symmetry (DF-218e) consumes a generic TEMPLATE that names a callee the coroutine
transform removed, because the template's body would otherwise name a function
that has left the program. `coro_transform._consume_templates_naming_removed` —
the FREE-function half — guards that with a `live` test: a template something
still calls is kept, since consuming it would trade a re-check error for a
codegen one. `_consume_method_templates_naming` — the METHOD half, same sweep,
twenty lines above — has NO such guard: it strips every generic method template
naming a consumed callee, called or not. `_names_the_survivors_call` collects
FREE-function keys only, so the guard could not simply be reused; a method-call
census is what it would need.

The free half's own ORDERING defect (a chain `outer<T> -> inner<T> -> leaf`
deadlocked between the two questions and consumed neither) was SL-331 and is
fixed by design 275 U2 — the candidate closure now runs to a fixpoint before the
`live` test does. That fix makes this cell easier to reach, because a chain that
used to die at the free half now gets as far as the method half; it does not
cause it (the isolating probe above has no chain at all and fails identically on
main).

Not in design 275 U2's scope: U2 owns TOTALITY (no silent decline), and this is a
DIAGNOSTIC-correctness bug in a neighbouring sweep with its own guard question to
settle — whether the method half should keep a called template (matching the free
half) or refuse the call with a diagnostic naming the transform. Not silent:
every face is a clean compile error about a sound program.

Workaround: call the generic method only from bodies the transform also consumes,
or move the suspending callee behind a non-generic wrapper the template names
instead.
