## Description

**Calling a receiver-less `borrows` function panics the MIR stage.** Found by the reviewer (chat m1256, f340, Nov 17) reading sawos's SO-124 design, which leans on this form; reproduced by the lead on main (v0.24.3 and after):

```saw
struct Res {
    n: Int
}

unsafe static var HELD: Res = Res(n: 3)

public func held() unsafe borrows -> &Res {
    lend HELD
}

func read() -> Int {
    held().n
}

func main() {
    print("{}", read())
}
```

`sawc typecheck --check` accepts it; `sawc mir --check` and `sawc build` panic: `panic at vector.saw:89: Vector.[]: index out of range: -1 (len 0)`. Declaring the function without calling it passes; the same lend as a method with a `&self` receiver passes every stage. Evidence: `.build/scratch/fborrows/` in the lead's checkout.

**Mechanism (UNVERIFIED, from the index):** the lowering of a call to a `borrows` function (its prologue, window and epilogue) reads the callee's receiver parameter, index -1 when there is none.

**Before the fix (brief obligation 4), a sweep:** what the spec says a `borrows` free function may be (a lend of a static, of a parameter's place; `borrows -> T?`, the conditional lend); and every receiver-less position, each compiled through mir and run: a free function, a static method (`static func ... borrows`), an extension's static, a generic free function, a conditional lend (`borrows -> &T?`), a lend of a parameter's place (`func first(v: &Vector<Int>) borrows -> &Int`), called from a sync body, a suspending body and a closure; the window held across a call and across a suspension. A position the typechecker should refuse is refused cleanly; one it accepts lowers and runs. A compiler panic is never a verdict.

Priority high: an internal error on accepted code, and the sawos S3 port's SO-124 uses the form.

**The sweep is done (Nov 17; `.build/scratch/p1155/sweep.md` in the lead's checkout, ~33 probes), and it moves the premise:** lending a static is refused by borrowck even from a `&self` method (`lend.root`: "not rooted in the receiver"); the method form passes `mir --check` only. The spec allows only receiver-rooted lends ("An accessor lends storage its receiver already owns"). The crash: `prepare_lend` (`compiler/mir/src/lower.saw`) returns an empty plan for a receiver-less callee (its `not_yet` never prints) and the callers index into it (`-1`); a `static func` reaches `value_root` on a type node and the compiler segfaults; `window_open` and borrowck's `lendable_root` assume a receiver. **The owner's ruling (Nov 17, in the lead's session): design lending statics.** So two steps:
1. **This issue (SL-1155): the crash fix, on the spec as it stands.** MIR never aborts on an accepted program: `prepare_lend` handles a receiver-less callee and a type-named base, so each cell reaches borrowck and gets the same clean `lend.root` refusal a method lending a static gets today (a parameter's place or a local likewise); a diverging receiver-less `borrows` keeps building. Refuse fixtures per shape (free function, `static func`, generic, conditional, from a suspending body); a run probe for the diverging one. The stale `check_prologue` comment in `compiler/borrowck/src/conflicts.saw` (it names "a static" as a lend root) is corrected. No declaration is refused at typecheck: the follow-up may make these legal.
2. **SL-1156 (filed): lending a static** (an Opus design: which statics, likely an `unsafe static var` in an `unsafe` function; the exclusivity story across tasks and threads; widening `lend.root`; a receiver-less window through mir, borrowck, drops, mono, coro), after this fix lands.
