## Description

**Calling a receiver-less `borrows` function panics the MIR stage.** Found by the reviewer (chat m1256, f340, Nov 17) reading sawos's SO-124 design, which leans on this form; reproduced by the lead on main (v0.24.3 and after):

```saw
struct Res {
    n: Int
}

unsafe static var HELD: Res = Res(n: 3)

public func held() unsafe borrows -> &Res {
    lend HELD
}

func read() -> Int {
    held().n
}

func main() {
    print("{}", read())
}
```

`sawc typecheck --check` accepts it; `sawc mir --check` and `sawc build` panic: `panic at vector.saw:89: Vector.[]: index out of range: -1 (len 0)`. Declaring the function without calling it passes; the same lend as a method with a `&self` receiver passes every stage. Evidence: `.build/scratch/fborrows/` in the lead's checkout.

**Mechanism (UNVERIFIED, from the index):** the lowering of a call to a `borrows` function (its prologue, window and epilogue) reads the callee's receiver parameter, index -1 when there is none.

**Before the fix (brief obligation 4), a sweep:** what the spec says a `borrows` free function may be (a lend of a static, of a parameter's place; `borrows -> T?`, the conditional lend); and every receiver-less position, each compiled through mir and run: a free function, a static method (`static func ... borrows`), an extension's static, a generic free function, a conditional lend (`borrows -> &T?`), a lend of a parameter's place (`func first(v: &Vector<Int>) borrows -> &Int`), called from a sync body, a suspending body and a closure; the window held across a call and across a suspension. A position the typechecker should refuse is refused cleanly; one it accepts lowers and runs. A compiler panic is never a verdict.

Priority high: an internal error on accepted code, and the sawos S3 port's SO-124 uses the form.
