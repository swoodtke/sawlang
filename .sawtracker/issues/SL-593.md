**Found by SL-591's profile (Air): secondary to the `noalias` issue; share not isolated.**

**The mechanism.** sawc2 lowers every aggregate result through an explicit out-pointer, even for `internal` functions that no C caller sees: `define internal void @push(ptr %ret, ptr %p1, i64 %p2)`, where `%ret` isn't even marked `sret`. Stage 0 returns a first-class aggregate by value, which LLVM places in registers: `define internal %"Result$2$Void$AllocError" @push(...)`.

On every fallible call:
- the callee stores the result tag (`str wzr, [x19]`);
- the caller reloads it (`ldr w8, [sp]` before `cbnz`);
- the caller sets up the slot, and every argument shifts up a register (`self` in `x1`, not `x0`).

Stage 1 does `mov w0, wzr` and `cbnz w0`. In the self-compile, `Vector<Int>.push` alone has 821 call sites, and every `Result`/`Optional`-returning function pays the same.

**Not yet measured in isolation:** rewriting the call sites by hand wasn't worth it, and with the `noalias` fix alone Stage 2 already beats Stage 1. Measure it with this fix.

**Fix.** For `internal` (non-`@export`, non-`extern`) functions, return aggregates up to a size bound by value as LLVM first-class aggregates. Keep the C ABI for exported and extern functions. Optionally mark the remaining out-pointers `sret noalias`.

**Done when:**
- `push`'s fast path returns `Ok` in a register and its callers test a register;
- a codegen golden pins it;
- the run lane and the fixpoint lane agree;
- the self-compile build time before and after is reported (best of 5 on the Air).
