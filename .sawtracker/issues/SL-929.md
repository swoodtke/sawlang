Found by SL-865 U9 stage 1 (p865u9).

**On `aarch64-unknown-none-elf`, sawc's freestanding default `-neon,-fp-armv8` makes every Float operation a soft-float libcall** (`__subdf3`, `__adddf3`, `__muldf3`, `__divdf3`, comparisons, conversions). The freestanding suite's `support.c` provides none, so `float_text` fails to link at `-O0`. The suite runs at `-O1` (Stage 0's default level), where `float_text` links only because its float arithmetic constant-folds away. That's not a real proof.

**Needs (by analogy with the user's Q4 atomics ruling, SL-865 c39):** the spec states which soft-float routines sawc's output can reference on a target without an FPU (from the backend's real emission and clang's lowering), and that the kernel or support code provides them (compiler-rt's builtins do). Then the suite's `support.c` (or a vendored compiler-rt subset) supplies them, and `float_text` runs at `-O0` too, with an `nm` check that the referenced set matches the spec's list. Whether sawos's arm64 HAL already provides them is to be checked at the sawos batch update.

Approved patch SL-929.p1 (revision 1)

**Air: SL-929.p1 approved.** Reviewed r1 on 6eec826d0.

**The spec's list is exactly what `sawc` emits.** `sl929p/f1_float_all.saw` exercises every Float operation a program can write:
- `+ - * /` and negation;
- all six comparisons and `is_nan`;
- `as Float` from Int, UInt, Int8 and UInt64;
- `as` to Int, UInt, Int8 and UInt64;
- `print("{}", f)`.

I built it with `-c --freestanding --runtime` for riscv32 (`+m,+a,+c`) and aarch64 at -O0 and -O2, then ran `llvm-nm -u`. Apart from `__saw_rt_*` seams and `memcpy`, every undefined name is one of the 19 routines:
- **riscv32:** `__adddf3 __subdf3 __muldf3 __divdf3 __eqdf2 __nedf2 __ltdf2 __ledf2 __gtdf2 __gedf2 __unorddf2 __fixdfsi __fixunsdfsi __fixunsdfdi __floatsidf __floatunsidf __floatundidf`;
- **aarch64:** the same, with `__fixdfdi`/`__floatdidf` in place of the 32-bit `unsigned` pair it doesn't need.

Float printing, now available freestanding, adds nothing: no `__multi3` or other helper outside the list. The list can't be incomplete through a missing operator either:
- Float `%` is refused (`operator.undefined`: "a shift or remainder operator takes integers"), so no `fmod`;
- `Float32` is still planned, so no `__extendsfdf2`/`__truncdfsf2`.

**The vendored compiler-rt is unmodified.**
- **Byte comparison:** I fetched each of the 30 files (the 29 sources and headers, plus `LICENSE.TXT`) from `raw.githubusercontent.com/llvm/llvm-project/0d261d1c…` (`llvmorg-23.1.3`, the commit your README names). **All 30 are byte-identical.**
- **Headers:** every source carries the Apache-2.0-with-LLVM-exception header, which is sawlang's own license.

**The case:** `soft_float.saw`'s 40 checks and reports cover 0.1+0.2, ties-to-even at 2^53+1, the tie to 0 below the least subnormal, every NaN comparison and `is_nan`, and the `from` refusals on NaN and infinity.

**Gates:**
- `battery.sh citations docverify freestanding childgroups`: `exit=0`. Freestanding is **50 passed, 0 failed, 0 due**; `soft_float` passes on both arches, and `test_freestanding_runner.py` reports `ok: 9 stub cases, the soft-float list`. docverify 575 OK;
- `corpus.py` on the new `.saw` accepts it. `steps_for_paths` maps no `run.py` step to these paths.
