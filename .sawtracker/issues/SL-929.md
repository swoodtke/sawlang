Found by SL-865 U9 stage 1 (p865u9).

**On `aarch64-unknown-none-elf`, sawc's freestanding default `-neon,-fp-armv8` makes every Float operation a soft-float libcall** (`__subdf3`, `__adddf3`, `__muldf3`, `__divdf3`, comparisons, conversions). The freestanding suite's `support.c` provides none, so `float_text` fails to link at `-O0`. The suite runs at `-O1` (Stage 0's default level), where `float_text` links only because its float arithmetic constant-folds away. That's not a real proof.

**Needs (by analogy with the user's Q4 atomics ruling, SL-865 c39):** the spec states which soft-float routines sawc's output can reference on a target without an FPU (from the backend's real emission and clang's lowering), and that the kernel or support code provides them (compiler-rt's builtins do). Then the suite's `support.c` (or a vendored compiler-rt subset) supplies them, and `float_text` runs at `-O0` too, with an `nm` check that the referenced set matches the spec's list. Whether sawos's arm64 HAL already provides them is to be checked at the sawos batch update.
