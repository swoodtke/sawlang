## Description

**sawc2 has no visible-`Void` binding refusal** (designs 122 and 132; the spec's "Binding a `Void` expression").

`let x = nothing()` with a `Void`-returning `nothing` typechecks clean under sawc2 (exit 0). Stage 0 refuses it: "cannot bind `x` to an expression of type `Void` — it produces no value". The spec says the line is syntactic: a `Void` visible in the source is refused at the binding, while one arriving by instantiation (a local typed by a type parameter) is a zero-sized binding.

- **Corpus evidence:** `errors/let_void_expression_rejected` is `wrong` ("accepts a refusal test") in `corpus_diff.tsv`.
- **Found by SL-769** (p769b): its `let x = h.join()` pin on a `Task<Void>` can't be written.
- **UNVERIFIED:** the rule was never ported to sawc2's typechecker.

**Scope:** the refusal with Stage 0's message, at every binding position the spec names (a `let`, a `var`, a tuple binding, an `if let`), with the instantiation exception kept. Pins: the corpus row, plus `let x = h.join()` on a `Task<Void>` and on a `Thread<Void>`.

**Air: the class sweep for SL-772.** Probes are in `air-review/sl772/` on the Air; sawc2 is main's (with SL-573 r2), and Stage 0 is `sawc/sawc.py`.

| position | sawc2 | Stage 0 |
|---|---|---|
| `let n = nothing()` | accepted | refused: "cannot bind `n` to an expression of type `Void` — it produces no value" |
| `var n = nothing()` | accepted | refused, same text |
| `let n: Void = nothing()` | accepted | refused, same text |
| `let y = f()`, with `f` a `Void` closure | accepted | refused, same text |
| `let x = h.join()` on a `Void` group task (today's `VoidTask`) | accepted | refused, same text |
| `case Ok(v) ->` on a `Result<Void, E>` | accepted | **accepted** |
| the spec's `around<R>` at `R = Void` (`let result = body(n)` in the generic body) | accepted, runs | accepted, runs, identical output |

So the refusal is missing at every visible-`Void` `let`/`var` binding, the five Stage 0 refuses. The generic case is right on both, as the spec's instantiation-uniformity requires. One shape: the fix belongs in the one place a `let`/`var` binding's type is settled, judged against the binding's type *as written or inferred in non-generic code*. A type parameter instantiated at `Void` stays a zero-sized binding.

**A question for the fix's scope:** a match-arm payload binding of a `Void` (`case Ok(v)` on `Result<Void, E>`) names a value that doesn't exist, the spec's stated reason, and Stage 0 accepts it. The spec's text speaks of `let n = nothing()` "at the binding". Whether a pattern binding is a binding for this rule, with `case Ok(_)` as the spelling, is worth a sentence in the spec either way. If it's ruled refused, it's a position Stage 0 misses, so a `stage0-wrong` annotation.

SL-769's `let x = h.join()` pin (lead, c-latest) is the fifth row, so it lands with this fix.
