## Description

Found while building SL-306's matrix (pre-existing: identical on main `607ab218` and on the pre-SL-280 compiler `f982f54c`). A cell of SL-287's class, at a location whose entry-module twin refuses cleanly — which is what makes it worth its own row.

A `yield_now()` (or any real suspension) inside a CLOSURE LITERAL's body is REFUSED when the closure is written in the entry module and SILENTLY DROPPED when the same closure is written in an imported module's helper. Same program shape, one file boundary apart, two different outcomes — and the silent one is the documented-impossible third outcome designs 96/101/104 rule out.

## Repro

`modules/dep/lib.saw`:

```saw
import std.task.{yield_now}

public func each_yield_public(values: &Vector<Int>) -> Int {
    values.each({ n in
        yield_now()
    })
    values.len()
}
```

Entry module:

```saw
import std.task.*
import dep.{each_yield_public}

func through_dep(values: &Vector<Int>) -> Int {
    each_yield_public(&values)
}

func main() {
    let values: Vector<Int> = [1, 2]
    print(__saw_drive_steps(through_dep(&values)))
}
```

Observed: compiles, prints `0` — no frame was built for `each_yield_public`, so the closure's `yield_now()` lowered outside any frame, where it codegens to nothing. Two drive steps are owed (one per element).

The ENTRY-MODULE twin — the same `each_yield` body written in the entry file — is refused, correctly and with the right anchor:

```
error: coroutine transform: the suspending call `yield_now(...)` appears inside a
CLOSURE BODY in driven `each_yield`, and a closure body is not driven — its
suspension has no frame to park in.
```

## Mechanism (probed as far as the boundary)

The refusal in the entry-module twin comes from the driven caller's own body scan (`_FrameBuilder._reject_buried_suspend_call`), which only runs over bodies the transform FRAMED. The entry-module body is framed because the closure's real suspension reaches its enclosing function's effect node, so the closure walk follows the edge; for the IMPORTED body it does not — nothing marks `each_yield_public` suspending, no frame is built, and no scan ever reads it. So the boundary is in what the effect graph records for a closure literal written in a non-entry module (or in what the walk asks of it), not in the rejector.

Worth pairing with SL-306's fix when this is picked up: SL-306 made the call-site classifier and the closure walk ask `effects.suspends_ignoring_closure_calls`, and verified (cell by cell) that a really-suspending closure body is still refused in every ENTRY-module position. This cell is the one that was never refused, before or after.

## Why it is SL-287's class and not a duplicate

SL-287 is the general failure MODE (a suspending callee the walk declines degrades silently). This row is a concrete, currently-reachable instance with a two-line repro and an entry-module control beside it, which SL-287 explicitly lacks; the io face of it is the dangerous one (a `stream.read()` in that closure body lowers through codegen's out-of-frame park and stops the executor's thread rather than losing a cede).
