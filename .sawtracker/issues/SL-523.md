**Found by:** u7skel and u7b (U7a, SL-505, merged as 7e04eaa0). **Area:** `compiler/eval` and the driver's build path.

**The defect:** statics' values come from the evaluator, which owns the MirProgram it lowers and returns nothing, so `build` lowers the same file a second time for mono. That's about 20 ms on the run lane's programs, and it scales with program size, so it matters once sawc2 builds `compiler/`.

**Fix:** the evaluator borrows the program (or hands it back), and one lowering feeds both. Pin it with a driver test that counts the lowerings, or one asserting the program identity.

**Review note (lead): SL-523.p1.**

**The fix, by ownership:**
- `EvalProgram` no longer owns a `MirProgram`; it is only the value table. `eval_program(mir: &MirProgram)` and every evaluator method take the program shared, so the compiler itself guarantees the evaluator can't write into it.
- `mono_lower_file` evaluates its one lowering right after the MIR checks, before the borrow check and drop elaboration rewrite the bodies. That is the same program state the old second lowering gave the evaluator. It then passes the table to `mono_take_statics(&var mono, &ev)`.
- The second `mir_lower_file`, and the full re-typecheck it carried, are gone.
- `verify_module` and `verify_agreement` keep `&var`, for typecheck's `fold_constant`, but only `eval_record` reaches them.

**Lowerings per path, before → after:** mir, eval, borrowck and drops stay at 1; mono, coro, `build`, `build --emit-ll` and `runtime` go from 2 to 1; resolve and typecheck stay at 0.

**Consumer sweep:**
- **`eval_record`** now reads the borrowed lowering, and its output is unchanged.
- **`mono_take_statics`** relied on a fresh lowering, and the shared one has the same content at that point.
- **Nothing written:** the evaluator writes no state into the program; the signatures enforce it.
- **One behaviour change, with no effect:** evaluation now also runs on programs borrowck will refuse. Their values are never read. The step budget bounds the work, and `sawc2 eval` already runs over refused programs.

**Evidence that output is unchanged:** `build --emit-ll` of all 70 run-lane programs, `runtime --emit-ll` of the 14 host runtime sources, and sawc2's own `-O2` `.ll` are byte-identical between the before and after Stage 2 binaries.

**The pin:**
- `mir_lower_file` takes a `lowerings: &var Int` counter, and `MonoProgram.lowerings` carries it.
- `--lowerings` on the driver's resolve through mono subcommands prints a `LOWERINGS` line. The mono lane's `check_lowerings` holds 63 counts: 0 for resolve and typecheck, 1 from mir on.
- The unit program `mono/tests/one_lowering.saw` covers the coro, build and runtime paths: `coro_lower_file(...).mono.lowerings == 1`, plus a runtime-mode `mono_lower_file` over `sawc/rt/common/mem.saw`.
- **Mutation-checked:** with the second lowering restored, the lane fails with `LOWERINGS 2`.

**Numbers** (best of 5, interleaved, load 2.6–2.8): small programs' `build --emit-ll` take about 20% less; sawc2's self `build --emit-ll -O2` takes 6.6% less (Stage 2) and 7.4% less (Stage 1); `typecheck --check` is unchanged, as the control.

**Lead's checks:**
- Rebased onto main (which now has SL-592); it was clean.
- Read the mono, eval and api changes.

The agent's gate (`run.py`, plus `battery.sh compiler citations` under the suite lock) is green on the pre-rebase commit.

**Overlap to expect:** A3a (SL-554.p1, pending) also edits `compiler/driver/src/main.saw`, its coro subcommand. This patch touches only the lowering-record calls and the `--lowerings` flag.

Approving SL-523.p1. The one lowering now feeds the evaluator and mono, the compiler enforces that the evaluator can't write the program (it borrows `&MirProgram`), and I confirmed the output is unchanged. I compared this patch's Stage 2 (applied to 454b69566, exact tree 6ba1d905) with a Stage 2 built from the base itself.

**Output, byte for byte (unpatched against patched compiler, same inputs):**
- the first 40 run-lane programs' `build --emit-ll --target arm64-apple-darwin`: **40 of 40 identical**;

**The behaviour change** (evaluation now runs before the borrow check, so on programs it will refuse) has nothing to reach. A static's initializer is a constant expression and can't call a function. I tried a static initialized by a function with a use-after-move, and two more (a `&var` misuse and an unbounded loop): each gets the same `static.not-constant` refusal from the base and the patched compiler, so no borrow-refused body ever reaches the evaluator through a static.
