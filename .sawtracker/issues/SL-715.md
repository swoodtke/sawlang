**sawc2's typecheck grants two builtin conformances the spec does not: `Bool: Comparable` and a raw pointer's `Equatable`.** Stage 0 refuses both bounds; sawc2 accepts them (found by p711scalar, SL-711).

```
$ .build/sawc2 typecheck --check --std-root std grants.saw
  (only `unsafe.undeclared` on main; both bounds below accepted)
$ sawc/sawc.py grants.saw
error: type `Bool` does not satisfy the `Comparable` bound        (order(false, true))
error: type `UnsafePointer<Int>` does not satisfy the `Equatable` bound   (same(p, p))
```
Probe: `.build/scratch/p711/grants.saw` in the p711scalar worktree (a `<T: Comparable>` generic called at `Bool`, a `<T: Equatable>` one at `UnsafePointer<Int>`).

**Spec.** LANGUAGE_SPEC "Equality": integers, `Bool`, `Float` and `String` conform builtin (no raw pointer). "Ordering": integers, `Float` and `String` (no `Bool`). "Hashing": primitives and `String`.

**Mechanism.** `primitive_grants` (`compiler/typecheck/src/tier.saw`) is one blanket rule: every non-pointer primitive gets all five value traits (ExplicitCopy, Equatable, Comparable, Hashable, Printable), and the raw pointers get ExplicitCopy and Equatable. The spec's builtin lists are per trait, so the blanket rule over-grants exactly these two cells.

**Backend side (SL-711).** The scalar hook table in `compiler/mono/src/glue.saw` lowers each builtin hook the spec grants and refuses these two cells by name (`mono.not-yet`, citing this issue), so the over-grant can't reach a run. The fix here is typecheck's: make `primitive_grants` per trait as the spec lists them, then the two mono refusals become unreachable and their fixture (`compiler/tests/mono/refuse/mono.not-yet.bool-order.saw`) moves to a typecheck refusal.

**Pins:** the probe's two calls refused by typecheck with the bound error, at each position a bound is checked (a call, a generic type argument, a conformance's bounded extension).
