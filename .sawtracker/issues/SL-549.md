**Runtime capability groups: a provider declares which seam groups it implements, and a program that reaches an undeclared group is refused at compile time.** (The user, Oct 12, choosing this over a single symbol returning a table of functions.)

## Why not a function table
A single `__saw_rt_table()` returning a table of function pointers would let a platform choose its functionality, with null entries for what's missing. It costs three things:
1. **Missing functionality surfaces at RUN time.** Today a missing seam is a link error, and `sawc2 runtime`'s exactly-once check refuses a runtime that leaves one undefined. A null entry is only found when called, so std would either check every call (adding error paths to code that can't fail on real hosts) or panic. Both are later than today ("never hide errors").
2. **Dead stripping stops working.** A table refers to every function in it, so the linker keeps them all. With one symbol per seam, a program links only the seams it references, which matters on kernels and embedded targets (the sos image took -24% from `-Oz` alone).
3. **Every seam call goes through a pointer,** which is slower and can't be inlined, on frequent seams like `alloc`, atomics and locks.

## The mechanism
1. **Keep one symbol per seam.** Group the seams in `sawc/rt/ABI.md`, for example: `core` (alloc, write, panic), `env`, `fs`, `process`, `net` (with the reactor), `threads`, `time`. Each seam belongs to exactly one group, and `core` is required of every provider.
2. **A runtime provider declares its groups:** in the runtime manifest `sawc2 runtime` writes, and in `[package] runtime = true` packages. sawc2 checks that the provider defines every seam of each declared group exactly once, as it checks every seam today, and defines no seam of an undeclared group.
3. **A compile-time refusal.** When a program reaches, through std, a seam whose group the target's runtime doesn't declare, sawc2 refuses it at compile time, naming the std API, the group and the runtime. For example: "`Env.executable_path` needs the runtime's `env` group, which the kernel/none runtime does not provide". Decide where it is checked as a funnel: the call graph after mono, from each `__saw_rt_*` extern a reachable std function calls, with its entry points named.
4. **A provider may still use a table internally:** a sos-hosted runtime can implement its seams as thunks into a table the OS hands it, without changing the ABI.

## Consequences
- D44's NULL stub for `__saw_rt_executable_path` on sos-hosted and kernel/none becomes unnecessary: those runtimes leave out `env`, and the stub is removed. Until then the stub is honest, since `Env.executable_path` returns a `Result`.
- `__saw_rt_alloc_deny_after`'s "optional" convention becomes a group of its own (testing), or the doc says why it stays the exception.
- The freestanding suite gets a refusal pin: a freestanding program reaching an `fs` or `env` API is refused with the message above. The hosted run lane is unchanged.

**When:** not on the self-hosting critical path. Schedule it after sawc2 is self-hosting, or when sawos resumes, since kernel and sos runtimes are its main users. About 1–2 days. Touches `sawc/rt/ABI.md`, `runtime_abi.py`, the runtime manifest, and sawc2's driver plus a post-mono check. sawos's runtime declares its groups in the same batch update.
