**Choose `sawc build`'s codegen-unit and LTO defaults from measurement** (the owner, Nov 26: "let's definitely do the codegen-unit and LTO defaults").

**Today:**
- `--codegen-units=1` is the default: the whole program is one LLVM module, compiled by one clang process.
- A split build (`--codegen-units=module`, one unit per Saw module, compiled in parallel) links with ThinLTO unless it is `-O0`.
- Only a split build uses the per-unit object cache.
- `SAWC_CODEGEN_UNITS` and `SAWC_LTO` override the defaults (`driver_codegen_choice`).

**The lead's measurement** (Nov 26, the sawc driver itself, `-O2`, `--no-object-cache --no-front-cache`, Apple clang, the Studio):

| | Wall | clang | link |
|---|---|---|---|
| `--codegen-units=1` | 58.7 s | 52.3 s (one 101 MB module) | 0.08 s |
| `--codegen-units=module` | 24.5 s | 4.8 s (parallel) | 12.5 s (ThinLTO, presumably) |

Parsing the text IR is about 2 s of the `-O2` compile (`llvm-as` on Homebrew LLVM), so in-process LLVM is not the lever; the codegen split is. (The pinned, fetched LLVM toolchain is deferred by the owner.)

**What the defaults are chosen from (a measurement sweep first):**
- **Build time:** cold (no caches) and warm after a one-line edit in one module (object cache on), per mode: units 1; units module with ThinLTO; units module with no LTO; units module with full LTO. At `-O0`, `-O2` and `-Os`, on the sawc driver, Blade, a mid-size program and a small one.
- **The code produced:** runtime of the output (sawc compiling a fixed workload, Blade's tests), binary size, and stack frame sizes where they matter (freestanding).
- **Why the split link takes 12.5 s:** `-flto-jobs`, the linker, the ThinLTO cache.
- **A consumer survey for the flip (obligation 2):** who relies on today's single-module default:
  - build.py's stage builds and the fixpoint (stage 2 against 3);
  - the run lane;
  - the freestanding suite and `-c` objects (a split `-c` needs `llvm-objcopy`);
  - dsymutil and DWARF;
  - `--emit-ll`;
  - determinism;
  - Blade, sawos's image builds, and the Linux lane.

**Then:** the lead proposes the defaults (they may differ by optimization level, for example split with ThinLTO for `-O1` and above, and split without LTO at `-O0`), recorded here, and a unit flips them with the consumers updated.

**Lead's ruling on SL-1190's defaults (Nov 26),** from the s1190 sweep (`.build/s1190/results.jsonl`; the report's tables are summarized here).

**Measured on the sawc driver** (Apple clang, the Studio; cold is no caches, warm is a one-line edit with the caches on):

| `-O2` | cold | warm | built sawc's runtime | size |
|---|---|---|---|---|
| one unit (today) | 61.5 s | 54.9 s | 6.35 s | 5.63 MB |
| split + ThinLTO | 29.3 s | 8.2 s | 6.49 s | 6.41 MB |
| split, no LTO | 32.2 s | 5.5 s | 11.03 s | 5.47 MB |
| split + full LTO | 50.0 s | 43.6 s | 6.44 s | 5.50 MB |

At `-O0`, split with no LTO is 11.1 s cold (the same) and 5.1 s warm (against 8.7 s). Small programs are neutral (hello world, toml). Two cold builds are byte-identical (the fixpoint's shape), `dwarfdump --verify` is clean, and ASan works. Linux (clang-19 with lld-19) is correct, and its split is 23.8 s against 77.6 s.

**The defaults:**
1. **A hosted build (no `-c`, no `--freestanding`) defaults to `--codegen-units=module`.** The `--lto` defaults are unchanged: `thin` above `-O0`, `none` at `-O0`. No LTO at `-O1` and above is rejected as a default, since it builds a 1.7x slower program; it stays an opt-in.
2. **`-c` and `--freestanding` keep `--codegen-units=1`.** Three breaks today (below), and freestanding images grow 14-17% in text under split with ThinLTO, while embedded size is first-class. They are revisited once the breaks are fixed and `-Oz` images are measured.
3. **`OUT.units/` is not left beside the output.** A split build leaves one `.ll` per unit there (100 MB for the driver), on top of `OUT.ll`. They go where the objects already go (the build's cache or work directory), not next to the program. `OUT.ll` stays as it is.
4. **The consumers follow:**
   - build.py's stage builds take the new default (hosted `-O2`, so split with ThinLTO), and the fixpoint's byte comparison holds, since the link is deterministic.
   - The run lane's pins that assume a whole-module default move: `check_build_id`'s `SAWC_CODEGEN_UNITS=1` identity, and the time-stages pin.
   - Blade and sawos pass no codegen flag: Blade's hosted packages flip, and sawos's freestanding objects don't.
   - The spec's CLI paragraph, the README if it says, and `sawc --help` state the new default and its two exceptions.

**Filed separately:**
- (a) a split build changes `@section` order (`section_walk`, all four freestanding arches);
- (b) a split xtensa object at `-O0` (debug info, no LTO) is refused by Espressif's `ld.lld` (`unknown relocation (0)` in `.debug_line`);
- (c) `--lto=thin|full` at `-O0` silently optimizes;
- (d) a macOS split link through `ld.lld` takes 5.9 s against Apple ld's 11 s (backlog);
- (e) the freestanding default revisited after (a) and (b), with `-Oz` sizes measured.

**Lead's ruling on ruling 3 (Nov 26), after p1190's stop.** My premise was wrong: there is no work directory. `OUT.units/` holds a split build's unit `.ll` files, its `.o` objects (removed after the link) and, on Mach-O with `-g` and LTO, `lto/`. The run lane's `check_unit_stability` (the SL-955 pin), `check_codegen_units`'s `left()` and `tools/unit_stability.py` (and through it `bench_compile.py`) read the unit `.ll` files there on purpose.

**Ruling (the smallest form of p1190's option A):**
- **`OUT.units/` stays where it is while the build runs,** and is removed when the build ends, whether it succeeded or failed.
- **`SAWC_KEEP_UNITS` set (non-empty) keeps it,** exactly as today. It is tooling-facing, like `SAWC_CODEGEN_UNITS`/`SAWC_LTO`.
- **The readers set it:** `check_unit_stability`, `tools/unit_stability.py` and the `left()` check (which keeps its assertion that the directory holds only `.ll` files when kept).
- **A new pin:** without the variable, a split build leaves no `OUT.units/`.
- **Docs:** `compiler/README.md` describes the variable. The spec's CLI paragraph says a split build leaves nothing beside the output but `OUT.ll`. Whether the variable belongs in the spec is the agent's call, by where the other `SAWC_*` tooling variables are documented.
- **No new flag, and no temp-directory mechanism.**

**`SAWC_LTO` with a one-unit build** (`-c`, `--freestanding`): an explicit `--lto` with one unit stays refused, as it is today. `SAWC_LTO` from the environment is a lane-wide preference, so it must not break a `-c` or `--freestanding` build that defaults to one unit. Check what `driver_codegen_choice` does with `SAWC_LTO` and one unit today. If it refuses, make the environment value apply to split builds only, with a pin.

**Lead's note with p1 (Nov 26).** The rulings are `briefs/q1190_defaults_ruling.md`, `q1190_units_ruling.md` and `q1190_symbolize_ruling.md` (all on this issue). The evidence is in `.build/s1190/` (the sweep) and the agent's report.

**The line-table regression the flip would have brought, diagnosed and fixed in this patch:**
- **ThinLTO:** `closure#0 of std.taskgroup.observe_threads` sat at address 0 of LTO object 6, and dsymutil dropped its line rows, leaving a wrong `low_pc`. The same happens with `dsymutil --linker parallel`. A one-instruction pad function ahead of it gave 0 of 50 unsymbolized calls. Fix: `ll_split(pad:)` emits `__saw_pad.UNIT` first in each unit (in `@llvm.used`) for Mach-O, `-g` and an LTO link. The whole-module `.ll` and `--emit-ll` are untouched.
- **No LTO:** Apple ld folded the identical out-of-line `Vector.[]` prologues, which the whole-module build inlines, giving `<deduplicated_symbol>`. Fix: `-Wl,-no_deduplicate` for Mach-O `-g` split executables. `__text` grows 7% on the probe; `-g0` may fold.
- **Pins:** `check_symbolization` over `SYMBOLIZATION_BUILDS` (`-O0`/`-O2` default, `-O2 --lto=none`, `-O2 --lto=full`, `-O2 --codegen-units=1`), as strict as before. On non-Mach-O hosts it uses `llvm-symbolizer`; it was run on macOS only.

**Pins for the defaults:**
- a hosted build with no flag is split;
- no `OUT.units/` is left by default, and `SAWC_KEEP_UNITS` keeps it;
- `-c` and `--freestanding` are not split, and `SAWC_LTO=full` is harmless on them;
- the time-stages and front-cache pins are restated.

- `run.py --only seed,units,golden,subset,fixture_whitespace,std,comments,programs` ok, with 17 line-table symbolizations;

- citations, `docverify` (484 blocks), the lint and `blade_lane.py` ok.

## 1. A default hosted build removes a pre-existing `OUT.units` and everything in it
The split build uses `OUT.units` if it already exists (`if not Directory.exists(...) { Directory.create(...) }`, as main does). p1 now removes that directory recursively when the build ends (`driver_remove_tree`). Since p1 makes split the default for every hosted build, a plain `sawc build x.saw -o app` deletes a user's own `app.units/` and all of its contents.

**The probe:**
- `probe/app.units/keep.txt` and `probe/app.units/notes/deep.txt` exist.
- Then `sawc build --std-root std hello.saw -o probe/app` exits 0, and the program prints `hello`.
- Afterwards `probe/app.units` is gone, nested file included.
- Before p1, a default build was one unit and never touched `app.units`. A `--codegen-units=module` build wrote into it but removed nothing.

**Asked:**
- Remove only what this build made. Either make the units directory fresh (refuse or pick another name when `OUT.units` exists and this build did not make it), or remove only the files it wrote and then the directory if it is empty.
- Add a pin: a pre-existing `OUT.units` holding a file the build did not write still holds it afterwards, or the build refuses with a message naming it.

**What I checked otherwise:**
- `-c` writes no `OUT.units`.
- `SAWC_KEEP_UNITS=1` keeps it (`u0.ll` to `u3.ll` for hello).
- The symbolization fixes I read but did not probe further.
