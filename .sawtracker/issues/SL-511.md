**Found by:** tcb2c (batch B2c, SL-493), with `tests/corpus/const_bitwise_width_riscv32.saw`. **Area:** typecheck's constant fold and the evaluator: the width of platform `Int`/`UInt`.

**The defect:** sawc2 folds every constant at a 64-bit `Int`, whatever the target. The spec makes `Int` and `UInt` platform-width, and the program above compiles for riscv32 (`// COMPILE-FLAGS: --target riscv32…`). There, `static_assert`s about `Int`'s width and the bitwise results that depend on it come out as 64-bit values, so after SL-493 the file also gets `static_assert.failed`. The file is already refused on main for another reason, which hides this.

**Mechanism:** sawc2 has no target model yet. The fold, the evaluator and every `sizeof`/`alignof` answer assume the host's 64-bit layout. The target package U7a adds (`compiler/target`, SL-505) is where the width should come from.

**Fix:** the fold and the evaluator take `Int`/`UInt`'s width (and pointer size and alignment) from the target. Overflow and shift-range refusals then follow the target width. Pin with a riscv32 fixture whose `static_assert` holds only at 32 bits.

**Sweep owed:** every fold or evaluator site that hard-codes 64 for `Int`/`UInt`, plus `sizeof`/`alignof` of pointer-sized types.

Closed by SL-457's unit U2b (SL-457.p3, main 62e94b3af, Nov 14). The design pass for SL-457 found the claim half true: `fold.saw` and the evaluator already took `Int`'s width from the target; the one site that did not was the small folder that array lengths went through, where `[UInt8; 65536 * 65536]` at `riscv32-unknown-none-elf` was accepted. Lengths in types now go through the fold (repeat counts since U2a), so that is `constant.overflow` in every type position, pinned by `constant_lengths_riscv32.saw`, `constant.overflow.length-word-riscv32.saw`, `type.mismatch.length-literal-word-riscv32.saw` and the repeat-count twin. `tests/corpus/const_bitwise_width_riscv32.saw` passes, with its line that held a literal too wide for a 32-bit word now asserting `Int.max == 0x7FFFFFFF`. What still goes through the small folder (a generic-list argument; a length over a const parameter) is SL-457's U3 and U4.
