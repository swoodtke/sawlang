## Description

REPORTED by the user, Sep 23; REPRODUCED on main 73dd98b8 (`.build/scratch/void_closure.saw`): `func keep<R>(make: () -> R) -> R { let r = make()  let later = { n: Int in n * 2 }  print("{}", later(3))  return r }` with `keep({ print("hi") })` dies with `internal compiler error … (Identifier): Undefined variable: r` at the `return r`; without the closure literal it compiles and runs. MECHANISM (obligation 4, named): `sawc/codegen/closures.py` saves the enclosing function's per-function codegen state before generating a closure body (lines 215-221: `variables`, `variable_types`, `cleanup_stack`, `drop_flags`, `moved_variables`, `borrowed_variables`; 234: `current_return_type`) and restores it after (420-427) — a HAND-MAINTAINED list — but `void_variables` (design 132's zero-sized-binding set, added later) is RESET at line 251 with no save and no restore, so a Void-typed local of the enclosing function (here `r` at `R = Void`) is forgotten past the first nested closure. SIBLINGS the mechanism reaches: every other per-function attribute a named function's prologue (methods.py) initializes that the closure list omits — the fix enumerates them (grep the prologue's `self.<x> = ` set against 215-227/420-427) and turns the pair into ONE saved-state record (a small dataclass or a tuple built from one list) so a future field cannot be added to one side only; the second closure-generation site at closures.py:643-664 (saves only the builder) is checked for the same omission. FIX: save/restore `void_variables` (and any sibling found) through that one record; pin = this program + a Void local read after TWO nested closures + a Void local declared BETWEEN two closures + the same shape inside a method and inside a driven body; a lane/assert that the prologue's state set and the closure's saved set are the same set (the astgraft/producertaxonomy pattern). Small; codegen/closures.py is outside SL-350's surface.

## The one-record mechanism

`FunctionCodegenState` in `sawc/codegen/closures.py`. ONE list, `FIELDS`, of `(attribute, factory-for-a-fresh-body)`; `capture` / `blank` / `restore` all iterate it, so a kind of state cannot be wired into one half and missed in the other. A `None` factory means the entry point installs its own value (`builder`, `current_return_type`) rather than an empty container. Containers are COPIED at capture, so `restore` is a real rollback rather than a re-binding. A second table, `SHARED_WITH_NESTED_BODIES`, names the per-function attributes a nested body sees on purpose, each with the reason. The docstring carries the ENTRY POINTS list (`_generate_closure`, `_generate_env_dtor`).

Repro before: `internal compiler error … (Identifier): Undefined variable: r`. After: compiles, prints `hi` / `6`.

## Prologue vs closure, attribute by attribute

The prologue set is exactly what the four body generators in `codegen/methods.py` (`_generate_method`, `_generate_init_method`, `_generate_static_method`, `_generate_function`) assign at their top statement level.

| attribute | prologue initializes | closure saved (before) | verdict |
|---|---|---|---|
| `builder` | yes | yes (separate `saved_builder`) | saved — now in the record |
| `current_return_type` | yes | yes (separate `saved_return_type`) | saved — now in the record |
| `variables` | yes | yes | saved |
| `void_variables` | yes | **NO — blanked only** | **was missing; the bug** |
| `variable_types` | yes | yes | saved |
| `cleanup_stack` | yes | yes | saved |
| `drop_flags` | yes | yes | saved |
| `moved_variables` | yes | yes | saved |
| `borrowed_variables` | no (only `core.py.__init__`) | yes | saved — on the list |
| `_current_decl` | yes | no | DELIBERATELY SHARED — the ICE breadcrumb names the enclosing declaration; a closure body has none |
| `_consumes_release_self` | yes (instance method only) | no | DELIBERATELY SHARED — `_emit_consumes_aware_drop` keys it on the receiver's own POINTER (`var_ptr is not entry[0]`), which a nested body's fresh allocas cannot match |

`void_variables` is the only member that was on the blank side and off the restore side. No sibling.

## Second site

`_generate_env_dtor` (the escaping-closure env destructor) saved the builder ALONE. It blanks nothing, so it had no omission of the SL-356 kind — but it emits a second function body from inside the first, so it now goes through the same record (capture + restore, no blank: its `_emit_drop_at` reads the enclosing `variable_types` for a capture's type). Sweep for other sites: `self.variables = ` / `cleanup_stack = ` / `variable_types = ` appear ONLY in `codegen/methods.py` and `codegen/closures.py` across all of `sawc/`, so there is no third nested-body generator. `core.py` has two `self.builder = b` / restore pairs around `_raw_bytes_ptr` while emitting the `__saw_string_*` runtime helpers; they touch no per-function state and emit no user body — checked, not siblings.

## Lane + injection

`tools/test_closure_state.py`, battery stage `closurestate` (inserted after `astgraft` in `tools/battery.sh` STAGES). Six checks:

1. the two tables are well formed (no duplicate, at least one blank factory, every SHARED entry carries a real reason, no attribute in both);
2. `capture`/`blank`/`restore` each READ `FIELDS` and name no field of their own (a string constant equal to a field name is a failure);
3. both declared entry points call `FunctionCodegenState.capture` and `.restore`, and neither keeps a private `saved_x = self.x` beside the record;
4. every attribute the four prologues initialize is in `FIELDS` or in `SHARED_WITH_NESTED_BODIES`;
5. every `FIELDS` name is state codegen actually touches (catches a typo);
6. INJECTION, beside an uninjected control: a `continue` keyed on `SAW_CLOSURE_STATE_DROP` is spliced into `restore`'s loop, the file restored in a `finally` (the `icebreadcrumb`/`corodiscovery` pattern), and dropping either `void_variables` or `variables` must break a real compile of the pin.

Both negatives verified by hand: deleting `void_variables` from `FIELDS` fires check 4 at all four prologues AND check 6; adding a name the pin does not exercise (`borrowed_variables`) to the injection list fires "compiled CLEANLY", which proves the injection discriminates rather than passing by construction.
