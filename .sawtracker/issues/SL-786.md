## Description

**A bound refusal that fails a CONDITIONAL conformance doesn't say which condition failed** (found by A17b's census, SL-579 c2).

Stage 0 explains: `` `Arc` is `Send` only when its payload is `Sync`, and `Cell` is not `` (`sawc/namespace.py` `thread_safety_note`, naming the unmet condition of `extension Arc<T: Send + Sync>: UnsafeSend`). sawc2 gives only:
```
ERROR	type.bound	…	`std.arc.Arc<probe_arc.Cell>` does not satisfy `Send`, the bound on `T` of `needs_send`
```
The same applies to A17b's `coro.spawn-not-send` once it lands (K31's second directive).

**Fix:** when a type fails a trait only because a conditional conformance's condition is unmet, the diagnostic appends a note naming the conformance and the unmet condition (`` `Arc<T>` is `Send` when `T: Send + Sync`; `Cell` is not `Sync` ``). This touches typecheck conformance (`tier.saw`/`conform.saw`), through one funnel that every bound-style refusal uses (obligation 1: name its entry points: `type.bound`, `coro.spawn-not-send`, `spawn.send`, …).

**Pins:** K31's second `EXPECT-ERROR-CONTAINS` (in sawc2's canonical spelling, so the directive may need re-spelling with a `stage0-wrong`-style note, or a sawc2-side pin), plus a `type.bound` fixture with a conditional conformance.
