## Description

Found while writing design 270's conformance rows (SL-212, unit C of SL-209).
The epic's acceptance for unit C is "sync and suspending versions have
equivalent ownership behavior"; this is the one row of that where they diverge.

## Symptom

A NON-ESCAPING closure that implicitly captures a `Copy`-tier local pays TWO
duplications in a driven body and ONE in its sync twin. Measured with a printing
`copy()` hook, which is called at exactly the transfer sites no source construct
names (design 219):

```saw
struct Counted { n: Int }
extension Counted: Copy {
    func copy(&self) -> Counted { print("copy {}", self.n)  Counted(n: self.n) }
}

func run_int(body: () sync -> Int) -> Int { body() }

func cap_sync(seed: Counted) -> Int {
    let held = seed
    run_int({ held.n })
}

func cap_driven(seed: Counted) -> Int {
    let held = seed
    __saw_suspend()
    run_int({ held.n })
}

func main() {
    print("-- sync")
    print("= {}", cap_sync(Counted(n: 1)))
    print("-- driven")
    print("= {}", __saw_drive(cap_driven(Counted(n: 1))))
}
```

```
-- sync
copy 1
= 1
-- driven
copy 1
copy 1          <-- the extra one
= 1
```

Counts BALANCE — the closure environment releases its reference at frame death
— so this is not a leak and not a double free. It is an extra implicit
duplication a driven body performs and its sync twin does not, which at a
hand-written hook is an unbounded cost the author never wrote, and at an `Arc`
payload is a refcount that reads one higher inside a driven body than outside
one.

## Mechanism (obligation 4)

`_materialize_closure_captures` (`sawc/coro_transform.py:7790-7891`) rewrites
every implicit capture of a frame-resident local into an EXPLICIT
`[move __capN_<name>]` capture, and materializes `__capN_<name>` with an
`owning_read` frame read — a fresh reference, per its own comment: "The
materialized local must be an INDEPENDENT OWNER — the `move` capture below
transfers it into the env, and the env releases it once at frame death."

That is the ESCAPING closure's discipline, applied unconditionally. The sync
lowering of a NON-escaping closure does not mint a reference at all: the
environment is stack-resident and the capture reads the local where it sits.
So the transform pays the escaping cost for a closure that does not escape.

## Sibling sweep — every neighbouring shape probed, compile-and-run

| Shape | sync | driven | Verdict |
|---|---|---|---|
| non-escaping closure, `Copy`-tier capture | 1 copy | **2 copies** | **the bug** |
| non-escaping closure, capture read TWICE in the body | 1 copy | **2 copies** | same bug, count unchanged by uses |
| ESCAPING closure (`let f = { held.n }`), `Copy` tier | 2 copies | 2 copies | parity — the sync env already retains |
| plain capture of an `ExplicitCopy` local | refused | refused | parity, identical diagnostic and position |
| `[move o]` capture of a `NoCopy` local | 1 drop | 1 drop | parity |
| trivial tier | no hook | no hook | unobservable by construction |

So the mechanism reaches exactly one cell: the escaping/non-escaping
distinction is the thing the materialization does not make, and every other
axis (tier, use count, capture mode) is already right.

## Fix shape (not done here — it changes behaviour)

The materialization should ask whether the closure ESCAPES, as the sync
lowering does, and for a non-escaping one read the frame field without minting
a reference (the field stays the frame's; the closure runs and returns inside
the frame's own lifetime, so nothing can outlive it). The `owning_read` arm
stays for the escaping case. `_frame_read_policy` is already the funnel the
branch asks; the missing input is the escape answer, which `noescape.py` /
the non-escaping parameter slot already carries at the call site.

Design 218 stage 1's `Slot` migration is the other end of this: a `Slot`-encoded
field's `value()`/`take()` is an ordinary method call the post-transform
re-check judges by the ordinary rules, so the capture materialization over a
migrated field would ask the language rather than answer for itself.

## Why unit C files it rather than fixing it

Design 270 is behaviour-preserving by construction — it records and verifies
decisions, it does not change any. This one changes an observable (a user's
`copy()` hook stops running twice), so it is a filed bug with a cited
conformance pin, per the epic's conduct rule. The pin is
`examples/conformance/V96_driven_capture_duplicates_once.saw`, XFAIL, asserting
the intended parity so the XPASS flip validates the fix.
