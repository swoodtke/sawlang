**B1. The cap family: semantic walks are memoized identity worklists, never depth budgets** (SL-606 bucket B; the review's M1 and Typecheck-decl 1, plus Mono 4 and SL-619's `borrowck_trace` cap).

- **Mechanism:** walks that answer a question about a type stop at a numeric depth and return a guess. Three of them return the UNSOUND answer past the cap:
  - `tier.saw` `is_no_move` (16) → false;
  - `satisfies` (64) → true;
  - `erasure.saw` `names_self_type` (32) → false.

  Others refuse valid programs: `TC_EVAL_DEPTH` (16) makes a false "may suspend", and `TC_CONTAINMENT_DEPTH` (64) refuses a finite chain of 70 structs. The rest are conservative or latent: `type_holds`, `is_trivial`, `decl_owns`, `exports.saw`'s depth function. Mono's `type_depth` and `mono_copies_bitwise` are unmemoized and exponential; a branching polymorphic recursion hangs mono.
- **Fix:** one memoized walk per question, keyed by interned `TypeId`, with cycle detection by an in-progress mark. Principle 6: identity worklists, never a budget. Where a real limit is meant (mono's polymorphic-recursion backstop), it is a diagnostic, never a silent answer.
- **Pins:**
  - the review's generated deep-type probes, at each cap plus one, for each walk;
  - the mono hang probe;
  - a pin that a cyclic type terminates.
- **Done when:** no walk in `compiler/` returns an answer because of a depth count. A grep plus each site's reason goes in the report.

**The mechanism:** one memo table, `TcProgram.walks` (`typecheck/src/walks.saw`), keyed by TypeId or by declaration, with cycles ended by an in-progress mark.
- `is_no_move`, `is_cell_carrying` and `is_trivial` share one inline summary per type: a declaration's rule over its own parameters, composed with its arguments', so no walk substitutes into a member.
- `satisfies` runs each (type, trait) pair once per question. A cycle holds coinductively; a false answer is final, and a true one is kept only once no cycle it leaned on is open.
- Finite size is now a cycle in the declaration-level containment graph: inline masks solved to a fixpoint, then Tarjan components. It also refuses `Fixed<T> { u: Fixed<Int>? }`, which the old walk accepted.

**Reversible decision, for review:** a new rule, `type.instantiation-depth`.
- What it refuses: deriving `Send`/`Sync` from the members of a type nested past 64. Only a non-regular type reaches that, e.g. `struct L<T> { next: Vector<L<(T,)>> }`.
- Where: at the type's declaration, citing the spec's "Instantiation depth is bounded".
- Before: the cap guessed true. Stage 0 crashes on this probe with a RecursionError. The exact alternative is per-declaration Send/Sync rules.
- `TC_INSTANTIATION_DEPTH` duplicates mono's `MONO_DEPTH_LIMIT`, since typecheck cannot import mono.

**Filed:** SL-635 (llvm `comparable_bits`, cap 16); SL-639 (`reference_in` and `has_error`, exponential on shared parts). A comment on SL-619 covers `from_receiver` (32).

**Census, not filed, never shown wrong:** syntax-tree step caps, which return a guess past the count.
- `bodies.saw`: `sigil_accessor`, `lent_place`, `projection_top` and `use_writes` (10000); `hint_root` (64; hint text only).
- `mutability.saw`: `window_use_writes` (10000), `shared_borrow_above` (64). A 70-hop place chain under a bare `borrow` is still refused.
