## Description

Found by the independent review of SL-350.p1 (SL-350's review comment, P2-1; Sep 23). Before SL-350, `_struct_init_info` looked field types up with `namespace.get_struct_fields(<mangled name>)`, which returns nothing for a monomorphized generic struct, so a generic struct's `Arc`/`String` field got NO retain at construction: `struct Cell<T> { value: T, tag: Int }` built as `Cell<Arc<Int>>(value: a, tag: 1)` printed strong counts 1 / 2 / 4554 and died with `over-release of an Arc (refcount underflow)` (main 73dd98b8); the `String` twin aborted with `over-release of a String reference`. SL-350 resolves the type through `_struct_field_saw_type` (base name + `mono_struct_args`, substituted), which fixes it (1 / 3 / 1) — but nothing PINS it, so a refactor of the field-type source could silently restore the bug. OWED: an `examples/` pin with the Arc and String cells (strong counts + deinit traces), plus the sibling positions the mechanism reaches (a generic ENUM payload, a nested generic literal, a generic struct built in a driven body). Small; ride the next codegen patch (SL-356's, say).
