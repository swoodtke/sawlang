A suspending `equals` reached through a compiler-synthesized tuple `==` in a `sync` function crashes mono with an INVARIANT. It should be refused with a clean `effect.*` diagnostic.

**Repro:** `.build/scratch/p1156u7c/design_r2/probes/s03_suspend_tuple_eq.saw` (found by the SL-1156.p8 r2 design pass, Nov 25).

**Mechanism (UNVERIFIED, from that pass):** the front end's effect summary does not count a synthesized structural `==` (tuple, `Optional`, fixed-array or array literal) as calling the element's `equals`, so the suspension goes unseen until mono. SL-1156.p8 r2 adds those structural calls to the root summary (`eval_root_condition_in`). The suspension side needs the same walk.

**Sweep owed (obligation 4):** every compiler-synthesized call (`==`, `hash`, `compare`, and the copy, render and drop hooks) against the effect rules, so a suspending element hook is refused, never an INVARIANT.
