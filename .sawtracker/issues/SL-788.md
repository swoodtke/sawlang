## Description

**Soundness gap: a multi-threaded `TaskGroup` passed to a helper escapes the Send-on-frames gate** (documented in the spec, TaskGroup section: "`threads:` is tracked on the group's binding, not yet through an opaque helper it is passed to"; found again by A17b, SL-579).

A17b's `coro.spawn-not-send` traces a spawn's group operand back to `TaskGroup.init(threads:)` in the spawner's own MIR. Tracing stops at a parameter, a field or a call result, so:
```saw-fragment
func fan_out(group: &TaskGroup) { group.spawn(work_with_a_nonsend_local()) }
func main() { let g = try TaskGroup(threads: 4) catch { return }; fan_out(&g) }
```
spawns a frame holding a non-`Send` value onto a worker thread. That is a data race the gate exists to prevent. A safety guarantee with a hole needs a conformance row (obligation 3), so the fix brief writes it first.

**Options (needs the user's ruling):**
- **(a) Conservative:** a spawn into a group whose origin is not traced (a parameter, a field, a returned group) is ALWAYS gated. It's simple and sound, but it over-refuses a single-threaded group handed to a helper whose frames aren't `Send`. A sweep would count the affected corpus programs first.
- **(b) In the type:** `TaskGroup(threads:)` yields a distinct type (for example a type parameter or a separate `ThreadedTaskGroup`), so a helper's parameter type states it and the gate keys on the type. It's reader-visible and an API change across std, spec and corpus.
- **(c) Inferred:** a function that spawns into a group parameter carries "spawns into parameter N" in its summary, and the check fires at the caller where the group's `threads:` is known, with the chain (1a's style). It's precise and needs no API change, but it's more compiler work, and a group stored in a field still needs (a) or (b).

**Lead lean:** (a) now (sound, cheap; the sweep shows its cost), then (c) if the over-refusal bites. Related: A17b gates `threads: 1` as Stage 0 does, while the spec says `threads: 1` stays the single-threaded engine. That's to be settled in the same ruling (does A17a's pool run `threads: 1` on a separate worker thread?).

**(d) A runtime backstop for whatever the static trace can't see.**
- A17b already decides, per task root, whether its frame crosses (`coro_check_root`).

- The pool's enqueue (`enqueue_pooled`, reached only when the group has `threads:`) then panics naming the root when it's handed a frame that doesn't cross: "cannot spawn `work` into a multi-threaded group: local `v` … is not `Send`".

- **Sound for every position**, with no API change and no over-refusal, because a single-threaded group never takes the pool path.

**Air on the uniform check's sweep: expect a second large bucket that SL-795 doesn't touch: erased errors.** Probes in `air-review/sl788u/` (sawc2 on main 164b4d6fb).

- **`u1`: no existential is `Send` today.** `Box<any Error>`, `Box<any Printable>` and `Result<Int, Box<any Error>>` are each refused: "… does not satisfy `Send`, the bound on `T` of `needs_send`".
- **`u2`:** a `Task.spawn` body that holds `let r: Result<Int, Box<any Error>>` across a `yield_now()` runs today (`joined 4`).
- **`u3`:** the same body spawned into `TaskGroup(threads: 2)` is refused: "cannot spawn `work` into a multi-threaded `TaskGroup(threads: ...)`: local `r` of type `Result<Int, Box<any Error>>` is held across a susp…". That's `u2`'s verdict under the uniform check.

`Result<T, Box<any Error>>` is the spec's general fallible return, so any task that calls a fallible function, suspends, and then inspects the result lands in this bucket. Step 1's bucketing should keep **existentials** separate from **closures**, because SL-795 (closure traits from captures) can't help here: an `any Error` erases the type whose `Send` it would need.

The fix would be a language decision, so these are options to measure, not a recommendation:
1. `Error` refines `Send`. Swift's precedent: `Error: Sendable`. Then `any Error` is `Send`, and every error type's payload must be.
2. A spelled bound on the existential, `any Error + Send`, written where it's needed (Rust's `Box<dyn Error + Send + Sync>`).
3. Keep refusing, and teach `match` the result before the suspension.

The sweep can price these: count how many flips are an erased `Result` or `Box<any …>` held across a suspension, and how many of the error types reaching them have only `Send` payloads (option 1's cost).


<!-- sawtracker:comment {"author":"agent:claude-sawlang","body_bytes":2082,"created":"1792442209","id":"c7"} -->
**The user confirmed (Oct 19) the full rule:**
1. **The Send-on-frames check is uniform:** every cooperative spawn (`group.spawn(...)` into ANY group, and `Task.spawn(...)`) requires the spawned task's frame to be `Send`, meaning its parameters, its resident locals (including embedded sub-frames') and its result. `Thread.spawn`'s brace keeps its own capture audit.
2. **References use Rust's rule:** `&T` is `Send` iff `T: Sync`; `&var T` is `Send` iff `T: Send`. This replaces A17b's outright refusal of a root's reference parameter.
   - The user: "references need to be usable across suspends. passing a reference into a function which suspends where the reference is used throughout the function is a common pattern."
   - Soundness: the existing spawn-borrow rules keep the referent alive for the task (declared before the group; LIFO), the borrow checker keeps the spawner off an `&var`-borrowed value until the group finishes, and a frame's address is stable while a worker runs it.
   - Consequence: K19 (`bump(&var n)` into a `threads:` group) flips from refused to ACCEPTED, and its conformance row changes.
3. **Outside spawned tasks** (a suspending `main`, a drive), references and values across suspensions are unchecked, as today.

**Units:**
- **(i) A read-only sweep:** apply the uniform rule plus the reference rule in a scratch build, then list every corpus/run/std program whose verdict would move, bucketed by the offending value's type (closure types, references to non-`Sync`, raw pointers, other).
- **(ii) If closures dominate:** SL-795 first.
- **(iii) The unit itself:** A17b's `send.saw` drops `coro_threaded_init`'s trace and gates every spawn; the reference rule; the spec's Send-on-frames bullet and its "A `threads: N` group takes neither spelling" paragraph rewritten; conformance rows (K19's flip; a new "the frame of a spawned task is `Send` whatever its group"); corpus moves with `stage0-wrong` annotations where Stage 0 disagrees; the refusal message without "into a multi-threaded `TaskGroup`". The `threads: 1` over-refusal (c2/c3) is moot.
