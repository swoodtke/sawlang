## Description

# U3: the migrated corpus (`examples/` to `tests/corpus/`)

- **Epic:** SL-398, unit 3.
- **Design:** SL:architecture §5, "Two corpora, paired by file" (Ruled: "the corpus/ for the tests is fine"), and SL:testing §6.
- **Instrument and rewrite rules:** SL-398 c1 (point 3) and SL:borrowing §9 and §9.1.
- **Survey counts:** SL:borrow-survey, "The examples corpus".

## Why
The new compiler refuses the spellings the lockdown retired, so it cannot be measured on `examples/`. `examples/` stays exactly as it is, as the frozen compiler's corpus.

U3 produces a migrated copy, `tests/corpus/`, once, with a mechanical rewriter, and pairs the two by file path. That copy is:
- the new-syntax half of the parser's acceptance corpus (epic acceptance item 1), which the parser units U4 and on are written against;
- later, the new compiler's side of the behavioural differential (the frozen compiler on the original, the new compiler on the copy).

After U3 the copy is maintained as source, and new cases are written in the new language only.

**The central risk is silent meaning change.** A rewritten file that parses and would compile but means something else is worse than a flagged one. Every rule below either rewrites with type evidence, or flags the site for a person. A text-level rewrite of a type-dependent shape is never allowed.

## Deliverables
1. **`tests/corpus/`:** one file for every tracked file under `examples/` (2,834 today: 2,829 `.saw`, plus `.md` and `.toml`), at the same relative path. The directory layout is preserved, including multi-file modules and packages, `// COMPILE-FLAGS:` and `{TESTDIR}`. Every EXPECT directive is kept verbatim (see Expectations).
2. **The rewriter, `compiler/tools/migrate/`:**
   - It is Python, it runs sawc in-process, and it is deterministic and re-runnable.
   - It has its own tests: a golden before/after fixture per rewrite rule and per refusal, run from `compiler/tests/run.py`.
   - It is tracked, so the migration can be audited and re-run. It is a one-shot tool, not part of any compiler.
3. **The manifest, `tests/corpus/MIGRATION.tsv`:** one row per file, sorted by path.
   - Columns: path, status, and the rules applied with their counts (`borrow.statement-form:3`, say).
   - A sibling `MIGRATION_SITES.tsv` has one row per rewritten or flagged site: path, line and column, rule, before text, after text, and the type evidence (the element type and its copy tier, the accessor).
   - The statuses:
     - `copied`: no change needed;
     - `rewritten`;
     - `manual`: migrated by hand, each site recorded with a one-line rationale;
     - `flagged`: left for a person; the file is copied unchanged, and the reason is recorded;
     - `expectation-pending`: an error test, whose code has migrated;
     - `ir-test`: carries `EXPECT-IR-*` (32 files), and is to be rewritten as a MIR or IR dump test, or retired;
     - `grammar-flip`: an error test whose parse outcome the ruled grammar changes.

     A file can carry several statuses.
4. **A pairing check** in `compiler/tests/run.py`. Every `examples/` file has its `tests/corpus/` twin and a manifest row, and every `tests/corpus/` file has an `examples/` original. The only exception is a file the manifest marks `new`, which should not exist in U3. The manifest parses, and its counts add up.

## The instrument (SL-398 c1)
The type-dependent rewrites run on the frozen compiler's front end: sawc's place-lowering funnel (`place_uses._PlaceUses._window_call` and its callers) after a full typecheck, patched in-process. This is the SL:borrow-survey instrument, which records each site's shape, element type, copy tier, accessor, root and enclosing statement.
- The lead has asked the Air to share its drivers, `.build/scratch/survey/probe_driver*.py`, `probe_run_examples.py` and `probe_ast_only.py` (chat m242). Start from them if they arrive. Otherwise rebuild from SL:borrow-survey's Methodology section, which describes them fully.
- **Its blind spots become flag lists, never guesses:**
  - trait default bodies;
  - static initializers;
  - default parameter values;
  - synthesized and monomorphized declarations;
  - files that fail before lowering, which covers most of the 966 error tests.

  For a file or region the instrument cannot see, a parser-only scan (the survey's `probe_ast_only.py` approach) finds candidate retired shapes. Each candidate is flagged; none is rewritten.
- Run each file with its own `// COMPILE-FLAGS:` (minus `--emit-*`), as the survey did.

## The rewrite rules (SL:architecture §5 and SL:borrowing §9 and §9.1)
Each rule rewrites only with type evidence from the instrument. It records the site, and it has a golden fixture. The row letters are the survey's.

| Row | Today | Migrated |
|---|---|---|
| A0 | whole-element store `v[i] = x` | unchanged (setitem) |
| A1 | field write through a place, `v[i].f = x` / `op=` | `borrow var v[i].f = x` (statement form) |
| A2 | whole-element compound `v[i] op= x`, Copy element | unchanged (get then set) |
| A3 | mutating call through a place, `v[i].m()` | `borrow var v[i].m()` |
| A4 | `m[k]! = v` (panics on an absent key) | `borrow var e = m[k] { e = v }`. Never `m[k] = v`, which inserts (K7) |
| B | `&var x[i]` / `&x[i]` argument | `borrow var x[i]` / `borrow let x[i]` (K6) |
| C | `m[k]?.f = v` | `borrow var m.find(&k)?.f = v` |
| D1 | a Map `m[k]` read as an optional | `m.get(k)` |
| D3 | presence test `if let _ = m[k]` | `m.contains_key(k)` on a Map; otherwise a `find` block (K8) |
| G3 | read through a non-Copy element | `borrow let` statement form |
| G4 | `match` on a place of an abstract element | `borrow let` block |
| K14 | a write through `get`, e.g. `v.get(i)!.n += 10` | a `borrow` of the place. Never left as a write to a copy |
| E | the std closure-borrow APIs `with_ref`, `with_var_ref`, `Mutex.lock { }`, `Arc.with_unique { }` | a `borrow` block over the accessor (§9) |
| §9 | a plain `if let` / `case Some(x)` that binds an optional place | `borrow let` / `borrow var` where the body writes or holds the place; a plain copy where it only reads a Copy value (§2.4) |

Visitor APIs (`each`, `map`, `fold`, `sort_by`, …) stay.

**Always flagged, never rewritten:**
- `#lend_var` (K1: two accessors, written by hand);
- a `&self` method writing through a pointer (design 200's carve-out, retired; "language changed");
- a closure that names its call's own root (K10 and SL-345);
- lend forwarding (Fwd, K2);
- any site whose rule does not apply cleanly.

If a rule's target spelling is not settled in SL:borrowing or GRAMMAR.md, stop, flag it, and report. Do not invent one.

## Grammar-level migration (GRAMMAR.md, as landed)
1. **Removed productions in non-error files.** `compiler/tests/grammar/corpus_expected.tsv` lists every tracked file GRAMMAR.md refuses, 99 of them under `examples/`. For each non-error one, the removed production names its replacement:
   - `export` becomes `public import` (`examples/modules/test_package/init.saw`);
   - `#lend_var` is flagged (above).

   An error file that tests a removed form keeps it, and becomes `expectation-pending`.
2. **The meaning-preservation check.** Some rulings change how an accepted text parses:
   - SL-400 c6: prefix operators bind tighter than `as`; `try` covers its operand only; `??` groups right to left; `(T)` is grouping and `(T,)` a one-element tuple; the head reset inside brackets; the `>=` split at a generic close;
   - SL-406 c11 and c17 to c25: a spaced call is a call; a line break after `..`/`..=` ends a range; any brace block in a head resets it; a cast target's `<` is local.

   For each of these rulings, find every site in `examples/` where sawc's parse (its AST, in-process) and GRAMMAR.md's reading (the reference recognizer's dump) differ. At each such site, add the parentheses that make sawc's reading explicit under both grammars. Record the site under the ruling's name. Where a detector cannot be exact, flag every candidate site for a person instead.
3. **Every migrated file must pass the grammar corpus.** It is accepted with one tree, or, for an error test or a flagged file, refused and recorded in `corpus_expected.tsv` with its reason. `grammarcorpus` walks every tracked `.saw`, so `tests/corpus/` joins it automatically.

## Expectations (SL-398 c1, point 4)
- Code migrates at U3. EXPECT directives stay verbatim, including `EXPECT-ERROR-CONTAINS` text, so the future differential can read them.
- Error tests are `expectation-pending` in the manifest. Their error text becomes rule IDs as each rule is named, which is not U3's work.
- `EXPECT-IR-*` files are `ir-test`.
- **Grammar flips.** An error test whose parse outcome the ruled grammar changes is `grammar-flip`, and the manifest says why. Two known examples: R3's trailing-operator continuation, and R7′'s statement arms. A flip goes either way: a refused text that now parses, or an accepted one that is now refused.
- Leave the XFAIL markers (`// XFAIL: …`) as they are, and record them in the manifest. They pin the frozen compiler's findings.

## Hand migration
After the mechanical pass, migrate the flagged sites by hand only where the target is determined by SL:borrowing and GRAMMAR.md. Each gets a `manual` site row with its rationale, in a commit of its own.

A site that needs a judgment stays `flagged`, and the report lists it. The report groups the flags by reason, with counts, so the lead can bring the undetermined ones to the user.
