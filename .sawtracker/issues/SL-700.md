**Found by SL-681's sweep (n681nomove).** sawc2 consumes a `match` on an owned NoCopy enum whose payloads own nothing, where the spec says it does not. Stage 0 follows the spec.

**Spec**, *Match consumes an owned enum*: "A `match` on an owned NoCopy or ExplicitCopy enum **with owning payload** consumes the scrutinee … Enums whose payloads are trivial or Copy are not consumed."

**Repro** (`sawc2 build --std-root std`, main at 2ffb3ad2f):

```saw
enum State {
    case Idle,
    case Busy(n: Int)
}
extension State: NoCopy {}

func main() {
    let s = State.Busy(n: 3)
    match s {
        case Busy(n) -> print("busy {}", n),
        case Idle -> print("idle")
    }
    match s {
        case Busy(n) -> print("busy {}", n),
        case Idle -> print("idle")
    }
}
```

sawc2: `move.use-after … s is used after it may have been moved` at the second `match`. Stage 0 prints `busy 3` twice.

**Mechanism:** typecheck's `scrutinee_origin` (`compiler/typecheck/src/bodies.saw`) decides `Owned` (consume) from the scrutinee's own copy tier alone (`copies_silently(t)`), and never asks whether any payload owns something. A NoCopy enum with trivial payloads is not Copy, so it is consumed.

**Why it interacts with SL-681:** since SL-681 a consuming `match` on an owned `NoMove` binding is refused as a relocation. So a `NoMove` enum with trivial payloads (`extension State: NoMove {}` beside the `NoCopy`) is refused today, though under the spec the match consumes nothing and relocates nothing. The refusal hangs off the `Owned` decision, so fixing this rule lifts it with no change to SL-681's funnel.

**Needs a reading before a fix:** what "owning payload" means. It could mean a payload with drop glue, or a payload that is not trivial, and a struct payload of all-`Int` fields that declares `NoCopy` falls between those two readings. It could also mean an enum with a hand-written `deinit`, which owns something even when its payloads are trivial. The sweep should cover each of these against Stage 0.
