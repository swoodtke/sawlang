## Description

A dependency that declares the name `main` makes the ENTRY module's `main` take design 249's `$M$root` codegen tag, so the program emits no `main` symbol at all and the LINK fails. Pre-existing on main (`be4a764e`); found by the SL-280 keying audit, not caused by it.

## Repro

`.build/scratch/mainprobe/modules/mpdep/lib.saw`

    import std.task.{yield_now}

    func main(n: Int) -> Int {
        yield_now()
        n
    }

    public func reach(n: Int) -> Int { main(n) }

`.build/scratch/mainprobe/entry.saw`

    import std.task.{yield_now}
    import mpdep.{reach}

    func worker(n: Int) -> Int { yield_now()  n + 1 }

    func main() {
        var group = TaskGroup()
        let h = group.spawn(worker(1))
        print(h.join())
        print(reach(7))
    }

    ./.venv/bin/python sawc/sawc.py .build/scratch/mainprobe/entry.saw \
        --module-path mpdep=.build/scratch/mainprobe/modules/mpdep -o .build/scratch/mainprobe/entry

    Linking failed: Undefined symbols for architecture arm64:
      "_main", referenced from:
          <initial-undefines>

Reproduced identically with the SL-280 branch and with the three SL-280 files reverted to HEAD, so it is not the funnel.

## Mechanism

`_free_function_symbol_base` (`sawc/typechecker/registration.py:1328-1354`) gives a free function a `$M$<module>` tag whenever `free_function_owners` reports that more than one module of the compilation declares the name — deliberately including the ROOT module (`module_tag(())` is `root`), because std is checked once and cached so the entry is the side that has to move. The census counts `main` like any other name. Nothing exempts it, and `main` is the C entry emitted by name.

The dependency's `main` need not be public or reachable; declaring the name is enough.

## Relation to SL-274

SL-274's own sweep already names `main` as exempt from BOTH the mangling and the internalization, and records why the distinction matters: "The codegen sites key on `func.name`, so a symbol-only rename is safe there — a `mangled_symbol` stamp is not." This issue is the same hole reachable today, through design 249 rather than through SL-274's widening — so the exemption SL-274 will add is the fix for both, and this is the case that says it is not merely prospective.

Severity is low in practice (a dependency has little reason to declare `main`) but the failure mode is a bare linker error naming no user construct.
