Found by the spec review twice: SL-1003 F5 (an unclosed bracket) and SL-1036 F11 (`static var` / `unsafe static` alone). When the parser refuses a file, `sawc build` and `coro --check` print only `resolve.parse-refused … (syntax.decl.refused-static)`, the rule id with no message. `sawc parse --check` prints the parser's own message, which names the right spelling. A user running `sawc build` never sees the teaching text.

**Expected:** the parse refusal's own diagnostic (rule, location, message) is what build and every later-stage command report. The probes are in .build/scratch/p1000l/ (F11) and .build/scratch/p1000c/c_unclosed_paren.saw.
