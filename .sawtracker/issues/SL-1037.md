**Implementation detail (lead, Nov 12): `resolve.parse-refused` carries the parser's own message and hint, so every command past `parse` shows the teaching text.**

**Confirmed on main today.** For a file with an unclosed `[`:
- `sawc parse --check`: `ERROR syntax.lex.unclosed-bracket 2:13 this bracket is never closed`
- `sawc build`: `ERROR resolve.parse-refused q.saw:2:13 the parser refuses `q.saw` (syntax.lex.unclosed-bracket), so its declarations are not available`

The second line has the rule id and the position, and not the message or the hint.

**Decision: one refusal, same rule id and position, a fuller message.** Emitting the parser's diagnostics as separate `ERROR` lines would change the first ERROR line of every parse-refused program, which the refusal fixtures (`// refuses: resolve.parse-refused at L:C`) and the corpus oracle key on. Keeping the one `resolve.parse-refused` line and leading it with the parser's words changes only message text.

**Where.** `compiler/resolve/src/loader.saw`, the two `refuse_at(…, "resolve.parse-refused", …)` sites: the module load (the parser refused the file) and `note_dropped` (an interface parse dropped a declaration). `parser.diagnostics[0]` is a `sawparse` `Diagnostic` with `message` and `hint` (`compiler/parse/src/diag.saw`).

**The new message, module load:**

> MESSAGE (ID)[: HINT]; the parser refuses `PATH`, so its declarations are not available[, and N more refusals follow: `sawc parse --check PATH` lists them]

- MESSAGE, ID and HINT are the first diagnostic's `message`, `diagnostic_id` and `hint`; the `: HINT` part only when the hint is non-empty.
- The `N more` clause only when `parser.diagnostics.len() > 1`, N being the rest. Say `1 more refusal follows` for one.
- With no diagnostic (the interface-arena case) the message stays as it is today.

**`note_dropped`:** `MESSAGE (ID at L:C)[: HINT]; the parser refuses the declaration `FIRST LINE`, so it is not available`, and unchanged when `d.count == 0`.

Build each with `StringBuilder` as the neighbouring code does. A message or hint containing a brace is data appended with `append`, never an interpolated literal.

**Sweep (obligation 4).** Other places a later stage replaces an earlier stage's diagnostic with a bare id: grep `compiler/*/src/` for messages built from `diagnostic_id(` and for `-refused"` rule ids. List each with what it drops. Expected: only these two sites. Report any other; don't change it.

**Expected outcomes.**
- Every `// refuses: resolve.parse-refused at L:C` fixture still passes (rule and position are unchanged).
- Goldens that record the full message move, by text only: about two files each under `compiler/tests/resolve/` and `compiler/tests/typecheck/`, one each under `mir/`, `eval/`, `drops/` and `borrowck/`. Regenerate each with its lane's own `--write` (read the lane's docstring first; never pass `--help`), and check the diff holds only the message change.
- `corpus_diff.tsv`: about 100 `pass` rows carry the old message in their detail column. No BUCKET or KEY may move; the patch re-records with `corpusdiff.py run --baseline --jobs 12` so the details are current. A bucket or key move is a mismatch: STOP.
- `docs` step: a spec or README example whose expected error text quotes the old message moves; fix the quoted text only.

**Pins.** One new resolve fixture or golden for each shape: a refusal with a hint (pick a parser rule whose `Diagnostic.hint` is non-empty; `sawc parse --check` shows the hint after a second tab), one with two diagnostics (the unclosed bracket above gives two), and a dropped interface declaration.
