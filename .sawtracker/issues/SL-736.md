Two semantics questions in `Int`'s numeric methods (spec "extension Int"; Stage 0 and SL-719's port agree, so it's the spec text that's in question).

**1. `clamp(low:high:)` with `low > high` is silent.** Stage 0's comment says "Assumes low <= high", and with `low > high` it returns `low` or `high` depending on the receiver. The doctrine says never hide errors and never clamp to a plausible-looking result (spec, near "never a clamp to a plausible-looking result"). A violated precondition here should panic (`panic at FILE:LINE:`), the way `substring`'s reversed range does. Needs a ruling, since it changes the spec's behaviour.

**2. `pow(exp:)` is repeated multiplication, linear in `exp`.** For `|self| >= 2` an overflow panic ends it within 64 steps, but `0`, `1` and `-1` loop `exp` times: `1.pow(Int.max)` does not finish. The spec names the algorithm ("repeated checked multiply"). Exponentiation by squaring keeps every answer and the overflow rule, as long as the last squaring is skipped so an unused square cannot overflow. Alternatively, answer `0`, `1` and `-1` directly. Perf doctrine is measure-first, but this is termination, not speed.

Lean: (1) panic, with a pin and a spec line; (2) by-squaring with the skipped final square, plus pins for `1.pow(Int.max)`, `(-1).pow(Int.max)` and the overflow edges `2.pow(62)`/`2.pow(63)`, `(-2).pow(63)`. Both are std-only (`std/numeric.saw`) plus the spec.

Approved patch SL-736.p1 (revision 1)

**Air: SL-736.p1 r1 approved; arming it.** Both rulings are implemented as ruled.

**`pow`, read:** `result` takes `base` only for a set bit, and `base` squares only while a higher bit remains (`e > 0` after the shift). So every partial product and every square computed divides the final result in absolute value, and nothing overflows unless the result itself is outside `Int`. `(-2).pow(63)` reaches `Int.min` on its last multiply. `Int.min.pow(2)` overflows at the square, as the result would.

**`pow`, measured:** `air-review/sl736/pow_grid.saw` runs every base in -12..12 against a naive multiply, for each exponent up to the last whose result fits (`Int.min` included). Run against a std copy carrying r1's `numeric.saw` (confirmed applied), it reports 831 compared and 0 mismatches at -O0 and -O2.

**Pins, rerun with that std:** `int_pow_edges` prints 2^62, `Int.min`, 1, -27, 7. `int_pow_63_overflows` panics with the overflow check. `int_pow_unit_bases` finishes (1, -1, 1, 0). `int_clamp_reversed_panics` prints 7, then 5 (`low == high` accepted), then panics `clamp: low 9 is greater than high 2`.

**`clamp` and the spec:** the panic comes before any comparison, and its doc says so. The spec bullet now describes `pow` by its results rather than its algorithm, and gives `clamp` its panic, as both rulings asked.
