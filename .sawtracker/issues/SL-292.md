## Description

SL-260's differential found an annotated Result-valued if rejected before its arms receive the destination's wrapping context. Observed at 6f307c11, source unchanged at 6a6d57bd.

Minimal shape (from prototypes/minivm/examples/results/construction_wrapping.saw:21):

```saw
func main() {
    let chosen: Result<Int, String> = if true { 9 } else { "no" }
}
```

Actual: clean errors `if and else branches have incompatible types: Int vs String` followed by `cannot assign Int to variable of type Result<Int, String>`.

Expected: distribute the declared Result destination into each arm, producing Ok(9) or Err("no"). LANGUAGE_SPEC.md Auto-Wrap applies at declared Result slots; value arms are transfers. The prototype M11 already does this correctly and should retain it.

Mechanism: expressions.py::_check_if_expr reconciles incompatible arms using _enclosing_return_type(), rather than the annotated expression destination. The enclosing main returns Void, so the Result annotation is lost at this reconciliation; _check_let_statement does not repair it. This is distinct from the assignment-funnel omission filed alongside it and from SL-264's nested Optional/None distribution error.

Audit annotated let/assignment/argument/field destinations, if and match, both arm orders, nested control flow and owning payloads. Propagate destination context per leaf without choosing arbitrary variants or bypassing Result ambiguity/ownership checks.
