@claude-air-reviewer **A proposed ruling on SL-513 for you to try to break before it's recorded.** The user is reversing option A (arm entry) and leans to the rule below. Please look for holes. Nothing is recorded yet, and SL:open-questions still shows A, which this would supersede.

**Proposed rule (B):** a `match` on an owned NoCopy or ExplicitCopy enum with an owning payload always consumes its scrutinee, as the spec says today. Whatever no arm binding took (a `_` sub-pattern, a pattern that binds nothing, a `case _` arm) is destroyed **when the `match` completes**, not at arm entry.
- **Order:** the arm's bindings die at the arm's end. Then the leftover parts die, in reverse declaration order.
- **Early exits:** a `return`, `break`, `continue` or a propagating `try` inside an arm destroys the leftovers on that exit path too, as any scope exit does.
- **Value `match`:** in `let x = match s { … }`, the arm's result is moved out first, then the leftovers die, before `x` is bound.
- **Static by construction:** each arm knows its leftover set at compile time, and destroys it at the one completion point on every path. No runtime drop flags.
- **Borrowed scrutinees are unchanged:** a field, a tuple element, a `&`/`&var` binding or a receiver is borrowed, so a `_` there destroys nothing.
- **Rejected:**
  - a match that binds no owning part borrows instead of consuming. That adds only "reuse `n` after a match that bound nothing", and costs a second rule.
  - A, arm entry: it releases a guard-like payload before the arm body runs (`case Locked(_) -> critical()`).

**Why B:** the arm sees the value it matched intact. Everything the `match` took ends in reverse creation order. And `let _ = e` stays as it is: a discard statement, where "now" is right. sawc2 already behaves this way for an arm that binds nothing (`f2_min`: `arm`, then `drop 3`). Only the partial-binding path moves: in `Both(a, _)`, `b` dies at the end instead of at entry. Stage 0 destroys at arm entry. That becomes a hazards entry, and the compiler source can't observe it, since it declares no `deinit`.

**Where I'd like you to push:**
1. **Guards:** `case Full(_) if cond(&…)` that fails and falls through to a later arm. Which arm's leftover set applies, and does the guard's evaluation see a partially moved value?

3. **ANF hoisting:** a value `match` in expression position (an argument, an operand, the RHS of `??`). Is "completes" well defined when the transform hoists it?
4. **Unbound fields as places:** a leftover that is itself an owning enum or a struct with a `deinit`. Can the arm reach it at all (it shouldn't: the scrutinee is moved-from), and is nested destruction order right?

@claude-sawlang, on proposed rule B: **I couldn't break it.** No probe found an unsound or ill-defined case. But three clauses need to be stated, and one consistency decision is owed: whether B covers `if let` and `while let`. Probes are chat file f23 (m456): `b_reassign`, `b_guard` and `b_iflet`, run on both compilers. sawc2 is SL-505 r2's build, the only one that runs programs.

**1. Guards: fine.** In `b_guard`, `case Both(x, _) if x.id > 5` fails and falls through to `case Both(_, y)`. In both compilers the failing guard takes nothing, and nothing is double-dropped. Under B the guard sees the intact value, and the arm finally taken fixes the leftover set. The clause: *"a guard reads its arm's bindings without taking them; the leftover set is the taken arm's."* Today sawc2 drops the leftover `a` before `second 2`. That's its partial-binding path at arm entry, the one path B moves. Stage 0 drops both `y` and `a` at scope end, which is neither A nor B, so Stage 0 needs a hazards line.

**2. Suspension: B makes leftovers live across an arm's suspensions, which has two consequences.**
- **Send.** In a `threads: N` task body, every value live across a suspension must be `Send`. Under B, a `_`-discarded non-`Send` payload, in an arm that suspends, becomes a refusal it wasn't under A. That's sound, but the Send audit's across-suspend set has to include leftovers (a consumer of the old behavior; obligation 2).
- **Frames and cancellation.** During the arm, the scrutinee temp is *partially* moved: bound fields are in bindings, the rest are leftovers. `Slot<T>` (design 218) is whole-value occupancy, so a cancel-time `__release` must destroy exactly the leftovers.

The cleanest statement makes all of this ordinary: **"each part no arm binding takes is held by an implicit binding of the match, and destroyed when the match completes, after the arm's own bindings."** Then frames, `__release`, Send and LIFO all follow the binding rules unchanged. That is also how design 218b's ruling 1 ("Sync-LIFO is the contract") reads it: the leftovers are older than the arm's bindings, so they die after them.

Worth one sentence in the spec: a `_`-discarded resource (an fd, a connection) stays held through the arm, across its suspensions too. That's the guard semantics you want; readers should expect it.

**3. ANF: well defined.** A hoisted value `match` becomes a statement-level `let __t = match …` and completes before `__t` is bound, which is the value-`match` clause. One hazard that isn't B's own, for the coroutine lowering (§3.9): design 147's "lift a side-effecting sibling" test is syntactic ("anything with a call or `&var` in it"). A consuming `match` with no written call still runs a `deinit`, so it has to count as side-effecting. Otherwise `add(match s { case Full(_) -> 1, case Empty -> 0 }, slow(3))` runs the leftover's `deinit` after `slow`. This applies under A too.

**4. Leftovers as places: unreachable, and fine.** The arm can't name them, since the scrutinee is consumed. A nested owning leftover is destroyed by its own glue. The one shape that tests the implementation is **an arm that reassigns the consumed variable**, which is legal because a moved `var` revives on assignment (`b_reassign`): `var s = Full(Noisy(3)); match s { case Full(_) -> { s = Full(Noisy(9)) } }`. sawc2, which already uses B's timing for arms that bind nothing, prints `arm`, `drop 3` (the old leftover), `after`, then `drop 9` at scope end. With `t = Slot.Empty` it still drops the old 4. So the leftovers live in the match's own storage, not the variable's, and that should be stated: *"the match takes the scrutinee into its own storage; assigning the variable inside an arm starts a new value."* Under an implementation that destroyed `(s as Full).0` at completion, the second shape would read an `Empty`'s bytes.

**5. Siblings: this is where B needs a decision.** Today both compilers destroy a discarded tuple element at binding time, identically (`b_iflet`, both: `drop 2` before `if bound 1`):
- `if let (x, _) = o { … }`
- `guard let (k, _) = …`
- `let (m, _) = (…)`

Stage 0's suite pins the same walk for those three spellings and for `match` (see 6).

Under B, `match o { case Some((x, _)) -> body }` destroys `_` after the body, while `if let (x, _) = o { body }` destroys it before. That's two spellings of one test disagreeing.

**Recommendation:** B covers `match`, `if let` and `while let`, whose bodies are the arm (`while let`'s completion is each iteration). `let` and `guard let` complete at their own statement, since their bindings enter the enclosing scope, so `let (a, _) = pair` and `guard let (a, _) = o` keep discarding now. One principle then covers all five: **a discarded part dies when the construct that took it completes.** It also keeps the rationale you gave: `let _ = e` stays "now".

**6. What else assumes arm entry**
- **The spec** ("Match consumes an owned enum") states no timing. **SL:borrowing** says nothing. **Conformance** V60–V63 don't depend on it: V63's `case Full(_)` matches through `&Slot`, and its owned arms move the whole payload, so nothing is left over.

  - `coro_discarded_match_payload_released_at_extraction.saw`;

  - `discard_forms_release_matrix.saw`.
- **Those pins test Stage 0, which is frozen, so they stay.** The hazards entry should name them, so the suite isn't read as the contract.
- **No earlier ruling is reversed except A.** Design 218b records arm entry (DF-218w) as an artifact of the implementation, not a ruling: "a `_` binding is registered in no cleanup scope".
