**A7b. The std executor core** (std track).
- **Scope:** the run queue; task slots with generations; cells holding the result and the cancel word (design 134); `Task<T>` and `VoidTask` with `join` (driving the scheduler), `detach` and `cancel`; the background group, built on the first `Task.spawn` and closed at `main`'s return (cancel, then join); the freestanding refusal. Ported from `sawc/std/taskgroup.saw` into the bootstrap language, calling frames only through the descriptor. Two invariants come with it (§3.1, t2 and t3):
  - a nested drive skips every frame that is active on the C stack;
  - a task box is released only after its root returned `Ready`, asserted.
- **Depends on:** A2. Testable before A7a against a hand-built descriptor.
- **Files:** `std/task.saw`, `std/taskgroup.saw` (new), `compiler/tests/std/`.
- **Pins:** a std-lane program driving two hand-built frames; then, with A7a, `background_task_spawn`.
- **Done when:** the pins pass.
- **Estimate:** 1.5.

**Plan:** SL:coroutines §4, unit A7b (approved by the user, Oct 12). The plan text is authoritative; this issue is its tracker entry. Dependencies are named by unit id; see the epic's child list for their issues.

**Scope gained (the lead's decision, reversible, from the Air's review of A7d, SL-595 c2):** the run-time half of the must-consume guarantee. The spec says "one that escapes the check and reaches its destructor unconsumed panics" (the THE HANDLE IS MUST-CONSUME paragraph).
- **The handle:** the new std's `Task<T>`/`VoidTask` carry a PROVENANCE word (singleton or group). Their destructor panics when a singleton handle reaches it unconsumed, with Stage 0's message ('Task was dropped without being joined, detached or cancelled …', from `sawc/std/taskgroup.saw`'s `__write_fate` path).
- **`join`/`detach`/`cancel`** mark the handle consumed.
- **Pins:** a std-lane program with a hand-built singleton handle dropped unconsumed panics with that message, and a group-provenance one doesn't. The end-to-end pin, a `Task.spawn` handle moved into a struct field and the struct dropped, comes with A7a.

**A7b (agent a7b): two places the plan doesn't hold as written, and how I handled them.** Branch `worktree-agent-a081bd9b419812045`, not submitted.

1. **`std/taskgroup.saw` isn't loaded without a loader line.** `compiler/resolve/src/loader.saw:load_new_std_modules` is an explicit table, so a new std module is never compiled until it's listed there; A7c's `known.task`/`known.void_task` (and the existing `known.task_group`) would find nothing. That file is outside A7b's list. I added the one row (`self.std_module("taskgroup")`, after `task`) as its own commit so the lead can take or drop it. Two consequences follow, both in that commit or forced by it:
   - once the module loads, resolve's prelude table requires it to declare `TaskGroup`, `Task` and `VoidTask` (else `resolve.prelude-table` fires for every program). So `std/taskgroup.saw` declares `TaskGroup`, as the run-queue record the background group is, with no public constructor. A8a adds `init`, `Deinit`, `NoMove` and `spawn`.
   - the run lane's due program `discard_send_leftover.saw` (`compiler/tests/run/`, also outside the list) is now refused first at `TaskGroup(threads: 2)` as `call.no-match` instead of `name.undefined`. Its header moved with it.

2. **The freestanding refusal can't be in A7b's files.** sawc2 has no freestanding profile yet (no `--freestanding` flag anywhere in `compiler/`). Stage 0's refusal is a typecheck rule at the `Task.spawn` form (`sawc/typechecker/expressions.py`, pinned by `errors/background_spawn_needs_a_hosted_entry`), and A18's scope already lists "the freestanding `Task.spawn`". A7b leaves it to A18.
