**A7b. The std executor core** (std track).
- **Scope:** the run queue; task slots with generations; cells holding the result and the cancel word (design 134); `Task<T>` and `VoidTask` with `join` (driving the scheduler), `detach` and `cancel`; the background group, built on the first `Task.spawn` and closed at `main`'s return (cancel, then join); the freestanding refusal. Ported from `sawc/std/taskgroup.saw` into the bootstrap language, calling frames only through the descriptor. Two invariants come with it (§3.1, t2 and t3):
  - a nested drive skips every frame that is active on the C stack;
  - a task box is released only after its root returned `Ready`, asserted.
- **Depends on:** A2. Testable before A7a against a hand-built descriptor.
- **Files:** `std/task.saw`, `std/taskgroup.saw` (new), `compiler/tests/std/`.
- **Pins:** a std-lane program driving two hand-built frames; then, with A7a, `background_task_spawn`.
- **Done when:** the pins pass.
- **Estimate:** 1.5.

**Plan:** SL:coroutines §4, unit A7b (approved by the user, Oct 12). The plan text is authoritative; this issue is its tracker entry. Dependencies are named by unit id; see the epic's child list for their issues.

Approving SL-562.p1 (A7b, the std executor core). I read `std/taskgroup.saw` against the plan's A7b scope and the scope it gained from SL-595 c2 (the runtime half of must-consume), and compared its messages with Stage 0's. Exact tree on c224ea4ca: 416accc1.

**The runtime half of must-consume is here, and exactly Stage 0's:**
- `Task<T>`/`VoidTask` carry `provenance: TaskProvenance` (`Singleton` | `Group`) and `consumed: UnsafeMutableInterior<Bool>`, which `join`/`detach`/`cancel` set through `&self`.
- The destructor panics only for an unconsumed `Singleton` handle. The message is word for word Stage 0's ('Task was dropped without being joined, detached or cancelled — …', and the `VoidTask` twin; `sawc/std/taskgroup.saw` lines 1909 and 2001).
- `detach` on a `Group` handle panics with Stage 0's text (line 1853).
- Pinned by `exec/singleton_dropped` (panics) and `exec/group_dropped` (doesn't).
- Because `consumed` lives in an `UnsafeMutableInterior`, the handle is cell-carrying, so SL-592's predicate keeps `noalias` off every `&Task` parameter. A `join(&self)` that writes the flag is therefore sound under the noalias rule the user ruled.

**The executor:**
- **A nested drive skips active frames.** `runnable` is false for a `done` or `active` slot, and `resume_slot` marks the frame `active` around `resume_frame`, so a join that drives the loop never re-enters a frame already on the C stack.
- **A frame is released only after `Ready`, asserted.** `release_slots` panics if a slot still holds a frame. A `Pending` that recorded no park panics too, rather than hanging.
- **Stale handles are recognised.** The (slot, generation) pairs make a joined or detached task's handle stale, and `join` on it panics, naming both causes.
- **The background group closes at `main`'s return:** `cancel_every_live`, then `exec_run` until the group has no live task, then `release_slots` and `unregister`. That is Stage 0's shape (`__cancel_every_live`, called once). A task spawned during the close isn't itself cancelled, in both stds, so that's not a divergence.
- **Parks it can't serve yet** (timer, descriptor, channel) give a named panic rather than a hang: 'executor: a task is parked on a timer, which this executor does not wait on yet', pinned by `exec/timer_park`.

**Accepted deviations** (lead, c3): the `taskgroup` loader row with its minimal `TaskGroup`, and the freestanding refusal moving to A18.

**Gate:** passed on the retest (tested_commit == applied_commit == 90367c9bf; the first run's "failed" was the stale pre-ST-81 server, which ran no test, see c7).
