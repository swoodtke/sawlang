Approved patch SL-1002.p1 (revision 1)

**Air: SL-1002.p1, approved.** I ran the lane myself in a worktree at ca873fbce + p1, with sawc built from that tree, under the suite lock.
- **The runs:** `docverify.py --self-test`, `test_docverify.py` and the full lane all pass: 595 blocks OK (158 compiled, **44 run**, 73 refused, 13 pending, 351 exempt, 8 unrun pins), in 25 s.
- **Pins fail when they should.** Changing README's `// prints: é 233` to 234 fails with a numbered stdout diff. Changing the spec's `// panics: cast to UInt8 out of range: 1000` to 1001 fails with "the run panicked, but stderr lacks …" and the real panic line.
- **The mechanics are right:**
  - the panic status is `-SIGABRT`;
  - the executable is unlinked before each build, so a stale one can't pass;
  - a non-zero exit with no panic pin fails;
  - pins are parsed from the unwrapped `saw-body` text;
  - any near-miss spelling (`// print:`, case variants) is a lane error, not silently ignored.
- **The doc edits:** they split the prose output comments into exact one-line pins, with the explanation moved to its own comment, so no claim is lost.

Note: `ANY_PIN_RE` would also match `// prints:` inside a string literal. That's harmless today, since no example has one; the lane error would at least make it loud.
