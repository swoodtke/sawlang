## Description

The parse corpus never checks the bare form of a §12 **P** cell (a construct allowed in a context only when parenthesized).
- `generate.py` writes every P cell parenthesized, which is the allowed form.
- `negative.py` makes negatives for N cells only.

So if the bare form wrongly parses, nothing notices. Where it parses as another construct, the tree is never compared either.

**Found in SL-416.p1's review (F1):**
- §12 has `syntax.borrow.block` × `cond` = P, and syntax.rule.borrow-form says a binding at an `if` head is the optional-place unwrap.
- So `if borrow let x = f { a } {` must not parse with the borrow block as its condition.
- The recognizer happens to refuse that reading today, and head-restriction takes the three-rule text. But no case pins it, and the gap is a class.

**Fix:**
- `negative.py` generates, for every P cell, the bare form in its context: the same program the generator writes, without the parentheses.
- Record it exactly as N cells are recorded:
  - refused, with its name or `parse-error` under the README's Refusals rules;
  - or "parses as another construct", with that reading's dump, which must not place the construct in the cell's context.
- `parsecoverage` requires a bare-form negative for every P cell, and waivers carry reasons.
- Re-run the grammar corpus. Any bare P form found accepted as the construct in its context is a finding: classify it against GRAMMAR.md and report it. Never record it as expected.
