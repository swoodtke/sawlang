## Description

**One file reached by two import spellings becomes two modules** (SL:hazards S27; the SL-425 sweep, c7; main and seed alike).

In a package laid out as `src/`, built with `--module-path ident=src`, `import layout` and `import ident.sub.user` (which itself imports `ident.layout`) both reach `src/layout.saw`. That gives:
- **a silent wrong answer:** a static bumped once through each spelling reads `1`, because there are two statics;
- **two types for one struct:** ``expected `&ident.layout.Slot` ... found `&layout.Slot` ``.

The dependency face works (`1 2`).

Module identity must be the FILE (its canonical path), not the spelling that reached it. Either both spellings name one module, or the second spelling is refused with a diagnostic naming both. Which one is a design question for the brief: is `import layout`, inside a package, legal at all when the package's own name is `ident`?

**Obligation 4:** every way a file can be reached:
- a relative module name;
- the package-qualified name;
- `--module-path` aliases (two names for one directory);
- a symlinked directory;
- the std root reached as a module path.

**Retires:** the subset checker's `import-allowlist` (S27 part).

**Lead, on step 1 (p826):** the mechanism is confirmed. Module identity is formed from PATH TEXT (`canonical_identity`, `loose_identity`, `res_is_within`), so a module is one only when every spelling shares a base; `load_entry` never canonicalizes the entry. The sweep (C1-C8) is identical on main and the seed.
- **Decided by the spec:** C1, C6 and C7 are ONE module (Package Structure: "Both name one module"); C5 (the std root under another name) is REFUSED (Qualifier collisions).
- **OPEN for the user:**
  - C2: two `--module-path` names for one directory, or nested roots (lead lean: refuse the second);
  - C3: symlinks and hard links (lean: one module by real path; hard links a documented leftover);
  - C8: case mismatch on a case-insensitive filesystem (lean: refuse when the spelled segments don't match the on-disk names).
- **A blocker:** the compiler needs a real-path function. std has none, and the compiler's source must still be accepted by Stage 0, so a `Path.canonical()` would have to be added to the frozen `sawc/std/` too, as SL-522 did. This waits on the user's call about lifting the intersection rule.
- **Found:** SL-831 (import cycles not refused under the new std, high).
- PARKED until then.

**The user ruled (Oct 23), agreeing with the lead's leans:**
- **C2:** a second `--module-path` naming a directory another mapping already names, or nested inside one, is REFUSED, naming both mappings and the directory.
- **C3:** a symlink resolves to ONE module by real path; hard links are a documented gap.
- **C8:** an import whose spelled segments don't match the on-disk names (case) is REFUSED.

**The intersection rule is lifted** (the user, Oct 23: the compiler's own source no longer has to be Stage-0-compilable). So the real-path function (`Path.canonical() -> Result<Path, SystemError>` over realpath) goes in the NEW std only; the frozen `sawc/std` is not touched. This issue is unparked and queued.

<!-- sawtracker:comment {"author":"agent:claude-sawlang","body_bytes":464,"created":"1792758257","id":"c3"} -->
**Lead:** `Path.canonical()` goes through a new runtime seam, `__saw_rt_fs_realpath(path, status_out)`, mirroring SL-720's getcwd seam, so a failure carries its cause (never hide errors). The direct-libc alternative, which would lose errno, is rejected.
