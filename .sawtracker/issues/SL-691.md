## Description

**`Task<T>.join()` panics for a zero-size `T`: "this task's result is gone".** Found by SL-688's zero-size sweep (agent:claude-sawlang/z688slot). Stage 0 builds the repro and prints `1`, `2`, `3`; sawc2's binary panics at the first join, at -O0 and -O2, whether or not the root suspends.

```saw
struct Marker {}

func make_marker() -> Marker {
    __saw_suspend()
    Marker()
}

func make_unit() -> () {
    __saw_suspend()
    ()
}

func make_unit_plain() -> () {
    ()
}

func main() {
    let m = Task.spawn(make_marker()).join()
    let _ = m
    print(1)
    let p = Task.spawn(make_unit_plain()).join()
    let _ = p
    print(2)
    let u = Task.spawn(make_unit()).join()
    let _ = u
    print(3)
}
```

**Mechanism:** std's `complete` (`std/taskgroup.saw`) treats a result of size 0 as no result: it sets `cell.holding` only inside `if size > 0`, so a finished `Task<T>` whose `T` is zero-size holds nothing and its slot is recycled at once, and `join` then finds the handle stale. That conflates a zero-size `T` with `VoidTask`, which has no result. A zero-size result with a deinit (an empty `NoCopy` struct) is never moved out or dropped either.

**Fix:** "holds a result" is decided by the handle's kind (a `Task<T>` always holds one, a `VoidTask` never), not by the result's size; the zero-byte copy is harmless.

**Sweep first (obligation 4):** every reader of `result_size` in std's task code (`complete`, `drop_held_result`, the detach and cancel paths, `TaskGroup`'s spawns), each with an empty struct, an empty `NoCopy` struct with a deinit, `()` and a zero-length array, joined, detached and cancelled.
