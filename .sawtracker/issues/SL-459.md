Follow-ups from U6c2 (SL-452.p2), all confirmed or reported by its agent. The first two are MIR correctness.

1. **A guard-let's absent path drops the scrutinee twice** (the lead confirmed it on the p2 tree). `guard let r = find(n) else { return 0 }` lowers its else-block as `drop(_2); _0 = const 0; drop(_2); return`. It is harmless for a None at run time, but the MIR is wrong, and the MIR verifier has no double-drop check, which is why it slipped through. Fix the lowering, and add a verifier check that no path drops an owned local twice without reinitialising it. That is a class: sweep every exit kind (return, break, continue, ?, else blocks) through the scope-drop path.
2. **`return None` in a lending function** leaves a dead `None` temporary.
3. **Aliases such as `Byte`** aren't treated as integers by the fold or the evaluator, so a constant typed `Byte` misbehaves.
4. **Typecheck doesn't enforce `consumes` every-path-or-none;** MIR refuses it. A user error belongs in typecheck, so move the rule there, with the same id and a fixture.
5. **Typecheck accepts a format string mixing `{x}` and `{}`** (`format_args_mixed_error.saw`), and lowering refuses it as slice.not-yet. Decide the rule in typecheck: refuse it, or define it.
6. **Typecheck's corpus_info.py** blames the last program seen for a crash. Fix it as the MIR one was fixed.
7. **`static_assert((1<<64)==0)`** is refused only by the evaluator, not by typecheck's fold. Check that the agreement gate covers static_assert overflow.
8. **The saw-lang skill's SKILL.md** still describes design 185's signed-domain constant gotcha, which the Sep 25 ruling retired. Update it.

Sequencing: after SL-452.p2 and SL-458 land. Items 1 and 2 touch compiler/mir; items 3 to 7 touch typecheck and eval.
