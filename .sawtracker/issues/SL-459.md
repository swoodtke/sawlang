Follow-ups from U6c2 (SL-452.p2), all confirmed or reported by its agent. The first two are MIR correctness.

1. **A guard-let's absent path drops the scrutinee twice** (the lead confirmed it on the p2 tree). `guard let r = find(n) else { return 0 }` lowers its else-block as `drop(_2); _0 = const 0; drop(_2); return`. It is harmless for a None at run time, but the MIR is wrong, and the MIR verifier has no double-drop check, which is why it slipped through. Fix the lowering, and add a verifier check that no path drops an owned local twice without reinitialising it. That is a class: sweep every exit kind (return, break, continue, ?, else blocks) through the scope-drop path.
2. **`return None` in a lending function** leaves a dead `None` temporary.
3. **Aliases such as `Byte`** aren't treated as integers by the fold or the evaluator, so a constant typed `Byte` misbehaves.
4. **Typecheck doesn't enforce `consumes` every-path-or-none;** MIR refuses it. A user error belongs in typecheck, so move the rule there, with the same id and a fixture.
5. **Typecheck accepts a format string mixing `{x}` and `{}`** (`format_args_mixed_error.saw`), and lowering refuses it as slice.not-yet. Decide the rule in typecheck: refuse it, or define it.
6. **Typecheck's corpus_info.py** blames the last program seen for a crash. Fix it as the MIR one was fixed.
7. **`static_assert((1<<64)==0)`** is refused only by the evaluator, not by typecheck's fold. Check that the agreement gate covers static_assert overflow.
8. **The saw-lang skill's SKILL.md** still describes design 185's signed-domain constant gotcha, which the Sep 25 ruling retired. Update it.

Sequencing: after SL-452.p2 and SL-458 land. Items 1 and 2 touch compiler/mir; items 3 to 7 touch typecheck and eval.

**Item 1 is wider than the scrutinee: a whole-corpus sweep and its mechanism.** From my SL-452.p2 review. A sub-agent ran a path-sensitive double-drop checker over `sawc2 mir --dump` (p2's sawc2) on the corpus and on sawc2's own source.

**The mechanism.** `lower_guard_let` enters the else block while the guard's head scope is still open, whereas `if let` stores its absent block and enters it only after `discard_scope()`. On the absent edge, the head scope's drops run, and then any exit from the else block unwinds through that same scope (`unwind_to(head)`) and drops everything in it again. The scrutinee is only ever `None` there, but the head scope also holds the subject expression's own owned temporaries.

**The repro** (both compilers accept it, and Stage 0 runs it with exit 0):

```saw
struct Holder { name: String }
extension Holder {
    func find(&self, n: Int) -> Int? { if n > 0 { return n }
        None }
}
func make() -> Holder { Holder(name: "held") }
func probe(n: Int) -> Int {
    guard let r = make().find(n) else {
        return 0
    }
    r
}
```

The else path is `bb4: drop(_2); _0 = const 0: Int; drop(_2); return`, where `_2: Holder`, a whole value that owns a String.

**The same shape for every exit kind:**
- `break` gives `drop(_4); drop(_4)`;
- `continue` gives `drop(_6); drop(_6); budget(…)`;
- on the `try` error edge, `bb4` drops the temporary, then the Err edge (`bb7`) and the Ok edge (`bb6`) each drop it again;
- with a present payload, `guard let x = s!.find(…)`, `_2: String?` is `Some` on that path and is dropped twice;
- also `guard var`, a guard inside a closure body, a nested guard in a loop, and a `try` inside the guard's subject.

**Clean in the same probes:**
- a `match` on a temporary whose arm returns, breaks or continues;
- `if let` in either branch;
- a `while let` that breaks;
- `try` with an owned `Err`;
- `??` chains over receiver temporaries;
- a boolean `guard` over a temporary;
- a conditional-window guard subject, whose absent edge does not close its window twice.

**Corpus extent:** every one of the 11 corpus sites, and the 1 site in sawc2 (`ResProgram.load_import`, `_16: String?`), is the `None` scrutinee. The owning-temporary shape doesn't occur in the corpus today. `golden/destructures.mir` (`unwrapped`, bb8) records the double drop as expected output.

**Severity:** the MIR README defines `drop(PLACE)` as "drop it if it is still initialised", and the lowering already relies on that, with 408 drop-after-move sites. So the second drop is a no-op under the documented semantics, and a double free only for a backend that drops unconditionally. Two consequences:
- **The verifier check** should be "no drop of a place already dropped on some path": a lowering-bug detector, since the semantics tolerate it.
- **The fix:** enter the else block after the head scope's drops, as `if let` does, and pin one golden row per exit kind.

The checker (`double_drop.py`, with case tags per switch edge) and all the repros are on the Air at `.build/scratch/air-review/sl452p2/dd/`; I can attach them if useful.
