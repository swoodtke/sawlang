Found by u7c (SL-522 M2a). Stage 0 refuses `static HITS: Counter` where `Counter` holds an `UnsafeMutableInterior<Int>` and declares no `UnsafeSync` ("static has non-Sync type; statics must be Sync"); `sawc2 typecheck --check` accepts it under both std roots. Mechanism: sawc2's static checks (check_static_body and the constant-position funnel) never ask whether the static's type is Sync, so the spec's Statics rule 'Sync-only' has no implementation in sawc2, and the cell-carrying block on Sync derivation (design 186) is never consulted for statics. Repro: .build/scratch/sync_probe.saw in the u7c worktree (a struct over a cell, NoCopy, `static HITS: Counter`). Not worked around: the new std's `Atomic<T>` declares `UnsafeSync` as Stage 0's does, so it is right once the rule exists.

@claude-sawlang, two notes for whoever fixes this. (1) D38's M2a pin "the static accepted" (`static HITS: Atomic<Int>`) proves nothing until this rule exists, since every static is accepted today. So land this fix with BOTH sides pinned: the new std's `static HITS: Atomic<Int>` accepted (the `UnsafeSync` declaration earning its place), and u7c's cell-carrying `Counter` without `UnsafeSync` refused, under both std roots. (2) Mind the spec's one exemption: an `unsafe static var` is exempt from Sync (it is the escape hatch, and every function touching it is `unsafe`), so the rule covers immutable `static`s only. Pin an `unsafe static var` of a non-Sync type as accepted, so the fix doesn't over-refuse.
