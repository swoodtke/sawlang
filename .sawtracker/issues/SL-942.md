## Description

**The seed bump is blocked: `seed.py`'s path-free check refuses absolute paths that sawc's own source spells.**

`seed.py write --target arm64-apple-darwin` at main f8b65c0aa refuses with:

```
seed: FAILED: sawc.ll.xz's .ll for arm64-apple-darwin holds an absolute path: /opt/homebrew, /bin/sh
```

Both are string literals in `compiler/driver/src/main.saw`:
- `"/bin/sh"`: the driver's tool runner (SL-887) runs it.
- `/opt/homebrew`: from the no-clang error message, SL-865.p10.

Both landed after the current pin (9c520edd3, Oct 23), so this bump is the first to meet them.

**The check's invariant:** the seed's IR is "a function of the source and the target alone, whatever machine wrote it". A path the source spells literally is exactly that; the regex detector can't tell it from a leaked build-machine path.

**Fix (the lead's):** `absolute_paths(text, commit)` leaves out a path that a `.saw` file under `compiler/`, `std/` or `runtime/` spells at that commit (`git grep -F`). `emit` passes HEAD, and `check_path_free` passes the pin.
- **Pin:** `test_seed_store.py` checks that a spelled path (`/bin/sh`) is left out only when a commit is given, and that `/Users/a/b` is still refused.
- **Proof on real IR:** the driver IR emitted by Stage 1 at f8b65c0aa holds exactly `/bin/sh` and `/opt/homebrew`, and with the commit both are left out (`.build/scratch/probe_seed_paths.py`).

Blocks: the seed bump, and with it SL-833's json patch and SL-924.

**Air: SL-942.p1 approved**, with one non-blocking nit. Reviewed r1 on 2f9bf5bdf.

**The case it unblocks, run end to end:** `seed.py emit --target arm64-apple-darwin` on the applied tree ends `seed: .build/seed-write/arm64-apple-darwin, emitted from 96e734e62…`, `exit=0`.
- **What the IR holds:** the emitted `sawc.ll` contains `/bin/sh` (the tool runner) and `/opt/homebrew`. That comes from the driver's no-clang message in `driver/src/main.saw` ("…`$HOMEBREW_PREFIX/opt/llvm/bin/clang`, /opt/homebrew when unset…").
- **The regex:** it doesn't extract `/opt/llvm/bin/clang`, because its lookbehind rejects the `X` before that slash. So the two paths it sees are both spelled in source, and both are now exempt.
- **Fail-closed:** a pinned commit the clone lacks makes `git grep` exit 128, which reads as "not spelled", so the path is still refused.

**Gates:**
- `run.py --only seed,units`: `exit=0` (27 seed-store cases, including your new one that keeps `/Users/a/b` refused while `/bin/sh` passes; 45 unit programs);
- `battery.sh citations`: `exit=0`.

**Nit (not blocking):** `spelled_in_source` searches `compiler/*.saw`. As a git pathspec that matches every `.saw` under `compiler/`, including `compiler/tests/**` and `compiler/prototypes/**`, and comments as well as literals. None of those reach the seed's IR, so a path spelled only in a test fixture or a comment would exempt a matching leak. Today that's theoretical: no comment in `compiler/`, `std/` or `runtime/` names a `/Users/` or `/home/` path, and the only home-style literal is `"/home/user/docs/file.txt"`. If you touch it again, the tighter set is the stage `src/` trees plus `compiler/driver/`, `std/` and `runtime/`, matching only string literals.
