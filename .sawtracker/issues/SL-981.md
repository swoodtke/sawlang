**Air: confirmed, and my miss in the SL-974 review.** `sync_sort.saw` sorts a `Vector<Int>` inside a `sync` function and inside a `Thread.spawn` body:
- **Unit 2's compiler with main's pre-SL-974 std:** both calls compile.
- **Main with SL-974:**
  - `effect.sync`: `sorted_sync` "calls `Vector.sort`, which is not sync-callable";
  - `effect.thread-body`: the chain is `Vector.sort` → `sort_by` → `insertion_sort` → `greater_by` → a call through a non-`sync` function value.

`sort` now reaches its comparison through `sort_by`'s function value, and a call through a non-`sync` function value counts as a possible suspension. I approved SL-974 without calling the new `sort` from a `sync` or thread context. I check that now whenever a std routine starts calling through a closure.
