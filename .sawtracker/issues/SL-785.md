## Description

**`EBADF` and `EIO` have no `SystemErrorKind`; both become `Unknown` ("other error")** (the Air, SL-768 c29). The hosts' classifier (`runtime/host_macos/net_os.saw`, `runtime/host_linux/net_os.saw`) maps EAGAIN, EINPROGRESS, …, EINVAL, EMFILE/ENFILE/ENOMEM/ENOSPC and the network errors, but not:
- `EBADF`: a closed or invalid descriptor, e.g. `print` to a closed stdout (`>&-`), the commonest `print` failure after SL-768 c2;
- `EIO`: a hung-up terminal, a failing disk.

**Interim (SL-768 c2, the lead's call):** `SystemError`'s text appends the raw code when the kind is `Unknown` (`write failed (other error, errno 9)`), so the cause is never hidden.

**Needs the user (API naming, doctrine: no abbreviations):** add named kinds? Candidates: `InvalidDescriptor` (or `BadDescriptor`, or `ClosedDescriptor`) for EBADF; `InputOutputFailed` (or `HardwareFailure`) for EIO. Each needs both hosts' classifier, both runtime trees, the describe text, and a sweep of corpus outputs quoting `other error` for these two errnos.

Approved patch SL-785.p1 (revision 1)

**Air: SL-785.p1 approved. One pre-existing bypass found, for its own issue.** Reviewed on origin/main 59c15970c plus r1; probes in `air-review/sl785p/`.

**What holds:**
- **Both classifiers** (`host_macos`/`host_linux` `net_os.saw`) map errno 9 → `InvalidDescriptor` (22) and 5 → `InputOutputFailed` (23). Both values are the same on both hosts.
- **Tags are appended**, nothing renumbered, and the `SysError` copies and `ABI.md` agree. `run.py --only runtime_table,std_cone` passes, so the trees are byte-identical and the cone matches.
- **The pins at -O0 and -O2:**
  - `print_to_closed_stdout_panics` → "write failed (invalid descriptor)";
  - `net_refusals_are_errors` → "getsockname failed (invalid descriptor)";
  - `io_error_unknown_names_its_errno` → "(other error, errno 2)" for an unclassified code, "invalid descriptor" and "input/output failed" for 22 and 23, and "(other error)" with no code for a std-raised `Unknown`.
- **Consumer sweep (obligation 2):**
  - Both reactors' `unregister` ignore `EV_DELETE`/`EPOLL_CTL_DEL`'s result, so a closed fd's EBADF reads the same.
  - No std or runtime code compares a raw tag or branches on `Unknown` for these errnos.
  - The spec's and skill's kind lists end in "…", so they owe nothing.

**The bypass: `File.close` never classifies** (`std/file.saw`). When close(2) fails, it returns `SystemError.raised("close", SystemErrorKind.Unknown)` with `code: 0`, so the errno is dropped before any classifier sees it. `k1_close_ebadf.saw` closes a `File`'s descriptor behind its back, then calls `File.close()`. It prints **"close failed (other error)"** at -O0 and -O2: EBADF, with neither the ruled kind nor the errno that `Unknown` now names.

The case that matters more is EIO from close(2), the deferred-write failure (NFS, a full or failing disk). That's exactly the data loss "never hide errors" is for, and here it reads as an anonymous "other error". It's the one std site that raises a fixed `Unknown` where an errno exists; every other `File` operation goes through a seam and `SystemError.of`. std can't classify it itself, since `__saw_rt_last_syserror` is runtime-internal (ABI.md). So the fix is a close seam in both trees, e.g. `__saw_rt_fs_close(fd) -> 0 | -tag`, used like `__saw_rt_fs_unlink`. It predates this patch and isn't in its ruled scope, so it belongs in its own issue, with `k1` as the pin ("close failed (invalid descriptor)").
