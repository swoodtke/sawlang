## Description

**Filed by the sawtracker lead (2026-10-13).** Hit while implementing sawtracker ST-90. It's the same mechanism as sawtracker's SAW_NOTES **ST-SAW-7**, which was never filed upstream.

**Compiler:** pinned `sawc 0.12.0` (sha 7e124389, the Python sawc.py). It fails at both -O2 and -O0.

## Reproducer (19 lines; std only)
```saw
// The callee suspends and borrows its own by-value String parameter.
func size(s: &String) -> Int { s.len() }

func call(body: String) -> Int {
    sleep(Duration.secs(0))
    return size(&body)
}

func text(n: &Int) -> String { "x" }

// The caller (a coroutine, since `call` suspends) passes, as that argument,
// a call that re-borrows the caller's own reference parameter.
func ask(n: &Int) -> Int {
    return call(text(&n))
}

func main() {
    let n = 1
    let _ = ask(&n)
}
```
`sawc -O2 ice.saw -o out/ice`:
```
error: internal compiler error: LLVM IR parsing error
<string>:4684:7: error: value doesn't match function result type 'ptr'
  ret {i1, i8*} %"autowrap_val"
      ^
```

## Variant that compiles
Bind the argument first, then move it:
```saw
func ask(n: &Int) -> Int {
    let body = text(&n)
    return call(move body)
}
```

## What triggers it
It fails only when ALL of these hold:
1. **The callee suspends.** `sleep` is the smallest suspending call found; `TcpStream.connect` also triggers it. A channel `send` alone does not.
2. **The callee passes `&param` of a by-value parameter to a function,** e.g. `size(&body)`. A method call such as `body.len()` does not trigger it.
3. **The caller's argument for that parameter reads through one of the caller's own REFERENCE parameters.** Either a call like `text(&n)` with `n: &Int`, or a receiver like `jobs.copy()` with `jobs: &Channel<Int>`.

Each of these compiles: `n` by value or a local; `call("{n}")`; `call(text2(n))` with a by-value `text2`.

## The mechanism (from --emit-ir)
- (2) makes the callee's frame store `body` in a presence-tagged slot, `{i1, i8*}`.
- The caller builds the argument as a closure passed to `UnsafeRef<Int>.deref(...)` (`__closure$__Frame_ask$m$_resume$…`), declared to return `i8*`.
- Its body is lowered against the destination's OPTIONAL slot type and auto-wrapped, so it ends in `ret {i1, i8*} %"autowrap_val"`, which LLVM rejects.

## The ST-SAW-7 shape gives the same error
A worker with `jobs: &Channel<Int>` calls `handle(jobs.copy())`, where `handle` sleeps and then calls `peek(&jobs)`:
```
ret {i1, %"Channel$1$Int"} %"autowrap_val"
```
It compiles without `peek(&jobs)`. Sawtracker's workaround since then has been "bind to a local, then move": SAW_NOTES ST-SAW-7, and now ST-90.

## Known-issue check (read-only)
- **SL-43 (DF-262b)** is the only other `autowrap_val` ICE. It's a different shape (a suspending interpolation piece plus `Task.spawn`), and closed/frozen. It lives in the same ANF/auto-wrap code.
- **No hazards-ledger entry.** L4 covers Optional/Result shaping, but not this shape.
- **The nearest precedent is SL-431,** a Stage 0 coroutine ICE that became loud hazard L20.

**Suggestion:** a new loud hazard (L26?) with this reproducer, so workaround sites can carry `// Stage 0 workaround (SL:hazards L26): canonical: …`. Fix it in Stage 0, or confirm the self-hosted compiler doesn't have it.

The reproducer files (`ice.saw`, `ok.saw`, `saw7.saw`, `saw7c.saw`) are available on request.
