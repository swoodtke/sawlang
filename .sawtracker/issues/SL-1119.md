## Description

**Filed by the sawos lead for the sawlang lead.** Hit while writing sawos's image builder in Saw (SO-104). Run against sawlang 0.23.0, hosted, macOS arm64, by the builder's implementer.

- **Tried (reproduced).**

  ```saw
  struct Unit {
      object: String
  }

  func pick(units: &Vector<Unit>) -> String {
      let object = (units.get(0)?.object) ?? ""
      return object
  }

  func main() {
      var units = Vector<Unit>()
      try! units.push(Unit(object: "a.o"))
      print(pick(&units))
  }
  ```

  The unparenthesised form and a tail return fail the same way.
- **What happened.** The compile stops with an internal invariant:
  `INVARIANT v2 5:43 v2.pick(...): owned local _6 may still be live at a
  `return` in bb9: a scope exit does not drop it`.
- **Expected.** It compiles, and the temporary is dropped.
- **Why sawos needs it.** Reading a field of a vector's element with a fallback is everyday code in a tool.
- **How badly.** Nice to have: binding the optional first (`guard let unit = units.get(0)`) works. But it is an internal error on ordinary code, not a diagnostic.

**Triage and implementation detail (lead, Nov 14).** Reproduced on main at df036fb2f. The `??` is not part of it, and neither is the lend.

**The sweep (20 programs, `.build/scratch/p1119/probe_variants.py`, results `variants_main.txt` in the lead's checkout).** `Unit` is `struct Unit { object: String, n: Int }`; `find(&units)` returns an owned `Unit?`.

| `units.get(0)?.object` alone, then `if let` on it | INVARIANT |
| `if let o = units.get(0)?.object`, `guard let o = units.get(0)?.object` | INVARIANT (twice) |

**The mechanism (obligation 4), read from the MIR dump** (`sawc mir --dump`, `.build/scratch/p1119/r_owned_chain_alone.mir`, function `pick`): the head call's result is an owned temporary `_5: Unit?` (`Vector.get(index:)` returns its `Unit?` by value, as `find` does). On the present path the final field is read as a MOVE out of that temporary's payload, `_6 = move (_5 as Some).0.object`, and after that no block drops `_5`: not the rest of the payload on the present path, and not the temporary on the absent path. The verifier refuses it (`owned local _5 may still be live at a return`), which is why this is an internal error and not a leak. So the class is: **a `?.` hop whose base is an owned temporary of the statement and whose final field read moves an owning value out of the payload.** A trivial field is a copy and leaves the temporary whole for the statement to drop; a method hop only borrows it; a named head is a local with its own drop. The owning final types to cover: `String`, a `Vector`, a `Box`, a struct of the automatic Copy tier that holds a `String`, a nested field (`?.a.b`), two hops (`?.a?.b`), a tuple index.

**Where.** `compiler/mir/src/lower.saw`: `hop_steps` calls `chain_hop_payload(p, -1, -1)`, so the funnel's own provision for this ("a temporary the present path takes its payload out of, consumed at node `taken`, is dissolved on the absent path too") is not used by a hop; and `held_payload` returns an owned temporary's payload "as it is", after which the field read is lowered as a move with nothing dissolving what is left. `payload_val` (the `o!` and `??` adjust) is the entry point of that funnel that does pass `taken`: read how it takes a payload out of a temporary and what `dissolve` emits, and make the hop's final read of an owning field do the same: the field moves out, the payload's other fields are dropped on the present path, and the temporary holds nothing on the absent path. The spec's rule is "Temporaries" (a statement's temporaries are dropped at its end) and design 111 (the final field of a chain must be copyable: the value read is the field's copy policy; for the Copy tier, moving out of a temporary nothing else names is that copy with the retain and the release cancelled, which is only right if the remainder is still dropped).

**Step 0 for the implementer, before any change:** the sweep above with the worktree's compiler (same table); the MIR of `pick` for the filed program and for `find(&units)?.object`, kept; then the same two with a second owning field in `Unit` whose type prints from a hand-written deinit body (a copy-policy conformance carries one), to state what the drop order must be after the fix: the remainder is dropped at the end of the statement, once.

**The test plan is the matrix:** head (a call returning an owned Optional; `Vector.get`; `Map` lookup by value if it returns one; a method returning `Self?`) × final read (the owning types above) × consumer (`let`, `??` with a literal and with a call, `if let`, `guard let`, `return`, a tail, an argument, `== None`, a `match`). Every cell builds, prints the value, and under the ownership oracle (`gmgate`) neither leaks nor double-frees; the deinit-printing cell prints each drop once. Controls that build today stay byte-for-byte: the trivial field, the method hop, the named head. Pins: run probes under `compiler/tests/run/probes/` for the filed shape and the deinit-order cell; a `compiler/tests/mir/` golden of the filed shape's `pick` if that lane holds chain goldens (read its README).

**Stops.** The fix is not inside the chain lowering (`hop_steps`, `held_payload`, `chain_hop_payload` and the final field read) or needs a change in `drops/` or `borrowck/`; a conditional-lend head (a `borrows -> T?` method, where the payload is not the statement's to move) shows the same INVARIANT, which would be a second mechanism; any existing golden or corpus row moves.

**Gate.** `compiler/tests/run.py --only seed,units,golden,subset,fixture_whitespace,std,comments,mir,borrowck,drops,programs`; `tools/battery.sh gmgate` for the new probes; `tools/battery.sh citations`.

Workaround until it lands (sawos uses it): bind the head first, `guard let unit = units.get(0)`.

**Lead's ruling on the implementer's checkpoint stop (Nov 14): its reading replaces the detail's on one point, and its plan is accepted with conditions.** The plan is `.build/scratch/p1119/u_plan.md` in the lead's checkout.

**The mechanism, corrected.** The present path is already right: the final field read goes through `take_from_temporary`, which forgets the temporary and dissolves it, so the field moves out and the rest of the payload is dropped there (the deinit program's MIR shows the second field's drop). What is missing is the ABSENT path. `forget_local` takes the temporary off its scope on every path, and the absent block was built earlier, at the hop, when nothing yet knew the temporary would be taken; so on the absent edge, where the temporary holds `None`, nothing drops it, and the verifier is right to refuse the function. The detail's model (pass `taken` from the hop) cannot work: the hop is lowered before the member read that decides, and passing it always would add a second drop to every chain that builds today.

**The fix, as the implementer planned it.**
1. `MirChain` (`compiler/mir/src/program.saw`) gains the absent blocks made for it, each with the root temporary local of the hop's base. `chain_hop_payload` records one in its absent branch (`absent < 0`), after `leave_chain`, when the base's root is an owned temporary.
2. `take_from_temporary`, right after `forget_local(l)`: for each record of the INNERMOST chain whose root is `l`, a `drop` of `l` is appended to that absent block, and the record is removed so it cannot fire twice. The cursor is restored.

**Conditions.**
- The hook fires only for a record whose root is the forgotten local. A shape with no chain, or a chain whose temporary is never taken, lowers exactly as today. **The proof is a whole-dump comparison, not a sample:** `sawc mir --dump` of each of the seven controls that build today (`d_copy_field`, `j_method_hop`, `k_no_chain`, `l_local_optional`, `q_local_chain_alone`, `s_index_field`, `t_if_let_then_field`), before and after, byte for byte. Each dump holds all of std's MIR, so equality there also shows std's lowering did not move.
- The expected MIR of the filed program is the before dump with one line added: the absent block becomes `drop(_6); goto -> bb2`. Any other difference in that function is a stop.
- If the verifier, borrowck or drops refuses a function for a statement appended to a block that already has its terminator, STOP with the message: the alternative is to make the absent block's drop when the block is built and take it back, which is the lead's to design.
- The two funnels' docstrings say what is true now (THE OPTIONAL-HOP FUNNEL records the absent block; the TEMPORARY-PART FUNNEL drops a forgotten temporary on the absent paths recorded for it), each with its ENTRY POINTS correct. Present tense, no history.
- `compiler/tools/front_parts.py --check` must still say current (the new field is lowering state; if the check disagrees, stop).

**The matrix, as the detail wrote it, with two changes the implementer's step 0 forces.** A head whose payload holds a `NoCopy` field cannot come from `Vector.get` (it needs `Copy`), so the deinit-order cells use a function returning an owned Optional. And the drop order to state and pin is: on the present path the rest of the payload is dropped where the field is taken, the same place and order as the chain-free `find(true)!.object` (dump both and compare); on the absent path nothing prints.

**Gate, added:** `front_parts` joins the `--only` list.

**Files:** `compiler/mir/src/lower.saw`, `compiler/mir/src/program.saw`, the pins. Anything else is a stop.
