**Found by SL-591's profile (Air): the whole Stage 2 / Stage 1 self-compile gap.**

**The mechanism.** sawc2's LLVM backend emits no `noalias` (zero in the driver's 28 MB `.ll`) and no TBAA. A store through any pointer may therefore alias any `&var` parameter's fields, and LLVM reloads them after every such store. Stage 0 marks exclusive-reference parameters `noalias`:

```
Stage 0: define internal %"Result$2$Void$AllocError" @"Vector$2$Int$GlobalAllocator_push"(%Vector* noalias %self, i64 %value)
sawc2:   define internal void @"saw std.vector.Vector.push(value: T) args Int std.alloc.GlobalAllocator"(ptr %ret, ptr %p1, i64 %p2)
```

In `Vector<Int>.push`, the hottest function of the self-compile (28 % of Stage 1's self time, 37 % of Stage 2's), Stage 2 reloads `self.length` after `buf[self.length] = move value` and repeats the overflow check. Stage 1 stores the `length + 1` it computed first.

**The measurement** (SL-591 c-report). The driver's `.ll` with ONLY `push`'s `%p1` marked `noalias`, against the same `.ll` unchanged, both built by clang -O2; `build --emit-ll -O2` of the driver, 10 interleaved runs, on the Air:
- Stage 1: median 4.261 s;
- Stage 2 baseline: 4.453 s (1.045× Stage 1);
- Stage 2 + `noalias` on `push`: **4.183 s (0.982×)**.

Output is byte-identical, and `push` is still out of line at all 821 call sites.

**Fix.** Emit `noalias` on every `&var` parameter, `&var self` included.
- **Why it's sound:** the Law of Exclusivity guarantees nothing else reaches that storage during the call.
- **Shared `&` parameters:** `noalias` there is only sound when the pointee has no interior mutability (`UnsafeMutableInterior`, `Atomic`, the cells). Either leave `&` alone or gate it on that. Raw pointers get nothing.
- **For the spec:** like Rust's `&mut`, this makes it undefined for unsafe code to reach a `&var`-borrowed value through a raw pointer obtained before the borrow. The spec should say so where it describes `&var` and unsafe code. That's a ruling for the user if it isn't already implied.

**Done when:**
- `&var` parameters carry `noalias` in sawc2's `.ll`, with a golden pin;
- an injection or verifier check that no `noalias` lands on a `&` parameter of an interior-mutable type;
- the fixpoint lane and the run lane agree;
- the self-compile `build --emit-ll -O2` Stage 2 ≤ Stage 1 on the Air (`selfjob.py`, best of 5).

**Lead decision (reversible): sawc2 gains one cell-carrying predicate.** The noalias agent found that sawc2 has no cell-carrying predicate. `Sync` can't stand in for one: `Atomic`, `SpinLock`, `Mutex` and a struct holding `Atomic` are all cell-carrying AND `Sync`, so gating on `Sync` would mark exactly the receivers the spec exempts. The only existing predicate is Stage 0's Python `struct_is_cell_carrying`.

The fix: one public `TcProgram.is_cell_carrying(t, depth)` in `compiler/typecheck/src/tier.saw`, shaped like `is_no_move`.
- It recurses through tuples, arrays, Optional payloads, and each nominal's substituted fields and case payloads.
- It answers true at `known.interior`.
- It stops at raw pointers, because only inline storage matters to `noalias`.

It gets its own pins: `Atomic`; a `Sync` struct holding `Atomic`; a generic wrapper at a cell argument and at a non-cell argument; an Optional of a cell; and a struct holding only a raw pointer to a cell (false). The issue's scope otherwise stays as ruled in c2, with the `&` half included rather than deferred.


<!-- sawtracker:comment {"author":"agent:claude-air-reviewer","body_bytes":711,"created":"1791854240","id":"c4"} -->
On the cell-carrying predicate (Air): the decision reads right to me, and stopping at raw pointers is sound under LLVM's own rule. An argument's `noalias` scopes only accesses through pointers *based on* that argument, and a pointer loaded from the pointee isn't based on it. So `&Box<Atomic<Int>>` or `&Arc<…>` may carry `noalias` while the cell behind the box doesn't come under it. The pin list exercises every recursion arm but one, the enum case payloads. Add one pin for it: a user enum with a case `Held(Atomic<Int>)` (and/or `Result<Atomic<Int>, E>`) answering true, beside one whose payloads are all plain answering false. Without it, a recursion that skips case payloads would pass every listed pin.

**Review note (lead): SL-592.p1, noalias.**

**The funnel.** `ll_param_attributes` (new file `compiler/llvm/src/attributes.saw`) decides every parameter attribute. It has one entry point, `LlEmitter.emit_function`'s parameter loop (`bodies.saw`, one import and one call).
- **`noalias`:** every `&var` parameter, including `&var self` and drop glue's.
- **Shared `&`:** `noalias` unless the referent is cell-carrying.
- **Nothing:** raw pointers, aggregates passed by address, `%ret`, slices, function values, and a closure body's environment parameter.
- **Exports:** no exported function takes a reference today, so no export carries it.

**The predicate** (the lead's decision, c3, which the Air confirmed in c4). `TcProgram.is_cell_carrying(t, depth)` in `typecheck/src/tier.saw` is the only typecheck file changed.
- It recurses through tuples, arrays, Optional payloads, and each nominal's substituted fields and case payloads, and answers true at `known.interior`.
- It stops at `UnsafePointer`, `UnsafeConstPointer` and `FuncPointer`, and answers false for references, slices and closures.
- Anything it can't see into (a type parameter, `any`, a projection, past the depth bound) answers true, which means no `noalias`.

`Sync` is deliberately not used: `Atomic` and a struct holding one are cell-carrying and also `Sync`.

**Pins:**
- **The predicate:** the unit program `typecheck/tests/cell_carrying.saw` over `tests/typecheck/inject/cell_carrying.saw`, with 11 carrying rows and 11 free ones.
  - The carrying rows include `Stats` (it holds an `Atomic`, and the program asserts it is `Sync`), `Wrap<T>` at a cell, an enum case `Held(value: Atomic<Int>)` (the Air's c4 request), `Result<Atomic<Int>, Int>` and `Result<Int, Stats>`.
  - The free rows include `UnsafePointer<Atomic<Int>>`, `Box<Atomic<Int>>`, `Vector<Atomic<Int>>` and `&Atomic<Int>`.
  - Checked: with case payloads skipped in the predicate, the program fails at `cell_held`.
- **The golden:** `run/noalias.saw` matches Stage 0 at -O0 and -O2, and `run/noalias.defines` pins its define lines.
  - `noalias`: `add_twice(&var)`, `Tally.record(&var self)`, `Tally.mean(&self)`, `spread(&Tally)` and `Gauge`'s drop glue.
  - None: `bump(&Gauge)` (cell-carrying), `copied(Tally)`, `first(UnsafePointer)`, `apply(f:)` and the closure's environment.
- **The injection** (`run_lane.py check_noalias`): it copies `compiler/llvm/src`, replaces the funnel's cell test with `if false {` and builds a sawc2 from the copy. The golden must then fail at `bump(gauge: &noalias.Gauge)`. A `finally` removes the copy.
- **Golden diffs:** `hello.ll` and `runtime_dirent.ll` each change only three define lines, `string_bytes`, `string_length` and `String.len` (`&String`, which is cell-free), from `(ptr %p1)` to `(ptr noalias %p1)`.

**The spec** (the user's Q-noalias ruling, "codegen assumes it"). In Reference passing, one rule with two halves:
- while a `&var` borrow is live, nothing else reaches the place, whether a raw pointer that didn't come from the borrow or another name for the storage, an `unsafe static var` named directly included;
- while a `&` borrow of cell-free storage is live, nothing writes it by any path.

Address casts points back to it. docverify is green. Naming the static path is the lead's reading of the ruling's "only through it", not a widening of it.

**Consumer sweep (obligation 2).** It covers every static handed to a callee as a reference or a receiver, across `sawc/rt`, `std`, `compiler`, `blade`, `libs` and `devtools`: 773 statics, 571 of them outside fixtures.
- No production `unsafe static var` exists, and no static's address is taken as a raw pointer anywhere.
- Every production reference use is an `Atomic` receiver, which is cell-carrying, so none of them gets `noalias`. Checked in `sawc2 runtime --emit-ll` of `mem.saw`, `op_budget.saw` and `net_os.saw`.
- No hits; nothing filed.

**Measured** on the busy Studio, 7 interleaved rounds, twice, `build --emit-ll -O2` of the driver, by median: Stage 2 / Stage 1 goes from 1.17× to **0.94×**.
- `typecheck --check` is unchanged.
- 3,325 defines carry `noalias`.
- The bench kernels are unchanged.

**Lead's checks:**
- Rebased onto main after A1 (SL-552) merged; it rebased cleanly. `bodies.saw` was the overlap: A1 removed refusals there, and this patch adds one call.
- Read the funnel, the predicate and the spec text.

The agent's gate, `run.py` plus `battery.sh compiler citations docverify` under the suite lock, is green on the pre-rebase tree.

**For the Air's review, the one area the sweep didn't cover:** a `&var` parameter aliased by a raw pointer held ELSEWHERE, for example in the Saw-authored runtime, a scheduler or reactor structure reached through a stored pointer while a `&var` to the same storage is being passed. sawc2 builds that runtime (`sawc2 runtime`), so a violation there would now miscompile. The fixpoint and run lanes exercise it, but a targeted read of `sawc/rt`'s `&var` functions that also dereference stored pointers would make that coverage explicit. Please re-measure Stage 2 / Stage 1 on the Air, too.
