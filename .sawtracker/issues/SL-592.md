**Found by SL-591's profile (Air): the whole Stage 2 / Stage 1 self-compile gap.**

**The mechanism.** sawc2's LLVM backend emits no `noalias` (zero in the driver's 28 MB `.ll`) and no TBAA. A store through any pointer may therefore alias any `&var` parameter's fields, and LLVM reloads them after every such store. Stage 0 marks exclusive-reference parameters `noalias`:

```
Stage 0: define internal %"Result$2$Void$AllocError" @"Vector$2$Int$GlobalAllocator_push"(%Vector* noalias %self, i64 %value)
sawc2:   define internal void @"saw std.vector.Vector.push(value: T) args Int std.alloc.GlobalAllocator"(ptr %ret, ptr %p1, i64 %p2)
```

In `Vector<Int>.push`, the hottest function of the self-compile (28 % of Stage 1's self time, 37 % of Stage 2's), Stage 2 reloads `self.length` after `buf[self.length] = move value` and repeats the overflow check. Stage 1 stores the `length + 1` it computed first.

**The measurement** (SL-591 c-report). The driver's `.ll` with ONLY `push`'s `%p1` marked `noalias`, against the same `.ll` unchanged, both built by clang -O2; `build --emit-ll -O2` of the driver, 10 interleaved runs, on the Air:
- Stage 1: median 4.261 s;
- Stage 2 baseline: 4.453 s (1.045× Stage 1);
- Stage 2 + `noalias` on `push`: **4.183 s (0.982×)**.

Output is byte-identical, and `push` is still out of line at all 821 call sites.

**Fix.** Emit `noalias` on every `&var` parameter, `&var self` included.
- **Why it's sound:** the Law of Exclusivity guarantees nothing else reaches that storage during the call.
- **Shared `&` parameters:** `noalias` there is only sound when the pointee has no interior mutability (`UnsafeMutableInterior`, `Atomic`, the cells). Either leave `&` alone or gate it on that. Raw pointers get nothing.
- **For the spec:** like Rust's `&mut`, this makes it undefined for unsafe code to reach a `&var`-borrowed value through a raw pointer obtained before the borrow. The spec should say so where it describes `&var` and unsafe code. That's a ruling for the user if it isn't already implied.

**Done when:**
- `&var` parameters carry `noalias` in sawc2's `.ll`, with a golden pin;
- an injection or verifier check that no `noalias` lands on a `&` parameter of an interior-mutable type;
- the fixpoint lane and the run lane agree;
- the self-compile `build --emit-ll -O2` Stage 2 ≤ Stage 1 on the Air (`selfjob.py`, best of 5).

**Ruled by the user (Oct 12): Q-noalias, "No; codegen assumes it".** See SL:open-questions, "Q-noalias" under Resolved. While a `&var` borrow is live, unsafe code may not reach the place through a raw pointer that didn't come from the borrow. The scope of this issue:
- `noalias` on every `&var` parameter, `&var self` included;
- on `&` only where the pointee is not cell-carrying (the spec already forbids it on cell-carrying storage);
- nothing on raw pointers;
- the spec sentence, in Reference passing and the unsafe section (`docverify`);
- the Air's done-when list.

Route every `noalias` decision through one funnel that names its entry points, and pin the cell-carrying exemption with an injection.

**Lead decision (reversible): sawc2 gains one cell-carrying predicate.** The noalias agent found that sawc2 has no cell-carrying predicate. `Sync` can't stand in for one: `Atomic`, `SpinLock`, `Mutex` and a struct holding `Atomic` are all cell-carrying AND `Sync`, so gating on `Sync` would mark exactly the receivers the spec exempts. The only existing predicate is Stage 0's Python `struct_is_cell_carrying`.

The fix: one public `TcProgram.is_cell_carrying(t, depth)` in `compiler/typecheck/src/tier.saw`, shaped like `is_no_move`.
- It recurses through tuples, arrays, Optional payloads, and each nominal's substituted fields and case payloads.
- It answers true at `known.interior`.
- It stops at raw pointers, because only inline storage matters to `noalias`.

It gets its own pins: `Atomic`; a `Sync` struct holding `Atomic`; a generic wrapper at a cell argument and at a non-cell argument; an Optional of a cell; and a struct holding only a raw pointer to a cell (false). The issue's scope otherwise stays as ruled in c2, with the `&` half included rather than deferred.
