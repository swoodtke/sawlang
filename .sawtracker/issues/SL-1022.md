Found by the SL-1021 spec review (F11), and reproduced by the lead.

LANGUAGE_SPEC states the rule twice:
- "Subscripts: getitem, setitem and the place": "A subscript head, scrutinee or projection base takes its plain role when one exists, a declared getitem or the getitem derived for a Copy-tier element … So `match v[i] { … }` over a Copy element matches a copy";
- "Value reads": "A `match` on a subscript of a Copy-tier element matches a copy, by the subscript's plain role."

Probe `/Users/shawn/Projects/sawlang/.build/scratch/p1000g/V7_match_copy.saw`:
```saw
enum Mode { case A, case B(n: Int) }
func main() {
    var v = Vector<Mode>()
    try! v.push(Mode.B(n: 3))
    match v[0] { case A -> { print("a") }, case B(var n) -> { n += 1; print(n) } }
    match v[0] { case B(n) -> { print(n) }, case A -> { } }
}
```
It prints `4` then `4`. The first match's `var n` is the vector's element, not a copy, so a local mutation silently writes the container.

Sweep (obligation 4): every scrutinee and head position over a subscript of a Copy element, and the projection base `v[i].n`, for Vector, Map, a fixed array and a user getitem.
