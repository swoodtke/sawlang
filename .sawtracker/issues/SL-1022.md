Found by the SL-1021 spec review (F11), and reproduced by the lead.

LANGUAGE_SPEC states the rule twice:
- "Subscripts: getitem, setitem and the place": "A subscript head, scrutinee or projection base takes its plain role when one exists, a declared getitem or the getitem derived for a Copy-tier element … So `match v[i] { … }` over a Copy element matches a copy";
- "Value reads": "A `match` on a subscript of a Copy-tier element matches a copy, by the subscript's plain role."

Probe `/Users/shawn/Projects/sawlang/.build/scratch/p1000g/V7_match_copy.saw`:
```saw
enum Mode { case A, case B(n: Int) }
func main() {
    var v = Vector<Mode>()
    try! v.push(Mode.B(n: 3))
    match v[0] { case A -> { print("a") }, case B(var n) -> { n += 1; print(n) } }
    match v[0] { case B(n) -> { print(n) }, case A -> { } }
}
```
It prints `4` then `4`. The first match's `var n` is the vector's element, not a copy, so a local mutation silently writes the container.

Sweep (obligation 4): every scrutinee and head position over a subscript of a Copy element, and the projection base `v[i].n`, for Vector, Map, a fixed array and a user getitem.

<!-- sawtracker:comment {"author":"agent:claude-sawlang","body_bytes":1037,"created":"1794252426","id":"c2"} -->
**Ruled by the user (Nov 9): sawc's behaviour is right, and the spec changes.** A `match` on a subscript lends the element like every other binding head (`if var`, `borrow var`, `for`). `case B(var n) -> n += 1` writes the element, which the `var` makes visible.

Why: the Copy-tier carve-out made the same code mean different things by the element's copy tier, which a field change can flip silently. It was also inconsistent with the other binding heads. A local copy is spelled `let m = v[0]; match m`.

The fix, spec only, since sawc already behaves this way:
- delete the scrutinee clause of the "takes its plain role" bullet (`match v[i] { … }` over a Copy element matches a copy);
- delete the last sentence of the "Value reads" paragraph;
- drop the SL-1022 pending notes chunk 5 added;
- add one sentence that a `match` on a subscript lends the element as the other binding heads do;
- align SL:borrowing's matching sentence (the Map `find` passage: "for a Copy slot it matches a copy").

Field reads (`v[i].n`) are unchanged.
