## Description

**One `Channel.receive()`, lowered by context; `recv` is removed** (the user, Oct 19: "yes, file that and queue it in the next agent slot").

**Why.** After SL-777 the two methods have the same signature (`(&self) -> Result<T, ChannelError>`), and only their spelling tells them apart. `recv` blocks the OS thread, so calling it from a cooperative task stalls the executor's thread and every sibling task on it, the sender included, and nothing in the type system prevents it (the spec's NAMING note; `recv`'s docstring). `recv` is also an abbreviation, which the API doctrine forbids. A rename would only label the hazard; unifying removes it.

**The model: the one `blocking` externs already have** (spec, "What the offload does"). Mono keys a thread-context copy of everything a `Thread.spawn` body reaches (`MONO_KEY_THREAD`, SL-765 T3b), so every specialization knows statically which context it is in.

| context | `receive()` |
|---|---|
| a cooperative body (task, `Task.spawn`, a suspending `main`) | parks on the channel and suspends, as today; `Cancelled` applies |
| a `Thread.spawn` body (the thread copy) | blocks the thread on the gate's condition variable, as `recv` does today; `Alloc`/`System` from the gate apply, and `Cancelled` never occurs |
| a plain `sync` function | REFUSED, exactly like a `blocking` extern (it could be called from a task and stall the executor) |
| through `&any Trait` or a function value inside a thread body | refused, as a `blocking` extern is today (SL-776's g3/g7 rows) |

**The mechanism (design, at the brief):** std needs one method with two context-dependent bodies. Today only externs get that, from the compiler. **The lead's default: a std-internal intrinsic** (`public(package)`, the `__saw_` family) that mono folds to a constant per specialization: true in a thread copy, false otherwise. The thread copy then keeps only the condition-variable branch, the cooperative copy only the park, and the dead branch's suspension never reaches the thread copy. **Open for the user:** whether user code may branch on the context too (a public `in_thread_context()`-style surface). The default is NO, std only, because it's reversible. Alternatives the brief weighs: the compiler treats `receive` as a known intrinsic call (no std branch), or std declares the thread body as an extern-like `blocking` twin the compiler substitutes.

**Depends on SL-776:** its thread-context key funnel keys a thread copy from the resolved instance's causes. That's the same decision this folds on, so this unit lands after SL-776's patch.

**Scope:**
- `std/channel.saw`: one `receive()`, with `recv` deleted, and the docstring rewritten for both contexts.
- The compiler: the intrinsic's typecheck, its fold in mono's thread keying, and the `sync` refusal through the same rule as `blocking` externs (one funnel; obligation 1: name its entry points).
- The spec (Channels, the NAMING note, the `Thread.spawn` example, the effect rules where `blocking` is listed), README and the skill.
- **Consumer sweep (obligation 2):** every `recv()` (SL-777's six sites, and `git grep` again), now `receive()`. Stage 0's frozen std has no thread-context `receive`, so its rows become `stage0-wrong`, annotated.
- The Air's SL-777 nit: `thread_recv_gate_allocation_refused`'s 50 ms closer can race the final receive, leaving "the retry made its gate" unchecked. Pin the retry deterministically.

**Pins:**
- one helper function calling `receive()`, called from a `Thread.spawn` body (blocks; drains until `Closed`) and from a task (suspends; a sibling task keeps running while it waits);
- `receive()` in a plain `sync` function is refused;
- `receive()` through `&any` in a thread body is refused;
- the gate refusals (`Alloc`) on the thread path.

**Air on c7: two invariants for the brief, from the executor code `Thread.join()`'s parking body will sit in** (`std/taskgroup.saw` on main 73584cbee):

1. **The thread's exit must publish the join word BEFORE `__saw_exec_thread_finished` lowers `LIVE_THREADS`.** The deadlock walk's first rule (`quiescent_now`) is that a running `Thread.spawn` body ends the walk, "read before any readiness word: a body that sends and then exits lowers the count after its send, so a walk that reads the count as zero sees the word set". A join park depends on the same order. If the decrement came first, a walk could read the count as 0 while the join word is still clear, and classify the joiner as waiting for good.
   - The double look a nap apart (`check_quiescent`) makes a false report unlikely, but the comment states an order, and the join should keep it.
   - The poke after the decrement (`poke_reactor`, seq_cst against `idle`'s `REACTOR` store) then wakes an executor blocked in the poll.
2. **The join park needs a place in `idle`, `waits_on` and the walk.**

   - If it reads as a channel park, the deadlock message ("every task is waiting to receive from a channel") must never fire with a join park among the waiters. Under invariant 1 it can't: the thread is either live (`LIVE_THREADS > 0`) or has set the word.
   - That reasoning belongs in the brief, with a pin that runs a join whose thread exits while the joiner is parked, repeated many times per level.

**The user ruled (Oct 19): the lead's points 1–4 (c9) are confirmed, and so are the lead's recommendations on visibility:** "i agree with your recommendations."

**SL-782's ruled design:**
1. **`blocking`** in the post-parameter effect slot of a Saw function marks a body that blocks its OS thread in a way the compiler can't offload: a condition-variable wait, `pthread_join`, a polling sleep.
2. **A lone `blocking` function** may be called only in THREAD CONTEXT: a `Thread.spawn` body, or a `main` that runs no executor, and whatever either reaches. A task, or a `main` that runs the executor, is not thread context.
3. **A pair** is a default declaration plus a `blocking` declaration with an IDENTICAL signature: name, labels, parameter and return types, receiver, generic parameters and bounds, visibility, and `unsafe`. Both are in one module, with one `///` doc on the default, and `--emit-docs` shows one entry. The compiler picks the body per copy: the `blocking` body in thread context, the default elsewhere. A mismatched twin is refused at its declaration.
4. **Inference:** callers do NOT write `blocking`. Their summaries carry "blocks the thread", and the refusal fires at the TASK ROOT that reaches it, with the chain (`task spawned here → load_config → File.read (blocking)`), never at the call in an ordinary function (c5, reading (ii)).
5. **The public boundary:** a PUBLIC function whose body blocks (by inference) must declare `blocking`; otherwise it's an error with a fix-it. Private and module-level helpers are inferred. The signature and `--emit-docs` are what a caller in another module sees.
6. **No call-site marker. No escape hatch** for blocking from a task (one can be added later without breaking anything if a use case appears; `recv` and `join` from a task can deadlock).
7. **Open to user code from the start.**
8. **`Thread.join()` becomes a pair in the same unit** (c7, with the Air's c8 invariants). `Channel.receive` is the first pair, and `recv` is removed.

**Unit 1a's design (agent p782, step 1) and the lead's rulings on its OPEN rows** (reversible; the principle is to start strict, since loosening later breaks nothing). The spec and GRAMMAR draft is WIP b47f33acb in `.claude/worktrees/p782`, rebased on main after SL-776.

- **Refused:** a trait requirement or default body; a conformance implementation that blocks (a pair's default may meet a requirement), so a call through a bound or `any` never blocks; `deinit` and `copy()`; closures (the `Thread.spawn` brace excepted); a `blocking` function type (a pair taken as a value is its default).

**Findings for the user and for 1b:**
1. An extern's `blocking` means "offload me from a task", while a Saw function's means "never call me from a task". Both block the thread; only the extern can be offloaded. The prefix and postfix spellings stay as they are.
