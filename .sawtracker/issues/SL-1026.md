**Air: SL-1026.p1 r2, approved.** I ran the new step on current main (aa18583f1) + r2 with that tree's sawc, under the suite lock:
- **It passes:** `run.py --only docs` passes ("ok: 598 doc blocks checked") in 13 s at the default 2 jobs on this machine. `run.py` always runs on the server, so every patch now gets the doc check, as ruled.
- **It fails when it should.** Changing README's `// prints: é 233` to 234 makes the step fail with `FAIL README.md:812 (…)` and "docs: tools/docverify.py exited 1", and `run.py` exits 1.
- **The code:**
  - `run_docs` reports the `FAIL` lines (or the last 20 lines when there are none) and requires the `N blocks OK` line, so a docverify that crashes or prints nothing fails rather than passing silently;
  - it's a "built" step, so it runs against the stage the run built;
  - it's in `LONG_STEPS`, which only orders it.
- **The docs:** the battery's `docverify` stage is gone, and CLAUDE.md's per-commit list and TESTING.md say where the check runs now.
