Requested changes on patch SL-1029.p1 (revision 2) (its test run was cancelled)

**Air: SL-1029.p1 (rev 2), changes requested: one marker, which the grammar contradicts.** I built sawc from 07168858c + p1 and probed each claim the patch adds.

**1. The SL-457 marker (~8763-8767) attributes the const generic argument to a sawc lag, but the grammar excludes it.** The sentence now reads "a bit position or a mask is an array length, a repeat count, a const generic argument or a `static_assert` operand (an array length, a repeat count and a const generic argument are not built in `sawc` yet, SL-457)". GRAMMAR.md §5.2 takes a smaller grammar in a generic list, with no bitwise operators even inside parentheses: "The bitwise operators are excluded because `<` and `>` delimit the list". So no evaluator work makes `width<(1 << 2)>(0)` legal. sawc refuses it at the parser (`syntax.expr.refused-compare-chain`), and the type-position `Ring<(1 << 2)>` gets `parse-error`. Through a NAME it works today: `static W: Int = 1 << 2` then `width<W>(0)` builds and prints 4. Suggested text: "…so a bit position or a mask is an array length, a repeat count or a `static_assert` operand, and a const generic argument through a named constant, since a generic list takes no bitwise operator (the six don't fold in an array length or a repeat count in `sawc` yet, SL-457)."

The marker's wording also reads as if array lengths and repeat counts weren't built at all: `[Int; BIT + 5]` / `[0; BIT + 5]` build and print 8. Only the bit operators fail there (`syntax.expr.shift` is not in the bootstrap slice, for `[Int; 1 << BIT]` and `[0; 1 << 3]`). The suggested text fixes both.

**Probed and right:**
- `Int.from(h)` with `h: Int8` builds and prints `-5` through `!`.
- **The merged-type list:**
  - Int8 and Int16 arms at `-> Int16` are refused with "only a lossless widening into or out of `Int` or `UInt` is implicit", which matches the new text;
  - Int8 and UInt32 arms into `Int` merge (`-3 7 -9`);
  - an `Int` arm beside an `Int64` arm at `-> Int64` merges.
- **SL-1030:** `a[5]` on `[Int; 3]` compiles and panics at run time ("index out of range: 5 (len 3)").
- **SL-1031:** `UInt.max.compare(&1)` is refused: expected `&UInt`, found `&Int`.
- **The dropped DF-259c workaround:** `try! jobs.map { j in j.label() }` and `try! jobs.map<String> { … }` both build and run.
- **The closure-suspends ```text block** (not docs-checked) matches sawc's message word for word.
- **`static_assert`:** shl, and-not, or, xor and shr all fold there (control).

Nit: the reflow at ~8488-8490 leaves a short line ("above. Each arm extends into it by its").
