Found through SL-865 U5's corpus moves (p865); reproduced by the lead on main.

**An undefined name called with explicit generic arguments crashes typecheck.** After the correct `name.undefined`, sawc reports `INVARIANT … an expression has no type` instead of recovering:

    import std.nosuchmodule.{Thing}
    func main() { var t = Thing<8>() … }
    → ERROR import.unknown-module …
      ERROR name.undefined … cannot find `Thing` in scope
      INVARIANT probe_undefined_invariant 4:19 an expression has no type

Without the generic arguments (`Thing(size: 4)`) there is no INVARIANT. Repro: `.build/scratch/probe_undefined_invariant.saw`.

**Corpus:** this is the `crash INVARIANT` family in corpus_diff.tsv: `fixed_string_builder`, `fixed_string_builder_too_small_error`, `byte_data_reads`, `byte_append_discrimination`, `const_static_generic_arg`, and with U5, `fixedbuf_set_oob_panic` and `fixedbuf_get_out_of_range_none` (all importing the not-yet-ported `std.fixedbuf`, SL-596).

**Mechanism (obligation 4, UNVERIFIED):** the call-head path with explicit type arguments (`explicit_type_args`, the SL-915/SL-920 bypass) leaves the expression untyped when the head fails to resolve, where the other paths give it the error type. Sweep: every expression form whose head can fail to resolve (a generic call head, a qualified head, a method with explicit arguments, a static member) should leave the error type, never no type. SL-920's classifier work touches this path, so it may close there; check at its landing.

**Implementation detail (lead, Nov 12): an explicit generic argument that is an expression gets a type even when its call head does not resolve. One unit with SL-1043, which is the same mechanism.**

**Probed on main today** (`.build/scratch/qinv_a.saw`):

```saw
func main() {
    var t = Thing<8>()             // name.undefined, then INVARIANT 2:19 "an expression has no type"
    var u = Other<Int>.make()      // name.undefined only
    let w = nothere.Thing<Int>()   // name.undefined only
}
```

The INVARIANT's position, 2:19, is the `8`: a CONSTANT generic argument, which is an expression node. A type argument (`<Int>`) leaves nothing untyped. SL-1043's `FixedBuf<4>()` with no import is the same node kind under a head refused as `name.not-in-prelude`.

**Mechanism (UNVERIFIED until the dump confirms it):** `compiler/typecheck/src/bodies.saw`, `call_expr` calls `explicit_type_args(callee)` first ("the types its head writes are the body's whichever way the call is resolved or refused, so every one is built here, once"), then returns the error type when resolve gave the call no class (`res_call_at[e] < 0`). `explicit_type_args` builds the written TYPES; a const argument's expression is typed only on the paths that know the parameter it fills, which an unresolved head never reaches. The body verifier (`bodyverify.saw`) then finds an expression with no type.

**The change.** In `explicit_type_args` (or the one helper it uses for a const argument): when the head has no declaration to say what the argument fills, type each expression argument on its own, with no expectation (`self.expr(arg, TC_WANT_NONE)`), so it and everything under it carries a type, an error type included. Do not add a second refusal: the head's `name.undefined` (or `name.not-in-prelude`) is the diagnosis. Confirm first with `sawc typecheck --dump` that the untyped node is the const argument; if it is another node, STOP and report the dump.

**Sweep (obligation 4): every way an unresolved head can leave an expression untyped.** A census in the evidence directory, one file per cell, each run through `sawc typecheck --check`; a cell passes when it prints its refusal and NO `INVARIANT` line:

| head | argument forms |
|---|---|
| an undefined name called, `Thing<A>()` | A = `8`; `N + 1`; a `static`'s name; `sizeof<Int>()`; a type |
| an undefined name constructed with labels, `Thing<8>(size: 4)` | the same |
| a static call on an undefined generic type, `Thing<8>.make()` | the same |
| an import-required std name with no import, `FixedBuf<4>()`, `FixedStringBuilder<16>()` | as written |
| a module qualifier that does not exist, `nothere.Thing<8>()` | `8` |
| a method with explicit arguments on an undefined receiver, `x.get<8>()` | `8` |
| a method that does not exist on a defined receiver, `v.nothing<8>()` | `8` |
| an annotation, `let t: Thing<8> = …`, and a parameter type `Thing<8>` | `8` |
| a call argument holding a closure, `Thing<8>({ x in x + 1 })` | the closure's body nodes |

Fix every cell that prints an INVARIANT through the same helper where the mechanism is the same; a cell with a DIFFERENT untyped node is reported, with its dump, not fixed.

**Corpus:** the `crash INVARIANT` rows SL-923 lists imported `std.fixedbuf`, which has since been ported, so they may already pass. Check `corpus_diff.tsv` for `crash` rows before and after; list each.

**Pins.** `compiler/tests/typecheck/refuse/name.undefined.generic-const-argument.saw` and `name.not-in-prelude.generic-const-argument.saw` (the lane fails a fixture that prints an INVARIANT); the census table goes in the report.

**Expected outcomes.** No golden moves. No bucket of `corpus_diff.tsv` moves except a `crash` row to `refused` or `pass`.

**Gate (agent, under the suite lock).** `compiler/tests/run.py --only seed,units,golden,subset,fixture_whitespace,std,typechecker,programs,comments,census`, `tools/battery.sh citations`; `corpusdiff.py run --baseline --jobs 12` only if a row moved.
