## Description

Found by the independent review of SL-350.p1 (SL-350's review comment, P2-2; Sep 23). `var chunk: [Int8; 70_000] = [0; 70_000]` — sync, or held across a `yield_now()` — asserts `NumValues wasn't wide enough for its operands!` in LLVM on main AND on SL-350: the constant array is stored as one SSA aggregate value. SL-350's R1 quantified over STRUCT literals and its array path declines REPEAT literals by design (`_materialize_array_literal_into` returns False for `repeat_count`; `_generate_repeat_array` short-circuits a zero seed to `ir.Constant(array, None)`), so the frame-tree COMPOSITION is closed (the 65536-pointer pin passes) while a single oversized constant array is a separate trigger. FIX SHAPE: route a constant repeat/fixed-array literal at a known memory destination through the same GEP-store/memset path the splat-loop case already uses (a zero seed IS a memset). Pin: the 70,000-byte repeat at a let, at a frame slot across a suspension, and as an `Optional` slot's payload (the `Command.output` 1025-leaf wrapper shape). Also the `Int??` parameter of a suspending function, which ICEs on both compilers (`Type of #1 arg mismatch: {i1, {i1, i64}} != {i1, i64}`), is a separate pre-existing finding — filed as its own issue.
