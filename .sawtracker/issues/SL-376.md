## Description

Found by the SL-355 implementer (Sep 23). SL-355's R6 made `__saw_rt_reactor_register` report a failed arm (errno, then a panic naming the fd), which covers the io-park arms. Two other kevent calls in `rt/host_macos/reactor.saw` still discard their return:
- arming the reactor's own wake event at create;
- triggering it.

A failure in either leaves the reactor unable to be woken, with no report. That breaks the never-hide-errors rule, and it is the same failure signature SL-354 fixed for registration. Check the epoll twin (eventfd write, epoll_ctl at create) in host_linux too. Fix direction: create returns a status the executor turns into a panic, as R6 does.
