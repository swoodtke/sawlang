**Found by:** the lead's first performance comparison, Oct 11: sawc2 at -O2 against Stage 0. The benchmark is `.build/scratch/bench/compute2.saw` (main checkout), four kernels inside sawc2's current slice. **Area:** the LLVM backend's check and panic lowering (`compiler/llvm`), and the accessor prologue's shape.

**Measurement** (best of 5 after a warm-up, Apple Silicon, the same checksums from every binary):

| kernel | Stage 0 | sawc2 -O2 |
|---|---|---|
| empty `main` (startup) | 0.0017s | 0.0018s |
| sieve to 2M (`Vector<Bool>` set and read) | 0.0067s | 0.0103s |
| insertion sort, 20k `Int` | 0.0277s | **0.2848s** |
| Collatz lengths to 300k (pure arithmetic) | 0.0398s | 0.0398s |
| push 1M, then fold | 0.0059s | 0.0057s |
| all four in one program | 0.0738s | 0.3363s |

Compile time: Stage 0 2.25s; sawc2 0.20s (-O2, clang included) and 0.31s (-O0). sawc2's -O0 binary runs in 1.44s.

**Mechanism:** after `clang -O2`, `saw prologue std.vector.Vector.[]` and `Vector.set` stay out-of-line calls in the sort's inner loop (`while k >= 0 && v[k] > key { v.set(k + 1, v[k]) … }`), and each access carries 24-byte `memcpy`s of the Vector header. The prologue isn't inlined because of its size, not because of any attribute (no `noinline` or `optnone` appears). Each bounds check's failure path is emitted INLINE, with two `alloca [512 x i8]` message buffers and the `__saw_append*` formatting. So every checked function carries its panic formatting on the hot side of the branch, in the same frame.

**Fix (perf by measurement; this is the measurement):**
- outline each check's failure path into a cold, `noinline` per-site or shared helper, with the message buffer in that helper's frame, so the checked function keeps a compare and branch;
- mark the failing branch cold (`!prof` weights or a `cold` callee);
- find out why the receiver's header is `memcpy`'d per access and remove it if it's a by-value copy.

**Done when:** the sort kernel is within 1.5× of Stage 0, with the sieve and the others unchanged or better, and a size note (the `.ll` and object for `compiler/` should shrink). Add the benchmark as a `devtools/bench` program, or as a run-lane timing report that gates nothing, so this is measured again later.

**Not on the self-hosting critical path** (correctness first), but sawc2 compiling itself will be the next big consumer: `compiler/` is index-heavy. Do it after U7b's M1, in `compiler/llvm`, which u7b2 owns until then.
