## Description

**Five small things two reviews left behind (SL-1085.p1 and SL-1079.p1, the Air, Nov 12 and 13). None blocks anything; each is a few lines.**

1. **An up-to-date image doesn't notice a changed tool.** After a Blade build of an `[sos]` package, the same package with `SOS_CLANG` naming no program prints `Finished ... (up to date)`. The image's stamp never held the C compiler or the linker. It should hold what was used (the variable's value or the recorded path), so a changed tool rebuilds. `blade/src/builder.saw`, where the stamp is computed; a test in `blade/tests/`.
2. **`check_blade_finds_tools` (`tools/blade_lane.py`) fails on a machine that has a riscv32 record but no `ld.lld` beside that clang or on `PATH`.** It skips only for a missing record. Skip, saying so, when no linker can be found by the route Blade itself uses.
3. **`sawc tools --target T` and `sawc build --freestanding --target T` disagree for a Linux triple with no record:** `tools` refuses ("no runtime for it is configured"), while the freestanding build compiles with the host's clang. Both follow the records as written. Decide which is right (a freestanding object needs no runtime, so `tools` should probably answer with the clang the build would use) and make the two agree through one function.
4. **`hand_on.check`'s second case loops forever if `write_all`'s `if not took: raise` is removed** (`compiler/tests/hand_on.py`): `view[None:]` is the whole view again. Give `_Sipping(0)` a limit on writes so the check fails in place of hanging.
5. **When `check_split_object` (or `check_sawc_tools`) fails before the part it leaves out under a twin, `check_twin_table` adds a second line** ("N checks were left ... names M") beside the real failure. Either say so in that message ("or a check failed before its left-out part"), or have such a check count its row on entry.

**Gate.** `tools/blade_lane.py`, `compiler/tests/run.py --only seed,programs,fixture_whitespace,comments` and its `parallel` step, `tools/battery.sh citations patchgate`.
