**Dogfood SL-1170's native inputs with a real C library: `libs/lz4`, then an mbedTLS TLS client example.** It follows SL-1170's design §8 ("Dogfood").

**1. `libs/lz4`** (this issue's first unit):
- **Vendored:** lz4, BSD-2: `lz4.c`, `lz4.h` and its LICENSE, pinned to one release with its SHA recorded. Since 1.9.4 it has an `LZ4_FREESTANDING` mode.
- **A safe Saw API:**
  - `compress(&Data) -> Result<Data, Lz4Error>` and `decompress(&Data, max: Int) -> Result<Data, Lz4Error>`;
  - the buffers cross as `UnsafePointer` inside small `unsafe` helpers;
  - every lz4 error code becomes a case, never hidden.
- **Tests:** `blade test` round-trips empty input, small input, incompressible input, a large buffer, and a corrupt stream (refused).
- **Freestanding:** an image build with `[native.riscv32-unknown-none-elf] defines = ["LZ4_FREESTANDING=1"]` proves the cross-compile. A freestanding case round-trip is a stretch goal.
- **The point:** the point is what the package exposes about Blade and sawc. Every surprise is recorded.

**2. The mbedTLS TLS client:** a later unit, sketched in the design.

**Lead's note with p1 (Nov 25): unit 1, `libs/lz4`.** The surprise log is at `.build/scratch/p1182/surprises.md`.

- **Vendored:** lz4 1.10.0 from `https://github.com/lz4/lz4/archive/refs/tags/v1.10.0.tar.gz`, SHA-256 `537512904744b35e232912055ccf8ec66d768639ff3abe5788d90d792ec5f48b`. `lz4.c`, `lz4.h` and the LICENSE are unmodified, and `vendor/README.md` records the per-file hashes.
- **`Saw.toml`:** `[native] c-sources` and `include-dirs`. `[native.riscv32-unknown-none-elf]` defines `LZ4_FREESTANDING=1`, `LZ4_memcpy`/`memmove`/`memset` as the `__builtin_` names (Blade refuses function-like defines, so these are object-like aliases), and `LZ4_STATIC_LINKING_ONLY_DISABLE_MEMORY_ALLOCATION`.
- **The API:**
  - `Lz4Error` has the cases `InputTooLarge(size:)`, `InvalidLimit(value:)`, `CompressFailed`, `Malformed(code:)` and `Alloc(e:)`. lz4 gives one negative code for corrupt data and for output that is too small, so those are one case.
  - The lead's fix: `decompress` reported an input past `Int32.max` as `Malformed(code: -1)`, a made-up code that could collide with lz4's own. It is now `InputTooLarge(size:)`, and the doc says so.
- **The tests:** `round_trip` and `refusals` both pass (re-run by the lead after the fix).
- **The lane:**
  - `lz4` is in `LIBRARIES`;
  - `check_lz4_image` builds `libs/lz4/image` for riscv32 and boots it under `qemu-system-riscv32`, requiring `fs check lz4_shrinks/lz4_length/lz4_bytes=1` and `fs done lz4_image ok`;
  - it skips, saying so, when the target record or QEMU is absent;
  - the whole `tools/blade_lane.py` passes.
- **Filed from the surprise log:**
  - `blade test` hides a test's compile errors;
  - `Data`'s spare-room API is package-private, which costs one copy per call;
  - there is no runtime-provider package outside `tests/freestanding/` (the image fixture reaches into that tree).

  The log's other items are by design (function-like defines, the safe-over-`unsafe` layering) or the agent's own slips.
