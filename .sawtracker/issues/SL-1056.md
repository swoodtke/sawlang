**The std members v0.18.0 had that the new std lacks, where no other issue covers them** (user, Nov 10: "let's fix up all these gaps"). Found by a public-name diff of v0.18.0's `sawc/std/` against `std/` (`.build/scratch/probe_std_member_diff.py`).

Covered elsewhere, not here: `std.fixedbuf` (SL-596), `Data.iter`/`DataIterator` (SL-1009), `std.compiler.frame` (retired, SL-1047).

Already accounted for, not gaps:
- renames: `Channel.recv` → `receive`, `Path.as_str` → `as_string`, `Path.ext` → `file_extension`;
- moves or redesigns: `Thread`/`VoidThread` → `std.thread` and `Thread<Void>`; `VoidTask` → `Task<Void>`; `Directory.current`/`set_current` → `Env.cwd`/`set_cwd`; `ProcessError` → `SystemError`;
- dropped on purpose: `Vector.with_ref`/`with_var_ref` (SL-596's plan); the `__`-prefixed executor internals.

**The names to classify and port:**
- `Arc.with_unique`
- `String.fromBytes`, `String.withCString`, `String.to_data`, `Vector.join` (string.saw's extension)
- `StringBuilder.as_str`, `StringBuilder.rebind`
- `Float.to_string`, `String.to_float`, `StringBuilder.append` for a `Float` (float.saw's extensions)
- `Command.arg_count`, `Command.env_count`, `Command.run`
- `Env.arg`, `Env.argc`
- `JsonDecoder.offset`, `JsonEncoder.len`
- `IoError.from_errno`

**The rule per name:**
1. **Already present** under another name, or in another module (check the whole of `std/`, including extensions): record where, and close it out.
2. **The spec documents it, or a program in `tests/corpus/`, `blade/` or `libs/` uses it:** port it under the current API rules (design 234's fallible allocation, `SystemError`, no abbreviations, so `fromBytes` becomes `from_bytes` and `withCString` becomes `with_c_string`). Corpus programs that used the old spelling are re-spelled.
3. **Neither:** a deliberate drop or an internal. Record it with the reason, and don't port it.

Each ported member gets a `///` doc and a pin. A member blocked by a compiler refusal is left out, named with the refusal verbatim, and filed.

No port needed: every name is already present under another name, or a deliberate drop (classification with evidence: .build/scratch/p1056/classification.txt). Present: Arc.with_unique → Arc.unique; String.fromBytes → Data.to_string; String.withCString → String.c_string; String.to_data (std.data); Vector<String>.join; Float.to_string (Printable); String.to_float; StringBuilder.append(Float); Command.run → wait; Env.arg/argc → Env.argument/argument_count; JsonDecoder.offset (the Decoder requirement). Dropped: StringBuilder.as_str (an alias of build), StringBuilder.rebind (an unsafe internal), Command.arg_count/env_count, JsonEncoder.len, IoError.from_errno (no callers; IoError.of replaces it). Left over: corpus programs still spelled with v0.18.0 names (fromBytes, withCString, Env.arg) refuse today, and the spec still lists String.fromBytes as a String producer.
