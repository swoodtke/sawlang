**From the Air's review of SL-456.p3 (U5b3).** These are three small follow-ups in the new std. The first is a correctness fix ahead of any second writer.

1. **`Data.spare()` checks sole ownership with a relaxed load, then hands out a pointer for writing.** Another thread's reads of the bytes, made before it released its copy, must happen-before our writes, which is why Rust's `Arc::get_mut` uses an acquire load for this check. The fix is `__saw_atomic_fence_acquire()` once the `== 1` test passes, the fence `deinit` already uses. Nothing is exposed today, since the only caller writes into a block `reserved` just made, but `spare()` is the uniqueness gate every future writer goes through. Add a std-lane pin, or at least a test, that names the ordering.
2. **Idiom: `std/systemerror.saw`'s `TAG_*` statics, mapped by an `if` chain, are a parallel static family.** A raw-backed enum with `from(raw:)` states the set once, and `std/file.saw` already uses raw-backed enums (`OpenMode`, `SeekOrigin`). The values themselves are right, matching all 21 tags in `sawc/rt/ABI.md`.
3. **Doc: `File.read` says it reads "from the current position to its end".** It reads up to the length lseek(2) reported when the read began, so a file that grows meanwhile is cut at that length. Add the clause, and say that a pipe or FIFO is `Err` (lseek).
