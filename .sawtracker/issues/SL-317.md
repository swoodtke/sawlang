## Description

Documented bound in sawc/coro_transform.py (~:474-500): `_split_for` can only state-split a RANGE for; a suspension anywhere inside a collection for (`for x in v.iter()` / `for key in keys.iter()`) — and anything nested in it — is a clean rejection ('use a while loop'), and such a loop is also left unpreempted by the op-budget instrumentation. Live consumer: sawtracker src/store.saw:285 open_store — `for key in pending.iter() { ... enqueue_tests(&var st, &var doc) ... }` where enqueue_tests suspends; reached only now because SL-280 stopped silently declining the imported edges that hid it (pre-280 IR had no frame for it: SL-287's silent-drop class). It is the SECOND thing the peer's build stops at, behind SL-215 (inline-catch), and the user ruled (Sep 18, on SL-306) to FIX the language limits rather than ask for a source refactor.

Fix shape: state-split the iterator for the same way the range for is split — the iterator value (`v.iter()`'s `Iterator<T>`) becomes frame state across the suspension, the loop head re-enters through `next()`; obligation 1: one split funnel for both for shapes with named entries; obligation 2: consumer sweep of everything that assumes a collection for is never split (the op-budget instrumentation's skip at :494, `_split_for` itself, the loop-control break/continue-with-value lowering, the SL-222 discarded-body rule). Matrix: {Vector.iter, Map keys/values, Set, a user Iterator} x {suspension in the body, in the head expression} x {driven root, spawned, nested in while/for}. Sequenced with SL-215 (same file); acceptance includes a read-only build of /Users/shawn/Projects/sawtracker/src/main.saw.
