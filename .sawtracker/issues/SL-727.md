**sawc2 builds a cast whose operand folds to a value the target cannot hold; the spec (design 170) and Stage 0 refuse it at compile time.** Found by p711scalar (SL-711): `tests/corpus/errors/cast170_const_out_of_range.saw` was refused by mono before SL-711 (an unsigned `format`), so its `EXPECT: error` was never reached; with SL-711 it builds and moves to `wrong / accepts a refusal test`.

```
$ .build/sawc2 build --std-root std tests/corpus/errors/cast170_const_out_of_range.saw -o x && ./x
panic at cast170_const_out_of_range.saw:21: cast to UInt8 out of range: 1000
```
Stage 0: `` `1000` is not representable as `UInt8`, so this cast would always panic ``, and the same for `(200 + 100) as UInt8`, `(0 - 1) as UInt` and `Wide.Big as UInt8` (a raw case value 1000).

**Spec.** LANGUAGE_SPEC, checked integer conversion (design 170): "A CONSTANT operand is answered at compile time: `0xFF as UInt8` is free, `1000 as UInt8` is a COMPILE ERROR (const arithmetic and a raw-backed enum's case value fold too)".

**Mechanism (UNVERIFIED, from reading the outcome only):** the `as` cast's typing in compiler/typecheck never asks the const evaluator whether the operand folds, so the runtime check (`fits`, compiler/llvm/src/ops.saw) is the only one. The sweep should cover each operand shape the spec names (a literal, const arithmetic, a raw case value, a static) and the partial `from` (whose folded `None` is not an error).

**Pins:** the corpus program refused with Stage 0's texts; its corpusdiff row moves to `pass`.
