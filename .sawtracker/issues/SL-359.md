## Description

Found by an SL-357 comment-review agent on Sep 23; I read the code on main fd2520e9.

`std/directory.saw`: `public static func current() unsafe -> Path?`
- panics with "Directory.current: allocation failed" when `malloc` refuses. That is not one of LANGUAGE_SPEC's five documented panic boundaries, and design 234 says every allocating std op returns `Result<_, AllocError>`.
- returns `None` for every `getcwd` failure (EACCES, ENOENT for a deleted cwd, the ceiling reached), so the cause is erased. That breaks the never-hide-errors doctrine.

Its sibling `set_current` already returns `Result<Void, IoError>` with the errno cause.

The retry loop cannot tell ERANGE apart from the other errors, because errno is not readable from std. The fix is a runtime seam (`__saw_rt_fs_getcwd` returning status-carrying results, following the os_ops.saw pattern) plus `current() -> Result<Path, IoError>`, with allocation refusal mapped into the error.

This is an API change, so it needs a ruling on the signature before dispatch. Consumer sweep: grep `Directory.current` across blade/, devtools/, libs/ and examples/.
