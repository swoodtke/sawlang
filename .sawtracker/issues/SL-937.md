## Description

**Found by:** p927, doing SL-927. **Area:** `compiler/typecheck/src/fold.saw` (the constant folder), `refuse_constant_cast`.

A Float to integer `as` whose operand is written as a constant and always panics (`1000.0 as UInt8`, `9223372036854775807.0 as Int64`, a constant NaN) builds and panics on its first run. The integer twin (`1000 as UInt8`) is a compile error, `constant.cast-range` (spec, Integer Conversions, "Constants"), because the folder sees through the constant. The folder holds no Float value (`fold_at` answers `NotConstant` for a Float literal, as the evaluator does for a static, SL-722), so the Float cast takes SL-927's run-time check, which is correct but later than the integer rule.

**Owed:** the folder holds a Float literal's value (typecheck's `tc_float_bits`), `fold_convert` answers a Float -> integer cast by SL-927's rule (truncate; out of range when NaN, an infinity, or the truncated value is outside the open interval (min - 1, max + 1), strict 2^63/2^64 tops at 64 bits), and an always-panicking constant cast is refused as `constant.cast-range` with the integer message's outs (`T.from(...)` for `None`; no `from(truncating:)` for a Float). `T.from(constant)` stays a run-time `None`, as for integers. The spec's Float conversions line citing this issue is rewritten then.

**Pins today:** `compiler/tests/run/probes/float_cast_panics_constant.saw` panics at run time for the constant; it flips to a typecheck refusal fixture when this lands.
