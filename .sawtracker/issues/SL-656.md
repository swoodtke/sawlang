**A function whose only suspension is a suspending default is never framed by coro, so `coro_check_summaries` reports an INVARIANT** (found by SL-638, d638default; its report on SL-638 has the full matrix).

**Mechanism:** under the spec's model (the lead's decision on SL-638: "A suspending default makes the callee suspending"), typecheck's summary of `f(n: Int = slow())` says `f` suspends. But `f`'s MIR body has no suspension, since the default is evaluated by the caller in its own default call, which SL-638 marks correctly. coro's `coro_solve_suspension` seeds only from MIR suspension points, so `f` is never marked suspending, and `coro_check_summaries` flags the disagreement: on `f` when the default is left out, and on the caller (`main`) when the argument is passed explicitly.

**Fix (d638default's proposal):** in `coro_solve_suspension`'s seeding loop, also mark an item suspending when its function has a default whose summary suspends at the item's instantiation (`tc.default_at` / `tc.defaults[..].summary`, from SL-638), with a cause the cause chain can name ("f's default value for `n` -> slow -> …"). `f` is then framed with no park point, as Stage 0 frames it (`FRAME f decision=framed`), and every check agrees.

**Pins:** SL-638's matrix rows that end in "INVARIANT (the coro change)" each pass: a suspending default left out and passed, a method and a generic default, and a spawn root's left-out suspending default. **Rescoped by the user's ruling, Oct 15:** "(b) is the correct answer - slow() is evaluated in the caller not the callee so the caller needs to be async, not the callee".

**The rule:** a default is evaluated at the call site, in the caller, once per call that leaves the argument out (the spec's "Per-call, at the call site"). So a suspending default's effect belongs to the call that fills it, never to the function:
- `f(n: Int = slow())` is an ordinary function. Its summary is its body's alone, and coro frames it only if its body suspends.
- `f()` suspends, in the caller. A `sync` context that writes it is refused (`effect.sync`), and anywhere else it runs (the user's earlier ruling).
- `f(n: 2)` doesn't suspend. A `sync` context may write it.

**So this issue is no longer the coro seeding change** (not needed). It is now:
1. **Typecheck:** a function's summary leaves out its defaults' effects. SL-638's per-default `TcDefault` summaries and the `call_effect` funnel already carry each default's effect to the call that fills it, so this removes the fold of the default into its function's unit summary. Check that a spawn or drive root's left-out default (SL-638's sibling fix) still counts in the spawning body.
2. **The spec:** "Effects flow through" becomes: a suspending default makes **the call that fills it** suspend, in the caller; a `sync` context that fills it is diagnosed; the function is unaffected, and an explicit argument suspends nothing.
3. **Pins:** SL-638's matrix rows that ended in an INVARIANT now run or are refused per the rule above, with no INVARIANT anywhere:
   - `f()` runs in a suspending context, and is refused in `sync`;
   - `f(n: 2)` is accepted in `sync`, a new refusal-turned-acceptance row;
   - `f` is not framed (coro golden or `--dump`);
   - the same for a method, a generic and a spawn root.
4. **SL:hazards (lead, at landing):** Stage 0 refuses every call that leaves out a suspending default, and also a `sync` caller that passes the argument explicitly. Both are loud.

**Files:** typecheck (`summaries.saw`, where the default's effect is folded into its function's), the spec, and the tests. coro is no longer touched.

- **Free function, spawn root, drive root:** the default is evaluated in the caller before the callee runs. A spawn root's default runs in the spawner at the site, before the task does.
