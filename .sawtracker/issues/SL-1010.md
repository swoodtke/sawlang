Found by the SL-1005 spec review (F17).

LANGUAGE_SPEC "Source-location literals" calls them ordinary compile-time constants, valid anywhere a literal of their type is. That includes an expression, an interpolation, a default parameter value and, for `#line`, a `static` initializer.

`coro --check` accepts them, so the doc example passes docverify, but `sawc build` refuses:
- `backend.not-yet`: the constant `#line` is not in the backend slice yet;
- for `#file` and `#function`: a memory constant is not in the backend slice yet;
- `static LN: Int = #line`: a static whose initializer the constant evaluator does not hold.

The probes are `/Users/shawn/Projects/sawlang/.build/scratch/p1000d/F17_srcloc_*.saw` and `/Users/shawn/Projects/sawlang/.build/scratch/p1000d/cases/srcloc_*.saw`.

Note: `print("{#file}:{#line}")` is the usual logging idiom, and assert and panic carry a location already.

**Implementation detail (lead, Nov 12): MIR lowers `#file`, `#line` and `#function` to ordinary Int and String constants, and the fold treats `#line` as one, so no backend work is needed.**

**Confirmed on main today:** `func main() { print(#line) }` is `backend.not-yet`: "the constant `#line` is not in the backend slice yet".

**Why it fails.** `compiler/mir/src/lower.saw` lowers the three (`Expr_SourceLocation_File`, `_Line`, `_Function`) as `self.literal(e, MirConstKind.Builtin, t)`, an operand whose text is the token itself. The backend's `const_value` (`compiler/llvm/src/places.saw`) knows `Builtin` only for integer bounds (`.min`/`.max`), and a String-typed one falls to "a memory constant". Typecheck's constant fold answers `-1` (not a constant) for `Expr_SourceLocation_Line` (`bodies.saw`, `constant_parts`), so `static LN: Int = #line` has no value.

**The rule (LANGUAGE_SPEC "Source-location literals").**
- `#line`: `Int`, the 1-based line of the token.
- `#file`: `String`, the source file's BASENAME, spelled as the panic prefix (`panic at FILE:LINE:`) spells it.
- `#function`: `String`, the enclosing function's or method's bare name with no type qualifier (`main`, `here`, `init`); `<module>` at module scope.
- Each expands at its definition site: in a generic it is the generic's own line; in a default parameter value it is the default's own site; in a suspending function it is the original source line and the user function's name; in a closure it is the enclosing named function.

**The change.**
1. **MIR** (`lower.saw`, the three arms that call `self.literal(e, MirConstKind.Builtin, t)`):
   - `#line` → `self.op_const(MirConstKind.Int, <decimal text of the node's line>, t)`. Take the line from the node's start offset through the same position function diagnostics use.
   - `#file` → a `MirConstKind.String` constant holding the basename. Find how a panic or assert site gets its `FILE` (the text after `panic at`), and use the same source, so the two always agree. A String constant's operand text is in the form the backend's `literal_into` reads (`ll_string_bytes`): read that function and one existing String literal's dump to learn whether it is the quoted source spelling, then build the text accordingly, escaping what that form requires.
   - `#function` → a String constant, the bare name by the rule above. The lowering knows the function it is lowering; for a closure or a default value walk to the enclosing named declaration.
   - The predicate near the top of the file that lists the three alternatives as constants stays.
2. **Typecheck fold** (`bodies.saw` `constant_parts`, and `fold.saw` where an integer leaf gets its value): `Expr_SourceLocation_Line` is an Int constant with the line's value, so `static LN: Int = #line`, a `static_assert` operand and an array length read it. `#file` and `#function` stay non-foldable (no String static exists).
3. **Evaluator** (`compiler/eval`): nothing if it reads the MIR Int constant; the agreement check between fold and evaluator must pass for `static LN: Int = #line`.
4. No change in `compiler/llvm`. If, after step 1, the backend still refuses one of the three, STOP and report the refusal and the MIR dump.
