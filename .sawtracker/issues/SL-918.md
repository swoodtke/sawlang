Found during SL-865 U3 (p865), confirmed by the lead in `compiler/tests/oracle.py`.

**Mechanism:** corpus programs state directives that corpusdiff's oracle never reads, so a verdict of `pass` is weaker than the program claims.

1. **`judge_refusal` ignores `EXPECT-ERROR-CONTAINS`.** It maps Stage 0's error MESSAGE to a rule (`plan_rule` / `PLAN_RULES`) and passes when sawc refuses with that rule. When the message maps to no rule, it passes on ANY refusal (`found[0][0]`). The program's own expected text is never compared. Example: `errors/freestanding_macho_target_rejected` passes with a message that doesn't contain its `EXPECT-ERROR-CONTAINS` text (`--target riscv32-unknown-none-elf`).
2. **`EXPECT-SYMBOL-UNDEFINED` and `EXPECT-OBJECT-MAX-BYTES` have no reader.** An `EXPECT: object` row is recorded `pass built` without running and without checking its symbols or size (SL-865's plan, risk "Corpus checks"). U3 checked its three rows' undefined seams by hand with `nm -u`.

**Obligation 4 sweep (for the unit):** enumerate every `// EXPECT*` / `// COMPILE-FLAGS` style directive used across `tests/corpus/`, mark which the oracle reads for each verdict kind (run, refusal, object, detached/native), and give each unread one a reader or a recorded reason. Then re-measure: any row whose verdict changes once its directives are read is reported with its cause (a sawc bug, or a directive gone stale), not silently re-baselined.

Not urgent for the sawos restart, but it bounds how much every `pass` in corpus_diff.tsv is worth.

**Implementation detail (lead, Nov 12): this is now SL-1061's unit 2a, a second dry run: refusal tests judged by their own `EXPECT-ERROR-CONTAINS`.**

**Why it comes before the flip.** SL-1062's measurement (its closing note) found that without a Stage 0 record a refusal test passes on ANY non-gap refusal: `judge_refusal` gets an empty Stage 0 error, and sawc's side never reads `EXPECT-ERROR-CONTAINS` (`compiler/tests/oracle.py`; only the Stage 0 recording reads it). 966 corpus programs are refusal tests. Example: `errors/vector_iter_requires_copy` passes on `result.discarded`, though the test is about `iter` needing `T: Copy`. Flipping corpusdiff to own-directives judging (unit 3) without this would take the teeth out of all of them.

**The catch this unit measures.** The `EXPECT-ERROR-CONTAINS` phrases were written against Stage 0's wording. sawc words many refusals differently, so enforcing the phrases will fail tests whose refusal is right. Nobody knows how many. This unit counts, and sorts them; it changes no test.

**Steps (a measurement: nothing is committed).**
1. In a worktree, extend SL-1062's dry-run flag (`.build/scratch/p1061m/dryrun.diff` in the main checkout: `--own-directives` in `compiler/tests/corpusdiff/corpusdiff.py`, `measure_all`) so that under it a refusal test passes only when every `EXPECT-ERROR-CONTAINS` phrase of the program occurs in the text of sawc's `ERROR` lines for that build (rule id, position and message together, case-sensitive, as `compiler/tests/expect.py` matches output phrases). A program with no such directive is judged as today and listed.
2. Under the suite lock, `corpusdiff.py run --own-directives --jobs 12` with the report and results written to the evidence directory (`/Users/shawn/Projects/sawlang/.build/scratch/p918/`).
3. A probe sorts every refusal test into:
   - **phrase-pass:** every phrase found;
   - **reworded:** refused, a phrase missing, and the refusing rule plausibly IS the test's subject. Give the heuristic you used and its evidence per row (the rule id, the phrase, sawc's message), and don't guess: where it is not evident, the row goes to `unclear`;

   - **accepted:** sawc builds it;
   - **unclear**.
