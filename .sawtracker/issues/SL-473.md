## Description

**sawc2's MIR runs a method call's arguments before an accessor receiver's window opens, against the spec's "the receiver is evaluated before the arguments".** Found pre-reviewing U6d2. Stage 0 follows the spec.

**Repro** (`.build/scratch/air-review/sl460/probe_receiver_order.saw` on the Air):

```saw
struct Grid { items: Vector<Int> }
extension Grid: NoCopy {}
extension Grid {
    func cell(&var self) borrows -> &var Vector<Int> {
        print("receiver prologue")
        lend self.items
    }
}
func note() -> Int { print("argument"); 1 }
func main() {
    var g = Grid(items: [])
    let _ = g.cell().push(note())
}
```

- **Stage 0 runs it:** `receiver prologue`, then `argument`.
- **sawc2's MIR** (main plus U6e) orders it `_4 = call note()`, then `_5 = window_open w0 prologue Grid.cell()`, then `push`. So the accessor's prologue, which is user code, runs **after** the argument.

**It also changes what borrowck accepts.** `vv[0].push(vv.len())` is refused by Stage 0 ("cannot read `vv` from inside a place window opened on it"), the consequence of the spec's order. sawc2's MIR evaluates `vv.len()` before `window_open`, so U6d2's loan model would accept it.

**Mechanism:** U6c1's "two-phase receiver" lowering (receiver expression first, the exclusive borrow after the arguments) is right when the receiver borrow is a plain `ref`, because no code runs, so deferring it is invisible, and that's what keeps `v.push(v.len())` legal in both compilers. It is wrong when the receiver is reached through a `borrows` accessor, because opening the window **runs the accessor's prologue**. Evaluating the receiver then has side effects and a loan, and the spec puts both before the arguments.

**Fix:** a receiver whose borrow runs code, i.e. a `window_open`, opens in receiver position, before the arguments; a plain `ref` receiver stays deferred. Pins:
- the repro's MIR order;
- `vv[0].push(vv.len())` refused by U6d2, matching Stage 0;
- `v.push(v.len())` still accepted.

**Sweep the siblings** (obligation 4), every position that defers a code-running receiver or operand:
- a chained receiver (`g.cell().inner().push(x)`);
- a compound assignment through an accessor (`g.cell()[0] += f()`);
- an optional-chain hop through a conditional lend.

**Ordering:** this should land before U6d2 builds its loan model on the current order, or U6d2 has to special-case it.
