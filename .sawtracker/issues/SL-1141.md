## Description

**Release v0.24.2.** The project owner's ruling (Nov 15, in the lead's session): tag after SL-1134's fix lands ("Wait for SL-1134"). The sawos project waits on it to move its pin and add windowed Saw cases (SO-112).

**The patch:** `.sawtracker/version` becomes `v0.24.2` and `driver_version()` in `compiler/driver/src/main.saw` becomes `"0.24.2"`, which run.py's `version` step holds equal. The server creates the annotated tag at the patch's merge commit. **It lands AFTER SL-1134.p1, with nothing between them.**

**What v0.24.2 holds beyond v0.24.1** (each merged; ancestors verified at landing):
- **SL-1134, a leak in safe code, every release so far:** a capturing closure literal called where it is written (`{ [w] in w.len() }()`, never bound) was never dropped, at every optimization level: its environment leaked and a `NoCopy` capture's `deinit` never ran, in a generic body too. It is now dropped at the end of its statement.
- **SL-1133: windowed Xtensa keeps no frame pointer** (`--target-features +windowed` on `xtensa-esp-unknown-elf`): a function with six or more argument words read a clobbered argument, and calls with stack arguments could raise an unhandled Alloca exception. Call0 and every other target are unchanged.
- **SL-1128:** the freestanding suite has a windowed ESP32-S3 row; the runner refuses an image that mixes call0 and windowed objects (the linker does not check).
- **SL-1092 unit 2: Blade reads `Saw.toml` and `Saw.lock` through the typed TOML tree.** A manifest that is not valid TOML is refused for every command, with its file, line and column; a value of the wrong type is an error; an error in a dependency's manifest names that manifest and the reason; `device-window` may be an integer; `Saw.lock` is written quoted (a lock an older Blade wrote raw with a backslash or a quote in a path needs `blade update` once); a float, a date-time or a multi-line string in any manifest key is refused until the library reads them. `toml.legacy` is gone; `libs/toml` is 0.2.0.
- **SL-1102 unit 2: `sawc --build-id`,** an identity of the compiler binary, its std, its runtime records and the two environment variables that change a build's output; `blade build` hashes it, so a rebuilt compiler or an edited std with an unchanged version rebuilds. Every package rebuilds once after moving to this release.

**Known, not fixed in v0.24.2:**
- SL-1126 / SL-1125: `(move x)` as the base of a field read or a method call does not move (`x` stays usable; an owning field is an internal error). Being fixed.
- SL-1139: `sawc` panics compiling `-9223372036854775808` for a 32-bit target.
- SL-1138: the windowed row's ABI check is fooled by a literal pool; both Xtensa start-ups write `WINDOWSTART` through a9.
- SL-1129: a const generic value past the target's `Int` is refused (`Mask<0x8000_0000u32>` on riscv32). Being built.
- SL-1123 (Mach-O link scratch collision), SL-1140 (`--build-id` on an installed toolchain, unchecked).

**For a project moving its pin from v0.24.1** (sawos): Blade's stricter manifest reader (all 333 of sawos's package directories read identically, the reviewer checked); one rebuild of every package; windowed Saw on the S3 is supported and tested under QEMU.

**Landing:** `git rev-parse v0.24.2^{commit}`; check each merge above is an ancestor (SL-1133 d6292a328, SL-1092 U2 14a583c57, SL-1128 94916c8fd, SL-1102 U2 f409f5717, SL-1134's merge); post the version and sha to the sawos lead.
