## Description

Since SL-280.p2 landed (`c19bf57a`, merged as main `25dc9a17` at 16:25 today), sawlang main cannot compile sawtracker at all. Plain sawtracker `main` (3e756fe) fails at the first `common.json(...)` reached from a driven frame; the previous commit `f982f54c` compiles and runs the full sawtracker suite green. Sawtracker's own test gate on this tracker runs with the live checkout's `bin/sawc`, so every ST patch now fails at compile time until this is fixed.

## Reproducer

Committed in the sawtracker repo as `repros/coro_module_json.saw` + `repros/coro_module_json_mod.saw` (ST-31 branch; copied below). A spawned task calls an ordinary imported helper that encodes a `JsonValue`. Nothing in the chain does io: `to_json_string` → `JsonValue._write`, which recurses into itself through the closure `Vector.each` runs (`sawc/std/json.saw:1477`).

```saw
// repros/coro_module_json_mod.saw
import std.json.{JsonValue}
public func to_text(doc: &JsonValue) -> String {
    let encoded = try! doc.to_json_string()
    encoded
}
```

```saw
// repros/coro_module_json.saw
import repros.coro_module_json_mod
import std.json.{JsonValue}
import std.channel.{Channel}
func worker(inbox: Channel<Int>, outbox: Channel<String>) {
    while {
        let n = try inbox.receive() catch { return }
        var doc = JsonValue.Object(fields: Map<String, JsonValue>())
        let _ = try! doc.as_object()!.insert("a", JsonValue.Number(value: n))
        let text = coro_module_json_mod.to_text(&doc)
        let _ = outbox.send(text)
        return
    }
}
func main() {
    let inbox = try! Channel<Int>()
    let outbox = try! Channel<String>()
    var group = TaskGroup()
    let task = group.spawn(worker(inbox.copy(), outbox.copy()))
    let _ = inbox.send(1)
    let text = try! outbox.receive()
    print(text)
    task.cancel()
}
```

Expected (and observed on `f982f54c`): compiles, prints `{"a":1}`.

Actual on `25dc9a17`:

```
error: coroutine transform: the suspending call `JsonValue._write(...)`
appears inside a CLOSURE BODY in driven `JsonValue__write`, and a closure body
is not driven — its suspension has no frame to park in.
  --> sawc/std/json.saw:1477:31
```

In sawtracker itself the first error surfaces as:

```
error: coroutine transform: suspending call to `json` in `test_runner` appears in a nested/expression position; only a top-level `let x = json(...)` or `json(...)` statement is supported
  --> src/main.saw:200:34
```

## Diagnosis

`JsonValue._write` is classified as suspending; that classification is the defect. SL-280 exposed it by keying imported free calls the way the effect graph keys them (the fix for the silent-degrade root cause), so `mod.f(...)` now pulls its callee through the transform instead of silently leaving it untransformed. Every `common.json(...)` in sawtracker reaches `_write` that way, and there is no call shape that avoids it, so there is no local workaround.

Related: SL-287 (silent degrade check) — this is the first case where the stricter keying reaches a std function that was never meant to be suspending.
