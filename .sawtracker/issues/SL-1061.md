**User ruling (Nov 11): every test is judged on its own merits, by its own directives, with no reference to Stage 0's recorded run.** ("We should just evaluate each test on its own merits with no reference to the original stage0 version.") This retires the Stage 0 oracle: the corpusdiff twins and snapshot, the `stage0-wrong` bucket and annotations, the run lane's `.stage0` records, the coro lane's Stage 0 census, the `std_suspension.txt` snapshot, and any lane's `--stage0` mode.

**Why:** the directives already judge almost everything. Lead measurement, Nov 11 (`.build/scratch/probe_oracle_dependence.py`):
- 2483 corpus programs are twin-judged;
- of the 1545 that run, 1470 state their output and 40 print nothing;
- 35 print output no directive pins (mostly panic tests, judged only through Stage 0's recorded stderr);
- 920 refusal tests are judged by `EXPECT-ERROR-CONTAINS`;
- 108 programs sit in `stage0-wrong`, with no real verdict, and Stage 0 fails 92 twin-judged programs' own directives.

Re-recording needs a v0.18.0 checkout, which the agents' sandbox can't reach. The snapshots are about 18 MB.

**Units, in order:**
1. **Measure.** A dry-run mode computes every twin-judged program's verdict by its own directives alone, against today's baseline. List each program whose verdict would move, by from → to. The `stage0-wrong` and `wrong` rows matter most. Also list programs whose directives under-specify: they run but pin no output, or are panic tests without `EXPECT-PANIC-CONTAINS`. Report only.
2. **Pin the gaps.** For each under-specified program, add the directives that state its behaviour. Take the expected text from the spec's intent: where sawc's output matches Stage 0's recorded output, that is evidence. Where they differ, the lead reviews it rather than pinning sawc's output by default. A program whose verdict would become `wrong` is a real finding: file it, or fix the directive when the directive is what's wrong. The lead triages.
3. **Flip corpusdiff.** Every program is judged by its directives. Delete `compiler/tests/corpusdiff/stage0/`, `annotations.tsv`, the `stage0-wrong` bucket, the twin states and `oracle.py`'s Stage 0 snapshot reading. Update corpusdiff's README, TESTING.md and the patch gate's inputs, and record the baseline.
4. **The run lane.** Every `compiler/tests/run/NAME.saw` that has a `stage0/` record states its output in its own header (a probe-style header, or the lane's stated form). Then delete `compiler/tests/run/stage0/`.
5. **The other Stage 0 oracles:** the coro lane's `stage0/` census, the `std_suspension.txt` snapshot, and every lane's `--stage0` mode (sweep `run.py`'s lanes: mono, borrowck, std, drops …). Each lane judges by its own expectations or golden files.
6. **What's left of Stage 0 in the test tooling:** `oracle.v0_root`, `v0_compiler` and the toolchain's v0 path where only tests used it. `bin/sawc0` and `tools/toolchain.py v0-root` stay only if the frozen dirs (SL-1059, SL-1060) still need them.

**Owed to the user:** CLAUDE.md describes the Stage 0 oracle in several places ("Testing", the corpusdiff gate). Each unit's landing lists the lines.
