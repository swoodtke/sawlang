## Description

**Soundness: sawc2 makes none of the declaration-site checks on `UnsafeSend`/`UnsafeSync`.** Found by SL-673's sweep (agent s673derive).

**Mechanism:** the spec's legality rule for the thread-safety assertion (spec, `UnsafeSync` / `UnsafeSend`, "Legality, checked at the header" and "Three fences") has no implementation in sawc2's typecheck. A declared `UnsafeSend`/`UnsafeSync` joins the conformance table like any other conformance, and `declares_conformance` grants `Send`/`Sync` through the refinement with nothing checked at the header. Stage 0 checks all of it in `_register_thread_assertion` (`sawc/typechecker/registration.py`). This is a different mechanism from SL-673's (that was a missing refusal of a conformance that may never be written; this is a declarable conformance whose legality goes unchecked), so it's filed apart.

**Evidence** (sawc2 at main plus SL-673, `sawc2 typecheck --check`; Stage 0 `sawc/sawc.py -c`):

| probe | sawc2 | Stage 0 |
|---|---|---|
| `struct Outer { b: Buf }` (`Buf` holds an `UnsafePointer`, asserts nothing), `extension Outer: UnsafeSend {}`, then `need<T: Send>(&o)` | accepted, and the bound is met | "cannot declare `UnsafeSend` for `Outer`: field `b` has type `Buf`, which is not `Send` and is not an unsafe type" |
| `struct W<T> { v: T }`, `extension W: UnsafeSend {}` (unconditioned) | accepted | "cannot declare `UnsafeSend` for `W`: field `v` has type `T`, which is not `Send` and is not an unsafe type" |
| `struct P { x: Int }`, `extension P: UnsafeSend {}` | accepted | "`P` already derives `Send`, so `UnsafeSend` asserts nothing" |
| `func need<T: UnsafeSend>(x: &T) {}` | accepted | "`UnsafeSend` is not a generic bound, so it cannot bound the type parameter `T`" |

The first row is the hole: safe code wraps someone else's non-`Send` type and asserts `Send` for it, which is exactly what the spec says the assertion may never do ("Asserting past a SAFE non-`Sync` field is refused naming the field"). The existential fence already holds in sawc2 (`erasure.not-object-safe.unsafe-sync`).

**Owed** (obligation 4, a class until swept): one declaration-site funnel for the assertion, covering every rule the spec lists:
- refused where the structural derivation already succeeds;
- refused past a blocking field that is not unsafe-typed (an interior cell, an `UnsafePointer`, an `UnsafeMemory`), naming the field, with the header's own bounds assumed for its parameters;
- refused with nothing blocking;
- refused on one instantiation (a specialized header), as Stage 0 does;
- `UnsafeSend`/`UnsafeSync` as a generic bound refused;
- the controls: the new std's assertions (`Vector`, `Map`, `Data`, `String`, `StringBuilder`, `Atomic`), Stage 0's std's, golden `static_sync` and golden `thread_assertions` (SL-673) stay accepted.

Pin each rule with a refusal fixture against Stage 0's wording, and sweep std and the corpus for declarations the funnel would newly refuse before building.

**Related:** SL-659 rule (a) puts these two in the policy set (defining file only); this is the per-header legality, in every file.
