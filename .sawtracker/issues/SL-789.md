## Description

**Pair selection doesn't reach through a `sync` requirement or a `sync` generic** (SL-782 1b-i census, M2/M3). A pair whose default never suspends, reached from a thread:
- **through a `sync` requirement on a bound (M2):** `eval_requirement`/`eval_condition_in` (`compiler/typecheck/src/summaries.saw`) return before recording a condition atom when the requirement is `sync`;
- **through a `sync`-declared generic (M3):** `summary_from` keeps no condition atoms for a `sync` function.

Either way the thread copy runs the DEFAULT. That's harmless (a default never blocks), but the spec has to carry an exception sentence ("through a `sync` requirement or a `sync` generic function … the default runs"), which 1b-i writes.

**Fix:** a thread-only atom list on `TcAcc`/`TcSummary`, recorded for every bound call whatever the function's `sync`, and evaluated only into `thread_causes` (`eval_summary`, mono's `instance_effect`), so suspension behaviour is unchanged. It touches `model.saw`, `summaries.saw`, the summary verifier and `instance_effect`. Then drop the spec's exception sentence and flip 1b-i's `pa`/`via_sync` pins to the twin.
