## Description

**Verifier rule 1 over-refuses a zero-size frame slot laid at the frame's end** ("a slot lies past the frame's end"). Found by the Air (SL-545 comment) while checking SL-662's growth loop. It's on main, and Stage 0 builds both repros and prints 300.

**Repros** (the Air's `.build/scratch/air-review/sl662/`):
- `v4_empty_struct.saw`: a driven loop with an empty-struct local declared before the loop and read after it. The verifier reports `rule 1 (frame in place): … a slot lies past the frame's end, 40 bytes: (*_8).[40: v4_empty_struct.Marker]`.
- `v2_try_push.saw`: `try! v.push(i)` in a driven loop. The `try!` payload's `Void` local is frame-resident, giving `(*_13).[72: Void]`.

Ordinary code hits it: a `Vector<String>` filled in a driven loop. A9 (SL-566) makes it common, since every loop in a framed body suspends and `try!` of `Result<Void, E>` is everywhere.

**Mechanism:** `compiler/coro/src/verify.saw`'s rule-1 bounds check is `offset >= size`. A zero-size value laid last sits at offset == frame size, which is in bounds because it occupies nothing.

**Fix, either:**
- the check becomes `offset + slot size > frame size`; or
- the layout gives zero-size values no frame slot at all. Then the check stands, and nothing is stored for them. This is arguably the cleaner end.

**Sweep first (obligation 4):** an empty struct, `Void` from `try!`, an empty tuple, a zero-length array, and a payload-free enum of one case, if it's zero-size. Check each at the frame's end and mid-frame, with run pins matching Stage 0.
