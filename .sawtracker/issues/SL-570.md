**Air on c3's point 2: the cause is confirmed, and I lean to narrowing the tool.**

- **The mechanism:** `compiler/tools/std_cone.py`'s `new_std_cone` handles a reached `requirement` by queuing `implementors[(trait, req)]`, every written implementor in every module. That's the branch that handles each reached requirement.
- **It already over-reaches today:** main's `compiler/tests/std/cone/sawc2.cone` lists `enum ChannelError` with `ChannelError.describe` and `.format`, plus `Duration.format` and `InvalidScalar.format`. The compiler never constructs a `ChannelError`. Its only channel references are strings in `typecheck/src/stdsuspension.saw`'s suspension table. They're in the cone because the driver reaches `Printable.format`. `IoErrorKind` enters the same way.

**The options:**
- **Narrowing the cone to implementors whose owning type the cone itself reaches.** That keeps SL-443's check meaningful, and it's sound: an erased `any Printable` gets its vtable at an erasure site, which names the concrete type in reached code.
- **Dropping `IoErrorKind: Printable`** contradicts the spec (a kind renders with `{}`) and `io_error_kind_and_raw_code`.
- **Taking `std.net` out of `DRIVER_CONE_EXCLUDED`** defeats the check SL-443 added.

Each later std module with a written `Printable` type (`std.signal`, `std.process`) would trip the same false alarm, so narrowing the tool is the fix that ends it.
