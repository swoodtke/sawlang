## Description

In a coroutine-transformed (driven) frame, a `break` inside a match arm unbinds that arm's payload binding, producing an internal compiler error at a USE of the binding BEFORE the break on the same line:

    error: internal compiler error at repros/coro_match_break.saw:22:20 (Identifier): Undefined variable: n

The identical loop in a sync function compiles and runs. `return` in an arm is fine; only `break` triggers it. Found adopting SL-204: the natural read-loop shape is `case Value(bytes) -> { if bytes.len() == 0 { break } ... }`.

Self-contained reproducer (sawtracker repros/coro_match_break.saw carries the same file; sync twin passes, driven twin ICEs — expected output `1 1`):

    enum Step { case Value(value: Int), case Done }

    func next(i: Int) -> Step {
        if i > 3 { return Step.Done }
        Step.Value(value: i)
    }

    func sync_loop() -> Int {
        var total = 0
        var i = 0
        while {
            match next(i) {
                case Value(n) -> {
                    if n == 2 { break }
                    total += n
                },
                case Done -> { return total }
            }
            i += 1
        }
        total
    }

    func driven_loop() -> Int {
        var total = 0
        var i = 0
        while {
            sleep(Duration.ms(1))          // makes this frame suspending
            match next(i) {
                case Value(n) -> {
                    if n == 2 { break }
                    total += n
                },
                case Done -> { return total }
            }
            i += 1
        }
        total
    }

    func main() {
        print("{sync_loop()} {driven_loop()}")
    }

Workaround used in sawtracker (src/http.saw read loops, src/main.saw accept loop): set a flag in the arm and break after the match. Reproduced against sawlang main 5755f60b. Filed from sawtracker adoption of design 272 (ST-25); sawtracker-side analysis in SAW_NOTES ST-SAW-13.
