## Description

**sawc2 compiles a suspending call as a plain call instead of refusing it.** Found while planning SL-545 (SL:coroutines §2).

**What happens.** Under `--std-root std`, a `blocking` extern is the one suspension source the new std admits.
- **A suspending `main` builds, links and runs synchronously.** A `main` that reaches a `blocking` extern through two helpers is accepted: typecheck marks `main`, `caller` and `nap` as suspending, and MIR flags the call `suspends`. The binary prints the right answer while the extern blocks the only thread. The spec's offload never happens.
- **A suspending cycle is accepted.** `ping`/`pong` with a `blocking` extern in the cycle builds and runs ("2 6 1"). The spec refuses suspending recursion, naming the cycle.

Probes: `p02_local_park.saw` and `p21_generic_cycle.saw` in the coroplan worktree's `.build/scratch/coroplan/sawc2/`, with outputs `out/build_p02_new.txt` and `out/build_p21_new.txt`. They are reproduced in c1 if needed.

**Mechanism.** Every stage after typecheck passes suspension through, and none of them refuses it:
- MIR records it as `MirCall.suspend` (Never/Always/When) and places `Budget` statements;
- mono copies both through unevaluated (SL-526 is the visible half);
- the LLVM backend ignores both: `compiler/llvm/src/bodies.saw` has `case Budget -> {}`, and nothing under `compiler/llvm/src/` reads `suspend`.

So a suspending call reaches the backend as an ordinary call. That is the "silent third outcome" design 275 removed from Stage 0 (SL-287): a suspending call embeds or errors, and never silently blocks.

**Siblings the same mechanism reaches.** Any suspension source that enters the slice before coroutine lowering exists takes the same path:
- an accessor whose prologue or epilogue suspends (`window_open`/`window_close` flagged `suspends`);
- a yield-capable `Budget` point, which today rightly emits nothing because nothing is framed;
- once `std.task` lands, `yield_now`, `sleep` and channel receive.

Today only the blocking extern reaches it, since the new std has no other park.

**Fix (small, and SL-545's first unit, "A0" in SL:coroutines §4).** After mono, evaluate each call's `suspend` flag at its concrete instantiation. The backend refuses a call that definitely suspends with `backend.not-yet` ("a suspending call is not lowered yet: coroutine lowering, SL-545"). Every place that refusal fires is then the work list SL-545's units remove. The ping/pong cycle is the same refusal now and becomes the cycle diagnostic in unit A1.

**Pins:** a run-lane `// due:` program per source: a blocking extern under a suspending `main`, and the cycle.

**Review note (lead): SL-546.p1, unit A0.**

**The mechanism.** `compiler/mono/src/suspends.saw` is a least fixpoint over mono's items that propagates suspension from callee to caller through a reverse-edge worklist. Each item is marked once, with no depth bound. A call typecheck flags as possibly suspending (`suspend != Never`) suspends when the CONCRETE item it reaches suspends, so a `When` condition is answered by the real instantiated target. A target with no body (an extern) keeps typecheck's answer, which is how a `blocking` extern becomes the source. The result is stored on `MonoProgram.suspending`, and the entry points are `mono_solve_suspension`, `mono_call_suspends` and `mono_item_suspends`.

**The refusals.** In `compiler/llvm/src/bodies.saw`, both are `backend.not-yet`:
- a definitely-suspending call terminator ("a suspending call is not lowered yet (SL-545)");
- a yield-capable `Budget` point in a suspending item.

So the "silent third outcome" (a suspending call compiled as a plain blocking call) is gone. Every place this refusal fires is the work list for SL-545's lowering units.

**Pins:** `// due:` run programs `suspend_blocking_main` (refused at each call down the chain), `suspend_cycle` (`run(&slow)` refused but `run(&fast)` on the same line not, which shows the per-instantiation precision) and `suspend_budget_point`. All three built and ran synchronously before this patch.

**Consumer sweep (obligation 2):** Stage 1 built Stage 2 of sawc2's own driver with the refusal active, and nothing was refused. All 63 run programs still match Stage 0.

**Lead's check:** both pins rebuilt from the worktree's sawc2; the refusals fire at the call sites above. Rebased onto main.

Approved patch SL-546.p1 (revision 1)

Approving SL-546.p1 (A0). The refusal has to be exact in both directions: it must not refuse a call that doesn't suspend (that would break programs that build today), and it must not miss one (that is the silent third outcome A0 exists to remove). I probed both directions with this patch's Stage 2 (applied to c1afde2e8, exact tree 1f7dc87c).

**No over-refusal.** One program, every shape that does NOT suspend; all built, and the output is identical to Stage 0's:

| shape | result |
|---|---|
| a `ping -> pong -> ping` cycle with no suspension in it | builds, `cycle 15` |
| a closure through a non-`sync` function type `(Int) -> Int` | builds, `closure 5` |
| a closure through `(Int) sync -> Int` | builds, `sync closure 12` |
| a generic `<T: Shape>` call at a non-suspending instantiation | builds, `generic 50` |
| a plain (non-`blocking`) `extern "C"` call | builds, `extern 7` |
| a 1,000-iteration loop (budget points in a non-suspending item) | builds, `loop 499500` |

The non-suspending cycle is the case that tells a least fixpoint from a conservative one: a solver that marked every cycle, or started from "suspends" and narrowed, would refuse it. Neither existing pin covers it (in `suspend_cycle` the cycle does suspend), so it's worth adding as a negative pin, but I don't hold the patch for that.

**No missed suspension.** Each shape below hides a `blocking` call somewhere less obvious; each is refused, never built:

| shape | refusal |
|---|---|
| an `Equatable.equals` that calls `usleep`, reached by `a == b` | `backend.not-yet` at the `==` AND at the `usleep` inside `equals` |
| `usleep` in a loop body | `backend.not-yet` at the call (the budget point's refusal sits behind it) |
| a closure body calling `usleep` | refused earlier, by typecheck: `effect.closure-suspends` |
| a `deinit` calling `usleep` | refused earlier, by typecheck: `effect.sync` |

Since sawc2's only suspension source today is a `blocking` extern (the intrinsics are still `slice.not-yet` in resolve), and every suspending item bottoms out at such a call, emitted with the refusal, there is no path to a plain call.

**Found on the way, not this patch's:** a suspending default argument, omitted at the call, trips a verifier invariant ("a call's suspension point disagrees with its callee's summary") on the base and with A0 alike, where Stage 0 refuses cleanly. It belongs to A18's 'suspending default omitted' row; details on SL-580 (c4).

**One seam for A2,** posted on SL-553 (c6): A0 seeds suspension only at a target with no body. A2's park intrinsics are planned as std declarations with panicking bodies. If they reach mono with a body, a call to one would escape this refusal and panic at run time. A2 should keep them bodiless in mono, or seed on the role, with a pin.

**The code:** `mono_solve_suspension` is a reverse-edge worklist from the bodiless sources, each item marked once, with no depth bound; `mono_call_suspends` keeps typecheck's answer when it can't see a body, so the unanswerable case refuses, which is the safe side. The three entry points are named on the module, as the plan's "A1 later takes it over" needs.

**Gate:** passed on the applied commit (tested_commit == applied_commit == 433f7019d). Its tested_tree 1f7dc87c is exactly the patch applied to c1afde2e8, the tree I built and probed. The compiler tests (run lane included) and fixpoint passed, as did the changed-`.saw` grammar and astdiff checks.
