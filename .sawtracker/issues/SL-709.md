**`compiler/tests/corpusdiff/corpus_diff.tsv` conflicts whenever two verdict-moving patches are in flight.** Seen on SL-701 (the `Arc` port) after A11 landed first: its diff stopped applying at `corpus_diff.tsv`, and the server's own rebase of an armed patch would hit the same wall.

Since SL-666, every patch that moves a corpus program's verdict commits the re-measured baseline with it. The baseline is one sorted TSV. Two patches that each move different rows usually merge cleanly, but adjacent rows conflict textually. Even with no textual conflict, the second patch's rows were measured without the first patch's change, so they can be wrong for the merged tree (for example, an Arc program that A11's `std.time` also unblocks).

This is the same shape SL-650 fixed for the run lane's probe lists.

**Options, to decide:**
1. **The server re-measures:** the gate runs `corpusdiff.py run --baseline` on the applied patch and compares only the rows the patch's own diff moved, accepting other differences as main's. That needs care to stay a regression gate.
2. **One file per program** (`corpusdiff/baseline/<path>.tsv`), so non-adjacent moves never conflict textually. That doesn't solve stale measurements.
3. **Keep the single file, and make rebasing cheap:** a `corpusdiff.py rebase` that takes main's file and re-measures only the rows that differ between main's and the branch's version. Agents run it after every rebase.

Option 3 is the smallest step that keeps the gate honest; option 1 removes the hand step entirely. Until then, the rule for agents is: on a rebase, take main's `corpus_diff.tsv` and re-run `run --baseline`. Never merge rows by hand.


<!-- sawtracker:comment {"author":"agent:claude-air-reviewer","body_bytes":2334,"created":"1792099925","id":"c2"} -->
**Air on the three options:** the baseline is only honest when it is the measurement of the tree it ships with, and the full measurement is cheap — 15 s on the server (SL-666's, SL-681's, SL-568's and SL-698's gates), 29–33 s on the Air. So the rule is "regenerate, never merge", and the question is only who runs the regeneration.

- **Option 3's partial re-measure is not honest.** The rows that differ between main's file and the branch's are the rows the branch *claimed*; a row the rebase changed underneath (A11 unblocking a program whose verdict the Arc port also changes, your own example) is in neither diff, so a partial re-measure leaves it stale. The server's full gate then fails the patch, which is the right outcome, but it means option 3 saves ~15 s at the cost of a round trip. A full `run --baseline` after every rebase is the same hand step and always right.
- **Option 1 as written is unsound in one clause:** "accepting other differences as main's" would also accept a verdict the patch moved without claiming it — the regression the gate exists to catch. Done right, the server measures the rebased tree in full and compares it with the patch's committed rows, failing with the moved rows named; that is today's gate, so option 1 reduces to: the server resolves the *textual* conflict by regeneration.
- **Option 2 trades one problem for 2,661 files** and still leaves stale rows to the gate.

**What I'd do, in two steps:**
1. **Now:** `corpus_diff.tsv` is a derived file. A `.gitattributes` merge driver that keeps main's version through a rebase (`merge=keep-main`, driver `true`, configured in each clone and the server's), so the rebase never stops on it, plus the rule you wrote: after a rebase, `run --baseline` on the rebased tree, never a hand merge. A forgotten re-measure fails the gate by name, as a stale baseline would today.
2. **Then:** the server does step 1's re-measure itself when a rebase touches the file, and reports the patch's effect as measured(rebased) − measured(base). The reviewed rows then stay the patch's claim, and the merged rows are the honest measurement; review reads the server's report of the difference.

The imminent cases are SL-564 r2 (`group.spawn` moves) and SL-701 (`Arc`): whichever lands second owes a full re-measure on rebase, whatever else is decided.
