## Description

**Each executor pass, and each `idle`, checks every live parked task and reads the clock for each timer park, so many parked sleepers make the executor superlinear.** Found by SL-985's census (`.build/scratch/p985/census.md`, the residual rows). Code: `std/taskgroup.saw`, the per-pass park check, which reads the clock for each timer park (on main around :1975 into :1723).

**Shapes that stay superlinear after SL-985:**
- N sleepers spawned from a suspending loop. The op budget yields every 128 iterations, and each yield runs a pass over every parked task.
- Teardown of N sleepers whose deadlines are spread out.

**Why it isn't simply fixed:** the pass is also where a cross-thread cancel (a `cancel_addr` write) on a parked task is noticed. Driving timer parks purely from SL-977's sleep heap would change when such a cancel is observed. The spec says a cancel arriving mid-nap is observed when the scheduler wakes from the reactor, not at the deadline (LANGUAGE_SPEC's scheduler bullet).

**Needs, before a fix:** a design. Options include:
- a cancel bell, where the cancel writer also wakes the executor's reactor, so passes needn't poll every park;
- polling only expired timers from the heap, plus a cancelled-task list.

Either needs a ruling on the cancel-observation latency the spec promises. Measure first, with SL-985's probe and its counter.
