**sawc2's mono lowers no `Map` or `Set` literal** (found by std1, SL-597). With `std/map.saw` and `std/set.saw` loaded, `{k: v}`, `{:}` and `{a, b}` type, lower to MIR and drop-elaborate clean under `--std-root std` (SL-547's panic is gone), and stop at mono:

```
$ .build/sawc2 build --std-root std tests/corpus/map_literal.saw
ERROR mono.not-yet tests/corpus/map_literal.saw:14:13 a fixed array, a repeat, a `Map` or a `Set` literal is not in the backend slice yet
```

**Mechanism.** `resolve_collection_literal` (`compiler/mono/src/worklist.saw`) resolves a literal to its container's `init()` plus one `push(value:)` per element, and only for `MirAggregate.Vector`. `MirAggregate.Map` and `MirAggregate.Set` reach the same refusal as a fixed array and a repeat.

**Fix:** a `Map` literal is `init()` then `insert(key:value:)` per entry, in order, so a duplicate key's last value wins; a `Set` literal is `init()` then `insert(value:)` per element. Both `insert`s return `Result<_, AllocError>`, and a refusal panics naming the error, the documented collection-literal panic boundary, as the Vector path does. The LLVM side presumably needs the matching aggregate lowering.

**Pins:** `compiler/tests/run/map_set_literals.saw` (a due program, String keys) flips; `tests/corpus/map_literal.saw` also needs SL-598 (its keys are `Int`).
