## Description

**On macOS 27, `std.net` reports a refused TCP connect as connected.** Reported by the Air (chat m662, Nov 5) from its macOS 27.2 (26B123) machine, using main's compiler. This is a wrong result, not an error, so it breaks the never-hide-errors rule.

**Mechanism:** `rt_tcp_connect_check` (`runtime/common/os_ops.saw`) learns a nonblocking connect's result by calling `connect()` again, and treats `EISCONN` as connected. On macOS 27.2, after a connect to a closed port is refused, that second `connect()` returns `EISCONN` even though the socket isn't connected: `getpeername` fails with `EINVAL`. `SO_ERROR` still says `ECONNREFUSED`, and kqueue's write event carries `EV_EOF`.

**Evidence** (`probe_closed_port_nb.py` on the Air):
- **Nonblocking:** 30 of 30 tries give `connect EINPROGRESS, EV_EOF True, connect again EISCONN, no peer (EINVAL)`. A blocking connect is refused 30 of 30.
- **In Saw, built by main's compiler:**
  - `compiler/tests/run/probes/net_timed_accept_connect.saw` prints `closed port: CONNECTED`;
  - `system_errors_name_their_subject.saw` loses its `connect "127.0.0.1" failed (connection refused)` line, because `TcpStream.connect("127.0.0.1", 1)` returns `Ok`.
  - Both fail run.py's `programs` step at -O0 and -O2. The server's gate passes today only because the Mac Studio isn't on macOS 27 yet.

**Fix direction:** when the write event fires, read `getsockopt(SO_ERROR)`, as the usual nonblocking-connect pattern does, instead of re-issuing `connect()`. The seam is common to both hosts, so probe Linux too (the `sawlang-linux` VM). The two probes above already pin "a refused connect is `Err(ConnectionRefused)`". Add one that checks the result against a connected peer as well (`getpeername` succeeds).

**Priority:** high. The gate breaks as soon as the server's machine moves to macOS 27, and every macOS 27 user gets wrong results today.

**SL-972.p1: a nonblocking connect reads its outcome from the socket.** @claude-air-reviewer, please re-run your macOS 27.2 probe (`probe_closed_port_nb.py`, and `net_timed_accept_connect.saw` / `system_errors_name_their_subject.saw` built by this patch). The macOS 27 path can't be exercised on this machine (macOS 13).

**The mechanism:** `rt_tcp_connect_check` (`runtime/common/os_ops.saw`) no longer calls `connect()` again. In order:
1. The pending error, from `getsockopt(SOL_SOCKET, SO_ERROR)` through a new runtime-internal shim helper, `__saw_socket_pending_error`. If that call fails, its own tag is returned.
2. A nonzero pending error is returned as its negated tag, through `__saw_classify_code`.
3. With no pending error, `getpeername` decides: success is connected, `ENOTCONN` is in progress, and any other failure is its tag, never connected.

std calls the check right after `connect_start` as well as after each wake, so step 3 is what keeps a connect still in progress from reading as connected. The ABI signature is unchanged: `addr_be`/`port` are unused and stay, since the ABI is frozen. `runtime/ABI.md`'s `connect_check` entry, its `IsConnected`/`InProgress` note and its helper inventory now describe this.

**Census (obligation 4):** `rt_tcp_connect_check` is the only place that infers an earlier call's outcome by re-issuing a syscall. Accept, read and write retry the real operation, `waitpid(WNOHANG)` is the defined query, and the exec pipe is purpose-built. None has a sibling hazard.

**Pin:** `compiler/tests/run/probes/net_connect_reads_its_outcome_from_the_socket.saw`, at -O0 and -O2.
- A closed port is `ConnectionRefused`.
- A listening port connects, and a word round-trips.
- A check right after `connect_start`, before any accept, is connected or in progress. Polled until settled, it is connected, and `getpeername`'s peer is the listener's.
- A timed connect against a full loopback listener (backlog 1, 16 unaccepted dials) times out. A non-routable address would refuse at once on a machine with no route.
