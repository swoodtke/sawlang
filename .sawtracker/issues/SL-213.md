## Description

Unit D of SL-209 (ownership uniformity). Plan step 6. Depends on Unit A (explicit decisions must exist to migrate onto).

## Remove codegen's independent ownership guesses
`_transfer_needs_copy` (`sawc/codegen/resources.py:1564`) currently derives ownership behavior from expression SHAPES, place markers, and frame markers in addition to checker annotations — a second, independent opinion that diverges from the front end. Migrate each such case INDIVIDUALLY to the explicit checker decision (Unit A):
- During development, compute both the old shape-derived answer and the new decision, compare, and investigate every difference.
- Once a category is fully covered by explicit decisions, remove its shape/marker fallback.

Codegen still chooses HOW to implement a copy — bitwise copy, retain, or memberwise operation — but it must NOT decide WHETHER the program owes one.

## Acceptance
An unclassified transfer reaching codegen becomes an INTERNAL COMPILER ERROR before LLVM emission, never an implicit permission to copy. No `_transfer_needs_copy` shape/marker fallback remains for a migrated category.

Requested changes on patch SL-213.p1 (revision 1)

Request changes on revision 1 (base 22625233, applied/tested 98766102).

[P1] Preserve reusable `[copy]` capture semantics when materializing a driven capture (`sawc/coro_transform.py:7926–7931`). Changing both the written capture spec and codegen mode from `copy` to `move` avoids the second duplication, but also selects the nonescaping move-capture protocol: the first invocation consumes/releases the materialized value and the second invocation panics. An authored copy capture is reusable; avoiding an extra copy must not make it one-shot.

Reproducer (full file in `/Users/swoodtke/Projects/sl213-review-r1/.build/scratch/copy_twice.saw`):

```saw
struct Dup { n: Int }
extension Dup: ExplicitCopy {
    func copy(&self) -> Dup { Dup(n: self.n + 1) }
    func deinit(&var self) { print("drop {}", self.n) }
}
func twice(f: () sync -> Dup) -> Int {
    let a = f()
    let b = f()
    a.n + b.n
}
func sync_case(d: Dup) -> Int { twice({ [copy d] in d.copy() }) }
func driven_case(d: Dup) -> Int {
    __saw_suspend()
    twice({ [copy d] in d.copy() })
}
func main() {
    print("sync={}", sync_case(Dup(n: 10)))
    print("driven={}", __saw_drive(driven_case(Dup(n: 10))))
}
```

On revision 1, sync returns 24, but driven aborts on the second invocation: `closure body ran twice on move capture d` (exit 134). Confirmed independently on the exact patch base: the base permits both calls and exits 0, although its known extra-copy bug gives driven=26. The intended fixed outcome is both versions returning 24, with balanced destruction and no panic. V106 only invokes each closure once and therefore misses the new restriction. Please retain the materialized duplicate for the reusable closure's lifetime without either duplicating it again or assigning deferred move-capture semantics; add a repeated-invocation sync/driven regression.
