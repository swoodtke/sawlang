## Description

**A non-escaping closure's environment dies at its creator's suspension: stack-use-after-return** (found by p795, SL-795's design step). Memory safety, in safe code.

**Repro** (`probe795_env5.saw`):
```saw
import std.task.{yield_now}

func run(f: () -> Int) -> Int {
    yield_now()
    f()
}

func main() {
    let base = 100
    print("by value {}", run({ [base] in base + 1 }))
}
```
Built with `--sanitize address` and run with `ASAN_OPTIONS=detect_stack_use_after_return=1`, ASan reports `stack-use-after-return … READ of size 8` in `closure#0 of main()`. The environment is `%tN = alloca [16 x i8]` in `resume main()` (`closure_into`, `compiler/llvm/src/ops.saw`): a stack slot of the resume function, not a slot of main's coroutine frame. So it is gone once `main` returns Pending at its suspension, and `run`'s frame still holds `f` pointing at it. The same fault occurs with borrow captures (`[&var n, &base]`, `probe795_env4.saw`) and through `group.spawn(run({ … }))` followed by a `yield_now()` (`probe795_env3.saw`). The corpus never showed it: in its spawn programs the spawner's `join` runs the scheduler inside the spawner, so the slot is still alive.

**Mechanism (obligation 4):** a value that the backend materializes in an `alloca` of its own, rather than in a local slot the coro frame layout knows about, is not frame-resident, however long it lives. The closure environment is one instance. **The sweep owes:** every `alloca` the llvm stage emits outside the frame layout's slots (aggregate temporaries passed by pointer, call results by out-pointer, optional/Result payload temporaries, interpolation and format scratch, `[v; N]` repeats, closure environments), and for each, whether its value can be live across a suspension of the function that creates it. Compile/run evidence under ASan with `detect_stack_use_after_return=1` for each.

**The fix's shape (for the brief):** a closure environment, and any sibling the sweep finds, is a MIR local the frame layout sees (so coro places it in the frame when it lives across a suspension), not a backend-private alloca. Or coro learns the backend's temporaries. Pick ONE funnel and name its entry points.

**Pins:** env3/env4/env5 under ASan, plus a row per sweep sibling. The c3 pin of SL-795 (a closure suspended across in a `threads: 2` group) is blocked on this issue.

**Air: SL-805.p1, CHANGES REQUESTED. I'm withdrawing my approval above: `Task.spawn` still lets a closure's environment outlive its creator.** This is SL-805's class, one route the patch doesn't close.

`k4_background_closure_env.saw` (`air-review/sl805p/`), on main a7e9b9f4b plus r1:
```saw
func run(f: () -> Int) -> Int { yield_now(); f() }

func main() {
    let base = 5
    var t = Task.spawn(run({ [base] in base + 1 }))
    t.detach()
}
```
- It is **accepted**, and runs (exit 0 plain).
- Under `--sanitize address` with `detect_stack_use_after_return=1`:
  - -O0: `stack-use-after-return … READ of size 8` in `closure#0 of main()`, from `resume …run(f: () -> Int) task root`;
  - -O2: `stack-use-after-scope … READ of size 8`, same frames, reached from `std.taskgroup.sweep`.
- The cause: the background task is detached, `main` returns, and the exit's cancel-then-join runs the task. The task calls `f()`, whose environment lived in `main`.

**The mechanism:** `Task.spawn` already refuses any borrow argument (`spawn.borrow`: "`Task.spawn` accepts no borrows: `&x` is an argument of the spawned call. A background task outlives the statement that spawned it and may be detached…", which my `k3` shows for `&x` in `main` and in a thread body). r1 makes a capturing non-escaping closure a `ref` of its `Environment` local, and teaches the GROUP spawn rules to judge it like a forwarded reference. But `spawn.borrow`'s check for `Task.spawn` doesn't see that `ref`, so the closure slips past the one rule meant to stop it.

**Fix:** `spawn.borrow` treats a capturing non-escaping closure argument as the borrow it now is, naming the closure ("the closure at L:C borrows its environment…"), with the same "spawn into a `TaskGroup`" out. A capture-less closure (null environment) stays accepted.

**Pins:** `k4` refused; its capture-less twin `Task.spawn(run({ 6 }))` with `detach()` accepted and ASan-clean. Under SL-806 a background task outlives its spawning statement on every thread, not only `main`'s, so the same rule covers a `Thread.spawn` body's `Task.spawn`.

Everything else in my approval stands: `c0`/`k1` ASan-clean at both levels, `k2` refused, `subset`/`std_cone`/`sanitize` pass.
