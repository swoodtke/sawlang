## Description

**A non-escaping closure's environment dies at its creator's suspension: stack-use-after-return** (found by p795, SL-795's design step). Memory safety, in safe code.

**Repro** (`probe795_env5.saw`):
```saw
import std.task.{yield_now}

func run(f: () -> Int) -> Int {
    yield_now()
    f()
}

func main() {
    let base = 100
    print("by value {}", run({ [base] in base + 1 }))
}
```
Built with `--sanitize address` and run with `ASAN_OPTIONS=detect_stack_use_after_return=1`, ASan reports `stack-use-after-return … READ of size 8` in `closure#0 of main()`. The environment is `%tN = alloca [16 x i8]` in `resume main()` (`closure_into`, `compiler/llvm/src/ops.saw`): a stack slot of the resume function, not a slot of main's coroutine frame. So it is gone once `main` returns Pending at its suspension, and `run`'s frame still holds `f` pointing at it. The same fault occurs with borrow captures (`[&var n, &base]`, `probe795_env4.saw`) and through `group.spawn(run({ … }))` followed by a `yield_now()` (`probe795_env3.saw`). The corpus never showed it: in its spawn programs the spawner's `join` runs the scheduler inside the spawner, so the slot is still alive.

**Mechanism (obligation 4):** a value that the backend materializes in an `alloca` of its own, rather than in a local slot the coro frame layout knows about, is not frame-resident, however long it lives. The closure environment is one instance. **The sweep owes:** every `alloca` the llvm stage emits outside the frame layout's slots (aggregate temporaries passed by pointer, call results by out-pointer, optional/Result payload temporaries, interpolation and format scratch, `[v; N]` repeats, closure environments), and for each, whether its value can be live across a suspension of the function that creates it. Compile/run evidence under ASan with `detect_stack_use_after_return=1` for each.

**The fix's shape (for the brief):** a closure environment, and any sibling the sweep finds, is a MIR local the frame layout sees (so coro places it in the frame when it lives across a suspension), not a backend-private alloca. Or coro learns the backend's temporaries. Pick ONE funnel and name its entry points.

**Pins:** env3/env4/env5 under ASan, plus a row per sweep sibling. The c3 pin of SL-795 (a closure suspended across in a `threads: 2` group) is blocked on this issue.

**Air: a first slice of the obligation-4 sweep. Five temporaries a suspending callee borrows are NOT siblings; they're frame-resident.** Probes in `air-review/sl805/`, built with `--sanitize address` at -O0 on main bd9cb0c75 plus SL-577.p1 (no change in this area) and run with `ASAN_OPTIONS=detect_stack_use_after_return=1`.

**Control:** the issue's own `env5` repro (`c0_env5_control.saw`) reports `stack-use-after-return … READ of size 8`, exit −6, so the setup catches the fault.

Each row below passes a temporary by `&` to a callee that `yield_now()`s and then reads it:

| probe | temporary | result |
|---|---|---|
| `s1` | a call result, `reads(&make())` (a 24-byte struct) | `6`, ASan clean |
| `s2` | a struct literal, `reads(&Big(a: 10, b: 20, c: 30))` | `60`, clean |
| `s3` | an `Int?` call result, `reads_optional(&maybe())` | `7`, clean |
| `s3` | a repeat literal, `reads_array(&[1; 4])` | `10`, clean |
| `s3` | an interpolated `String`, `reads_text(&"x{n}")` | `x5`, clean |

So the MIR temporaries a borrow takes are locals the frame layout sees, and the closure environment's backend-private `alloca` (`closure_into`) is the odd one out among these. The sweep's remaining rows are the backend's own scratch: the call-result out-pointers, payload temporaries the backend makes outside MIR, and the format and interpolation scratch. Those are best checked by listing the `alloca`s `compiler/llvm` emits outside the frame's slots, since none of them is reachable by a borrow from source the way these five are.

**Lead on p805's sweep (reversible):** a census of every backend `alloca` outside the frame layout found ONE live-across-a-suspension sibling, the closure env (the Air's c1 slice agrees: MIR temporaries are frame-resident). But it found a SECOND class: a closure passed into a spawned call outlives its env altogether. env7 (three spawns in a loop share one env) gives a silent wrong answer; env11/12/13 fault, and env13 is a borrow-check hole (a forwarded `[&var n]` reaches a task past `n`'s life).

**Ruling: ONE mechanism, funnel (a).** The env is a MIR local, and the closure value is a LOAN of it. Then Class A is handled by the frame layout's existing local rules, and Class B by borrowck's existing spawn-extent rules (whatever is ruled for `run(&x)` is ruled for `run({ [&x] in … })`). env7 and env11 are refused unless joined or owned; env12/13 are judged as a forwarded reference parameter. SL-525 later gives escaping closures owned heap envs. This also answers SL-795 c3, whose pin moves here.
