Context for whoever picks this up: today's gap is a duplication hazard, not a live disagreement, and it stays that way only while `build_const` doesn't grow.

- **Why the two folders can't disagree now:**
  - `fold_chain` refuses any operand, or running value, beyond `TC_CONST_LIMIT` (2^31 − 1) as `slice.not-yet` before each operation, so every `+ − *` it accepts is exact in Int64.

Until this issue lands, any widening of a const-argument position should go through this issue, not into `build_const`.
- **Suggested now (cheap):** one fixture per refused form above, asserting today's `slice.not-yet`. Then a change that grows `build_const` flips a fixture visibly instead of quietly forking the semantics.

**The state of the code (comments c1 to c8 above, re-read today).**
- Two folders. `fold.saw` (typecheck's constant fold, agreeing with the MIR evaluator under typed arithmetic) serves static initializers, raw values, `static_assert` and `@align`: those positions fold shifts, bit operators, division and `sizeof` already.

- GRAMMAR.md §5.2: a generic argument LIST takes no bitwise operator (`Buf<(1 << BIT)>` is not grammar); a named constant there works. So bit operators belong to lengths and repeat counts only.

**The design must decide, with evidence:**
1. **One evaluator, which way?** (a) route the three positions through `fold.saw` (teach it the `Const_*` alternatives, or re-read the same tokens as expressions) and retire `build_const`; (b) the issue's original plan: record a value per const-argument node, lower each to a small MIR function and run the MIR evaluator, extending the agreement gate. 4. **`sizeof`/`alignof` in these positions:** they need the target's layout (`compiler/target`), which typecheck defers to "a layout" today (`ll_align_value` in the backend folds an `@align` the fold left). # SL-457 design pass: one constant evaluator for lengths, repeat counts and const arguments

Evidence: `.build/scratch/p457d/` in the main checkout (sawc rebuilt from `bcfc0e808`, `sawc 0.23.0`).
Probe scripts `probe_matrix.py`, `probe_generic.py`, `probe_genlist.py`; their outputs `matrix_today.tsv` /
`matrix_today.md`, `generic_today.tsv`, `genlist_today.tsv`; single programs under `width/` and `extra/` with their
`*.typecheck.txt` / `*.build.txt` outputs. Every "today" claim below is one of those outputs or a quoted line;
anything else is marked UNVERIFIED.

## 1. Recommendation

1. **Design (a): route the three positions through `fold.saw` and retire `build_const`.** Each array length, repeat
   count and const argument (and a const parameter's default) is typed as a constant expression and judged by the
   existing constant-position funnel `check_constant_position`, which gains three positions (Length, Repeat,
   Argument) and returns the folded value. `build_const`, `fold_chain`, `const_literal`, `const_unfolded` and
   `TC_CONST_LIMIT` go away.
2. **Do not lower these positions to MIR functions now (design (b) deferred).** The value a type needs is
   typecheck's in either design, since mir and eval sit above typecheck; (b) only adds a second computation held in
   agreement. The fold those positions would use is the same `fold_constant` the agreement gate already holds to the
   evaluator at static initializers. A statement-position `static_assert` already lives fold-only (eval README:
   "which has no MIR function here"). (b) becomes the right shape when `constexpr` brings on-demand lowering (§3.10),
   and that is when to build it.
3. **`sizeof`/`alignof` of a type the target alone lays out folds in typecheck** from one scalar table read off
   `TcTarget` (`target_fixes_layout`'s set), and **the evaluator folds the same call from `Target.layout`**, so the
   agreement gate holds the table to the layout funnel at every static and raw value. This also fixes
   `static W = BYTES / sizeof<UInt>()` (`backend.not-yet` today) and a raw case over `sizeof` (an `INVARIANT` today).
4. **Arithmetic over a const parameter becomes a symbolic length** (a new `TcKind`), compared structurally before
   instantiation, folded when substitution makes every parameter concrete, its faults reported per instance by mono.
5. **SL-511 is refuted for `fold.saw` and the evaluator** (both already take `Int` from the target, pinned by the
   riscv32 goldens); the remaining host-width site is `build_const` itself, so SL-511 closes with the unit that moves
   array lengths onto the fold (U2b).

What would change it: a ruling that §3.10 requires every constant position to have a MIR function **now** (then (b)
follows U2-U4 as one more unit, costed in §4.1); or `constexpr` being scheduled before U4 (then build U4's symbolic
length as a node reference that on-demand lowering can evaluate).

## 2. The position × form matrix

annotation, a static's type, a parameter type). **R** a repeat count (`syntax.expr.repeat`, `"[" expr ";" expr
"]"`: in a body and in a static's initializer). **G** a const generic argument or a const parameter's default
(`syntax.generic.arg.value` / `syntax.generic.param.const`, the §5.2 `const-expr` grammar: integer literals, paths,
`+ - * / %`, unary `-`, parentheses, `sizeof`/`alignof`). Controls: **S** a static initializer, **A** a
`static_assert` (both already on `fold.saw`).

GT type argument, GC call argument, SI, SA; the prelude declares `static S8: Int = 8`, `SHIFT = 3`,

## 3. Findings, point by point

### 3.1 Point 1: one evaluator, which way

What decides today:
- `build_const` (signatures.saw:1646-1689) takes `Expr_Int`/`Const_Atom_Int`, a name, a module-qualified static,
  negation and the `Const_Expr`/`Const_Term`/`Expr_Additive`/`Expr_Multiplicative` chains; everything else is
  `self.not_in_slice(node, alt)` (1687). `fold_chain` (1692-1731) refuses any operand or running value past
  `TC_CONST_LIMIT` (`static TC_CONST_LIMIT: Int = 2147483647`, line 64) and any operator but `+ - *` (1723-1725).
  It folds in the compiler's own `Int`, untyped, and never asks the target.
- A static named in these positions is already folded by `fold.saw`: `evaluate_constant_statics` (statics.saw:56)
  types each such static's initializer ahead of signatures (`type_static_ahead`) and folds it with
  `fold_constant` (statics.saw:329), storing `static_values[d]`, which `static_constant` (signatures.saw:1393)
  turns into `mk_const`. So today two folders already meet inside one length: `[UInt8; S8 * 2]` is `fold.saw` for
  `S8` and `fold_chain` for `* 2`.
- The repeat count is typed as a body expression already: bodies.saw:6360-6365, "The count is an `Int` expression
  of the body, and a constant the array's type folds", `self.expr(count, i)` then `build_length(count, ...)`. The
  array length in a type and the generic-list value are never typed: `build_type`'s `Type_Array` case
  (signatures.saw:1063-1069) calls `build_length` on the raw node, and `generic_arg` (1298-1305) calls `build_const`.
- The MIR evaluator covers `Static`, `RawValue`, `Align`, `Assert` MIR functions (eval/program.saw:93-95). Its
  verifier holds it to `fold_constant` per function (eval/check.saw:60-88). Nothing it computes feeds typecheck:
  mir and eval import typecheck, never the reverse (eval/api.saw imports; target/layout.saw imports typecheck).

**Design (a), retire `build_const` into `fold.saw`.** Cost:
- typecheck/bodies.saw: the expression typer and `constant_offender` learn the `Const_*` alternatives
  (`Const_Expr`, `Const_Term` as flat operator chains like `Expr_Additive`/`Expr_Multiplicative`, `Const_Negate`
  as `Expr_Unary_Negate`, a `Type_Path` atom as a name or member read, `Const_LayoutQuery_Size/Align` as the
  `sizeof`/`alignof` builtin call). The parser shapes are the same flat chains with operator leaves
  (parse/parser.saw:6397-6450), so `arithmetic_expr`/`fold_operators` apply unchanged once dispatched.
- typecheck/fold.saw: `fold_as` gains the same `Const_*` cases and the layout query (§3.4).
- typecheck/statics.saw: the pre-signature pass types each length/argument expression ahead, as it types a static's
  initializer, and readies the raw cases they name (`evaluate_raw_case`).
- typecheck/model.saw + bodies.saw: `TcConstPosition` gains Length, Repeat, Argument; `check_constant_position`
  returns its `TcFold`; `constant_offender` admits a const parameter at the three positions.
- typecheck/signatures.saw: `build_length`/`generic_arg` read the funnel's value; `build_const`, `fold_chain`,
  `const_literal`, `const_unfolded`, `TC_CONST_LIMIT` are deleted (`check_constant_fit` and
  `refuse_negative_length` stay).
- The agreement gate: unchanged. Every operator and leaf the three positions take is folded by the one function the
  gate holds to the evaluator at statics and raw values; the eval lane gates it over the corpus. What the gate does
  not see is the position-specific typing (the slot a length expression adopts, Q1). U2's run program pins that by
  printing a length beside a static holding the same expression (the static's value is the evaluator's; the
  length is the fold's).
- Duplication left: none in folding. `fold.saw` remains a second implementation beside eval, as it is today.

**Design (b), a MIR function per node, evaluated and gated.** It is (a) plus:
- mir/model.saw: a `MirFuncKind` (say `Length`); mir/lower.saw `lower_root` lowers it; typecheck pushes each node
  into `body_roots`/`body_decls` (statement-position nodes inside bodies too, which no MIR function holds today).
- eval: `eval_is_constant_kind` admits it; a node over a const parameter has no value without an instance, so the
  evaluator needs a deferred end (like `EvalEnd.Deferred` for layout asserts) or mono-time evaluation.
- Golden churn: `sawc eval --dump` prints every module's constants, std's included (eval_SI_f26.txt shows std's
  statics in a user program's record), so every eval golden moves, and mir dumps that list functions move. There
  are 11 length/repeat sites in std and 29 in the compiler's own source (grep counts), each a new MIR function the
  eval lane's "compiler's own source evaluates whole" check would then evaluate.
- What it buys: the agreement check sees the length's typed tree as MIR. With (a) that tree is already the one the
  fold reads; the only extra coverage is the lowering of these specific nodes.

**What §3.10 requires.** "One evaluator for every constant position: const-generic arguments, array lengths, repeat
counts, `static` initializers, `static_assert` and enum raw values. Today's special-purpose folder goes away", and
"The bootstrap slice builds the MIR interpreter scoped to exactly those ... rather than a separate folder". Read
strictly, neither design satisfies it: `fold.saw` is itself a tree folder kept for typecheck (its header: "lowering
this fold to MIR on demand is a later unit's"), and a type's value cannot come from MIR until on-demand lowering
exists. Both designs retire "today's special-purpose folder", `build_const`. (b) puts all six positions under the
evaluator's agreement, matching statics' status; (a) matches statement-position `static_assert`'s status. The
recommendation is (a) because the value-bearing folder is the same either way and (b)'s cost is golden churn plus a
deferred-evaluation state for generic lengths that the constexpr work would redesign.

### 3.2 Point 2: per-instantiation folds

Today: `const_unfolded` (signatures.saw:1735-1744) refuses any operator over a `TcKind.Param`, "arithmetic over a
const parameter, which folds only per instantiation, is not in the bootstrap slice yet" (g02, g04-g06, g08, g10,
g14, g15). A type's length is `TcKind.ConstInt` (value) or `TcKind.Param` (types.saw:41-46); `Target.compute` needs
`ConstInt` (target/layout.saw:540-544, "an array whose length is not a folded constant"). The machinery to fold at an
instance exists: `fold_name` reads a `TypeParam` from `instance_params`/`instance_values` (fold.saw:440-452), which
`mono_check_instance` fills per item (mono/api.saw:290-327) to judge a `static_assert` over a const parameter.

Design:
- **Typecheck, before instantiation.** An expression over at least one const parameter is a new
  `TcKind.ConstExpr` type: its args are the `Param` types it reads (so `mentions_param` and `subst` see them), its
  representative node in `b`, interned by a structural key (operator tree with literal values at their adopted types,
  folded statics and cases as values, parameters as `(owner, index)`). Q3 decides whether the key is normalized.
  Typecheck checks: the position's grammar (`constant_offender`, a const parameter admitted), that every operand is
  an integer, and every fault in a parameter-free subexpression (`check_constant_faults` on the parts, as the
  deferred `static_assert` does: bodies.saw:2026-2030).
- **Where the fold runs.** In `subst` (typecheck/conform.saw, used by typecheck and by mono's `substituted`,
  mono/worklist.saw:421-437): a `ConstExpr` whose parameters all substitute to `ConstInt` folds (one funnel,
  `fold_const_expr(t, &subst)`, setting the instance values the way `mono_check_instance` does) and interns a
  `ConstInt`; a fault leaves a marker type the instance check reports. So a concrete `W<4>` written in ordinary code
  gets its layout at typecheck, and a generic body's `[0; N + 1]` gets it per item in mono.
- **The refusal at an instance.** Mono's instance-validation pass walks each item's `ConstExpr` positions at that
  item's arguments and reports a negative length, an overflow, a shift out of range or a division by zero, naming
  the instance as `mono_check_instance` does ("at `f() inst 64`"). The rule ids are Q5. §3.8: "Obligations that depend
  on a concrete value ... are checked per instantiation ... as ordinary user diagnostics with an instantiation trace",
  and "An internal error is reserved for a broken compiler invariant, never for an invalid concrete argument".
- A negative bare parameter keeps today's typecheck-time refusal at the call (`record_length_params`, g13).

### 3.3 Point 3: the grammar of each position

From GRAMMAR.md: `array-type ::= "[" type ";" expr "]"` and `repeat-literal ::= "[" expr ";" expr "]"` take the full
expression grammar; §5.2: "An array length and a repeat count are closed by `]`, and take the full expression
grammar." A generic argument and a const default take `const-expr`: `int-literal | path | "(" const-expr ")" |
layout-query` under unary `-`, `+ -`, `* / %`. syntax.rule.generic-arg-value decides a type-shaped argument: "One that
parses as a type and is then followed by `+ - * / %` is re-read as a value ... Otherwise it is a type, and a bare
name such as `N` is decided against the parameter it fills." The semantic filter on both is LANGUAGE_SPEC "The
constant grammar". The matrix in §2 is the cell-by-cell result. Two text conflicts surfaced:
- spec 3521 ("an array length, a repeat count and a const generic argument accept [an alias construction] only once
  those positions are folded by the same evaluator"): a call is not in `const-expr`, so `Buf<Count(8)>` is not
  grammar. GRAMMAR governs spelling; the spec sentence drops "and a const generic argument".
- compiler/tests/typecheck/README.md (around 854): "`build_const`, which takes no static at all" is stale; it takes
  statics through `static_constant` (signatures.saw:1653-1673).

### 3.4 Point 4: `sizeof`/`alignof` in these positions

Today: the funnel admits a target-fixed measurement everywhere and a struct only in a `static_assert`
(`constant_call`, bodies.saw:2429-2434; `target_fixes_layout`, 2495-2501: integers, `Bool`, `Float`, `String`, raw
pointers). `fold.saw` folds a measurement only when a caller supplies its value in `measured_nodes`
(fold.saw:199-208): the layout-assert funnel (asserts/layout.saw:142-163) and the backend's `@align`
(`ll_align_value`, llvm/program.saw:649-676) do, from `Target.layout`. Typecheck cannot call `Target.layout`:
target/layout.saw imports `sawtypecheck.program.{TcProgram, TcTarget}`.

Design:
- **Which stage folds `[UInt8; sizeof<Header>()]`:** for a target-fixed `T`, typecheck, during signatures, from a
  scalar table over `TcTarget` (`word_bits` for `Int`, `UInt`, raw pointers and `String`; 1/2/4/8 for the fixed
  widths and `Bool`; 8 for `Float`, size and alignment equal, as `TargetLayout.init(kind:bytes:)` makes them,
  target/layout.saw:453-456). `fold_as`'s `Expr_Call_Paren` (and the `Const_LayoutQuery_*` cases) read it after
  `measured_nodes`. The length is then an ordinary `ConstInt`, so `[T; N]` identity is never pending.
- **Holding the table to the layout funnel:** the evaluator folds the same call from `Target.layout`
  (eval/interp.saw `next_block`'s `Call` arm, refused today as "a call", 216-219), so the agreement verifier compares
  the two at every static and raw value in the corpus; `tests/corpus/const_sizeof_agrees_across_phases.saw` compares
  them row by row through a length (`sizeof<[UInt8; sizeof<T>()]>() == sizeof<T>()`), and a target unit test compares
  the table with `Target.layout` for every triple in `target_triples()`.
- **A struct, enum, tuple or array `T` outside a `static_assert`:** Q4. With the spec's text, it stays
  `static.not-constant` naming the type at every position, and identity never sees an unknown layout.
- **A type parameter `T`** (g20): not target-fixed, so `static.not-constant` (LiC); no per-instance layout in a
  length.

## 5. Open questions for the owner

**Q1. What type does a length or repeat-count expression adopt?**
- (A) None: it keeps its own integer type, and its folded value converts to `Int` with a range check (negative →
  `constant.negative-length`, past `Int` → `type.mismatch`). `[UInt8; SU8 / 2]` divides at `UInt`;
  `[0; E.A + 250]` overflows at `UInt8`.
- (B) `Int`, as an integer slot: statics and cases convert into `Int` where they stand (spec 14256: "except that a
  static or a raw-backed case converts into the type its expression adopts where it stands"), so `[0; E.A + 250]` is
  258.
- Evidence: every cell accepted today behaves as (A): `static_constant` converts any integer static's value to `Int`
  (golden `static_constants.saw` uses `static SMALL: UInt8` as a repeat count, `[0; SMALL]`); the body repeat count is typed with `want`
  `Int`, which does not force a mismatch (RB_f17 `[0; SU8]` prints 8). (B) needs the conversion the spec sentence
  describes, which is not implemented for statics today: `static X: Int = SU8` is `type.mismatch` (SI_f17).
  Recommended default if no ruling: (A).

**Q2. What type does a const-argument expression adopt?**
- (A) `Int`, then checked against the parameter's declared type (today: `Small<200 + 100>` with `const N: UInt8` is
  `type.mismatch` "is 300, which does not fit `UInt8`", genlist t10).
- (B) The parameter's declared type (spec 14055 for reading `N`; spec 14223 "an integer slot"): `200 + 100` overflows
  at `UInt8` (`constant.overflow`), and `Small<255 + 1 - 1>` is refused though the result fits. At a call head the
  slot is unknown until a candidate is chosen (`TcArgSlot.Unknown`), so (B) types the argument after overload choice.
- Recommended default: (A).

**Q3. Is `[UInt8; N + N]` the same type as `[UInt8; 2 * N]` before instantiation?**
- (A) Structural: one type exactly when the operator trees over the same parameters and folded leaves match; `N + N`
  and `2 * N` differ (g15 refused with a type mismatch).
- (B) Normalized: sums of products in a canonical order, so the two are one type.
- Deferring the comparison to mono is excluded: SL:architecture §3.4 "monomorphization cannot produce a *type*
  error", §3.8 "No *type* error can occur here".
- Recommended: (A); (B) can be added later without breaking an (A) program.

**Q4. `sizeof`/`alignof` of a struct, enum, tuple or array outside a `static_assert`.**
- (A) As the spec says ("Layout in a constant": refused by name, `static.not-constant` "whose layout only code
  generation knows"); the fence at 14322 flips to a passing `saw-error` with that pin; corpus
  `errors/const_builtin_aggregate_length_error.saw` stays a refusal test.
- (B) As SL:architecture §3.10 "`sizeof` of a struct in a constant position (Ruled, Sep 25)" says: legal, with a
  struct's layout computed on demand during typecheck and one acyclic graph over layouts and constants. CLAUDE.md
  makes a Ruled section supersede the spec text it names, and this one names it ("Today the spec refuses it").
  Needs layout callable from typecheck (target imports typecheck today) and a cycle rule for
  `struct A { x: [Int; sizeof<A>()] }`.
- Recommended: (A) for SL-457, with (B) filed as its own issue; or rule that (B) is out of the bootstrap slice and
  amend the architecture text.

**Q5. Which rule reports a fault met only at an instantiation?**
- (A) The typecheck rule of the fault (`constant.negative-length`, `constant.overflow`, `constant.shift-range`,
  `constant.divide-by-zero`), reported by mono with the instance in the message; precedent: mono reports
  `static_assert.failed` for an instance (mono/api.saw:328-331, `mono_rules` includes it).
- (B) One mono rule (say `mono.constant`) naming the fault.
- Recommended: (A): one fault has one rule wherever it is met.

**Q6. A path naming a raw-backed case or an integer limit as a whole generic argument (`Buf<E.A>`,
`cap<Int8.max>()`).**
- Today: `type.argument-kind` / `type.not-a-type` / `name.undefined` (matrix f19 GT/GC, genlist t01, t03).
  syntax.rule.generic-arg-value makes such an argument a type unless an operator follows, and decides only "a bare
  name such as `N`" against its parameter; `names_constant` already extends that to a module-qualified static.
- (A) Decide any path against the parameter it fills: one binding a static, a raw-backed case or naming an integer
  limit fills a value parameter. GRAMMAR's rule text widens from "a bare name" to "a path".
- (B) Keep it a type; the author writes `Buf<E.A + 0>` (re-read as a value, designed to fold) or names a static.
- Recommended: (A).

Not open, decided by the texts: the shift, bit, `~`, `as` and call forms in a generic list are not grammar (§5.2);
`0x80000000` at riscv32 is refused, so the corpus program is edited (spec 8771-8774); a type parameter's layout in a
length is refused (LiC).

Terms used throughout:
- A **const parameter** is a generic parameter declared `const N: T` (T an integer type). Typecheck represents it as the
  type `TcKind.Param` (`decl` its declaring declaration, `a` its index).
- A **constant position** is an array length `[T; e]` in a type (a struct field, a local's annotation, a parameter or
  return type), a repeat count `[v; e]`, a value-spelled generic argument `Buf<e>` / `cap<e>()`, or a const parameter's

- A **folded constant** is `TcKind.ConstInt`, the value in `a`. Today a constant position holds a `ConstInt`, a bare

- An **instance** is one monomorphized item (a function at concrete arguments) or one concrete nominal type

- **Stuck**: a symbolic constant whose parameters are all substituted but whose arithmetic faults (overflow, shift range,
  divide by zero, a value that does not fit); defined in §2.

## 0. Summary

**Representation.** A new type kind `TcKind.ConstExpr`, an operator node interned in the ordinary type table: `a` the
operator, `b` the integer type it computes at, `decl` the operand's own type for a shift count or a conversion, and its
operands as type arguments (each a const `Param`, a `ConstInt`, or another `ConstExpr`). Identity is the interner's:
structural over the operator tree, with every parameter-free part folded to its value (Q3 (A)). One funnel,
`mk_const_expr`, forms every such node and folds it the moment its operands are all values, so substitution (typecheck's
`subst`, which mono also uses) turns `[UInt8; N + 1]` at `N = 3` into the type `[UInt8; 4]` itself. A fault that depends
on the parameter leaves a stuck node, reported per instance by mono (U4b); a fault in a parameter-free part is refused
at the declaration, once.

**U4a (typecheck, plus two small safety pieces):** the kind, the funnel, the builder that turns a typed expression over
a const parameter into the symbolic type, the walks the new kind meets, inference refusing arithmetic, a default
naming a parameter refused as `type.default` (as a bare `N` already is), the layout funnel no longer panicking or
producing negative sizes, and a chain limit in mono so `f<N + 1>()` calling itself is `mono.depth`, not a hang.
**U4a0** (before U4a, independent): an array literal adopting a const-parameter length silently, a soundness bug found
here (`let a: [Int; N] = [1, 2]` at `N = 5` prints 5).
**U4b (mono):** typecheck records every constant position that names a const parameter; mono checks each at every
instance (function items and nominal instances): a stuck value, a negative length, a value that does not fit its
parameter. **SL-1111 closes with U4b:** all 24 cells of its sweep end in a sawc `ERROR`, none in clang.
**`UInt64` past `Int.max`:** the representation is neutral; the limit stays and is stated (default), and widening is a
conditional unit U4c for the project owner's ruling (§8 Q-W). The evidence shows the limit is the TARGET's `Int`, so on
riscv32 a `const M: UInt32` cannot take `0x8000_0000`.

### 1.5 Two findings outside the design's matrix

**An array literal adopts a const-parameter length (soundness).** `probe_lit.py` → `lit.tsv`. In a generic body,
`let a: [Int; N] = [1, 2]` at `f<5>()` builds and prints 5; so do the same literal as a return value, a call argument
`take<N>([1, 2])`, a field `Buf<N>(d: [1, 2])`, an assignment, and `[]`. Mechanism (read): `array_expr` (`bodies.saw`)
takes the expected array type as the literal's type (`result = array`) and compares lengths only when the expected
length is a `ConstInt` (`li.kind == TcKind.ConstInt && li.a != values.len()`). A `Param` length (and, after U4a, a
`ConstExpr`) passes unchecked. A repeat literal is checked (LL rows with `[0; 4]` against `[UInt8; N]` were
`type.mismatch` in the first run of `probe_p.py`, before the probe was corrected). This is older than SL-457 and U4a
widens it; U4a0 fixes it. **The lead should file it** (I file nothing).

**The layout funnel overflows the compiler's own `Int`.** `extra.tsv` h01, h02: a plain, non-generic
`struct S { d: [UInt64; 2305843009213693952] }` and `[0u64; 2305843009213693952]` panic sawc at `layout.saw:547`
(`l.size = el.size * lt.a`). At riscv32 `[UInt32; 1073741824]` (4 GiB, past a 32-bit `Int`) is not refused: `mono
--check` passes (h03) and `static_assert(sizeof<S>() == 0)` fails rather than refusing the type (`one/h03b.riscv.txt`;
the value it measured is UNVERIFIED). `record`, `laid_cases` and `target_align_up` add sizes unchecked the same way
(read, `target/src/layout.saw`). U4a removes the panic; the diagnostic it deserves is Q-S.

### 1.6 What mono, MIR, the evaluator and LLVM do with a bare `N` today

`one/bare.saw` (field, local annotation + repeat, parameter, return, type argument, call argument, `sizeof<Buf<4>>()`),
`one/bare.mono.txt` (`sawc mono --dump`), `one/bare.ll` (`--emit-ll`); it builds and prints `3 5 6 8 4`.

- **Typecheck** forms `[UInt8; N]` with the length type `Param(f, 0)`; a repeat count's MIR operand keeps the parameter
  as a `Generic` constant (`MirConstKind.Generic`).
- **MIR** lowers `[v; N]` as `MirAggregate.Repeat` whose operands are the value and the count (`mir/src/lower.saw`
  `repeat`); a type-position length is never lowered (it is a type, not an expression).
- **Mono** instantiates each item by substitution (`substituted` → `tc.subst`, `worklist.saw`): in
  `item #5: bare.local() inst 3` every local is `[UInt8; 3]` and the repeat is `[const 7: UInt8; const 3: Int]`; a const
  parameter read as a value becomes its decimal text (`copy_operand` → `const_argument`, which normalizes the stored
  `ConstInt` to the parameter's width with `tc_arith_normalize`).
- **The item name** (symbol) is `item_name` (`mono/src/program.saw`): the source signature as typecheck spells it plus
  ` inst ` and the concrete arguments' `type_text`: `@"saw bare.param(a: [UInt8; N]) inst 5"`. A `ConstInt` spells as
  its `a` in decimal (`spell.saw`).
- **Layout** (`target/src/layout.saw`, `Target.compute`): an `Array` needs a `ConstInt` length, else
  `unsupported("an array whose length is not a folded constant")`; size is `el.size * length`, unchecked.
- **LLVM**: `alloca [3 x i8]`; a repeat is a loop bounded by the layout's length (`icmp slt i64 %t1, 3`), the MIR count
  operand is not read (`llvm/src/literals.saw` `repeat_into` reads `l.length`). `sizeof<Buf<4>>()` is the constant 4
  (`store i64 4`).
- **The evaluator** (`compiler/eval`) sees no const parameter: statics cannot name one, and a `static_assert` over one is
  deferred to mono (`mono_check_layout_asserts` → `mono_check_instance`, which sets `instance_params` /
  `instance_values` so `fold.saw`'s `fold_binding` reads the instance's value).
- **SL-1111's IR** (`one/d5.ll`): `define internal i64 @"saw d5.fill() inst -1"` with `%l1 = alloca [-1 x i8]`: nothing
  between typecheck and clang checks a length's sign.

## 2. The representation

### 2.1 Alternatives

| | (A) a symbolic type kind (chosen) | (B) a deferred closure over the expression node | (C) re-typecheck per instance |
|---|---|---|---|
| what a length holds | `ConstExpr` tree in the type table | a type `Deferred(node)`, the value computed by refolding the AST node with `instance_values` set (as `mono_check_instance` does for asserts) | the generic body is typechecked again at each instance |
| identity before instantiation | structural for free (hash-consing in `TcTypes.intern`); Q3 (A) | by node: `[0; N + 1]` and an annotation `[UInt8; N + 1]` are two nodes, so two types unless a structural key is added beside the node, which is (A) again | n/a: no generic identity question |
| substitution | `subst` recurses into the arguments and refolds: one funnel | the node has no parameters to substitute; every reader must refold the AST at an instance, in typecheck and in mono, with the right `instance_params` stack | n/a |
| folding at an instance | arithmetic over interned values (`arith.saw`), no AST | `fold.saw` over the AST (needs `expr_types`, adjustments, bindings) | full typecheck |
| identity after substitution (`W<3>` vs `W<4>` field types, mangling) | the folded `ConstInt` is the ordinary `[UInt8; 4]` | each instance's type must be rebuilt as a `ConstInt` by hand at every site | natural |
| faults at an instance | a stuck node, reported by mono at a recorded node | refold reports the fault, but with no type-level marker every reader must ask | type errors in mono, which SL:architecture §3.4 forbids ("monomorphization cannot produce a *type* error") |
| cost | one kind + sweep of the walks (§2.6) | every type reader learns `Deferred`, and identity is wrong or needs (A)'s key anyway | excluded by §3.4/§3.8 |

(B) fails Q3 (A) without (A)'s machinery; (C) contradicts the architecture. (A) it is. The design's §3.2 sketch
("args are the `Param` types it reads … its representative node in `b`") is refined: the operator tree itself is the
key, so no node is stored in the type and two spellings at two nodes are one type.

### 2.2 `TcKind.ConstExpr`

`types.saw`:

```saw-fragment
    // An integer computed from const parameters, folded once each has a value:
    // `a` its operator (`TC_CONST_*`), `b` the integer type it computes at,
    // `decl` the operand's own type for a shift count or a conversion (-1
    // otherwise), its operands as args: a const parameter, a constant, or
    // another `ConstExpr`.
    case ConstExpr = 12
```

`tc_kind_code`: `case ConstExpr -> 14`. Operator codes (public statics in `types.saw`) and their spellings, one function
`tc_const_op_text(op: Int) -> String` and its inverse `tc_const_op_of(text: &String) -> Int` (0 for an operator it does
not know):

| code | spelling | arity | arithmetic (`arith.saw`) |
|---|---|---|---|
| `TC_CONST_ADD` 1, `SUB` 2, `MUL` 3, `DIV` 4, `REM` 5 | `+ - * / %` | 2 | `tc_arith_binary` |
| `TC_CONST_SHL` 6, `SHR` 7 | `<< >>` | 2 | `tc_arith_shift`, count read at `decl` |
| `TC_CONST_AND` 8, `OR` 9, `XOR` 10 | `& \| ^` | 2 | `tc_arith_binary` |
| `TC_CONST_WRAP_ADD` 11, `WRAP_SUB` 12, `WRAP_MUL` 13 | `&+ &- &*` | 2 | `tc_arith_binary` (parity with `fold_operators`, which passes any chain operator through) |
| `TC_CONST_NEG` 20, `TC_CONST_NOT` 21 | unary `-`, `~` | 1 | `tc_arith_unary` |
| `TC_CONST_CAST` 30 | `x as T` (written) | 1 | `tc_arith_convert` from `decl` to `b` |
| `TC_CONST_ADOPT` 31 | an implicit conversion: an `Adopt`/`Widen` adjustment, an alias construction `Count(N)`, the conversion of a non-`Int` result into a length or argument | 1 | `tc_arith_convert` from `decl` to `b` |

**Holds bits.** A new bit `public static TC_HOLDS_UNFOLDED: Int = 4`: in `TcTypes.intern`, after the argument loop, a
`ConstExpr` whose arguments hold no `TC_HOLDS_PARAM` is a stuck node and sets it; like `TC_HOLDS_ERROR` it propagates to
every type that has it as a part. Mono asks "does this type hold a stuck constant" in O(1).

**The value convention.** `ConstInt.a` is a value as a signed 64-bit integer (its mathematical value). Every `ConstInt`
a type holds today is one: written arguments and lengths are converted to the target's `Int` (`fold_length`), statics
too (`evaluate_static`), literals are their value. Folding reads an operand at the type it is used at with a fit check
(`tc_arith_fits(v, 64, true, width, signed)`); a misfit is a `NotFit` fault. For a value in range, the value is the bit
carrier `arith.saw` uses ("a narrow type's value exactly, sign- or zero-extended"), so the arithmetic functions take it
as is. The only value the convention cannot hold is a `UInt64`/64-bit `UInt` value at or above 2^63; today no constant
position can hold one (§1.4), and a part of a symbolic expression that is one is refused (§3.3). Q-W decides whether
that limit moves.

### 2.3 Identity (Q3 (A), structural)

Two lengths or arguments are one type exactly when their interned ids are equal, which is when the trees are equal
node by node: the same operator, the same computing type `b`, the same `decl`, and equal operands, where an operand is a
const parameter by (declaration, index), a folded value, or a subtree. What is NOT structure: parentheses (the parser
keeps none: `one/paren.parse.txt` shows `(N + 1) * 2` as `(Binary (Binary (Name N) + (IntLit 1)) * (IntLit 2))`), and
any part that names no parameter, which is folded to its value before it becomes an operand (§3.3).

| pair | one type? | why |
|---|---|---|
| `[UInt8; N + 1]` (annotation) and `[0; N + 1]` (repeat) | yes | same tree `Add(Int; N, 1)`; the annotation is typed ahead and the count in the body, both with no expected type |
| `N + 1` and `1 + N` | no | operand order differs |
| `N + N` and `2 * N` | no | `Add` vs `Mul` (g15 is refused `type.mismatch`) |
| `(N)` and `N` | yes | no paren node; both are the bare `Param` |
| `N + 0` and `N` | no | `Add(N, 0)` vs `Param` |
| `N + 2 * 3` and `N + 6` | yes | `2 * 3` names no parameter and folds to 6 |
| `N + S8` and `N + 8` (`static S8: Int = 8`) | yes | the static folds to its value |
| `1 + 2 + N` and `3 + N` | yes | the left-associated prefix `1 + 2` folds before `N` joins (§3.3's chain rule) |
| `N + 1 + 2` and `N + 3` | no | `Add(Add(N, 1), 2)` |
| `N + 1` over `const N: Int` of `f`, and `M + 1` over `const M: Int` of `g` | no | different parameters |
| `f`'s parameter type `[Int; N + 1]` substituted `N := K` inside `g<const K: Int>`, and `g`'s own `[Int; K + 1]` | yes | substitution re-forms `Add(Int; Param(g,0), 1)` through the same funnel |
| `[UInt8; N + 1]` at `N = 3`, and `[UInt8; 4]` | yes | the funnel folds to `ConstInt(4)`, and `mk_array(UInt8, ConstInt(4))` is the existing id |
| `Buf<N * 2>` at `N = 4` and `Buf<8>` | yes | same |
| `N + 1` with `const N: UInt8`, and with `const N: Int` | no | different parameters (and `b` differs) |

Normalization (Q3 (B)) can be added later in `mk_const_expr` alone; every program (A) accepts keeps its meaning.

### 2.4 Spelling (diagnostics, dumps, `type_text`)

`spell.saw` `append_type` (exhaustive match) gains `case ConstExpr -> self.append_const_expr(&var out, t, false)`:

- a binary node: its left operand, ` op `, its right operand. An operand that is itself a binary `ConstExpr` is
  parenthesized, except a LEFT operand in the same class as its parent (classes: `+ - &+ &-`; `* / % &*`; `<< >>`;
  `&`; `|`; `^`), so `N + 1 - 2` prints as written and `(N + 1) * 2` keeps its parentheses;
- `NEG`/`NOT`: `-` or `~` then the operand, parenthesized if it is a binary node;
- `CAST`: the operand, ` as `, `type_text(b)`; the operand parenthesized if binary;
- `ADOPT`: the operand alone (it is no spelling the author wrote);
- a `ConstInt` operand: its value; a negative one in parentheses, `N + (-1)`;
- a `Param` operand: its name, as today.

A folded static or case therefore prints as its value: `[UInt8; N + S8]` reads `[UInt8; N + 8]` in a message. A stuck
node prints the same way with values in place of parameters (`4 * 9223372036854775807`).

### 2.5 Mangling

An item's name is `item_name` = the source function's signature text + ` inst ` + each concrete argument's
`type_text` (§1.6). Before substitution a `ConstExpr` only appears in the signature part, spelled by §2.4
(`saw m.f(a: [UInt8; N + 1]) inst 4`). After substitution every instance argument is a `ConstInt` (folded) or the
instance is refused before an item is made (U4b), so no symbol spells a stuck node. Two instances never share a name:
their `inst` lists differ. Glue items (`drop glue [T; 4]`) spell concrete types only. No change to `item_name`.

is, except in `subst`, `intern`, `append_type`, `unify_pair`, and where a length's value is read.**

## 3. Substitution and folding

### 3.1 The funnel

`signatures.saw` (beside `mk_const`; `conform.saw` and `bodies.saw` already import this module, and it cannot import
`typeops.saw`, which imports it):

```saw-fragment
    // THE CONST-EXPRESSION FUNNEL: the type of operator `op` at integer type
    // `ty` over `args`, `aux` the operand's own type for a shift count or a
    // conversion. Every `ConstExpr` is formed here, so one whose operands are
    // all values is folded here and is that value's `ConstInt`; one whose
    // arithmetic faults stays a `ConstExpr` with no parameter, which mono
    // reports at its instance (`TC_HOLDS_UNFOLDED`). An operand that is the
    // error type makes the error type.
    // ENTRY POINTS:
    //     subst
    //     symbolic_operator
    //     symbolic_convert
    //     parameter_constant
    public func mk_const_expr(&var self, op: Int, ty: Int, aux: Int, args: &Vector<Int>) -> Int
```

Body: for each arg, `< 0` or kind `Error` → return `self.error_type`; if every arg is a `ConstInt`, `let r =
self.fold_const_node(op, ty, aux, &args)` and when `r.v.ok` return `self.mk_const(r.v.bits)`; otherwise
`self.types.intern(TcKind.ConstExpr, aux, op, ty, &args, &none)`.

The design named the funnel `fold_const_expr(t, &subst)`; forming and folding are one step here, so the forming
function is the funnel and `fold_const_expr` is its arithmetic (below), which mono also calls to recover a stuck node's
fault.

```saw-fragment
// A constant expression's fold: its value or fault (`v`, whose `bits` is the
// value as a signed 64-bit integer, or for `NotFit` the value that did not
// fit), and for `NotFit` the type it did not fit (`into`).
public struct TcConstFold { v: TcValue  ty: Int  into: Int }
```

(`TcValue` is `arith.saw`'s; `fold.saw`'s `TcFold` cannot be used here, since `fold.saw` imports `signatures.saw`.
`ty` is the type the faulting operation ran at, for messages.)

- `fold_const_node(op, ty, aux, args) -> TcConstFold`: `read(v, t)` = `tc_arith_fits(v, 64, true, w(t), s(t))` else
  `NotFit` with `into = t`. Binary non-shift: both operands read at `ty`, `tc_arith_binary(&text, a, b, w(ty), s(ty))`.
  Shift: left read at `ty`, count read at `aux`, `tc_arith_shift`. Unary: read at `ty`, `tc_arith_unary`. `CAST`/`ADOPT`:
  read at `aux`, `tc_arith_convert(x, w(aux), s(aux), w(ty), s(ty))`, `NotFit` → `into = ty`. Then the result, a
  carrier at `ty`, back to the 64-bit value: `tc_arith_convert(r.bits, w(ty), s(ty), 64, true)`; a failure (a 64-bit
  unsigned result at or above 2^63) is `NotFit` with `into` = the `Int64` type. `w`/`s` are a local
  `const_width(t)`/`const_unsigned(t)` pair (`int_width`'s answer, which this module cannot import): factor them out of
  `check_constant_fit`'s hand copy so one copy serves both.
- `public func fold_const_expr(&var self, t: Int) -> TcConstFold`: a `ConstInt` is its value; a `ConstExpr` folds each
  operand (a `ConstExpr` operand recursively; a fault returns at once; a `Param` is `NotConstant`), then
  `fold_const_node`. ENTRY POINTS: `mk_const_expr` (through `fold_const_node`), `check_instance_constant` (mono, U4b),
  `symbolic_operator`.

### 3.2 Where it is called

1. **`subst`** (`conform.saw`), new arm: `case ConstExpr -> { var args = self.subst_args(t, &s); self.mk_const_expr(
   info.a, info.b, info.decl, &args) }`. Typecheck substitutes at every call with explicit or inferred arguments
   (`check_candidate`, `finish_call`), at every nominal's member type (`target_member_type`, also used by layout), and
   mono's `substituted`/`concrete_type` call the same `subst`. So the fold runs wherever an instance is formed, in
   either stage, through this one arm.
2. **The builder** (§3.3), when typecheck turns a typed expression into the symbolic type.
3. **A generic body's own uses** need nothing: inside `f<const N>` the length stays `ConstExpr` and is compared by id.

**Memoization and depth (SL-1110 items 2 and 3).** The interner is the memo: an operator node over the same values
is one id, and `mk_const_expr` folds one node per call (its operands are already folded), so no fold walks a tree
except `fold_const_expr` on a stuck node. Recursion depth is the expression tree's depth: `subst`, `append_type`,
`nesting_depth` and `type_holds` recurse once per operator on the left spine of a chain like `N + 1 + … + 1`. No new
limit is added. UNVERIFIED: a 4,000-term chain (SL-1110 item 3's depth) does not crash; a probe after U4a confirms it.

### 3.3 The builder: a typed expression over a const parameter to its symbolic type

`bodies.saw`, beside `const_parameter_value`. A small struct `TcSymbolic { t: Int  ty: Int }`: the symbolic type (a
`ConstInt`, a const `Param`, a `ConstExpr`, the error type once refused, or -1 when the expression is outside what
folds per instance) and the integer type its value has.

`func symbolic_part(&var self, e: Int) -> TcSymbolic`, which mirrors `fold_at` and `fold_as` (`fold.saw`) arm for arm:

1. `e < 0` or `expr_types[e] < 0` (untyped) → `(-1, -1)`.
2. **A part that names no const parameter** (`const_parameters_named(e).len() == 0`): `let v = self.fold_constant(e)`
   (adjustments included). `v.ok` → the value as a 64-bit integer, `tc_arith_convert(v.bits, int_width(v.ty),
   not is_unsigned(v.ty), 64, true)`; if that fails (a 64-bit unsigned value at or above 2^63), refuse `type.mismatch`
   at `e`: "constant `{text of e}` is {value}, which an expression over a const parameter cannot hold: its parts are held
   in `Int64`" and return the error type; else `(mk_const(value), v.ty)`. `v.fault == Cycle` → error type, no refusal
   (the static's own declaration refuses it: SL-1110 item 1's "quiet" rule). `NotConstant` → `(-1, -1)`. Any other fault
   → `check_constant_faults(e)` (which refuses it inside `e`) and the error type.
3. Dispatch on `node_alt(e)`:
   - `Expr_Name`, `Const_Atom_Name`, `Type_Path` whose last leaf binds a `TypeParam` `b` that is const → `(param_type(
     b.node), const_parameter_declared_type(param_owner(b.node), param_index(b.node)))` (§3.4 for the second function),
     then step 4 (a parameter never adopts another type, spec Const generics, so in practice no adjustment).
   - `Expr_Paren` → `symbolic_part` of its inner node (defensive; §2.3 shows the parser keeps no paren node).
   - `Expr_Additive`, `Expr_Multiplicative`, `Expr_Shift`, `Expr_Bitand`, `Expr_Bitor`, `Expr_Bitxor`, `Const_Expr`,
     `Const_Term` → `symbolic_chain(e)`: walk the children left to right exactly as `fold_operators` does (a leaf child
     is the operator text, `op = tc_const_op_of(&text)`, 0 → `(-1, -1)`); `acc` = the first operand's part; for each
     further operand `rhs`: either part -1 → `(-1, -1)`, either error → error; a shift → `symbolic_operator(e, op,
     acc.ty, rhs.ty, acc.t, rhs.t)`; any other operator with `acc.ty != rhs.ty` → `(-1, -1)` (as `fold_operators`
     answers `NotConstant`), else `symbolic_operator(e, op, acc.ty, -1, acc.t, rhs.t)`; the result type stays `acc.ty`.
   - `Expr_Unary_Negate`, `Const_Negate` → `NEG` over the operand's part (a negated literal names no parameter and was
     folded whole in step 2, as `fold_negate` treats it); `Expr_Unary_Complement` → `NOT`.
   - `Expr_Cast` → `symbolic_convert(e, TC_CONST_CAST, expr_types[e], operand part)`.
   - `Expr_Call_Paren` that is an alias construction (`call_at[e]` → a call with `role == TcRole.Conversion` and spelling
     `alias`, as `fold_alias_construct` tests) → `symbolic_convert(e, TC_CONST_ADOPT, expr_types[e], argument part)`.
     (Under SL-1108 Form 2 (A) the generic list's new construction alternative joins this arm.)
   - anything else (`Bool` forms, comparisons, other calls) → `(-1, -1)`.
4. Then each `Adopt`/`Widen` adjustment on `e`, in order (`adj_head[e]`, as `fold_at` walks them):
   `symbolic_convert(e, TC_CONST_ADOPT, adj.to, s)`; any other adjustment kind → `(-1, -1)`.

`symbolic_operator(e, op, ty, aux, a, b)` and `symbolic_convert(e, op, to, s)` (`s.ty == to` → `s` unchanged) call
`mk_const_expr`; if the result holds `TC_HOLDS_UNFOLDED` (a parameter-free prefix of a chain faulted, like
`Int.max + 1 + N`), refuse it at `e` with the fault's own rule and message (`constant_fault_text`, §5.4) and return the
error type: **a fault that does not depend on the parameter is reported at the declaration, once**.

`func parameter_constant(&var self, node: Int, use: TcConstPosition) -> Int` (the root):

- `let s = self.symbolic_part(node)`; `s.t < 0` → -1; error → error type.
- `s.ty` not an integer → refuse with `fold_length`'s non-integer sentence ("{an array length|a repeat count|a constant
  argument} is an integer, and `{text}` is a `{type}`", `type.mismatch`; factor that sentence out of `fold_length` into
  `refuse_non_integer_constant(node, use, ty)` and call it from both) → error type.
- `s.ty != self.int_type()` → `s.t = symbolic_convert(node, TC_CONST_ADOPT, int_type(), s)`: the value converts to `Int`
  as every length and argument does (Q1 (A), Q2 (A); `fold_length`), so a value that does not fit `Int` is a `NotFit` at
  the instance.
- return `s.t`.

**`const_parameter_value` (`bodies.saw`, THE CONST-PARAMETER FOLDER).** Its `named > 0` branch today refuses

```saw-fragment
    // typing an expression over the parameter must not build the list's
```

`ensure_generic_list(owner)`; out of range or not `is_const` → -1; `const_type >= 0` or `node < 0` → it; else, in

### 3.5 Faults: which, where, by which rule

| fault | parameter-free part (`Int.max + 1 + N`, `N + (1 << 64)`) | depends on the parameter (`N + 1` at `UInt8` 255) |
|---|---|---|
| when | at the declaration, typecheck, once (§3.3) | at each instance that meets it, mono (U4b) |
| rule | the fault's own: `constant.overflow`, `constant.shift-range`, `constant.divide-by-zero`, `type.mismatch` (`NotFit`) | the same rule (Q5 (A), the lead's ruling: "the fault's own typecheck rule, reported by mono with the instance named; `static_assert.failed` is the precedent") |
| node | the faulting sub-expression (or the chain node for a prefix) | the written expression (the length, count or argument node in the generic declaration): Q-P's default |
| text | `refuse_constant_fault`'s sentences | the same sentences (§5.4), plus where: "at this instance" or "in `Dflt<-1>`"; mono's `refuse` appends "(in the instantiation `f<0>`)" for a generic item |

A negative length is not a fold fault: `N - 1` at `N = 0` folds to `ConstInt(-1)`, and the array type `[UInt8; -1]` is
what is wrong. That is U4b's length check, the same one SL-1111's negative defaults need.

### 3.6 U4a's two safety pieces (no new diagnostics, no hang, no panic)

**The layout funnel** (`target/src/layout.saw`). In `compute`'s `Array` arm, after the `ConstInt` test: `lt.a < 0` →
`unsupported("an array whose length is negative (`{a}`)")`; an element size `> 0` with `lt.a > max / el.size`, `max` =
`tc_arith_max(self.word * 8, true)` (the target `Int`'s largest value; import `sawtypecheck.arith.{tc_arith_max}`) →
`unsupported("an array of {a} elements of {size} bytes, more bytes than `Int` counts on this target")`. In `record` and
`laid_cases`, each `at + m.size` and each `target_align_up` result checked against `max` the same way →
`unsupported("a type of more bytes than `Int` counts on this target")`. The backend turns an unsupported layout into
`backend.not-yet` "the type … is not in the backend slice yet: …" at the node it lays out (`lay_at`, `llvm/src/prims.saw`);
the layout-assert funnel into `slice.not-yet`. Both are an `ERROR` line where today there is a panic or clang. The
wording is a backstop; Q-S asks what the real diagnostic is.

**The instantiation chain** (`mono`). `function_item` (THE function-item funnel, `worklist.saw`) checks nesting depth
only, which a constant never grows; `func f<const N: Int>() { … f<N + 1>() … }` would instantiate without end (by
reading: each `N + 1` is a new key, `nesting_depth(ConstInt)` is 0; UNVERIFIED by run, since no program can write it
today). After the existing `depth_exceeded` checks and before the item is made: walk `origin` from `origin` (the caller
item) to the root counting items whose `source` equals `source`; at `MONO_CHAIN_LIMIT` or more, set `depth_chain = node`
if it is -1 and return -1. `public static MONO_CHAIN_LIMIT: Int = 128` in `mono/src/program.saw`, commented "twice
`MONO_DEPTH_LIMIT`, so a type that grows meets the nesting refusal first". New `MonoProgram` field `depth_chain: Int`
(-1 in `mono_program`); `report_depth` reports it when `depth_call` and `depth_glue` are both -1, rule `mono.depth`:
"this call instantiates `{decl name}` more than 128 times along one chain of calls, each at different arguments: a
generic that instantiates itself at a changing constant has no finite set of instances (SL-507)". The existing
`mono.depth` fixtures keep their messages (they grow a type, which the nesting check meets at 65; the chain count there
is 65 < 128).

## 4. Inference

The spec (LANGUAGE_SPEC Const generics, "Inference: explicit in this version, with one exception. A `[T; N]` parameter
binds `N` from the argument's length") allows a bare `N` only. So a `ConstExpr` never binds a parameter.

- `infer.saw` `unify_pair`: before the generic comparison, `if pi.kind == TcKind.ConstExpr { self.note_symbolic_params(p,
  &var s); return true }`: no binding, no conflict; the argument check after substitution reports a mismatch.
  `note_symbolic_params` pushes into a new `TcSolve` field `symbolic: Vector<Int>` each index `k` of a `Param(s.owner, k)`
  among `p`'s operands (walk the `ConstExpr` tree; `tc_solve` initializes the vector).
- `bodies.saw` `settle_solutions`: for an unsolved parameter with no default whose index is in `solve.symbolic`, the
  refusal (still `infer.failed`) reads: "cannot infer `{N}` of `{f}`: it appears in this call's parameter types only
  inside a length such as `{text of the first ConstExpr}`, and an argument's length binds a bare `[T; N]` alone; write it
  on the call". Others keep today's sentence. (`settle_solutions` has `solve`; the `ConstExpr`'s text: keep the first
  one seen in a second field `symbolic_type: Int`, -1 initially.)
- A bare `[T; N]` parameter given an argument of type `[T; K + 1]` binds `N := K + 1` (a symbolic value); the instance
  check covers it (U4b).

| call | result | authority |
|---|---|---|
| `f([1, 2, 3])`, `a: [Int; N]` | `N = 3` (unchanged) | spec, Inference |
| `f([1, 2, 3])`, `a: [Int; N + 1]` | `infer.failed`, one error (today two `slice.not-yet`) | spec, Inference |
| `f<2>([1, 2, 3])`, `a: [Int; N + 1]` | accepted, prints 2 | CGen arithmetic; identity §2.3 |
| `f<3>([1, 2, 3])`, `a: [Int; N + 1]` | `type.mismatch` (`[Int; 4]` vs `[Int; 3]`) | identity |
| in `g<const K>`, `f(x)` with `x: [Int; K + 1]`, `a: [Int; N]` | accepted, `N := K + 1` | spec, Inference (bare `N`) |
| same with `a: [Int; N + 1]` | `infer.failed` | spec, Inference |
| `f<const N>(a: [Int; N], b: [Int; N + 1])`, `f([1], [1, 2])` | accepted, `N = 1` | spec, Inference + identity |

### 5.1 What typecheck records


(The last, the use `Length`/`Repeat`/`Argument`, words the message.) Regenerate `compiler/mono/src/frontparts.saw`

**THE INSTANCE-CHECK RECORD** `note_instance_check(node, t, use, owner, index)` (`signatures.saw`): records once per
node (`tc_contains(&self.instance_checks, node)` → return) when `mentions_param(t)`; `holder = self.instance_holder(node)`

- `const_parameter_value` (lengths and counts, symbolic and bare, through `note_length_check` = `note_instance_check(node,

### 5.2 What mono checks, and where

New in `mono/src/worklist.saw` (with `MONO_KEY_CONSTANT_CHECK: Int = 14` and `MONO_KEY_INSTANCE_CHECKED: Int = 15` in
`program.saw`; at `run`'s start, index each check `j` under `(instance_check_holders[j], MONO_KEY_CONSTANT_CHECK)` in
`by_key`):

**THE INSTANCE-CONSTANT FUNNEL** `check_instance_constant(j, t, at: String) -> Bool`: check `j`, its type substituted to
`t` at an instance spelled `at` ("at this instance" for a function item, "in `{type_text}`" for a nominal). Refuses and
answers false when:
1. `t` holds `TC_HOLDS_UNFOLDED`: `let r = tc.fold_const_expr(t)` (a stuck node) → the fault's rule and text
   (`constant_fault_text`, §5.4) at `instance_checks[j]`;
2. use is `Length`/`Repeat` and `t` is a `ConstInt` with `a < 0` → `constant.negative-length`,
   `negative_length_text(use, a, "`{written}` is {a} {at}")`;
3. use is `Argument` and `t` is a `ConstInt` that does not fit the declared type of parameter `index` of `owner`
   (`check_constant_fit`'s test) → `type.mismatch`, `constant_fit_text(written, a, const_type, name, false)` + " " + at.
ENTRY POINTS: `instance_constants_hold`, `check_nominal_instance`.

**Function items** — `instance_constants_hold(k) -> Bool`: for each check `j` indexed under `items[k].decl`,
`check_instance_constant(j, self.substituted(k, instance_check_types[j]), "at this instance")`; all must hold. Called
first in `instantiate(k)` for a `Function` item; when false, `instantiate` returns before `copy_function`, so nothing the
item reaches is made and no stuck type reaches `const_argument`, glue or layout.

**Nominal instances** — `check_nominal_instances(k, t)`, called from `concrete_type` beside `refuse_narrow_atomics`: a
walk over `t` and its parts, memoized by type id (`by_key` `(t, MONO_KEY_INSTANCE_CHECKED)`); for a `Nominal`: for each
check indexed under its `decl`, `check_instance_constant(j, target_member_type(&var tc, t, instance_check_types[j]),
"in `" + type_text(t) + "`")`; then the walk descends into each struct field's and enum payload's type at `t`'s arguments
(`target_struct_fields`/`target_enum_cases` + `target_member_type`, as `Target.nominal` reads them), so `Outer { inner:
Dflt }` reaches `Dflt<-1>`. `concrete_type` is called for every local, place, projection, operand, rvalue and call
instance type of every item (`copy_function`, `copy_place`, `copy_operand`, `copy_rvalue`, `copy_call`, read), so every
nominal an instance uses is met, a non-generic `main`'s included.

**Arguments with no written node** — in `function_item`, after the depth and chain checks: for each const parameter of
`func_decl` (the `inst` list) and of `type_decl` (the `args` list) whose argument is a `ConstInt` that does not fit its
declared type, refuse at `node` (the call) `type.mismatch` with `constant_fit_text(name, a, const_type, name, true)`
("`N` is inferred as 300 here, which does not fit `UInt8`, the type of `N`") and return -1; an argument that holds
`TC_HOLDS_UNFOLDED` → `self.problems.push("an instance's constant argument was not checked where it was written")` and
return -1 (an invariant: every stuck value comes from a recorded position whose holder's check refused first and kept
the caller from resolving its calls). A written argument never reaches this: its holder's check refused it first.

`mono_rules` (`worklist.saw`) gains `constant.divide-by-zero`, `constant.negative-length`, `constant.overflow`,
`constant.shift-range`, `type.mismatch` (the mono lane requires a `refuse/` fixture per rule, §6.6).

### 5.3 The instantiation chain in the message

`MonoProgram.refuse` already appends " (in the instantiation `{instance_text(current)}`)" when the current item is a

## 8. Questions for the project owner

**Q-W. May a const generic value exceed the target's `Int`?** Today (§1.4) every const argument is converted to the
target's `Int`, so on riscv32 a `const M: UInt32` cannot take `0x8000_0000` and a `const N: Int64` cannot take 5e9; on a
64-bit host a `UInt64` parameter cannot take values at or above 2^63. The spec's Const generics text says "Value type:
any primitive integer type, `Int` and `UInt` or a fixed width from `Int8` to `UInt64`" and does not state a limit.
- (A) A const value is held at its parameter's type: every value the type holds is accepted. Cost: U4c (§7).
- (B) State the limit (U4b's spec sentence): a const value must also fit the target's `Int`.
- Default: (B) (no behaviour change; U4a and U4b work under either). Recommended: (A), since a 32-bit register mask or
  address as a const parameter is the kernel and embedded case the design doctrine names first.

**Q-P. Where is a fault met only at an instance reported?** The lead's ruling (Q5 (A)) fixes the rule (the fault's own)
and names `static_assert.failed` as the precedent, which mono reports at the condition inside the generic declaration
with the instance named; the brief suggests the instantiation site.
- (A) At the written expression in the generic declaration, the instance named ("(in the instantiation `f<0>`)", or
  "in `Dflt<-1>`" for a type). One node per fault, as for `static_assert`.
- (B) At the call or type that makes the instance, the declaration's expression named in the message. A type formed by
  a default in non-generic code has no written site to point at, so (B) falls back to (A) there.
- Default: (A).

**Q-S. What does an array or a type whose size in bytes does not fit the target's `Int` get?** Today sawc panics

- (A) `constant.overflow` ("a size counts bytes in an `Int`"), reported at the array type's length where typecheck can
  measure the element (a target-fixed element type) and at the instance in mono otherwise; a follow-up issue.
- (B) A rule of its own (say `type.too-large`).
- Default: keep U4a's backstop and file the follow-up with (A).

Not a question, decided by the texts and the lead's defaults: identity (Q3 (A)); the rule (Q5 (A)); inference (spec);
