Follow-up from U6c2 (SL-452, chat m330): one constant evaluator for EVERY constant position (SL:architecture §3.10, 'one evaluator for every constant position').

**Today:** U6c2's MIR evaluator covers static initializers, raw values, static_assert and @align, each lowered to a MIR function, and typecheck's fold.saw agrees with it under typed arithmetic. But const-generic arguments, array lengths and repeat counts are folded by typecheck's OTHER folder, build_const in signatures.saw (literals, +, -, * and a const parameter). Their nodes are Const_* type-grammar alternatives that no body types, and typecheck records no per-node value. So there are still two folders, and one of them is outside the agreement gate.

**Do:**
1. Record typecheck's value per const-argument node (a typecheck change, with its own commit and pin).
2. Lower each const-argument node to a small MIR function, a const-grammar lowering in compiler/mir.
3. Evaluate it with the MIR evaluator, and extend the agreement gate to cover these positions.
4. Then decide whether build_const can be retired into fold.saw, or into on-demand lowering.

**Sequencing:** after SL-452.p2 (U6c2) and SL-453 (T.Item, now in typecheck) land.

Context for whoever picks this up: today's gap is a duplication hazard, not a live disagreement, and it stays that way only while `build_const` doesn't grow.

- **Why the two folders can't disagree now:**
  - `fold_chain` refuses any operand, or running value, beyond `TC_CONST_LIMIT` (2^31 − 1) as `slice.not-yet` before each operation, so every `+ − *` it accepts is exact in Int64.
  - Const parameters are `Int` only, so typed arithmetic at Int computes the same value.
  - Everything else the spec allows in these positions is refused rather than folded differently: `/ %`, `sizeof<T>()`/`alignof<T>()`, a module `static` argument, and an array length's full grammar, including shifts.
- **The hazard is growth.** Each of those additions brings a semantic choice the evaluator already makes: `/` and `%` rounding and sign, a static's typed value, and shift range under typed arithmetic. Until this issue lands, any widening of a const-argument position should go through this issue, not into `build_const`.
- **Suggested now (cheap):** one fixture per refused form above, asserting today's `slice.not-yet`. Then a change that grows `build_const` flips a fixture visibly instead of quietly forking the semantics.

**Add to this issue's scope (user ruling, Oct 10):** an alias constructor over a constant, `A(e)`, is a constant expression in every constant position. SL-459 item 3b (misc459) implements it in the fold (`fold_alias_construct`) and the evaluator, for static initializers, static_asserts and raw case values.

The array-length, repeat-count and const-argument positions still go through `build_const` (signatures.saw). It accepts only literals, a const parameter and `+ - *`, so `[UInt8; Byte(4)]` is refused as `slice.not-yet`, and so is a static in a length. When this issue moves those positions onto the one evaluator, pin `[UInt8; Byte(4)]` and `[0; Count(BASE)]` as accepted.

Two more constant-position gaps, found by the SL-1005 spec review:
- F2: `/` in an array length or repeat count (`[0; 8 / 2]`) is slice.not-yet (syntax.expr.multiplicative). `*` works.
- F3: a raw-backed enum case as an array length (`[Int; E.A]`, or `E.A as Int`) is slice.not-yet (syntax.expr.member / syntax.expr.cast). The spec says a backed case is a compile-time constant usable as an array length.
The probes are in .build/scratch/p1000d/: F2_array_length_division.saw and F3_array_length_enum_case.saw. The spec's examples are marked saw-pending SL-457.

<!-- sawtracker:comment {"author":"agent:claude-sawlang","body_bytes":551,"created":"1794256674","id":"c6"} -->
The SL-1029 spec review (F3): shift, and, or and xor don't fold in an array length or a repeat count (`[0; 1 << BIT]`, `[0; MASK & ~ALIGN]`, `[0; 1 | 2]`, `[0; 6 ^ 3]`, `[0; 64 >> 3]`, and the same as struct field lengths): slice.not-yet `syntax.expr.shift|bitand|bitor|bitxor`. A const generic argument with an expression (`Buf<(1 << BIT)>`, `Buf<{1 << BIT}>`) is resolve.parse-refused. `static_assert` operands fold fine. The probes are .build/scratch/p1000i/F14_const_fold.saw and F36_fold_positions.saw. The spec's bullet is marked pending SL-457.
