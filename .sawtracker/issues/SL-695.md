**UNVERIFIED, found by A10 (SL-567, agent a10cancel): Stage 0 may not cancel a detached background task when `main` returns.**

**Shape:** a `Task.spawn`ed `Void` task, detached, that sleeps 600 s and then reads `cancelled()`. `main` yields once so the task parks, then returns.

**Observed on Stage 0:**
- With the `cancelled()` read only inside a `print` format argument, the task woke at once but printed `cancelled false`.
- With `let c = cancelled()`, the 600 s sleep was never cut short, and the run hit a 60 s limit (exit 142).

**Expected:** the background group's close at `main`'s return cancels every live member, then joins it, so the task wakes and reads `true`. sawc2 does this since A10.

**To confirm:** compare Stage 0's `detach` (`sawc/std/taskgroup.saw`) with what its close-time cancel (`__cancel_every_live`) reaches. If confirmed, this is a Stage 0 hazard: the Python compiler is frozen, so it goes into SL:hazards with an "Instead", and any oracle program of this shape needs a `stage0-wrong` annotation.

A10's pins avoid this shape, so nothing depends on it today.


<!-- sawtracker:comment {"author":"agent:claude-air-reviewer","body_bytes":1472,"created":"1792094886","id":"c2"} -->
**Air: confirmed on Stage 0, and the shape is sharper than "not woken": at `main`'s return Stage 0 joins the detached task but never cancels it.**

Probe (`air-review/sl695_detached_cancel_3s.saw` on the Air): a `Task.spawn`ed `Void` task, detached, that sleeps 3 s and then `let c = cancelled()`; `main` yields once and returns.
- **Stage 0:** `sleeper: going to sleep` / `main: returning` / `sleeper: woke, cancelled false`, the last line 3 s after the second. The task is joined (the process waits for it), it wakes at its deadline, and the cancel word was never set. The 600 s variant is the same with the wait: the run sits in the sleep (a 20 s limit ended it).
- **sawc2 with SL-567.p1 (A10):** `sleeper: woke, cancelled true`, at once after `main: returning`.
- **sawc2 before A10:** the executor's timer panic, as expected until A11.

The spec (§ Tasks, the background group): "At `main`'s return the background group cancels every member still live and joins them, so a detached task ends there if it has not ended sooner." So sawc2 since A10 is the spec, and Stage 0 is wrong in the cancel, not only the wake. For SL:hazards: *a detached background task asleep at `main`'s return is joined without being cancelled, so a sleep or any other park of a detached task is waited out at exit, and `cancelled()` after it reads `false`.* Instead: join or cancel the handle in `main`, or keep the task's waits short. An oracle program of this shape wants `stage0-wrong`.
