# Grammar batch 4: `while {` (D10), match-arms naming, §2.7 wording, the doc-run drop

- **Epic:** SL-398, following SL-424, which landed the parser.
- **One patch.**
- **Every expectation derives from GRAMMAR.md through the reference recognizer.** Nothing is invented.

## 1. D10: a `{` right after `while` opens the infinite loop's body (SL:open-questions D10, r28)

GRAMMAR.md is ambiguous at `while {`:
- the recognizer accepts `while { a } { }` as `While.conditional`, with a closure literal as its condition;
- it finds `while { a }` NEWLINE `{ }` AMBIGUOUS.

sawc2 and the frozen compiler read `while {` as the infinite loop, and 81 tracked files use that form.

**The work:**
- **§13:** add the rule that a `{` right after `while` begins the infinite loop's body, never a condition. Give it a stable `syntax.rule.*` name, following the naming of the existing rules.
- **The recognizer:** add the matching filter, and resolve the ambiguity.
- **sawc2:** at the `(` of `while { check() }() { step() }`, name the new rule instead of `syntax.rule.block-tail`. Its hint names the rewrite `while ({ check() }()) { step() }` (the Air, t7).
- **Pins:**
  - `while { c }() { }` is refused by the new rule's name;
  - `while ({ c }()) { }` is accepted as a conditional loop;
  - `while { a } { }` is refused;
  - `while { a }`, a line break, then `{ }`, is the infinite loop followed by a closure statement, with exactly one tree.

## 2. Naming: a `{` after a complete `match` that has arms (the Air's review of SL-424.p9, item 1)

In `match x { case _ -> 1 } { }`, sawc2 names `syntax.rule.head-restriction` at 2:13, but the reference names `syntax.rule.trailing-closure` at 2:29.
- **The mechanism:** `head_restricted()` judges its lifted re-read by what `parse_expr()` returns. The re-read takes the arms as a trailing closure, fails at `case`, recovers to the `}`, and returns true. So it "goes on", and `restore` drops the recorded error.
- **The fix:** count the re-read as going on only when it recorded no diagnostic.
- **Pins:**
  - `match x { case _ -> 1 } { }` → trailing-closure at 2:29;
  - `match x { } { }` → head-restriction at 2:13.
- **Also check** the head forms the Air listed: a member or call scrutinee, a `match` as a value, and arms over several lines.
- **Recordable:** by the README's rules this text can be recorded, so add it as a negative case.

## 3. §2.7's closing sentence (the Air, p9 review item 2)

"The rule reads only the digits of `INT` and `FLOAT`" is wrong for a tuple index, which is an `INT` too (`t.0u9` is a two-token refusal). Reword it, along the lines of: "…only the digits of a number literal, so `$0u8` and `t.0u9` each end before a name."

## 4. The recognizer drops a doc run (SL-410 c2)

For `/// one`, `@test`, `/// two`, `func f() {}`, the recognizer accepts, and "one" is neither attached nor refused. The lead's decision: refuse it as `syntax.lex.doc-attach` at the second run, as sawc2 does. Fix the recognizer and add the text as a negative case.

SL-440.p1 is up: grammar batch 4, with 5 commits touching 21 files (+591/−189). Most of the churn is the regenerated `grammar.saw`.

**1. D10: `syntax.rule.infinite-loop`, built on a removed production (c1).**
- **The removed production** is `syntax.expr.refused-brace-condition ::= "while" head-expr NEWLINE* block`, reached through `@syntax.expr.while.refused-brace-condition`. It has its own §10 row, and §7.6 gains a sentence.
- **The rule:** a `{` right after `while` begins the infinite loop's body, never a condition. A token on the line after the loop's `}` that the refused form would take is refused at that token, wherever the loop stands. The hint reads "write `while ({ check() }()) { step() }`". A loop the refused form cannot continue stays an operand (`let n = while { break 1 } + 2`). A line break after the `}` ends the loop.
- **The recognizer:** `_infinite_loop` on `while-expr` refuses a conditional loop whose head starts with `{`, and refuses an infinite loop at a continuing token. `_brace_condition` narrows the removed production to heads that start with `{`.
- **sawc2:** `parse_infinite_while` re-reads the condition inside a speculation, in `brace_condition_ahead`:
  - a clean body followed by a continuing token names `infinite-loop` at that token;
  - a broken body names `refused-brace-condition` at the `{`.
- **Pins:**
  - **Negatives:** `while { c }() { }` at the `(`, and the second `{`, `.x`, `[0]` and `+` forms. Also `let n = while { a } + b { }`, and two `refused-brace-condition` shapes: a map condition, and a set condition before a line break.
  - **Goldens:** `while { a }`, a line break, then `{ }`, which has exactly one tree; `while ({ c }()) { }`; and `let n = while { break 1 } + 2`.
