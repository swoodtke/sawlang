## Description

**An effect error's suspension path stops at a generic instantiation instead of naming the call that suspends.** Found by SL-981.

With SL-981's std, a `Thread.spawn` body that calls `v.sort_by({ … })` is refused with `effect.thread-body`, as it should be. But the chain now ends at "→ `merge_sort`". Before SL-981, when the sort was methods, it went on to "→ `greater_by` → a call through a non-`sync` function value".

The spec (LANGUAGE_SPEC, "Effect polymorphism") says the error names "the instantiation and the full suspension path (e.g. `run$1$Slow → Slow.step → __saw_suspend`)". So the path should continue through the generic free functions `merge_sort` → `greater_at` → `ClosureOrder.greater`, to the function-value call.

**Census first (obligation 4):** where does the path report stop?
- through generic free functions and generic methods;
- through trait-method calls on a generic receiver (`order.greater`);
- through per-instantiation inference in general.

Check both `effect.sync` and `effect.thread-body`, which may build their paths separately. Route every path report through one funnel.

**Pins:** an EXPECT on the full chain for each census row.
