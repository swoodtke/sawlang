## Description

**An effect error's suspension path stops at a generic instantiation instead of naming the call that suspends.** Found by SL-981.

With SL-981's std, a `Thread.spawn` body that calls `v.sort_by({ … })` is refused with `effect.thread-body`, as it should be. But the chain now ends at "→ `merge_sort`". Before SL-981, when the sort was methods, it went on to "→ `greater_by` → a call through a non-`sync` function value".

The spec (LANGUAGE_SPEC, "Effect polymorphism") says the error names "the instantiation and the full suspension path (e.g. `run$1$Slow → Slow.step → __saw_suspend`)". So the path should continue through the generic free functions `merge_sort` → `greater_at` → `ClosureOrder.greater`, to the function-value call.

**Census first (obligation 4):** where does the path report stop?
- through generic free functions and generic methods;
- through trait-method calls on a generic receiver (`order.greater`);
- through per-instantiation inference in general.

Check both `effect.sync` and `effect.thread-body`, which may build their paths separately. Route every path report through one funnel.

**Pins:** an EXPECT on the full chain for each census row.

**SL-982.p1: an effect refusal names the whole suspension path, through generics**

- **Before** (census, 8 shapes, in `.build/scratch/p982/census.md`):
  - `effect.sync` and `effect.closure-suspends` printed no path.
  - `effect.thread-body`, `effect.suspending-value` and `effect.format-suspends` stopped at the first generic function or method, or the first requirement on a type parameter: `sort_by` stopped at `merge_sort`.
- **Mechanism:** three walkers (`thread_chain`, `suspend_chain`, `block_chain`) found the next hop by re-evaluating the callee in its generic template. There, a call that depends on a type parameter is a condition, not a cause, so the walk stopped. A requirement called through a parameter had no implementation to name.
- **Fix:** one funnel in `typecheck/src/effects.saw` (`effect_path` / `chain_from`, its callers listed) follows each function at the type arguments the path reached it with. A requirement through a type parameter names the implementation it dispatches to. `blamed_call_text` appends the path once it goes past the called function. Example: `` `sorted` → `Vector.sort_by` → `merge_sort` → `insertion_sort` → `greater_at` → `ClosureOrder.greater` → a call through a non-`sync` function value ``.
- **Not the cause:** the std suspension table. It is generated from v0.18.0's std and read only for interface modules. Untouched.
- **Pins:** 18 typecheck refusal fixtures, one per census row for each of `effect.sync` and `effect.thread-body`, each checking the full chain.
- **Moved:** no fixture or golden moved. Corpus messages only gain the appended path, and the corpusdiff gate holds all 2,676 with no `stage0-wrong` detail changed.
- **Gates:** `run.py --only seed,units,golden,subset,fixture_whitespace,std,typechecker,programs`: ok (1,412 refusal fixtures). corpusdiff: ok.

**Left open:**
- Hops print plain names (`merge_sort`), not the spec example's instantiation names (`run$1$Slow`).
- A generic `sync` function called at a concrete type names its condition but no path past the implementation (`refuse_forbidden`).

Approved patch SL-982.p1 (revision 1)

**Air: SL-982.p1, approved.**

**Read:** the path funnel (`effect_path` / `chain_from` / `follow_path`) follows each callee at the type arguments the path reached it with. It keeps the `visited` set keyed by declaration, so a generic that recurses at a growing type is walked once and the walk always ends. Only the message gains the path, and no refusal decision depends on it.

**Probed** (main's compiler against the patch, `typecheck --check`):
- **`growing_generic.saw`:**
  - `deepen<T>` recurses at `Wrap<T>`, the shape mono refuses at depth 64, and is called from a `sync` function;
  - `ping`/`pong` are mutually recursive generics, also called from `sync`.
  
  Both are refused promptly, the same errors as main, now ending `(`deepen` → `yield_now` (parks the task))` and `(`ping` → `yield_now` (parks the task))`.
- **`sort_slow_sync.saw`** (my SL-981 probe: a `Comparable` whose `compare` yields, sorted from a `sync` function):
  - main: "…calls `Vector.sort`, which may suspend", with no path;
  - the patch: `(`Vector.sort` → `merge_sort` → `insertion_sort` → `greater_at` → `NaturalOrder.greater` → `Slow.compare` → `yield_now` (parks the task))`. It goes through the dispatched implementation to the user's own `compare`, which is the reason SL-982 was filed.

The exit status and refusal set match main in every probe.
