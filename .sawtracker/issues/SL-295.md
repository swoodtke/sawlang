## Description

SL-260 found Python sawc rejecting valid code when dead statements follow an unconditional return. Existing fixture prototypes/minivm/examples/unreachable.saw:

```saw
func stop() -> Int32 {
    return 7
    print(99)
    if true { print(98) }
}
func main() { print(stop()) }
```

Actual: clean compiler error, `function stop should return Int32 but returns Void`. Expected: compile and print 7; unreachable statements may still be typechecked, but cannot replace the reachable function result. Prototype behavior is correct.

Mechanism: block checking reports the final, unreachable statement's Void type and function return reconciliation uses that type despite the earlier unconditional return. Preserve path termination separately from the final syntactic expression type. Sweep explicit returns followed by dead scalar/Void/control-flow statements, functions/methods, and branch nesting; retain type errors inside unreachable code. This is distinct from failing to reject a reachable missing-return path.
