## Description

**Spec vs sawc2: how far a declared type drives inference, and how a disagreement is reported** (surfaced by SL-657's agent; true of constructions before SL-657, and of static calls after it).

1. **Reach.** LANGUAGE_SPEC "Generic type-argument inference" says a declared slot at an initializer (a `let`/`var`, a module `static`, a parameter default) reaches the constructor, and that "the slot reaches the initializer only". sawc2 passes the expected type into a construction in argument, return and assignment positions too: `take(Bag(n: 1))` and `b = Bag(n: 4)` check clean. Stage 0: (to probe).
2. **The error.** A slot that disagrees with an argument (`let w: Wrap<Int> = Wrap(value: "x")`) is described by the spec as a solver conflict ("required to be both `Int` and `String`", a checked `saw-error`). sawc2 reports a plain `type.mismatch` on the argument.

**Needs a ruling (1):** either the spec widens to "every position with an expected type" (sawc2's behaviour, and arguably what a reader predicts), or sawc2 narrows to initializers. Item 2 is a diagnostic-shape difference to align with whichever reading wins; docverify would catch the spec example once sawc2 drives docverify.
