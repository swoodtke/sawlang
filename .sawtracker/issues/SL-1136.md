## Description

**The refusal for comparing an Optional with a bare value whose type is not `Equatable` names two Optionals.** From the reviewer's notes on SL-1124.p2 (Nov 14). `NE? == NE`, with `NE` not `Equatable`, says "`==` compares two `NE?`, which is not `Equatable`": the reader wrote one Optional and one bare value. SL-1124 added clearer wording for this comparison, but it is reached only when a member an extension declares on `Optional` would have answered.

**Asked:** the message for `T? == T` (and `!=`) with `T` not `Equatable` says what was written (an `NE?` compared with an `NE`) and what is missing (`NE` is not `Equatable`), from the one place the present comparison is decided (`compare_expr`, `compiler/typecheck/src/bodies.saw`). A refusal fixture pins the text. Low priority: wording only.
