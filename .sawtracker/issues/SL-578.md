**Air: two single-threaded assumptions A13a (SL-571, merged bc7bbf3f6) leaves for this unit.**

1. **The readiness word's read.** `park_wakes` reads a channel's `ready` word with a plain load (`word[0] != 0`). `publish_ready` writes it with the channel's lock held, but the executor reads it without that lock. Once a pool worker sends while another worker sweeps, that plain load races the store: a data race, and a load the compiler is free to keep stale across the sweep. It needs an atomic load. The queue itself is safe, because the woken receiver's `take` re-reads `count` under the lock, so a relaxed load is enough for the wake decision.
2. **`idle`'s deadlock panic.** `idle` panics when only channel parks are left and no timer is pending, on the premise that only code this thread runs can set a readiness word. With N workers, a channel park on one worker can be woken by a task running on another, so `idle` has to wait rather than panic while any worker is busy. SL-765 has the `Thread.spawn` side of this (my c2 there).

**Air, on the A17a stop: evidence for the lead's choice between (a) and (b).**

1. **The capture-list refusal is a missing feature, not a hazard guard.** `subset_check.py`'s own header says the std profile is "the subset's rules over the new std in `std/`, which only sawc2 compiles, with exactly the low-level features SL:architecture §4 names allowed". A `Thread.spawn` capture list is the spec's parameter list for a spawned brace ("the capture list IS the parameter list"), so a pool can't start a worker that knows its group without one. The (a) fix is a named entry there, plus its line in SL:architecture §4. That's a design addition for the lead/user, not a lint exemption.
2. **(b)'s static handoff swaps a lint for a race.** One static carries the group address to every worker start. It's sound only if no two worker starts ever overlap, so it needs a lock and a per-worker handshake (the worker confirms it read the address before the next start writes it). 3. **`borrowed-match-payload` (1314, 1355): (b)'s spelling is behaviour-neutral either way.** Binding the call result to a local before matching (`let made = Thread.spawn(...)`; `match made`) and binding `pop()` first changes nothing at run time, since a `Thread` handle isn't `NoMove` (unlike SL-778's case).
