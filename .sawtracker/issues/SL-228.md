## Description

MOTIVATION: a hosted Saw process cannot intercept SIGTERM/SIGINT — the sawtracker server dies with no flush, no socket drain, and stale lockfiles. The C idioms (signal(2) callbacks, atexit) fight deterministic destruction, the cooperative runtime, and never-hide-errors.

RULED DESIGN (user, Sep 10 2026):
1. SURFACE = SUSPENDING WATCH, no callbacks anywhere: hosted-only std.signal; watch(.terminate) returns a watch handle (Result — registration can fail; never hide errors) whose next() SUSPENDS until delivery, parking the task on the reactor exactly like a socket read. Watching a signal replaces its default disposition; unwatched signals keep OS behavior; SIGKILL/SIGSTOP are inexpressible.
2. NO EXIT REGISTRY: cleanup rides cancellation + deinits. The pattern is a shutdown task that watches the signal, cancels the rest of the work (cancel already wakes io-parked tasks, design 102), values deinit deterministically as tasks unwind, main returns normally. process.exit(code) is documented as the no-cleanup escape hatch (no unwinding mid-flight).
3. SCHEDULING: paired with SL-204 (io_wait deadline) as the server-hardening pair at the queue tail, behind the current soundness pipeline.

MECHANISM SKETCH: both hosts integrate natively with the design-117 instance-based Saw reactor — kqueue EVFILT_SIGNAL (macOS; set SIG_IGN so the default action never fires) and signalfd (Linux; pthread_sigmask block, including at Thread/TaskGroup worker spawn — shim change). shim.c grows sigaction/sigprocmask-family wrappers (FFI-blocked bodies). Check whether any __saw_rt_* seam addition is needed or the reactor side suffices — rt/ABI.md is frozen, abidoc lane gates any change.

BRIEF-TIME SCOPING (open, for the designs/NN brief at dispatch): the curated Signal enum membership + spellings (no-abbreviations doctrine applies); double-watch policy (error at second watch vs broadcast); whether the hosted runtime should default-ignore SIGPIPE for servers; interaction with op-budget fairness while a watcher task parks; freestanding simply lacks the module (like std.net). Obligation-2 consumer sweep: who relies on default signal dispositions today (test_runner child processes, blade, the QEMU harnesses).

Requested changes on patch SL-228.p1 (revision 1)

Request changes on revision 1 (base 78d328de, applied 178c64e8): two independently reproduced concurrency bugs in the signal bridge.

1. [P1] Serialize watch ownership and lifecycle (`sawc/rt/shim.c:400–428`). The lazy initialization, already-watched check, descriptor publication and sigaction installation are unsynchronized. Two threads can both pass the check and both return a successful watch for one signal, violating AlreadyExists and the single-owner contract. Their descriptor and saved-disposition writes overwrite one another; one pipe becomes unreachable, and a saved “previous” disposition can be Saw's own handler. Dropping either handle can then invalidate the other or restore the wrong disposition. `volatile sig_atomic_t` does not serialize this transaction.

   Reproduced with the exact patched shim: preinitialize with a different signal, then gate two callers at pipe() so both have passed the availability check before either publishes. Both SIGUSR1 watches succeed (`watch results: 5 3`) instead of exactly one returning -2. Harness: `/Users/swoodtke/Projects/sl228-review-r1/.build/scratch/watch_race.c`. Initialization, acquisition and teardown need coordinated synchronization, with a concurrent same-signal regression test.

2. [P1] Quiesce in-flight handlers before reclaiming their pipe (`sawc/rt/shim.c:444–450`, handler fd load/write at 360–363). Restoring the disposition prevents future handler entries but does not wait for a handler already running on another thread. Such a handler can have loaded the old write descriptor before unwatch clears the slot and closes the pipe. If another pipe or file reuses that number, the delayed handler writes its notification byte into the unrelated resource. A mutex around watch/unwatch alone will not fix this handler-versus-close race.

   Deterministic reproduction against the patched source: a scheduling hook pauses the actual signal handler immediately before write(), after it has loaded the descriptor; another thread unwatches and opens an unrelated pipe that reuses the descriptors; resume the handler. Output: `unrelated pipe received 1 byte, value=1`. Harness: `/Users/swoodtke/Projects/sl228-review-r1/.build/scratch/signal_close_race.c` (build with `clang -std=c11 -pthread -Wl,-dead_strip .build/scratch/signal_close_race.c -o .build/scratch/signal_close_race`). Please establish a signal-safe reclamation protocol and pin teardown concurrent with delivery and descriptor reuse.

Validation: all four focused K98/K99/K100/hosted-only fixtures pass, as do the ABI documentation, citation and diff checks. These passing fixtures do not cover concurrent acquisition or in-flight delivery during teardown. Server tests were still pending when the review was prepared.
