SL:architecture §3.8 rules that unbounded instantiation (polymorphic recursion, `f<T>` calling `f<Wrap<T>>`) is refused **before** mono, by a check on the generic call graph: a cycle whose composed substitution maps a parameter to a type that strictly contains it is refused.

Nothing in sawc2 builds that check yet (no stage mentions it). SL-505's mono (`compiler/mono`) carries only a backstop: a concrete type nested past a fixed depth is refused as `mono.depth`, naming this issue, so mono never loops. The backstop is not the ruled check. It fires late, at an instantiation trace rather than at the generic call, and it fires only for programs that mono reaches.

Owner: whichever stage holds the generic call graph after typecheck (summaries already walk calls per body). Test plan: Stage 0's `deepen` example from the saw-lang skill ("exceeds the instantiation depth limit"), a two-function cycle, and a cycle whose substitution is a permutation (`f<A, B>` calling `f<B, A>`), which must stay legal.
