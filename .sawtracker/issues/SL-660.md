## Description

**What:** the `ZeroInit` marker conformance, and the refusal of a zero-initialized static that this module isn't entitled to build. Ruled by the user on Oct 14; the ruling is quoted in SL-648's comments.

**Mechanism closed:** sawc2 accepts a bare `static P: dep.Port` (no initializer) when `dep.Port`'s fields are all private and its only `init` validates. So zero-init builds a value no construction this module could write would produce, bypassing the type's invariant. SL-648 closes the same bypass for a type with an init override (`static.zero-init`); this issue closes it for hidden fields.

**The rule:** a bare static is legal when either:
- the declaring module could build the value field by field: every field visible to it, at any depth, and no init override (SL-648); or
- the type conforms to `ZeroInit`.

Otherwise it is refused, naming the hidden field or the override.

**`ZeroInit`:**
- a marker trait in the prelude's trait vocabulary, declared `extension T: ZeroInit {}` in the type's own module (the orphan rule);
- checked structurally: every field must be a scalar, a raw pointer, or `ZeroInit`, and an Optional zeroes to `None`;
- a type with an init override can't declare it;
- a generic type's conformance may be conditional on its parameters.

**Use site:** unchanged. A bare static is zero-initialized (.bss, no image bytes).

**Owed:**
- one funnel (SL-648's `check_zero_static` gains the hidden-field clause);
- a position matrix: field private at the top, nested, inside an array, behind a generic argument; a `ZeroInit` type; a conditional conformance; an override plus `ZeroInit` refused;
- std's `Mutex`, `Once` and `SpinLock` declare it as they reach sawc2's std, or say which issue ports them;
- docs: the spec's statics tier 1 and the Mutex/Once/SpinLock sections, the saw-lang skill, GRAMMAR.md if a name is added, and an SL:hazards entry for Stage 0, which has no `ZeroInit`.

**Depends on:** SL-648 (its zero-init walk and funnel).

**Air, pre-dispatch: the rule's first clause has to keep tier 1's validity half, which sawc2 doesn't check today.**

As written, the first clause makes a bare static legal when "the declaring module could build the value field by field". The spec's tier 1 asks a second thing: that "all-zero is a valid value of the type". A `String` has no hidden field, so the first clause alone keeps `static S: String` legal. Stage 0 refuses that, and so does tier 1.

`typecheck --check` on sawc2 at main (e0250b480) against Stage 0, one bare `static S: …` each:

| type | sawc2 | Stage 0 |
|---|---|---|
| `Int` | accepted | accepted |
| `String` | accepted | refused: "needs an initializer: … only when all-zero is a valid value" |
| `struct N { s: String }` | accepted | refused, the same |
| `struct N { v: Vector<Int> }` (NoCopy) | accepted | refused, the same |
| `struct N { m: M }`, `enum M { case A(n: Int), case B }` | accepted | refused, the same |
| `struct N { m: M }`, payload-free `enum M { case A, case B }` | accepted | accepted; a `match` reads `A` |
| `struct N { m: M }`, `enum M: UInt8 { case A = 1, case B = 2 }` | accepted | accepted (see below) |
| `struct N { m: M }`, `enum M: UInt8 { case A = 0, case B = 2 }` | accepted | accepted |

So sawc2 has no tier-1 validity check. Its backend's `backend.not-yet` for non-integer statics is the only thing stopping these today, and that goes away when statics of aggregates arrive.

**Points for the brief:**
1. **One structural test, used by both clauses:** every leaf of the zeroed value is a zero-valid scalar, a raw pointer, or `ZeroInit`. The first clause adds "and visible to this module, with no override at any depth"; the second replaces visibility with the author's declaration. `String`, `Vector`, `Box` and a payload enum fail at the leaf under both clauses.
2. **A raw-backed enum is zero-valid only with a `= 0` case.** Stage 0 accepts the `A = 1, B = 2` row, reads `raw 0` through `as UInt8`, and an exhaustive `match` over the two cases silently takes the first arm (it prints `read`). That's a value no case names. Pin it in the matrix, and give it an SL:hazards entry beside the "no `ZeroInit`" one, since Stage 0 has it today.
3. **`FuncPointer`, when it arrives, isn't "a raw pointer" here.** The spec makes it a safe type with closed construction, so a null one couldn't come from any expression. I couldn't probe it (sawc2's std doesn't declare it yet, and Stage 0 doesn't call a static one in this form), so it's a design point, not a finding.
4. **The generic payload.** `SpinLock<T>` vouches for its own private fields, so its conformance is conditional, `extension SpinLock<T: ZeroInit>: ZeroInit {}`. The spec's idiom `static LOCK: SpinLock<Counters>` then needs `Counters: ZeroInit`. Say whether an all-scalar struct satisfies that bound without a declaration (an automatic conformance would reopen the hidden-field case for a type with private scalar fields), or whether the idiom gains a line, `extension Counters: ZeroInit {}`. The spec's Mutex, Once and SpinLock sections need whichever answer it is.

**SL-660.p1 (z660zeroinit).**

- **The funnel:** one walk, `zero_fault` in `bodies.saw`, with entry points `check_zero_static` and `check_zero_init_declaration`. Both run in `check_zero_inits` after every body is typed, so a raw case's value is folded.
- **Valid at zero:** scalars, `Bool`, `Float`, raw pointers, an Optional (`None`), a payload-free enum, a raw enum with a `= 0` case, and a tuple, array or cell of valid parts.
- **A struct passes** when it has no override, its fields are all visible and every one is valid, or when it is `ZeroInit` and its conditions hold.
- **Your validity point:** bare `String`, `Vector`, payload enums, functions and `FuncPointer` are refused.
- **Rules:** `static.zero-hidden`, `static.zero-invalid`, `zeroinit.override` and `zeroinit.invalid`, plus SL-648's `static.zero-init`.
- **`ZeroInit`:** `public trait ZeroInit {}` in `std/prelude.saw`, as lang role 39 and `TcKnown.zero_init`. It is unbound under Stage 0's root.
- **Docs:** the spec's tier 1, the override, Mutex, SpinLock and Once sections and the prelude list; the skill; conformance rows B34 and B35.

The matrix is in `compiler/tests/typecheck/README.md`, every row pinned (golden `zero_init`, multi `zero_init_modules`, and the refusal fixtures).

**Sweep:**
- Nothing changes in std, rt, freestanding, libs or blade, none of which has a bare static.
- One compiler fixture now holds its enum as `Slot?`.

- `errors/borrowing_struct_type_positions` gains `static.zero-invalid` on two function-typed statics.
