**Interpolating a value whose `Printable.format` blocks is accepted, then fails in clang, from a task as from a thread.** Found by SL-776's sweep (agent p776), sawc2 Stage 2 from main 3e31616a1, the same at -O0 and -O2.

```saw
extern "C" {
    blocking func __saw_rt_blocking_sleep(ms: Int) -> Int
}
struct Slow { n: Int }
extension Slow: Printable {
    func format(&self, into: &var StringBuilder) {
        let _ = __saw_rt_blocking_sleep(1)
        try! into.append(value: self.n)
    }
}
func render() -> Int { "{Slow(n: 4)}".len() }
func main() {
    var group = TaskGroup()
    let h = group.spawn(render())
    print("rendered {}", h.join())
}
```

clang: `use of undefined value '@saw ….Slow.format(into: &var std.stringbuilder.StringBuilder)'`. A `Thread.spawn { "{Slow(n: 4)}".len() }` body fails the same way.

**Mechanism, UNVERIFIED:** the render is a call the compiler inserts (an interpolation rvalue, not a MIR call), so nothing marks it a suspension point: mono reaches `format` through `render_of` -> `member_item_at` as an ordinary item and the backend calls it plainly, while coro frames that item because its body blocks. `Printable.format` is not declared `sync`, so typecheck accepts the blocking body. Siblings to sweep: every compiler-inserted call whose target is user code that may suspend (render, a hand-written `copy()` hook is already refused by coro_refuse_copy_hooks, `equals`/`compare` behind `==`/`<`, `hash` behind a `Map` key, `deinit`).

Open question for a ruling: is a suspending `format` refused (typecheck, as the copy hook is), or rendered through a frame?

**What this says about the mechanism:**
- The render is the one inserted call that is neither a MIR call nor refused.
- `==`, `<` and `hash` reach user code through ordinary calls, so they suspend correctly, a genuine `yield_now` included (h10).
- h12 shows why plain `main` fails too. An explicit call to the frame-only `format` makes `main` a driven frame. The render marks nothing, so `main` stays plain and calls a plain item that is never emitted.
- So the gap isn't specific to tasks or threads. Every render site (interpolation, format arguments, `print(x)`, `panic`/`assert`) reaches `format` outside the suspension analysis.

**For the ruling, the evidence on each side:**
- **Render through a frame** (the render becomes a real call, a suspension point when its target's summary suspends). This is what `==`/`<`/`hash` already do (h3, h4, h5, h10). It fits design 120's rule that a suspending call works in any expression position, interpolation included. A caller can't see from `print("{x}")` that `x`'s format suspends, and colorless code shouldn't need to.
- **Refuse a suspending `format`.** The precedent is `deinit` (h6), refused because it "runs where nothing may suspend". Refusing at the declaration would also refuse the explicit calls that work today (h7, h12). A refusal would have to sit at the render site to keep them.
- **Either way, `panic`/`assert` need their own answer.** A message render that suspends lets sibling tasks run after the program has decided to panic and before it says so, and those tasks could act on state the panic is about. Refusing a suspending render there, while the other render sites go through frames, would be consistent with `deinit`'s reason.

SL-776 c2's verifier guard ("a plain call to a never-emitted item is a compiler problem, never a clang error") would catch these as well. Whatever the ruling, h1, h2, h8, h11 and h13 make a ready pin set.

**The user ruled (Oct 19): `format` is `sync`.** `Printable.format(into:)` (and, by the same reasoning, every hook the compiler calls in a render position) is a `sync` requirement: an implementation that suspends is refused at its conformance, and one that blocks is already refused by SL-782 1a. Rationale: printing must not do I/O or wait; `print`, interpolation and panic messages render into stack scratch with no allocation, and none of them is a suspension point. A type that needs async rendering exposes an ordinary method, and the caller fetches first and then prints.

**Scope:** the requirement declared `sync` (builtin/std) and the conformance check; a refusal fixture (a suspending `format`); the INVARIANT the plain-call guard raises today (SL-776) becomes this clean refusal; the spec's Printable section; and a sweep of std and corpus `format` bodies (none are expected to suspend). SL-782 1b-i's note: render sites run a pair's default, which a `sync` `format` makes moot for suspending defaults.
