## Description

**Faster builds 4c: module-local typed ids with per-module early cutoff.** This follows SL-955, where 4a gave std's front cache and 4b gave one layer per package, shipped in v0.20.0. The user ruled that 4c is a separate design, written once 4b was measured.

**The question:** 4b's cache works per package, so an edit to one module re-runs the front end for its whole package and every package above it. 4c would give each module ids local to it, so a module whose interface doesn't change stops the rebuild at that module, an early cutoff.

**Before any brief:**
- measure on sawc and on sawtracker, the largest non-compiler codebase: what an edit to one module costs under 4b, by stage;
- survey what ids are global today across resolve, typecheck and MIR, and what making them module-local would touch;
- write the design with the user. It is not dispatched until then.

**Related, still open:** the verifiers are about 30% of a warm build (SL-955 notes).
