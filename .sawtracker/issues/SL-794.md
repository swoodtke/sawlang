## Description

**`Void` derives no `Send`, so `Thread<Void>` (and anything holding one) is not `Send`** (found by SL-782 1b-ii, agent p782b2). A `Pool` holding `Thread<Void>` handles can't be moved into a `Thread.spawn` body (`spawn.send`), so the spec's `Pool` `retire` hand-off (thread-context drop) doesn't compile with that `Pool`. It predates 1b-ii.

`Void` has no state, so it is trivially `Send` and `Sync` (A17b already treats `Void`/`Never` as always crossing in its Send-on-frames gate, SL-579). The tier/auto-trait derivation (`compiler/typecheck/src/tier.saw` or wherever `Send` is derived for primitives) should grant `Void` (and `Never`) `Send + Sync`, matching Stage 0 if Stage 0 does (check).

**Obligation 4, a class:** "a primitive with no state missing an auto trait". Check `Void`, `Never`, `()` and empty tuples or structs for `Send`, `Sync`, `Copy`, `Equatable` and `Hashable`, each against the spec's auto-trait rules.

**Pin:** `Thread<Void>` in a struct moved into a `Thread.spawn` body compiles and runs (the spec's `Pool` hand-off).
