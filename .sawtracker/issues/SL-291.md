## Description

SL-260's differential found Python sawc rejecting implicit Result payload wrapping at assignment destinations, while the prototype implements the declared-slot rule. Observed at 6f307c11; source unchanged at 6a6d57bd.

Two existing minimal target shapes:

* prototypes/minivm/examples/results/review_composition.saw:6: `value = Trouble(message: "changed")` where `value` is `&var Result<String, Trouble>`; rejected as `cannot assign Trouble to referent of type Result<String, Trouble>`.
* prototypes/minivm/examples/results/match_snapshot_ownership.saw:12: `source = "changed"` where local `source` is `Result<Message, String>`; rejected as `cannot assign String to variable of type Result<Message, String>`.

Expected: choose the unique matching Result payload and construct Err at the destination, preserving normal transfer/ownership checks. LANGUAGE_SPEC.md, Auto-Wrap, says construction fires wherever a value lands in a declared Result slot. This is a Python over-rejection, not a requested weakening of the prototype.

Mechanism: statements.py::_check_assign_rhs is the common assignment reconciliation funnel. It pushes the expected type, checks the RHS, handles bare None for Optional, then tests compatibility; it never calls the Result wrapping machinery. Both local assignment and reference replacement reach it.

Required scope: audit all nine assignment target kinds listed by _check_assign_rhs (local, static, reference, self replacement, field, named tuple, tuple index, array/pointer element, borrowing place). Add positive Ok/Err/exact-Result assignments plus ambiguity and ownership controls, and route wrapping through the existing transfer checkpoint. Do not duplicate the conversion in each target handler. SL-79/SL-211 concern ownership of return wraps and do not cover this refusal.
