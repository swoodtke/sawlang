## Description

Unit A of SL-209 (ownership uniformity). Plan steps 2-3. FOUNDATION — start here. USER PRIORITY.

## Step 2 — inventory every ownership boundary
Separate two questions:
- WHERE does a value acquire a new owner? Bindings, assignment, arguments, returns, aggregate elements, captures, loop results.
- HOW does an expression produce that value? Existing storage, fresh construction, explicit move, borrowing, or forwarding another expression's result.

Establish ONE table of rules (source -> transfer into an owned destination):
- Fresh owned temporary -> transfer its ownership; no additional copy.
- Existing `Copy` value -> duplicate using the type's copy operation.
- Existing `ExplicitCopy`/`NoCopy` value -> require explicit duplication or a legal `move`.
- Borrowed storage -> apply the referent's copy policy; borrowing does not grant ownership.
- Explicit move -> transfer ownership and retire the source.
- Diverging expression -> no value and no transfer.
Preserve existing partial-move and `NoMove` restrictions: a field projection must not become movable merely because it reaches the common checker.
DELIVERABLE: a checked-in inventory mapping every boundary and producer to its implementation and its conformance tests.

## Step 3 — record an explicit decision on each transfer
Evolve `_check_value_transfer` (`sawc/typechecker/types.py:4372`) from "may report an error and set `needs_copy`" into an operation that produces a STRUCTURED ownership decision identifying:
- Source binding or place, by STABLE IDENTITY (not spelling).
- Destination and diagnostic location.
- Action: take-temporary, copy, move, or no-value.
- Required cleanup-state change.
- Any generic copy requirement awaiting specialization.
Attach the decision to the TRANSFER OCCURRENCE, not to the expression node — evaluating an expression and transferring its result are different operations. "Checked and needs no copy" MUST differ from "never checked"; a false/absent `needs_copy` cannot establish that distinction.

## Acceptance
Every successful ownership boundary carries an explicit decision, INCLUDING trivial copies. The inventory (step 2) is checked in and maps each boundary+producer to impl + conformance tests.

## Step 3 — the structured decision

`sawc/typechecker/ownership.py`. `_check_value_transfer` now returns a
`TransferDecision` on EVERY exit path, carrying the five things this issue
asks for: the source by STABLE IDENTITY (`VariableInfo.binding_id` plus a
projection path — never the spelling), the destination and diagnostic site,
the action, the required cleanup-state change, and any generic copy
requirement awaiting specialization. Eight actions, each earned by an arm the
function demonstrably has: `take` / `copy` / `move` / `none` from the issue's
rule table, plus `borrow`, `refused`, `delegated` (a value branch, whose arm
keys it carries) and `deferred` (design 218c's provenance skips and design
219's abstract tier).

Attached to the TRANSFER OCCURRENCE, not the expression node: the ledger key
is `(source node_id, destination context, line, column)` and the node id is in
it only to NAME which occurrence. Living outside the AST is what makes it
correct — `dataclasses.fields()` cannot see it (so the design-126 contract has
nothing to declare and `substitute_ast_types` nothing to walk), a
monomorphized clone gets fresh node ids and therefore its own decisions, and
the table is per-compile so `reemit`/`irdet` byte-identity is untouched.
Assign-never-accumulate per design 218 stage 1, with a `revision` counter.

"Checked and needs no copy" is now distinguishable from "never checked" by the
PRESENCE of an entry, and that property is enforced statically:
`tools/test_transfer_decisions.py` parses the checkpoint and fails on a bare
`return`, a `return` of anything that is not a recorded decision, or a
function that can fall off its end — then checks a ten-fixture boundary
matrix. Wired as the `transferdecisions` battery stage. Acceptance's "INCLUDING
trivial copies" is met: the `free`-tier fall-through that used to leave no
trace is now an explicit `copy` record, and the fresh-temporary path an
explicit `take`.

Cost: +2.5% on a small compile (1.752s -> 1.796s, 9 samples each), flat on a
large one.

## Findings — three unchecked boundaries, filed and NOT fixed

Each changes which programs compile, so fixing one here would have broken this
unit's behaviour-preserving contract. All measured with compile-and-run
evidence; evidence lives in the issues.

- **SL-218** — a `self` receiver read is not an aliasing expression, so every
  by-value transfer of `self` is judged a fresh temporary. Double free at exit
  0 across six faces (return, argument, `let`, struct field, tuple element,
  `&var self`); SIGABRT on ExplicitCopy; CORRECT on `Copy` — because codegen's

  opinion can mint a missing retain, it cannot deliver a missing refusal.
- **SL-219** — `try` / `try!` / `try?` / `try ... catch` over a BINDING or a

  control row: a payload extracted from a fresh temporary inline is never

Requested changes on patch SL-210.p1 (revision 1)

Review of SL-210.p1 revision 1 (applied commit 52390666, base b53a844c): requesting changes for two defects in the new ownership records. These concern Unit A's own record contract, not the separately filed pre-existing language defects in SL-218/219/220.

1. [P2] Capture the resolved source binding before its scope is popped.

Location: sawc/typechecker/ownership.py:391-395 (_transfer_binding_id).

The ledger obtains a supposedly stable source identity by looking up the expression's spelling in current_scope at the time the boundary is recorded. That scope is not necessarily the expression's original scope. Body tails are checked after their body scope has been popped, and the value-branch recursion likewise visits branch results after their inner scopes have gone away. This loses the ID for a local tail return and, more seriously, resolves a shadowed branch result to a DIFFERENT binding.

Tested example:

```saw
func choose(flag: Bool) -> Int {
    let x = 7
    let y = if flag {
        let x = x + 1
        let z = x
        print(z)
        x
    } else { x }
    y
}
func main() { print(choose(true)) }
```

Collected the new transfer decisions through tools/test_transfer_decisions.py's compile_and_collect. In one checking pass, the `let z = x` transfer correctly used inner binding_id 3811. The immediately following branch-tail `x` used outer binding_id 3810, identical to the else-arm `x`. The absolute counters vary per compile; the incorrect equality is stable. The function-tail `y` had binding_id=None. A separate NoCopy `move x` tail likewise produced action=move / cleanup=retire-source / binding_id=None.

This prevents a later consumer from reliably selecting which source to retain or retire, directly violating SL-210's stable-identity requirement. Preserve the resolved binding identity while checking the expression, or pass the owning scope/identity explicitly to the boundary record; do not re-resolve a spelling in the later ambient scope. Add assertions for the actual IDs in tail-return and shadowed value-branch fixtures, not only source.kind.

2. [P2] Record diverging sources as no-value rather than adopted temporaries.

Location: sawc/typechecker/types.py:4741-4748.

The non-aliasing branch classifies every non-aliasing expression as ACTION_TAKE / CLEANUP_ADOPT_TEMPORARY without first excluding Never. A valid binding whose initializer diverges therefore records an ownership acquisition that can never occur:

```saw
func main() {
    let x: Int = panic("stop")
    print(x)
}
```

Compilation succeeds. Its `let binding` decision is source_type=Never, action=take, cleanup=adopt-temporary. SL-210 explicitly requires a diverging expression to have no value and no transfer; ownership.py's ACTION_NONE documents that rule too. Record ACTION_NONE / CLEANUP_NONE for the diverging case before the fresh-temporary classification, while retaining an explicit ledger entry. Add a fixture checking Never's action and cleanup together.

Validation: isolated worktree at the patch's exact base; custom compile-and-collect probes for local tails, NoCopy move tails, shadowed branch results, and Never initializers. The new transfer-decision gate passes (10 fixtures); the citation gate also passes. The tracker reports 2431 compiler tests passed, 10 expected failures, and all 36 freestanding tests passed for 52390666. Full server gates were not repeated locally. These findings affect the new metadata rather than asserting a change in generated program behavior.
