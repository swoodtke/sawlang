## Description

**The hosted runtime ignores `align` above malloc's 16, and `runtime/ABI.md` calls alignment optional.** `__saw_rt_alloc` is `malloc(size)` on the host (`runtime/common/mem.saw`); ABI.md says "`align` is currently ignored ... A runtime that honors alignment may use `align`". sawc's IR states the alignment of what it loads from an allocation, and since SL-1158 a by-address aggregate parameter is declared `align A`, so alignment is a requirement. A user's `GlobalAllocator().alloc(size, 64)` returns a 16-aligned block on the host today, which breaks that.

To do:
- The hosted body honours any power-of-two `align`: `malloc` when `align <= 16`, otherwise `posix_memalign` or `aligned_alloc` (and `dealloc` frees the matching kind).
- ABI.md says a runtime MUST return a block aligned to `align` (a power of two, at least up to 4096, `@align`'s cap).
- Fixtures: a run probe allocating at 32, 64 and 4096 and checking each address on the host. Confirm whether sawc or std ever requests size 0, and state the answer in ABI.md.

Related: SL-1158; sawos's allocator (told, Nov 18).

**Lead's note with p1 (Nov 18).** Evidence: `.build/scratch/p1167/` in the lead's checkout.
- **`runtime/common/mem.saw`:**
  - `__saw_rt_alloc` takes `malloc` for `align <= 16` (malloc's `alignof(max_align_t)` on every hosted target) and `posix_memalign` above that. A non-zero result becomes NULL.
  - The deny-after hook sits in front of both paths. `__saw_rt_dealloc` stays `free`, which releases both kinds of block.
  - Size 0 is served as 1 byte, because malloc(0) and posix_memalign(..., 0) may return NULL.
- **`runtime/ABI.md`:** a runtime MUST return a block aligned to `align` (a power of two, at least up to 4096, `@align`'s cap), because sawc's IR relies on it. `dealloc` gets the matching size and align. Size 0 is requested: std does it for a zero-sized element or payload (`Vector<Empty>.push`, `Box.make(Empty())`, measured with a logging build in `size0_log.txt`).
- **Every allocator in the tree:**
  - The freestanding suite's bump arena already rounds the address; it is unchanged.
  - The two probe-local hosted providers (`runtime_provider.saw`, `cooperative_executor_seams.saw`) were `malloc` and are fixed the same way.
  - The corpus `Allocator` conformances delegate to `GlobalAllocator`.
  - sawos's allocator (TLSF) honours any power of two (chat m1336).
- **Test:** `global_allocator_honours_align.saw` (stated, `-O0`/`-O2`, no leaks):
  - It allocates at alignments 1 to 4096, writes each whole block and deallocates it. It also covers size 0, and the deny hook at align 64 and 8.
  - On the base it is red at 64 and 256 in five runs of five (`misaligned 64 at 32`). Align 32 and 4096 passed by luck there.
- **Gate:** run.py (`seed,units,golden,subset,fixture_whitespace,std,comments,programs`) green; `tools/battery.sh citations freestanding abidoc` green (209); lint ok.
- **Left for a follow-up:** `conformance/N11_align_refuses_frame_resident_local.saw` gives "the seam's `align` is documented as ignored" as the reason `@align` on a frame-resident local is refused. That reason no longer holds. Rewording the comment would detach the corpus row, and the refusal itself is a language question, so it is filed separately.
