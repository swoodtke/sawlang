## Description

**The hosted runtime ignores `align` above malloc's 16, and `runtime/ABI.md` calls alignment optional.** `__saw_rt_alloc` is `malloc(size)` on the host (`runtime/common/mem.saw`); ABI.md says "`align` is currently ignored ... A runtime that honors alignment may use `align`". sawc's IR states the alignment of what it loads from an allocation, and since SL-1158 a by-address aggregate parameter is declared `align A`, so alignment is a requirement. A user's `GlobalAllocator().alloc(size, 64)` returns a 16-aligned block on the host today, which breaks that.

To do:
- The hosted body honours any power-of-two `align`: `malloc` when `align <= 16`, otherwise `posix_memalign` or `aligned_alloc` (and `dealloc` frees the matching kind).
- ABI.md says a runtime MUST return a block aligned to `align` (a power of two, at least up to 4096, `@align`'s cap).
- Fixtures: a run probe allocating at 32, 64 and 4096 and checking each address on the host. Confirm whether sawc or std ever requests size 0, and state the answer in ABI.md.

Related: SL-1158; sawos's allocator (told, Nov 18).
