## Description

**`assign.rhs-borrow` refuses an assignment whose right-hand side borrows the root only for a value, which the spec accepts** (found by p847, SL-847, Oct 23; repro `scratchpad/p847/p847_rhs.saw`, user types only; corpus row `place_two_windows_one_nocopy_root`, lines 57 and 65).

`borrow var h.at().n = borrow h.at().n + 10`, where `at` is `(&var self) borrows -> &var Cell` with no shared twin, is refused: "`h` is written by this assignment while its right-hand side borrows `h` exclusively at 57:27; the right-hand side runs first, so what it writes through that borrow is overwritten". It's the same on a Copy-tier type. The spec's Assignment section says a borrow whose result is only a value doesn't conflict, because it closes at the read, before the target's borrow opens (`borrow var v[i].x = borrow v[j].x` is its example). SL-838 made MIR close such windows at the read. The corpus program states `EXPECT: success` (DF-218j).

**Mechanism (UNVERIFIED, p847):** the rule reads the root's charge (exclusive, because `at` has only the `&var self` form) and refuses any exclusive right-hand-side borrow of the root, without asking whether that borrow ends in a value that closes before the target opens.

**Scope:** the rule asks the same "only a value" question as MIR's `close_windows_since` funnel (SL-838) and SL-844's fresh-value close, one source of truth, not a second copy. Obligation 4: right-hand side {a `borrow` value read, a fresh call off the chain, a by-reference argument, a `borrow` kept as a reference} × the accessor {exclusive only, with a shared twin} × the target {the same place, a sibling field, another element}. Pins: accepted cells run right (print order shows the close), refused cells stay refused with the existing message.

Approved patch SL-857.p1 (revision 1)

**Air: SL-857.p1 approved.** Reviewed r1 on 406686b8f.

**The asymmetry is the spec's.**
- **Forward order accepted:** a value-only `borrow` closes at its read, before later arguments run (spec "Window extent and nesting", and the `show(borrow doc.section("net").title(), next())` example).
- **Mirror refused:** a nested call's `&var` joins the outer call's access set and extends over the whole call expression (spec "Nested calls"), so a later value read overlaps it in both spellings. The `.get()` spelling's acceptance on main was the node-stamping leniency the lead names.

**Base vs patch, exclusive-only accessor (no shared twin), owning `String` fields (`a3`):**

| right-hand side | main 406686b8f | + SL-857.p1 (-O0 and -O2, ASan clean) |
|---|---|---|
| `borrow var h.at(0).s = borrow h.at(1).s` (copied out) | `assign.rhs-borrow` | `a.s beta` |
| `h.t = borrow h.at(1).label()` (a fresh call) | accepted | `t beta#2` |
| `borrow var h.at(1).s = borrow h.at(1).label()` (the same place) | accepted | `b.s beta#2` |
| `borrow var h.at(0).n += borrow h.at(1).n` (compound) | `assign.rhs-borrow` | `a.n 3` |

The first and fourth rows are the bug. A 2,000,000-iteration loop of all three String forms peaks at 1.4 MB resident, so the copied-out and replaced Strings are retained and released once each.

**Unchanged, and consistent with R3** (a reference handed to a callee stays refused). Both are recorded identically on the base, using a base build:
- `h.k = if borrow h.at() == other {…}` and `borrow var h.at(0).s = "{borrow h.at(1).n}-x"`: comparing or rendering the place hands `&self` to `equals`/`format`. That's the same shape as the new `assign.rhs-borrow.shared-reference-argument` fixture, so both are refused.
- `h.k = match borrow h.at() {…}` is accepted, since a `match` isn't a callee.

One observation for the lead, not a blocker: an interpolated `Int` field (`"{borrow h.at(1).n}"`) is refused, while `borrow h.at(1).n + 0` is accepted. That follows the spec's "rendering … the place", but a reader may not expect it. If it's meant, the refusal's text could suggest the hoisted binding.

**The spec's own examples** (`a1`) run unchanged before and after: `borrow var v[i].x = borrow v[j].x`, `borrow var v[0].n = v.pop()!.n`, a `String` field, the compound, and SL-847's Map forms (`m["a"] = borrow m["b"] + 10`, `borrow var m["b"] += borrow m["a"]`).
