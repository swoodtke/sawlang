## Description

**`assign.rhs-borrow` refuses an assignment whose right-hand side borrows the root only for a value, which the spec accepts** (found by p847, SL-847, Oct 23; repro `scratchpad/p847/p847_rhs.saw`, user types only; corpus row `place_two_windows_one_nocopy_root`, lines 57 and 65).

`borrow var h.at().n = borrow h.at().n + 10`, where `at` is `(&var self) borrows -> &var Cell` with no shared twin, is refused: "`h` is written by this assignment while its right-hand side borrows `h` exclusively at 57:27; the right-hand side runs first, so what it writes through that borrow is overwritten". It's the same on a Copy-tier type. The spec's Assignment section says a borrow whose result is only a value doesn't conflict, because it closes at the read, before the target's borrow opens (`borrow var v[i].x = borrow v[j].x` is its example). SL-838 made MIR close such windows at the read. The corpus program states `EXPECT: success` (DF-218j).

**Mechanism (UNVERIFIED, p847):** the rule reads the root's charge (exclusive, because `at` has only the `&var self` form) and refuses any exclusive right-hand-side borrow of the root, without asking whether that borrow ends in a value that closes before the target opens.

**Scope:** the rule asks the same "only a value" question as MIR's `close_windows_since` funnel (SL-838) and SL-844's fresh-value close, one source of truth, not a second copy. Obligation 4: right-hand side {a `borrow` value read, a fresh call off the chain, a by-reference argument, a `borrow` kept as a reference} × the accessor {exclusive only, with a shared twin} × the target {the same place, a sibling field, another element}. Pins: accepted cells run right (print order shows the close), refused cells stay refused with the existing message.
