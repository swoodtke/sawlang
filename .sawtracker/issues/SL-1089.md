## Description

**Release v0.23.0.** User instruction (Nov 13): finish the last ESP32-S3 issue, then tag another release. It waits for SL-1087 (the `Result` fix sawos reported), which must be in it.

**The patch:** `.sawtracker/version` becomes `v0.23.0` and `driver_version()` in `compiler/driver/src/main.saw` becomes `"0.23.0"`, which run.py's `version` step holds equal. The server creates the annotated tag at the patch's merge commit (ST-46).

**Why 0.23 and not 0.22.1:** main has two new refusals since v0.22.0 that can reject a program v0.22.0 built (SL-1006, SL-1018), a new command (`sawc tools`), and after SL-1087 a changed meaning for one shape (an error enum's case in a `Result` slot is `Err`).

**What v0.23.0 holds beyond v0.22.0** (each merged; ancestors of the tag are verified at landing):
- **SL-1087:** a raw-backed error enum's case in a `Result` slot is `Err`, never `Ok(raw value)`.
- **SL-1006:** a closure literal standing as a statement is a compile error (it used to compile and never run).
- **SL-1018:** a `@synthesize`d `Copy` or `ExplicitCopy` is checked member by member, and refused beside a written `deinit`.
- **SL-934 and SL-1083 part 1:** an `@section` placement is kept through the optimizer and a collecting link, exported or not, suspending or generic included.
- **ESP32-S3:** the suite's Blade package case (SL-1073), the 32-bit word check and the builtin check for Xtensa (SL-1076, SL-1081), the docs and the `[sos]` manifest's specification (SL-1077), and SL-1085: `sawc tools`, Blade finding Espressif's tools by itself, `[sos.priorities]` read in either spelling and an unknown `[sos]` subtable refused, the link script's literal order.
- **Gate health:** SL-1079 (a passing run prints no `failed`; the twin hands on output of any size).

**For a project moving its pin from v0.22.0** (sawos): SL-1006 and SL-1018 can refuse code that built; SL-1087 changes `Ok(raw)` to `Err` at the affected sites with no source change; Blade refuses an unknown `[sos.<name>]` subtable (every one in sawos is a known triple, by the Air's count).

**Landing:** `git rev-parse v0.23.0^{commit}`; check each commit above is an ancestor; post the version and sha to the sawos lead in chat.
