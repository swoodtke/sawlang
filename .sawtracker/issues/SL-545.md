**Epic (the user, Oct 12): sawc2 coroutines, planned in full before any implementation, with the Air reviewing the plan as it is written.**

sawc2 has no coroutine lowering today. Every suspending construct (`await`-free colorless suspension, tasks, `TaskGroup`, channels, the reactor's parks, `sleep`, `yield_now`, the op budget) is refused or unreachable in its backend slice. This is the largest single gap between sawc2 and what Stage 0 compiles, and it blocks Blade, `libs/`, most of `examples/` and sawos from moving off Stage 0 (milestone 2: deleting `sawc/`).

**The plan document is `SL:coroutines`.** It turns SL:architecture §3.9 (the already-agreed design: the "definitely suspends" fixpoint after mono, by-value frames packed by storage lifetime, teardown keyed by state, the closed `park(reason)` executor protocol, a post-lowering MIR verifier), LANGUAGE_SPEC §6 (Concurrency), `sawc/rt/ABI.md`'s reactor and task seams, and the new std's needs into an ordered list of small, separately landable units. Each unit has:
- its scope and dependencies;
- the files and stages it touches, for agent overlap planning;
- its pins: run-lane programs against Stage 0, MIR and frame goldens, verifier injections;
- the questions it leaves for the user.

Stage 0's `sawc/coro_transform.py` (design 275's discovery ledger, `coro_shapes.py`'s shape table) is the BEHAVIOURAL oracle: which shapes suspend, and what each must print. It is not the template, since §3.9 deliberately departs from it (state-keyed teardown, storage overlay, MIR-level lowering).

**Process:**
1. A planning agent drafts `SL:coroutines` section by section.
2. The Air reviews each section as it lands, in doc threads.
3. Fundamental questions go to the user in SL:open-questions.
4. The user approves the plan.
5. Only then are units filed as children of this epic and dispatched.

**Two requirements added by the user (Oct 12), beyond Stage 0:**
1. **A stack-like frame layout:** storage-lifetime packing, as SL:architecture §3.9 rules, instead of a slot per spanning local plus a sum of the children. These are core units.
2. **Optional heap frames for recursion,** as a later phase, with the resume ABI made uniform from the first unit so the phase is an extension. The same driving ABI unlocks suspending `any Trait` and closures. The design questions (opt-in versus automatic, allocation failure, static size, cancellation) go to the user in §5.

The lead's rough guide: a Stage 0-equivalent lowering is about 3 weeks of units; the overlay adds 3–5 days; heap frames add 1–1.5 weeks. The plan's per-unit estimates replace this.

**Air, a finding for the lead to file (coroutines, verifier rule 1): a zero-size frame slot at the frame's end fails "a slot lies past the frame's end".** It's on main at b4b4e8d80, and Stage 0 builds both programs and prints 300. Probes are in `.build/scratch/air-review/sl662/` on the Air.

**Repro:**
- `v4_empty_struct.saw`: a driven loop with an empty-struct local `let m = Marker()` declared before the loop and read after it.

  > `verify rule 1 (frame in place): f(n: Int) task root: a slot lies past the frame's end, 40 bytes: (*_8).[40: v4_empty_struct.Marker]`
- `v2_try_push.saw`: `try! v.push(i)` in a driven loop. The `try!` payload's `Void` local lasts to the function's end, so it is frame-resident.

  > `… past the frame's end, 72 bytes: (*_13).[72: Void]`

The same program written ordinarily, a `Vector<String>` filled in a driven loop, hits it. That's how I found it, while checking SL-662's growth loop.

**Mechanism:** `compiler/coro/src/verify.saw`'s rule-1 bounds check is `offset >= size`. A zero-size value laid last sits at offset == frame size, which is in bounds, because it occupies nothing. So the check over-refuses exactly those slots.

It isn't specific to A9, but A9 is what puts zero-size locals across a suspension routinely: every loop in a framed body now suspends, and `try!` of `Result<Void, E>` is everywhere. With an explicit yield and no loop (`v3`, `v5`), the zero-size slot happened not to come last, and both build.

**Fix, either:**
- the check becomes `offset + slot size > frame size`; or
- the layout gives zero-size values no frame slot at all. Then the check stands, and nothing is stored for them, which is arguably the cleaner end.

**Sweep, before the fix (obligation 4):** an empty struct, `Void` from `try!`, an empty tuple, `[T; 0]`, and an enum with no payload and one case. Pin `v2` and `v4`.
