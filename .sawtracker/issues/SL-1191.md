Found by the SL-1190 sweep (`.build/s1190/`, `fs_module.log`).

The freestanding case `section_walk`, built with `SAWC_CODEGEN_UNITS=module`, has all four `@section("saw_table")` entries present and correct, but in the order `4,1,2,8` instead of `1,2,4,8` (the `@export`ed one first). This holds on riscv32, arm64, xtensa and xtensa-windowed, and under `--lto=thin`, `none` and `full`. The case pins "the order the object lists them". With one unit, the order is source order.

**Cause (UNVERIFIED):** the order in which the units are joined by `-r`.

**Owed:** decide whether the order of placements is a promise (SL-1104 asks this), and then make a split build keep it, or state that it doesn't. This blocks a split default for `--freestanding` (SL-1190, ruling 2).
