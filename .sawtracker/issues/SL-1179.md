**A deadlock among pool frames that wait in place on different workers hangs unreported.**

**The probe:** SL-1161.p1 r4's `.build/scratch/p1161r4/probes/walk_active_t2.saw`. It hangs 3/3 both before SL-1161 and after it.

**The mechanism** (from the r4 agent): each frame is ACTIVE, waiting in place in a join on its own worker. Each worker's deadlock walk reads the other worker's active slot as running, so no walk ever concludes. K205 names this case as out of scope today: "a pool join made by a pool's task (the joining frame reads as running on its worker)".

**Why it matters:** never-hide-errors. A silent hang is the worst failure shape for a deadlock.

**Directions** (unruled): workers publish "waiting in place on word W" beside their active slot, so a walk can treat an active-but-waiting frame as blocked and follow the wait graph. Or a pool task's join parks rather than waiting in place, which is design 1161 §6's open alternative, now plausible since a worker runs its own groups between turns.

It follows SL-1161 (the pool's progress and walk changes land there first).

**Design input from SL-1161 r6 (Nov 25).** SL-1161 r6 built a lock-waiter edge for the deadlock walk ("W"), and the review showed it unsound. It is dropped from SL-1161, and a sound reporter for lock-blocked and in-place-on-different-workers deadlocks belongs here. Lessons (`.build/scratch/p1161r7/review_r6.txt`, probes f487–f493):
- **Register a waiter only while it waits,** and release at the acquire. A per-acquisition, never-released 64-entry list silently disables reports after about 64 locking threads.
- **An executor may run user code on the holder's thread after its slot goes inactive** (retire, then `drop_held_result`, then a deinit). "A waiting thread runs code only in an active slot" is false there.
- **A thread with no executor record** (a `blocking` main that never drove, or a foreign thread) can be the only sender. The walk must not count it as blocked.
- **A task join and a thread join share a park tag.** Tell them apart before reading a thread control block.
- **Two workers each waiting in place** see each other's active slots as running (`inplace2_dl`).
- **Cost:** W made contended `Mutex` about 2.5× slower. A sound design should be measured against r4.

Shapes to pin when this is built: `coopchild`, f493's `lockwin_thread_sender`, `inplace2_dl`, and f489/f490 at 64+ threads.
