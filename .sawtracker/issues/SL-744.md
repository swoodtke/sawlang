**`A(x)` for a distinct alias over a struct resolves as the struct's construction, not the alias's.** Found by SL-721: `import247b_pair_one_identity.saw` moved from `slice.not-yet` (its existential calls) to `refused typecheck type.mismatch` at `Outline(inner)` (`type Outline = pair247b.Widget`), and the program is valid (Stage 0 runs it).

**Repro** (`.build/scratch/p721/t/alias2.saw` in the p721dyn worktree), refused by `sawc2 typecheck --check --std-root std`:

```saw
struct Widget { n: Int }
extension Widget {
    init(count: Int) -> Widget { Widget(n: count) }
}
type Outline = Widget
func main() {
    let w = Widget(count: 9)
    let outline: Outline = Outline(w)
    print("{}", (outline as Widget).n)
}
```

> `call.no-match: no candidate takes these arguments; the candidates are Widget.init(count: Int) [alias2]; Widget(n: Int) [alias2]`

The qualified spelling in the corpus program picks `init(count:)` and reports `expected Int ... found pair247b.Widget` instead.

**Mechanism (UNVERIFIED, from the candidates the refusal names):** an alias's construction `A(x)` reaches the construction candidates of the type the alias names (its `init`s and its memberwise construction) before, or instead of, `alias_construct` (`compiler/typecheck/src/bodies.saw`), so whenever the underlying is a struct the alias conversion is never a candidate. Confirm by tracing which arm of the call dispatch takes `Outline(...)` when `Outline`'s underlying is a struct versus an `Int` (design 250's `Byte(...)`, which works).

**Sweep before the fix (obligation 4):** an alias over a struct with and without an `init`, over a generic struct, over an enum (refused by design), over a qualified type; and each position `A(x)` can stand in.
