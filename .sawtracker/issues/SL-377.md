## Description

A cast to an optional type is refused with a message that does not explain itself. On main:
- `(n as Int?) ?? 9` with `n: Int?` says ``cannot cast `Int?` to `Int?` ``. It reads as the compiler refusing an identity.
- With `n: Int8?` it says ``cannot cast `Int8?` to `Int?` ``.
- `n as Optional<Int?>` says ``cannot cast `Int?` to `Int??` ``.

The rule itself is intended: a cast converts a value and never produces an optional (SL-309, amended ruling c2). The message should say so and name the ways out:
- coalesce first, then convert: `(n ?? 9) as Int`;
- unwrap with `if let` / `guard let`, then cast the payload;
- for a non-optional source, let assignment auto-wrap it (`let x: Int? = n as Int`) rather than casting to `Int?`.

Mechanism, per obligation 4. Name the check that produces "cannot cast" in the typechecker's cast path, then sweep every place an optional can appear on either side of `as`:
- an optional target;
- an optional source with a non-optional target (`n as Int` where `n: Int8?`), which probably gives the same unhelpful message;
- an optional nested inside a generic target (`x as Vector<Int?>`);
- an existential target over an optional source.

Each cell gets a pinned diagnostic in examples/errors/. This is diagnostics only; no cast gains a meaning.

Filed by the lead from the U0′ r2 review (SL-2.p2). Small; fits any lane after U0′ lands (the parser's cast-target note, which teaches the same rule, is in U0′).
