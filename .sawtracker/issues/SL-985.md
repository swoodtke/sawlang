## Description

**Joining N finished tasks of one `TaskGroup()` one by one is quadratic in N, on main.** Found by SL-977 unit 3 while measuring its sweep.

**Evidence** (`.build/scratch/p977c/bench_expired.saw` and `probe_bench.py`): N tasks each sleep 10 ms once and return. One sweep wakes them all, and then `main` joins the N handles in order. Those N−1 joins after the first dominate the process's instructions retired, with r about 3.5 to 4.0 on main's std (r = (I(2N) − I(2)) / (I(N) − I(2)), so about 2 is linear). They take 28 ms at N = 8,000.

**Mechanism:** not yet named. A first guess (UNVERIFIED) is that each join walks the group's slots, or sweeps the run queue, from the start.

**Direction (obligation 4):** profile it and name the mechanism. Then sweep its siblings with timings:
- joins in reverse order;
- a pool's joins;
- group teardown with N finished tasks;
- `Task.spawn` handles.

Make each near-linear, and pin it with a complexity-lane shape that counts a program run, not a build.

**SL-985.p1: joining N tasks one by one is near-linear**

- **Mechanism (profiled):** `Task.join` called `group_on_this_stack`, which walked every slot. Finished slots are recycled onto `free` and never leave `slots`, so each join cost O(N): 2,558 of 2,565 samples sat there, with r 3.96 to 3.98. Siblings also scanned from slot 0 per join, resume or worker turn: `has_live` and `live_besides` (called after every resume in a teardown), the sweep walk, `idle`, `SleepQueue.rebuild` and the pool's `worker_turn`. And each sweep built a fresh `SleepQueue`.
- **Fix** (`std/taskgroup.saw`):
  - **`LiveSlots`:** a three-level bitset plus a count, with its ENTRY POINTS listed. Only `place` adds and only `complete` removes, which are the only writes of `done`. It lives behind one pointer, allocated on a group's first spawn through the spawn path's existing `exec_alloc` and freed at teardown.
  - **O(1) checks:** `has_live` and `live_besides` become O(1). The walks step through `next()` in the same ascending order.
  - **Joins:** `group_on_this_stack(g, slot)` reads one slot.
  - **The sleep queue** persists in `ExecutorRecord.wake`, passed by pointer since nested sweeps reach it.
- **Census r** at N=4k and 8k, before → after:

  | shape | before | after |
  |---|---|---|
  | joins in spawn, reverse or random order | 3.96–3.98 | 1.99–2.00 |
  | `Task.spawn` joins | 3.96–3.98 | 1.99–2.00 |
  | cancel then join | 3.96–3.98 | 2.02–2.04 |
  | expired sleepers joined | 3.96–3.98 | 2.06–2.08 |
  | teardown of tasks not yet run, or that yield | 3.73–3.94 | about 2.00 |

  The pool's whole run at N=16,000 went from 752M to 82M instructions.
- **Size:** `TaskGroup` is 184 bytes, against 176 on main (+1 word). `sendable_closure_spawn.main()`'s frame goes from 440 to 456. The 31 coro goldens are re-recorded, and the masked diff holds only std items plus that frame.
- **Pin:** `probes/task_joins_scale_linearly.saw` requires each phase's work at 2N to be under 3.0× its work at N, across seven rows. The counter is declared from Saw, with no `.c` file: `proc_pid_rusage` via `dlsym` on macOS, `perf_event_open` via `syscall` on Linux, and a `clock_gettime(CLOCK_THREAD_CPUTIME_ID)` fallback. It alternates N and 2N over 7 rounds and keeps each size's least.
  - Main's std fails all seven rows, and undoing each fix fails its row.
  - 50 of 50 loaded runs pass at -O0 and -O2 in the VM, with 8 busy loops and a host load of 64. The VM run lane passes on aarch64 and x86_64.
