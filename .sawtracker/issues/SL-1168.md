## Description

**`String`, `StringBuilder` and `Arc` take no allocator type parameter, so text and shared values cannot live in a named heap.** Requested by sawos (chat m1341, Nov 18), from SO-142 phase 2 (`SO:heap-growth`). A process wants its logs in PSRAM while its working memory stays in SRAM. `Vector`, `Box`, `Map` and `Set` already take an `Allocator`: a `mono --check` probe of `Vector<UInt8, Heap<DATA>>` over a field-less `Heap<const SLOT: Int>` passes. Text and `Arc` still go through `GlobalAllocator` alone. Nothing in sawos waits on this.

**Wanted:**
- `String<A: Allocator = GlobalAllocator>`
- `StringBuilder<A>`, with formatting into a `StringBuilder<A>`
- `Arc<T, A>`

**Design questions (OPEN, for a design pass before any unit):**
- A literal is built from static bytes, never an allocation, so what is a literal's `A`?
- Interpolation and `{}` format arguments: which allocator does the result use, and how does a caller name it?
- `Equatable`, `Hashable`, `Comparable` and `Printable` across two allocators (`String<A> == String<B>`).
- A conversion between allocators (`copy(into:)`?), and `Data`, which has the same shape.
- The prelude's `String` stays the `GlobalAllocator` default, so no existing spelling changes (design 108's default type parameters).
- `Arc`'s control block and its `Send`/`Sync` with a non-global `A`.
- The five documented panic boundaries (the String layer is one).

Related: SO-142, design 123/234 (allocation-failure policy).
