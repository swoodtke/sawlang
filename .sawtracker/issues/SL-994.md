## Description

**Subscript pairing: a plain getitem beside a `borrows` view of a different type is typed from its first pick, which miscompiled in a prototype, and main already refuses plain-plus-lend pairs with `subscript.role`.** Found by SL-988 unit 2b, whose evidence is in `.build/scratch/p988/u2b/` (`d01_data_positions.saw`, `d02_var_arg.saw`, `d03_pair_positions.saw`).

- **The case:** SL:borrowing §6 says `let w = d[a..b]` on a `Data` is an O(1) owned window, so `Data` wants a plain `[](&self, range: Range) -> Data` beside its `borrows` views lending `&[UInt8]`/`&var [UInt8]`.
- **What happens:**
  - The pickers in `typecheck/src/bodies.saw` (`shared_twin`, `lend_pair`) resolve only two-member ties. Three gives `call.ambiguous`.
  - A prototype three-way picker (`lend_trio`) passed every stage, then segfaulted on `zero(&var d[0..2])`: ASan reports a stack-buffer-overflow in the exclusive view's prologue at -O0, and a heap overflow in `writable_view_parts` at -O2.
  - UNVERIFIED reading: the expression keeps the plain member's type (`Data`) while the call settles onto the exclusive view (`&var [UInt8]`). The pairing assumes the plain type equals the lent type, which holds for `Int`/`&Int` (P30) but not here. A d02 MIR dump showing a `Data`-typed operand fed to the view would confirm it.
- **Already on main:** any user subscript pair of a plain getitem and a `&self` lend is refused with `subscript.role` ("used as a place accessor: its `[]` is a getitem") in by-reference-argument and method-receiver positions (`show(&b[0])`, `b[1].twice()`; d03 fails on main's stage2).

**Needs a design** that touches SL:borrowing §12.4 ("the plain one wins"):
- deciding at filter time which positions take the lend (by-reference arguments, receivers) and which take the plain member;
- whether a plain member of a different type may pair at all;
- then fixing the existing refusal for all pairs.

Until then, `Data` has no plain range getitem: `d.slice(a, b)` is the O(1) window, and `let w = d[a..b]` is refused (SL-988 unit 2b).
