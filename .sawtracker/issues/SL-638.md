## Description

**Decided (the lead, Oct 14): model (a). c1's proposed fix is superseded.** The spec is authoritative and Stage 0 agrees with it: "A suspending default makes the callee suspending" (LANGUAGE_SPEC, "Default parameter values"). So a function's summary includes each of its defaults' effects, whichever argument a call passes. A `sync` caller of `f(n: 2)` is refused, as Stage 0 refuses it, and `f`'s own call stays `suspends`. c1's proposal (b), which put the effect only at the sites that fill the default, was a4drive's suggestion, not a ruling. It would change the language.

**What this issue fixes under (a):** a call that leaves out a default is two MIR calls at one node, the default's and the function's. Before the fix, both were evaluated as the function's summary, so the verifier wanted the default's call to suspend whenever the function did. The real defect is the sibling: a literal default on a suspending function (`func f(n: Int = 3) -> Int { yield_now(); n + 1 }` called as `f()`) failed MIR verification, while Stage 0 runs it and prints 4.
- Each default value now has a summary of its own (`TcDefault`, solved in the fixpoint beside its function's).
- `default_argument` sets its call's suspension from that summary, through `call_effect` in `mir/src/build.saw`, and the verifier checks a Default call against the same summary.
- A spawn or drive root's defaults are evaluated by the site, so `eval_call` counts them whole for the site's body.

**Left for coro (a3cpark's area), not done here:** a function whose summary suspends only through a default has no suspension in its MIR body. Coro doesn't frame it, and `coro_check_summaries` reports `INVARIANT` on that function, or on a caller that passes the argument explicitly. Stage 0 frames such a function. See the d638default report comment for the exact change.

**Symptom.** A default argument whose value suspends fails MIR verification (sawc2 at 9734b1183, `--std-root std`):

```
import std.task.{yield_now}

func slow() -> Int {
    yield_now()
    4
}

func f(n: Int = slow()) -> Int {
    n + 1
}

func main() {
    print("{}", f())
}
```

`sawc2 mir --dump` prints `INVARIANT  a4_default  12:13 a4_default.main(): a call's suspension point disagrees with its callee's summary`. In `main`'s MIR:

```
_1 = call default a4_default.f(n: Int).n [] -> [return: bb1];
_2 = call a4_default.f(n: Int) [move _1] -> [return: bb2] suspends;
```

The suspension sits on `f`'s own call, though `f` never suspends. The default call that does suspend is unmarked.

**Mechanism.** Typecheck's `eval_call(e)` folds a suspending default argument's effect into the call node `e`. The `f(...)` call and its `MirCallKind.Default` call both carry that node, so the effects cannot be split per call. `function_call` sets the flag from `suspension(e)` and gets `Always`. `default_argument` (`compiler/mir/src/lower.saw`) sets no flag, so its call is `Never`. The verifier's `verify_suspension` evaluates `eval_call(e)` for both calls and wants `Always` for each. Adding `self.suspension(e, &var call)` to `default_argument` is not the fix: it would mark both calls, which still misplaces `f`'s. The default's effect has to be attributable to the default call alone (by node, or by a per-default summary), and `f`'s call has to carry only the target's own.

**Sweep** (every `blank_call` constructor in `compiler/mir/src/lower.saw`, plus `close_window` in `build.saw`):
- **Run `suspension`:** `getitem`, `store_setitem`, `function_call`, `operator_call`, `lower_for`, `lent_struct_window`, `window_open` (through `open_half`), `close_window` (build.saw), and `builtin_call`, which SL-637's fix adds (SL-557's patch carries it).
- **Skip it on purpose:**
  - `panic_taken_twice`: a synthesized `panic`, which never suspends;
  - `lower_lend`: a lend is the accessor's pause, not a call that suspends;
  - `call_copy`: the copy hook, at node -1. A suspending `copy()` is refused, in typecheck and per instantiation in coro;
  - `spawn_site`: a spawn site makes no call of its root;
  - `value_call`: a function value never suspends (SL:architecture §3.9).
- **The defect:** `default_argument`, as above.

Found by SL-557's sweep of SL-637's mechanism. It doesn't block A4a.

**d638default report (worktree commit 61a0b9e66, rebased on main 7642b2735; not submitted).**

**Reproduced on 96400ff44.** c1's program gives `INVARIANT ... a call's suspension point disagrees with its callee's summary`. So does the sibling with no ruling question: a literal default on a suspending function, `f()` for `func f(n: Int = 3) -> Int { yield_now(); n + 1 }`. Stage 0 runs that one and prints 4.

**Mechanism.** A default value's body is a body root of its function, so its items sit in the function's unit. Under (a), that is why the function's summary includes the default's effect. The default's call and the function's call share one node, and every reader evaluated `eval_call(node)`, which is the function's summary, for both. Nothing could give the default's call an effect of its own.

**Fix:**
- **Typecheck** (`summaries.saw`): each default gets a `TcDefault` record: its run of items and its own summary. The summary is solved inside the worklist with its function's unit, and a unit that reads it depends on the function. `eval_default(e, j)` evaluates it at the call's type arguments. The verifier checks each default's summary is a fixpoint.
- **Spawn and drive roots** (`eval_call`): a spawn or drive root's left-out defaults are evaluated at the site (`spawn_site`/`drive_site` lower them in the spawner). `eval_call` now counts them whole for the site's body, alongside what `join_spawned` keeps of the root. Before, a suspending default of a spawn root was a plain call in the spawner, and a `sync` spawner of one was accepted.
- **MIR:** one funnel, `call_effect` (`build.saw`), picks `eval_default` for a Default call and `eval_call` for any other. `suspension` and `verify_suspension` both go through it. `default_argument` now runs `suspension`.

**Where Stage 0 evaluates a suspending default:** nowhere. Every call that leaves one out is refused:
- at a call the transform builds a frame for (embedded, drive root, spawn root), by `_arity_args`: "the default value of parameter `n` of `f` suspends ... Pass the argument explicitly";
- in a `sync` context, by the sync check.

An explicit argument never reads the default. A literal default is materialized caller-side, at the site. Stage 0 frames `f` itself (`--emit-frame-ledger`: `FRAME f decision=framed causes={cooperative}`), and a caller of `f(n: 2)` "itself suspends".

**What every check needs to agree under (a):**
- The default's call is marked by its own summary. Done.
- `f`'s call is marked by `f`'s summary, which includes the default. Done: unchanged.
- **`f`'s frame: needs a coro change, not made (a3cpark holds coro).** `coro_solve_suspension` seeds an item only from a source call in its MIR body. `f`'s body has none, so `f` is not suspending there. `coro_check_summaries` then reports `item `f(n: Int)`: does not suspend here, but typecheck's summary says it suspends`. A caller passing the argument explicitly gets the same report on itself (`main()`).
- **The change:** in the seeding loop of `coro_solve_suspension`, also mark an item suspending when its MIR function is a `Body` whose declaration has a default that suspends at the item's instantiation. Concretely: `tc.default_at.first(d, j)` finds an entry, and `tc.defaults[..].summary.suspends` is set, or its conditions hold at the item's type arguments. Give it a cause the cause-chain printer can name ("through the default of `n`").
- The item is then framed with no park point, as Stage 0 frames it. Its calls, already marked `suspends`, become drives, its callers suspend, and `coro_check_summaries` agrees.
- I can add a typecheck accessor for coro (`default_suspends(d) -> Bool`, or the conditions) if that's wanted.

**The other places a call node could fold a child's effect** (checked with compile and run evidence; `s3_args_receiver_try` matches Stage 0, `3/6/103/8/9`):
- a suspending positional or labelled argument, a suspending receiver (`make().get(...)`), a `try` operand and a `try!` operand: each is its own call node with its own mark. No folding.
- **Compound subscript, getitem then setitem at one node:** unreachable. `c[i] += x` over a declared getitem/setitem pair is refused (`subscript.role`), and Stage 0 refuses a non-`borrows` `[]`.
- **Windows:** two calls at one node, told apart by `half` already.
- **`for`:** `next` is at the `for` node and the head call at its own node.

Default plus target is the only pair with this mechanism.
