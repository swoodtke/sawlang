## Description

In a driven body, `let x = try f() catch { take(move r) }` -- an INLINE catch whose value is consumed, with a `move` of a frame local in the catch block's tail -- is refused: "move of a frame local in a nested tail-expression of driven X whose value is used is not supported; bind it first".

Repro (single file, no modules):

  import std.task.{yield_now}
  struct Res { name: String }
  extension Res: NoCopy {}
  struct Bad { why: String }
  extension Bad: Error {
      func format(&self, into: &var StringBuilder) { try! into.append(self.why) }
  }
  func note(r: &Res) -> Int { r.name.len() }
  func take(r: Res) -> Int { 1 }
  func fallible(k: Int) -> Result<Int, Bad> {
      if k < 0 { return Bad(why: "neg") }
      k
  }
  func run(items: Vector<Int>) -> Int {
      yield_now()
      var total = 0
      for i in items.iter() {
          var r = Res(name: "item")
          if note(&r) + i < 0 { return -1 }
          let got = try fallible(0 - i) catch { take(move r) }
          total = total + got
      }
      total
  }
  func main() { print(__saw_drive(run([1, 2]))) }

MECHANISM: every OTHER value-carrying tail is turned into an ASSIGNMENT before the tail handling sees it, and an assignment hosts the drop-flag clears fine -- that is what `_lower_value_conditionals` / `_cond_to_branch` / `_attach_sink_block` do for a value `if`, a value `match`, `??`, and the BLOCK form `try { } catch { }`. The INLINE catch is a `TryExpr`, and `_is_value_conditional` does not list it, so no sink lowering runs and its catch tail stays a genuine value tail with nowhere to put the forget. Adding `TryExpr` to that lowering is the shape of the fix; it is a change to the value-conditional path (which also carries SL-215's open inline-catch limitation), so it is filed rather than bundled into SL-222's review round.

Workaround, and what the diagnostic already says: bind it first -- `let v = take(move r)` inside the catch, then `v` as the catch's tail.

PRE-EXISTING: reproduces identically on the SL-222 patch base with none of the review-round changes applied. Found by the review-r2 CONTAINER_KINDS audit, which is also what makes it worth recording: it is the one source shape that DOES reach the value-used refusal, so SL-222's claim that nothing reaches it is now stated with this exception rather than as an absolute.
