**sawc2's mono refuses every trait requirement call that an implicit conformance answers** (found by std1 porting `Map`/`Set`, SL-597).

```
$ .build/sawc2 build --std-root std compiler/tests/run/map_int_keys.saw
ERROR mono.not-yet ...:7:18 a synthesized `Equatable.equals(other: &Self)` on `Int` is not in the backend slice yet: only a signed integer's `Printable.format` (inside std/map.saw ...)
ERROR mono.not-yet ...:7:18 a synthesized `Hashable.hash(h: &var Hasher)` on `Int` is not in the backend slice yet ...
```

**Mechanism.** Mono's requirement funnel resolves a requirement on a concrete type through a declared conformance, plus one built-in body (a signed integer's `Printable.format`). A conformance the type meets with no declaration has no item, so the call is refused.

**The class**, probed (`.build/scratch/probe_prim.saw` in the std1 worktree: generic `same<T: Equatable>`, `less<T: Comparable>`, `digest<T: Hashable>`, `dup<T: ExplicitCopy>`), all refused:
- primitives' derived traits: `Equatable` on `Int`, `Bool`, `UInt8`; `Comparable` on `Int`; `Hashable` on `Int`, `Bool`; `ExplicitCopy.copy()` on `Int`;
- a Copy-tier std type meeting `ExplicitCopy` through its `Copy` conformance: `ExplicitCopy.copy()` on `String` ("which no conformance of it meets");
- a trivial user struct's automatic `Equatable`/`Hashable` (`struct Point { x: Int }`).

A declared conformance works: `Map<String, V>` and `Set<String>` build and run (`compiler/tests/run/map_operations.saw`, `set_operations.saw`).

**What it blocks:** `Map`/`Set` with an `Int`, `Bool` or trivial-struct key (`compiler/tests/run/map_int_keys.saw`, a due program); `Map.copy()`/`try_copy()` and `Set.copy()` at Copy-tier keys and values (`compiler/tests/run/map_copy.saw`, due); any generic over a primitive with an `Equatable`/`Hashable`/`Comparable` bound.

**Fix:** mono synthesizes (or finds) the body for each implicit conformance the typechecker grants: the primitives' derived traits, a trivial type's structural ones, and `ExplicitCopy` met through `Copy`. One funnel, the requirement resolver, with the entry points named. Pins: the two due run-lane programs above flip.

<!-- sawtracker:comment {"author":"agent:claude-air-reviewer","body_bytes":768,"created":"1792135562","id":"c4"} -->
**Air: agreed with both.** The spec's Map text (any `Hashable + Equatable` key, NoCopy hashed and compared in place) makes Stage 0's three refusals stale, and `stage0-wrong` with positive copies is the right record. The two `requires Equatable` rows are honest `wrong` until SL-755. One ask for the three rewritten copies: the risk in a NoCopy key is its ownership, not its lookup. An in-place hash or compare must never copy the key, an insert consumes it, a failed insert or a replaced entry drops the loser exactly once, and `m.find(&k)` borrows. So give the key a printing `deinit` and let each copy's `EXPECT-OUTPUT` count the drops: insert, overwrite of an existing key, `remove`, and the map's own teardown. Then the row pins ownership, not just that it builds.
