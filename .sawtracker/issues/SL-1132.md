## Description

**Release v0.24.1.** The project owner's word (Nov 14, typed, on the lead's list of open decisions, where the recommendation was "tag as soon as the SL-1124 fix merges"): "for the blocking work, i agree with the recommendations." The sawos project is waiting on it to move its pin.

**The patch:** `.sawtracker/version` becomes `v0.24.1` and `driver_version()` in `compiler/driver/src/main.saw` becomes `"0.24.1"`, which run.py's `version` step holds equal. The server creates the annotated tag at the patch's merge commit (ST-46). **It must land AFTER both SL-1124 patches (p1, the MIR verifier's check; p2, the fix), so the tag holds the fix.**

**What v0.24.1 holds beyond v0.24.0** (each merged; ancestors of the tag are verified at landing):
- **Memory safety, safe code, every release so far: SL-1124.** `==` and `!=` of an Optional with a bare value of its payload type (`s == want` with `s: String?`; any payload that is not trivially copied; a generic `T? == T` at every instance; the Optional on the right when the left takes its type from its position) wrapped a REFERENCE to the bare operand as the Optional's payload: wrong answers, crashes, out-of-bounds reads, a release of memory never owned. It now tests presence and then the payload in place. A comparison only a member an extension declares on `Optional` would answer (`s < want`) is refused. The MIR verifier refuses any aggregate whose operand is not its part's type.
- **SL-1120:** an error `main` returns is written whole, however long (it was cut at 512 bytes); under `--no-hidden-alloc` it stays the bounded rendering.
- **`libs/toml` (SL-1092 unit 1):** a TOML 1.0 reader that builds a typed tree and refuses, by line and column, what it does not read: `TomlDoc.parse`, `TomlTable`, `TomlArray`, `TomlValue`; required reads (`string(key)`, a `Missing` error) and optional ones (`optional_string(key)`); `unsigned(key)` with hexadecimal, octal and binary up to `UInt64.max`; a repeated key, a table given twice and a redefinition are errors naming both places; one nesting limit, 32 by default. It refuses multi-line strings, floats and date-times by name until a later unit. The old reader is `toml.legacy` until Blade moves; Blade's reading of every manifest is unchanged.
- **Blade (SL-1102 unit 1):** `blade build`'s up-to-date check covers nested sources, a root `main.saw`, a dependency's manifest, native units, the C compiler and linker, the `SAWC` command and the compiler's version.
- **SL-457's follow-up:** a faulting const value that reaches a callee by inference prints its errors and no internal line (SL-457 and SL-1111 are closed).

**Known in this release, NOT fixed:**
- SL-1131: with standard error a non-blocking pipe, a line longer than the pipe holds is cut at its capacity.
- SL-1123: two builds that link one executable on macOS collide on `OUT.o` and the `.dSYM`.
- SL-1125: `(move p)!.label` is refused with an internal error.
- SL-1102 unit 2: a rebuilt development compiler or an edited `std/` with an unchanged version still reads as up to date to Blade (`sawc --build-id` is approved and not built yet).

**For a project moving its pin from v0.24.0** (sawos): nothing that built is refused except a comparison of an Optional with a bare value that only an `Optional` extension member answered (unsafe before); `main -> Result<Void, E>` now prints the whole error; `libs/toml`'s API is new (the old one is `toml.legacy`, to be removed in the next release).

**Landing:** `git rev-parse v0.24.1^{commit}`; check each merge above is an ancestor (SL-1102 40c366232, SL-457.p7 637a7c0e4, SL-1120 77dc979dd, SL-1092 U1 8bbec6ed3, and both SL-1124 merges); post the version and sha to the sawos lead in chat.
