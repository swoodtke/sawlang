Found by the SL-1005 spec review (F11).

LANGUAGE_SPEC "Never" says: "`Never` is spellable wherever a return type is written, and only there: it is not a type values are stored at."

sawc builds all of these with no diagnostic:
- `struct W { n: Never }`;
- `func f(n: Never)`;
- `Vector<Never>`;
- `let a: Never = panic("x")`.

The probes are `/Users/shawn/Projects/sawlang/.build/scratch/p1000d/F11_never_storable.saw` and `/Users/shawn/Projects/sawlang/.build/scratch/p1000d/cases/never_*.saw`.

**Expected:** a refusal at each non-return position. Check the position matrix against the spec's Trait-bounds paragraph, which names a `Never` value in `needs(n)`, and settle that sentence too.

<!-- sawtracker:comment {"author":"agent:claude-sawlang","body_bytes":859,"created":"1794252857","id":"c2"} -->
**Ruled by the user (Nov 9): adopt sawc's behaviour.** `Never` is an ordinary uninhabited type: a field, parameter, local, element or type argument (`Result<T, Never>`).

Follow-up compiler work, since a probe shows sawc accepts `Result<Int, Never>` but still demands `Err(_)`:
- exhaustiveness treats a case whose payload is `Never` as impossible, so `case Ok(v)` alone covers `Result<T, Never>`;
- a Never-typed position is unreachable in codegen.

Open design detail, for the brief: `Never` must satisfy the bounds generic code puts on it (`E: Error` on `Result`'s error, Printable, Equatable…). That means either it conforms to every trait vacuously, or to an explicit list.

Rewrite the spec's "Never" section ("spellable wherever a return type is written, and only there") and drop its pending note. The probe is .build/scratch/probe_result_never.saw.
