**Never support: the scope (user, Nov 9).** "Those seem like reasonable patterns; update 1007 to add Never support."

`Never` is an ordinary uninhabited type. It's legal at every type position, and the compiler uses the fact that no value of it exists.

**Patterns to support** (each is an acceptance row with a run pin):
1. `Result<T, Never>`: an infallible step through a generic fallible API. `match r { case Ok(v) -> … }` alone is exhaustive, and `r!` / `try` never take the Err path.
2. `Task<Never>` / `Thread<Never>`: a task that never finishes normally, as in `Task.spawn(serve_forever())` with `serve_forever() -> Never`. `join()` returns `Never`, so code after it is unreachable.
3. `Channel<Never>`: a signal-only channel. It carries no value, and only its close is observable (shutdown broadcast).
4. A generic enum's case switched off: `enum Event<E> { case Data(Int), case Failed(E) }`. For `Event<Never>`, a `match` needs no `Failed` arm.
5. An infallible implementation of a fallible requirement: a trait's `-> Result<Self, E>` met with `E = Never`.
6. `Vector<Never>` and other always-empty collections are legal: their length is 0, and no element access is reachable.
7. `() -> Never` as a parameter type: a callback the type forces to diverge, such as a panic hook.

**Compiler work:**
- **Exhaustiveness:** a case whose payload contains a `Never` (directly, or through a tuple or struct field that is `Never`) is impossible. It needs no arm, and an arm for it is unreachable, which is a note, not an error.
- **Type positions:** a field, parameter, local, element or type argument of type `Never` is accepted. A struct with a `Never` field is itself uninhabited, and so can't be constructed.
- **Codegen:** a value of type `Never` is unreachable. Layout gives it size 0, and every use is after a diverging point.
- **Trait bounds:** `Never` must satisfy the bounds generic code places on it: `E: Error` for a Result's error, `T: Printable` / `Send` for a channel element, and so on. The lead recommends that **`Never` conforms to every trait vacuously**, since no method can be called on a value that doesn't exist. Rust takes roughly this approach. The alternative is an explicit conformance list. *This choice is confirmed with the user at brief review.*
