A `for x in v.iter()` body may mutate `v`, and the iterator then reads FREED memory — a use-after-free in safe sync code, no `unsafe` in the source.

Found Sep 18 by the lead while answering the user's question on design 275 ruling 1 (is an owned std iterator that holds its parent's buffer the same as a `borrows` reference? — yes, semantically, and nothing tracks it). Pre-existing: the iterator model dates from design 53 / design 122 unit A; unrelated to SL-274 or the transform.

Repro (compiles clean, exit 0, wrong output):

```saw
func main() {
    var v: Vector<Int> = [1, 2, 3, 4]
    var seen = 0
    for x in v.iter() {
        seen = seen + x
        var k = 0
        while k < 64 {
            let _ = v.push(100 + k)
            k = k + 1
        }
    }
    print("seen = {}", seen)
    print("count = {}", v.len())
}
```

Prints `seen = 1025` (correct: 10) and `count = 260`: after the first body's pushes reallocate, the iterator's captured buffer pointer is stale and the remaining three `next()` reads come from freed memory.

MECHANISM (obligation 4): `Vector.iter(&self) unsafe -> VectorIterator<T>` returns an OWNED value carrying a raw `UnsafePointer<T>` + a length snapshot; the `&self` borrow ends at the return, so the type system holds no link between the iterator and the vector, and the Law of Exclusivity never sees the loop body's `&var v` as conflicting. vector.saw's own comment records the choice (owned-copy model over a scoped-borrow shape) for double-deinit reasons; the aliasing half was left to the `unsafe` marker on `iter`/`next`, which design 130 says is the AUTHOR's soundness promise — a promise no safe caller can break, which this program breaks.

CLASS — sweep owed before a fix is dispatched: `Vector.enumerated()` / `EnumeratedIterator` (same layout), Set's iterator, Data's iterator if any, `StringBytes`/`StringScalars` (String immutability may make those safe — verify), any user `Iterator` built on `UnsafePointer`. Map's `keys()`/`values()` return owned Vector COPIES and are safe. Also the same shape without a `for`: `let it = v.iter()` held across a `v.push`.

FIX SHAPE (a ruling, not a point fix): either (a) the iterator becomes a `borrows`-shaped accessor so the collection is lent for the loop's window and a body mutation is the clean exclusivity error `v.push` already gets inside a `with_ref` window (design 141/146), or (b) the loop desugaring charges the collection's ROOT for the loop's extent as a place borrow. Interacts directly with design 275 U3 / SL-317 ruling 1: once the iterator is a tracked borrow, "may a borrowed-place iterator span a suspension" is the real question for `for x in v.iter()` too, and design 88's driven-in-place rule is the answer to extend — refusal in v1 would refuse sawtracker's `store.saw:285` loop. Conformance row owed (the guarantee is "no use-after-free in safe code").
