## Description

# The general postfix call: a `Call` node whose callee is any expression

RULED by the user, Sep 23 2026 (see the ruling comment): calling a function value that a call returns — `func foo() -> (Int) -> Int { … }` then `let x = foo()(1)` — is useful sugar and gets built. Whatever else the same node admits without a use case of its own (`{ n: Int in n + 1 }(1)`, `v[i](x)`, `(1)(2)` refused by the typechecker) falls out of the design and is fine. This issue is that unit; it left design 274's U0′ at the implementer's ownership-guard stop (chat m94), because the parser has nothing to build for a non-name callee and the fix reaches ast_nodes, ast_dump, the typechecker and codegen.

## Mechanism (obligation 4, named by agent:claude-sl2-u0, confirmed by the lead)

`ast_nodes.FunctionCall` carries `name: str`; `MethodCall` carries `object` + `method_name: str`. No node has a callee that is an expression, so `parse_postfix` cannot represent `<expr>(args)` unless `<expr>` is a name. Every cell below is the one missing node seen from a different expression position. Since SL-347 the symptom is a clean juxtaposition refusal (`two statements on one line need a ';'`), no longer a silent `()` drop; the grouped-name face `(f)(1)` lands in U0′ as a parser-only fold to `FunctionCall f`.

Three INDIRECT-CALL paths already exist and are the funnel this node joins (obligation 1):
- a name-callee closure value: `_check_function_call` → codegen `_generate_function_call`'s closure arm (`self.variables[expr.name]`, the 3-tuple `{fn, env, dtor}` extract + `_emit_call(..., closure_call=expr)`), with the `FuncPointer<F>` bare-pointer twin (design 226);
- a function-typed FIELD: `MethodCall` flagged `is_field_call` by the typechecker (design 24 item 3), lowered as a field load + closure invocation;
- both apply `_effect_indirect_call` (a non-`sync` callee type marks the caller suspending).

## Contract

- New node `Call(callee: Expression, arguments: List[Argument], type_args=None)` — parser builds it in `parse_postfix` for `(args)` after ANY primary/postfix expression that is not a bare `Identifier` (which stays `FunctionCall`) and not a `.name` member (which stays `MethodCall`). Trailing-closure syntax is NOT extended to a general callee (`foo() { … }` keeps its current meaning; design 138's matrix is unchanged).
- Typechecker: the callee's type must be a function type (closure or `FuncPointer<F>`); arguments check against `param_types` positionally (a structural closure type has no labels, exactly like the field path); the result is `func_return_type`; `_effect_indirect_call` applies. A non-function callee (`(1)(2)`) is a located error `cannot call a value of type Int`. Ownership: the callee value is evaluated once into a temporary that the call's borrow/move accounting sees like a name-callee closure local (design 199's access set; a callee that is a place borrows for the call only).
- Codegen: evaluate the callee to its closure value, then take the SAME closure-invoke arm the name path takes — ONE chokepoint (`_emit_closure_value_call` or the existing arm refactored to accept a value), with its docstring naming the entry points: name-callee local, `is_field_call`, `Call`. The `FuncPointer` twin routes through the same chokepoint.
- Coroutine transform: a `Call` in any expression position is an ANF-hoistable suspension site when the callee type is not `sync` (design 120); `sawc/coro_shapes.py` and `ast_walk.CONTAINER_KINDS` gain the node (the `corototality` lane fails otherwise — that is the point of the lane).
- AST dump (design-259 freeze): `Call` renders as a NEW row `Call()` with the callee as its first child and the arguments after, so every existing `FunctionCall f()` / `MethodCall` byte is unchanged. `docs/AST_DUMP.md` gains the row. codex reconciles the prototype renderer's `canonical FunctionCall requires an Identifier callee` refusal against this shape (274 U2′); the shape is the LEAD's recommendation and the user rules if codex objects.
- `--emit-docs`, `astgraft`, `astdiff`, `lexdiff`: the node's fields are declared dataclass fields; no runtime grafts.

SL-301 AST design audit broadens this existing missing-postfix-call mechanism beyond closure literals. Parse-only probes against unchanged Python sawc (900cbb07 source; parent independently reproduced grouped identifier) all exit 0 but lose the call relationship:

```
func f(x: Int) -> Int { x }
func main() { (f)(1) }
```

The main body dumps `ExpressionStatement Identifier(f)` followed by `final_expr IntLiteral(1)`, rather than calling f with 1. `factory()(1)` similarly dumps a factory() statement plus a final integer; `(1)(2)` dumps two integers instead of retaining a call node for later typechecking. Direct `f(1)` is the positive control and preserves its argument.

Mechanism: ordinary call parsing is attached to the IDENT primary arm; parse_postfix has no LPAREN arm for a general expression head. parse_block then accepts the leftover adjacent parenthesized expression as a separate statement on the same line. This is the same funnel gap as DF-284b, so no separate issue was filed. A fix should include grouped names and call-result heads alongside immediate closure invocation, and preserve typechecking's responsibility to reject non-callable values.

The M18 arena parser will represent a general Call(callee, arguments) as intended syntax. These Python accidents are pre-freeze parser debt; no known-divergence allowance is being added to a canonical AST differential.
