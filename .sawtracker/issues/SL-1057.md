**Re-spell the corpus programs refused only because they use v0.18.0 std names** (user OK'd, Nov 10). SL-1056 mapped every leftover v0.18.0 name to today's std; these programs still use the old spellings, so they measure nothing.

The candidates, from `compiler/tests/corpusdiff/corpus_diff.tsv` (refused on a std member):
- `Path.as_str` → `as_string`, `Path.ext` → `file_extension`, `StringBuilder.as_str` → `build`;
- `Env.arg` → `Env.argument(index:)` (a `Result<String?, SystemError>`);
- `Directory.current`/`set_current` → `Env.cwd`/`set_cwd`;
- `String.fromBytes` → `Data.to_string` (and `string_from_bytes` where a raw pointer is the point);
- `String.withCString` → `String.c_string` (a `borrows` accessor, not a closure);
- `String.to_data` without its import → add `import std.data.*` (the extension is import-scoped).

**The rule:** a re-spelled program keeps its POINT, the behaviour it measures, and states its expected output in its own directives. A program whose point is the old API's own semantics (for example `errors/withcstring_escape`, which tests a closure escaping `withCString`) isn't rewritten. It's reported with a recommendation (retire it, or re-aim it at the current API's matching guarantee), and the lead decides. A conformance row's guarantee is never weakened.
