**Found by:** the Air's review of SL-482.p1 (a faithfulness agent's probes, rerun by me). **Area:** typecheck (the statement form of `borrow`). **Severity:** soundness.

**The defect:** the statement form of `borrow` accepts writes through a lend that grants no write. Both kinds pass typecheck, borrowck and mir:
- through a read-only `-> &T` lend under `borrow var`;
- through any lend under a bare (shared) `borrow`.

On a `let` root or a `&T` parameter, that mutates storage nothing may write.

**Repro** (`.build/scratch/air-review/sl482/probe_write_ro_let.saw`; main b163513d's sawc2, `--std-root std`):

```saw
struct Cell { n: Int }
struct Grid { cells: [Cell; 2] }
extension Grid {
    public func ro(&self, i: Int) borrows -> &Cell { lend self.cells[i] }
}
func let_root_var_form() -> Int {
    let g = Grid(cells: [Cell(n: 1), Cell(n: 2)])
    borrow var g.ro(0).n = 99          // accepted: writes a `let` through a read-only lend
    borrow g.ro(0).n
}
func let_root_bare_form() -> Int {
    let g = Grid(cells: [Cell(n: 1), Cell(n: 2)])
    borrow g.ro(1).n += 50             // accepted: a write through a shared borrow
    borrow g.ro(1).n
}
func shared_param(g: &Grid) { borrow g.ro(0).n = 7 }   // accepted
```

`typecheck`, `borrowck` and `mir --check` print no error for any of the three.

**The matrix** (`.build/scratch/air-review/sl482/agent/p08_mode_matrix.saw`, root `g: &var Grid`, with `ro` lending `-> &Cell` and `rw` lending `-> &var Cell`):

| statement | field `= 1` | compound `+= 1` | `&var self` method | whole place `= Cell(…)` | `&var` argument |
|---|---|---|---|---|---|
| `borrow var g.ro(0)…` | **accepted** | **accepted** | refused (`mutability.immutable`) | **accepted** | refused (`mutability.immutable`) |
| bare `borrow g.rw(0)…` | **accepted** | **accepted** | **accepted** | **accepted** | refused (`type.mismatch`) |

**What the spec says** (LANGUAGE_SPEC after SL-479/SL-482): a `-> &T` lend gives a read-only place, and "a write through [a bare `borrow`] is refused" (bare `borrow` is shared, SL:borrowing §2.2). The spec's own Document.section example, "`borrow var` through `Document.section`, which lends the place READ-ONLY", is accepted the same way (`agent/p07b_cond_forced.saw`, `p07c_plain_stmt.saw`, `p07d_shared_write.saw`).

**The fix:** one capability check that every write position of the statement form reaches, the same one block bindings and arguments already use: an assignment target, a compound assignment, a whole-place assignment, a `&var self` method receiver. The capability is the lend's (`&T` read-only) intersected with the form's (bare `borrow` read-only). Pin each matrix cell, plus the `let`-root and `&T`-parameter rows above.

**Siblings found in the same sweep**, to check with the fix:
1. **`if var x = e` over a conditional lend's payload** (`agent/p16_if_var.saw`) passes typecheck. The spec says it is refused with a hint. borrowck then stops at `slice.not-yet`, so it's low priority.
2. **The assignment's right-side borrow depends on the accessor's spelling** (`agent/p09_rhs_borrow.saw` against `p10b_rhs_named_no_epilogue.saw`). With two exclusive-only accessors of the same shape, `borrow var b[0].x = borrow b[1].x` is accepted, while `borrow var b[0].x = borrow b.at(1).x` is refused with `assign.rhs-borrow`. SL:borrowing §2.2 makes both legal ("a borrow whose result is only copied closes as soon as the value is read … the right borrow closes, and only then does the left borrow open"), so the named-accessor refusal is an over-refusal.
