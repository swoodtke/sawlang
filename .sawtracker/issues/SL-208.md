## Description

## DF-300e — a suspending free function that parks on io (a socket read), called ACROSS A MODULE BOUNDARY, registers with the reactor with a TOKEN OF ZERO, so its wakeup is never routed and the task parks forever (filed Sep 8 by the lead from the sawtracker SL-205 investigation; COMPILER BUG in the coroutine transform; PRE-EXISTING). The identical function called in the ENTRY module works.

### Symptom
An HTTP server whose per-connection reader lives in an IMPORTED module wedges: while any accepted socket is parked in its first `stream.read()`, no new connection is accepted, until unrelated traffic on the parked socket forces a reactor rescan. Surfaced as 30+ second page-load stalls in sawtracker (ST-7). The runtime reactor is correct; the bug is upstream in the coroutine transform.

### Minimal repro (`.build/scratch/wedge/`)
A 12-line reader — `while { let chunk = try! stream.read(); if chunk.len()==0 { return 0 }; try! data.append(move chunk); if (try! data.to_string()).contains("\r\n\r\n") { return 1 } }` — spawned per connection from one accept loop. Placement is the only variable:
- callee in an IMPORTED module (`import src.v0; v0.read(...)`) → WEDGES
- byte-identical body as an ENTRY-module same-file helper, or inlined into the spawn root → PASSES

Nesting depth is NOT the trigger (a same-file helper called by the handler passes). The store, http parsing, and the `try…catch` value-catch are all red herrings; the axis is the callee's HOME MODULE. Oracle: `.build/scratch/probe_205_client.py` (idle preconnect then a real request; WEDGE = the real request times out, recovers when the idle socket sends data). Confirmed against a clean stdlib (`.build/rt` rebuilt), so it does not depend on instrumentation.

### Direct evidence
Instrumented `SystemReactor.register/poll` (reverted after):
```
wedging build:  [reg] fd=5 dir=0 tok=0            <- connection socket parks with token 0
passing build:  [reg] fd=5 dir=0 tok=4345002096   <- real &frame.__wake address
```
The token (design 91) is the parked frame's `__wake`-word address. `rt_reactor_poll` guards `if ud != 0 { *tok = 0 }`, so a zero token latches nothing — the frame's wake word is never cleared, the task never becomes runnable, and because all tasks share one reactor the listen fd starves until an out-of-band event forces a rescan.

### Mechanism (obligation 4)
`coro_transform.py`. `__io_tok` is the ROOT frame's `__wake`-word address: set on a frame's first `resume` (`io_tok_init`, ~line 5363, only when the field is still 0) and propagated into an embedded sub-frame's `__io_tok` by the parent's drive block (~line 6896). The `io_wait` lowering registers `self.__io_tok` (~line 5918). For a cross-module suspending callee, the embedded frame runs its `io_wait` with `__io_tok` still 0 — the token does not cross the module boundary (the sub-frame drive does not propagate it, or the cross-module callee is materialized as a frame whose `__io_tok` is not the field the drive block writes).

Presumed a CLASS, one module-boundary materialization divergence with THREE faces, to sweep at fix time:
1. THIS one — silent token-0 miscompile of a cross-module suspending io callee.
2. The Slot<Byte> face (peer, SL-205): cloning the same function into the ENTRY module fails to BUILD — `cannot assign UInt8? to field of type Byte?` at `frame.saw:91` in `Slot<Byte>.clear`, because the frame-field type carries an unresolved prelude alias in entry-module context. Reproduced here with a 7-line function (`let b: Byte = ...` held across a suspend, entry module) and with a user alias (`type Handle = UInt32`); the same shape via `--module-path` or a sibling module compiles and runs. This is the DF-270b/DF-286c alias-and-materialization family surfacing in the frame builder.
3. An accept/reject asymmetry (peer, SL-205, NOT independently reproduced here — a clean reconstruction accepted both sides): a suspending SAME-module call reported "appears in a nested/expression position" in a catch block and `let _ =` position where the byte-identical CROSS-module call is accepted. If real, it is the same divergence deciding embed-vs-reject by module origin. Repro lives in sawtracker's `src/http.saw` read_request; wants its own minimal shape before it is trusted.

The unifying hypothesis: cross-module frame materialization does not reproduce the in-module frame path. A fix that makes the two paths identical (token propagation included) likely clears all three.

### Cross-refs
SL-205 (symptom + the full investigation trace), ST-7 (sawtracker, closed by a temporary entry-module workaround marked delete-when-fixed), DF-270b, DF-286c. sawtracker will revert its workaround and re-run its wedge oracle the day a transform fix lands.

Requested changes on patch SL-208.p1 (revision 1)

Review of SL-208.p1 revision 1 (applied commit 6c3cc826): requesting changes for three findings.

1. [P1] Materialize omitted default arguments before constructing the subframe.

Location: sawc/coro_transform.py:4883-4885.
The new classifier passes only explicit mc.arguments into _build_sub_frame. Defaults normally filled by module-call codegen are bypassed; _build_frame_init indexes one argument per formal parameter and raises IndexError: list index out of range at line 8364.

Minimal two-file repro:
```saw
// dep.saw
import std.task.{yield_now}
public func defaulted(a: Int = 7) -> Int { yield_now(); a }
// main.saw
import dep
func root() -> Int { dep.defaulted() }
func main() { print(__saw_drive(root())) }
```
Baseline compiler: compiles and prints 7. Patched compiler: uncaught IndexError. Resolve defaults and the checked argument binding plan before frame construction; cover omitted positional and labeled defaults.

2. [P2] Include newly imported bodies in generic-call promotion.

Location: sawc/coro_transform.py:10254-10260.
Imported functions enter the driven closure after the generic promotion passes have run. The splice rewrites labels, yield intrinsics, and spawn sites, but does not promote suspending generic callees within the new body.

Minimal two-file repro:
```saw
// genericdep.saw
import std.task.{yield_now}
func identity<T>(x: T) -> T { yield_now(); x }
public func wrapped(x: Int) -> Int { identity<Int>(x) }
// main.saw
import genericdep
func root() -> Int { genericdep.wrapped(42) }
func main() { print(__saw_drive(root())) }
```
Baseline compiles and prints 42, although its old cross-module path does not preserve the yield. Patched compilation rejects __Frame_root.resume and __Frame_wrapped.resume for calling suspending identity$1$Int from generated sync methods. Discover and promote callees from newly imported bodies before building frames.

3. [P2] Force a parked reader in the socket regression.

Location: examples/coro_cross_module_io_wake.saw:44-46.
Each client immediately writes its entire request after connecting. A handler can find all bytes already available and never park its imported read, bypassing the token-0 defect. Five runs of this new test compiled with the baseline compiler produced three 8-second timeouts and TWO successful exits with the exact expected output (3, 3). Five patched runs all succeeded. Thus the test is not a deterministic regression oracle as its comments claim. Coordinate an idle connection and a subsequent request while the imported reader is parked, then release the parked reader and verify its wakeup.

Validation: tested in an isolated checkout with revision 1 applied to base 7467b1f2. Baseline compiler sources match that base (local HEAD differs only in tracker metadata). The patch's position and Byte examples passed locally. The tracker reports 2434 compiler passes, 9 expected failures, and 36 freestanding passes; those full gates were not repeated locally.
