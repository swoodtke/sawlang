- **Port `sawc/std/arc.saw`** (145 lines) to `std/arc.saw`, and load it with one line in `compiler/resolve/src/loader.saw`'s `load_new_std_modules`: `self.std_module("arc")`. The resolver's prelude already names `Arc` from `std.arc` (`compiler/resolve/src/prelude.saw`).
- **Semantics from the spec, not Stage 0's leftovers:** `Arc` is `Copy` (LANGUAGE_SPEC: "`Arc` and `Data` are `Copy`"), so a copy retains. Under SL-641, a Copy type's `copy()` lives only in its `Copy` conformance, which is the one structural change from Stage 0's file. The constructor is a fallible init (`init(value:) -> Result<Arc<T>, AllocError>`, design 234). `extension Arc<T: Send + Sync>: UnsafeSend {}` / `UnsafeSync {}` carry over as written; SL-675's header checks must accept them (the raw pointer is what blocks the derivation).
- **Intrinsics:** `__saw_atomic_add_i64`, `__saw_atomic_sub_i64_release` and `__saw_atomic_fence_acquire` are already wired in sawc2 (resolve, typecheck, mono and llvm). If one doesn't lower, stop.

- **Pins:** run programs from the corpus's Arc programs that now build (with Stage 0 records), including a retain/release count check (`strong_count`) and a `deinit` that runs exactly once; and the re-measured corpusdiff baseline (SL-666).

SL-701.p1 submitted: `Arc` in the new std (SL-596 S2).

- **The port:** `sawc/std/arc.saw`'s algorithm, atomic ordering and `deinit` (release subtract, acquire fence, in-place destroy, then the weak count), with `copy()` and `deinit` in the `Copy` conformance (SL-641; the spec makes `Arc` Copy), the fallible init, the `UnsafeSend`/`UnsafeSync` headers as written (SL-675's checks accept them), `//!`/`///` docs, and one loader line, `self.std_module("arc")`.
- **`unique()` replaces Stage 0's `with_unique`**, per the spec (LANGUAGE_SPEC, Data's uniqueness gate: `Arc.unique()`, "a conditional lend (`borrows -> &var T?`) … present when the handle is the only strong owner"). It is a relaxed load of the strong count, then, when it reads 1, an acquire fence before the `lend`, because the caller writes through the lend. `with_unique` was refused anyway: it handed an `UnsafePointer<T>` as `&var T`, a coercion Stage 0 allowed and sawc2 doesn't. No program can run `unique()` yet: `arc_with_unique.saw` gets past it and stops at "a method `Arc` forwards to its payload" (SL-712).
- **Pins:** run programs `arc_basic` (strong_count across copies and drops, `deinit` exactly once), `coro_moved_arc_param_deinit_once`, `df151c_optional_dest_copy`, `coro_iflet_move_scrutinee_releases_payload` and `destructuring_wildcard_over_a_borrowed_projection`, each matching Stage 0 at -O0 and -O2 (darwin records; the Linux ones aren't made yet).
- **Corpusdiff (rebased onto main after A11, re-measured, not merged):** of the 72 rows that named `Arc`, 16 move to pass and 52 stay refused at a later piece (mostly SL-712's forwarding, owning captures, `group.spawn`, and collection literals). Three move to `stage0-wrong`: `coro_discarded_match_payload_field_drop_order`, `coro_discarded_match_payload_released_at_extraction` and `coro_mixed_match_payload_released_at_extraction` are hazard C11 under the SL-513 ruling (B). A discarded payload dies when the construct completes, which sawc2 does and Stage 0 doesn't, so they're annotated like their siblings. One becomes `wrong`: `conformance/V112_destructuring_let_retains_a_projection` (sawc2 shows `inside 5` where 4 is expected), filed as **SL-705**.
