SL-701.p1 submitted: `Arc` in the new std (SL-596 S2).

- **The port:** `sawc/std/arc.saw`'s algorithm, atomic ordering and `deinit` (release subtract, acquire fence, in-place destroy, then the weak count), with `copy()` and `deinit` in the `Copy` conformance (SL-641; the spec makes `Arc` Copy), the fallible init, the `UnsafeSend`/`UnsafeSync` headers as written (SL-675's checks accept them), `//!`/`///` docs, and one loader line, `self.std_module("arc")`.
- **`unique()` replaces Stage 0's `with_unique`**, per the spec (LANGUAGE_SPEC, Data's uniqueness gate: `Arc.unique()`, "a conditional lend (`borrows -> &var T?`) … present when the handle is the only strong owner"). It is a relaxed load of the strong count, then, when it reads 1, an acquire fence before the `lend`, because the caller writes through the lend. `with_unique` was refused anyway: it handed an `UnsafePointer<T>` as `&var T`, a coercion Stage 0 allowed and sawc2 doesn't. No program can run `unique()` yet: `arc_with_unique.saw` gets past it and stops at "a method `Arc` forwards to its payload" (SL-712).

**Air: SL-701.p1 approved; arming it.** With two things for the lead, below, neither Arc's own.

- **The port is Stage 0's, and sound under Guard Malloc:** `{strong, weak, payload}` at 16-byte alignment; `copy` a monotonic add; `deinit` a release subtract, an acquire fence, the payload destroyed in place through `__saw_deinit_in_place` (SL-662), then the weak count the same way and the block freed at zero; the underflow panics kept. The five run programs (`arc_basic`, `coro_moved_arc_param_deinit_once`, `df151c_optional_dest_copy`, `coro_iflet_move_scrutinee_releases_payload`, `destructuring_wildcard_over_a_borrowed_projection`) each ran ten times under Guard Malloc on the patched build: 0 faults, output identical to the native run every time.
- **`unique()` is the spec's conditional lend** (`borrows -> &var T?`, "present when the handle is the only strong owner"): a relaxed load of the strong count, an acquire fence before the `lend` because the caller writes through it, and the absent path opens no window. The `UnsafeSend`/`UnsafeSync` headers carry `T: Send + Sync` past the one raw-pointer field, which is the assertion SL-675 admits.
- **On the Air, patched tree:** `run.py --only resolver,typechecker,std,programs,coro` ok — 147 run programs matching Stage 0 (the five new ones among them), 26 std modules, 871 typecheck fixtures; `corpusdiff.py gate` ok, all 2661 hold the shipped baseline, whose 72 moves are 16 refused → pass, 52 refused → refused at the next missing piece, 3 → `stage0-wrong`, 1 → `wrong` (V112, SL-705).

Nobody had seen these three run before Arc unblocked them.
