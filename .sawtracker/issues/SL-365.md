## Description

Found while building SL-356's pin matrix (Sep 23), on the SL-356 branch off main 8d2c0563; NOT caused by SL-356 and reproduces without any closure.

REPRO (`.build/scratch/driven_void.saw`):

    import std.task.*

    func driven<R>(make: () sync -> R) -> R {
        let r = make()
        yield_now()
        return r
    }

    func main() {
        __saw_drive(driven({ print("drive") }))
    }

    error: function returns void but return has a value of type `Void`
      --> driven_void.saw:6:5
      note: in the instantiation `driven@<Void>`

The same body compiles and runs at `R = Int` (`__saw_drive(driven({ 7 }))` prints 7), and the SYNC twin of the same generic compiles at `R = Void` (`func plain<R>(make: () sync -> R) -> R { let r = make(); return r }` called as `plain({ print("sync void ok") })`). So the refusal is specific to a SUSPENDING generic instantiated at Void.

MECHANISM to name before a fix (obligation 4): design 132 says a Void that arrives by INSTANTIATION is a zero-sized binding rather than a visible Void, and every non-suspending return position honours that. The coroutine transform rewrites the body into a resume method whose return position is checked again after the rewrite, and that second check appears to read the LLVM-level void return against the source-level `Void` type instead of the instantiation rule — so the sibling positions to probe are the other return-shaped positions of a rewritten body at `R = Void`: a tail expression, an auto-wrapped `-> R?`/`-> Result<R, E>`, a `break <value>` out of a loop in such a body, and a suspending generic METHOD (as opposed to a free function).

WORKAROUND in the corpus today: `examples/closure_leaves_enclosing_void_local_visible.saw` reads its Void local through a rebinding (`let echo = r`) and returns an `Int`, which is what the SL-356 pin needed and is why the shape was found.
