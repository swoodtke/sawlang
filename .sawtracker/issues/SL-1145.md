## Description

**The per-patch gate never runs the freestanding runner's own unit test.** Found by the reviewer of SL-1138.p1 (Nov 15). The gate's `freestanding` part runs `tools/freestanding_runner.py` alone (`tools/patch_gate.py`), and `tools/test_patch_gate.py` holds a change to `tools/test_freestanding_runner.py` to the compiler tests only; `tools/battery.sh freestanding` (which runs the unit test first) is its one caller, and nobody runs the battery per patch. So a patch that changes the runner's decision logic and its unit test (SL-1128, SL-1138) has its pin held by no server run.

**Fix:** the gate's `freestanding` part runs `tools/test_freestanding_runner.py` before the runner, as `battery.sh freestanding` does, and the part's inputs (`SUITE_INPUTS`) include the unit test file. `tools/test_patch_gate.py` gains the row. Check the other gate parts for the same shape (a lane whose own unit test only the battery runs: `test_child_groups.py`, `test_linux.py`, `test_patch_gate.py` itself) and say for each whether the gate should run it.

Related: SL-1138, SL-1128.
