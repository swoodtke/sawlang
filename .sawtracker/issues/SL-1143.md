## Description

**A freestanding `main`: a compiler-synthesized entry that runs it under design 221's contract and returns the status.** Approved by the project owner as relayed by the sawos lead in chat (Nov 15, message m1023: "tell sawlang i approve of its plan"), on the lead's proposal (`.build/scratch/chat/post_nov15_freestanding_main.md` in the lead's checkout). sawos's half is SO-124 (its runtime `sosrt` keeps `_start`); on sawos's side it is ordered after the ESP32-S3 PLL work, so there is no hurry.

**Today** (v0.24.2): under `--freestanding`, "a freestanding object's roots are its `@export`ed functions. It has no C entry point and no program-argument accessors, and a `main` it declares is an ordinary function, held to no entry-point rule" (LANGUAGE_SPEC.md, Freestanding). So there is no entry, no exit-status contract, no `Err` line, and a suspending `main` cannot be driven at all (an `@export` is a `sync` effect root and cannot call it). Hosted, the backend synthesizes C `main(argc, argv)` (`entry_point`, `compiler/llvm/src/program.saw`), which stores the arguments, drives a suspending `main` with the entry executor, applies the 221 contract (0...255 check through `__saw_rt_panic`; `error: <rendering>` through `__saw_rt_write_error`, status 1) and returns the status.

**What is approved:**
- Under `--freestanding`, a `main` in the entry module gets a compiler-synthesized, synchronous, C-ABI entry with a reserved name (the lead's proposal: `__saw_main`, returning the status as a C `int`; the exact name and signature are the design's to fix and record in `runtime/ABI.md`) that runs `main`, drives a suspending one with the entry executor, applies design 221's contract through `__saw_rt_write_error` and `__saw_rt_panic`, and RETURNS the status. It does not exit: the runtime provider calls it from its own `_start` and exits through its own operation.
- `main` keeps taking no parameters; a freestanding runtime hands its boot context to the program through its own state (sosrt stores the boot handle before calling the entry).
- A freestanding object with no `main` is unchanged: its roots are its exports.

**Open for the design (owed before a unit):**
- The name, the C signature and the ABI document entry; whether the hosted C `main` becomes a thin wrapper over the same synthesized entry (one implementation of the contract) or stays separate.
- `Task.spawn` freestanding: refused today because there is no `main` to close its group at; with an entry, whether it is allowed in the entry-driven program (the owner's call if it changes the language).
- The entry executor freestanding: what it needs from the runtime (the reactor seam, a clock for `sleep`), and what a program with no reactor gets.
- `--no-hidden-alloc` and the `Err` rendering (the bounded 512-byte form).
- The freestanding suite: a case per return shape of `main` on each row, through a start-up that calls the entry and reports the status; the spec's Freestanding paragraph and the entry-point section.

Related: SO-124 (sawos's half), design 221 (the return contract), SL-1120 (the `Err` line written whole), SL-1131.
