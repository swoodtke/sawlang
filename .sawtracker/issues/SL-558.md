**A5. The post-lowering verifier, first cut.**
- **Scope:** `compiler/coro/src/verify.saw` checks §3.9's rules on lowered MIR, by recomputing them, not by trusting the lowering's tables:
  1. a frame slot is only ever addressed in place through the frame pointer, so nothing relocates a frame a loan points into;
  2. at each suspension state, the maybe-initialised resident values equal what `MirInit` gives for the matching point, and every drop on every edge is one drop elaboration placed. Lowering added none (teardown by state, §3.1);
  3. every window is closed exactly once on every path, those out of a resumed state included;
  4. each park's record store dominates its arm.

  Injections go in `tests/coro/inject/`, as `tests/mir/inject/` does: drop a drop, add a second `window_close`, swap a record and its arm. Each must fail naming the rule.
- **Depends on:** A4.
- **Files:** `compiler/coro/src/verify.saw`, `compiler/tests/coro/inject/`.
- **Pins:** the three injections, plus every A3–A4 golden verifying clean.
- **Done when:** the injections fail and the corpus census shows no verifier failure.
- **Estimate:** 1.5.

**Plan:** SL:coroutines §4, unit A5 (approved by the user, Oct 12). The plan text is authoritative; this issue is its tracker entry. Dependencies are named by unit id; see the epic's child list for their issues.

**From A4a (SL-557, agent a4drive): the lowered drive form, and the invariants A5's verifier should recompute.**

A4a lowers a drive into MIR statements on frame slots, so the backend's drive passes nothing. In a lowered frame (frame pointer `_F`, child slot at offset S), the call `dest = g(args)` in block `bbB` becomes:
- `bbB`'s statements gain one write per argument, `(*_F).[S + P_j: T_j] = arg_j`. P_j is parameter `_j`'s offset in g's frame, and the operand is moved, copied or constant exactly as the call passed it;
- the call terminator keeps its target with `arg_count` 0 and `dest` -1. It is the drive point (`CoroPoint.Drive`);
- when the call had a destination, its `next` is a new block, numbered after the body's own: `dest = move (*_F).[S + R: T]` (R is `_0`'s offset in g's frame), then `goto` the call's old return block;
- a `__saw_test_suspend` call's block ends in a `goto` to its return block instead. No point, no state.

**Invariants A5 should check by recomputing them from the lowered MIR and the child's frame, never from `CoroPoint`'s recorded fields:**
1. A drive's call carries no arguments and no destination.
2. The drive's block writes each of the child's parameter slots exactly once, after every statement that computes the arguments. The slots come from the child's frame values (`CoroValueKind.Param`), and each write's type is the parameter's.
3. When the source call had a destination, the drive's return edge reaches a block whose one statement moves the child's result slot into that destination, ending in a `goto` to the original return block. When the child returns `Never` (`next` -1), there is no move-out.
4. Teardown: the writes move what the call moved, so each moved argument is consumed exactly once (by its slot write). The child's body drops its own parameters, and nothing else drops a parameter slot. The child's result slot is read exactly once, by the move-out, and never dropped in place.
5. Re-entry at the drive's state jumps past the writes, to the resume, so the arguments are written once per call, not once per resume.

A4a checks 1–3 structurally inside coro (`coro_check_drives`, an `INVARIANT\tcoro` line), and the unit program `compiler/coro/tests/drive_invariant.saw` unlinks a parameter write and requires it. 4 and 5 are A5's.

**Why A5 needs its own verifier, not `mir/src/verify.saw`:** a throwaway probe ran `mir_verify_module` over coro's lowered bodies. Over golden `drive_arguments` it reported 5 problems:
- three "a call passes fewer arguments than its target has parameters" (the drives);
- "bb6 moves a `String` out through a reference, `(*_8).[64: String]`" (the move-out);
- in `label`, "owned local _1 may still be live at a `return`": the parameter's drop is now `drop((*_5).[16: String])`, which the initialisation analysis doesn't tie to `_1`.

A3b's `drive_and_park` passed (0 problems) only because its owned resident locals are never written through their own local after the rewrite, so the analysis never sees them initialised.
