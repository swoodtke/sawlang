## Description

**`Vector.reserve(additional:)` with a negative `additional` is a silent no-op; make it panic, as `Data.reserve` now does** (the sweep from SL-735 part 2).

Evidence (p735b's probe): `reserve(-2)` answers `Ok`. With the allocator denied, so do `reserve(-1000)` and an empty vector's `reserve(-5)`, and `len` is unchanged. It is silent because `capacity >= length + additional` holds whenever `additional < 0`.

SL-735 ruled (lead, reversible) that `Data.reserve` panics on a negative `additional`: a precondition violation, under the doctrine of no silent no-ops and no clamps (as `clamp` and `substring` do). `Vector.reserve` is the one other public `reserve` in std (Map, Set, String and StringBuilder have none), so it should match:
- `panic("Vector.reserve: additional {} is negative", additional)`;
- a `///` line;
- a `panics` probe;
- the spec's Vector API line, if it states `reserve`'s contract.

`Vector(capacity:)` and `Data(capacity:)` with a non-positive capacity allocate nothing, and their docs say so. That is documented, not silent, and is left alone.
