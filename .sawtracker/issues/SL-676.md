## Description

**An argument already moved into its temporary leaks when a later argument leaves early** (found by t670try on SL-670).

`sink_rev(move r, try fail())`: MIR moves `r` into the argument temporary, then the second argument's `try` takes its error edge and returns. Nothing drops the temporary on that edge, so `r`'s value is never destroyed. The MIR verifier does not report it ("owned local may still be live at a return" stays silent for this temporary).

Probe (`.build/scratch/p9.saw`, p10.saw in the t670try worktree), `sawc2 build --std-root std`, `Res` a NoCopy type whose `deinit` prints:

```
func row2() -> Result<Int, Bad> {
    var r = Res(name: "kept")
    let n = sink_rev(move r, try fail())   // prints "caught", never "drop kept"
    n
}
```

MIR (drops dump): `_4 = move _1;` then `_5 = call fail()`, and the `Err` block `bb3` returns with `drop(_5)` alone; `_4` is never dropped.

**Mechanism:** an argument evaluated into a temporary that the call is meant to consume is registered with no scope, so every exit taken between its evaluation and the call skips it. **The class**, each probed and leaking:
- a propagating `try` in a later argument (sync, no `try` block involved);
- a `return` in a later argument's value `if` (`sink_rev(move r, if c { return -2 } else { 1 })`);
- with SL-670: a `try` in a later argument inside a `try` block (edge to the catch block), and an inline catch's catch block that returns, in a later argument.
`break`/`continue` in an argument would be the same.

The corpus program `tests/corpus/coro_try_landing_relinquishes_by_position.saw` (rows 2 and 3b) expects the drop, which is how it showed; it builds under sawc2 only once SL-670 lands. Not fixed in SL-670 (the mechanism is the call-argument lowering, not the catch forms).
