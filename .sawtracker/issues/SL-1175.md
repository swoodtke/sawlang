## Description

**sawc never compares an `extern "C"` declaration with an `@export` of the same C symbol, so one program can call its own export through a mismatched signature with no `unsafe`.**

Found by the SL-1159 `@weak` design pass (Nov 19; probes `.build/scratch/p1159d/saw/`). A hosted arm64 program with no `unsafe` declares `extern func hook(x: Int) -> Int` and exports `@export("hook") func my_hook(x: Int32) -> Int32 { x - 1 }`. Then `print(hook(0))` prints `4294967295` and exits 0. On aarch64 freestanding the IR has `define i32 @"hook"` beside `call i64 @hook()`, and `llc` accepts it.

Two externs of one symbol are already checked against each other (`extern.signature-disagree`); an extern against an export is not.

**Fix:** widen `check_extern_agreement` (`compiler/typecheck/src/effects.saw`) to cover every export, under the rule `export.signature-disagree` (or the existing one, as the fix argues). Write the conformance rows first: the design's "one C symbol, one signature per compile" family, S-a to S-e, where S-b is this bug.

**Sweep:**
- an export against an extern, in the same module and across modules;
- std's externs against a runtime compile's exports (the seams);
- a builtin export (`memcpy`) against a program's extern of it;
- parameter labels vs types only;
- `sync`/`blocking`/`unsafe` effects.

This is unit U1 of the `@weak` design (SL-1159), and lands first. Related: SL-1159.

**The implementer's stop (Nov 19): exact types refuse the runtime.** std declares seams with an optional pointer result (`std/env.saw`, `std/alloc.saw`, `std/string.saw`, `std/path.saw` and `std/directory.saw`), and the runtimes export the plain pointer (`__saw_rt_executable_path` in `runtime/host_macos` and `host_linux`, `tests/freestanding/rt`, sawos's sosrt). That pairing is the seam's documented idiom: one machine word, NULL meaning absent. `runtime/common/mem.saw` says so: "std/alloc.saw's `extern` declaration adds the optional wrapping, because an `@export` return cannot be optional".

**Lead's ruling (Nov 19): option B.**
- An `extern` and an `@export` of one C symbol agree when their types are exactly equal, OR when one side has `T?` where the other has `T`, in any parameter or the result, and `T?` is laid out as `T`'s nullable form: the same word, with the absent case the all-zero value.
- The comparison asks the layout which Optionals have that form (find the existing niche or nullable-pointer rule; never a hand list of type names). Expect `UnsafePointer<T>` and `FuncPointer<F>`. A plain `Int` against a pointer still disagrees, which option A would have let through.
- The extern-to-extern rule (`extern.signature-disagree`) stays exactly as it is.
- **Effects** (`blocking`, `sync`, `unsafe`) are not compared between an extern and an export. The spec decides effect agreement only among externs, and an export's effects govern its own body, not the bits that cross the call. The spec text says so in one sentence.

**Next:**
- compile every runtime and provider program under the rule (macOS, Linux, `tests/freestanding/rt`, the provider probes, `blade/tests/fixtures/runtime_pkg`) and confirm none is refused;
- add a pin that the nullable pairing is accepted, and a pin that `Int` against a pointer is refused;
- then the rows (N13–N15), the pins, the corpus baseline, the gate, the lint, and the commit.

**Lead's second ruling (Nov 19), on the implementer's second stop.** The provider probes export `__saw_rt_alloc` as `(UInt, UInt)`, and std declares `(Int, Int)`.
- **Integers of the same width agree whatever their signedness.** The same bits cross the call: a same-width signedness difference is a defined reinterpretation, not undefined upper bits as `Int` against `Int32` is. It is also what the `export.seam-signature` check already allows.
- **Still a disagreement:** a different width (`Int` against `Int32`, the issue's bug), an integer against a pointer, and any other type pair beyond these two rules.
- **`FuncPointer?` is not added:** the nullable rule follows the layout's existing `NullablePointer` class, which does not include it. The first ruling's expectation is withdrawn.
- **The run lane's planted-defect runtime** (`fs_chdir` "defined by both") keeps its purpose. Its planted copy is given an agreeing signature, so it still reaches the duplicate-definition check.
