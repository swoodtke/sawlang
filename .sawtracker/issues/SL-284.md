## Description

Found while implementing minivm M14 / SL-257. Reproduced on Python sawc at production base 4af54288 (compiler sources identical to c13d2385), using the project's venv. No production compiler changes in the prototype worktree.

Python sawc accepts an implicit receiver borrow in a nested argument where the explicit-reference equivalent is rejected. LANGUAGE_SPEC.md, Law of Exclusivity / Nested calls (around lines 4014–4045), says the receiver is an ordinary member of the whole-call access set. This is a wrong acceptance against that rule, not evidence of a demonstrated memory-safety failure.

Accepted, prints oldold:

```saw
func main() {
    var b = StringBuilder()
    try! b.append("old")
    try! b.append(b.build())
    let result = b.build()
    print(result)
}
```

The equivalent explicit-reference wrapper is rejected with an exclusive access violation at the nested &b:

```saw
func built(b: &StringBuilder) -> String { b.build() }
func main() {
    var b = StringBuilder()
    try! b.append("old")
    try! b.append(built(&b))
}
```

The gap also reproduces on an ordinary user record:

```saw
struct Counter { n: Int }
extension Counter {
    func read(&self) -> Int { self.n }
    func write(&var self, n: Int) { self.n = n }
}
func main() {
    var c = Counter(n: 7)
    c.write(c.read())
    print(c.n)
}
```

Mechanism: typechecker/types.py:_check_call_exclusivity adds nested access entries from _nested_reference_exprs. That walker collects only explicit ReferenceExpr nodes, so implicit method receiver borrows in nested MethodCall nodes never join the outer call's access set. The top-level receiver is collected, but the nested receiver is missed.

Fix the common nested-access collection using resolved receiver passing modes. Cover mutable/shared and mutable/mutable nested receivers, ordinary and std methods, reference-parameter receivers, and generic/erased dispatch where applicable. Shared/shared and disjoint roots/fields must remain legal; hoisting the inner result into its own statement must remain legal. Keep closures' deferred bodies outside this walk under the existing capture policy.

Evidence files in /Users/swoodtke/Projects/sawlang-m14/.build/scratch/: builder_overlap.saw, builder_overlap_explicit.saw, nested_receiver_overlap.saw and corresponding compiler logs. The minivm Builder frontend will enforce the documented rule; it must not reproduce this Python acceptance.
