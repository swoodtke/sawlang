**Two readings to review.** Both are recorded in the README; both are reversible.
1. An optional parameter is a wrap, not an `Int` overload, so Int? / Int8? stays ambiguous. Stage 0 types the literal `Int` before it chooses, so it picks `Int?`.
2. "Fits" is by type: the value is range-checked after the choice, as for the `Result<Int32, Int8>` peel. So `h(300)` over Int8 / Int16, and `h(-5)` over Int8 / UInt8, are ambiguous, as in Stage 0. If "fits" is meant by value, `arg_fit` must range-check a constant there. That needs a ruling, so I left it alone.

**Not this mechanism.** sawc2 has no declaration-site check for indistinguishable signatures. Two identical `func h(x: Int8)`, or `h(UInt8)` beside `h(Byte)` (the same after aliases), are accepted, and surface only as `call.ambiguous` at a call. Stage 0 refuses both at the declaration. I've commented this on SL-641, which is the same mechanism for members.
