## Description

**`__saw_rt_alloc` is declared without a `noalias` return, so LLVM can't prove a fresh buffer is disjoint from any other pointer.** Found by SL-971 unit 1, UNVERIFIED as the cause.

**Evidence** (`.build/scratch/p971/ir.opt.ll`, `ir_bin.s`): `Vector.copy()`'s bulk loop over a trivially copyable element type into a just-reserved buffer compiles at -O2 to a NEON loop behind a runtime overlap check (`cmp x12, #0x40; b.lo`). It doesn't become `llvm.memcpy`. std's `copy_bytes` in `StringBuilder.reserve_bytes` compiles the same way. Throughput already matches libc `memcpy` (50–80 GB/s), so this costs code size and an overlap branch, not bandwidth.

**Direction:** declare the allocation seam's return `noalias`, the way `malloc` is. That means the LLVM declaration sawc emits and, if it changes, the runtime ABI contract in `runtime/ABI.md`. Then re-read the IR: the loop-idiom pass should form `memcpy`/`memset`, and alias analysis should improve downstream. Check that the attribute is sound for every allocator path, the slab and custom `Allocator`s included, and wherever a buffer can alias. Measure code size and a benchmark before and after (perf via measurement).
