**Port the std modules the new `std/` lacks, outside the coroutine plan.** The user asked for this on Oct 13 ("can we flesh out the stdlib?") and approved a third agent for it.

**Why.** The new `std/` has 18 modules against Stage 0's 32. By the number of tracked programs importing each (`.build/scratch/probe_missing_modules.py`):

| missing | programs | notes |
|---|---|---|
| `Map` / `Set` (prelude) | 182 / 61 | the coroutine census's top first refusal, `name.undefined` (134) |
| `std.time` | 48 | A11 (SL-568) later adds timer deadlines on top |
| `std.json` | 44 | |
| `std.directory` | 29 (9 in Blade) | |
| `std.fixedbuf` | 14 | |
| `std.cbor` + `std.serde` | 12 (Blade) | serde's traits are already in the prelude |

The async modules (`net`, `channel`, `signal`, `taskgroup`) are SL-545's, and `mutex`, `arc`, `spinlock`, `once` and `slab` stay out of this epic until they're scheduled.

**The milestone:** Blade builds and passes its tests under sawc2, with `--std-root std`. Blade is a real program, and that is a precondition for retiring `sawc/` (SL-539).

**Units, in order** (one agent at a time on this track, file-disjoint from SL-545's units):
1. **Map and Set:** `std/map.saw` and `std/set.saw`, plus their prelude exposure.
2. **`std.directory`, and `std.time`'s clock** (`Instant`, `Duration` arithmetic). The time unit is coordinated with A11, whose files include `std/time.saw`.
3. **`std.serde`, then `std.cbor`, then `std.json`.**
4. **`std.fixedbuf`, `std.numeric`, and `std.float`'s text conversion.**

**Rules for every unit:**
- Port from `sawc/std/` into the bootstrap language, which `compiler/tools/subset_check.py`'s std profile enforces.
- Follow the current spec and design rulings, not Stage 0's leftovers: allocating ops return `Result<_, AllocError>`, there are no abbreviations, and docs follow saw-docs.
- A sawc2 gap is filed and the unit stops. Never work around it.

A scope gap for unit 1, from the reviewer (Air): **iteration isn't on the list**, and the milestone needs it.
- **Blade iterates.** `blade/src` has 7 `for x in v.iter()` loops (`git.saw`, `lock.saw` ×3, `manifest.saw`, `resolver.saw`, `tester.saw`), so 'Blade builds under sawc2' needs `Vector.iter` at least.
- **The new std has no lending iterator.** `std/prelude.saw` declares `Iterator` but not `LendingIterator`, the trait the spec's collection `for` uses (`func next(&var self) borrows -> &var Item?`, 'Two iterator traits'), and no std type has an `iter`. A ported `Map`/`Set` without it can be built and queried but not walked.
- **It ungates census pins.** A0b's census keeps `conformance/K149_sawtracker_loop_shape` and `coro_discarded_tail_move_cross_module` gated on exactly `Vector.iter` and `Map` (SL-551's ruling: they flip on 'when their ports land, which is milestone-2 std work'). This track is that work.

Suggest unit 1 becomes **'the iteration protocol, then Map and Set'**: `LendingIterator` in the prelude, `Vector.iter`, then `Map`/`Set` with their iterators. Its pins should include a borrowing `for` over each, and K149 flipping from gated to counted in the census. A6's collection-`for` lowering (SL-559) consumes the same trait, so the trait's shape should be settled here first, against the spec's signature.
