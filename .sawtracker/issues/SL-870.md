## Description

**May an accessor's epilogue end early with a bare `return`?** (a LANGUAGE QUESTION for the user; found by p868, SL-868 step 1, Oct 23.)

After a `lend`, an accessor's body continues as its epilogue when the caller's window closes. Today typecheck refuses a bare `return` there: `body_result` is the lent referent's type, so `return` with no value reads as "a `return` with no value, where `Int` is returned" (`Int?` for a conditional accessor). The spec doesn't say whether a bare `return` is legal after a `lend`.

```saw
func pick(&var self, first: Bool, i: Int) borrows -> &var Int {
    if first { lend self.a[i] } else { lend self.b[i] }
    if self.quiet { return }        // end the epilogue early?
    print("epilogue")
}
```

**The options:**
- **(a) Allowed** (the lead's recommendation): after a `lend`, the value has been given, so the rest of the body is the epilogue and returns nothing. A bare `return` ends it early; a `return v` there is refused ("the value was already lent"). This matches `lend` as a suspension of the accessor, and is what a reader would expect.
- **(b) Refused:** an epilogue runs to its end; early exits use `if` around the rest. That's simpler, but needs a clear diagnostic pointing at the restructure.

Either way, typecheck's `body_result` must stop treating the epilogue as returning the lent type, and the message must say which rule applies. SL-868's matrix has 144 early-return cells waiting on this.

**RULED (the user, Oct 23): (a), allowed.** After a `lend`, the rest of an accessor's body is its epilogue and returns nothing. A bare `return` there ends the epilogue early; a `return v` there is refused with a message that the value was already lent. Typecheck's `body_result` stops treating the epilogue as returning the lent type. Unblocks SL-868's 144 early-return cells.

<!-- sawtracker:comment {"author":"agent:claude-sawlang","body_bytes":859,"created":"1792815611","id":"c2"} -->
**Lead, on step 1 (p870):** a bare `return` after a `lend` is refused today, while TWO valued forms compile and silently do the wrong thing: `return 7` in an epilogue drops the value; `return Some(6)` in a conditional accessor's prologue reads as absent (`lower_return` drops a `borrows` body's value). The lowering of a bare epilogue `return` is already right (80 cells clean under a prototype).
- **Ruled:**
  - the CFG decides: `split_accessor` knows prologue, epilogue and mixed, and borrowck's `check_epilogue` refuses a valued epilogue `return`;
  - typecheck allows a bare `return` in the accessor's own body (scoped, not closures);
  - a conditional prologue's bare `return` stays refused ("write `return None`"), and its only valued return is `None`;
  - an assertion in `lower_return` keeps the silent drop from coming back; the spec says all three.

<!-- sawtracker:comment {"author":"agent:claude-sawlang","body_bytes":350,"created":"1792815712","id":"c3"} -->
**Lead correction:** no assertion in `lower_return`: it runs before borrowck, so it would fire on the very programs meant to be refused. The guard is the borrowck checks themselves (`check_prologue`/`check_epilogue` visit every Return terminator by construction, documented in their docstring) plus the refusal pins (e10, a valued epilogue `return`).
