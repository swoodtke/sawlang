**An optional assignment whose head reads through a `?.` hop of its own is `slice.not-yet` in sawc** (found while building SL-883's chain read; the lead accepted the refusal).

Repro:

```saw
struct Leaf { n: Int }
struct Shelf { leaf: Leaf? }
extension Shelf {
    func find(&var self, i: Int) borrows -> &var Leaf? {
        if i != 0 { return None }
        lend self.leaf!
    }
}
struct Room { shelf: Shelf }

func main() {
    var r: Room? = Room(shelf: Shelf(leaf: Leaf(n: 1)))
    r?.shelf.find(0)?.n = 4
}
```

The target's head is the conditional lend `r?.shelf.find(0)`, and the head itself reads through `r?.`, a hop below the hops the assignment writes through.

**Why it is refused:** ruling W3 (spec, Optionals, "Chained assignment") evaluates the right side FIRST, on every path, and a short-circuit skips only the write. sawc's chain read tests a hop when its base is evaluated, and the assignment evaluates its head before its right side. So this hop would be tested before the right side runs, and an absent `r` would skip the right side, which W3 forbids. sawc refuses it with `slice.not-yet` at the hop's base (`check_head_hops` in `compiler/typecheck/src/bodies.saw`), citing this issue. The fixture is `compiler/tests/typecheck/refuse/slice.not-yet.optional-assign-head-hop.saw`.

Before SL-883 the same program was refused as `syntax.expr.optional-member`, so no program has moved.

**The work:** the assignment lowering (`lower_chain_write` in `compiler/mir/src/lower.saw`) prepares the head's subexpressions, then the right side, then the head's hops. A hop inside the head has to wait for the right side the way the write's own hops do. That means deferring the head's `payload` test past the right side, where the read path takes it eagerly (`hop_steps`).
