**Found by:** the Air (chat m433), while answering tcb2b's SL-492 question. **Area:** the new std (`std/vector.saw`), not Stage 0's frozen `sawc/std`.

**The defect:** `std/vector.saw` declares `public func get(&var self, index: Int) unsafe borrows -> &var T?`. That is the conditional lend's signature, under `get`'s name. There is no `find`.

**The ruling it contradicts:** SL:borrowing (Ruled, Sep 29) says "`v[i]` stays the panicking place, and `v.get(i)` the optional copy". It also says "`Vector.find(i)` is the Vector's conditional lend: `(&var self, index: Int) borrows -> &var T?` … with a shared twin … derived with `@synthesize(shared)`". Migration note K14 says "`get` returns an optional value, not a place". LANGUAGE_SPEC agrees, since SL-482: "`Vector.get(i)` is the optional copy of `v[i]` … `Vector.find(i)` is the conditional lend".

**Owed:**
1. `get(&self, index: Int) -> T?` becomes a plain value method. It copies the element, which is licensed by the element's Copy tier, as an inferred requirement in its generic body (D27).
2. Add `find(&var self, index: Int) unsafe borrows -> &var T?`, with its `@synthesize(shared)` twin. Use the hand-written `&self` twin if sawc2 can't synthesize yet; say which in the patch.
3. Sweep the rest of the new std for the same confusion. `Map`, `Data`, `String`, `Optional` and the other containers each get an optional copy under `get`, and a conditional lend under `find` or the name the spec gives.
4. Census the callers of `get` in the new std and in `compiler/tests` programs that build against `--std-root std`. A caller that writes through `get(i)!` must move to `borrow var v.find(i)…`.

**Why it matters now:** it decides the census for the "a `borrows` method is called only through `borrow`" rule that tcb2b is filing. With `get` a value method, the plain `.get(` calls in `compiler/*/src` are not `borrows` calls under the ruled language.
