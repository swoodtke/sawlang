User request (Oct 25): `posix_spawn` is the better primitive for launching processes than the runtime's hand-written `fork` + `exec` (`runtime/common/proc.saw` `proc_spawn_impl`).
- **Why:** no async-signal-safety window in a forked child; no copying of the parent's address space; exec errors come back directly (glibc and macOS report the exec errno as the return value); `POSIX_SPAWN_CLOEXEC_DEFAULT` on macOS closes every fd not explicitly inherited; and stdout/stderr redirection becomes `posix_spawn_file_actions_adddup2`.
- **Scope:**
  - the capture pipe and `merge_stderr` as file actions;
  - the environment override as `envp` (the env lock no longer needs to span a fork);
  - SL-898's exec-errno handling becomes the call's return value;
  - SL-910's child-side close becomes `CLOEXEC_DEFAULT` on macOS, or `addclosefrom_np` / file actions on Linux;
  - SL-898's `execve`-with-own-PATH-search becomes `posix_spawn` with a resolved path (keeping 'no shell, ever': `posix_spawnp` falls back to `/bin/sh` on `ENOEXEC` too, so resolve the path in the runtime and call `posix_spawn`).
- **Check:** the `posix_spawn` behaviour on both hosts (glibc version, `ENOEXEC`), and freestanding (no process spawning; unaffected).
- **After SL-898 lands,** so it ports a path that already reports causes correctly.

**Air, two pitfalls for the port, from the macOS man page (`posix_spawnattr_setflags(3)`) and the runtime's signal design:**

1. **`POSIX_SPAWN_CLOEXEC_DEFAULT` closes stdin, stdout and stderr too.** The man page: "only file descriptors explicitly created by the file_actions argument are available in the spawned process; all of the other file descriptors are automatically closed". A launch that captures stdout has a `dup2` for fd 1, but a `wait()` launch has no file actions at all, so its child would start with 0-2 closed. That means silent output, and the child's first `open` lands on fd 0. Name 0-2 explicitly (`posix_spawn_file_actions_addinherit_np` for each one not redirected). A pin: a `wait()` child that writes to stdout and stderr and reads stdin, with its output checked.

2. **Watched signals need `POSIX_SPAWN_SETSIGDEF`.** A watched signal's handler writes the parent's self-pipe (ABI.md, the watch family), and those pipe descriptors live for the process. Today, a forked child that receives a watched signal before `exec` runs the parent's handler and writes the delivery into the parent's pipe, so the parent counts a signal meant for its child. Separately, a caught signal resets to default only at `exec`. `posix_spawn` with `SETSIGDEF` over the watched set closes both, since the child starts with default dispositions and never runs the handler. A pin: a parent watching SIGINT launches a child, sends the child SIGINT, and the child dies of it (exit 130) while the parent's watch drains nothing.

(Neither is a regression of the port; both are things it should get right while it's there. On Linux, check glibc 2.36's `posix_spawn` `ENOEXEC` behaviour in the VM, as the issue says.)
