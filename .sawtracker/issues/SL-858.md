## Description

**On x86_64 Linux, `float_hook_hash` hashes a NaN differently from Stage 0** (found by p669, SL-669, Oct 23; pre-existing: reproduces at 2926dac32).

`tools/linux.py run-lane --arch x86_64 float_hook_hash`, deterministically: `line 5: sawc2 'nan 8058138970211093139', Stage 0 'nan 1165233065239906963'`. aarch64 Linux and darwin agree with Stage 0.

**Mechanism (UNVERIFIED):** the NaN's bit pattern differs on x86_64. An arithmetic NaN there gets the "default NaN" with the sign bit set (`0xFFF8…`), where ARM gives `0x7FF8…`, so a hash over raw bits differs, or the Float `Hashable` doesn't canonicalize NaN.

**Decide:**
- **Option 1:** `Float`'s `Hashable` canonicalizes every NaN to one bit pattern (and +0/−0, if equality treats them equal), so hashes agree across targets, matching `Equatable`.
- **Option 2:** the program pins a target-dependent value.

The spec's Float hashing text decides. Pin the bits under each compiler on x86_64 first. Obligation 4: every Float hash path (`Float`, `Float32`, a Float field in a synthesized `Hashable`, a Map or Set key).
