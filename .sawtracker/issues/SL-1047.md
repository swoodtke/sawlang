**User ruling (Nov 10, SL-1044 F1):** `std.compiler.frame` (`Slot<T>`, `UnsafeRef<T>`, `Resumable`, and its `Poll`) is RETIRED from the language. It was Stage 0's coroutine-transform vocabulary. sawc's transform lowers MIR directly and checks itself with the post-lowering verifier (`compiler/coro/src/verify.saw`), so the spec's reason for making the vocabulary public no longer holds. SL-596's port plan already says "do not port".

The SL-1044 round 2 removes it from §9 (the module table row and the `std.compiler.frame` section). This issue retires the rest:

1. **LANGUAGE_SPEC.md outside §9:** the "Value reads" fragments and the other uses marked "not in `sawc`'s std yet (SL-704)". Rewrite each example over a user-defined type that shows the same point, or drop the example when the point needs no type. Never change the rule an example demonstrates.
2. **tests/corpus/:** the programs that import `std.compiler.frame` (`grep -rl "compiler\.frame" tests/corpus`). Three of them are conformance rows: K27 (a receiver window never spans a suspend), K28 (a slot's payload is released exactly once) and O14 (a presence test is tier-independent). Each guarantee keeps a covering test: re-express it over a user type, or name another program that covers it, updating `tests/corpus/conformance/INDEX.md` first (obligation 3). The remaining programs are re-expressed or deleted. Each verdict move is recorded with `corpusdiff.py run --baseline`.
3. **The saw-lang skill:** its `std.compiler.frame` entries.
4. **SL-704 and SL-596:** close the `compiler.frame` line of each as retired.
