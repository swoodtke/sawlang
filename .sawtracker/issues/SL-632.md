**Local suite-lock runs yield to the server's gate: `suite_lock.sh acquire --yield-to-gate`** (proposed by the Air, chat m551; lead-approved).

- **Why:** the merge path waits on local runs. From today's merged gates (suite-lock wait / tests): SL-607 26m17s / 19m10s; SL-613 9m31s / 29m24s; SL-608 29m47s / 17m54s. A server gate that needs the lock queues behind an agent's local pin or step run. This is the merge path's single biggest cost now.
- **The rule:** `acquire --yield-to-gate` waits while the server's SL gate either holds the lock OR has a run queued. `sawtracker gate --project SL --json` reports both. It takes the lock only between gate runs, and re-checks right after taking it: if a gate run appeared, it releases and waits again. The gate's own acquire (`build.sh`) is unchanged.
- **Never starve the local run forever:** report the wait as the existing heartbeat does. If `sawtracker gate` can't be reached, fall back to the plain acquire, saying so.
- **Docs:** CLAUDE.md's suite-lock paragraph says local agent runs use `--yield-to-gate`. Its edit is one sentence; SL-622's patch also edits CLAUDE.md's per-commit paragraph, so expect a hunk merge. The lead's brief templates follow.
- **Pins:** `tools/test_suite_lock.py` gains cases with a stubbed `sawtracker gate`:
  - a queued gate run makes a yielding acquire wait;
  - an idle gate lets it take the lock;
  - a gate run that appears between the check and the take makes it give the lock back;
  - an unreachable tracker falls back, with the message.
- **Files:** `tools/suite_lock.sh`, `tools/test_suite_lock.py`, CLAUDE.md's suite-lock sentence, and TESTING.md if it describes the lock.
