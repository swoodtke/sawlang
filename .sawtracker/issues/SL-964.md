## Description

**Typecheck grants primitives builtin conformances the spec doesn't give, and mono refuses each one later, citing closed SL-715.** SL-715's last comment found the first two cells and named the fix (`primitive_grants` made per trait, as the spec lists them). The issue closed without that fix. SL-962's sweep (`.build/scratch/p962/sweep.md`, `matrix_after.txt`) found the rest still live on main.

**Cells typecheck accepts as a bound, which mono then refuses as `mono.not-yet`:**
- `Bool`: `compare` and `<` under `Comparable`. The spec's "Ordering" lists integers, `Float` and `String`.
- Raw pointers (`UnsafePointer`, `UnsafeMutablePointer`): `equals` and `==` under `Equatable`, and `hash` under `Hashable`. "Equality" lists integers, `Bool`, `Float` and `String`.
- `FuncPointer`: `equals`, `==`, `compare`, `<`, `hash`, `format`, `to_string` and `print("{}")`. `primitive_grants` treats it like a number, but the spec says only that it copies bitwise and is compared through `address()`.

**Mechanism:** `primitive_grants` (`compiler/typecheck/src/tier.saw`) is one blanket rule: every non-pointer primitive gets all five value traits, and the raw pointers get ExplicitCopy and Equatable, with Hashable through the trivial rule. The spec's lists are per trait.

**Fix:** make `primitive_grants` per trait, as the spec lists them, at every position a bound is checked: a call, a generic type argument, a bounded extension. The over-granted bounds become typecheck's bound error. mono's named refusals become unreachable, and their fixtures in `compiler/tests/mono/refuse/` (`bool-order`, `pointer-equality`, and the `std`/`derived`/`aggregate` cells citing SL-715) move to typecheck refusals.

**One spec question first (user):** "Hashing" says "primitives and `String`". Are raw pointers and `FuncPointer` primitives for hashing? The spec's other lists name raw pointers nowhere.
