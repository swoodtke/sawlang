## Description

**User ruling (Sep 29):** SL:hazards S23 gets a subset-checker rule, as an exception to the Stage 1 leak ruling.

**Why.** Stage 0 leaks an owned value consumed without a binding at three positions its owned-temporary check does not list:
- a comparison operand;
- an interpolation segment;
- a format argument of `print`, `panic` or `assert`.

A Stage 1 parser comparing token text (`self.toks[self.pos].text == word`), or interpolating a diagnostic, would leak once per token over every file it compiles. S23 has the evidence (chat f13 and f14, and the lead's format-argument measurements).

**The rule.** In `compiler/` source, refuse an owned operand that sawc's `_is_owned_temporary` accepts, at those three positions.
- String literals are exempt, since they are static.
- Use the predicate itself, not a list of syntactic shapes. The Air's census tool (`probe_cmp_census.py`, f14) wraps `_generate_binary_op` the same way.
- The refusal names S23 and the fix: bind the operand to a `let` first.

**Tests.** A fixture per position, covering:
- leaking shapes: a call, a subscript read, a field through a subscript, an interpolation;
- exempt shapes: a named place, a literal, a receiver inside a trivial operand.

The checker over `compiler/` must stay clean; the census finds 0 today in sawc2's cone. Lanes: `compiler` and `citations`.

**The rule, `owned-operand`** (SL:hazards S23; the user's exception to the Stage 1 leak ruling). The subset checker now compiles each build with Stage 0, in a child process with an object-only compile that writes nothing, up to 8 in parallel. It refuses at S23's positions, using sawc's own predicates:
- **Comparison operands:** `_generate_binary_op` for the six comparison operators, asking `_is_owned_temporary`.
- **Interpolation segments:** in `visit_StringInterpolation`:
  - a segment that `_is_builtin_interp_type` rejects renders through a synthesized `to_string()` that is never freed. It is refused whatever it names, a named `Printable` local included;
  - any other segment gets the owned-temporary check.
- **Format arguments of print, panic and assert:** `_format_pieces`, with the owned-temporary check. `Printable` format arguments measure clean and stay allowed.

String literals are exempt. Each refusal names S23 and the measured-clean fix. A build Stage 0 refuses gets a new `compile` diagnostic instead of skipping the check.

Approving SL-422.p1.

**The rule matches the measurements exactly.** I ran `subset_check.py --generated` on the ten probes behind S23's evidence (probes 2, 3, 4, 5, 7, 8, 9, 10, 12 and 13 in chat f13, f14 and f16). I compared its sites line by line with my census, which each probe's `leaks --atExit` numbers calibrate. On every probe the two flag the same lines: 65 sites, none flagged by one and missed by the other. That covers comparisons, interpolation segments (Printable included), format arguments, coroutine frame reads, and every clean shape: bound, sync-helper and named-place.

**What I checked**
- **`judge`:** string literals are exempt. `_needs_cleanup` is asked of the substituted `resolved_type`, then `_is_owned_temporary`. Aliases never reach it, because the subset's `type-alias` rule refuses them in `compiler/`.
- **Coverage:** `visit_StringInterpolation` records every non-builtin segment as `rendered`, and `_is_builtin_interp_type` resolves aliases itself. `_format_pieces` judges each argument. Sites outside the checked files, std's say, are dropped.
- **Harness:** the Stage 0 compile runs object-only in a child process, and a refused build reports `compile` instead of skipping.
- **Markers:**
  - ids are validated against the committed `.sawtracker/docs/hazards.md` (S and L headings), so the check stays hermetic;
  - the driver's two `IoError` interpolations become format arguments, each with its canonical marker;
  - the lexer's S4 comment is now a marker with its canonical text and a reason;
  - CLAUDE.md's rule 3 names the marker as the sanctioned leading reference.
- **Gate:** passed on the applied commit (tested_commit == applied_commit == 375bbe61). The tested tree 8106ca85 is the tree I get applying the diff to 4c610577.

**Nit, for parity only.** Codegen's `visit_StringInterpolation` substitutes `type_param_context` before `_is_builtin_interp_type`; the checker's `rendered` branch does not. In a generic body that interpolates a `T` instantiated as `String`, the checker would call the segment `rendered` where codegen takes the builtin path. That over-refuses and never misses a leak, and nothing in `compiler/` does it today. Mirroring the substitution keeps the checker and codegen asking the same question.
