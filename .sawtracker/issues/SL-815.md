## Description

**`Error` refines `Send`: the std half (SL-788 ruling 2), after a seed bump.** The user ruled on Oct 20 (SL-788 c11) that `Error` refines `Send`, so `any Error` is `Send`. The std edit, `public trait Error: Printable, Send` in `std/prelude.saw`, can't land with SL-788's unit. The `Error` lang item's shape is checked against a table (`compiler/typecheck/src/lang.saw`, `ErrorTrait`: `trait (parents Printable)`), and the seed carries the old table. Stage 1, the seed compiling the tree's `std/`, then fails with `lang.shape` (p788, Oct 22). This is the two-patch rule (compiler/README.md "The seed", SL-662).

**Sequence:**
1. **SL-788's unit (the compiler half):** `lang.saw` accepts both shapes, `(parents Printable)` and `(parents Printable Send)`, with a comment naming this issue. The existential's supertrait satisfaction is pinned there with a user-defined trait. `erased_error_spawned_task` and `coro_try_propagate_suspending` are refused in the meantime: a root whose result is `Result<Int, Box<any Error>>`, under the uniform check. Their baseline entries cite this issue.
2. **This issue, once SL-788's patch is on main:**
   - bump the seed to its merge commit (`compiler/tools/seed.py`, the Linux seeds through `tools/linux.py seed`, `seed.py check`);
   - make the `std/prelude.saw` edit and update the `Error` doc comment;
   - tighten `lang.saw` to the new shape only;
   - the spec's `Error` section states the refinement;
   - the two rows return to `pass` (baseline);
   - check every `Error` conformer in std and the corpus for a non-`Send` payload, and list what the refinement refuses (the SL-788 c9 sweep found one, `MyErr { code: Int }`, which is `Send`).
