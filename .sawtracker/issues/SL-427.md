## Description

# std File/Directory leak one block per call with a freshly built path (`path.as_str() as UnsafePointer<Int8>`)

Found by sawtracker's ST-66 (the per-request leak work) and reproduced by the sawtracker session on sawlang main **db49bc5e** at -O2.

## Reproducer
The body of `fileleak.saw`:
```saw
import std.env.{Env}
import std.file.{File}
import std.path.{Path}
func main() {
    let args = try! Env.args()
    let which = args[1]
    let n = args[2].to_int() ?? 0
    var hits = 0
    for i in 0..n {
        let path = "/tmp/st66-no-such-file-{i}"   // a fresh path each call, as a server builds one per request
        if which == "exists" {
            if File.exists(Path(s: path)) { hits += 1 }
        } else if which == "open" {
            if let _f = try? File.open(Path(s: path)) { hits += 1 }
        } else if which == "path" {
            let p = Path(s: path)
            if p.as_str().len() == 0 { hits += 1 }
        } else if which == "stored" {
            if File.exists(Path(s: which)) { hits += 1 }
        }
    }
    print("{hits}")
}
```
`sawc -O2 fileleak.saw -o fileleak`, then `leaks --atExit -- ./fileleak CASE N`:

| case | N=1000 | N=2000 |
|---|---|---|
| `exists` (fresh path) | 1,001 leaks | 2,001 leaks |
| `open` (fresh path) | 1,001 leaks | 2,001 leaks |
| `path` (`as_str()` only as a receiver) | none | none |
| `stored` (a path whose String outlives the loop) | 2 | 2 |

So each `File`/`Directory` call made with a newly built path leaks one block.

## Where
`std/file.saw` (~93 `_opened`, ~225, 231, 242, 243) and `std/directory.saw` (~61, 112, 123, 133, 168) do `path.as_str() as UnsafePointer<Int8>` and never release the String that `as_str()` returns. This is the S23 shape (an owned value consumed without a binding), inside std.

## Impact
In sawtracker, after ST-66 fixed every sawtracker-side site, this is the only leak left on the request path: 7 blocks per issue write (the event and issue files, each written through a temp file and a rename, plus a presence check), and 1 per past description a feed read has to load. Any long-running Saw program that opens files by computed path leaks this way.

## Suggested fix
Bind the String before the cast: `let path_text = path.as_str()` then `path_text as UnsafePointer<Int8>`, at each site, or through one helper. Mark each with `// Stage 0 workaround (SL:hazards S23): canonical: …` if that is how the std cone tracks it.

## Related findings from the same work, for the SL:hazards owner
Reproducer `trytail.saw` is in the sawtracker session's scratch (ST-66); ask if you want it posted.
- `try … catch { return … }` never releases the caught error, in synchronous and coroutine code alike.
- In a coroutine, `return try f()` never releases the error it propagates; in synchronous code it does not leak.
- A `match` on the Result drops the error in both cases.
- ST-66 marked its fixes for these `S3`. It is not certain that S3's text covers these shapes.
