## Description

The self-hosted Saw compiler, built test-first in the top-level `compiler/` directory. The Python compiler (`sawc/`) is frozen (Sep 24). It builds this compiler at bootstrap Stage 0, and it is the behavioural oracle, with known wrong answers.

## The design

- **SL:architecture:** the stages and their contracts, shared representation, caching, bootstrap, and the subset the compiler's own source is written in.
- **SL:borrowing** and **SL:testing:** the locked-down language features the compiler implements.
- **SL:hazards:** the shapes Stage 0 mishandles. The subset checker refuses the ones it can.
- **SL-393:** the rule inventory's carried rulings and test inputs.

## Strategy (user, Sep 25)

1. **The parser handles all valid Saw first,** as defined by the spec and the lockdown docs, with tests showing that everything parses as expected. With a valid AST for every valid program, the AST contract is complete before any later stage consumes it.
2. **Then bootstrap on a subset.** Resolve, typecheck, MIR, borrow check, drop elaboration and LLVM go deep, but only for the features the compiler's own source uses: the subset in SL:architecture §4. The first goal is self-hosting, the Stage 1 = Stage 2 fixpoint.
3. **Then widen,** one aspect at a time, to the full language.

The parser handles the full language, but it is written in the subset, so Stage 0 builds it. Syntactically valid forms that the lockdown retired (such as `g[4].weight += 1`) still parse. The semantic stages refuse them, with a hint naming the new spelling. So the whole existing tree is the parser's acceptance corpus.

## Standing rules

- **Test-first.** Every rule has a stable name (SL:testing §6), and each unit lands its tests with its code.
- **Internal tests until self-hosting** (SL:architecture §4): golden dumps, plus small subset programs the frozen compiler builds.
- **The compiler's source stays in the subset,** which the subset checker enforces. Its std imports come from a short allowlist.
- **The per-patch gate is path-aware** (SL:architecture §4).
- **Each unit is one squashed patch,** validated by the lead and reviewed by codex.

## Units

1. **U1:** the `compiler/` skeleton, with the lexer moved in, golden token fixtures, the test runner, the subset checker, and the path-aware gate.
2. **U2:** the grammar inventory. Every syntactic rule in the spec and the lockdown docs gets a stable name and a test matrix: every production, in every position.
3. **U3: the migrated corpus** (user, Sep 25: "the corpus/ for the tests is fine"; SL:architecture §5). A mechanical rewriter copies `examples/` into `tests/corpus/` in the new spellings. It flags what it cannot rewrite, and refuses the look-alikes that would silently change meaning (`m[k]! = v`, writes through `get`). `examples/` stays unchanged as the frozen compiler's corpus. The two are paired by file name for the behavioural differential. It lands before the parser units, so they have a new-syntax acceptance corpus.
4. **U4 to Un:** the full parser, one grammar area per unit, test-first against U2. The areas are declarations, types and generics, expressions and operators, statements and control flow, patterns, closures, and the lockdown forms. It has an arena AST with byte spans and the depth funnel. The finish line is the acceptance corpus: every tracked `.saw` except the parse-error tests. The Python parser's ASTs are checked once, for the unchanged part of the language, and after that only golden fixtures count.
5. **The bootstrap std:** the std modules in the compiler's dependency cone, in a form the new compiler can build at self-hosting (user, Sep 25: revisit std so it uses the same simplified Saw).
6. **The bootstrap slice:** semantics and codegen for the subset, up to self-hosting.
7. **Widening,** aspect by aspect.

Each unit is briefed when the one before it lands.

Review of the plan (claude-air-sawlang), against the docs it builds on. The order and the strategy read well. Five points:

1. **The bootstrap slice's scope is wider than "the subset".** Strategy step 2 and unit 6 scope semantics and codegen to "the features the compiler's own source uses: the subset". But from Stage 1 on, the new compiler also builds the new std. SL:architecture §4 says that std is "the subset plus a short, named list of low-level features: raw memory and pointers for buffers, allocator parameters, the runtime's extern seams, and `borrows` accessors with `lend`", and that "the bootstrap slice implements exactly that union". So unit 6 must cover `unsafe`, pointers, externs, allocator parameters and accessors, or Stage 1 cannot build its own std. Say "the subset plus the std's named features" in both places.

2. **Running clang is unresolved.** `Command.run()` and `output()` suspend, and the subset is sync-only. I've raised it on SL:architecture §4, with three options. U6 depends on the answer.

3. **U3's rewriter needs types, and the new compiler has none until U6.** Telling a `Vector` subscript (rewrite to `borrow var`) from a fixed-array index (leave alone), or a `Map` read (rewrite to `get`) from a `Vector` read, is a type question. So the rewriter has to run on the frozen compiler's front end, as SL:borrow-survey's instrument did: sawc's place-lowering funnel after a full typecheck, patched in-process. It inherits that instrument's blind spots, which then become "flag for manual migration" lists:
   - trait default bodies, static initializers and default parameter values, none of which the place pass walks;
   - files that fail before lowering, which covers most error tests.

   Naming the instrument in U3's brief avoids a text-level rewriter, which would get these wrong silently.

4. **U3 migrates expectations as well as code.** `examples/` has 966 error-test files (1,794 `EXPECT-ERROR-CONTAINS` lines). The new testing model matches refusals by rule-name ID, not text (SL:testing §5). Those IDs come from the rule inventory, which is only complete for syntax at U2 and for semantics much later. So:
   - code migrates at U3;
   - error expectations migrate as each rule gets its name, and until then a migrated error test is "expectation pending", not counted as a pass or a failure;
   - the 32 files with `EXPECT-IR-CONTAINS`/`-ABSENT` lines assert the Python compiler's IR text, which no new compiler will reproduce, so they are flagged for rewriting as MIR or IR dump tests, or retired;
   - error tests whose parse outcome the ruled grammar changes (R3's trailing-operator continuation, R7′'s statement arms) flip from "error" to "parses" in their migrated copy.

5. **The epic has no acceptance checklist,** so `close` has no definition of done beyond its units. Suggested items:
   - every file in the parser's acceptance corpus parses;
   - the Stage 1 = Stage 2 fixpoint holds;
   - the `tests/corpus/` differential passes, apart from annotated mismatches;
   - the subset checker (forms plus the API allowlist) passes over `compiler/` and the std cone;
   - the cone's hazard review is recorded.
