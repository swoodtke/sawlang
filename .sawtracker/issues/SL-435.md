## Description

The Air found this reviewing SL-408.p1 (SL:hazards t21). It is a new face of S7: a signed width suffix does not protect a literal.

Stage 0 checks a suffixed literal only against the unsigned range of its width. So a value above the signed maximum wraps silently:

| literal | prints |
|---|---|
| `255_i8` | -1 |
| `128_i8` | -128 |
| `65535_i16` | -1 |
| `4294967295_i32` | -1 |
| `18446744073709551615_i64` | -1 |

These are handled correctly today:
- `256_u8`, refused by the lexer;
- `-129_i8`, refused once negated;
- every literal whose type comes from context, such as `let v: Int8 = 255`.

**1. The checker rule (`compiler/tools/subset_check.py`).** This extends the existing `int-literal-range` rule.
- Refuse a literal with a signed suffix (`i8`, `i16`, `i32`, `i64`) whose value exceeds 2^(w−1) − 1.
- Allow exactly 2^(w−1) when it is the operand of a unary minus (`-128_i8`), the same way the rule already allows `-9223372036854775808`.
- Add fixtures for both sides.
- The rule's message names the unsigned suffix or the typed binding as the way out.

**2. GRAMMAR.md §2.7 `syntax.lex.int-range`.** It says a literal must fit "in its suffix's width", but not how a signed width counts. State it (SL:open-questions D6, reversible):
- The lexer checks the unsigned range of the width. So `256_u8` and `256_i8` are lexical errors.
- A signed suffix's literal is then held to the signed range by a later stage. The exception is 2^(w−1) as the operand of a unary minus, since the lexer cannot tell a negation from a subtraction.
- §16 records sawc's silent wrap as a `defect` row, and the self-hosted type layer owns the refusal.

Both are small, and they can ride with another checker or grammar batch.

One more measurement for item 1's fixtures. A signed suffix also wins over a context type in an argument:
- `take8(x: 200_i8)`, with `func take8(x: Int8)`, is accepted and prints -56;
- the unsuffixed `take8(x: 200)` is refused ("does not fit in `Int8`").

A typed binding is different: Stage 0 refuses `let v: Int8 = 255_i8` itself ("out of range for INT8"). So the existing `_allow_typed` exemption, which covers `let` and `static` only, stays harmless if the extension reuses it. But the rule must not exempt a suffixed literal in argument position.

Suggested fixtures:
- the argument case;
- `x - 128_i8`, which is refused, since the literal is a binary operand. The existing rule already keys on `UnaryOp`, so it should hold.

SL-435.p1 is up: 3 commits, 4 files, +68/−12.

**The rule** (`subset_check.py`, `int-literal-range`)
- **A literal's limit** depends on its suffix:
  - no suffix: `Int.max`;
  - a signed suffix `i8`, `i16`, `i32` or `i64`: 2^(w−1) − 1;
  - an unsigned suffix: none, since the lexer already holds it to its width.
- **The unary-minus exemption** is the same everywhere: exactly the limit + 1, as `-`'s direct operand.
- `_allow_typed` now covers unsuffixed literals only, so nothing but the unary minus exempts a signed-suffixed literal.
- **The new message:** "an `i8` literal above 127 wraps; give it the unsigned suffix `u8` or a typed binding".
- **Edge case:** Stage 0's parser drops parentheses, so `-(128_i8)` also passes. Stage 0 prints -128 for it, so nothing wraps, the same as the existing `-(9223372036854775808)`.

**The measurements**, all with the frozen compiler:
- **S7's table holds.** Every width wraps at 2^(w−1) (`32768_i16` is -32768, and `0x80_i8` is -128). The maximums and the negated minimums print correctly.
- **Refused today:**
  - by the lexer: `256_i8` and `65536_i16`;
  - once negated: `-129_i8` and its siblings at each width;
  - by the type checker, in a typed `let` or `var`: `let v: Int8 = 128_i8`.
- **The Air's c1 holds:** `take8(x: 200_i8)` prints -56, and `x - 128_i8` wraps.
- **New:** a typed `static` doesn't protect a literal either. `static wide: Int8 = 200_i8` prints -56. So do a return (`func f() -> Int8 { 200_i8 }`), an assignment and an array element. Only a typed `let` or `var` refuses one.

**The fixture:** `compiler/tests/subset/int-literal-range.signed-suffix.saw`.
- **Refused:**
  - `128_i8`, `32768_i16`, `2147483648_i32` and `9223372036854775808_i64`;
  - `255_i8`, `0x80_i8` and `-129_i8`;
  - the argument and binary-operand cases;
  - `let s: Int8 = 200_i8`, `let t: UInt64 = 9223372036854775808_i64` and `static wide: Int8 = 200_i8`;
  - a literal inside an interpolation.
- **Allowed:** each width's maximum and minimum, `255_u8`, and `static least: Int8 = -128_i8`.
- **Verdicts:** the checker reports exactly the 13 marked lines, and it reports nothing over `compiler/`.

**GRAMMAR.md (D6)**
- **§2.7 `syntax.lex.int-range`:**
  - a literal must fit in 64 unsigned bits, or in its suffix width's unsigned range, so `256_u8` and `256_i8` are both errors;
  - a later stage holds a signed suffix to its signed range, so `128_i8` is refused there;
  - the one exception is the minimum's magnitude as the direct operand of a unary minus (`-128_i8`), because `-` is a separate token and the lexer can't tell a negation from a subtraction.
- **§2.3's Integers bullet** agrees with it.
- **§16** gains a `defect` row: sawc wraps silently, and only a typed `let` or `var` refuses such a literal.
- `compiler/README.md`'s rule-table row now covers signed suffixes.
