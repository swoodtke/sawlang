## Description

U3 (SL-418) migrated accessor *uses*, not accessor *declarations*. `examples/`, and so `tests/corpus/`, has 124 `(&var self) borrows` and 107 `(&self) borrows` accessor declarations, and no `@synthesize(shared)`.

Under SL:borrowing §3 (declared modes), the accessor's receiver is the charge on the root. A `borrow let` through a `&var self` accessor holds its root exclusively for the window, even though the body only reads. `borrow let` prefers a `&self` variant when one exists, and `@synthesize(shared)` derives one, where the body permits.

**To decide, per accessor:**
- whether its migrated uses need a shared twin (`@synthesize(shared)`, or an explicit `&self` accessor when the bodies differ, K1);
- or whether the exclusive charge is what the test means.

A read through a `let` root of a `&var self`-only accessor is the case to find first. The migrate instrument records `accessor_self` for each window, so it can list them.

This is not needed for the parser units (U4 and on), which parse either way. It matters when resolution and typecheck reach `tests/corpus/`.

Two findings from SL-420 (see SL-420 c7) belong here:
1. **A class the migrate tool misses.** §5.2 derives getitem only from a `&self` place accessor. So on a type whose only accessor is `&var self`, a plain `x[i]` read or `x[i] += v` is a refusal in the new language, and rules G1 and A2 don't flag them. That includes files already marked `copied` or `rewritten`, such as K123's `b[0] += 1`. Sweep for these first. Each hit is the same per-accessor decision this issue already asks for: add a shared twin, or re-aim the test as a refusal.
2. **Std shared twins.** SL:borrowing rules twins only for `Vector.[]`, `Vector.find` and `KeyedPlace.find`. `json_value_accessors` needs `as_array`/`as_object` on a `let` root. Proposed default, as a reversible D entry when this is dispatched: a std accessor whose body only reads gets a `@synthesize(shared)` twin (§4), and the lead lists each such std accessor for review.
Also D8 (SL:open-questions): a type declaring a shared/exclusive pair derives getitem from the `&self` accessor and setitem from the `&var` one.
