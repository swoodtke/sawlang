**The conformance ledgers merge by union, and their row ids are checked unique** (the Air, chat m555; lead-approved).

- **Why:** every safety patch appends rows at the same place in `examples/conformance/INDEX.md` and `compiler/tests/borrowck/CONFORMANCE.md`, so in a queue of them each one conflicts with whatever merged ahead of it. SL-612 alone needed two hand rebases today, over SL-608 and then SL-611, and the E, B and D units will hit the same thing.
- **The change:**
  - mark both ledgers `merge=union` in `.gitattributes`. `git apply --3way`, which the server uses, and the merge queue's rebase both go through ll-merge, which honours it, so appended rows from both sides are kept. Sweep for other accumulator files with the same shape, other conformance-row tables or `*.tsv` ledgers, and include each that is append-only with a unique id per row;
  - add a uniqueness check over each ledger's row ids. Union silently keeps a duplicate id when two patches pick the same number. The check runs IN THE SERVER'S GATE, as a `compiler/tests/run.py` step or inside an existing step that already reads the ledger (the borrowck lane reads CONFORMANCE.md), never only in a battery lane. A duplicate fails with both rows quoted.
- **Pins:**
  - a fixture ledger with a duplicate id fails the check;
  - a scratch git repository shows two branches appending different rows at the same place merging cleanly under the attribute (and conflicting without it), through `git apply --3way` as the server does.
- **Files:** `.gitattributes` (new or extended), the check's home, and its fixture. CLAUDE.md's integration paragraph, which warns against `checkout --theirs` on accumulator files, gets one sentence naming the union-merged ledgers.
