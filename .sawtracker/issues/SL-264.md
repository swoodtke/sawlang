## Description

Found while fixing SL-239 (value-branch reconciliation). PRE-EXISTING and orthogonal to SL-239's over-rejection — the SL-239 fix does not touch the None-handling reconciliation path, so this reproduces before and after it.

At an annotated, NON-tail value destination whose type is a NESTED optional (`Int??`, `String??`), a bare `None` arm of a value `if`/`match` is treated as `Some(None)` (the inner absence, one wrap applied around the whole branch) rather than as the OUTER absence — which is what DF-289d ruled a bare `None` arm means at a TAIL (`-> Int??`), where `Map._get_value`/`Vector.pop` rely on it.

Minimal repro:

    func main() {
        let inner: Int? = None
        let x: Int?? = if false { inner } else { None }   // else = bare None
        if let a = x {
            if let b = a { print("some-some {b}") } else { print("some-none") }
        } else {
            print("outer-none")
        }
    }

Actual: prints `some-none` (x == Some(None)). Expected (for consistency with the DF-289d tail rule): `outer-none` (the `else { None }` is the outer absence, x == None).

Mechanism (source inspection): a value `if` in an annotated `let`/assignment/arg/field position reconciles its arms in `_check_if_expr` (typechecker/expressions.py) to the inner optional (`Int?`), then the POSITION's ordinary transfer checkpoint wraps the WHOLE branch result once into `Int??` (an OptionalWrap around the entire `if`). That is exactly the DF-289d hazard: wrapping the merged expression rather than DISTRIBUTING the wrap into the arms per-leaf adds the layer where the merge landed on a payload, and turns a bare-None arm (which should be the outer absence) into `Some(None)`. Tails avoid it via `_wrap_tail_into_optional` (statements.py), which distributes per-leaf and honours a None arm as the outer absence; the non-tail annotated positions have no equivalent distribution.

Fix direction (not attempted): thread `_wrap_tail_into_optional`-style per-leaf distribution into the annotated non-tail value positions (let/assignment/argument/field/element/static) so the None-arm-is-outer-absence rule is uniform with tails, OR do the arm-wrapping inside `_check_if_expr`/`_reconcile_match_arm_types` using the destination expected type. Scope per obligation 4: every annotated value position × a nested-optional destination × a bare-None arm, both `if` and `match`, both arm orders.

Distinct from SL-239 (which was over-REJECTION of a T?/T mix; this is a wrap-layer semantics bug on the ACCEPTED path). Filed as a separate finding rather than folded into the SL-235/239 patch to keep that patch scoped.
