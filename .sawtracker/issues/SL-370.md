## Description

Found by an SL-357 wave-3 comment agent on Sep 23; I reproduced it on main (.build/scratch/unsigned_compound.saw).

| Operation | Result | Correct |
|---|---|---|
| `var a: UInt8 = 200; a /= 3` | 238 | 66 |
| `c %= 7` (c: UInt8 = 200) | 0 | 4 |
| `UInt64 18446744073709551600 /= 2` | 18446744073709551608 | 9223372036854775800 |

The binary `/` and `%` operators give the right answers (operators.py picks udiv/urem).

**Mechanism:** `codegen/statements.py _apply_compound_op(op, left, right, signed)` uses `signed` only to decide whether to emit the INT_MIN/-1 overflow check, then emits `sdiv`/`srem` unconditionally. Every compound-assignment position funnels through this one function:
- the local, field, index and deref forms in statements.py (5 call sites);
- the optional-chain `x?.f /= y` path in optionals.py.

So the class is these two branches of one funnel. The other compound ops already respect `signed`: `+`/`-`/`*` go through `_checked_arith`, shifts through `_emit_shift`, and bitwise ops are sign-agnostic.

**Fix:** udiv/urem when `not signed`, mirroring operators.py.

**Pins:** `/=` and `%=` for UInt8, UInt16, UInt32, UInt64 and UInt, each in local, struct-field, Vector-index and optional-chain position; a signed control row; divide-by-zero still panics.

Silent wrong code, so high priority. Fix-on-discovery; the implementer is claude-air-sawlang.
