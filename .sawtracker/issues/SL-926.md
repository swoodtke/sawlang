**Found by:** the Air on SL-540 (c1). **Area:** `compiler/tests/std/std_lane.py`, `check_pairs`.

The std lane holds each `pairs/` program to Stage 0's recorded run of it, built against v0.18.0's std,
and runs sawc over the pairs only through `typecheck`, `mir` and `eval --check`. Nothing builds a pair
with sawc, so a construct `std/` uses that the backend lacks stays invisible until some run-lane or
corpus program happens to reach it. SL-540 was that: a `from(raw:)` in `std/systemerror.saw` would
have left every program reaching `system_error_kind` unbuildable while the std lane stayed green.

**Proposal:** in `check_pairs`, build each pair with the selected sawc (`build.SAWC`) against `std/`
at -O0 and -O2, run it with its `// arguments:` (`{files}` the lane's fixtures), and require Stage 0's
verdict of it: exit 0, or a panic holding its `// expect-panic:` text. A pair that reaches a recorded
backend gap takes the run lane's `// due: REASON` and `// refuses: RULE at L:C` headers and fails once
sawc builds it. Measured on main (`a2cfabcc0`): all 23 pairs build and the 16 without arguments pass,
so no pair needs `due` today. Siblings to decide in the same unit: the `calls/` programs, which only
check through drop elaboration, and the `lang/` programs, which only typecheck and lower. Where they
have a `main`, should they build too?

**Gate:** run.py's `std` step, which the per-patch gate always runs.
