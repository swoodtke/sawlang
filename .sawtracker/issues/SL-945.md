**`x == None` needs `T: Equatable` on one spelling of an Optional and not on another.** Found by SL-941's census (`.build/scratch/p941/census.md`).

- A conditional lend compared with `None` (`v.find(0) == None`, `!= None`, `None == v.find(9)`, where `find` is `borrows -> T?`) reads the tag alone and reaches nothing. It compiles when `T`'s derived `Equatable` has a member that doesn't conform.
- A plain `let a: Holder? = …; a == None` runs Optional's `==`, which reaches `Holder`'s derived `equals`. With such a member it is refused as `synthesize.unmet-member` (SL-941, pinned as a refusal row).

The spec has no comparison rule special to `None`, so the refusal is what the spec says today, and the lend shape is the exception.

**The question for the user:** should comparing any Optional against the `None` literal be a tag test that needs no `Equatable` (Swift's `x == nil` works for any Optional), or should both spellings need `T: Equatable`? Either way the two spellings should agree.
