## Description

# U6a: name resolution (the bootstrap slice, stage 1)

- **Epic:** SL-398, unit 6 (the bootstrap slice): the first semantic stage. The user gave the go on Sep 30.
- **Design:**
  - SL:architecture §3.0 (what every stage shares), §3.3 (name resolution), §4 (the subset and bootstrap), and §5 (testing per stage);
  - the resolution rules of designs 80, 100/107, 142, 150, 229 and 255, which the spec states;
  - SL:borrowing and SL:testing, for names in the lockdown forms.
- **Package:** `compiler/resolve/`, package `sawresolve`. It depends on `sawparse`, is registered in `STAGE_PACKAGES`, and is written in the bootstrap subset. The subset checker passes over it, and Stage 0 workaround markers apply (compiler/README.md).

## Decisions (the lead, with the user's go)
1. **The input is the parser's arena, unchanged.** Resolve produces side tables keyed by AST ids, and the AST is never modified (§3.0). No lowered form comes in between.
2. **`import std.*` paths keep today's layout:** one module per file, as `sawc/std` has it. So the compiler source means the same thing against either std. Until the new std exists, resolve reads std's *interfaces*, meaning its declarations, from `sawc/std`'s sources, parsed by sawc2.
   - **Say what this needs:** the new std, unit 5, replaces the sources, not the paths.
   - **What is out of scope:** a std file that sawc2 can't parse, such as `data.saw`'s `#lend_var`. Resolve takes such a module's interface only as far as the compiler's cone needs, per `compiler/tools/std_cone.txt`, and reports any declaration it can't take.
3. **The dump is an S-expression, like the AST dump.**
   - **Contents:** each name occurrence is listed with its span and its binding. A binding is a local (by declaration span), a declaration (module plus path, plus the signature for an overload), an overload set, an enum case, a type parameter, a module or a trait.
   - **Call heads:** each carries its classification (§3.3).
   - **Tables:** the module symbol, export and import tables follow.
   - **Specified in** `compiler/tests/resolve/README.md`, the way `compiler/tests/parse/README.md` specifies the AST dump.
   - **Invocation:** `sawc2 resolve --dump <files>`.

## Scope: the subset, not the full language (the epic's strategy step 2)
**Resolve these:**
- everything that `compiler/`'s own source uses;
- the std cone's declarations;
- the new std's named low-level features: `unsafe`, raw pointers, extern seams, allocator parameters, and `borrows` accessors with `lend`.

**The position matrix.** Write down the constructs from the subset checker's rules and the cone, as the unit's matrix.

**Refusals outside the slice.** A construct outside the slice is refused with a stable diagnostic, "not in the bootstrap slice yet", naming the construct. It is never silently mis-resolved.

## The contract (§3.3)
1. **Phase 1, collect.** Each module's top-level declarations go into its symbol table before any name is looked up. That covers types, functions as overload sets, enum cases, traits, statics, extensions and conformances. Duplicates are refused here.
2. **Phase 2, imports.** A qualifier, `.*` or `.{A, B as C}` binds what it names (design 150). Re-exports (design 229) reach a fixpoint by worklist, with cycle detection.
3. **Phase 3, signatures and bodies.** Names are looked up in design 150's order: locals, then module declarations, then imported bare names, then the gated std tier (design 255, for the precise "import it" error), then qualifiers. Self-reference and mutual recursion work.
4. **Call heads are classified once:** a type's `init` set, an overload set, a closure local, a type parameter, an enum case, or a function-value call (SL-73).
5. **Rules about names live here:**
   - path visibility (design 80);
   - shadowing (designs 100 and 107);
   - test-only names;
   - duplicate and orphan conformances (design 142);
   - each module's visible extension set, handed on to typecheck.
6. **Invariant:** no later stage looks a name up by its spelling. Cross-module references are symbolic, and ids are module-local.

## Tests, test-first
- **Golden dumps** under `compiler/tests/resolve/`, with a runner lane in `compiler/tests/run.py`.
- **A refusal fixture for every name rule,** with its stable id (SL:testing §5). Multi-file refusals are corpus files.
- **A verifier,** run on every dump:
  - every name occurrence is resolved exactly once;
  - every reference is in range;
  - no lookup by spelling is left over.
- **The acceptance target:** `compiler/`'s own source resolves whole, with no refusals and no "not in the slice" diagnostics. Report how much of `tests/corpus/` resolves as information only, and don't gate on it.
- **A cross-check against the frozen compiler,** where it resolves the same program: its answers are checked once and recorded, and are never the definition.

## Rules
- **Where to work:** stay inside `compiler/resolve/`, `compiler/tests/resolve/`, `compiler/driver/` (the `resolve` subcommand), `compiler/tools/build.py` (to register the package) and `compiler/tests/run.py` (the lane). SL-410 is working concurrently in `compiler/parse/`, `compiler/tests/grammar/` and `compiler/tests/parse/`.
- **Parser gaps:** if resolve needs something the parser doesn't give (a span, a node kind), report it, and don't edit `compiler/parse/`.
- **`sawc/` is frozen.** A Stage 0 bug that blocks you stops that item, and you report it with a minimal repro. Work around it only with a Stage 0 marker for a hazard that SL:hazards names.
- **Decisions:** a reversible reading goes in the report. A change of meaning, or something the design doesn't settle, stops that item and goes in the report.
- **Measured performance:** report the time to resolve `compiler/`'s own source.

## Gates

Comments on the brief before the agent gets far. The contract follows §3.3. Three things it doesn't settle, and the acceptance target meets the first two on its first line.

1. **Builtins have no declaration to bind to.** Nothing in `sawc/builtin.saw` or `sawc/std` declares these:
   - the primitive types (`Int`, `UInt8`, `Bool`, `Float` and the rest);
   - `String`: std/string.saw holds only its extension;
   - `Optional` and `Result`, which Stage 0 synthesizes (the SL-441 review);
   - `print`, `panic`, `assert`, `sizeof`, `alignof`;
   - `Self`, `Void`, `Never`.

   §3.3's binding kinds (local, declaration, overload set, enum case, type parameter, module, trait) have no slot for them. One way to fill it: a synthetic `builtin` module whose declarations bind like any other, so that `String` becomes (builtin, String). It is one table, and the prelude draws from it. The unit should decide that up front, not discover it at `compiler/`'s first `Vector<String>`.
2. **The prelude needs one table.** Stage 0 defines it by exclusion. Every std or builtin symbol is visible bare except `IMPORT_REQUIRED_STD_MODULES` and `IMPORT_REQUIRED_STD_SYMBOLS` (`sawc/sawc.py`), and `_is_prelude` applies them.
   - Design 82 describes the prelude as a curated core, which is an inclusion list. An inclusion list also fails safe: a new std module is then gated by default.
   - **Suggested:** resolve keeps an inclusion table, and a one-time check shows that it equals Stage 0's computed set over today's std. The design-255 gated tier then comes from the same table.
3. **The frozen cross-check needs a source of answers.** `sawc.py --emit-ast` prints names and types, not the declaration each name bound to. That is what my probe of a small program showed. Hooking the frozen typechecker in-process would record what each call head and name resolved to. `compiler/tools/std_cone.py` does the same for codegen, and it worked well. Scoping the check to call-head classification and import bindings would keep it bounded.

SL-445.p1 is up: U6a, name resolution (SL:architecture §3.3). 6 commits, 99 files, +9017/−4:
- `compiler/resolve/` (package `sawresolve`): about 5,400 lines of Saw;
- `compiler/tests/resolve/`: the golden cases, the fixtures, the READMEs and four Python scripts;
- the driver's `resolve` subcommand, `run.py`, `build.py`, and `compiler/README.md`'s layout and testing lists.

**The stage.** `sawc2 resolve (--dump | --check) [--notes] [--std-root DIR] [--module-path N=D]... FILE...` reads the parser's arena unchanged. It produces side tables keyed by arena ids, and `compiler/resolve/README.md` has the phases.
1. **Collect,** as each module loads: top-level declarations per (module, name), functions as overload sets, members per (parent, name), and enum cases by name. Duplicates and prelude-name clashes are refused here.
2. **Imports:** cycle detection by an explicit-stack depth-first search, then each surface grows to a fixpoint (design 229), then selective imports resolve.
3. **Signatures and bodies** go through one lookup funnel (`lookup.saw`, design 150's order with design 255's gated tier) and one binder (`bind_local`, the shadowing rule of designs 100 and 107). Both docstrings list their entry points.

Then the orphan and duplicate conformance rules run. Std is read as interface only. Builtins live in the synthetic `builtin` module, and the prelude is an inclusion table (D12).

**The dump** is specified in `compiler/tests/resolve/README.md`. Each module's S-expression holds `names`, `calls` (9 classes), `declarations` with signatures in resolved identities, `surface`, `imports` and `extensions`.

**The verifier** runs on every resolve. It finds occurrences from the tree by its own rule and checks three things:
- each is recorded once, and each call is classified once;
- each binding is in range and of its stated kind;
- nothing is left unbound.

**Coverage:**
- **The position matrix:** about 40 rows in the tests README, each naming its golden case. There are 10 single-file cases, one of them covering the lockdown forms, and one multi-file case.
- **Refusal fixtures:** 40, covering all 25 rule ids. The lane fails any rule without one.
- **The slice:** `slice.not-yet` refuses `$0`, `module` declarations, `package`/`parent` paths, `Thread.spawn`/`Task.spawn` and the `__saw_*` test intrinsics.

**Acceptance:** the sawc2 build and 13 unit programs resolve with no refusal and no invariant. `compiler/lex/tests/escapes.saw` is counted apart: the parser refuses it, as its `corpus_expected.tsv` row already records. Resolving all of sawc2, including parsing the 33 std files it reads interfaces from, takes about 0.04 s.

**Readings (reversible):**
1. A lone name pattern is a case when any enum declares it, and otherwise binds. This is logged as **D13**, and U6b's typecheck refuses a candidate set with no case in the scrutinee's enum.
2. Case selectors record their candidates, and typecheck picks.
3. Only module members, and enum cases reached through their enum, are resolved here. Other members are typecheck's.
4. The import search order: a mapped package's `lib.saw`, then beside the importing file, then beside the entry, then under the nearest `Saw.toml` root.
5. `public(parent)` means modules under the owner's parent path.
6. Refusal fixtures are one per file, since resolve has no test-build mode yet.

**Findings:**

Routed to SL-443 as a new-std input.

The frozen compiler refuses `self.take(&parser.builder.tree.nodes, …, root)` across modules, after `let root = parser.builder.tree.root`, with ``undefined variable `root` ``.
