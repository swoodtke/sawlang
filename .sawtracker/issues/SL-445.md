## Description

# U6a: name resolution (the bootstrap slice, stage 1)

- **Epic:** SL-398, unit 6 (the bootstrap slice): the first semantic stage. The user gave the go on Sep 30.
- **Design:**
  - SL:architecture §3.0 (what every stage shares), §3.3 (name resolution), §4 (the subset and bootstrap), and §5 (testing per stage);
  - the resolution rules of designs 80, 100/107, 142, 150, 229 and 255, which the spec states;
  - SL:borrowing and SL:testing, for names in the lockdown forms.
- **Package:** `compiler/resolve/`, package `sawresolve`. It depends on `sawparse`, is registered in `STAGE_PACKAGES`, and is written in the bootstrap subset. The subset checker passes over it, and Stage 0 workaround markers apply (compiler/README.md).

## Decisions (the lead, with the user's go)
1. **The input is the parser's arena, unchanged.** Resolve produces side tables keyed by AST ids, and the AST is never modified (§3.0). No lowered form comes in between.
2. **`import std.*` paths keep today's layout:** one module per file, as `sawc/std` has it. So the compiler source means the same thing against either std. Until the new std exists, resolve reads std's *interfaces*, meaning its declarations, from `sawc/std`'s sources, parsed by sawc2.
   - **Say what this needs:** the new std, unit 5, replaces the sources, not the paths.
   - **What is out of scope:** a std file that sawc2 can't parse, such as `data.saw`'s `#lend_var`. Resolve takes such a module's interface only as far as the compiler's cone needs, per `compiler/tools/std_cone.txt`, and reports any declaration it can't take.
3. **The dump is an S-expression, like the AST dump.**
   - **Contents:** each name occurrence is listed with its span and its binding. A binding is a local (by declaration span), a declaration (module plus path, plus the signature for an overload), an overload set, an enum case, a type parameter, a module or a trait.
   - **Call heads:** each carries its classification (§3.3).
   - **Tables:** the module symbol, export and import tables follow.
   - **Specified in** `compiler/tests/resolve/README.md`, the way `compiler/tests/parse/README.md` specifies the AST dump.
   - **Invocation:** `sawc2 resolve --dump <files>`.

## Scope: the subset, not the full language (the epic's strategy step 2)
**Resolve these:**
- everything that `compiler/`'s own source uses;
- the std cone's declarations;
- the new std's named low-level features: `unsafe`, raw pointers, extern seams, allocator parameters, and `borrows` accessors with `lend`.

**The position matrix.** Write down the constructs from the subset checker's rules and the cone, as the unit's matrix.

**Refusals outside the slice.** A construct outside the slice is refused with a stable diagnostic, "not in the bootstrap slice yet", naming the construct. It is never silently mis-resolved.

## The contract (§3.3)
1. **Phase 1, collect.** Each module's top-level declarations go into its symbol table before any name is looked up. That covers types, functions as overload sets, enum cases, traits, statics, extensions and conformances. Duplicates are refused here.
2. **Phase 2, imports.** A qualifier, `.*` or `.{A, B as C}` binds what it names (design 150). Re-exports (design 229) reach a fixpoint by worklist, with cycle detection.
3. **Phase 3, signatures and bodies.** Names are looked up in design 150's order: locals, then module declarations, then imported bare names, then the gated std tier (design 255, for the precise "import it" error), then qualifiers. Self-reference and mutual recursion work.
4. **Call heads are classified once:** a type's `init` set, an overload set, a closure local, a type parameter, an enum case, or a function-value call (SL-73).
5. **Rules about names live here:**
   - path visibility (design 80);
   - shadowing (designs 100 and 107);
   - test-only names;
   - duplicate and orphan conformances (design 142);
   - each module's visible extension set, handed on to typecheck.
6. **Invariant:** no later stage looks a name up by its spelling. Cross-module references are symbolic, and ids are module-local.

## Tests, test-first
- **Golden dumps** under `compiler/tests/resolve/`, with a runner lane in `compiler/tests/run.py`.
- **A refusal fixture for every name rule,** with its stable id (SL:testing §5). Multi-file refusals are corpus files.
- **A verifier,** run on every dump:
  - every name occurrence is resolved exactly once;
  - every reference is in range;
  - no lookup by spelling is left over.
- **The acceptance target:** `compiler/`'s own source resolves whole, with no refusals and no "not in the slice" diagnostics. Report how much of `tests/corpus/` resolves as information only, and don't gate on it.
- **A cross-check against the frozen compiler,** where it resolves the same program: its answers are checked once and recorded, and are never the definition.

## Rules
- **Where to work:** stay inside `compiler/resolve/`, `compiler/tests/resolve/`, `compiler/driver/` (the `resolve` subcommand), `compiler/tools/build.py` (to register the package) and `compiler/tests/run.py` (the lane). SL-410 is working concurrently in `compiler/parse/`, `compiler/tests/grammar/` and `compiler/tests/parse/`.
- **Parser gaps:** if resolve needs something the parser doesn't give (a span, a node kind), report it, and don't edit `compiler/parse/`.
- **`sawc/` is frozen.** A Stage 0 bug that blocks you stops that item, and you report it with a minimal repro. Work around it only with a Stage 0 marker for a hazard that SL:hazards names.
- **Decisions:** a reversible reading goes in the report. A change of meaning, or something the design doesn't settle, stops that item and goes in the report.
- **Measured performance:** report the time to resolve `compiler/`'s own source.
