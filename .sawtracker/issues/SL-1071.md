## Description

**SL-1063 unit C: Blade builds an ESP32-S3 image: the `SosimgArch` tag, the arch answer for the triple, and the C half's CPU and feature flags.** Independent of units A and B in files (`blade/`, `libs/imgformat/`), and the next thing sawos is blocked on after its kernel boots: root and child images go through Blade, so no user process runs on the S3 until this lands (the sawos lead, chat m717). The lead posts the merged sha to them at once.

**Agreed with the sawos lead (chat m701): `SosimgArch` Xtensa = 3.**

**What the sweep found (`.build/scratch/pxtensa/sites.tsv`, the `blade/` and `libs/` rows).**
- `libs/imgformat/src/lib.saw`: `enum SosimgArch: UInt8 { Riscv32 = 1, Arm64 = 2 }` with `tag()` and `describe()`. The kernel compares the tag.
- `blade/src/sosimg.saw`: `arch_for_target` maps a triple's prefix to the tag and makes an unknown triple an error; `toolchain_defaults` gives a triple's `march`, `mabi` and `target_features`; `SosConfig` reads the `[sos]` keys `march`, `mabi`, `target-features`, `linker-script`, `native`; `sos_clang()`/`sos_ld()` take `SOS_CLANG`/`SOS_LD` from the environment.
- `blade/src/builder.saw`: the C compile passes `--target=`, `-march=` and `-mabi=` (each only when non-empty); the sawc compile passes the manifest's `--target-features`.
- Espressif's clang refuses `-march=` and `-mabi=` for Xtensa. It selects the chip with `-mcpu=esp32s3`, and a feature for C is `-Xclang -target-feature -Xclang <feature>`. `.S` files need `-fintegrated-as`.

**The rule that matters: the two halves of an image are compiled for one convention.** sawc (unit A, SL-1067) compiles every Saw function for this triple with CPU `esp32s3` and the features `-windowed,-fp,-loop,-mac16,-bool`, then whatever `--target-features` adds. `-windowed` is the calling convention. So Blade must hand the C half the same CPU and the same list, in the same order, or a call between the halves is wrong.

**Lead decisions (reversible; logged here).**
1. `ToolchainDefaults` gains `mcpu` and `native_features`. For a triple starting `xtensa`: `march` and `mabi` empty, `mcpu` `"esp32s3"`, `target_features` empty (sawc's own default applies; Blade passes `--target-features` only when the manifest states one), `native_features` `"-windowed,-fp,-loop,-mac16,-bool"`. For riscv32 and aarch64 the two new fields are empty and nothing they emit changes.
2. `[sos]` gains an `mcpu` key, read and overridden per `[sos.<triple>]` exactly as `march` is.
3. The C compile for an image: `--target=T`; `-mcpu=X` when `mcpu` is non-empty; then for each feature of `native_features` followed by the manifest's `target-features` (the same append rule sawc applies on this triple), `-Xclang -target-feature -Xclang F`; and `-fintegrated-as` when the unit is a `.S` file and `mcpu` is non-empty (the external assembler writes sections Espressif's linker refuses). For a triple with empty `mcpu` and `native_features` the command line is byte-identical to today's.
4. Blade restates sawc's default list (decision 1) rather than asking sawc for it, as it already restates riscv32's `+m,+a,+c`. **A pin keeps the two from drifting:** a check that the feature list Blade gives the C half for the Xtensa triple equals the `"target-features"` sawc writes for it (step 5).

**Changes.**
- `libs/imgformat/src/lib.saw`: `case Xtensa = 3`; `describe()` answers `"xtensa"`; the doc line that says riscv32 and arm64 are both little-endian names Xtensa too (the sweep: `__XTENSA_EL__` is 1). Whatever decodes a tag byte back to a case (`SosimgArch.from(raw:)` call sites, any `match` over the enum in `libs/` and `blade/`) gains the case; a `match` that is not exhaustive after the change is a compile error, which is the sweep you want: fix each by adding the case, and list them.
- `blade/src/sosimg.saw`: `arch_for_target` answers `SosimgArch.Xtensa` for a triple starting `xtensa`; `ToolchainDefaults`, `toolchain_defaults`, `SosConfig` and its reader per decisions 1 and 2.
- `blade/src/builder.saw`: the C compile per decision 3.
- Nothing in `compiler/`, `std/` or `tools/freestanding_runner.py`.
