## Description

Found by the SL-340 implementer (Sep 24). Reproduces on main.

A generic struct constructed with an EXPLICIT nested type argument never drops its field; the same construction with the argument INFERRED drops correctly:

```saw
struct Noisy { name: String }
extension Noisy: NoCopy {
    func deinit(&var self) { print("drop {}", self.name) }
}

struct Plain<T> { v: T }
extension Plain<T>: NoCopy {}

func plain_scope() {
    var v: Vector<Noisy> = []
    try! v.push(Noisy(name: "plain"))
    let w = Plain<Vector<Noisy>>(v: move v)     // never drops: a leak
    print("plain scope end")
}

func inferred_scope() {
    var v: Vector<Noisy> = []
    try! v.push(Noisy(name: "inferred"))
    let w = Plain(v: move v)                     // drops once, correctly
    print("inferred scope end")
}

func main() { plain_scope(); inferred_scope() }
```

The implementer's mechanism: `_type_method_base` (codegen) fills DEFAULT type arguments only on the outer type. `Vector<Noisy>` written explicitly lacks its defaulted allocator argument, so the mangled deinit symbol it looks up is not the one that was generated, the lookup misses, and nothing drops. Confirm, and sweep the other places a written type with omitted defaults is mangled:
- deinit, retain and copy lookups;
- statics;
- trait conformance thunks.

The fix belongs in the canonicalization funnel: a type is completed with its defaults at every depth before it is mangled.
