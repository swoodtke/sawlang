## Description

**Filed by the sawos lead for the sawlang lead.** The user asked that sawos's build tools be written in Saw, not Python, and that the gaps be filed here. Each was hit while designing sawos's image builder (SO-95, tracker doc `SO:images-and-packaging`, section 11). Run against sawlang 0.23.0 (`sawc-stage2` and its `blade`), hosted on macOS arm64, by the design's author; "reproduced" means it was run, "read" that only the source was read.

- **Tried.** A hosted package depending on
  `toml = { path = "<checkout>/libs/toml" }` parsed files with
  `TomlDoc.parse`, then walked `section_at`, `names`, `get`, `get_int`,
  `table_value`. Reproduced.
- **What happened**, by construct:
  - `format = 1` before the first `[section]`: dropped. The document has no
    section for it, and no error.
  - `tier = "flat"   # trailing comment`: the value is
    `"flat"   # trailing comment`, quotes and comment included.
  - `base = 0x6000_0000`: stored as the string `0x6000_0000`, and
    `get_int` answers `None`. Every integer is a string, and `get_int` is
    base 10 only.
  - `reserved = [57]`: the string `[57]`. There are no arrays.
  - `[[process]]` three times: three sections each named `[process]`.
    `section("[process]")` finds the first only, though iteration with
    `section_at` sees all three.
  - An inline table across two lines: `windows = { ledc = "LEDC",` became a
    string key `windows`, and the next line, `clock = "SYSTEM_CLK" }`, a
    key `clock`. No error.
  - `x = { gpio = "p, q", clock = "r" }`: `gpio` reads `"p`. The table is
    split on commas inside strings.
  - `expect = ["a",` followed by `"b"]`: `TOML parse error: Invalid line:
    "b"] (line 19)`.
- **Expected.** TOML 1.0 for these constructs: top-level keys, comments,
  integers with hex and underscores, arrays (multi-line too), arrays of
  tables, and strings containing commas. An error, never a silent misread,
  for anything outside what the library supports.
- **Why sawos needs it.** The board, image, process and test descriptions
  are TOML. Blade's manifests would benefit too: Blade parses hex itself
  (`parse_manifest_word`).
- **How badly.** It blocks reading the description files in Saw. Workaround:
  the runner-to-builder path uses JSON (`std.json` works), so unit U1 is not
  blocked. Unit U3, the first that reads hand-written descriptions, is.
  Writing a strict TOML reader inside sawos is the fallback if sawlang
  declines.

# SL-1092 design: what `libs/toml` reads, and how it refuses the rest

Design pass by agent:claude-sawlang/p1092d, Nov 14 2026, against main at
`df036fb2f` with `.build/sawc-stage2` built from it. Nothing tracked was changed.
Every claim names its evidence file; paths are relative to
`/Users/shawn/Projects/sawlang/.build/scratch/p1092d/` unless they start with a
repository path. A claim that was not run is labelled UNVERIFIED.

**Terms used throughout.**
- *Today's library*: `libs/toml/src/lib.saw` at `df036fb2f`.
- *Row*: one TOML input in the conformance table (section 1.5), with an id
  such as `K6`.
- *Reads right / misreads / refuses*: what today's library does with a row.
  A *misread* is a successful parse (`Ok`) whose contents differ from what TOML
  1.0 says the text means, or an `Ok` for text TOML 1.0 says is invalid. A
  *refusal* is `Err(TomlError)`.
- *Position*: a 1-based line and a 1-based column. The column counts Unicode
  scalars from the start of the line, so `é` is one column.
- *Rendering*: the one-line text the new library's `Printable` gives a table:
  inline TOML, keys in document order, for example
  `{format = 1, board = {name = "x"}}`. The conformance table states each
  accepted row's expected reading in this form (section 3.6 defines it).

## 0. Summary

- **The issue's eight reproduce** exactly (step 0, `out/today/r00_issue.txt`).
- **175 rows were run in all**, the eight included (`out/today/*.txt`).
  Today's library reads 35 right, refuses 15 (11 of those are valid TOML it
  should read), and misreads 125 silently. The new findings, in short: a comment after
  a table header refuses the file, and one containing `=` silently deletes the
  header; strings keep their escapes raw and literal strings keep their quotes;
  quoted keys keep their quotes and a quoted key containing `=` is split at it;
  dotted keys become one flat name; every integer, float, boolean and date is a
  string, and `get_int` reads the *string* `"42"` as 42 but `1_000`, `0x10` and
  `0o7` as `None`; `[ sos ]` is a section named ` sos `, so Blade would see no
  `[sos]`; a nested inline table or an array inside one is split into bogus
  keys; an inline table followed by a comment becomes one string (a line the
  consumer's own `board.toml` has); not one duplicate key or table redefinition
  is refused, and `get` answers the *first* of two keys; a lone CR splices two
  lines into one value; and every invalid value (`key = # x`, `name = hello`,
  `True`, `012`, `1__2`, an unterminated string or array) is accepted as text.
- **The rule recommended: TOML 1.0 in full, in two steps.** Unit U1 reads all
  of TOML 1.0 except multi-line strings, floats and date-times, and refuses
  those three by name, line and column. Unit U4 reads them. No input is
  misread at any point. Full conformance costs about 350 lines more than the
  consumer's subset (UNVERIFIED estimate); a subset still has to recognise each
  excluded construct to name it, saves little, and leaves a second, private
  dialect every user of `Saw.toml` has to learn.
- **The API.** `TomlDoc.parse(text) -> Result<TomlDoc, TomlError>` builds a
  typed tree: `TomlTable` (keys in document order), `TomlArray`, and a
  `TomlValue` enum with `Text`, `Integer` (`Int64`), `Float`, `Boolean`,
  `DateTime`, `Array` and `Table`. Every key and value keeps its position.
  Typed reads (`string`, `integer`, `boolean`, `float`, `date_time`) answer
  `Ok(None)` for an absent key and `Err(WrongType)` for a present one of another
  type; `table`, `array` and `value` lend places. `TomlSection`, `get`,
  `get_int`, `table_value`, `section_at`, `index_of` and their kin go. Who it
  touches: Blade's `manifest.saw`, `sosimg.saw` and `lock.saw`, `libs/toml`'s
  four tests, and five doc passages that cite the old API.
- **Errors.** `TomlError { kind, line, column, message }`, ten kinds, the first
  error wins. A duplicate key and each of the four redefinitions SL-1121 lists
  is an error naming both lines.
- **Units.** U1: the new library, beside today's moved to `toml.legacy` so
  Blade is untouched but for its imports. U2: Blade on the typed tree, `legacy`
  deleted, docs. U3: Blade's two TOML writers quote what they write. U4: the
  rest of TOML 1.0.
- **Owner questions** (section 8): full TOML 1.0 or a subset; date-times;
  integers past `Int64.max` and the integer type; the API names; Blade's
  `device-window` as an integer; Blade refusing `runtime = "true"`.

## 1. Today, measured

### 1.1 The library

`libs/toml` is a package of one source file, `src/lib.saw` (378 lines), four
tests and a two-key `Saw.toml` (`name = "toml"`, `version = "0.1.0"`). Its
header says it supports `[section]` headers, `key = "value"` strings, one-level
inline tables and `#` comments.

Its data model:

| Type | Holds | Copy policy |
|---|---|---|
| `TomlDoc` | `sections: Vector<TomlSection>` | NoCopy |
| `TomlSection` | `name`, `values: Vector<TomlValue>`, `tables: Vector<TomlTable>` | NoCopy |
| `TomlValue` | `key: String`, `value: String` | automatic Copy |
| `TomlTable` | `key`, `values: Vector<TomlValue>` (one inline table) | NoCopy |
| `TomlError` | `message: String`, `line: Int`; `Error`, renders `TOML parse error: M (line N)` | Copy |

`TomlDoc.parse` splits the text on `\n` and reads it line by line (`lib.saw`
`parse`):

- a trimmed line starting `#` is skipped; nothing else ever strips a comment;
- a trimmed line starting `[` and ending `]` starts a section named by
  everything between the outer brackets, untrimmed;
- any other line with an `=` is split at the *first* `=`; the right side is a
  value, and when it starts and ends with `"` the two outer bytes are dropped;
  when it starts `{` and ends `}` it is cut at every comma into `k = v` pairs;
- any other line is `Invalid line`;
- a section is pushed when the next header arrives *only if its name is
  non-empty*, so the keys before the first header are dropped, but at the end
  of the file a nameless section with keys is kept.

Accessors: `section_names`, `has_section`, `section_count`, `index_of`,
`section_at(i) borrows -> &TomlSection` (panics out of range),
`section(name) borrows -> &TomlSection?`; on a section `get(key) -> String?`
(first match), `get_int(key) -> Int?` (`String.to_int`, so decimal with an
optional sign, and `012` is 12), `is_table`, `table(key) borrows ->
&TomlTable?`, `table_value(key, subkey) -> String?`, `names()` (scalars first,
then inline tables), `add`, `add_table`; on an inline table `get(subkey)`,
`add`; `TomlValue.int_value()`. Allocation is `try!` throughout, so a refused
allocation panics.

Its tests (`libs/toml/tests/`): `toml_parsing` (a section and two strings),
`toml_int_value` (`get_int` on `count = "42"`, a quoted string),
`toml_missing_section`, `inline_table` (two dependency tables). All four pass
on main (`out/toml_main/blade_test.txt`; the copy differs from main only by
the diagnostic `debug_dump` appended at its end, `toml_main/src/lib.saw`).

### 1.6 What is misread beyond the issue's eight

Grouped, each with its rows:

1. **A comment after a table header** refuses the file (C4, AT5: the
   consumer's `[[setup]]  # ...` and `[limits.default]  # ...` lines), and one
   containing `=` silently deletes the header and moves its keys to a nameless
   section (C6).
2. **Strings**: escapes are kept raw (S2, S3, S5); literal strings keep their
   quotes (S15, S16, S18, K5, IT12); an unterminated string, a raw control
   character and text after the closing quote are accepted (S6, S8, S11, KV2);
   `"""one line"""` reads as `""one line""` (S14).
3. **Keys**: quoted keys keep their quotes (K3–K8, T3), a quoted key containing
   `=` is split at it (K6), dotted keys become one flat name with the dots and
   any spaces in it (K9–K14, IT3, X8), and invalid bare keys are accepted (K2,
   X5).
4. **Types collapse to text.** Every integer, float, boolean and date is a
   string; `get_int` reads only a signed decimal, so `1_000`, hex, octal and
   binary are `None` (N5–N11, N24), but it reads the *string* `"42"` as 42
   (N23) and `012` as 12 (N12). The string `"true"` and the boolean `true` are
   the same to a caller (B3), which is how Blade reads `runtime`.
5. **Invalid values are accepted as text**: a missing value, a bare word,
   `True`, malformed or out-of-range integers, malformed floats, an impossible
   date, an unterminated array or inline table, a missing comma, a trailing
   comma in an inline table (KV1, KV4, B2, N12–N15, N18, N20–N22, F6–F8, D6,
   A12, A13, IT6, IT11).
6. **Headers**: whitespace inside the brackets is part of the name, so
   `[ sos ]` is not `[sos]` and Blade would treat the package as having no
   image section (T4, T5, AT6, AT7); `[]` drops its keys (T7); `[ ]` and `[a.]`
   are accepted (X10, X3).
7. **Inline tables**: a nested one or an array inside one is split into bogus
   keys (IT4, IT5, X11), and a trailing comment turns the whole inline table
   into one string (IT9; the consumer's `board.toml` has this line).
8. **Arrays** keep a trailing comment in their text (A10) and an array of
   inline tables is raw text (A14).
9. **Arrays of tables** nested, or with sub-tables, become flat sections with
   bracketed names (AT2, X6).
10. **Duplicates and redefinitions**: none is refused (all of section 1.5's
    last group, and T13, T15, T16, AT3, AT4, X7, X9); `get` answers the first
    of two keys, not the last; a second `[fruit]` is a section no `index_of`
    finds.
11. **Newlines**: a lone CR splices two lines into one value (W5).
12. **The top level** behaves two ways: dropped before a header (I1, T12),
    kept as a nameless section when there is no header (T11).

**The consumer's own example files** (copied verbatim out of the sawos design
by `extract_consumer.py` into `consumer/`; read by today's library in
`out/consumer_today.txt`): `board.toml` is refused at line 91
(`[limits.default]  # ...`), the useless-box image at line 11 (`[[setup]]  #
...`); every process declaration and the logger image parse, with
`format`/`arena`/`ram` dropped, `handles = 11  # floor 8: ...` read as that
whole text, and each `[[boot]]` a section named `[boot]`.

## 2. The rule

### 2.1 What each reader needs

**The consumer** (the sawos lead's statement, `chat/m865.txt`, and the files in
the sawos design's §3–§5, revision 6):

- top-level keys before the first table (`format = 1`, `arena = 0x1000`);
- tables with dotted names (`[ram.kernel]`, `[devices.UART0]`,
  `[types.esp32s3-uart]`, `[limits.default]`), with comments after headers;
- arrays of tables (`[[boot]]`, `[[process]]`, `[[setup]]`, `[[pool]]`) in
  file order, with comments after the header;
- one-line inline tables, nested one level, strings in them holding `,`, `[`
  and `]`, and a comment after them;
- arrays of integers and of strings, on one line or several, empty ones
  (`modules = []`), with a comment after them;
- integers in decimal and hexadecimal with `_` grouping, "up to 64 bits";
  `get_int` on a hexadecimal literal is the call it makes most;
- booleans; basic strings; bare keys with `-` (`root-slot`, `on-exit`);
- **dotted keys on the left of `=`.** The statement says the files do not use
  them, but revision 6 of the design does: `registers.ENABLE1_W1TS = { offset
  = 0x030 }` and `arrays.out_sel = { ... }` in `[devices.GPIO]`, with the note
  "Registers and arrays use TOML's dotted keys" (§3.1). The rule reads them
  either way;
- an error naming the line for anything else, and (SL-1121) a repeated key or
  table refused.

**Blade's manifests and locks** (section 1.2, `out/pin_before.txt`): `[package]`
strings and the boolean `runtime = true`; `[dependencies]` one-line inline
tables of strings and a bare string; `[sos]` strings, an inline table of
integers, `[sos.priorities]` and `[sos.<triple>]` headers with `-` in the key,
hexadecimal addresses written as *strings* (`device-window = "0x10000000"`);
comments; `Saw.lock`'s `[lock]` and `[pkg.<name>]` tables of strings.

**Everything else in TOML 1.0**: literal strings, quoted keys, multi-line
strings (both kinds), octal and binary integers, floats (`inf`, `nan`,
exponents, `_`), the four date-time kinds, and the full redefinition rules.

### 2.2 The two choices

| | A: TOML 1.0 in full | B: a stated subset, the rest refused |
|---|---|---|
| Reads | every TOML 1.0 document | the consumer's list, Blade's, and the structural rules |
| Still needs | the structure (tables, dotted keys, inline tables, arrays of tables, redefinition rules), which B needs too | the same structure, plus a recogniser for each excluded construct so the refusal can name it |
| Extra code over B (UNVERIFIED estimate) | multi-line strings ~80 lines, floats ~70 (validation, then `String.to_float`), date-times ~200 (a value type, its parser with calendar checks, its rendering) | none; recognising the excluded constructs ~40 |
| For a user | "it is TOML" | a dialect: a `Saw.toml` with `'literal'`, `1.5` or a date is refused, and the list of what is refused must be documented and learned |
| Doctrine | "APIs do the expected thing": a library named `toml` reads TOML | the easy-to-implement thing |

**Recommendation: A, staged.** U1 reads the structure and every scalar the two
readers need, plus literal strings, quoted keys, octal and binary (each a few
lines once the rest exists). It refuses multi-line strings, floats and
date-times with `Unsupported`, naming the construct, line and column, so main
never misreads. U4 then reads those three and retires `Unsupported`. If the
owner rules B instead (question Q1), U4 is dropped and `Unsupported` stays as
the permanent "outside the subset" kind; nothing else in U1–U3 changes.

Whatever is chosen, no input is misread: every construct the library does not
read is an error naming the line, the column and the construct.

## 3. The data model and the API

### 3.1 The types

```saw-fragment
public struct TomlPosition { line: Int, column: Int }      // automatic Copy; renders "line L, column C"

public enum TomlKind { case Text, case Integer, case Float, case Boolean,
                       case DateTime, case Array, case Table }
// @synthesize Equatable; renders "a string", "an integer", "a float",
// "a boolean", "a date-time", "an array", "a table".

public enum TomlValue {
    case Text(value: String),
    case Integer(value: Int64),
    case Float(value: Float),
    case Boolean(value: Bool),
    case DateTime(value: TomlDateTime),
    case Array(array: TomlArray),
    case Table(table: TomlTable)
}                                                           // NoCopy; renders as TOML

public enum TomlDateTimeKind { case OffsetDateTime, case LocalDateTime,
                               case LocalDate, case LocalTime }
public struct TomlDateTime {
    kind: TomlDateTimeKind
    year: Int, month: Int, day: Int                         // 0 for a LocalTime
    hour: Int, minute: Int, second: Int, nanosecond: Int    // 0 for a LocalDate
    offset_minutes: Int                                     // OffsetDateTime only; Z is 0
}                                                           // automatic Copy; renders RFC 3339

public struct TomlTable { ... }    // NoCopy; private fields below
public struct TomlArray { ... }    // NoCopy
public struct TomlDoc { ... }      // NoCopy; owns the root table
```

All seven `TomlValue` cases and `TomlDateTime` are declared in U1, so the enum
a caller matches on never changes shape; U1 never produces `Float` or
`DateTime`.

- **Integers are `Int64`.** TOML 1.0 says integers are 64-bit signed and that
  a value that cannot be held losslessly is an error. `Int` is 32 bits on a
  32-bit target, where `Int` would make a valid document unreadable. (Q3.)
- **Copy policy: NoCopy** for the tree, as `TomlDoc` and `TomlSection` are
  today. A caller reads scalars as copies and reaches tables and arrays as
  places. An `ExplicitCopy` derivation can be added later without breaking
  anyone.
- **Key order is document order**: a table's entries are a `Vector`, in the
  order each key was first defined. Lookups are a linear search, as today's
  are; manifests have tens of keys. (Perf via measurement: no index until one
  is shown to be needed.)
- **Where every value came from**: each entry keeps the position of its key
  and of its value; each table keeps where it was defined and its path; each
  array element keeps its position. That is what lets a consumer write "line
  42: unknown key `foo` in [devices.UART0]".

Module-private parts (one file, `libs/toml/src/lib.saw`, so the builder reaches
the private fields directly):

```saw-fragment
enum TableOrigin { case Root, case Header, case Implied, case Dotted,
                   case Inline, case Element }              // payload-free, Copy
struct TomlItem { value: TomlValue, at: TomlPosition }      // NoCopy; `at` = where the value starts
struct TomlEntry { key: String, key_at: TomlPosition, item: TomlItem }   // NoCopy
// TomlTable { private entries: Vector<TomlEntry>, private origin: TableOrigin,
//             private path: Vector<String>, private defined_at: TomlPosition }
// TomlArray { private items: Vector<TomlItem>, private of_tables: Bool,
//             private defined_at: TomlPosition }
// TomlDoc   { private root: TomlTable }
```

`of_tables` is true only for an array made by `[[name]]`; it is what lets a
header extend `[[name]]` and refuse a written `name = [...]` (AT3).

### 3.2 The accessors

On `TomlDoc`:

| Signature | Meaning |
|---|---|
| `static func parse(text: String, max_depth: Int = 64) -> Result<TomlDoc, TomlError>` | parse the whole text; the first error wins |
| `func root(&self) borrows -> &TomlTable` | the top-level table, as a read-only place |
| `Printable` | the root's rendering |

On `TomlTable` (every `key` is the decoded key text, one part, no dots):

| Signature | Meaning |
|---|---|
| `func len(&self) -> Int` | number of keys |
| `func keys(&self) -> Result<Vector<String>, AllocError>` | the keys in document order |
| `func contains(&self, key: String) -> Bool` | |
| `func kind(&self, key: String) -> TomlKind?` | `None` when absent |
| `func position(&self, key: String) -> TomlPosition?` | where the key was written; for a table made by a header, its key part there |

section 5.8):

```saw-fragment
    let names = try devices.keys()
    for name in names.iter() {
        if let device = devices.table(name) { check_device(&device) }
    }
}
if let boot = doc.root().array("boot") {

    }
}
```

`if let ... { } else { }`; `expect` answers presence without a lend.

### 3.4 Consumer-contract sweep (brief obligation 2)

What today's callers rely on that a correct reader changes:

1. **A value was text with its quotes or comment in it.** No Blade fixture has
   a trailing comment after a value or a quoted value with escapes
   (`out/pin_before.txt`), so no Blade reading changes from this.
2. **Every scalar was a string.** Blade reads three non-strings as text:
   `runtime` (`get("runtime") == "true"`), the priority bands (`to_int` on the
   text) and `device-window`/`-size` (written as strings, read by
   `parse_manifest_word`). U2 reads `runtime` with `boolean`, the bands with
   `integer`, and the window keys as an integer *or* the string form (Q5). The
   one behaviour that changes: `runtime = "true"` (a string) and `low = "2"`
   were accepted and become `WrongType` errors (Q6). No tracked manifest
   writes either (`out/pin_before.txt`).
3. **A header was a section named by its dotted text.** Blade finds
   `[sos.<triple>]` by the section-name prefix `sos.` and `[pkg.<name>]` by
   `pkg.`. In the tree these are the table-valued keys of `sos` and of `pkg`.
   The difference: an inline table `<triple> = { ... }` inside `[sos]` is the
   same TOML as `[sos.<triple>]` and now counts as a machine too; a deeper
   header `[sos.a.b]` is a table `b` inside machine `a` rather than a machine
   named `a.b`. Neither appears in any tracked manifest.
4. **`[sos.priorities]` beside `priorities = { ... }`** was Blade's own check
   ("stated both inline and as a [sos.priorities] section"). It is now invalid
   TOML (a header may not extend an inline table, T16), so the parse refuses
   it first, with a Redefinition naming both lines. Blade's check becomes
   unreachable and goes in U2; `blade/tests/sosimg_config.saw`'s assertion on
   the old wording changes in U2.
5. **`[[x]]` was a section named `[x]`.** Nothing in Blade uses it.
6. **The first of two equal keys won.** No tracked file has a duplicate; after
   U1 a duplicate is an error.
7. **A parse error rendered as `TOML parse error: M (line N)`.** Blade
   surfaces it with `try`; its tests assert none of that text. After: `line L,
   column C: M`, and Blade prefixes the file path (U2).
8. **`[ sos ]`, `[package] # comment`, `name = "x" # comment`** were misread or
   refused; they now read as the user meant. This only widens what Blade
   accepts.
9. **Writers.** Blade's `serialize` and `add_dep` write `"{value}"` with no
   escaping. Today's reader keeps backslashes raw, so a value with `\` or `"`
   round-trips by accident; the strict reader decodes escapes, so such a value
   would be refused or changed. No tracked lock or manifest holds one. U3
   makes both writers quote with `string_literal` and `key_literal`.
10. **Lock parse errors** stay `None` from `parse_lock` (Blade then reports
    "Saw.lock is malformed"); U2 keeps that contract.

Found while sweeping, outside this issue (read, not run): `add_dep` appends the
new dependency at the end of the file whenever `[dependencies]` exists, so in
a manifest whose last table is `[sos.<triple>]` the dependency lands in that
table; `README.md`'s manifest example shows `tiny = "0.3.1"  # bare = EXACT
pin`, which Blade refuses ("no registry yet"); `Manifest.load` defaults a
missing `name` to `"unknown"` and `version` to `"0.0.0"` without an error.
Each wants its own issue.

### 3.5 What SL-1121 asks, for TOML

SL-1121 (filed for `std.json`, saying the same should hold here) asks that a
repeated key and a table defined twice be errors. TOML 1.0 already makes all
five invalid. Today's library accepts each (rows DUP1, DUP2, DUP3, DUP4, DUP5,
`r10_duplicates.txt`): a repeated key in a table keeps both and `get` answers
the first; in an inline table the same; a header given twice makes two
sections, the second unreachable by name; a dotted key redefining a value
keeps both; an array-of-tables name reused as a plain table makes sections
`[x]` and `x`. After U1, each is refused at the second definition, naming
where the first was (section 4.2).

### 3.6 The rendering

`Printable` on `TomlDoc`, `TomlTable`, `TomlArray`, `TomlValue` and
`TomlDateTime` writes inline TOML on one line:

- a table: `{` + entries in document order as `key = value` joined by `, ` +
  `}`; an empty table is `{}`; keys through `key_literal`;
- an array: `[` + elements joined by `, ` + `]`;
- a string through `string_literal`; an integer in decimal; `true`/`false`;
- [U4] a float as Saw renders it (`1.0`, `5e+22`, `1000000.0`, `-2e-22`, `inf`,
  `-inf`, `nan`; `out/probe_float.txt`), which is valid TOML; a date-time in
  RFC 3339 with `T`, the fraction's trailing zeros dropped and omitted when
  zero, offset 0 as `Z`.

It is what the tests compare, and it is valid TOML for every value U1 reads.

## 4. Errors

### 4.1 The type

```saw-fragment
public enum TomlErrorKind {
    case Syntax,          // the text is not TOML at this point
    case InvalidString,   // an unknown escape, a control character, a string not closed
    case InvalidNumber,   // an integer or float TOML 1.0 does not allow, or one past 64 bits
    case InvalidDateTime, // [U4] a date-time TOML 1.0 does not allow, or an impossible date
    case DuplicateKey,    // a key given twice in one table
    case Redefinition,    // a table defined twice, or a name used as two kinds
    case Unsupported,     // valid TOML 1.0 this version does not read (removed by U4)
    case TooDeep,         // arrays, inline tables or key parts nested past max_depth
    case WrongType,       // a typed read found another kind; raised by accessors, never by parse
    case Alloc            // the allocator refused a container
}                         // @synthesize Equatable

public struct TomlError {
    kind: TomlErrorKind
    line: Int
    column: Int
    message: String
}
// Error + Printable: "line {line}, column {column}: {message}"
```

The message names no file: a caller knows which file it read and prefixes it
(Blade writes `Saw.toml: line 9, column 2: ...`, U2).

**The first error wins.** `parse` stops at the first error and returns it.
After a structural error the rest of the document is read against a state the
author did not mean, so later errors are mostly echoes of the first; the
consumer refuses the file on the first anyway; `std.json` does the same; and a
single error keeps `Result<TomlDoc, TomlError>` the whole signature.

### 4.2 The wording

`K` is the key or path rendered with `key_literal` parts; `T` describes a
table: `the top-level table`, `[a.b]` for a header-made, implied or dotted
table, `the inline table \`a.b\`` for an inline one, `[[a.b]]` for an element
of an array of tables. `P` is a position written `line L, column C`.

| Kind | Case | Message |
|---|---|---|
| Syntax | expected a key | ``expected a key, found {what}`` |
| Syntax | bad byte in a bare key | `` `{c}` is not allowed in a bare key; write the key in quotes `` |
| Syntax | no `=` | ``expected `=` after the key `K`, found {what}`` |
| Syntax | no value | ``expected a value after `=`, found {what}`` |
| Syntax | a bare word | `` `{token}` is not a value; a string is written in quotes `` |
| Syntax | `True`, `FALSE` | `` `{token}` is not a value; booleans are written `true` and `false` `` |
| Syntax | after a value | ``expected the end of the line after the value, found {what}`` |
| Syntax | after a header | ``expected the end of the line after the table header, found {what}`` |
| Syntax | empty header | ``a table header needs a key`` |
| Syntax | `[a` | ``expected `]` to close the table header, found {what}`` |
| Syntax | `[[a]` | ``expected `]]` to close the array-of-tables header, found {what}`` |
| Syntax | `[a.]` | ``expected a key after `.`, found {what}`` |
| Syntax | array | ``expected `,` or `]` in the array, found {what}`` |
| Syntax | array not closed (at the opener) | ``the array is not closed before the end of the document`` |
| Syntax | inline table across lines | ``an inline table must close on the line it opens, found the end of the line`` |
| Syntax | inline table, trailing comma | ``a trailing comma is not allowed in an inline table`` |
| Syntax | inline table | ``expected `,` or `}` in the inline table, found {what}`` |
| Syntax | lone CR | ``a carriage return must be followed by a line feed`` |
| Syntax | control character outside a string | ``control character U+XXXX is not allowed in a comment`` / ``... here`` |
| InvalidString | escape | ``unknown escape `\{c}` in a string`` |
| InvalidString | `\u`/`\U` | `` `\u{hex}` is not a Unicode scalar value `` / ``expected {4 or 8} hexadecimal digits after `\{u or U}` `` |
| InvalidString | control character | ``control character U+XXXX must be written as an escape in a string`` |

| InvalidNumber | range | `` `{token}` does not fit in a 64-bit signed integer `` |
| InvalidNumber | otherwise | `` `{token}` is not a valid integer `` ([U4] `` ... float ``) |
| DuplicateKey | | ``duplicate key `K` in T; first defined at P`` |

| Redefinition | header on a dotted table | ``table [K] was already made by the dotted key `K2` at P`` |
| Redefinition | header extends an inline table | ``[K] would extend the inline table `K2` defined at P; an inline table is complete where it is written`` |
| Redefinition | header on an array of tables | ``[K] names the array of tables made at P; add an element with [[K]]`` |
| Redefinition | header on a written array | ``[K] names the array written at P, not a table`` |

| Redefinition | `[[K]]` on a written array | ``[[K]] cannot add to the array `K` written at P; only an array made by [[K]] takes more tables`` |
| Redefinition | dotted key through a value | ``the dotted key `K` needs `K2` to be a table, but it is {kind} defined at P`` |
| Redefinition | dotted key into a closed table | ``the dotted key `K` cannot extend T, defined at P`` |
| Unsupported | | ``{construct} are not supported yet: libs/toml reads TOML 1.0 except multi-line strings, floats and date-times`` with construct one of `multi-line basic strings`, `multi-line literal strings`, `floats`, `offset date-times`, `local date-times`, `local dates`, `local times` |

| Alloc | | ``the allocator refused memory while reading the document`` |

`{what}` describes what is there: `` `x` `` (the run of non-blank bytes there,
cut at 16 scalars), `the end of the line`, `the end of the document`, `a
comment`.

### 4.3 Where each error is reported

- Syntax: at the byte that is wrong (an unclosed array: at its `[`).
- InvalidString: at the backslash of a bad escape, at a bad control
  character, or at the opening quote of a string not closed.
- InvalidNumber, InvalidDateTime, Unsupported: at the token's first byte.
- DuplicateKey and Redefinition: at the key part that conflicts (for
  `[fruit]` given twice, the `f` of the second). "First defined at" names the
  earlier key part.
- WrongType: at the value.
- A table's `defined_at` is the position of the key part that named it where
  it was defined: the last part of its header (or of the header that implied
  it, until a header defines it), the part of the dotted key that made it, the
  key of an inline table, the last part of `[[name]]` for an element; the root
  is line 1, column 1.

### 4.4 Decisions inside the rule

- **Multi-line inline tables are an error** (TOML 1.0 forbids newlines inside
  `{ }`; I6, IT11). The consumer writes them on one line.
- **One leading U+FEFF is skipped** (X1). TOML 1.0's grammar is silent on it,
  and editors on some systems write one. (UNVERIFIED against toml-test.)
- **CRLF inside a multi-line string becomes LF** [U4] (W8); TOML 1.0 lets a
  reader normalise newlines.
- **A finite float literal that rounds to infinity** (`1e400`) is
  InvalidNumber [U4]: reading it as `inf` would be a silent misread.
  `String.to_float("1e400")` gives `inf` (`out/probe_float.txt`), so this is a
  check of its own.
- **Seconds 00–60** are allowed in a time [U4] (RFC 3339 permits a leap
  second); a time without seconds is InvalidDateTime (TOML 1.0 requires
  them); fractional seconds past nine digits are truncated (TOML 1.0's rule).

## 5. The parser's shape

All in `libs/toml/src/lib.saw`, one module, ordered: model, accessors,
errors and rendering, reader, builder, `parse`. A character scanner over the
bytes (`String.byte_at`, as `std/json.saw`'s `JsonReader` does) with
recursive descent for values; no separate token stream, because a TOML token
depends on where it stands (`1234` and `true` are keys on the left of `=`).

### 5.1 The reader

```saw-fragment
struct Reader {
    text: String
    pos: Int          // byte offset
    len: Int
    line: Int         // 1-based
    line_start: Int   // byte offset of the current line's first byte
    depth: Int        // open arrays and inline tables
    max_depth: Int
}
```

Methods (each that can fail returns `Result<_, TomlError>`):

- `position()`: `line`, and 1 + the count of bytes in `line_start..<pos` that
  are not UTF-8 continuation bytes (`0x80`–`0xBF`).
- `error(kind, message)`, `error_at(at, kind, message)`.
- `peek()`, `peek_at(offset)`, `starts_with(word)`.
- `skip_blank()`: spaces and tabs only.
- `comment()`: at `#`, consume to the end of the line; a control character
  other than tab is a Syntax error; the line ending is not consumed.
- `newline() -> Result<Bool>`: LF, or CR LF: consume, `line += 1`, `line_start
  = pos`, `Ok(true)`; a CR not followed by LF is a Syntax error; else
  `Ok(false)`.
- `end_of_line(after: String)`: `skip_blank`, an optional `comment`, then a
  `newline` or the end of the text; anything else is the "expected the end of
  the line" error.
- `skip_blank_lines()`: inside an array: blanks, comments and newlines, in
  any number.
- `key() -> Result<Vector<KeyPart>>`: `simple_key`, then while (after
  `skip_blank`) a `.` follows: consume it, `skip_blank`, `simple_key`. More
  than `max_depth` parts is TooDeep. `KeyPart { name: String, at:
  TomlPosition }`.
- `simple_key()`: `"` reads a basic string (a `"""` there is a Syntax error: a
  key is one line); `'` a literal string; else the run of `A-Za-z0-9_-`. An
  empty run is "expected a key". After a non-empty run, a byte that is not a
  blank, `.`, `=`, `]`, `}`, `,`, `#`, CR, LF or the end is the "not allowed in
  a bare key" error naming that character (K2, X5).
- `value() -> Result<TomlItem>`: dispatch on the first byte:
  - `"` → `basic_string`; `'` → `literal_string`; `[` → `array`; `{` →
    `inline_table`;
  - otherwise read the *scalar token*: the run of `A-Za-z0-9_+-.:`. If it is
    exactly `true` or `false`, a Boolean. If it is `inf` or `nan` with an
    optional sign, a float. If it starts with a digit, or a sign then a digit:
    a date-time when it matches `dddd-` or `dd:` at its start, a float when
    it holds a `.`, or an `e`/`E` and no `0x` prefix, else an integer. An
    empty token is "expected a value"; a token of letters that is
    `true`/`false` in another case is the boolean message; any other token is
    the bare-word message.
  - [U4] for a date: when the token is exactly `dddd-dd-dd` and is followed by
    one space, two digits and `:`, the space and the time after it belong to
    the same token (D2).
- `basic_string()`: at `"`. `""` followed by `"` is a multi-line opener
  (Unsupported in U1; [U4] `multi_basic_string`); `""` followed by anything
  else is the empty string. Then byte by byte: `"` ends it; `\` reads an
  escape (`b t n f r " \` → that byte; `u` + 4 and `U` + 8 hexadecimal digits →
  a scalar, refused when above `0x10FFFF` or in `0xD800`–`0xDFFF`; any other →
  "unknown escape"); LF, CR or the end → "not closed" at the opening quote; a
  control byte (`0x00`–`0x08`, `0x0B`–`0x1F`, `0x7F`) → InvalidString at it;
  tab and everything else is appended. Bytes are appended to a
  `StringBuilder` (`append(Byte)`, `append(Scalar)` as `std.json` does).
- `literal_string()`: at `'`; `'''` is the multi-line opener (Unsupported in
  U1); bytes up to the next `'`; LF, CR or the end → not closed; control
  bytes other than tab → InvalidString.
- `integer(token, at) -> Result<Int64>`:
  - a leading `+` or `-` is the sign;
  - `0x`, `0o`, `0b` select radix 16, 8, 2; with a sign that is the
    signed-prefix error; `0X` and the like fall to "not a valid integer";
  - a decimal of more than one digit starting with `0` is the leading-zero
    error;
  - digits accumulate in a `UInt64` against the limit `2^63 - 1` (or `2^63`
    when negative); `_` only between two digits; the result is
    `Int64.from(truncating: 0 &- acc)` when negative. This is the prototype's
    `scan_integer` (`proto/src/lib.saw`), run in `out/proto/tree.txt`.
- `array()`: at `[`; `depth += 1` (TooDeep past `max_depth`); loop:
  `skip_blank_lines`; `]` ends it; else `value`, `skip_blank_lines`, then `,`
  continues or `]` ends it, anything else is the array error, and the end of
  the text is "not closed" at the opener. A trailing comma is allowed.
  Elements may mix kinds (TOML 1.0 allows it).
- `inline_table(path)`: at `{`; `depth += 1`; a fresh `TomlTable` with origin
  `Inline`; `skip_blank`; `}` is the empty table; loop: `key`, `skip_blank`,
  `=`, `skip_blank`, `value`, then `insert_dotted` into this table (5.2), then
  `skip_blank` and `,` (then `skip_blank`; a `}` here is the trailing-comma
  error) or `}`; a CR, LF, `#` or the end is the "must close on the line"
  error; anything else is the inline-table error.
- [U4] `multi_basic_string`, `multi_literal_string`: a newline right after
  the opener is dropped; CRLF becomes LF; in the basic form a `\` followed by
  blanks and a newline removes the newline and all blanks and newlines after
  it; one or two `"` (or `'`) inside are content; the closer is three, and up
  to two more quotes before it are content (`""""` ends with one `"` of
  content). `float(token)`: validate `[+-]? (inf | nan | dec-int frac? exp?)`
  with at least one of `frac`, `exp`; `dec-int` without a leading zero;
  `frac = . digits`; `exp = [eE] [+-]? digits` (leading zeros allowed); `_`
  only between digits; then strip `_` and use `String.to_float`; infinite
  from a finite token is InvalidNumber. `date_time(token)`: the four forms of
  section 3.1, with `T`, `t` or the one space as the separator, `Z`/`z` or
  `±HH:MM`, calendar checks (leap years: divisible by 4 and not by 100, or by
  400).

### 5.2 The builder and the definition rules

The parser holds `root: TomlTable` (origin `Root`) and `current:
Vector<KeyPart>`, the path of the last header (empty for the top level). Three
recursive functions take `t: &var TomlTable` and descend one key part per call
into an entry's payload with `borrow var e = t.entries[i] { match
e.item.value { case Table(var sub) -> recurse(&var sub, ...) ... } }`: the
shape the prototype compiled and ran (`proto/src/lib.saw` `insert_at`,
`append_table`, `insert_into_last`; `out/proto/tree.txt`).

**Descending a header path** (used by both header kinds for every part but
the last, and by key/value lines to reach `current`): at each part, an absent
key gets a new table of origin `Implied`; a `Table` of origin `Root`,
`Header`, `Implied`, `Dotted` or `Element` is entered; an `Array` with
`of_tables` is entered at its *last* element; an `Inline` table, an array
without `of_tables`, or any other value is a Redefinition (the "extend the
inline table", "array written at", "needs ... to be a table" messages).

**`[name]`, at the last part:**

| Found | Result |
|---|---|
| absent | new table, origin `Header` |
| table, `Implied` | becomes `Header`; `defined_at` moves to this header |
| table, `Header` or `Element` | Redefinition: defined twice (DUP3) |
| table, `Dotted` | Redefinition: made by a dotted key (T13) |
| table, `Inline` | Redefinition: would extend the inline table (T16, sosboth) |
| array with `of_tables` | Redefinition: names an array of tables (DUP5) |
| array without | Redefinition: names a written array |
| any other value | Redefinition: needs a table (T15) |

**`[[name]]`, at the last part:** absent → a new array with `of_tables` and
one table of origin `Element`; an array with `of_tables` → push a new
`Element` table; an array without → Redefinition (AT3); a table →
Redefinition (DUP5b, AT4); any other value → Redefinition.

**A key/value line** descends `current` with the header rule (it cannot fail:
the header that set `current` succeeded; a failure there is an internal
invariant broken, and panics naming it), then calls `insert_dotted(t, parts,
0, item)`:

- at the last part: an existing key is DuplicateKey (DUP1, DUP4b, DUP6–8);
  else push the entry;
- at any other part: an absent key gets a table of origin `Dotted`; a table of
  origin `Dotted` is entered; any other table is a Redefinition "cannot extend
  T" (X7, X9); any other value is a Redefinition "needs ... to be a table"
  (DUP4).

Inside an inline table the same `insert_dotted` runs on the inline table being
built, so `{ a.b = 1, a.c = 2 }` makes a `Dotted` table `a` (X8) and `{ a =
{...}, a.c = 2 }` is refused.

Why these rules: TOML 1.0 says a table is defined once; a header may not
redefine a table made by dotted keys, and dotted keys may not extend a table a
header made, but a header may define a sub-table inside a dotted-key table
(T14); an inline table is complete where it is written; `[[name]]` adds to an
array of tables and to nothing else. Restricting dotted keys to `Dotted`
tables enforces all of that in one test, because a `Dotted` table can only be
reached from the body that made it.

### 5.3 The document loop

```text
skip one leading U+FEFF
while not at the end:
    skip_blank
    LF or CR        -> newline
    '#'             -> comment, then newline or the end
    "[["            -> consume; skip_blank; key; skip_blank; expect "]]";
                       end_of_line; open the array header; current = the key
    '['             -> consume; skip_blank; ']' here is "needs a key"; key;
                       skip_blank; expect ']'; end_of_line; open the header;
                       current = the key
    otherwise       -> key; skip_blank; expect '='; skip_blank;
                       a newline, '#' or the end here is "expected a value";
                       value; end_of_line; insert into current
```

`[ [boot] ]` is refused because after `[` and blanks the key reader meets `[`
(AT7).

### 5.4 Positions

The reader records a position for every key part (before reading it) and every
value (before dispatching). Columns are computed on demand from `line_start`,
so a long line costs one scan per recorded position; manifests have short
lines.

### 5.5 Allocation and failure

`std`'s policy is `Result<_, AllocError>` for every allocating operation.
Today's library spells `try!` on every push, so a refused allocation panics.
The new one maps every `Vector.push` and `StringBuilder.append` result into
`TomlError(kind: Alloc)` at the current position, through one helper shaped
like `std/json.saw`'s `json_decoded`. The `String` layer (`build()`,
`substring`) panics on a refused allocation, as `std.json`'s `//!` states for
its strings; the library's `//!` states the same. `keys()` returns
`Result<Vector<String>, AllocError>`. `Printable.format` spells `try!` (its
signature is the trait's).

### 5.6 Depth

`max_depth` (default 64) bounds open arrays plus inline tables, and separately
the parts of one key. Every recursion in the parser and the builder is then
bounded, and so is the tree's depth (each header level is at most one key
part), which bounds the recursive `deinit` of a dropped tree.

### 5.7 What the old code's shape does not survive

Nothing of today's `parse` is kept: line splitting is the cause of I6, I8, A7–A9
and W5, and outer-byte stripping the cause of most of the rest.

### 5.8 Saw constraints met, and what the prototypes showed

Prototypes: `proto/` (a scratch Blade package, `proto/src/lib.saw`,
`proto/tests/tree.saw`, `proto/tests/consumer_shapes.saw`; outputs
`out/proto/tree.txt`, `out/proto/consumer_shapes.txt`, both `ok`), and
`u1check/` (Blade's sources with the U1 import lines, compiled against a
package holding `legacy.saw` beside a stub `lib.saw`; `u1check/compile.txt`,
exit 0).

- **The recursive tree compiles and runs**: `TomlValue` → `TomlTable` →
  `Vector<TomlEntry>` → `TomlItem` → `TomlValue`, all `NoCopy` (one
  indirection through `Vector` is enough, design 246).
- **Building it by recursive `&var` descent works**: a `borrow var` window on
  `t.entries[i]`, a `match` binding `case Table(var sub)` as a writable place,
  and a recursive call with `&var sub`, three levels deep, plus the same into
  the last element of an array (`insert_into_last`).
- **Chained conditional lends work**:
  `root.table("devices")!.table("UART0")!.table("registers")!.table("X")!.integer("offset")`,
  and `root.array("process")!.table(1)!.text("name")`; an absent or
  wrongly-typed key lends nothing.
- **The consumer shapes compile**: `if let sos = doc.root().table("sos") {
  f(&sos) }` passing the bound place to a `&TomlTable` parameter; iterating
  `keys()` and lending each sub-table; a named `borrow let root = doc.root() {
  }` window; a typed read's error propagated by `try` into `Box<any Error>`.
- **Recursive `Printable` on the NoCopy tree works**, including `"{doc.root()}"`
  on a lent place.
- **`Result<String?, String>` is refused as ambiguous** for a bare value
  (`type.ambiguous-result`): a distinct error struct (`TomlError`) avoids it.
- **Forwarding a reference parameter needs its sigil**: `insert_at(&var sub,
  &path, ...)` where `path` is already a `&Vector<String>`.
- **A test in `tests/` cannot reach a `public(package)` member** of a second
  module (`visibility.private`, `out/proto/scan_visible_compile.txt`), and
  `blade test` runs only `tests/*.saw`. So the reader stays module-private in
  `lib.saw` and is tested through `parse`, which is what the conformance
  table is anyway.
- **The interim `toml.legacy` module works**: Blade compiles with `import
  toml.legacy` / `legacy.TomlDoc.parse` / `import toml.legacy.{TomlDoc,
  TomlSection}` while `toml` itself defines a different `TomlDoc`.
- **`String.to_float`** accepts every TOML float spelling once `_` is removed,
  and renders them as valid TOML (`out/probe_float.txt`); it turns `1e400`
  into `inf`.
- **`String.to_int` accepts `012` and `+99`** (std `parse_signed`), which is
  why today's `get_int` reads N12; the new scanner does not use it.

Not prototyped (the design avoids each): `if try f() { }`, `guard try`,
passing `&t.table(k)!` as an argument, and `borrow let x = t.table(k)! { }`.
Write `let has = try t.expect(...)` then `if has`, and bind a place with `if
let`.

## A. Integers past `Int64.max` (Q3: the extension, option B)

**Why.** The sawos tree links its arm64 kernel at `0xFFFF_FF80_0000_0000`, and its builder is moving link addresses into descriptions. A reader that cannot hold an address the consumer's tree already uses fails on the first 64-bit board that states one.

**The rule.** This is the library's ONE extension beyond TOML 1.0, and the `//!` says so in those words:
- A **decimal** integer is as TOML 1.0 says: `Int64`, and one outside it is `InvalidNumber` (rows N17, N18, N19 unchanged).
- A **hexadecimal, octal or binary** integer may be as large as `UInt64.max`. One above that is `InvalidNumber`: `` `{token}` does not fit in 64 bits ``. The decimal message stays `` `{token}` does not fit in a 64-bit signed integer ``.

**The tree.** `TomlValue` gains one case, declared after `Integer`:
```saw-fragment
case Unsigned(value: UInt64),    // a hexadecimal, octal or binary literal above Int64.max
```
- The reader makes `Integer(value:)` for every integer that fits `Int64`, whatever its base, and `Unsigned(value:)` ONLY for a prefixed literal above `Int64.max`. So one number has one representation, and a caller that matches on `TomlValue` meets `Unsigned` only for such a literal.
- `TomlKind` is unchanged: both cases are `TomlKind.Integer` ("an integer").
- Rendering: `Integer` in decimal, as designed; `Unsigned` in hexadecimal, `0x` and uppercase digits with no underscores (`0xFFFFFF8000000000`), since a decimal above `Int64.max` would not read back.

**The reads.** A new error kind, `OutOfRange` ("a typed read found an integer the asked type does not hold; raised by accessors, never by parse"), reported at the value like `WrongType`:
- `integer`: an `Integer` answers its value; an `Unsigned` is `OutOfRange`: `` `K` in T is {rendered}, which does not fit in a 64-bit signed integer ``.
- `unsigned` (new, on a table by key and on an array by index, beside `integer`): an `Integer` that is zero or positive answers it as `UInt64`; a negative `Integer` is `OutOfRange`: `` `K` in T is {value}, which is negative ``; an `Unsigned` answers its value. Any other kind is `WrongType` with wanted "an integer".

**Rows.** N20 (`0xFFFF_FFFF_FFFF_FFFF`) becomes: read; renders `0xFFFFFFFFFFFFFFFF`; `unsigned` = 18446744073709551615; `integer` = `OutOfRange` at 2:5. New rows for the numbers file: N25 `0x8000_0000_0000_0000` (the first `Unsigned`: `unsigned` = 9223372036854775808); N26 `0x7FFF_FFFF_FFFF_FFFF` (still `Integer`; both reads answer); N27 `0x1_0000_0000_0000_0000` (`InvalidNumber`, "does not fit in 64 bits"); N28 `0o1777777777777777777777` (= `UInt64.max`, `Unsigned`); N29 `0o2000000000000000000000` (`InvalidNumber`); N30 a binary literal of 64 ones (`Unsigned`) and N31 one of 65 digits (`InvalidNumber`); N32 `unsigned` of `-17` (`OutOfRange`, negative); N33 `unsigned` of `"42"` (`WrongType`); N34 *consumer*: `kernel_base = 0xFFFF_FF80_0000_0000`, `unsigned` = 18446743523953737728.

## B. Required and optional reads (Q4)

**Why.** In the consumer's three formats most keys are required. With one read per kind returning `Result<T?, TomlError>`, nearly every call site unwraps an Optional only to turn `None` into the same "missing key" error. Absence is a value for a key that has a default and for nothing else, so the signature should say which the caller means.

**The reads on a table, replacing the design's five scalar accessors.** For each of `string`, `integer`, `unsigned`, `boolean`, `float`, `date_time` (the last two produce only `WrongType` or `Missing` until U4):

| Signature | Meaning |
|---|---|
| `func string(&self, key: String) -> Result<String, TomlError>` | the value; `Missing` when the key is absent; `WrongType` when it is another kind |
| `func optional_string(&self, key: String) -> Result<String?, TomlError>` | `Ok(None)` when absent; `WrongType` when another kind |

and the same pair for the other five (`optional_integer`, `optional_unsigned`, `optional_boolean`, `optional_float`, `optional_date_time`). No abbreviation in a name.

- **`Missing`**, a new error kind ("a required key is absent; raised by accessors, never by parse"). Message: `` `K` is missing from T ``, with `K` and `T` rendered as section 4.2 renders them; its position is the table's `defined_at` (so the consumer's message reads "board.toml: line 12, column 2: `base` is missing from [devices.UART0]").
- **Tables and arrays stay places:** `table(key)`, `array(key)` and `value(key)` answer `&T?` as designed, `None` for an absent key and for one of another kind, because a lend cannot be a `Result`. `expect(key, kind)` stays (`Ok(true)`, `Ok(false)` absent, `WrongType`). Beside it, new: `func require(&self, key: String, kind: TomlKind) -> Result<Void, TomlError>`: `Missing` when absent, `WrongType` when another kind. A strict reader writes `try t.require("devices", TomlKind.Table)` and then binds `t.table("devices")`.
- **On an array, by index:** the required reads only (`string(index)` and the rest answer `Result<T, TomlError>`); an index outside `0..<len()` is `Missing` with the message `` element {i} is past the end of `K` in T, which has {n} `` at the array's `defined_at`. Arrays are walked by `len()`, so an optional read by index has no caller. `value(index)`, `table(index)`, `array(index)` stay places answering `None` out of range.
- **`TomlErrorKind` is now twelve:** the design's ten, `Missing` and `OutOfRange`.

**What moves in the design.** Section 3.2's tables and its example (the example's `try doc.root().integer("format") ?? 0` becomes `try doc.root().optional_integer("format") ?? 0`, and a required read is `try uart.unsigned("base")`); section 4.1's enum and 4.2's table (the two new kinds and their messages); the test file `typed_reads.saw` (each kind: required present, required absent = `Missing` with the table's position, optional present, optional absent, wrong kind both ways; `require` three ways; an array index past the end). Unit U2 (Blade) uses `optional_*` wherever today's code has a default and the required read where the manifest must state the key; its text in section 7 is read with that substitution.
