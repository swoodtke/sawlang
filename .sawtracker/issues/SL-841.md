## Description

**Code after an unconditional `return` (or any diverging statement) is refused with a dedicated diagnostic** (user ruling, Oct 23, SL-425 c26; SL:hazards S6).

Today sawc2 refuses it, but only through a confusing `type.mismatch` ("found `Void`"): the body's type comes from its last statement. The new rule is a diagnostic at the first unreachable statement, saying code after a `return`/`break`/`continue`/`panic`/a `Never`-typed call never runs, with an id such as `flow.unreachable`.

**Obligation 4, the positions:** after `return`; after `break`/`continue` in a loop body; after a call returning `Never` (`panic`, `fatal`); after an exhaustive `match` or `if`/`else` whose arms all diverge; inside closures, `init`s, trait default bodies, and suspending bodies. Each pinned.

Also confirm that the existing tail-type refusal no longer fires first in these positions (one diagnostic, not two). Retire the subset checker's `function-exit` rule if U2 left any of it.
