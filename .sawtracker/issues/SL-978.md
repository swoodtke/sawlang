## Description

**A closure with two `_` parameters is refused: `v.sort_by({ _, _ in Ordering.Greater })` gives `name.shadowing`.** Found by the Air while probing SL-974.

The full message is `` `_` is already defined in this scope; a redefinition must derive from it ``. A single `{ _ in … }` compiles, so `_` appears to be bound as a name in a closure's parameter list rather than treated as the discard pattern.

**Expected:** `_` is the wildcard. It binds nothing, so any number of `_` parameters is legal, as in a `match` pattern or a `let (_, _) =` destructuring.

**Census first (obligation 4):** every position a `_` parameter can appear, checked with compile-and-run evidence:
- closure parameters, one and several, with and without types;
- function parameters, if the grammar allows `_` there;
- `for _ in`, tuple patterns, `if let`/`while let`, `match` arms, `let _ =`.

Find where resolve or typecheck binds `_` as a name, and route every position through one rule that `_` declares nothing.

**SL-978: `_` declares nothing, at every position**

- **Mechanism:** resolve's `bind_local`, the funnel every binding position goes through, declared whatever name it was given. Only `bind_binding_name` (`let`/`var`, the optional-binding heads, `for`) skipped `_`. So closure parameters, function/method/`init` parameters, `var`/`borrow` payload patterns and captures all put `_` in scope.
- **Fix:** `bind_local` declares nothing for `_`, so it is never found, never shadows, is never shadowed and is never a duplicate. `bind_binding_name`'s own copy of the check is gone.
- **Census** (29 positions, compile-and-run evidence before and after):
  - Two or three `_` closure parameters, typed, mixed with names, or by reference; two `_` function, method, static and `init` parameters; nested closures; two `var _` payloads: all were refused, and all now run.
  - Reading a `_` parameter as a value, `{ _ in _ }` or `func one(_: Int) -> Int { _ }`, used to compile and return the argument. It is now `name.undefined`, the same error `let _ = 33; print(_)` already gave.
  - Reading a `var _` payload used to hit an internal compiler error, and is now `name.undefined`.
  - Every position that already worked is unchanged.
- **Pins:** 12 stated run probes (`compiler/tests/run/probes/wildcard_*.saw`, -O0 and -O2), and three resolve refusal fixtures (`name.undefined.wildcard-{parameter,closure-parameter,payload}.saw`).
- **Docs:** none needed. LANGUAGE_SPEC already says `_` binds nothing at every binding position, parameters included.
- **Gates:** `run.py --only seed,units,golden,subset,fixture_whitespace,std,resolver,typechecker,programs`: ok. citations: ok. No corpus program has the changed shapes.

**Air: SL-978.p1, approved.**

**The fix** is the funnel: `bind_local` declares nothing for `_`, so every binding position inherits it, and `bind_binding_name`'s private copy of the check goes. That matches LANGUAGE_SPEC's "`_` binds nothing".

**Checked:**
- **Ownership through the new positions** (`owning_wildcards.saw`, chat m668 / f36). A NoCopy `Res` with a printing `deinit` goes through:
  - a `_` parameter, and two `_` parameters in one function;
  - a method and an `init` `_` parameter;
  - a `_` closure parameter;
  - `var _` payloads in a consuming `match`, one and two in a pattern.
  
  Every value drops exactly once. A parameter drops when the callee returns, two `_` parameters in reverse order. A payload drops after its arm, two in reverse. Output is identical at -O0, -O2 and under `--sanitize address`, with no ASan report.
- **The shapes main already accepted** (single `_` parameters and a single `var _` payload) drop at exactly the same points on main as on the patch.
- **Corpus:** main's compiler against the patch's, `build --emit-ll` over all 2,833 programs: 2,833 identical.
- **Blast radius:** no `.saw` under `std/`, `runtime/`, the compiler's sources, `blade/` or `libs/` declares a `_` parameter, so nothing in-tree that reads one can break.

**A suggestion, not blocking:** your 12 probes are all `Int`-typed, so none of them would catch a dropped or doubled release through a `_` binding. `owning_wildcards.saw` is yours to fold in as a stated probe if you want that pinned. Its output is above, the same at both speeds.
