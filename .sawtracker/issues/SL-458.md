## Description

**sawc2 accepts a silent copy of `Self.Item` in a trait default body, and the MIR drops the value once per copy plus once for the original.** Found reviewing SL-453.p1, which names this as a pre-existing gap. Stage 0 refuses the same program.

**Repro** (`.build/scratch/air-review/sl453/probes/a4c_item_copy_policy_deinit.saw` on the Air):

```saw
struct Token { id: Int }
extension Token: NoCopy {
    func deinit(&var self) { print(self.id) }
}
trait Source {
    type Item
    func make(&self) -> Item
    func dup(&self) -> Int {
        let v = self.make()
        let a = v
        let b = v
        2
    }
}
struct Maker { n: Int }
extension Maker: Source {
    type Item = Token
    func make(&self) -> Token { Token(id: self.n) }
}
func main() { print(Maker(n: 5).dup()) }
```

- **sawc2** (`mir --check`, with SL-453.p1) accepts it. `Source.dup` lowers once, generically:
  `_5 = copy _2; _6 = copy _2; … drop(_6); drop(_5); drop(_2)`. Instantiated at `Token`, that is three `deinit`s of one value.
- **Stage 0** refuses both copies: "cannot copy value of type `Token` which implements NoCopy", twice. It checks the default body per conformer.

**Mechanism:** a trait's own associated type (`Self.Item`, or bare `Item` in the trait body) gets a copy policy that permits a silent copy. Nothing in the slice states its policy, so the only sound reading is the one SL-453 gives `T.Item`: NoCopy, meeting no bound.

**Likely fix:** treat a trait's own associated type as the projection on `Self`, with the same NoCopy reading. The body then writes `move v` or borrows, as a generic body does for `T.Item`. Pin: a refusal fixture with this repro (`transfer.implicit-copy` at both copies), plus an accepted golden using `move`.

**Sweep owed (obligation 4):** the other places a trait body reads an associated-type value by value:
- a default body's `return v` / tail with `v` read twice;
- passing `v` to two calls;
- a field of type `Self.Item` in a conformer's default helper;
- a closure capturing `v`.

**Ordering:** it must land before any backend lowers default bodies from this MIR.

**The mechanism (obligation 4: one rule, not a patch on the symptom).**
- A trait's own `Item`/`Self.Item` had its own type kind, `TcKind.Assoc`, which copied silently and met every bound. **That kind is deleted.**
- `own_projection` (`signatures.saw`) builds `mk_projection(Self, d)` with `Self` as the trait it is written under, so a refining trait's `Self.Item` is projected from its own `Self`.
- The copy tier, the bound answer and the spelling are SL-453's single projection rule.
- `subst` (`conform.saw`) keeps the conformance assignment as a fast path for a projection on `Self`, and otherwise falls back to `project`.
- `Assoc` is removed from types, tier, typeops, members, spell and conform. Nothing in `compiler/mir` named it.

**Pins:**
- `refuse/transfer.implicit-copy.own-associated.saw`: the issue's repro.
- `golden/own_associated_refusals`: the repro is refused at both copies, plus every sweep row, each `transfer.implicit-copy`. The binary from before the change refused none of them:
  - a tail `(v, v)`;
  - `return` after a binding;
  - `v` passed to two calls;
  - a field of `Holder<Self.Item>`;
  - a closure capturing `v`.
- `golden/own_associated`, accepted: `move` into a binding, a call and a tuple; a borrow through `&Item`; a refining trait's default body; a generic `drive<P: Pipe>`.

**MIR:** the accepted golden's dump has no `copy` of a `Self.Item`. `Source.dup` reads `_2 = move _4; _5 = move _2; _7 = ref(shared, _5); _11 = move _5; … take(v: Self.Item) [move _12, move _11]`. A moved-out local's `drop` is a no-op under drop-if-initialised.

**Corpus:** the `corpus_info.py` summary is unchanged (860 of 1,430 clean). One expected-error program, `std_import_gate_signature_position.saw`, loses a follow-on `infer.failed`, which is the cascade fix.

**The SL-453 approval's two notes:**
1. **The error cascade is fixed.** The funnel (`expect`) now passes a slot that holds a refused type on as the hint, so a `None`, an implicit member or an empty literal adopts the error type. `golden/poisoned_results` pins it: before the fix it gave 7 extra errors, now 0.
2. **A plain-extension `deinit` is refused** as the new rule `deinit.outside-policy`. The spec's "The Deinit trait" says "A hand-written body goes inside the type's copy policy". Stage 0 refuses it beside a NoCopy conformance, but on a type with no policy it accepts it and **never runs it**, so the program printed `1` and never the deinit's `7`. Fixtures: `refuse/deinit.outside-policy` and `.no-policy`. The lane's rule-id regex gains `deinit`, without which the new rule escaped the fixture check.
