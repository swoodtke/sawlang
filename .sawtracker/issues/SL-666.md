## Description

**Unit 5 of SL-661: the per-patch gate without `sawc/`.**

`tools/patch_gate.py` (run by `./build.sh test` on every patch) decides by changed path which runners run:
- `compiler/tests/run.py`;
- the full suite (`test_runner.py` over `examples/`);
- freestanding on both arches;
- fixpoint;
- grammarcorpus;
- astdiff (the Python parser's AST dump).

Several of these need Stage 0.

**Owed:**
- **The new gate:**
  - `compiler/tests/run.py`, always;
  - fixpoint, from unit 2's seed;
  - grammarcorpus, against sawc2 only;
  - corpusdiff's baseline as a **regression gate**: a patch fails when any corpus program leaves the `pass` bucket, or changes bucket or key without a deliberate baseline edit in the same patch. The full measurement takes about 140 s. Say whether it runs in full or in a quick form, and on which paths.
- **The Stage-0-only lanes**, each removed from the gate and from `tools/battery.sh`, or kept against snapshots, with a reason each: the full suite, freestanding, astdiff, astgraft, corodiscovery, corototality, windowseam, stdseed, irdet, reemit, gmgate, fuzz, corodiff, bootstrap, forgetgate, ircontract, preludegate, stdtypes, abidoc, bttable, bench, floatvectors, minivm, icebreadcrumb, transferdecisions.
- **The gate's own tests:** `tools/patch_gate.py`'s `SUITE_INPUTS` and its tests, `.sawtracker/tests.json` (if its command changes), and the CLAUDE.md Testing section.
- **Obligation 2:** who relies on the old gate (the Air's review habits, the server's run time, the 75% core cap) is surveyed before dispatch.

**Depends on:** unit 4 (no oracle reads a live Stage 0) and unit 2 (fixpoint from the seed).

**g666gate: SL-666 built (worktree commit, not submitted), with one piece stopped for a ruling: gmgate.**

**Stopped: gmgate.** `tools/gmgate.py` is the only lane that runs ownership and concurrency oracles under Guard Malloc, where a missing retain becomes a fault rather than a silent use-after-free. It drives Stage 0, so it can't see sawc2, and sawc2 has nothing like it. Dropping it from the battery would drop the last lane guarding that safety property, so it stays (a slow stage, as before) until there's a ruling: **retire it with Stage 0, or port it** (sawc2-built corpus twins of its program list under `libgmalloc`)? docverify stays too, as the only check of the docs' Saw examples, until SL-667 points it at sawc2.

**Obligation 2, who relied on the old gate:**
- **The Air's reviews** cite the server's gate output (the `gate:` summary line, `python suite`, `grammar corpus`, `astdiff: changed .saw files`). The part names change: `python suite`, `freestanding` and both astdiff parts are gone, and `corpusdiff` is new. A failure now lists each moved program with old and new verdicts.
- **The server's run time** goes down. The Python suite cost 7m40s–7m56s per run that reached `sawc/` or `examples/`. The corpusdiff gate measures all 2,661 programs in about 15 s wall on 12 workers (about 150 s of sawc2 builds in total).
- **The 75% core cap:** corpusdiff measured on its own `ThreadPoolExecutor(--jobs)`. Both `run` and `gate` now draw on `gate_jobs.map_ordered`, so `--jobs` is held to the ceiling and `gate` uses the whole budget.
- **Lanes named in docs:** CLAUDE.md's per-commit policy named astgraft, transferdecisions, bootstrap, irdet and reemit as pre-submit lanes. It now names docverify, citations and patchgate. TESTING.md, compiler/README.md and the corpusdiff README ("It gates nothing") are updated. Not changed, for SL-667's sweep: the remote worker's battery (`tools/test_worker.py`: suite/compiler/astdiff/irdet), Makefile targets, and TESTING.md's per-tool sections.
- **One correctness issue the gate surfaced:** `stage_of`'s table was filled lazily from many threads. A thread that read it half-filled keyed a refusal by the wrong stage: `D21_substituted_never_is_a_value` flipped between `refused asserts slice.not-yet` and `refused typecheck …` across two runs. It now fills under a lock, pinned by `tools/test_patch_gate.py`, which shows the race without the lock.

**The gate:** `compiler/tests/run.py` always; then fixpoint, grammarcorpus and `corpusdiff.py gate`, each on its own inputs.
- **corpusdiff in full, never the quick form.** One program per bucket and key can't see a passing program regress, and the full run is cheap.
- **When it runs:** on changes to what sawc2 is built from (each stage's `src/`, driver, seed, `build.py`, `std/`, `runtime/`), or to what the measurement reads (`tests/corpus/`, the cbor/float vectors, `examples/` because of the snapshot's twin hashes, the corpusdiff directory, `oracle.py` and its imports).
- **What fails:** any bucket or key move (improvements included), a detail change inside `stage0-wrong`, a program the baseline lacks, and a baseline row that nothing measured.
- **Deliberate edits:** a patch that means the move commits `run --baseline` output. A `slow` row is written and compared as the verdict its second try reached.

Verified: the gate is stable over three runs. An injected baseline edit (pass→refused, plus a stage0-wrong detail) fails it, naming both programs, and ignores a refused-detail edit. After rebasing onto main, the gate caught SL-675's three real moves (`errors/unsafe_sync_*`, wrong→pass), which this baseline now records.

**Annotations:**
- `errors/coro_guarded_arm_owning_payload` (SL-283) and `while_let_tuple_over_suspension_refused` (SL-566). An annotated refusal test is built and run, and its detail is what the run did: the first panics on sawc2's timer-executor gap, the second exits 0.
- **SL-682's two programs are not annotated:** the spec says the replaced binding drops at the redefinition point (comment on SL-682).
- **Unannotated candidate:** `coro_suspending_default_omitted*` (SL-221) is a Stage 0 limit that sawc2 accepts, but the spec says nothing either way.

**grammarcorpus:** it classifies with `sawc2 parse --check` instead of the Python parser. The nine `c-conflict` rows become `a-error`, since sawc2's parser implements every one of those rules. `c-conflict` now means "sawc2's parser accepts what the grammar refuses", which a ruling or a filed finding must explain.

**Still on `sawc/` in the gate, SL-667's to remove:** `run.py`'s `subset`/`std_cone` steps and the resolve lanes read `sawc/` as a library (SL-665 named these). The fixpoint keeps `sawc/` as an input because sawc2's default `--std-root` is `sawc`.
