## Description

**An alias over a function type launders a non-escaping function value; safe code reads a returned frame.** Found by the reviewer of SL-1012.p1 (chat m1261, f341, Nov 17); reproduced by the lead on main (v0.24.3 and after; `.build/scratch/fnalias/`):

```saw
type Fn = (Int) -> Int

func keep(f: (Int) -> Int) -> Fn { Fn(f) }

func make(n: Int) -> Fn {
    keep({ x in x + n })
}

func main() {
    let k = make(5)
    print(k(2))
}
```

Accepted; `ASAN_OPTIONS=detect_stack_use_after_return=1` reports `stack-use-after-return`; at `-O2` it prints `-1`, not `7`. Without the alias (`return f`) the same function is refused `escaping.stored`.

**Mechanism (the reviewer's reading):** `alias_construct` checks its argument as an argument (a call's parameter position), where `check_escape` returns early, and nothing afterwards treats `Fn(f)` as a non-escaping value, so the alias construction's RESULT carries `f`'s non-escaping kind out unchecked. SL-1012.p1 widens the road (an alias over an Optional, a Result or a struct of a function type is newly accepted the same way).

**The fix is SL-1012.p1's revision** (the owner's rule: a review finding is fixed in the same patch), closing this issue with it: an alias construction over a non-escaping value is itself non-escaping (`nonescaping_value` reads through it, as SL-1137 made it read `move f`), so `check_escape` refuses it at every holding position SL-1137 funnelled; a conformance row first; a cell per alias shape (direct, an alias of an alias, over an Optional, a Result, a generic struct of a function type) and per holding position (return, tail, `let`, field, element). Priority high.
