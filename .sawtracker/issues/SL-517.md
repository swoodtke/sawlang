**Found by:** the Air, reviewing SL-513's rule B. It applies under any timing rule, so it isn't B's own. **Area:** the coroutine lowering's ANF hoist: design 147's sibling-lifting test, in Stage 0's `coro_transform.py` and in whatever sawc2's coroutine lowering (§3.9) adopts.

**The defect:** the test that decides whether a sibling operand must be lifted ahead of a suspending one is syntactic: "anything with a call or `&var` in it". A consuming `match` with no written call still runs a `deinit`, for its leftovers or for a whole consumed scrutinee, so it is side-effecting. The test misses it. In `add(match s { case Full(_) -> 1, case Empty -> 0 }, slow(3))`, with `slow` suspending, the leftover's `deinit` would run after `slow` instead of before. That breaks left-to-right evaluation order.

**Class, not instance (obligation 4):** any construct that runs user code without a written call has the same problem:
- a consuming `match`, `if let` or `while let`;
- a `let _ = e` inside a value block;
- a `move` of a value whose scope ends in the operand;
- an implicit `copy()` hook;
- operator sugar (`==` through `equals`);
- interpolation through `Printable`.

**Fix:** the lift test asks the one question "can evaluating this run user code", answered from the typed tree (drops, hooks, calls), not from the spelling. Stage 0 is frozen, so its half goes in SL:hazards if compiler source could hit it. The compiler source has no coroutines, so it can't. The sawc2 half is a requirement on §3.9's brief.
