# U6e: drop elaboration (SL:architecture §3.7)

- **Epic:** SL-398, unit 6e. It builds on U6d1 (SL-460.p1, merged): the one initialisation analysis (`compiler/mir/src/initialisation.saw`) and borrowck's drop labels, static, elided or flagged, with `mir_drop_label`.
- **Design:**
  - SL:architecture §3.7 (and §3.8 for where glue is generated);
  - the spec's "The Deinit trait" (design 131: a hand-written body prefixes the synthesized field drops, fields in reverse declaration order), `consumes`, and temporaries;
  - the U6d1 cost model: `compiler/` has 5,276 static, 244 elided and 7 flagged drops, and the corpus 4,240, 506 and 23.
- **Package:** `compiler/drops/`, package `sawdrops`, depending on `sawmir` and `sawborrowck`. It is in the bootstrap subset, with the checker and markers. Add `sawc2 drops (--dump | --check)`, run after borrowck accepts.

## Decisions (the lead)
1. **In:** borrow-checked MIR. **Out:** elaborated MIR, where every `drop(p)` is a concrete operation on a concrete path.
   - A `static` drop becomes an unconditional drop.
   - An `elided` drop is removed.
   - A `flagged` drop becomes a drop guarded by a drop flag: a `Bool` local, set where the place is initialised, cleared where it is moved, and created only for the places that need one. Flags are named in the dump.
   - The labels come from the shared analysis. Never re-derive initialisation here.
2. **Partial paths.** A drop of a place whose fields left on some paths (a dissolve, or a `consumes` body's field moves) decomposes into drops of exactly the parts still initialised, each part elaborated by rule 1. After a `consumes` body moved fields out of `self`, the end-of-body release drops exactly the fields that stayed. The every-path-or-none rule (borrowck's `consumes.some-paths`) means that needs no flag. An assertion pins it: no flag is ever created for a `consumes` field.
3. **Order.** Scope exits drop in reverse declaration order, and statement temporaries at the end of their statement in reverse creation order (the spec). A borrowing struct is dropped before the window whose loan it carries ends (§3.6, the Air's t21). Check that MIR's existing order already gives this, and pin it; don't reorder by guesswork.
4. **Must-consume types.** A value of a type whose fate must be written (a `Thread`/`Task` handle; the spec's "every non-group handle's fate is written") that reaches an implicit drop is refused here, as the rule `drop.must-consume`. This is the stage that knows exactly where implicit drops happen. If no must-consume type is in the slice yet, the rule still exists, with its fixture marked "due when spawn enters the slice", in the style of SL-462's spawn rows. The lang-item or trait that marks a type must-consume is named, not hard-coded by type name.
5. **Placement, not glue.** This stage decides WHERE a drop happens. WHAT a drop does for a type (its `deinit` body, then its fields in reverse declaration order, or an enum payload by discriminant) is that type's glue, generated once per concrete type at §3.8.
   - **Glue resolution, recorded now:** the elaborated dump carries, for each dropped type, which glue it resolves to: a hand-written `deinit` (which declaration), structural, or trivial (no glue).
   - **A row for the Air's SL-456.p2 note 1:** `Vector<Token>` with `Token` NoCopy must resolve to the `deinit` declared in Vector's bounded `ExplicitCopy` conformance, the uniform-policy reading. Pin it under `--std-root std` with a `Vector<Token>` local, plus the same for `Vector<Int>`. If the resolver can't find it, stop and report: that is a spec question (where a generic container's destructor lives when its policy conformance is bounded), not something to code around.
6. **The verifier, after elaboration:**
   - no `drop` remains unlabelled;
   - every drop flag is set before any guarded drop reads it, on every path;
   - every value is destroyed exactly once on every path to a return, re-checked through the shared analysis, so the double-drop and leak checks run over the OUTPUT;
   - no flag on a `consumes` field.

Pre-review of the U6e brief. The decisions are right, and the glue-resolution row and the borrowing-struct order are in. One interaction the brief doesn't name, with a live false positive behind it today, and three smaller points.

**1. Drop flags across the accessor split.** The split happens in MIR lowering, before borrowck and U6e, and the record can't carry a "maybe moved" state.

Repro (`.build/scratch/air-review/sl460/probe_accessor_flag.saw`):

```saw
func noted(&var self, i: Int, tag: String, keep: Bool) borrows -> &var Int {
    let note = tag
    if keep {
        let _ = self.log.push(move note)
    }
    lend self.cells[i]
    self.cells[0] = self.cells[0] + 1
}
```

- **Stage 0 accepts and runs it** (it prints `9`). It's legal: `note` is moved on one path and never used again.
- **sawc2 on main refuses it:** `move.use-after` at 14:9 (the `lend`), "moved at 12:21". The split writes every live local into the record at `lend`, and the borrowck dump shows the prologue moving the maybe-moved local, `[M WM UM UD] (*_1).2 = move _6`.
- **If that refusal were lifted naively, it would be a double free:** the epilogue loads the slot (`_4 = move (*_1).2`) and drops it with a **`static`** label, since its own analysis starts fresh at the load.

So the record has to carry initialisation state across the split. U6e is where flags are born, which makes this its question:
- **Either** the record gains a flag slot for each local that's only maybe-initialised at `lend`: the prologue writes the slot and the flag, the epilogue's drop is `flagged` on that flag, and the shared analysis models the record write as a state transfer rather than a use;
- **or** the split drops a maybe-moved local in the prologue, under its flag, and doesn't carry it at all. That's simpler when nothing after `lend` reads it, and it is the case here.

Either way, it needs a `compiler/mir` change to `split.saw` with approval, and the probe becomes a golden: accepted, one drop, flagged or prologue-side. Until it lands, the false positive is worth an entry in SL-460's findings.

**2. Suspension.** If coroutine frames are built after elaboration, a flag is an ordinary local and the frame builder carries it like any other. Pin a golden with a flagged drop across a suspending call, so the frame stage can't silently drop the flag.

**3. Generic drops.** In a generic body, a drop of `T` (or `Vector<T>`) has no glue yet. The resolution record should say "per instantiation" for it, and never pick structural or trivial by guessing. One golden row covers it.

**4. Panic.** State in §3.7 that a panic doesn't unwind (`__saw_rt_panic` writes and exits), so elaboration generates no cleanup paths and the verifier's "destroyed exactly once on every path to a return" excludes diverging paths. That's one sentence, but it's what makes the leak check sound.

SL-468.p1 is up: **U6e, drop elaboration** (`compiler/drops`, `sawc2 drops --dump | --check`). It is 3 commits squashed, 48 files, +5,412/−63 (about 2,770 of that is golden dumps), on main 20b88b7c. It doesn't touch typecheck or std, where SL-462 runs concurrently.

**The elaborated form**
- **Static** drops stay plain.
- **Elided** drops are removed, as is any drop in a block nothing reaches.
- **Flagged** drops become `switch copy _F -> [true: bbD, false: bbC]`, where bbD drops, clears the flag and joins.
- **Flags:**
  - they are `Bool` locals, noted `// flag _N` in the dump, created only for the paths a flagged drop names and for the accessor-record locals that need one;
  - bb0 sets each from the entry's conditions;
  - each update is placed after the statement that changes its path, taken from the shared analysis's own `apply`, never re-derived.
- **Glue:** each function's dump ends with its `glue TYPE: …` lines.

**Flag counts**
- `compiler/` has 7 flags for U6d1's 7 flagged drops.
- The corpus has 18 for 23. The README explains the 5: 3 are in programs borrowck refuses (`use_after_move_*`), and 2 are where the MIR verifier already reports a whole drop after a part moved (`move p.f`, which is SL-462's). Elaboration runs only on programs nothing earlier refused.
- 1,227 corpus programs elaborate, and the post-elaboration verifier is clean on all of them.

**Your c2 points**
1. **Flags across the accessor split.**
   - A Stage 0 probe with a printing `deinit` shows Stage 0 drops the maybe-moved local AFTER the epilogue, so the lead's flag-slot choice stands.
   - The record gains a `Bool` per owning local that isn't definitely whole at `lend`.

**The rest of the brief**
- **Partial paths and `consumes`:** MIR already breaks a partly moved value into drops of its parts, each labelled.
