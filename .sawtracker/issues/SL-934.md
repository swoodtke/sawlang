Found by SL-865 U8 (pplace). The spec counts an `@section` placement as a code-generation ROOT (a placed function is emitted even when nothing calls it, as an exported one is), but mono's root list (`add_roots`) doesn't include `@section` items. So an unreached internal `@section` function is never emitted, and the placement silently doesn't happen. (At -O1 and above, clang would also delete an unreferenced internal function unless it's marked `used`.)

The fix: `add_roots` takes `@section`-placed items as roots (through the profile/root funnel), and the backend marks them `llvm.used` (or gives them the linkage the spec requires) so the optimizer keeps them. Pin: an unreached `@section` function present in the object at -O0 and -O2 (`nm`/`objdump -h`).

**Implementation detail (lead, Nov 12): an `@section` placement is a root in mono and is kept through the optimizer by `@llvm.used`, for a function and for a static.**

**Why it matters to sawos:** a vector table, a boot header or an interrupt stub is placed by `@section` and named only by the linker script. Today an unreached placed function is never emitted, with no diagnostic.

**The rule (LANGUAGE_SPEC, Attributes):** code generation "emits only the functions reachable from `main`, the exports, and an `@section` placement"; a placement without `@export` keeps internal linkage ("the section is a placement request and never a second way to publish a symbol"). So the fix may not change linkage.

**What the code does today.**
- `compiler/mono/src/worklist.saw`, `add_roots`: roots `main`, each export (`export_symbols`), and the lang functions. No `@section` item.
- `compiler/llvm/src/program.saw`, `llvm_emit_program`: emits a placed STATIC's global whether or not a body reads it (the loop after `ll_placement`), but as `internal global` (`places.saw`, `static_global`), with nothing keeping it; `bodies.saw` `emit_function` writes `define internal` for an unexported function.
- `compiler/llvm/src/module.saw`, `bt_table_global`: the module's only `@llvm.used`, a one-element array naming `@__saw_bt_table`.

**Step 1, census (evidence before the change).** In the evidence directory, four small programs, each built for the host at -O0 and -O2, with `--codegen-units=1` and with `--codegen-units=module`, and for `riscv32-unknown-none-elf` with `--freestanding --runtime -c`; list each object's symbols and sections (`nm`, `objdump -h` or `llvm-objdump`):

|---|---|
| A: an unreached `@section` function | absent everywhere |
| B: an unreached `@section` static | present at -O0; UNVERIFIED at -O2 (the optimizer may delete an unreferenced internal global) |
| C: A and B, each also `@export`ed | present everywhere |
| D: a reached `@section` function and static (the existing probes' shape) | present everywhere |

Record the table. If B is present at -O2 today, say so: the static half of step 3 is then unnecessary, and the brief's step 3 keeps only the function half.

**Step 2, mono.** In `add_roots`, after the export loop: for every declaration `d` of kind `ResDeclKind.Func` that carries `@section` (`self.dp.bc.mir.tc.res.decl_attribute(d, Alt.Attr_Attribute_Section) >= 0`), is top-level and has no generic parameter, call `self.root_item(d, &none)` and push the item on a new `placed_items: Vector<Int>` of `MonoProgram`, beside `export_items`. A generic placed function has no instance to root: it is placed at each instance a call reaches, as today (`item_section`'s comment). A test-only declaration follows whatever `root_item` already does for an export. Update `add_roots`' leading comment (the roots now are `main`, the exports, the placements, the lang functions).

**Step 3, the backend keeps them.** One `@llvm.used` per module, holding in order: `@__saw_bt_table` when the table exists, then each `placed_items` function's symbol that is not exported, then each placed, unexported static's global (when step 1 shows B is deleted at -O2). The array's length is the element count: `@llvm.used = appending global [N x ptr] [ptr @a, ptr @b], section "llvm.metadata"`.
