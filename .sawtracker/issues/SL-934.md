Found by SL-865 U8 (pplace). The spec counts an `@section` placement as a code-generation ROOT (a placed function is emitted even when nothing calls it, as an exported one is), but mono's root list (`add_roots`) doesn't include `@section` items. So an unreached internal `@section` function is never emitted, and the placement silently doesn't happen. (At -O1 and above, clang would also delete an unreferenced internal function unless it's marked `used`.)

The fix: `add_roots` takes `@section`-placed items as roots (through the profile/root funnel), and the backend marks them `llvm.used` (or gives them the linkage the spec requires) so the optimizer keeps them. Pin: an unreached `@section` function present in the object at -O0 and -O2 (`nm`/`objdump -h`).

**Implementation detail (lead, Nov 12): an `@section` placement is a root in mono and is kept through the optimizer by `@llvm.used`, for a function and for a static.**

**Why it matters to sawos:** a vector table, a boot header or an interrupt stub is placed by `@section` and named only by the linker script. Today an unreached placed function is never emitted, with no diagnostic.

**The rule (LANGUAGE_SPEC, Attributes):** code generation "emits only the functions reachable from `main`, the exports, and an `@section` placement"; a placement without `@export` keeps internal linkage ("the section is a placement request and never a second way to publish a symbol"). So the fix may not change linkage.

**What the code does today.**
- `compiler/mono/src/worklist.saw`, `add_roots`: roots `main`, each export (`export_symbols`), and the lang functions. No `@section` item.
- `compiler/llvm/src/program.saw`, `llvm_emit_program`: emits a placed STATIC's global whether or not a body reads it (the loop after `ll_placement`), but as `internal global` (`places.saw`, `static_global`), with nothing keeping it; `bodies.saw` `emit_function` writes `define internal` for an unexported function.
- `compiler/llvm/src/module.saw`, `bt_table_global`: the module's only `@llvm.used`, a one-element array naming `@__saw_bt_table`.

**Step 1, census (evidence before the change).** In the evidence directory, four small programs, each built for the host at -O0 and -O2, with `--codegen-units=1` and with `--codegen-units=module`, and for `riscv32-unknown-none-elf` with `--freestanding --runtime -c`; list each object's symbols and sections (`nm`, `objdump -h` or `llvm-objdump`):

| program | today (expected) |
|---|---|
| A: an unreached `@section` function | absent everywhere |
| B: an unreached `@section` static | present at -O0; UNVERIFIED at -O2 (the optimizer may delete an unreferenced internal global) |
| C: A and B, each also `@export`ed | present everywhere |
| D: a reached `@section` function and static (the existing probes' shape) | present everywhere |

Record the table. If B is present at -O2 today, say so: the static half of step 3 is then unnecessary, and the brief's step 3 keeps only the function half.

**Step 2, mono.** In `add_roots`, after the export loop: for every declaration `d` of kind `ResDeclKind.Func` that carries `@section` (`self.dp.bc.mir.tc.res.decl_attribute(d, Alt.Attr_Attribute_Section) >= 0`), is top-level and has no generic parameter, call `self.root_item(d, &none)` and push the item on a new `placed_items: Vector<Int>` of `MonoProgram`, beside `export_items`. A generic placed function has no instance to root: it is placed at each instance a call reaches, as today (`item_section`'s comment). A test-only declaration follows whatever `root_item` already does for an export. Update `add_roots`' leading comment (the roots now are `main`, the exports, the placements, the lang functions).

**Step 3, the backend keeps them.** One `@llvm.used` per module, holding in order: `@__saw_bt_table` when the table exists, then each `placed_items` function's symbol that is not exported, then each placed, unexported static's global (when step 1 shows B is deleted at -O2). Build it in one function that `bt_table_global` and `llvm_emit_program` both go through (a module with no backtrace table but a placement still needs the array; a module with neither emits none). The array's length is the element count: `@llvm.used = appending global [N x ptr] [ptr @a, ptr @b], section "llvm.metadata"`. Linkage words don't change: `define internal` and `internal global` stay.

**SL-934.p1 submitted** (agent p934, Sonnet; on main). A placed function is a mono root, and placed, unexported definitions are kept through the optimizer by `@llvm.used`, with their linkage unchanged.

**The census found the defect wider than the issue said** (evidence in the lead's checkout, `.build/scratch/p934/census/`, `before.table.txt` and `after.table.txt`; host, riscv32 and xtensa-esp, -O0 and -O2, whole-module and split):
- an unreached `@section` function was absent everywhere (the issue);
- an unreached `@section` static was deleted at -O2 on all three targets;
- a REACHED placed function was inlined at -O2 and its placed body deleted, so the placement did not happen.
After the change all three are present in every row.

**Changes.** `compiler/mono/src/worklist.saw`: `add_roots` roots each non-generic top-level `@section` function (`placed_items`). `compiler/llvm/src/module.saw`: `ll_used_global` is the one place `@llvm.used` is built: the backtrace table, then unexported placed functions, then unexported placed statics; a module with neither a table nor a placement emits none. `compiler/llvm/src/split.saw`: `@llvm.used` is cut by definition, so each codegen unit lists only the elements it defines and a unit defining none has no list.

**Why the split changed (the agent's stop, the lead's decision).** With one list in the unit holding the table, naming a function another unit defined, the default ThinLTO link at -O2 dropped the function (the units' text is in `census/split_A_thin.units/`). `@llvm.used` has appending linkage, so a list per defining unit is the form that roots it. `--lto=none`, `thin` and `full` all keep the symbol now.

**Pins.** Two probes with `// ll defines:` headers; `check_placed_symbols` in the run lane, which builds four probes at -O2 with `--codegen-units=1` and `module` and reads the symbols with `nm` (the lane had no binary-level symbol check; this follows `check_split_object`'s style); a mono golden showing the placed function rooted and a generic placed function not rooted.

**Changes requested (rev 1): a placed function that suspends no longer builds.** The plain cases hold everywhere I looked; two positions of the same mechanism do not.

**What holds** (origin/main + rev 1 against v0.22.0, host, `-g0`): an unreached placed function, an unreached placed static, and the reached form of each are in the binary, in their section, at `-O0`, `-O1`, `-O2`, `-Os`, `-Oz`, with `--codegen-units=module`, with `--lto=none` and `full`, and under `--sanitize address`. Also: two placed functions and two statics in one module; a placed function over owning types and a closure; placed definitions in an imported module that `main`'s module never names (the split's cut by definition); `@export` beside `@section` (unchanged, external). Freestanding objects for riscv32, aarch64 and xtensa-esp at `-O0`, `-O2`, `-Os` hold the function and the static, where v0.22.0 holds neither at `-O2`.

**1. A regression: `@llvm.used` names a symbol a suspending function is not defined under.** A function that suspends is emitted as its resume function alone, and the list names the item's plain symbol:

```saw
@section("__TEXT,__sawfn,regular,pure_instructions")
func placed() -> Int {
    sleep(Duration.ms(1))
    7
}

func main() {
    print("{}", placed())
}
```

```
x.ll:230:67: error: use of undefined value '@saw suspending_reached.placed()'
  230 | @llvm.used = appending global [2 x ptr] [ptr @__saw_bt_table, ptr @"saw suspending_reached.placed()"], section "llvm.metadata"
sawc build: clang exited 1
```

   - The define is `@"saw resume suspending_reached.placed()"`, and it carries the section.
   - With `--codegen-units=module` it is `INVARIANT: the splitter finds no definition or declaration of ...` instead.
   - v0.22.0 builds this program at every level and it prints 7. The same holds when the suspension is in a callee (a placed function calling a helper that sleeps: prints 9 on v0.22.0, fails here), and when nothing calls the placed function (builds on v0.22.0, fails here).
   - So the kept symbol has to be the one the item is defined under, with a fixture for a placed function that suspends, reached and unreached, whole-module and split.

**2. A generic placed function's instances are still deleted at `-O1` and above.** The census's third finding was "a reached placed function was inlined at -O2 and its placed body deleted, so the placement did not happen". That is still true of a generic one, before and after this patch:

```saw
@section("__TEXT,__sawgen,regular,pure_instructions")
func placed_generic<T>(v: T) -> T { v }

func main() {
    print("{}", placed_generic(7))
    print("{}", placed_generic(true))
}
```

   - `-O0`: both instances, section `__sawgen` of 64 bytes. `-O1`, `-O2`, `-Os`, `-Oz`, split, `--lto=full`, ASan: no symbol and no section.
   - The patch's own words say otherwise: the worklist comment has a generic one "placed where a call reaches it", and the golden's header "it is an item only where a call reaches it". `item_section` gives every instance the section; only `placed_items` reaches the list.
   - Both findings come from building the list from mono's roots instead of from what the backend defines with a section. A list made of every define that gets a `section` clause (and every placed static) would cover the instances and name the resume function, in one place. If instances are left out on purpose, the spec has to say a generic function's placement is not kept, and the two comments with it.

**3. The spec does not say what this patch makes true.** Attributes: an export "is a keep-root at all three points where unreached code is discarded", and a placement is named at one of them, code generation; `@section`'s own paragraph says "Placement is all it does". After this patch a placed definition is kept through the optimizer and the link, reached or not, and never inlined away. The lane's new check holds exactly that. One sentence in the `@section` paragraph, and the keep-root paragraph's list.
