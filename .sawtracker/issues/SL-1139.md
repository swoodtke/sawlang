## Description

**sawc panics on a 32-bit target compiling the literal `-9223372036854775808`.** Found by SL-1129's design pass (Nov 15); reproduced by the lead on main (`.build/scratch/pneg/neg.saw` in the lead's checkout):

```saw
func main() {
    let x = -9223372036854775808
    print(x)
}
```

- `sawc build --target riscv32-unknown-none-elf --freestanding -c neg.saw`: `panic at arith.saw:508: integer overflow` (the compiler itself aborts; no diagnostic).
- On the host (64-bit `Int`) it builds.
- The same happens in a const generic argument with no expected type (SL-1129's matrix).

**The mechanism** (`tc_arith_negative_literal`, `compiler/typecheck/src/arith.saw`): the literal's magnitude `m` arrives as `Int.min` (2^63 does not fit the compiler's own `Int`, and the magnitude wrapped). On a 64-bit target `m == low` returns `Int.min`. On a 32-bit target `low` is -2^31, so the function takes the refusal branch, `m < 0`, and computes the fault's bits as `0 - m`: `0 - Int.min` overflows in the compiler's own checked arithmetic, and the compiler panics where it should refuse the literal for not fitting `Int`.

**The fix's shape:** the refusal must not negate a magnitude that is `Int.min` (record the bits without overflowing, or refuse on `m < 0` before any negation), and the literal is then refused with the ordinary "does not fit `Int`" diagnostic and its suffix suggestion, as `-2147483649` is on the same target. **Obligation 4:** every `0 - x` / unary minus in `compiler/typecheck/src/arith.saw` and the fold (`compiler/typecheck/src/` const evaluation, `compiler/eval/`) on a value that can be `Int.min`; a probe per site on riscv32, arm64 freestanding and the host, at the literal, in a const generic argument, in a static's initialiser and in a fold (`-(N)` with `N` at `Int.min`).

**Pins:** a refusal fixture for the literal on riscv32 (the lane's `COMPILE-FLAGS` for a target), and the sweep's other sites as rows.

Related: SL-1129 (its design keeps `ConstInt` at [-2^63, 2^64) and touches this file).
