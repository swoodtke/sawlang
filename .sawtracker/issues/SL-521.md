**Ruled by the user (Oct 10), Q-args in SL:open-questions.** `Env.args` takes a defaulted policy for an argument that isn't valid UTF-8.

**API:**
```saw
let args = try Env.args()                    // default: panics, naming the argument's index
let args = try Env.args(invalid: .replace)   // each invalid sequence becomes U+FFFD
```
- **The policy is an enum,** default `panic`, with cases `panic` and `replace`. An enum rather than a `Bool`, so the call site reads as what it does, and a later policy doesn't break callers. The working name is `InvalidArgumentText`; settle the final name with the spec text, following the no-abbreviations doctrine.
- **`replace` keeps every argument in place.** The count and positions match `argv`. The replacement follows the WHATWG/Unicode "maximal subpart" practice, one U+FFFD per maximal invalid subsequence, which is what `std/utf8.saw`'s validator boundaries give.
- **Rejected:** skipping an invalid argument, which shifts every later index (`args[1]` silently becomes the next argument); and a compound error type, which is heavier for the common case. A bytes-level, lossless `arguments()` is deferred until a program needs one.

**Work:**
1. **Spec:** `Env.args` in the std overview and the Allocation-failure list (its signature gains the parameter), plus the policy enum's text.
2. **`std/env.saw`:** the parameter, the enum, the `replace` path through `std/utf8.saw`, and the panic message naming the index.
3. **The std lane:** the equivalence row for `Env.args` gains the parameter. That's an exception against Stage 0, with its reason: Stage 0 has no parameter and silently builds an invalid String. Add behaviour pairs for valid arguments, a `replace` with an invalid argument in the middle (count and positions kept, `�` present), and the default panic (exit status and message).

Not on the bootstrap path, since sawc2's arguments are paths and flags, so take a free slot. Gate: `compiler`, `docverify` and `citations`.

@claude-sawlang, a pre-review note for SL-521's `replace` path: **`std/utf8.saw`'s validator gives where a malformed sequence starts, not how far its maximal subpart runs, and "one U+FFFD per maximal subpart" needs the second.**

`utf8_sequence_width` returns 0 at the lead byte and nothing more, so a loop built on it would replace one byte per U+FFFD. The maximal subpart is the lead plus every following byte that is still a valid continuation for *that* lead: the narrowed first continuation after `E0`, `ED`, `F0` and `F4`, then `80..BF`. It stops at the first byte that can't continue, or at the end. So `replace` needs one more helper beside the validator, for example `utf8_maximal_subpart(bytes, count, at) -> Int` (1 to 3), sharing the validator's range table so the two can't drift.

Vectors for the behaviour pairs. These are Unicode's recommended practice (Unicode 3-8; the WHATWG decoder agrees):

| bytes | U+FFFDs | why |
|---|---|---|
| `C3 28` | 1, then `(` | `C3` alone; `28` can't continue it |
| `E0 A0` at end | 1 | a valid 2-byte prefix of a 3-byte sequence, cut off |
| `F0 9F 98` at end | 1 | a valid 3-byte prefix, cut off |
| `E0 80 80` | 3 | after `E0` the first continuation must be `A0..BF`: `E0` alone, then two bare continuations |
| `ED A0 80` (a surrogate) | 3 | `ED`'s first continuation is `80..9F` |
| `C0 80` | 2 | `C0` never leads |
| `F4 90 80 80` | 4 | past U+10FFFF: `F4`'s first continuation is `80..8F` |
| `80` | 1 | a bare continuation |

The middle-argument pair in the work list could carry `E0 80 80`, since it's the case that tells "one per subpart" apart from "one per sequence start".
