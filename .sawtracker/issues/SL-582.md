- **Scope:**

**p582 STOP (step 2, before any edit): B1's lifetimes leave out the point of a value's initialising statement, so B2's packing as written may overlap a statement's destination with the operand it moves out of.**

**Evidence**
- Probe `.build/scratch/probe_move.saw` (worktree agent-a4937b4bb4d2c5477) does `let y = Big(...)` (NoCopy, 56 B), `__saw_suspend()`, `let x = move y`, `__saw_suspend()`, then uses `x`.
  - `sawc2 coro --std-root std --dump` gives `_1 y: bb1.t s1 r1 bb2.0` and `_4 x: bb2.t s2 r2 bb3.0-t bb4.0-2`.
  - `--lowered` bb2.0 is `(*_10).[72: probe_move.Big] = move (*_10).[16: probe_move.Big];`.
  - So `coro_lifetimes_meet(x, y)` is false, and the plan's packer may give the two any offsets, a partial overlap included.
- Cause in the code: `coro_lifetimes_of` marks point p before it applies statement p's accesses. A fresh destination is live from p+1, and the operand it moves is live through p. §3.9 says a lifetime runs "from initialisation".
- The backend writes an rvalue straight into its destination's address:
  - a `Move` of a memory value is one `llvm.memcpy(dest, src)` (llvm/places.saw `operand_into`, then prims.saw `copy_bits`);
  - an aggregate writes member by member (ops.saw `members_into`), reading each operand after the earlier members are stored.
  - A memcpy whose source and destination partly overlap is UB. A member-by-member write over its own source corrupts it outright.
- A layout that partly overlaps them under the plan's greedy order (decreasing size, then first id, first fit):
  - the state word at [0,8);
  - `a` (32 B, interferes with `x` only) at [8,40);
  - `b` (24 B, interferes with `y` only, not with `a`) at [8,32);
  - `y` (16 B) at [32,48);
  - `x` (16 B) at [40,56).
  - `x = move y` is then `memcpy(frame+40, frame+32, 16)`.
- Scope seen so far:
  - The MIR builder routed aggregates through a stack temporary in the probes (`_3 = Pair{..}; x = move _3`), so the shape I can show is `x = move y` between two residents.
  - Erase and collection literals are not checked.
  - Call terminators look safe: a Saw callee copies its memory arguments on entry, before it writes `sret`; a child slot meets its argument sources at `t` and the move-out's destination at `r`.
- B3, as planned, recomputes lifetimes on the same point model, so it would not catch this.

**Options (for the lead's ruling)**
- (a) **lifetimes.saw:** a statement's whole-write destination is live at that statement's own point, its definition.
  - It is one definition of a lifetime, and B3 inherits it.
  - Residency is unchanged: a statement point is a suspension point only for a budget statement, which writes nothing.
  - It moves every `.coro` golden that prints such a local. This brief forbids `.coro` moves, and the file is outside my list.
- (b) **layout.saw only:** two values also interfere when one's set ends at statement point p and the other's starts at p+1.
  - p+1 is in the same block, p's only successor.
  - It reads only the sets, and nothing in `.coro` moves.
  - It departs from the plan's "interference = lifetimes meet".
- My recommendation is (a); (b) is the in-scope stopgap.

**A smaller gap, which I would settle myself unless told otherwise:** the state word must stay at offset 0.
- llvm/bodies.saw's resume entry does `%state = load i64, ptr %frame`.
- A drive starts a child "at state 0" at its slot's base.
- So the packer places the state word at 0 before the greedy order. By decreasing size alone, any larger value would take offset 0.

**Step 1's map** (ready, for a quick resume)
- **Assignment:** `coro_lay_out_frames`, then `coro_lay_out_frame`, then `coro_interference` (`coro_lifetimes_meet` per pair), then `coro_assign` (no sharing).
- **Readers that are safe under sharing**, since each finds a value by kind and local:
  - lower.saw's resident rewrite (`coro_frame_place` at the value's offset), `coro_child_offset`, the drive and offload slots (`coro_next_value`), and `CoroResume.result`;
  - drive.saw and spawn.saw's parameter, state and result writes;
  - `coro_slot_writes`' owed count by (kind, offset, type). Parameters all meet at entry, so only zero-size ones share.
  - The backend: the state at frame+0, the result from `resume.result`, and slots from their `FrameSlot` steps.
  - verify.saw rule 1's per-local offsets (`coro_verify_layout_offset`), and `coro_verify_child_slot`, which goes by drive order.
- **Readers that assume no sharing** (verify.saw, the fix each needs):
  1. `coro_verify_local_at`, which maps an offset to the first held local, as used by `coro_verify_index_source`. Two locals packed at one offset make an index temporary's source ambiguous, which is a false rule-1 INVARIANT. The fix: compare the copied slot with the named local's own offset and type.
  2. `coro_verify_regions`, which sorts a place lowering added by its offset: the offload range first, then the child regions, then `slots[l] == offset`. A child's allowed parameter write that lands in bytes an offload's storage or a local also uses (disjoint lifetimes) is flagged. The fix: accept a place in `allowed` first.
- **dump.saw:** prints the offsets. It gains the extent and the lower bound.

Nothing is edited; the worktree is clean apart from gitignored `.build/scratch/` probes.

**SL-582.p1 submitted: B2, interference and fixed-offset packing (one commit 89f2bf795; agent p582).** The c3 rulings apply.

**The packing (`layout.saw`):** `coro_assign` packs.
- The state word is pinned at offset 0: the resume entry loads it there, and a drive starts a child at its slot's base.
- Every other value is placed by decreasing size, then frame order, at the lowest aligned offset clear of every interfering value already placed.
- Zero-size values go last and never sit on a byte another value holds.
- Funnel entry points: `coro_lay_out_frames`, `coro_interference` (only `coro_lifetimes_meet`), `coro_assign` and `coro_lower_bound`.
- `--layouts` prints `(size S align A, lower bound B)`.

**The lifetimes fix (ruling (a), the soundness gap B2 found):** a local is live at the assignment that writes into it, whole or a field, unless the write goes through a dereference. A destination and the operand it moves out of therefore always interfere, which the backend's `memcpy` and member-wise writes need. B3 inherits the definition.

**Verifier:** `coro_verify_local_at` is removed; an index source is checked against its local's own offset and type. `coro_verify_regions` accepts a drive's allowed place or an index load first.

**Pins:**
- `pack_sequential`, `pack_arms` and `pack_disjoint`: shared offsets.
- `pack_move`: the `x = move y` overlap case, which is disjoint now and would overlap without the rule.

- `pack_p2_layout`: rebuilt; Stage 0's 432 B `caller` → 80 B, at the bound.
