## Description

Confirmed on production sawlang checkout 30c5a55016aed806a2f94a64d62224c6cafc135a, macOS arm64, using its Python sawc compiler.

The lexer encodes an escaped brace as byte 0x01 followed by the brace. A legitimate Unicode escape for U+0001 followed by a Unicode escape for a brace produces the same token bytes. The parser unconditionally removes the marker, silently deleting real String content.

Reproducer:

```saw
func main() {
    let escaped = "\{"
    let literal = "\u{1}\u{7b}"
    print(escaped.len())
    print(literal.len())
    print(literal.byte_at(0) as Int)
}
```

Expected stdout: `1`, `2`, `1`. Actual stdout: `1`, `1`, `123`, exit 0. The intended two-byte String (U+0001 and `{`) is changed to a one-byte `{` String. This example does not use interpolation. The same marker mechanism is used for closing braces.

Relevant implementation: sawc/lexer.py:381-383 inserts `\x01{` / `\x01}` for escaped braces; sawc/parser/expressions.py:731 removes either sequence by replacement, without provenance. The existing selfhost/lexer/src/lib.saw read_string follows the same marker protocol, so its StringLit token representation is also ambiguous. Preserve whether a brace came from an escape independently of real content (or use an unambiguous encoding), and test literal marker bytes beside both braces as well as ordinary escaped braces/interpolation.

Local standalone source: /Users/swoodtke/Projects/sawlang/.build/scratch/string_brace_provenance.saw. Compiled with `/Users/swoodtke/Projects/sawlang/.venv/bin/python sawc/sawc.py .build/scratch/string_brace_provenance.saw -o .build/scratch/string_brace_provenance`, then executed directly. No production files changed. Found while implementing isolated owned-String support in the compiler prototype; that prototype will preserve literal provenance rather than reproduce this behavior.
