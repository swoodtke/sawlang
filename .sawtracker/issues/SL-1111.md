## Description

**A negative const DEFAULT for a parameter that sizes an array is accepted, where the same value written as an argument is `constant.negative-length`.** Found by the Air's review of SL-457.p4 (Nov 14); older than that patch, the same on main. The reviewer's programs: chat file f76 (`gen_more.py`: d1 to d6, d9 and d12), generated by the lead under `.build/scratch/p457u3/air_p4/more/`.

- `struct Dflt<const N: Int = -1> { d: [UInt8; N] }`: builds, and `sizeof<Dflt>()` prints -1. The same for a default of `2 - 3`, and for a static of -4 (prints -4). `Dflt<-1>` written out is refused.
- `func fill<const N: Int = -1>() -> Int { let a = [0u8; N]; a.len() }`, then `fill()`: `sawc build: clang exited 1` on the IR sawc wrote, with no `ERROR` line.

**Mechanism (UNVERIFIED, by the shape):** `check_argument_kind`'s rule (a value that sizes an array is not negative) runs for a written argument and not where a default fills the parameter. The second program is the per-instantiation side: a repeat count over a const parameter is checked nowhere once the parameter has a value. Sweep before fixing: every way a const parameter gets a value (written, defaulted, inferred from an argument's type `[T; N]`, forwarded from an enclosing generic) × every way it sizes something (a field length, a local's length, a repeat count, a nested generic's argument).
