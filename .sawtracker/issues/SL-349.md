## Description

Found by design 275 U3's codex-r2 sweep (SL-318, agent:claude-sl318u3d, Sep 22), while probing the window-root identity fix (r2 #8) in its DRIVEN twin. Pre-existing: reproduces on the base compiler (main, pre-U3) with no window in sight.

REPRO (`.build/scratch/u3d/f3_iso_shadow.saw` in the sl318u3 worktree):

```saw
import std.task.{yield_now}
struct Owner { value: Int }
static ROOT: Owner = Owner(value: 1)

func static_shadow_driven() -> Int {
    yield_now()
    var ROOT = Owner(value: ROOT.value + 1)   // a design-107 derived shadow of a STATIC
    ROOT.value = ROOT.value + 1
    ROOT.value
}
func main() { print(__saw_drive(static_shadow_driven())) }
```

Expected `3` (the sync twin prints 3; the same shape over a LOCAL root — `let base = …; yield_now(); var base = Owner(value: base.value + 1)` — prints 3 driven). Observed: `panic at frame.saw:107: Slot.value: slot is empty`, SIGABRT.

MECHANISM (named per obligation 4, unverified in code): the coroutine transform's identifier rewrite inside the shadow's INITIALIZER resolves `ROOT` by NAME to the frame field of the binding being declared (the shadow), rather than to the module static the typechecker resolved it to — the sync codegen and the local-root twin both order the read before the binding, the driven static case does not. The typechecker is right (design 107's mentions-rule admits the shadow; the initializer's `ROOT` is the static). Sibling positions to probe with the fix: a derived shadow of a static inside a driven loop body, inside an `if let` branch, and a static read in the initializer of a same-named local declared in an inner scope.

Not worked around: the U3 r3 accept pin (`examples/borrowing_rules_resolve_aliases.saw`) carries the sync cell only and cites this issue for the driven one.
