## Description

**Found by A8a (SL-563).** The new std's `std.mem.drop_in_place` is not in place: it relocates the pointee to a temporary and destroys the temporary, so a `NoMove` value's `deinit` runs at an address that is not the value's home.

**Mechanism.** `std/mem.saw`:

```saw
public func drop_in_place<T>(at: UnsafePointer<T>) unsafe {
    let _ = move at[0]
}
```

`move at[0]` moves the value out into a temporary on the stack, and `let _` destroys that temporary. For an ordinary type that is unobservable. For a `NoMove` type it is the one thing the trait forbids, and nothing refuses it: the generic body's `move` is checked once, at an abstract `T`, and the instantiation at a `NoMove` `T` is never checked (spec: `NoMove` "moves once, into its home"). Stage 0's std has an intrinsic for this, `__saw_deinit_in_place` (`sawc/std/box.saw`); the new std has none.

**Who reaches it:** `Box<T, A>.deinit`, `Vector`'s element teardown (`std/vector.saw`), `Map`'s slot teardown (`std/map.saw`), and `std/taskgroup.saw`'s background-group publish race. So `Box<TaskGroup>`, the spec's sanctioned movable handle over pinned state, destroys its group at a stack copy.

**Why it matters for `TaskGroup`.** A group registers its own address in the ambient scheduler list at its first spawn, and its `Deinit` unregisters by that address. Run at a copy, the `Deinit` drives the copy's tasks (the copy shares the slots' buffers) and then fails to find the copy in the list. The real group stays linked after its storage is freed, and the next sweep walks freed memory. Under A8a's std-lane probe the next join returned early and panicked: `Task.join: the task cannot finish while this join waits for it`.

**Repro** (`sawc2 build --std-root std`):

```saw
import std.mem.{drop_in_place}

struct Pinned { id: Int }
extension Pinned: NoCopy {
    func deinit(&var self) unsafe {
        print("deinit {} at {}", self.id, (&self) as UnsafePointer<Pinned> as Int)
    }
}
extension Pinned: NoMove {}

func main() unsafe {
    let raw = GlobalAllocator().alloc(sizeof<Pinned>(), alignof<Pinned>())!
    let p = raw as UnsafePointer<Pinned>
    p[0] = Pinned(id: 1)
    print("placed at {}", p as Int)
    drop_in_place(p)                                   // deinit at a stack address
    let b = try! Box<Pinned>.make(Pinned(id: 2))       // deinit at a stack address too
}
```

prints `placed at 4342013088`, then `deinit 1 at 6131755040`; the boxed one also reports a stack address. A local, a struct field, and a whole-referent replacement through `&var` all run `deinit` at the value's own address, so the class is exactly the callers of `drop_in_place`.

**Sweep of the mechanism's other positions.** Every generic body that moves a `T` out of storage it then frees: `drop_in_place` and its three callers above, plus every move-out of a `Vector` element at a `NoMove` type. The spec refuses a `Vector` at a `NoMove` element "where that move is written"; sawc2 accepts it: `var v = Vector<Pinned>()`, `try! v.push(Pinned(id: 1))`, `let p = v.pop()` builds, runs, and runs the `deinit` at a stack address. The fix needs an in-place drop the compiler lowers (a lang intrinsic, as Stage 0's `__saw_deinit_in_place`, or a MIR `drop` of a pointer place), plus the per-instance `NoMove` check of a generic body's `move`.

**Air, for the fix's per-instance `NoMove` check: keep the spec's one placement exception.** LANGUAGE_SPEC, *The NoMove trait*, "Placement into heap storage": a by-value **parameter** may be placement-moved into freshly allocated storage at a `NoMove` type, provided the body took no reference to it first. - refuse a relocation (`Vector` growth, refused "where that move is written");
- accept the fresh-parameter placement (and refuse it once the body has taken `&value`, as the spec's `observe(&value)` example shows).
