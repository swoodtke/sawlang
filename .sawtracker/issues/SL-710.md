**SL-710 implemented on branch `worktree-agent-a6f098c61bce625db`** (head e5649a95c, rebased on main 2026-10-15; not submitted).

**The funnel.** Mono's half is `resolve_collection_literal` (`compiler/mono/src/worklist.saw`, entry point `resolve_stmt`); the backend's is `collection_literal_into` (new `compiler/llvm/src/literals.saw`, entry point `aggregate_into`).
- A fixed array writes each element into its slot, in index order.
- A repeat writes its value once, as element 0, and copies element 0 into each later slot through the element's copy glue, which is Stage 0's order. An all-zero scalar fills by one `memset`, and a count of 0 drops the value.
- `Vector`, `Map` and `Set` each call `init()`, then `push(value:)`, `insert(key:value:)` or `insert(value:)` per entry. A refused insertion panics `collection literal: …`, and the value a repeated map key replaces is dropped at once.
- Also taken, because the literal programs need them:
  - fixed-array indexing, with Stage 0's bounds panic (`array: index out of range: I (len N)`), in `places.saw`;
  - the builtin `len` (SL-714);
  - a fixed array's drop glue (reverse index order) and copy glue (index order), as loops, in `compiler/mono/src/glue.saw`.
  - SL-599 (Map and Set literals in mono) is covered too, and its due pin `map_set_literals` now builds.

**Pins:** run programs that match Stage 0 at -O0 and -O2: `fixed_array_literal`, `repeat_literal`, `fixed_array_glue`, `map_set_literal`, `map_literal_alloc_failure` and `map_set_literals`.

**SL-710.p1: collection literals in the backend, summary for review.**

**The funnel, in two halves, each docstring naming its entry points:**
- **Mono's half** (`resolve_collection_literal`, entry `resolve_stmt`) makes the items each literal kind needs:
  - a repeat gets its element's copy and drop glue;
  - `Vector`/`Map`/`Set` get `init()` plus `push(value:)`/`insert(key:value:)`/`insert(value:)`, and the rendering of the error a refused insertion panics with;
  - a `Map` also gets the drop of a replaced value.
- **The backend's half** (`collection_literal_into`, entry `aggregate_into`, new file `compiler/llvm/src/literals.saw`):
  - fixed arrays are written in index order;
  - a repeat is evaluated once into slot 0 and then copied through the element's hook. That's Stage 0's order, checked (`hook 1, hook 1` gives `1 101 101`). An all-zero scalar is one `memset`, a zero count drops the value, and the count comes from the array type, so a const-generic `N` works;
  - containers are `init()` plus one insertion per entry, and a refused insertion panics `collection literal: …` (design 234's panic boundary for literals).

**Also taken, because the same programs need them:**
- fixed-array indexing, with Stage 0's bounds panic;
- the builtin `len` (SL-714);
- array drop and copy glue, as loops: drops in reverse order, copies in index order;
- SL-599 (Map/Set literals in mono). The due pin `map_set_literals` builds.

The spec is silent on duplicate Map literal keys, so Stage 0's replace-and-drop holds.

**Pins:** `fixed_array_literal`, `repeat_literal`, `fixed_array_glue`, `map_set_literal`, `map_literal_alloc_failure` and `map_set_literals` match Stage 0 at -O0 and -O2. The sweep matrix covers each literal kind × element kind (trivial, Copy-with-hook, String, owning NoCopy, ExplicitCopy, nested) × position (let, argument, return, field, suspending function, indexed read).

**Corpusdiff (SL-666), re-measured on main with SL-564:**
- 57 rows move to pass.
- `repeat_literal_static` stops at a later refusal (statics, SL-722).
- 5 move to `wrong`/`link`. All are pre-existing or unmasked, and all are filed:
  - SL-730: a negative repeat count or array length, and a constant out-of-bounds index;
  - SL-731: a `move` argument leaks when a later argument's `try` fails;
  - SL-732: the panic text for `m[k]` on a missing key;
  - SL-733: a primitive `&self` receiver passed by pointer.
- SL-734 covers the siblings: builtin `swap`/`copy`, and `==` on a fixed array.
