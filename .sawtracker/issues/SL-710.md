**The backend slice refuses collection literals:** "an array, a repeat, a `Map` or a `Set` literal is not in the backend slice yet" (50 corpus programs) and "a fixed array, a repeat, a `Map` or a `Set` literal …" (15), per main's corpusdiff baseline on Oct 15. Found while porting gmgate (SL-697), where it blocks `df139a` and other ownership twins. Collection literals are a design-75 surface with a documented panic boundary (allocation failure in a literal panics). Plan the lowering per literal kind (fixed array `[T; N]`, repeat `[v; N]`, growable `Vector`, `Map`, `Set`), with the element moves and drops the drops lane already specifies. Pins: the corpus programs that move, the corpusdiff baseline (SL-666), and drop-order run programs matching Stage 0.

**SL-710 implemented on branch `worktree-agent-a6f098c61bce625db`** (head e5649a95c, rebased on main 2026-10-15; not submitted).

**The funnel.** Mono's half is `resolve_collection_literal` (`compiler/mono/src/worklist.saw`, entry point `resolve_stmt`); the backend's is `collection_literal_into` (new `compiler/llvm/src/literals.saw`, entry point `aggregate_into`).
- A fixed array writes each element into its slot, in index order.
- A repeat writes its value once, as element 0, and copies element 0 into each later slot through the element's copy glue, which is Stage 0's order. An all-zero scalar fills by one `memset`, and a count of 0 drops the value.
- `Vector`, `Map` and `Set` each call `init()`, then `push(value:)`, `insert(key:value:)` or `insert(value:)` per entry. A refused insertion panics `collection literal: …`, and the value a repeated map key replaces is dropped at once.
- Also taken, because the literal programs need them:
  - fixed-array indexing, with Stage 0's bounds panic (`array: index out of range: I (len N)`), in `places.saw`;
  - the builtin `len` (SL-714);
  - a fixed array's drop glue (reverse index order) and copy glue (index order), as loops, in `compiler/mono/src/glue.saw`.
  - SL-599 (Map and Set literals in mono) is covered too, and its due pin `map_set_literals` now builds.

**Pins:** run programs that match Stage 0 at -O0 and -O2: `fixed_array_literal`, `repeat_literal`, `fixed_array_glue`, `map_set_literal`, `map_literal_alloc_failure` and `map_set_literals`.

- 5 move to `wrong` or `link`. Their causes are outside this change, and each is filed: SL-730 (`array_const_index_out_of_bounds`, `repeat_literal_negative_error`), SL-731 (`coro_try_in_borrowed_place_index`), SL-732 (`T18_map_forced_absent_key`) and SL-733 (`self_receiver_pointer_reaches_caller`).
