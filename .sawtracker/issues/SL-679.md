## Description

**Finding (a9budget, while pinning SL-566):** once a group has recycled slots, its tasks run in the opposite order to their spawning, where Stage 0 runs them in spawn order.

- **Repro:** `Task.spawn` a task printing "a" and one printing "b", join both, then spawn "c" and "d" and join them. sawc2 prints `a 1 b 1 d c 1 1`; Stage 0 prints `a 1 b 1 c 1 d 1`.
- **Mechanism:** `std/taskgroup.saw`'s free list is a stack. `recycle` pushes slot 0, then slot 1, so `place` pops slot 1 for `c` and slot 0 for `d`. The sweep in `exec_run` resumes slots in index order, so `d` runs before `c`. Run order therefore depends on recycling history, not on spawn order.
- **Reach:** every program that spawns after earlier tasks finished, in the background group and in a `TaskGroup`. Any test asserting an interleaving across such spawns differs from Stage 0. `compiler/tests/run/op_budget_interleaving.saw` spawns its tasks in one round to stay clear of it.
- **Fix direction:** reuse slots lowest first (a FIFO or a sorted free list), or make the sweep follow a run queue in spawn order, whichever Stage 0's executor does. That is std track work (`std/taskgroup.saw`).
