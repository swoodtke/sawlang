**A5. A `consumes` body that moves a field out and refills it leaks the refill** (SL-606, bucket A). Finding: Drops 2.

- **Mechanism:**
  - `bind_consumed_receiver` (`mir/src/lower.saw`) leaves out of the release every field moved ANYWHERE in the body, judged syntactically (`fields_moved_from_self`), even when the field is refilled later.
  - `consumes.some-paths` judges by the conditions at return, so the two rules disagree.
  - The drops verifier registers a consumed receiver with `scope_fieldwise`, which never sets `owned`, so its leak check skips every consumed receiver.
- **Fix:** decide the receiver's release from the initialisation state at each return, the same facts `consumes.some-paths` uses, and register consumed receivers so the leak check covers them. Alternatively, refuse the refill shape as Stage 0 does. The spec decides which; read the `consumes` section first.
- **Pins:** the review's `review_drops_consumes` probe, which must print `drop 99` or be refused per the spec, plus a verifier injection: a consumed receiver with a leaked field is reported.
- **Done when:** the probe matches the spec, and the verifier's leak check covers consumed receivers.

Stage 0's refusal is stricter than the spec and isn't a meaning it gives an accepted program. This is a reversible decision, recorded as conformance row V125.
- **Fix, by mechanism:**
  - The release no longer decides anything syntactically. `bind_consumed_receiver` drops every owning field, and the borrow check labels each drop by the conditions at the return: elided where the field left, static where it stayed or came back. The syntactic scan (`moves_out_of_self`) now decides only whether the release goes field by field.
  - `consumes.some-paths` judges each return by what the body leaves there, before the release's own drops (`init_walk_body_exit`), so the two rules read the same facts. A field assigned again on one path only is still refused; the new fixture is `.refill`.

- on the straight line;
