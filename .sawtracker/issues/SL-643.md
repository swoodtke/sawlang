**A spelled `move` at a Borrow position moves nothing** (SL-606; found by SL-623's sweep).

- **The bug:** `let a = Res(n: 1); print("fmt {}", move a); print("again {}", a.n)` is accepted by sawc2 and prints `fmt res / again 1 / drop res`. The frozen `sawc` refuses `a.n` as a use of a moved variable. The value drops once, so nothing is freed twice, but the `move` the reader wrote is silently dropped. A later consuming use of `a` is then accepted, and a `move` that a reader relies on to end a lifetime does not end it.
- **Mechanism:** positions that borrow their operand call `set_use(operand, TcUse.Borrow)` directly (`bodies.saw`: comparison operands, format arguments, interpolation and more; grep for `set_use(.*TcUse.Borrow)`). That overwrites the use `consume` would have recorded, a `Move` for `Expr_Move_Place` (`by_value_use`). MIR's `move_val` returns the moved place as not fresh, and `transfer` with `Borrow` then reads it in place. The borrow check runs on MIR, so it never sees a move. The inner name keeps its `move` use in typecheck's record, so the two records disagree.
- **Fix shape:** at a Borrow position, a spelled `move` operand is still a move into a temporary that the statement drops (spec, Temporaries), as SL-623 does at the raw enum cast. Either the positions route through one helper that keeps `Move` for a spelled move (a funnel, with its ENTRY POINTS), or MIR's `transfer` treats a `move` under `Borrow` as a hand-off it owns.
- **Positions to sweep:** each `set_use(..., TcUse.Borrow)` whose operand is a value expression: comparison, format argument, interpolation segment, `??`'s subject, a receiver.
- **Probe:** `.build/scratch/c623/movecmp.saw` in agent worktree `agent-a6601eb0884059b7f`.
- **Pins:** for each position, a `borrowck` refusal of a use after the `move`, and a run program whose moved value drops at the end of its statement.

Approved patch SL-643.p1 (revision 1)

Approving SL-643.p1. At a position that borrows its operand, a spelled `move` now moves the place into a temporary (`moved_to_temporary`), which the position borrows and its statement drops. It's done once, in `move_val`, which every spelled move passes through, so it covers every `set_use(…, Borrow)` site without a funnel per site. Exact tree on 78f4bda25: e6ff8562.

**Every value drops once, where the spec puts it** (`.build/scratch/air-review/sl643/moves2.saw`, a `NoCopy` `Res` with a printing deinit, a `Printable`, a hand-written `Equatable` and a `&self` method):

| build | output |
|---|---|
| main | `fmt res 1\|after fmt\|equal\|after cmp\|look 30\|after look\|first res 4\|between\|drop 5\|drop 4\|show -> 5\|end\|drop 3\|drop 2\|drop 2\|drop 1\|` |
| patch, -O0 and -O2 | `fmt res 1\|drop 1\|after fmt\|drop 2\|equal\|after cmp\|look 30\|drop 3\|after look\|first res 4\|drop 4\|between\|drop 5\|show -> 5\|end\|drop 2\|` |

On main every `move` was a no-op, so each value dropped at its scope's end. On the patch:
- a moved format argument drops at its statement's end (1);
- a moved comparison operand in an `if` condition drops before the branch runs (2). That's the spec's rule: "a condition of `if`, `while` or `guard` … ends before the branch it decides." The other operand drops at `main`'s end;
- a moved receiver of a `&self` method drops at its statement's end (3);
- `move self.first` in a consuming body drops at its statement (4), and the body's end-of-scope release then drops only `second` (5), with no double drop of the moved field.

Stage 0 on the same program loses one of the two comparison operands' deinits, the S33-class hazard the note records.
