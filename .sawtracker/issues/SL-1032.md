Requested changes on patch SL-1032.p1 (revision 1) (its test run was cancelled)

**Air: SL-1032.p1, changes requested: three statements sawc contradicts.** I built sawc from 7f0d350e7 + p1 and probed each claim.

1. **"a `for` is over a range" (~10075) is wrong.** The patch drops the parenthetical but keeps the restriction. A `for x in v.iter()` whose body calls `yield_now()` builds and prints 7, and the corpus pins the same span as passing (`coro_for_of_frames_stress.saw`, "pass" in corpus_diff.tsv: a `for value in vector.iter()` across suspensions, output 150). `for x in v` over a bare Vector is refused everywhere ("`for` walks an iterator"), so that isn't a suspension rule either. Suggested text: "…are supported, and a `for` over a range or an iterator spans a suspension like any other loop."
2. **The dropped "or a `join()` after `detach()`, panics" (~10571) is still true.** `Task.spawn(work())`, `t.detach()`, `t.join()` panics (rc 134), and std's own doc comment on `Task.join` says "…or after `detach`, panics". Keep it beside the new `group.spawn` sentence. Aside for a std issue: the panic it gives is "Task.join: this task's result was already joined", which misnames the cause.
3. **"in an `unsafe` function" (~10502) isn't owed.** `try! Box<TaskGroup>.make(TaskGroup())` builds and runs in a plain `func run() -> Int`. Calling an unsafe std function from safe code needs no marker, and nothing here names an unsafe type. Drop the clause.

**The three rulings are written as rules, and the probes agree:**
- **any-suspend:** the conversion is refused (`effect.any-suspends`, a checked block).
- **Reference-parameter closures:**
  - `make(step:) -> (&var Int) -> Void` returning `{ [step] &var d: Int in d += step }` is called after it escapes and prints 16;
  - the escaping-capture refusal is a checked block;
  - `let g: (&Int) -> &Int` is `type.reference-position` ("a function type's return may not name a reference"), as the text says.
- **`ChannelError.System`:** kept. Its std doc comment (std/channel.saw, the case's comment) gives the OS mutex/condvar reason the new doctrine paragraph states.

**Also probed right:**
- a `group.spawn` handle's `detach()` panics with the quoted "Task.detach: this handle came from `group.spawn`, …";
- `x.a?.b?.c = read()` with a suspending `read` builds and prints 42, so dropping it from not-supported is right;
- `yield_now` with no import is `name.not-in-prelude` naming `import std.task.{yield_now}`;
- `close(&self) unsafe` matches std/channel.saw:209;
- std has no `std/compiler/`, so the SL-704 marker is right.

**Nit:** ~10376 and ~10447 now say "unsupported (below) (not built in `sawc` yet, SL-674)" and "Not yet supported (…): a value-producing `break` … (not built in `sawc` yet, SL-674)", two markers on one fact. One is enough.
