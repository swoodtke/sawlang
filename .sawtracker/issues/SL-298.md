## Description

SL-260's rejection corpus found Python sawc accepting a value-returning function with a reachable fallthrough path:

```saw
func f(x: Int32) -> Int32 { if x > 0 { return x } }
func main() { print(f(0)) }
```

Actual: compile succeeds and the uncovered path prints a fabricated 0. Existing fixture prototypes/minivm/examples/reject_missing_return.saw calls f(1), prints 1, and exposes the same incorrect acceptance. Expected: a located missing-return diagnostic; an Int32 result must exist on every continuing path. The prototype correctly rejects the function.

Mechanism: function checking uses a global found_return_with_value fact; any return anywhere can suppress a no-value diagnostic when the block has no tail. That fact is not proof that every reachable path returns. Track control-flow outcomes at joins, preserving valid all-returning branches, divergence and implicit tails; cover if/else, loops, match, methods and nested early returns. This is distinct from the dead-statements-after-unconditional-return over-rejection filed alongside it.
