**E1. Visibility and test-only filters apply per overload, not per name** (SL-606; ranked beside bucket B by the Air in m520, as a soundness hole). Findings: Resolve 1 and 2.

- **Mechanism:** an overload set is bound as (module, name) (`res_decl_binding`, `imports.saw`). Nothing downstream can apply visibility or test-only per declaration:
  - typecheck's `push_functions` expands the binding to every function of that name, private and `@test`-only ones included;
  - `lookup.saw`'s test-only check reads only the newest overload.
- **The bugs:**
  - a `private func pick(x: Bool)` beside a `public func pick(x: Int)` is callable from an importer, both bare and qualified. A private, `unsafe`-reaching helper that relies on its caller's invariants becomes callable from safe user code;
  - ordinary code can call a `@test`-only overload;
  - with the order reversed, an ordinary call is falsely refused as test-only.
- **Fix:** carry per-declaration visibility and test-only through the overload binding, or filter at the one expansion point (`push_functions`/`candidates.saw`), so that every consumer sees only the declarations it may use. One funnel, with its entry points named (obligation 1).
- **Pins:** the review's probes (`review_resolve_testonly*`, `review_resolve_privover/`) as resolve/typecheck fixtures. Each should agree with Stage 0's verdict, or the spec's where Stage 0 errs.
- **Sweep:** every other place an overload set is expanded: method sets, extension members, statics, `init`s.
