## Description

Found by the Air (chat m278, probe_leak15/16/17). In a coroutine (after or before a suspension), a propagating `try` leaks the error in every position except a try nested in a call argument: a `try g()` statement, `let`, `v = try …`, `total += try …`, `return try …` (SL-427's face), inside an if, and `try … catch { return 0 }`. Clean: `add1(try fail(i))`, `return fail(i)`, `match`. Loud twin: an ExplicitCopy error type is refused there ('cannot copy value of type Solo which implements ExplicitCopy'), and the sync form compiles and leaks 0, so the coroutine path copies the error. Frozen compiler: ledgered in SL:hazards S3; the self-hosted compiler is sync-only, so Stage 1 is unaffected.

- **Note:** All nine positions and both orders (before/after suspension) of the issue run; positions were measured as an aggregate under one leaks run (0 total), not individually, but one leak in any would have shown.
