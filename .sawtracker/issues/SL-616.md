**Ruling 1 (the user, Oct 13): packed (module, index) ids, migrated one id kind at a time** (SL-606; the review's M5 and Resolve 10). This unit is the §3.0 amendment and step 1. Steps 2 and 3 are their own epic, SL-617.

**The ruling,** with the user's words:
- "can we have a hybrid model in which we encode the module id in the global id e.g. the top 24 bits are modules id and the bottom 40 bits are index?"
- "can we use a module id == 0 to mean global id? … and incrementally change to per-module ids"
- "yes record it".

The content:
- **§3.0 is amended.** Each id kind (`DeclId`, `NodeId`, `LocalId`, `FuncId`, …) is a typed wrapper over a `UInt64`: 24 bits of module and 40 bits of index within that module's arena. Real modules are numbered from 1.
- **Module 0 means a program-wide index** during the migration. Every id today is already valid as module 0, so nothing changes on day one.
- **Never mix encodings within one id kind.** Two encodings of one entity would compare unequal, and every map, dedupe and identity test would break silently. So a kind migrates all at once, and once it has, a module-0 id of that kind is an `INVARIANT`.
- **"None" is `Id?`, never `-1`.**
- **`TypeId` stays program-wide,** interned and serialized by canonical key. Mono's instantiated items stay program-wide too.
- **Persistence:** a module's own references are its local indices, and a cross-module reference is (module-table entry, index), the module table mapping each entry to (package, module path). Declaration paths are used only in published interfaces, because a persisted index is stable only while its dependency module is unchanged.

**This unit:**
1. **Amend SL:architecture §3.0** to the ruling: the id bullet, the cross-module-reference bullet and the serialization list. Also add a line to `compiler/resolve/README.md` replacing its "Ids are the program's" deviation note.
2. **Step 1, typed wrappers, all module 0.**
   - Introduce the wrapper types in one shared place, and route every arena access through an accessor. There are about 600 direct `.decls[`/`.nodes[`/`.funcs[`/`.items[` sites; count them per stage when you start.
   - Replace each `-1` "none" with `Id?`.
   - Behaviour is identical: each stage's dumps stay byte-identical, which the golden lanes and fixpoint check.
   - It can land stage by stage, with a raw-to-wrapper conversion at each boundary until both sides are done. Split it into sub-units per stage if it's big; the lead reviews the split first.
3. **The guard:** a check that no dump, record or diagnostic prints a raw arena index. Since every id is a typed wrapper after step 1, the check can be a lane over the dump-rendering funnel, or a rule that a wrapper has no `Printable` except through its symbolic renderer.

- **Pins:** the byte-identical dumps are the main evidence; the guard's own fixture; and a unit test of the packing (the module and index round-trip, module 0, the boundary values).
- **Done when:** §3.0 is amended, every id kind is a wrapper, there are no `-1` id sentinels, and the guard runs in `run.py`.

Review of ruling 1, at the user's request (Air): the design is sound. Five more things step 1 must get right, the first with evidence.

1. **The wrappers must WRITE their conformances, or Stage 2 can't build.** sawc2 compiles the compiler for Stage 2, and today it can't compile equality on a wrapper unless the conformance has hand-written bodies. Probe (`.build/scratch/air-review/fable/id_wrapper.saw` on the Air, current Stage 2):
   - `struct DeclIdSynth { raw: UInt64 }` with `@synthesize extension DeclIdSynth: Equatable {}`: `a == b` gives `mono.not-yet … a synthesized Equatable.equals … not in the backend slice yet`, directly AND through `same<T: Equatable>`;
   - an undeclared (automatic) `Equatable`: refused through a generic bound (`which no conformance of it meets`), SL-598's case;
   - hand-written `equals`/`hash` bodies comparing `self.raw`: build and run.

   So each id kind's wrapper declares `Equatable`/`Hashable` (and `Comparable` if ordered maps need it) with written bodies, or SL-598 (plus synthesized bodies) lands first. Otherwise the first generic container or `==` that reaches a wrapper breaks the fixpoint.
2. **No mask literal at or above 2^63 in the compiler's source.** Stage 0 folds constants in the signed domain (CLAUDE.md, the `UInt64` fold note), so a top-bits module mask like `0xFFFF_FF00_0000_0000` is refused by the compiler that builds Stage 1. Decode by shift (`raw >> 40`, `raw & ((1 << 40) - 1)`), which stays in range.
3. **Module numbers must never reach a dump or record either,** not just raw indices. Module numbering is assigned per compilation, so a printed module number would make every golden depend on load order, and adding one module would churn all of them. Extend the guard to cover the module half, and make numbering itself deterministic (sorted by package and module path, or load order if that's already deterministic and documented).
4. **The reverse invariant during the migration:** a NON-zero module on an id of a kind not yet migrated is an INVARIANT too. 'Never mix encodings' needs both directions checked, or a premature producer slips through until its kind's turn.
5. **Overflow is an INVARIANT, not a wrap:** pushing past 2^40 entries in one module's arena, or numbering past 2^24 modules, must fail loudly at allocation. It's cheap, and a wrap there would silently alias two entities.

c2's two points (measure the self-compile and RSS; typed keys in the index structures) stand as accepted.

Correction to my c4 point 2 (Air), which c5 restated as binding. I hadn't probed it; now I have, and the rule is the other way round.
- **A literal at or above 2^63 is fine.** `static MODULE_MASK: UInt64 = 0xFFFF_FF00_0000_0000` compiles under Stage 0 and sawc2, and both print 3 for `(0x0000_0300_0000_0005 & MODULE_MASK) >> 40` (`.build/scratch/air-review/fable/mask_literal.saw`).
- **What Stage 0 refuses is a constant EXPRESSION that crosses 2^63.** `static MODULE_MASK: UInt64 = 0xFF_FFFF << 40` gives `constant expression -1099511627776 does not fit in UInt64` (`mask_expr.saw`). That's the signed fold the saw-lang skill describes: 'code it compiles masks (`~0 & 0xFFFF_FFFF`) or writes the literal'.

So c5's point 2 should read: decode by shift with `(1 << 40) - 1` as before; **no constant expression whose value reaches 2^63** (a shift or `~` into the top bit) in source Stage 0 compiles; and write such a value as a literal if one is needed. Runtime encoding (`(module as UInt64) << 40 | index`) isn't a constant, so it's unaffected either way. Sorry for the noise.
