**Found by:** tcb2b (SL-480 edge 2); the Air classed it as soundness in its SL-490.p1 review. **Area:** typecheck, `conform.saw`'s requirement-against-implementation comparison.

**The defect:** conformance can't see an `escaping` difference between a requirement's parameter and its implementation's. Since SL-480, `escaping` lives on the parameter (`TcParam.escaping`), not in the type, so a type-only comparison misses it.
- **The unsound direction:** the requirement says `func take(g: () -> Int)`, which is non-escaping, and the implementation says `func take(g: () escaping -> Int)`. The implementation may store `g`. A caller through a bound or an `any Trait` checks against the requirement and passes a value it only lent, so the implementation outlives it.
- **The safe direction:** the requirement is `escaping` and the implementation is not. This narrows the contract and stays accepted.

**Fix:** compare parameter escaping-ness in the conformance check. An implementation parameter may be `escaping` only where the requirement's is. Refuse it with a stable rule id at the implementation, naming the requirement.

**Sweep:**
- a trait default body overridden by a conformance;
- a generic requirement's parameter;
- a function-typed parameter nested inside a parameter type (`(() -> Int) -> Void`). That reaches the nested-`escaping` edge, which is SL-480 edge 1;
- `init` requirements, if traits have them.
