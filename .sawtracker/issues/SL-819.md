## Description

**Move `String.to_float` and `StringBuilder.append(value: Float)` into their receivers' modules (SL-722 U5, second patch, after the seed bump).** Per the lead's ruling (SL-722 c50), the public members live in `std/string.saw` and `std/stringbuilder.saw`, as thin calls into `std.float`'s `public(package)` `float_parse`/`float_append`, so that they work without `import std.float`, as `String.to_int` does. Those two modules import `std.float`, and every compiler stage reaches them.

The pinned seed's `load_new_std_modules` has no `float` line, so Stage 1 then fails (`import.unknown-module std.float`; p722u5, Oct 22). That is the two-patch rule (compiler/README.md "The seed", SL-662).

**Sequence:**
1. **U5's first patch (SL-722):** the `float` loader line, `std/float.saw`, numeric's Float half, the Format cell, and the std profile's `fixed-array`. Until this issue lands, `to_float` and `append(value: Float)` stay `std.float` extensions, visible with `import std.float`.
2. **ONE seed bump, in SL-815,** to a main commit holding both SL-788's patch and U5's first patch.
3. **This issue:** move the two members, using p722u5's worktree work (the members, the one-way imports, the free-function helpers). `string_to_float` and `float_text_format` then pass without an import; record the baseline.

Approved patch SL-819.p1 (revision 1)

**Air: SL-819.p1 approved.** Reviewed on origin/main ad82a703c plus r1.

**The move is exact.** Both members' doc comments carry over verbatim, and each body is the one-line call into `float_parse`/`float_append`. `std/float.saw` has NO `import` at all, so the imports really run one way, `string` and `stringbuilder` → `float`. I checked that by reading the source rather than relying on `import.cycle`: SL-831 means the resolver wouldn't report a cycle under the new std.

**Behaviour** (-O0 and -O2 identical):
- `v1`, no import: `"1.5".to_float()` → `1.5`, `"1_000".to_float()` → `None`, `"0.1".to_float()` → `0.1`. `sb.append(value: 2.5)` beside `append(" ")` and `append(7)` → `2.5 7 x`, so a bare `7` still takes the `Int` overload.
- `v2`: a U5-era program that still writes `import std.float` compiles and prints `2.25`.
- `f1`: a `String`/`StringBuilder` program with no `Float` passes `typecheck --freestanding` on this std and on the pre-patch std alike, so pulling `std.float` into every `std.string` user costs the freestanding profile nothing. sawc2 builds no freestanding image yet, so the profile check is what there is to test.

**Records:**
- `hello.ll` moves by line renumbering only.
- The ten Stage 0 records change their source hash, and the two panicking programs' `panic at` lines move up by the dropped import lines (15→11, 13→9). Darwin and aarch64 move together.

**Consumer note, not a defect:** a user's own `extension String { func to_float(&self) -> Float? }` now meets std's member at the call: `call.ambiguous` (`v3`). Before the move it was visible only under `import std.float`. That's the spec's call-site ambiguity, the same as a user `String.to_int`, and it's the cost of the lead's ruling (c50). corpusdiff's 2662 hold, so no tracked program relied on it.

**Gates:**
- `run.py --only subset,std_cone,typechecker,programs` passes.
- `gmgate` and `floatvectors` are green, after the two moves to pass.
