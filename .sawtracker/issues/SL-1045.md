Found by the SL-1044 spec review (F9). The spec ("Function pointers (`FuncPointer<F>`)") says a method with a receiver is no function value, and that a generic type's `static` method is none either. sawc refuses both, but not with the teaching error:

- `let p: FuncPointer<(Int) sync -> Int> = m.g` (an instance method), and the same with `M.g`: `slice.not-yet`: "`syntax.expr.member` is not in the bootstrap slice yet". No named rule says a method with a receiver is no value.
- `let p: (Int) sync -> Int = GM<Int>.h` (a generic type's static): the right `call.generic-value` error, followed by a stray `INVARIANT fp3_gstatic 6:32 a type written in a body has no type`.

Probes: `.build/scratch/p1000n/many/fp3_method.saw`, `fp3_methodtype.saw`, `fp3_gstatic.saw` (checked with `coro --check --no-front-cache`, sawc at main 0cab22184). The free generic, non-sync, signature-mismatch, blocking-extern, capture and suspending cases all give the spec's named refusals.

**Expected:** a named refusal for a method taken as a value, saying why (the receiver) and what to write instead (a closure), and no INVARIANT after `call.generic-value`. The same `syntax.expr.member` slice gap shows in SL-1015 and SL-1038: sweep the member-expression positions that still reach the slice message before fixing one.
