main: `mono.not-yet ... a call of Equatable.equals(other: &Self) on Inner, which no conformance of it meets ... (in the instantiation Wrap<Inner>.equals)`. p1: `INVARIANT mono ...`, with no position.

**Why the matrix missed it.** Its generic-member cells gave `Wrap` a DERIVED conformance (`@synthesize extension Wrap: Equatable {}`), and the reach analysis tried a bounded WRITTEN extension only where the user names the type (`type.bound`). The two were never combined: a written conformance on a bounded extension, as the member of a derived type.

**The mechanism (the Air's, to be confirmed in the code before anything is changed).** Typecheck asks an extension's bound wherever a user names the instance. A derived type's members are left to mono by rule (spec, Equality: "a genuinely non-Equatable member remains a clean error at the comparison site"). **The class (obligation 4).** Every place mono takes a conformance for a concrete instance without asking the declaring extension's bounds:
- by status: `Written`, `Default` (a trait's default body through a bounded extension), `Synthesized` (`@synthesize extension Wrap<T: Equatable>: Equatable {}`, if a derivation may carry a bound: try it), `Implicit`;
- by who asks: a derived type's glue (the Air's eight cells), another written body, a `render_of`/format path, a bound's construction (`resolve_bound_construction`), the copy policies (the Air found the copy sibling refused at the derivation by SL-1018: confirm, and say why it cannot arrive here);
