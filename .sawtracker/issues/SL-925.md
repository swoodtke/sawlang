Raised by the Air during SL-754's review and never filed; surfaced again by p921 (SL-654).

**A `@synthesize` conformance doesn't check that every field meets the derived trait.** `tests/corpus/equatable_field_not_equatable_error.saw`: `struct Inner { name: String }` declares no Equatable; `@synthesize extension Outer: Equatable {}` over an `inner: Inner` field typechecks. The failure surfaces only in mono, as `mono.not-yet` ("a call of `Equatable.equals…` on …, which no conformance of it meets"). The spec (design 32) says deriving requires every field to conform, and that it fails naming the offending field (the program's EXPECT: "does not conform to `Equatable`").

**Obligation 4 sweep:** every `@synthesize`-derivable trait (Equatable, Comparable, Hashable, Copy, ExplicitCopy, Printable if derivable, `shared` twins) over a field (and an enum payload) that lacks it, plus a generic field whose argument lacks it. One check at the derivation, naming the field.

**Why it matters for SL-654:** this is the last route to mono's "a call … which no conformance of it meets" message, which SL-654 wants to reword as an internal INVARIANT once nothing user-reachable gets there. Do that reword here, after this check lands.

Requested changes on patch SL-925.p1 (revision 2) (its test run was cancelled)

**Changes requested (rev 2).** A program a user can write reaches the line, so it is not an invariant yet. By the unit's own step 3 this is the stop.

**The program** (`sl925_p1/p2/j01…` on my side; 25 lines):

```saw
struct Inner { s: String }
struct Wrap<T> { v: T }

extension Wrap<T: Equatable>: Equatable {
    func equals(&self, other: &Wrap<T>) -> Bool { self.v == other.v }
}

struct Holder { x: Wrap<Inner> }

@synthesize
extension Holder: Equatable {}

func main() {
    let a = Holder(x: Wrap(v: Inner(s: "a")))
    let b = Holder(x: Wrap(v: Inner(s: "a")))
    print(a == b)
}
```

| compiler | answer |
|---|---|
| main's `worklist.saw` | `ERROR mono.not-yet …:11:9 a call of Equatable.equals(other: &Self) on Inner, which no conformance of it meets, is not in the backend slice yet (in the instantiation Wrap<Inner>.equals)` |
| this patch | `INVARIANT mono a call of Equatable.equals(other: &Self) on Inner found no conformance, grant or derivation that meets it, which typecheck's bound and derivation checks should have refused earlier`, with no position |

**The mechanism (obligation 4).** The member's conformance is WRITTEN, on an extension with a bound the instance does not meet. Typecheck asks that bound everywhere a user names the type: `Wrap<Inner> == Wrap<Inner>` is `type.bound`, the same in a tuple is `operator.undefined`, `Set<Wrap<Inner>>` is `type.bound`, formatting it is `format.argument` (all four run). A derived type's members are left to mono by rule, and there `resolve_requirement` takes the conformance by its type declaration (`one.type_decl == d`, status `Written`) without asking the extension's bound for this instance. So `refuse_unmet_member` is never asked about `Wrap<Inner>`; the written `equals` is instantiated at `T = Inner`, and its own `self.v == other.v` asks `equals` of `Inner` from a function that is no glue, which is the fall-through.

**Every cell of it I tried reaches the line** (patched stage 2, each alone):

| the derived type's member | trait | reached by | answer |
|---|---|---|---|
| a field `Wrap<Inner>` | Equatable | `==` | INVARIANT |
| the same | Equatable | a generic `<T: Equatable>` | INVARIANT |
| a field `Wrap<Inner>?`, both values `None` | Equatable | `==` | INVARIANT |
| a field `(Wrap<Inner>, Int)` | Equatable | `==` | INVARIANT |
| a field `Wrap<Wrap<Inner>>` | Equatable | `==` | INVARIANT |
| an enum case's payload `Wrap<Inner>`, comparing two payload-less cases | Equatable | `==` | INVARIANT |
| a field `Wrap<Inner>` | Hashable | a `Set` insert | INVARIANT |
| a field `Wrap<Inner>` | Comparable | `<` | INVARIANT |
| the same field with `Wrap<Int>` (the bound met) | Equatable | `==` | runs, `true` |
| a field `Wrap<Res>` under a derived `ExplicitCopy`, `Res` NoCopy | the copy policy | `.copy()` | `synthesize.member` at the derivation, naming the field: right |

So the copy policies are closed where SL-1018 put them, and the three comparison traits are open through this route. What the answer should be is the one the neighbours give: `synthesize.unmet-member`, naming `Holder`'s field `x` of type `Wrap<Inner>`, and it would help to say that `Wrap`'s `Equatable` is declared where `T: Equatable`.

**What did not reach it** (60 other one-route programs, none printed the old text or an INVARIANT): a tuple, an optional and a fixed array of a non-conforming type compared directly and through a bound (`operator.undefined`, `type.bound`); `<` on a tuple, an optional or a struct that is Equatable without a conformance; `Set` and `Map` over tuples, optionals, arrays and trivial structs holding `Float` or `Bool` (they run); a tuple, optional or array over a derived type whose member fails (`synthesize.unmet-member`, naming the field); distinct aliases of `Int` and of a tuple as members and as type arguments (they run); `copy()` through an `ExplicitCopy` bound on tuples, optionals and a `Result`. The two new fixtures pass, and so does what `refuse_unmet_member` already covered.

**For the revision:** the check belongs wherever you place it (mono asking the extension's bound before it takes a written conformance looks like the natural seat, since that is the question `refuse_unmet_member` exists to answer), then these eight cells as fixtures, then the invariant.
