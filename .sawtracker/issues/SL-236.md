## Description

The Python compiler accepts the valid source below, but the resulting executable crashes instead of printing `false`. Binding the cloned token to a named local before inspecting its String field makes the control program run correctly.

Freshly reproduced on local main `30c5a55016aed806a2f94a64d62224c6cafc135a`, arm64 macOS, default compiler optimization. It also reproduces with the prototype bootstrap compiler (last sawc change `d592e716d562990656b98ced5a391b7d3d282246`). No production source changes were needed to reproduce.

```saw
enum Kind { case Ident, case Number, case Let, case Var, case Return, case While, case Brace }
struct Tok { kind: Kind, value: String, line: Int, col: Int, suffix: String? }
func clone(t: &Tok) -> Tok {
    Tok(kind: t.kind, value: t.value, line: t.line, col: t.col, suffix: t.suffix)
}
struct Reader { tokens: Vector<Tok>, pos: Int }
extension Reader: NoCopy {}
extension Reader {
    func token(&self) -> Tok { clone(&self.tokens[self.pos]) }
    func at(&self, k: Kind) -> Bool { self.token().kind == k }
    func classify(&self) -> Bool {
        if self.at(Kind.Let) || self.at(Kind.Var) || self.at(Kind.Return) || self.at(Kind.While) || self.at(Kind.Brace) { return true }
        if self.at(Kind.Ident) && self.token().value == "print" { return true }
        false
    }
}
func main() {
    var tokens = Vector<Tok>()
    try! tokens.push(Tok(kind: Kind.Number, value: "42", line: 1, col: 1, suffix: None))
    let reader = Reader(tokens: move tokens, pos: 0)
    print(reader.classify())
}
```

Save as `.build/scratch/token_cleanup.saw`, compile with `.venv/bin/python sawc/sawc.py .build/scratch/token_cleanup.saw -o .build/scratch/token_cleanup`, and run the executable.

Expected: stdout `false\n`, exit 0. The token is Number, so the second condition's String-field operand must not be evaluated.

Actual: compilation succeeds; the executable emits no stdout and terminates with SIGBUS (shell status 138). The larger self-hosted compiler reproductions also showed SIGSEGV on a rejected-expression path. Crash reports put those larger failures in generated String cleanup. The standalone failure and named-local control are confirmed; the exact incorrect cleanup scheduling/ownership mechanism still needs diagnosis.

Passing control: replace the second condition with:

```saw
let t = self.token()
if t.kind == Kind.Ident && t.value == "print" { return true }
```

That separately compiled control prints `false` and exits 0 on the same main checkout. Local evidence lives in `/Users/swoodtke/Projects/sawlang-minivm/.build/scratch/m5_token_cleanup.saw` and `m5_token_cleanup_named.saw`; the complete failing source above makes the report portable.

This was found during the Saw-written compiler prototype's independent tests. Its statement classifiers now use named Token locals. That source restructuring does not fix Python sawc; this issue records the underlying bootstrap failure separately. Related temporary-payload ownership work exists in SL-220, but that report describes leaking fresh Optional/Result payloads, while this is an ordinary struct field on a short-circuit path with an observed crash.

Acceptance: make the exact inline source run correctly; cover both condition outcomes and repeated calls; check temporary owning-field cleanup in &&/|| and diagnostic/early-return paths. Keep the named-local control as a semantic comparison, not as the production fix.
