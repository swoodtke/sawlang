## Description

**A statement-form `borrow` reaching a field of a call's NoCopy result trips a MIR invariant instead of the clean refusal** (found by p838, SL-838, Oct 23; it predates SL-838, reproduced with the pre-fix compiler).

`let tag = join(borrow h.get().make().tag, loud("c"))`, where `make()` returns a NoCopy `Token` with a written `deinit`, gives `INVARIANT` in `sawc2 mir`: "local _40 is dropped whole after a part of it moved out: a destructure does not dissolve it". The same read without `borrow` (`make().tag`) is the clean refusal `slice.not-yet` ("a consuming destructure of a type that writes its own `deinit`").

**Mechanism (UNVERIFIED):** the statement-form `borrow` path (`prepare_borrow` / `prepare_as`) doesn't reach the check that produces the plain path's refusal.

**Obligation 4:** every way a field of a fresh NoCopy-with-deinit value can be read: through `borrow`, a method chain, `??`, a `match` scrutinee, an interpolation segment. Find the plain path's refusal site, route the borrow path through it (one funnel), and pin each cell as the clean refusal.

An INVARIANT is a compiler bug the user would see as an internal error.
