## Description

**About 35 run-lane probes and corpus programs order their output by timers, or pass only within a measured time margin, so load can change their verdict.** Found by SL-975's sweep (`.build/scratch/p975/`: `stall_sweep1.log`, `probe_stall.py`, `stall_list.txt`). SL-975 itself fixes K90 and the deadline-poll and sleep-then-read programs. These need a redesign.

**Groups** (frozen-run evidence: runs stopped and resumed at random moments, 16 tries each):
- **Order set by timers:**
  - `taskgroup_sleep_ordering` (5 of 16 failed frozen);
  - 24 of the 31 `join_inversion_*` probes (1–5 of 16);
  - the ten `running_task_dump_*_drive` probes (a 300 ms hold).

  When two timers expire together, slots resume in slot order, not deadline order.
- **Measured margins in the passing path:**
  - `offload_cancelled_during/before_the_call_parks` and `pool_teardown_drives_while_a_worker_ends` (at least 10 ticks in 200 ms; 10–11 of 16 failed);
  - `background_close_parks_over_an_offload` (14 of 16);
  - `offload_parked_task_defers_the_deadlock_report` (3 of 16);
  - `process_output_cancel_ends_its_drain` (4 of 16) and `process_output_cancel_reaps_child` (2 of 16);
  - `thread_receive_both_contexts`, `thread_join_both_contexts` and `pool_waits_in_a_task_run_siblings`;
  - `thread_receive_gate_allocation_refused`, `background_close_waits_on_a_join` and `offload_seam_first_tick`;
  - `process_run_concurrent`, `process_output_concurrent` and `process_cancel_during_child`;
  - the `quick<1000` checks in `borrows_body_suspends_*`, `consumes_suspending_cancel_and_unjoined` and `init_suspends`;
  - `process_output_waits_for_no_other_child`, `taskgroup_cancel_during_sleep`, `task_backtrace_panic/churn/nest` and `prelude_import_makes_visible`.

**Direction:** each program states what it pins without depending on the machine's speed.
- **Order:** set it with explicit gates (a channel or atomic the earlier step signals), not timer lengths.
- **"Something ran while X waited":** prove it by an event the sibling causes, not a tick count in a time window.
- **Waits:** use TESTING.md rule 3 (a generous deadline, then a panic).

Some offloaded calls can only end on a condition through a C helper in `probes/`, for example a blocking `read` on a pipe the sibling writes. Whether to allow one is a question for the user. Pin each fixed program as SL-975 does: 200 runs at a 1-minute load above 20, every run giving its stated output.

**Ruled (user, Nov 5): no C helper by default.** A condition-based offload probe uses libc declared directly from Saw: `pipe`, `read` and `write` as `extern` functions, with the blocking one declared `extern blocking`, as `thread_spawn_refused.saw` already does. For example, the offloaded call does a blocking `read` on a pipe, and the sibling task writes one byte once its work is done.

A new `.c` file in `probes/` needs the user's ruling, case by case, and only when a case can't be expressed with libc externs. Name the case and the missing primitive.

**SL-977.p1: unit 1, the timer-ordered programs**

- **`join_inversion_*` (all 32):** two atomics, `ARRIVED` and `RELEASED`, set the order. `leaf` sets `ARRIVED` and waits for `RELEASED`, `main` polls `ARRIVED`, and `main` sets `RELEASED` just before the step under test. Each wait follows TESTING.md rule 3: a 10 s deadline ending in a panic that names what never arrived.
- **`running_task_dump_*_drive` (10):** the thread holds until `RELEASED` instead of sleeping 300 ms. The edits replace lines one for one, so every pinned dump line number holds.
  - **Found while doing it:** the deadlock walk reports only once the thread has ended, so the four deadlock probes set `RELEASED` just before their last join.
- **`taskgroup_sleep_ordering`:** its point is timer order, so it keeps timers, spaced far apart (20 s against 10 ms). `main` joins the short one and cancels the long one, which panics if it ever runs to the end.
- **Unchanged:** every `// prints:`, `// panics:` and EXPECT line. No `.c` file (the ruling).
- **Pins** (85 binaries, the probes at -O0 and -O2):
  - 200 frozen runs each: 0 failures;
  - 200 loaded runs at a 1-minute load of 20–29: 0 failures;
  - a second loaded round at 36–37: 0 failures;
  - the original `taskgroup_sleep_ordering` fails 6 of 48 under the same harness.
- **corpusdiff:** one row moved, `taskgroup_sleep_ordering`, now a pass judged by its own directives.
- **Gates:** `run.py --only programs`: ok; corpusdiff: 2,675 programs hold.

**Unit 2:** the measured-margin group, plus `compiler/tests/run/task_sleep_ordering.saw`, the `Task.spawn` twin with the same 10/30 ms timers.
