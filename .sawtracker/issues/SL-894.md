## Description

**Found porting sawtracker to v0.18.0 (ST-97), at 4ab60f12c.** `sawc build` emits no debug info at any `-O` level, and offers no flag that asks for it.

**Expected:** the binary carries DWARF, or a debug map naming an object that does, as Stage 0 builds did. Then `dsymutil` writes a usable `.dSYM`, and lldb/atos can symbolize a crash or a hang with file:line.

**Actual:**
- `dsymutil` prints "warning: no debug symbols in executable (-arch arm64)" and the `.dSYM` is empty.
- sawc leaves `NAME.ll` beside the binary, but no `NAME.o`.
- `sawc` usage lists no `-g`.

**Impact on sawtracker:** ST-52 keeps a `.dSYM` beside every production binary, for symbolizing a hang or crash in the server. Under sawc2 that bundle is empty, so a production incident loses file:line symbols. The switch (ST-97) can proceed without it, but we would like `-g` (or default line tables) before long.

**Reproducer** (build with `bin/sawc build no_debug_info.saw -o no_debug_info`, then run `dsymutil no_debug_info`):
```saw
// sawc 0.18.0 (4ab60f12c): `sawc build` emits no debug info, and has no flag
// that asks for it.
//
// Build: bin/sawc build no_debug_info.saw -o no_debug_info (any -O level), then
// `dsymutil no_debug_info -o no_debug_info.dSYM` on macOS.
// Expected: the binary carries DWARF (or a debug map naming an object that
// does), as Stage 0's builds did, so dsymutil writes a usable .dSYM and lldb /
// atos can symbolize a crash or a hang with file:line.
// Actual: dsymutil prints "warning: no debug symbols in executable (-arch
// arm64)" and the .dSYM is empty; sawc leaves NAME.ll beside the binary but no
// NAME.o, and `sawc --help` lists no -g or equivalent. Sawtracker's ST-52
// (a .dSYM beside every production binary) gets an empty bundle under sawc2.
func crash(n: Int) -> Int {
    if n > 2 { panic("crash at depth {}", n) }
    crash(n + 1) + 1
}

func main() {
    print("{}", crash(0))
}
```
