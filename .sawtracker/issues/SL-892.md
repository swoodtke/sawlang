**RULED (the user, Oct 25): a `main` whose exit value is outside 0...255 PANICS.** That covers `-> Int` and `Result<Int, E>`'s `Ok`.
- **Found by the Air** (SL-874.p1 verdict c8, chat m594). Today the platform keeps the low 8 bits, so `Ok(256)` exits 0 (reads as success), `Ok(300)` exits 44, and `Ok(-1)` exits 255. The spec states the narrowing ("Saw passes the value to the C entry unchanged and the platform does the narrowing"); the ruling replaces that.
- **The rule:** the entry point checks the value before the exit, and outside 0...255 is a panic naming it (`panic at FILE:LINE: …` on stderr, exit 134). FILE:LINE should be `main`'s return; say what the backend can name. The check lives in SL-874's `main_status` funnel, the ONE place the exit value is computed (sync and frame paths both).
- **The pins:**
  - run probes for 0, 255, 256, 300, -1 and `Int.max`, for `-> Int` and `Result<Int, E>`, in sync and suspending `main`, at -O0/-O2;
  - the spec's entry-point paragraph rewritten (the table's 'the value' and the narrowing paragraph);
  - a conformance row (an exit status never collides with success);
  - the corpus checked for any program returning a value outside the range.
