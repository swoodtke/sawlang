**SL-718.p1: Env and File in the new std, summary for review.**

- **Env:**
  - `argument_count()` is now public, and `argument(index:) -> String?` returns `None` out of range. Lead ruling: the no-abbreviations doctrine applies, so these replace Stage 0's `argc`/`arg`; the spec names only `Env.args`. The old package-private panicking `argument` is folded in, and `args()` behaves the same for every input.
  - Also `get`, `contains`, `set(name:value:overwrite:)` and `unset`, which return `Result<Void, SystemError>`.
  - Text holding a NUL byte is refused before it reaches C: `InvalidArgument` from `set`/`unset`, `None`/`false` from `get`/`contains`.
  - `cwd`/`set_cwd` wait on Path (SL-720).
- **File:** `OpenMode.Append` and `open_append`, `seek_start`/`seek_current`/`seek_end` and `position` (one `sought` helper over lseek), `exists`, `remove` and `rename(from_path:to_path:)`. These keep Stage 0's names, which are words the corpus uses. Every `__saw_rt_*` seam is in runtime/ABI.md, and `getenv`/`access` are bare libc, as in Stage 0.
- **Pins:** `env_variables`, `file_path_ops` and `file_append_seek` match Stage 0 at -O0 and -O2. The argument accessors have no Stage 0-matched pin, because Stage 0 can't build the new names; `program_arguments` covers `args()`.
- **Corpusdiff:** `env_error_surfaced`, `env_simple` and `file_error_surfaced` move to pass. `link_dead_strip` stays refused at Stage 0's `Env.arg`, as ruled.
- **Gate (Sonnet, after the rebase onto main with SL-716):** `run.py --only resolver,typechecker,std,programs,coro` ok, `corpusdiff gate` ok (all 2661), citations green.
- **Lead follow-up commit (idiom only):** the two identical NUL-scan helpers (`env_holds_nul`, `file_holds_nul`) became `text.index_of(0).is_some()`, on SL-717's `index_of`, and one stray blank line went. The three pins rebuilt against the edited std still match their Stage 0 records; the server's gate covers the rest.
- **Filed separately (a ruling):** `Env.set`/`unset` race `getenv` across threads in libc. That's undefined behaviour reachable from safe code once an MT TaskGroup exists, and Stage 0 has the same API.

Approved patch SL-718.p1 (revision 1)

**Air: SL-718.p1 r1 approved; arming it.** Env's six members and File's nine are Stage 0's bodies over the same seams (`__saw_rt_env_set`/`_unset`, `__saw_rt_fs_unlink`/`_rename`, bare `getenv`/`access`, all in runtime/ABI.md; mode 2 is `O_WRONLY|O_CREAT|O_APPEND` in `shim.c`), with `SystemError`, the `argument`/`argument_count` names (Stage 0's `arg` already answers `None` out of range, so only the name moved), and one improvement Stage 0 lacked: text holding a NUL byte never reaches C. Stage 0 hands the String's bytes to `setenv`/`getenv`, which read to the first NUL, so `Env.set("A\0B", "x")` silently set `A` and `Env.get("A\0B")` found it; the patch refuses the set as `InvalidArgument` and answers `None`/`false` on the reads. That is the honest answer, since no environment entry can hold the byte.

Checked on a build of origin/main (d2446cfc0, the base) plus the diff:
- the run lane: 162 programs matching Stage 0, the three new pins among them; re-recording the three with `run_lane.py --stage0` left the records byte-identical;
- `run.py --only std` ok; the corpusdiff gate (`--no-build`): all 2661 hold, the three moves to pass as listed;
- my probe (`air-review/sl718/probe_env_file.saw`, run in its own directory on Stage 0 and on the patch's sawc2 at -O0 and -O2): a name holding `=` (`err` on all three), `overwrite: false`, get after unset, an appending write after `seek_start(0)` landing at the end with `position()` 4, `seek_current` before the start refused with the position unmoved, `seek_end(-4)` then a 4-byte read, `rename` replacing an existing 2-byte file with a 4-byte one, `exists(".")` true and `remove(".")` `err`, a NUL in a path refused by `remove`/`rename` and `false` from `exists`, and `open_append` in a missing directory surfaced: 30 lines, identical across the three builds except the six NUL-in-env lines above, where Stage 0's answers are the truncation;
