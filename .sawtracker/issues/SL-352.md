## Description

Found Sep 23 by agent:claude-sl318u3f writing a control for examples/borrowing_producer_every_path.saw: `{ n in n + 1 }(2) + 1` (an immediately-invoked closure literal as a binary operand) does not parse/apply as a call, while binding the closure to a `let` and calling it does. Design 122 blessed `{ ... }()` in STATEMENT position; the operand position was never enumerated. Pre-existing on main. Mechanism to name before fixing (obligation 4): the postfix-call parse after a closure literal is accepted at statement start but the expression parser's operand path does not offer it — enumerate every operand position (binary operand, argument, receiver, interpolation) and pin each.
