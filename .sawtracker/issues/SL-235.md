## Description

The Python compiler accepts a value-producing if whose continuing else branch supplies no value, and the resulting executable returns an invented zero.

Freshly reproduced on local main `30c5a55016aed806a2f94a64d62224c6cafc135a` on arm64 macOS, using the repository Python environment. Also observed in the prototype bootstrap base (last sawc change `d592e716d562990656b98ced5a391b7d3d282246`).

Minimal source:

```saw
func choose(flag: Bool) -> Int {
    if flag { 1 } else { let x = 2 }
}
func main() { print("{}", choose(false)) }
```

Reproduction: save as `.build/scratch/missing_value_tail.saw`, run `.venv/bin/python sawc/sawc.py .build/scratch/missing_value_tail.saw -o .build/scratch/missing_value_tail`, then run the executable.

Expected: a located compile-time error because the reachable else branch cannot supply the required Int. An explicit return in that arm would be valid because it exits the function; a declaration alone does not.

Actual: compilation succeeds, execution exits 0 and prints `0`.

This was found while independently checking value-control semantics for the Saw-written compiler prototype. The prototype now explicitly rejects the missing-value case; no production fix is included here. The confirmed finding is acceptance and fabricated output; the exact checker/lowering mechanism still needs diagnosis.

Acceptance: reject this source with a located diagnostic; audit equivalent if/match block arms and declared/assigned/argument result contexts; retain valid mixed early-return/value arms and fully returning branches. Add a small regression test with the intended compile error.
