## Description

Found by SL-640/SL-629's sweep (agent t640testonly). Not a test-only defect: no conformance is involved at all.

**Mechanism (probable, from reading the order):** typecheck records a type argument's bound as an obligation (`oblige`, `compiler/typecheck/src/signatures.saw`, from `apply_nominal`) and checks the whole list once, in `check_obligations` (`compiler/typecheck/src/tier.saw`), which `typecheck_program` (`api.saw`) runs *before* `tc_check_bodies`. A type written inside a body is built during the body pass, so its obligation is pushed after the only reader has run and is never checked. A signature's types are built before, so they are checked (`func peek(h: &Holder<Money>)` is refused `type.bound`); an inferred argument goes through `settle_solutions`, which checks its own bounds.

**Evidence** (`sawc2 typecheck --check --std-root std`, main at 65d3aba8b): rc=0, and `sawc2 build` runs it, printing `1 0`. Stage 0 refuses it: "type argument `Money` does not satisfy bound `T: Equatable` on struct `Holder`" at 18:28.

```saw
struct Money {
    cents: Int
    tag: String
}

struct Holder<T: Equatable> {
    t: T
}

extension Holder {
    static func empty_count() -> Int {
        0
    }
}

func main() {
    let m = Money(cents: 1, tag: "a")
    let h: Holder<Money> = Holder<Money>(t: move m)
    print("{} {}", h.t.cents, Holder<Money>.empty_count())
}
```

**Positions to sweep:** every type written in a body: a `let`/`var` annotation, an explicit construction `Holder<Money>(...)`, a static call's head `Holder<Money>.f()`, a closure's parameter and result types, a cast's target, a nested generic argument (`Vector<Holder<Money>>`), a default value's type, a test case's body, and a generic function's explicit arguments (`same<Money>(...)`, which is refused today, so the explicit-call path checks its own).

**Fix shape:** check a body's obligations once the body pass has recorded them (a second `check_obligations` over the ones pushed since, or checking at `oblige` when the conformance table is settled), one funnel either way. SL-640/SL-629's patch adds `test` to `TcObligation`, so a body's obligation is answered with the right viewer once it is checked.

**Severity is soundness (raise to high):**
- a `Copy`-bounded generic given a NoCopy value with a `deinit` copies it bitwise and runs the deinit THREE times for one value, at exit 0 (`i04`, `i07`), which is a double free with a heap payload;

**Mechanism (three causes):**
1. `oblige` records obligations, but `check_obligations` (tier.saw) runs ONCE, before `tc_check_bodies`, so a body's obligations are never read.
2. `named_owner` (call heads: `init_call`, `static_call`, `written_enum_owner`) records no bound.
3. `defaulted` (Set/Map literals) records no bound.

**Wrongly accepted:** a `let` annotation, a cast target, a closure parameter, nested arguments, function types, `sizeof<…>`, `@test` bodies, explicit constructors, a static through a generic type, an enum case head, `Set<Plain>()`, set and map literals, a primitive lacking a user trait; for every bound kind (a trait, a trait with an associated type, `Copy`, `Send`, `Sync`).
