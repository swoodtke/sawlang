**U7a design (u7skel).** Implementation follows without waiting; the Air reviews this with the patch.

## 1. Mono (`compiler/mono`, package `sawmono`)
- **Input.** The `DropsProgram`, moved in whole: every module's drop-elaborated MIR, std's included under `--std-root std`. Statics' values come from `saweval`. `EvalProgram` owns its `MirProgram` and nothing hands it back, so `build` lowers the program twice: once for the evaluator and once for the borrowck → drops → mono chain. Both lowerings are pure functions of the same input, and the values cross keyed by declaration. A lowering takes about 20 ms. An evaluator that borrows MIR would retire the second lowering, and I'll file that.
- **Output.** Concrete MIR functions *appended* to the same arenas. No existing function is edited, and the generic ones stay as they were. Side tables, keyed by the new functions' ids, record each call's resolved item and each drop's or copy's glue item. Because the concrete functions are ordinary MIR, the MIR dumper prints them, and every backend reads one representation.
- **Item identity.** (kind, source MIR function, canonical concrete arguments).
  - For a function, the arguments are the receiver type's arguments (`Self` for a trait default body) followed by the function's own type arguments.
  - Typecheck interns every type by canonical form with defaults filled (SL-382), so identity is TypeId equality.
  - A closure, a default value's function and an accessor's halves are items under their parent's substitution.
  - Glue items are (drop or copy, concrete type).
- **Roots, in this order.**
  - the entry module's `main`;
  - the lang functions the backend's own lowering calls: the panic sink (every check ends there), `string_literal` and `string_length`.
  - `@export` (`has_attribute`) is refused as `mono.not-yet` in this slice. Nothing reached declares one.
- **Order.** FIFO over discovery. Within an item, blocks are visited in order, then statements and terminators in order. There is no hash-order iteration anywhere.
- **Substitution.** Typecheck's `subst`: the owner declaration's parameters take the receiver's arguments, the function's own parameters take `inst`, and `SelfType` takes the receiver. Projections resolve through `project` once their base is concrete.
- **Trait calls become direct calls.** A call whose target is a requirement, with a concrete owner, goes through the conformance table:
  - `Written`: the member;
  - `Default`: the requirement's default body, with `Self` set to the owner;
  - anything else (`Synthesized`, `Implicit`, or no conformance): refused as `mono.not-yet`, located.
- **Glue.** One funnel, `glue_of(t)`, makes one synthesized concrete MIR function per type. Its entry points are drop statements, copy operands and glue bodies.
  - **Drop glue** follows drops' resolution (`deinit_member`): the `deinit` call, then the owning fields in reverse declaration order, or an enum's active payload by switch, or a tuple's elements.
  - **Copy glue** runs only for a `copy` of a type that is not trivially copyable, read from typecheck's tier (`copies_silently`, `is_trivial`): the written `copy()` when there is one, else a memberwise rebuild.
  - Concrete MIR already spells `String.copy()` as a call, so copy glue only appears where a generic body's `copy` lands on such a type.
- **Builtins** stay `call builtin` with concrete types. Mono checks each against the backend's slice: `print`, `panic` and `assert` with a format of integer, `Bool` and `String` arguments; `sizeof`, `alignof`; the four `__saw_atomic_*`. Anything else is refused.
- **Budget points.** Spawn isn't lowered, so no task root exists, and mono marks every budget point inert. A later coroutine lowering decides which stay live (§3.9). The backend emits nothing for an inert point and refuses a live one.
- **Polymorphic recursion.** No pre-mono check exists, so I'll file it (§3.8's ruling). Mono's backstop: a concrete type nested deeper than 64 is refused as `mono.depth`, naming that issue, so mono never loops.
- **Dump and lane.** `sawc2 mono --dump FILE`: per item, `item #K <kind> <name> [owner T] [inst ...]`, the concrete function in MIR dump form, then a `calls` table mapping each call terminator to its item. Goldens live in `compiler/tests/mono/`.

## 2. Target (`compiler/target`, package `sawtarget`)
- **Targets.** `arm64-apple-darwin` (the default) and `x86_64-unknown-linux-gnu`. Both are LP64, and they differ only in the C ABI for aggregates, which the slice refuses in extern signatures.
- **One layout per concrete type:** size, alignment and class (`Zero`, `Int(bits)`, `Float64`, `Pointer`, `Memory`), plus field and element offsets, the enum tag's width and offset, each case's payload offsets, and the tag value of each case.
- **The rules match Stage 0's, by `sizeof`/`alignof` probe:**
  - primitives are natural size, `Bool` is 1 byte, and references and raw pointers are 8;
  - structs and tuples use C declaration-order layout;
  - `Optional<T>` is a 1-byte flag, then `T` at its alignment. `Some` is 1 and `None` is 0, Stage 0's `{i1, T}`;
  - every other enum, `Result` included, is an i32 tag at 0, then the payloads overlaid at the largest payload alignment;
  - a closure value is `{code, env}`, 16 and 8.
- **C calling convention for externs.**
  - Scalars and pointers pass directly.
  - An extern returning `UnsafePointer<T>?` returns a nullable pointer, and null is `None` (Stage 0's rule; `__saw_rt_alloc` relies on it).
  - An aggregate by value is refused.
- **Goldens.** `sawc2 mono --layouts FILE` prints the layout table of every concrete type the items reach. A lane check builds a Stage 0 probe that prints `sizeof` and `alignof` for each source-expressible type in those goldens, and fails on a size or alignment difference.

## 3. Backend (`compiler/llvm`, package `sawllvm`)
- **Shape.** Textual `.ll` with opaque pointers, one function per item, one `alloca` per local (`[N x i8]` for `Memory`).
  - Places become `getelementptr i8` at target offsets.
  - Terminators map 1:1, and a switch on a discriminant compares the tag values the target gives.
  - The internal convention passes scalars by value and aggregates by pointer (the callee copies), and returns an aggregate through an sret pointer.
- **Checks.** These use the `llvm.{s,u}{add,sub,mul}.with.overflow` intrinsics, plus zero, `MIN/-1` and shift-range tests and the forced-payload tag test. Each branches to a block that calls the panic sink item with a static message `panic at FILE:LINE: <reason>\n`, using Stage 0's reason texts (design 122). Mono supplies the location of each statement's node.
- **Strings.** A literal is a private constant in the String layer's literal block (`{-1, len, bytes, NUL}`), wrapped through the `string_literal` item. A literal message's bytes go straight to `__saw_rt_write`.
- **Print and panic.** A computed String's bytes and length come from `string_bytes` and the new `string_length` (ruled in chat m448). Format arguments render through two synthesized internal helpers, of the `__saw_print_int` kind that ABI.md sanctions. `print` writes piece by piece through `__saw_rt_write`, and `panic` renders into stack scratch and calls the panic sink.
- **Statics** are globals initialized from the evaluator's values. **Atomics** are `load atomic`, `atomicrmw` and `fence`.
- **Determinism.** Functions are emitted in item order and globals in first-use order. Every symbol is derived from what the code is, as the quoted item name (`@"p1.pick(a: T, b: T, first: Bool) inst p1.Point"`). There is no hashing.
- **The backend decides nothing.** Every choice it consumes is already in the concrete MIR or mono's side tables.

## 4. Runtime linkage
- **The binary spawns nothing (§4).** `.build/sawc2 build FILE -o OUT [--std-root D] [--target T] [-O0|-O1|-O2|-Os|-Oz]` writes `OUT.ll` plus a link manifest `OUT.link` (`ir`, `target`, `speed`, `runtime hosted`, `output`), and exits 1 on any refusal.
- **The script.** `compiler/driver/sawc2` (tracked shell) dispatches `build` to the binary, then runs `compiler/tools/runtime_objects.py`. That script calls Stage 0's `rt_build.build_runtime` at llvmlite's default triple, so it returns the very `.build/rt/<key>/` objects a Stage 0 build links, building them under Stage 0's flock on first use. Every other subcommand execs the binary.
- **clang** is `$CLANG`, else `clang` on `PATH`: `clang SPEED -x ir OUT.ll RTOBJS -o OUT`.
- **Optimisation level.** One driver funnel maps the flag to the manifest's `speed` (the design 265 shape). `-O0` is the default.

## 5. Entry and program shape
- **Entry.** The emitted C `main(i32, ptr)` stores argc and argv in `__saw_argc` and `__saw_argv`, and defines `__saw_rt_get_argc` and `__saw_rt_get_argv` (ABI.md: "the compiler emits both accessors, and the globals, into every program"). It then calls the Saw `main` item.
- **Exit code.** `-> Void` exits 0, and `-> Int` exits with the value truncated to i32. A `Result` main is refused for now.
- **Program shape.** Whole program only: one `.ll` per build.

Requested changes on patch SL-505.p1 (revision 1)

Requesting changes on SL-505.p1 (U7a). The skeleton holds up structurally:
- mono, the target funnel, glue, determinism and the refusal discipline all hold;
- the 26 lane programs match;
- two probe sweeps (about 60 programs, plus 110 panic, 146 cast and 486 `from` probes) found no undefined behaviour between -O0 and -O2, no invalid IR, and no nondeterministic `.ll`.

But sawc2 now builds binaries that are silently wrong for ordinary programs, which breaks the brief's one hard rule. Four changes are needed. The first one's cause is in MIR, which predates this patch, and this backend is the first stage to run it. Every repro is in chat file f22 (m454).

**Required**

1. **A store through a raw-pointer slot drops the slot's old contents.** The spec calls `ptr[i] = move v` a placement into storage that holds no value (Unsafe surface; "a pointer place tracks no occupancy"), and the new std relies on that (`std/vector.saw`, `std/box.saw` say so).
   - **The mechanism:** `compiler/mir/src/lower.saw` `lower_assign` emits `emit_drop(p)` before every write to an owning target, a raw-pointer index included. Main's sawc2 already has the same drops.
   - **Census** (`census.saw`, `drops --dump`): four sites in the std this reaches, each `drop(P[i])` with `P: UnsafePointer<T>`: `Box.make` (`drop(_12[_14]); _12[_14] = move _1`), `Vector.push`, `Vector.set`, and `Optional.take_payload`. The last two are a double drop, because the slot was just moved out (`_5 = move _2[_6]; drop(_2[_7])`).
   - **What the binaries do:**
     - `Box<Noisy>.make` and `Vector<Noisy>.push` run `deinit` on garbage (`drop 0`).
     - `Vector.set` drops the old element twice.
     - `Optional<String>.take()` prints garbage, then panics with a String refcount underflow at -O0, and prints garbage and exits 0 at -O2.
     - `Vector<String>` with a few pushes segfaults (exit 139). Stage 0 prints `abc a 4`.
   - **The fix:** in MIR, a whole-slot write through a raw-pointer index or `*p` doesn't drop. Settle from the spec whether a field write through a pointer (`p[i].f = v`) does, and keep the drop for `arr[i] = v` on a fixed array, which is tracked storage. File it as an issue (it's an earlier-stage defect, per the brief). Either land it ahead of U7a, or carry it here as a named MIR edit.
   - **Pin it in the run lane** with owning element types: `Vector<String>` push and set, `Box<Noisy>`, `Optional<String>.take()`. Today every run-lane Vector is `Vector<Int>`, which is why the lane missed this.
2. **String comparisons compare the operands' addresses.** For `a == c`, where `c` is a copy of `a`, sawc2 prints `false`. `c6_streq.saw`: sawc2 prints `false true false false`, Stage 0 prints `true false true true`. Ordering is wrong too (`c8_strcmp.saw`).
   - MIR spells a String comparison as `Eq` over two `&String` operands. `compiler/llvm/src/ops.saw` accepts any pointer-layout operand and emits `icmp eq ptr` on the references, which are the addresses of the two locals. That's what the `.ll` shows.
   - **The class** (`cmp_refs.saw`): `&Int` and `&Bool` compare correctly (MIR dereferences them). Strings are wrong at every position: locals, `&String` parameters and String fields.
