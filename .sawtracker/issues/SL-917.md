**A `?.` chain that ends in a `borrows` accessor is `slice.not-yet` in sawc** (found while building SL-883's chain read; the lead ruled it out of that unit, decision 6).

`o?.at()`, where `at` is `(&self) borrows -> &T`, and `o?.find(0)`, where `find` is a conditional lend `borrows -> &T?`, end the chain in a lent place rather than a value. The spec reads a lend used as a value as a copy: "A lend whose result is only a value … closes as soon as the value is read", and "A conditional lend read as a whole value is an optional copy". So the chain's value should be the lent place copied out at its copy tier (`T?`; flattened for the conditional lend, so never `T??`), with the window closing once the copy is made. A NoCopy or ExplicitCopy lent type is refused, as `let x = v[0]` is.

sawc refuses the shape where the chain's last hop is written, with `slice.not-yet` naming this issue. A chain that only passes THROUGH an accessor (`o?.at().n`) is not affected.

**The work:**
- Typecheck: the chain funnel (`optional_chain` in `compiler/typecheck/src/bodies.saw`) types the top as the lent place's copy, under the copy-tier rule `borrows.let-lend` uses.
- MIR: the chain funnel (`optional_chain_val` in `compiler/mir/src/lower.saw`) copies out of the window the way `lent_copy` does, and closes the window on the present path before the join.
- Pins: a run probe for both accessor kinds (present and absent), and a refuse fixture for a NoCopy lent type.
