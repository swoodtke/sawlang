Found by SL-895's sweep (p895). SL-895 makes every std site that decodes OS bytes return `Err(SystemErrorKind.InvalidUtf8)` instead of panicking (the user's ruling, Oct 25). But `Path` is a `String`, so a non-UTF-8 file name on Linux is still UNREACHABLE: one bad entry makes the whole `Directory.list` an `Err`, and no API can name, open or remove that entry. Design question (a language/std ruling): an OS-native path type (bytes on Unix, as Rust's OsString/Path), a lossless escape in `Path`, or per-entry results from `Directory.list`.
