## Description

Found by SL-459's misc459 agent while checking item 3, which is closed as stale: aliases are transparent in sawc2 and fold at their underlying type.

**Defect.** sawc2's typecheck accepts a static initializer that is not a constant expression. Only the constant evaluator refuses it, and it uses `slice.not-yet` ("a conversion in `static m.A` is not evaluated as a constant in the bootstrap slice yet"), which reads as a slice gap. Under the language, the program is wrong: LANGUAGE_SPEC "The constant grammar" lists what a static initializer may be, and Stage 0 refuses each such static with "static `A` must be initialized by a compile-time constant". A user error belongs in typecheck, which is SL-459 item 12's class.

**Mechanism.** No typecheck check holds a static's initializer to the constant grammar. The fold (`compiler/typecheck/src/fold.saw`) answers `NotConstant` for anything outside it and never reports that. The evaluator then meets the construct in MIR and refuses it with its own `slice.not-yet` (interp.saw `rvalue`: `Conversion`, a call, an aggregate, `Interpolate`).

**Shapes seen.** The evaluator refuses each with `slice.not-yet`, and typecheck says nothing:
- an alias back-conversion, `static A: Byte = Byte(65)`, including in a `static_assert` (`static_assert(Byte(65) == 65, ...)`);
- a call (`T.from(truncating: x)` and any function call; "a call");
- an interpolation, as a String static's initializer.

Some aggregates over constants are legal by the spec ("memberwise aggregation"), so an aggregate refusal is a genuine slice gap and not this defect. The check has to tell the two apart.

**Fix site.** Wherever typecheck checks a static initializer: `check_static_value` and its callers in `compiler/typecheck/src/bodies.saw` / `checks.saw`, which are tcb2b's typecheck files. A refusal such as `static.not-constant` names the sub-expression that fails, as the spec asks ("the diagnostic names the sub-expression that failed rather than the whole condition"), at every position the constant grammar governs: a static initializer, a `static_assert` condition, a raw case value and an `@align` argument. Every position is one funnel or one matrix (brief obligation 1). The evaluator's `slice.not-yet` then stays only for the true slice gaps.

Probe: misc459 worktree `.build/scratch/alias3c.saw`.

The typecheck halves of SL-459 items 7 and 12 are added here, as the lead ruled (SL-459 misc459), so that SL-493 becomes **one constant-position reporter funnel**.

- **Item 7.** `static_assert((1 << 64) == 0, ...)` is refused only by the evaluator (`eval.shift-range`), and so is every fault of a `static_assert` condition: `Int.max + 1`, `BIG * 4`, `1 / 0`, `-Int.min` and `300 as UInt8`. Typecheck's fold computes the same fault, and eval's agreement verifier holds the two to it, which SL-459's eval golden pins. Typecheck's only fault reporter, though, is `check_constant_range` (bodies.saw), and it fires only where a constant expression adopts an integer slot. A condition is a `Bool`, so nothing reports there. The same holds for the faults the fold does not range-check today, behind a cast or `Int.max` (tests/eval/README, Refusals: "the evaluator meets the rest").
- **Item 12.** `static A: Int = B + 1` with `static B: Int = A + 1` is accepted by typecheck and refused only by eval (`eval.cycle`). The fold already detects it, since `fold_static` returns `TcFault.Cycle`, but `check_constant_range` skips Cycle explicitly and nothing else reports it. Cycles longer than two take the same path.

**The funnel.** One reporter, its docstring naming its entry points (brief obligation 1):
- **positions:** a static's initializer, a `static_assert` condition, a raw case's value, an `@align` argument;
- **it refuses:** a non-constant sub-expression (this issue's original shapes), a cycle among statics (naming them in order), and the overflow, shift-range, divide-by-zero and not-fit faults;
- **it reads `fold_constant`**, so typecheck and the evaluator stay one rule. The evaluator's own refusals of these faults then become the agreement check's business, and `slice.not-yet` is left only for genuine slice gaps (an aggregate the evaluator does not hold yet).

Fix site: tcb2b's typecheck files (bodies.saw / checks.saw), so this goes to the next typecheck batch after tcb2b.

**User ruling (Oct 10):** `static A: Byte = Byte(65)` is a constant. In general, a type alias's constructor applied to a constant expression, `A(e)`, is a constant expression. It folds to `e`'s value at the underlying type, gets the same fit check a bare literal gets, and is accepted in every constant position. The scope is recorded in SL:open-questions under "Resolved".

misc459 implements the accepting half (fold, evaluator and the spec's alias passage) under SL-459. This issue's refusal funnel must not refuse the shape. Other calls, `init` bodies and non-alias constructors stay refused, and are what this issue refuses.
