**Ruled by the user (Oct 10): a package's module root is its `src/` directory, everywhere.** Logged in SL:open-questions.

**Today:** the spec says a bare import searches "the importing file's own directory, its package root and the configured search paths", but never defines "package root". Stage 0 takes it to be the directory holding `Saw.toml`, so a package's imports of its own modules spell `src.`: Blade writes `import src.layout.*` in `blade/src/builder.saw` and across `blade/tests/`. From outside, nothing leaks, because Blade passes `--module-path dep=<dep>/src`.

**The rule:**
- **Inside the package:** `import layout`, which already resolves through the importing file's own directory under Stage 0, or `import <package>.layout` by the package's own name.
- **A package's tests:** `import <package>.layout`, as a Rust test writes `use mycrate::layout`. Blade's tester passes the package's own `--module-path <name>=<root>/src`.
- **From outside:** unchanged.

**Work:**
1. **Spec:** define "package root" as the package's `src/` (the directory of its `lib.saw` or `main.saw`) in the import-search sentence and in Package Structure. Say how a package names itself.
2. **Blade:** the tester and builder pass the package's own module path. Rewrite `blade/` and `libs/` from `src.X` to `X` or `<package>.X`, which Stage 0 already accepts. Stage 0's extra search of the `Saw.toml` directory is frozen and harmless. Gate: `bootstrap`.
3. **sawc2's resolver** implements the defined rule, with fixtures for an in-package bare import, a self-named import, and a test importing its package. SL-518 does the same for `compiler/`'s own stage packages.

Do it after SL-518, which owns the compiler half.

@claude-air-reviewer **SL-519.p1 is up for review: a package's module root is `src/`** (the user's ruling; sl519, 4 commits squashed: 78 files, +637/−167).

1. **Spec (`fc420063`).**
   - The import-search sentence defines the package root as the package's `src/`.
   - "Package Structure" adds:
     - module paths start at `src/`;
     - a file outside `src/`, such as a test, has no package root;
     - the two in-package spellings, bare or `import <pkg>.x` through the package's own `--module-path`, which Blade passes from `Saw.toml`;
     - tests import their package by name;
     - `src` is never a segment of a module path, so `import src.x` is refused with a hint.
   - The `--module-path` CLI entry says it is also how a package names itself.
2. **Blade and libs (`75bfecc3`).**
   - 64 imports rewritten: Blade's `src` (16) and `tests` (38) to `import blade.X`, and libs' tests (10) to `toml.*`, `semver.*` and `imgformat.*`.
   - 45 redundant field `public` markers dropped (SL-518's convention).
   - `Manifest.own_module_path()` feeds the builder and the tester.
   - Every other Blade build, `tools/blade_bootstrap.py`, the Makefile, CI, the README, `framesizes.py` and `freestanding_runner.py`, maps `blade=blade/src`.
   - **Deviation from the brief, within the ruling:** Blade's own modules use `import blade.X`, not bare `import X`. Stage 0 resolves a module's imports against the ENTRY file (so a bare import inside `src/` fails when a test is the entry), and it keys module identity by import text (so mixing spellings duplicates types). Both are filed as SL-531, with repros and two suggested SL:hazards entries.
3. **sawc2 resolve (`98c3b5f7`).**
   - **Package root:** the mapped package's directory, else the `src/` beside the nearest `Saw.toml`, when the file is inside it.
   - **One module per file:** a file in a mapped package has identity `NAME.path` (or `NAME` for `lib.saw`), whichever spelling reached it.
   - **Rule `import.src-path`:** refuses an import headed by `src` (unless `src` is a mapped name), with a hint naming both spellings.
   - **Fixtures:** `resolve/package/shelf/` (a bare import plus a self-named one in `src/`, a test importing by name, and the refusal message), plus `refuse/import.src-path.saw`.
4. **Subset checker (`61266833`).** `src` is no longer a package-relative head, so a `src.` import is refused as `import-allowlist` with its own message.
