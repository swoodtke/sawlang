## Description

Constant-folding divergences from Stage 0, found by SL-760's sweep (p760; probes were in its worktree). None is caused by SL-760; split any that grows. Per obligation 4, the first is probably its own rule.
1. **Static forward reference:** `static A = B + 1` with `B` declared later builds (prints 3). The spec allows a static's initializer to name only the statics above it; Stage 0 refuses "declared after this point". The corpus row `errors/static_forward_reference` is `wrong`.
2. **A raw case as a binary shift count:** `x << Late.Big` is accepted by sawc2, while Stage 0 refuses it ("requires integer operands") and accepts `<<=`. Check the spec for which is right.
3. **`static_assert(Late.Big == 1)`** is `type.mismatch` in sawc2 in either order; Stage 0 folds the case to its value.
4. **`Big | Small` (256 | 1) at `UInt8`:** sawc2 reports 256 at the first leaf, Stage 0 reports 257 (the folded whole).
5. **`@align(3)`:** sawc2's typecheck doesn't check for a power of two; Stage 0 refuses it.

**Item 1, a static's forward reference.** Rule (LANGUAGE_SPEC, Compile-Time Evaluation; restated in `defer_constant`'s comment in `compiler/typecheck/src/bodies.saw`): "a static's initializer may name only the statics above it." Add the refusal where a static's initializer is checked (`check_static_body`, an ENTRY POINT of `check_constant_position`): a name in the initializer that resolves to a `static` of the same module declared at a later position, or to the static itself, is refused as `static.forward-reference`, at the name: "the static `B` is declared after this point, and a static's initializer names only the statics above it; move `B` above `A`". A static of ANOTHER module is not a forward reference (module initialization order is not this rule); a cycle through another module is out of scope, and if the census shows one building, report it. Position matrix: a bare name; inside arithmetic; as a call argument of an alias constructor (`Byte(B)`); inside an array literal or a struct literal initializer; the static naming itself; a raw-backed case declared later is NOT a static (the spec lets a case be named before its declaration: check the text; if it is silent, mark the cell OPEN).

**Item 3, a raw-backed case compared in a constant.** The spec section on raw backings (`e as UInt8` is the total conversion) decides it: if a case converts to its backing only through `as`, then `static_assert(Late.Big == 256)` is a type error by design and the right spelling is `Late.Big as Int == 256`; Stage 0's folding of the bare case was then lenient, the row is a stale test, and nothing changes but a fixture pinning the refusal and its message naming `as`. If the spec says a case is an integer constant where a constant is required (the SL-457 c5 note quotes "a backed case is a compile-time constant usable as an array length"), then the comparison takes the case's value. Read both passages; quote them in the report; implement only what they determine, and mark the cell OPEN if they disagree. The same reading answers item 2 (whether a case is a legal shift count).

**Item 4, the range refusal names the whole value.** In the constant-range check (`check_constant_range`, which refuses "constant expression N does not fit in `T`"), the reported N and the refused node are the first failing LEAF. Report the whole folded expression when the whole folds: fold the full initializer first; if it folds and does not fit, refuse at the whole expression with its value (4111); only when the whole does not fold fall back to today's per-leaf report. Pin: the two lines above, and a case where a leaf alone is out of range but the whole fits (`let n: UInt8 = 256 - 1`): accepted or refused as today, recorded either way and not changed.
