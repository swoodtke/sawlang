## Description

Found by the SL-357 p2 fact-check on Sep 23; I read the code on main.

- **Allocation:** codegen/calls.py (the spawn lowering) allocates the thread control block as `_abi_size({i8*, i8*, Int, slot})` with align 16. That is the padded size: `{i8*, i8*, i64, i8}` is 32 bytes on a 64-bit host.
- **Free:** std/task.saw `Thread<T>.join` calls `GlobalAllocator().dealloc(h, 24 + sizeof<T>(), 16)`, and `VoidThread.join` calls `dealloc(h, 24, 16)`. These are unpadded sums, so they disagree with the allocation whenever the slot needs tail padding (Void, Int8, Bool, any T whose size is not a multiple of 8).
- **Impact:** harmless with malloc/free, which ignore the size. It is wrong for any size-taking allocator (a slab, or a freestanding allocator that trusts the size), so it is latent rather than live.
- **Related:** `(h + 24)` for the result slot assumes 8-byte pointer and Int fields. That holds on every hosted target Thread.spawn exists on, but it is the same hand-copied layout knowledge.

**Mechanism.** The block layout lives in codegen, and std recomputes it by hand. The detach seam avoids this: the SIZE travels in the state word (shim.c `__saw_rt_thread_detach`), so the runtime frees without knowing T.

**Fix direction.** join reads the size from the same state word, or std gets the size from one compiler-provided source. Then there is ONE place that knows the layout.

**Sweep owed.** Every other std or runtime site that frees a compiler-built block with a hand-computed size: grep `dealloc(h,` and `+ 24` in std/ and rt/.

**Pin.** A Thread<Int8> and a VoidThread spawned and joined under a size-checking test allocator, or `__saw_rt_alloc_deny_after`-style instrumentation that asserts free-size == alloc-size.
