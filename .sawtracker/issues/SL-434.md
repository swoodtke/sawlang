## Description

U4d measured this (SL-424.p4 report). `SourceFile.offset_of(line, col)` in `compiler/parse/src/source.saw` walks forward from the line's start, one scalar at a time, for every token the parser converts. So a parse costs time quadratic in line length: 20,000 call arguments on one line take 2.1 s, while 20,000 pairs one per line take 0.013 s.

This is not urgent. Real sources have short lines, and tests/corpus parses in 0.09 s. But a generated or minified input is a plausible input for a compiler, and nothing refuses a long line.

**Fix: carry the byte offset on the token.** The lexer already knows it, so the parser never recomputes one.
- If the lexer's token layout makes that awkward, a (line, col, offset) memo of the last conversion would make sequential calls O(1).
- Either way, pin it with a cell: a 20,000-argument single-line call parses in linear time. The depth cells show how.
- Report the change's cost on tests/corpus.
