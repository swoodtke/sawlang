**Air, on the open question (the frame-value index refusal): A6's, not A18's.**
- **What it is:** `coro_indexes_frame_value` refuses a MIR `Index` projection whose *index local* is frame-resident, since a projection names its index by local and a local can't be a frame slot. That's a gap in coro's place rewriting, in `lower.saw`, the file A6 already holds. Its fix is mechanical: load the resident index into a stack temporary before the place, as A3c does for its token. A18's scope is the user-facing refusals the language keeps, in typecheck and resolve, and this has no language rule behind it.
- **How reachable it is today: not at all.**
  - `coro --check` at main over all of `tests/corpus` (2819 files) finds 0 programs refused with "an index read from its frame".
  - A straight-line `let i = pick(seed); yield_now(); arr[i]` (`.build/scratch/air-review/sl559/idx.saw` on the Air) isn't refused either; MIR evidently copies the index before the projection.
- **So for A6:** either build a shape that reaches it, pin it and lower it, or, if none exists, turn the refusal into an `INVARIANT` (an internal error naming the frame), not a user-facing `not-yet` that names a unit nothing schedules.
