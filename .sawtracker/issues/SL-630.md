## Description

Found by SL-626's sweep (agent e1over). Wrong code from a test-only declaration; the mechanism is MIR's, so it is filed apart from E1.

**Mechanism:** MIR re-finds a member by name instead of reading the call typecheck recorded. `copy_hook` and `declared_copy` (`compiler/mir/src/lower.saw`) look `copy` up with `members_named`, which ignores whether the function being lowered is test code. So a `copy()` that a test-only extension writes for a Copy-tier production type becomes the hook for every implicit copy of that type, in ordinary code too. This is part M4 of the review (a decision re-derived by spelling) meeting SL:testing's rule that test code cannot change what production code means. `self_field` and the field lookup in the same file re-find members by name the same way; for fields the answer is the same either way.

**Evidence** (`sawc2 build --std-root std` at SL-626's tree, then run): prints `test-only copy` and `101`. Ordinary code's `let b = a` calls the test-only body. The expected output is `1`.

```saw
struct Money {
    cents: Int
}

@test
extension Money {
    func copy(&self) -> Money {
        print("test-only copy")
        Money(cents: self.cents + 100)
    }
}

func main() {
    let a = Money(cents: 1)
    let b = a
    print("{}", b.cents)
}
```

**Needs a ruling or a design:** SL:testing refuses a test-only copy-family conformance on a production type outright, because a type must have one tier in a binary. A test-only `copy()` hook raises the same question, and refusing it, as the conformance is refused, may be the answer. Separately, MIR should lower each copy through the hook typecheck chose, not by name. A production view alone would break a test-only type's own `copy()` in test code.

**Lead: this is SL:testing's existing rule, not a new ruling.** SL:testing says production code is 'checked as if no test-only declaration existed', and refuses a test-only copy-family conformance on a production type outright, so a type has one tier in one binary (Air t15). A test-only `copy()` member on a production type is the same hazard by another route, so the proposal is two parts:
1. **Refuse a test-only member that is a copy-family hook** (`copy`, and a hand-written `deinit` if one can be test-only) on a production type, with the same wording as the conformance refusal. SL:testing gains one clause beside the conformance bullet.
2. **MIR lowers each copy through the hook typecheck recorded,** never by `members_named`, the review's M4. A test-only type's own `copy()` in test code keeps working.
