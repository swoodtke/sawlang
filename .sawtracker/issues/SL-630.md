## Description

Found by SL-626's sweep (agent e1over). Wrong code from a test-only declaration; the mechanism is MIR's, so it is filed apart from E1.

**Mechanism:** MIR re-finds a member by name instead of reading the call typecheck recorded. `copy_hook` and `declared_copy` (`compiler/mir/src/lower.saw`) look `copy` up with `members_named`, which ignores whether the function being lowered is test code. So a `copy()` that a test-only extension writes for a Copy-tier production type becomes the hook for every implicit copy of that type, in ordinary code too. This is part M4 of the review (a decision re-derived by spelling) meeting SL:testing's rule that test code cannot change what production code means. `self_field` and the field lookup in the same file re-find members by name the same way; for fields the answer is the same either way.

**Evidence** (`sawc2 build --std-root std` at SL-626's tree, then run): prints `test-only copy` and `101`. Ordinary code's `let b = a` calls the test-only body. The expected output is `1`.

```saw
struct Money {
    cents: Int
}

@test
extension Money {
    func copy(&self) -> Money {
        print("test-only copy")
        Money(cents: self.cents + 100)
    }
}

func main() {
    let a = Money(cents: 1)
    let b = a
    print("{}", b.cents)
}
```

**Needs a ruling or a design:** SL:testing refuses a test-only copy-family conformance on a production type outright, because a type must have one tier in a binary. A test-only `copy()` hook raises the same question, and refusing it, as the conformance is refused, may be the answer. Separately, MIR should lower each copy through the hook typecheck chose, not by name. A production view alone would break a test-only type's own `copy()` in test code.

**Air: three probe results the brief should carry.** None changes the user's ruling; they widen what each part has to cover. Probes in `.build/scratch/air-review/sl630/`, built by sawc2 (Stage 2, `--std-root std`) at 80e7c5e3f plus SL-625, and by Stage 0 where it can.

1. **The hijack isn't test-only, so part 2 is the fix for production too.** `prod_copy.saw`: a Copy-tier `struct Money { cents: Int }` with a plain production `extension Money { func copy(&self) -> Money { print("user copy"); … } }`, no `@test` anywhere, then `let b = a`. sawc2 prints `user copy` `101`; Stage 0 prints `1`. Stage 0 is right: the spec's retain hook is the `copy()` body of a DECLARED `Copy` conformance ("The Copy trait"), and a plain extension's `copy()` is an ordinary method. So part 2 must read the hook from the copy-policy conformance, not "a member named `copy` from any extension". Its pins should include this production program, expected `1`.

2. **There is a second by-name hook lookup, in mono.** `compiler/mono/src/glue.saw` `copy_member` takes the first `copy` with `source == Extension`, the same mechanism as MIR's `declared_copy` and `copy_hook`. Part 2 should cover both stages. (`build.saw:deinit_member` has the same shape but is safe by itself, because `deinit.outside-policy` refuses a `deinit` outside a copy-policy conformance; see 3.)

3. **SL:testing's Air t15 refusal isn't enforced, and its absence lets test code replace a production destructor.** `test_conformance.saw`: a production `struct Noisy { id: Int }` (Copy-tier) and `@test extension Noisy: NoCopy { func deinit(&var self) { print("test-only deinit {}", self.id) } }`. A production `sawc2 build` accepts it and the binary prints `made 7` `test-only deinit 7`. So the test-only conformance changes the type's tier and runs its destructor in production. Part 1's clause "a hand-written `deinit` if one can be test-only": a `deinit` in a plain `@test extension` is refused (`deinit.outside-policy`, `test_deinit.saw`). The one route is the test-only conformance, so enforcing t15, which is already ruled, closes it. Part 1 should enforce t15 itself, a test-only `Copy`/`ExplicitCopy`/`NoCopy` conformance on a production type refused outright, not only the member. Pin `test_conformance.saw` as that refusal.

Control: `test_copy_explicit.saw`, an `ExplicitCopy` conformance with a `copy()` body, gives `prod copy` `2` on both compilers.
