## Description

**The freestanding suite's `bladepkg` case does not run on the ESP32-S3 row.** Found by SL-1069's triage (Nov 12): `error: Saw.toml [sos]: no configuration for target xtensa-esp-unknown-elf (this manifest declares riscv32-unknown-none-elf, aarch64-unknown-none-elf)`. The case's package manifest (`tests/freestanding/bladepkg/`) declares the other two targets only, and until SL-1071 lands Blade has no answer for the triple at all.

**Work, after SL-1071 and SL-1069 have both merged:** add a `[sos.xtensa-esp-unknown-elf]` section to the case's manifest (the linker script and native sources of `tests/freestanding/hal/xtensa/`; `mcpu` defaults to esp32s3), have the runner hand Blade Espressif's clang and its `ld.lld` through `SOS_CLANG` and `SOS_LD` for this row, and remove the row's `due_on` marker, which cites this issue. Expected: the case passes on all three rows. A small Sonnet unit; gate: the freestanding suite and the blade lane.
