## Description

**`r = move r` inside a loop trips a MIR invariant: "local _2 may be used in bb7 after a path dropped it".** Found by the SL-677 review (Nov 18; the `cx_self_move_assign.saw` cell in its file f401). Both main's compiler and the SL-677 patch fail, so this is not that patch's. A self move-assign is legal (the value moves out and back before the next use), and the compiler must either accept and lower it or refuse it cleanly, never trip an internal check.

To do (brief obligation 4: a class until a sweep says otherwise):
- reduce the cell;
- probe the siblings: `x = move x` outside a loop, in `while`/`for`/`loop`, through a field (`s.f = move s.f`), with an `Optional`/enum value, with a NoCopy type with `deinit`;
- name the mechanism (the drop elaboration's per-path state across a back edge?) and fix it with the matrix as its pins.

Related: SL-677.

**Lead's note with p1 (Nov 19).** Evidence: `.build/scratch/p1171/sweep/` (the implementer's sweep) and `.build/scratch/p1171/nested.saw` (the lead's), both in the lead's checkout.

- **Reduction:** no loop is needed. `var r = Nc(n: 1); r = move r` (a NoCopy type with `deinit`) trips the invariant on main ("local _1 may be used in bbN after a path dropped it").
- **Mechanism:** MIR lowering. `lower_assign` (`compiler/mir/src/lower.saw`) evaluated `move r` to an operand not yet emitted, called `emit_drop(target)`, and the store then read the operand: `drop(_1); _1 = move _1;`.
- **The fix:** when the operand moves out of the same local the target is rooted in (`moves_from_root`), the value is taken into a temporary first: temp = move r, then the old r's drop (a no-op, since r was moved), then r = move temp. An assignment between different locals lowers as before.
- **The sweep:** each of these was an INVARIANT on main and now runs with one drop each:
  - straight line, `while`, `for`, `while {}` with `break`;
  - `continue`/`break` between the move and the assignment;
  - `Nc?` (straight and in a loop);
  - a NoCopy enum payload in a loop;
  - the reviewer's cell.

Requested changes on patch SL-1171.p1 (revision 1) (its test run was cancelled)

**Changes requested, one point: the mechanism you named has a second entry, a copy instead of a move, and it still trips the invariant.**

The issue asks for the class (brief obligation 4). `lower_assign` reads the operand at the store, after `emit_drop(target)`. `moves_from_root` covers a `Move` operand only. A self-assignment that copies a type whose copy retains a member hits the same order:

```saw
struct Ticket { code: String }

func ticket_cell() {
    var t = Ticket(code: heap_text(40))   // heap_text builds a 40-byte String
    t = t                                  // INVARIANT: local _1 may be used in bb1 after a path dropped it
}

func closure_cell() {
    let text = heap_text(40)
    var f = { [text] in text.len() }
    f = f                                  // INVARIANT: local _3 may be used in bb2 after a path dropped it
}
```

Both stop the build with that `INVARIANT` on the patch and on main. By the spec's Copy rule, `Ticket` (a `String` field) and an escaping closure are `Copy` with a compiler-handled retain. These shapes compile and run clean under ASan at `-O0` and `-O2`:
- `s = s` on a heap `String` itself;
- `t.code = t.code`;
- `s = s` in a `while` loop.

So the bare `String` copy is safe, and it is the struct or closure copy that is read after the drop.

**Ask:** cover the copy entry of the same mechanism, as you did the move. For example, take the operand into a temporary when it reads the target's own local, `Copy` as well as `Move`. Then pin `t = t` (a struct holding a `String`) and `f = f` (an escaping closure) in `self_move_assign.saw` or a sibling stated probe, ASan-clean.

**Read and held:**
- The move fix: `moves_from_root` matches a move out of the target's root local, and the temporary takes the value before the old one's drop.
- **My four extra move cells**, each printing `live=0` under ASan at `-O0` and `-O2`:
  - a generic body, `y = move y` with `T` a NoCopy type that has a `deinit`;
  - a closure body;
  - one `if` branch only, both ways;
  - a `Task.spawn` body.
