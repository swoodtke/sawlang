Found by the SL-1190 sweep.

With `--codegen-units=module` at `-O0` (so `--lto=none`) and the default `-g`, Espressif's `ld.lld` 20.1.1 refuses the object: `ld.lld: error: …/soft_float.o:(.debug_line+0x38d9): unknown relocation (0) against symbol` (also in `.debug_ranges`).

This is hit by `soft_float`, `float_methods_unoptimized`, `integer_helpers`, `soft_float_vectors` and `bladepkg` (`blade build --target xtensa-esp-unknown-elf`). The same object links with one unit, with `-g0`, or with `--lto=thin`/`full`.

**Suspect (UNVERIFIED):** the relocatable `-r` join of the units' debug sections for Xtensa, or `llvm-objcopy` localizing symbols that debug relocations name. This blocks a split default for `--freestanding` (SL-1190, ruling 2).
