## Description

**`sawc2 coro` panics on a framed loop that `break`s after a suspension: `panic at vector.saw:90: Vector.[]: index out of range: -1`.**

Found by A4b (SL-636). Its drivers let the census reach programs that used to stop at resolve's `slice.not-yet` on `__saw_drive`. The crash is older than A4b: it reproduces on origin/main at 24d9db172 with no drive site.

**Repro** (`sawc2 coro --check --std-root std`; mono `--check` is clean):

```saw
func count_break(limit: Int) -> Int {
    var n = 0
    while n < 10 {
        n = n + 1
        __saw_suspend()
        if n >= limit {
            break
        }
    }
    n
}

func main() {
    print(count_break(2))
}
```

- `while { ... }` with the same `break` also panics.
- The same loop without the `break` is fine (`coro.not-yet` at its budget point, as expected).
- So is a `return` in place of the `break`.

The MIR puts the yield-capable budget point (`bb4`) after the suspension, and that block is reached only through the `break`'s `false` arm. The panic is in coro's decision phase: `--dump` panics too, before printing anything.

**Mechanism: not yet found.** It is in coroutine lowering's frame finding or lowering decision (`frames.saw` or `lower.saw`), where some index is -1. The census lists the same panic as the crash of `coro_break_reentered_in_loop`, `coro_done_path_releases_in_scope_order`, `coro_frame_local_released_at_scope_end`, `conformance/K70_driven_scope_end_release_matrix`; whether every one of them is this shape is unchecked.

**Mechanism found, and fixed in A4b (SL-636).** `coro_unlowered_chain` (`compiler/coro/src/lower.saw`) follows each `Child` reason into the child it drives. When that child is refused for an op-budget point, its `CoroUnlowered.suspend` names a suspension point whose `call` is -1, since a budget point is no call. The walk then labelled `coro_driven_child(-1)`, which is item -1, and `item_label` indexed `items[-1]`. The `break` only matters because the repro calls the child directly from `main`: any framed caller of a child whose loop holds a live budget point hits it (the same loop under `__saw_drive`, where `main` has no frame, never did). **Fix:** the chain ends at a suspension that is no call, as it already did for a frame-wide reason (window, index). That is the only reason with `suspend >= 0` and `call < 0`, so the mechanism has no other sibling. **Pin:** `compiler/tests/coro/refuse/coro.not-yet.budget-child.saw`. The four census crashes now refuse as `coro.not-yet`: `coro_break_reentered_in_loop`, `coro_done_path_releases_in_scope_order`, `coro_frame_local_released_at_scope_end` and K70.
