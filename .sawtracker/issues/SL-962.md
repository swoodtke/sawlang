## Description

**`x.copy()` under a `<T: Copy>` bound is refused when `T = Int`.** Found while fixing SL-961.

**Repro:** `.build/scratch/p961/probe_copybound.saw`, a generic `func f<T: Copy>(x: T) -> T { x.copy() }` called with an `Int`.
- **What happens:** mono refuses it with `mono.not-yet`: "Copy.copy() on Int, which no conformance of it meets".
- **What works:** the same function bounded `<T: ExplicitCopy>` compiles and runs.

**Expected:** a primitive in the Copy tier answers `copy()` with its bits, under either bound. Typecheck accepts the call, so this is a mono gap, not a type error.

**First step, per obligation 4:** sweep the primitives (every integer width, Bool, Float, Byte, the pointer types) against both bounds, and against the other trait-method routes mono resolves for primitives, then fix the mechanism.

**SL-962.p1: a `copy()` under a `Copy` bound answers a primitive by its bits**

**Mechanism** (`.build/scratch/p962/sweep.md`):
- Mono answers a trait method on a concrete type in `resolve_requirement` (worklist.saw). It tries a written conformance, then `primitive_grants` (typecheck's tier.saw), then `met_without_conformance`.
- `primitive_grants` gives primitives `ExplicitCopy` but never `Copy`, since a primitive is `Copy` by its tier. And `met_without_conformance` answered a `copy()` only when `copy_glue_builds`, which is false for every primitive.
- So `Copy.copy` on a primitive found nothing, while `ExplicitCopy.copy` reached member glue.
- `FuncPointer` has no `glue_kind` row, so its `copy()` was refused under either bound.

**Fix:**
- `met_without_conformance` answers a `copy()` on any type copied by its bits.
- `member_refusal` admits a bitwise `copy()` for any row.
- The answer is member glue that loads and returns the bits, with no copy glue (SL-961's rule).

**Matrix:** 23 type rows × 11 trait-method columns, every cell compiled and run.
- Refused before, working after: `copy()` under `Copy` on every integer width, `Bool`, `Byte`, `Float`, both raw pointers and `FuncPointer`; and `FuncPointer`'s `copy()` under `ExplicitCopy`.
- No other cell moved.

**Pin:** `compiler/tests/run/probes/copy_bound_on_primitives.saw` covers every flipped cell. It also checks that `Int`'s member glue is defined and that no copy glue exists for `Int` or `FuncPointer`.

**Gates:**
- `run.py --only seed,units,golden,subset,fixture_whitespace,std,typechecker,mono,coro,programs,sanitize,census`: exit 0;
- `battery.sh citations`: green;
- no `.ll` golden moved.

**Not in this patch:** the cells typecheck accepts but the spec doesn't grant are a different mechanism. Those are `Bool`'s `compare`, a raw pointer's `equals` and `hash`, and `FuncPointer`'s value traits. They are SL-964, which takes over the refusals that cite closed SL-715.
