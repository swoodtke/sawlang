## Description

SL-423's unit C (SL-417's bare-form negatives for §12 P cells) found two P cells whose bare form parses as the construct in its context. Both are waived, with the finding as the reason, and never recorded as expected. The same text is accepted on main before SL-423.

1. **`syntax.borrow.block` × `cond`.** `if borrow let x = a { x } {` parses with the borrow block as the `if` condition. §12 codes the cell P: parenthesized only.
   - `syntax.rule.borrow-form` says a binding at an `if` head is the optional-place unwrap (`if borrow let x = e { … }`), and head-restriction would refuse the block reading, but the recognizer does not apply that clause.
   - SL-417's premise, that "the recognizer happens to refuse this text", was wrong. It was first seen in SL-416.p1's review (F1).
2. **`syntax.borrow.block` × `bhead`.** `borrow let x = borrow let x = a { x } {` parses with the inner block as the head. No production or §13 rule backs the P code there.

**To do:**
- Decide each from GRAMMAR.md's text: which rule refuses the bare form, or whether the §12 code is wrong.
- Make the recognizer apply it: borrow-form's head clause for `cond`, and a rule or a matrix correction for `bhead`.
- Record the bare-form negatives, and drop the two p-cell waivers.

A §12 correction is a grammar change. A new refusal rule may need the user's ruling if the text does not already decide it.

<!-- sawtracker:comment {"author":"agent:claude-air-sawlang","body_bytes":1352,"created":"1790694153","id":"c1"} -->
GRAMMAR.md's text, as written, decides the two cells differently.

1. **`cond`: the P is backed.** `syntax.rule.borrow-form` says that after `let` or `var`, a name and `=` form a binding: "a `borrow` block, or **at an `if` head** an optional-place unwrap". So at an `if` head the block reading is excluded. `if borrow let x = a { x } {` is the unwrap, with `{ x }` as the `if`'s body, and the trailing `{` is refused. That is a recognizer fix only, with no grammar change.
2. **`bhead`: the P contradicts `syntax.rule.head-reset`.** Head-restriction stops a *trailing closure* from attaching at a head's outer level; it says nothing against a nested construct. Head-reset says a brace-delimited block nested in any head starts a fresh level, and it names "the body of an `if`, `else`, `while`, `for`, `try`, `catch` or `borrow` construct". An inner `borrow let y = a` in a borrow head needs its block, as `match` needs its arms, so it takes `{ y }`. So `borrow let x = borrow let y = a { y } { … }` parses by the same rule that makes `while match m { … } { step() }` parse.
   - If P is wanted, it needs a new rule, which is the user's ruling. Otherwise the §12 code for `bhead × borrow.block` becomes B.
   - The inner block's value is a copy, not a place, so a typing refusal catches the case anyway.
   - Either way it is a GRAMMAR.md change.
