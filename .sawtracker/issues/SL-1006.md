Found by the SL-1005 spec review (F10).

LANGUAGE_SPEC "Composite Types", "The `{ }` closure rule" says: **there is no bare block statement**. A closure literal alone in statement position is a compile error naming the two real spellings: call it (`{ ... }()`) or bind it.

sawc builds `func main() { { print(1) } }` with exit 0, and the program prints NOTHING. The body silently never runs, which is a correctness trap for anyone coming from a language with block statements. `{ print(1) }()` prints 1.

The probe is `/Users/shawn/Projects/sawlang/.build/scratch/p1000d/F10_bare_block.saw`.

**Expected:** a compile error at the literal naming both spellings. Sweep (obligation 4): every statement position, such as a function body, a branch, a loop body or an arm block, and a closure literal as an expression statement after another statement.
