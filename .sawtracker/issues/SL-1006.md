**Implementation detail (lead, Nov 12): refuse a closure literal that is a statement of its own, at the one funnel every discarded expression already passes.**

**Confirmed on main today:** `func main() { { print(1) }; print(2) }` (two lines) builds, exits 0 and prints only `2`. `sawc parse --dump` shows the statement as `(ExprStmt (Closure …))`.

**The rule (LANGUAGE_SPEC "The `{ }` closure rule", GRAMMAR.md "There is no bare block statement"):** a closure literal alone in statement position is a compile error naming the two real spellings.

**Where.** `compiler/typecheck/src/bodies.saw`, `check_discarded(e)`. It is already the funnel for "an expression computed where nothing reads it" (design 151's discarded `Result`), with two entry points: `check_statement_as`'s `Stmt_Expr` arm and `arm_body`'s statement-position arm. Every statement position reaches one of them: a bare statement, a `Void` body's or a loop body's last statement, a statement-position `if` branch's last statement, a statement-position `match` arm, a `Void` closure's tail.

**The change.**
1. At the top of `check_discarded`, before its `is_typed` test (a closure checked with `TC_WANT_STMT` may have no usable type): take `self.unparen(e)`; if that node has `Alt.Expr_Closure`, refuse at `e` and return.
2. Rule id: `closure.discarded`. Message, one sentence, which must contain both phrases the corpus test expects (`closure literal is never called` and `there is no bare block statement`):
   > this closure literal is never called: there is no bare block statement, so a `\{ ... \}` standing as a statement builds a closure and drops it, and nothing inside it runs; call it, as `\{ ... \}()`, or bind it, as `let f = \{ ... \}`

   (In a Saw string literal a bare `{` opens an interpolation: escape each brace as `\{` and `\}`.)
3. Update `check_discarded`'s leading comment so it names both things the funnel refuses, and add an ENTRY POINTS list (names only): `check_statement_as`, `arm_body`.
4. Nothing else changes: no parser change (the grammar is right: `{` at a statement's start opens a closure literal), and no MIR change.

**Not refused (each must still build; pin them in one golden or run program):**
- a called literal, `{ print(1) }()`;
- a bound one, `let f = { print(1) }`, and the explicit discard `let _ = { print(1) }`;
- a literal that is a VALUE: a call argument, the tail of a function or closure whose result type is a function type, a value `if`/`match` arm;
- a `match` arm whose body starts with `{`: that is a block, not a closure (GRAMMAR.md syntax.rule.brace).
