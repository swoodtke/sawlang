**The spec's `LendingIterator` and `for borrow` are unbuilt in sawc2 (and absent from Stage 0).** Found by SL-703's probe. Stage 0's `Vector.iter` is a plain `Iterator` over a `borrows struct`, so no corpus program needs this. It's planned work, not parity.

From the probe (`.build/scratch/s703/` in its worktree), sawc2 with `LendingIterator` added to the prelude in the spec's shape (`func next(&var self) borrows -> &var Item?`):
- `slice.not-yet`: `syntax.expr.lends` and `syntax.expr.for.borrow` are not in the bootstrap slice.
- `type.reference-position`: a borrowing struct's field may hold a shared reference only, so the spec's `&var Grid` field for an exclusive lending iterator is refused. The spec marks that form as planned.
- `conformance.signature`: a shared lending iterator (`-> &Cell?`) does not meet the trait's `-> &var Item?`. The spec's text allows the shared form, so the trait needs a way to state both (UNVERIFIED: likely two traits, or a mode parameter; that's a spec question).
- A trait added to `std/prelude.saw` is not auto-visible (`name.not-in-prelude`). The prelude's exported set is a list somewhere, and it needs the new name.

Scope when scheduled: an Opus compiler unit, with the spec questions above settled first (the trait's shape for shared vs exclusive lending, and the `&var` borrowing-struct field). Not on the parity path.
