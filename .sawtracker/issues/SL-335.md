## Description

FOLLOW-UP to SL-333 (user ruling Sep 21: land SL-333 as built, retire the constant afterwards). Sequenced AFTER design 275 U3 lands.

## Why

SL-333 gave `borrows` signatures a declared lend mode (`-> &T` read-only, `-> &var T` writable, use site narrows). With that in the signature, `#lend_var` (design 179) has ONE production user left: `sawc/std/data.saw`'s `Data.[]`, where it gates the copy-on-write separation (`_make_ready`) before lending a writable byte. Every other occurrence (16 files at SL-333's tip) is a test of the mechanism itself; blade, libs and devtools never name it. The constant exists because design 179 had one body per accessor name and needed a way for that body to DIFFER between the shared and exclusive flavours. Two declarations, one per mode, are the reader-visible spelling of the same fact (doctrine: reader-visibility trumps; no hidden switch inside one body).

## What changes

1. PER-MODE ACCESSOR OVERLOADS: a type may declare both `func [](&self, i: Int) borrows -> &T` and `func [](&var self, i: Int) borrows -> &var T` (same name, same parameters, different lend mode). Resolution is by the USE SITE's window mode — the one fact SL-333's opener funnel already computes: a read picks the `&T` overload when one exists, else opens the `&var T` one shared (today's narrowing); a write picks the `&var T` overload (a write with only a `&T` overload keeps SL-333's R1 refusal). Overloads today resolve on arguments only — this is a NEW resolution key and gets its own funnel entry + matrix (read/write × {only &T, only &var T, both} × the seven opener entries).
2. `Data.[]` rewritten as two declarations (the bounds-check prologue duplicated, three lines); R4's eligibility computed on each body as written — the "on the shared specialization AFTER the fold" clause goes away.
3. DELETE `#lend_var`: the lexer constant, the fold in `place_transform.py` (~902), the scope fence in `typechecker/expressions.py` (~446), the spec section "`#lend_var`: a body that knows its flavor" and its rules, the skill mentions; the 16 test files either retarget to the overload spelling (the CoW/gate-count rows, K128/K129/M33/M34, `lend_var_*.saw`) or are deleted with their INDEX rows rewritten. Naming `#lend_var` becomes an unknown-directive error with a fixit naming the two-declaration spelling.

## What does NOT change

SL-333's R7 two-specialization SPLIT of a `-> &var T` accessor stays — a writable FORWARDER (`lend self.inner[i]`) still needs a shared body whose inner call follows the outer window's mode, and that body is compiler-generated, invisible to the author. R4's recorded receiver-eligibility bit stays.
