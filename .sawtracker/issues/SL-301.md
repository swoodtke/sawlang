## Description

Child of SL-300. M18: implement a flat append-only AST arena and standalone syntax parser over the unchanged selfhost lexer. Source runs under the existing mini-VM and Python-built Saw; no semantic frontend or production compiler changes.

Initial grammar: functions with typed named parameters, named return types, let/var bindings, return, expression statements/tails, integer/String/Bool/name expressions, parentheses, unary/binary operators and positional calls. Unknown names/types remain syntax. Explicitly reject unsupported syntax and malformed inputs; preserve token spans and source anchors; implement the design-259 depth 256 independently of VM call-stack limits.

Validation: independently authored expected trees and arena invariants, deterministic complete dumps across VM/native O0/O2/Python-sawc, ASan cleanup, malformed/unsupported/depth-boundary tests. Full examples classification and canonical Python AST differential follow after this foundation works. Design: prototypes/minivm/M18_AST.md in the implementation patch. Parent owns design/review; Sol agents own source and harness.

Submitted patch SL-301.p1 (revision 1): M18: indexed AST generation with a standalone Saw syntax parser

M18 introduces a standalone syntax parser written in Saw, using the unchanged selfhost lexer and an append-only index arena. Recursive syntax is represented by flat nodes and ordered child-index ranges. The parser source runs under the existing mini-VM as well as Python-built Saw; the mini-VM's semantic frontend is unchanged.

The initial grammar covers functions, named types/parameters, bindings, returns, expression statements/tails, names and integer/String/Bool literals, unary/binary operators, grouping and positional calls on expression heads. It preserves token spans and source anchors without resolving names or checking types. Unsupported forms are explicitly refused, including documentation metadata that this AST does not yet store.

Explicit expression stacks preserve the agreed depth 256 independently of the VM call-stack limit. Tests cover valid trees and arena invariants, precedence/order, literals and source positions, malformed/unsupported inputs, and depth boundaries across VM, native O0/O2, ASan and Python-sawc builds. Full top-level examples classification and canonical Python AST comparison are the next phase; this patch's dump is a diagnostic arena representation, not the canonical AST dump.

Design and compatibility documentation reconcile the arena representation with design 259 and record the remaining work. The related Python non-identifier callee parsing defect was documented on existing SL-73 rather than reproduced as intended AST behavior.

Validation: all 52 focused cases passed with identical complete AST/error records across VM, emitted LLVM O0/O2, AddressSanitizer and the updated production compiler after SL-269. All 8 harness unit tests passed; git diff --check is clean. The final gate used the assembled parent implementation tree, with independently authored tree/span expectations and explicit malformed/unsupported/depth-boundary controls. No production compiler or mini-VM implementation source changed.
