W4 ruled (user, Oct 9): a generic body names its type parameter's associated type as `T.Item` (SL:open-questions W4, Resolved).

**Resolve:** a qualified type path whose head binds to a type parameter names the associated type that parameter's bounds declare. An absent one is refused, as name.undefined naming the bounds searched. An ambiguous one, where two bounds both declare it, is refused naming both. It replaces today's slice.not-yet for `T.Item`. Bare `Item` in a generic body stays refused, with a fix-it to `T.Item`.

**Typecheck:** a projection key (type parameter, trait, associated type) in the interner, substituted per instantiation through the conformance's type assignment. Generic bodies type-check against the projection.

**Pins:** a single bound, two parameters, an ambiguous pair of bounds, an absent associated type, and the bare-form fix-it. The three corpus programs (associated_type_generic.saw, generic_instance_associated_type_binding.saw and generic_instance_associated_type_return.saw) are re-aimed to `T.Item` at the next corpus migration.

**Sequencing:** it touches compiler/resolve and compiler/typecheck, so it is dispatched after SL-452's U6c1 lands, to avoid overlapping U6c1's typecheck tables.

The plan follows the ruling. Four cases worth pinning before dispatch:

1. **Ambiguity is about declarations, not bounds.** In `<T: Collection + Sequence>`, with `Item` declared once in `Sequence` and `Collection` refining it, both bounds reach the same declaration. That's one projection, not an ambiguous pair. Refuse only when two distinct declarations are reachable, and pin the redundant-bound case as accepted.
2. **Inherited associated types.** "The associated type that parameter's bounds declare" should read "declare or inherit through refinement". `T: Collection` names `T.Item` when `Item` is declared in the parent `Sequence`. That needs a pin of its own.
3. **Chained projections.** If an associated type can itself carry a bound, `T.Item.Key` is reachable. Either type it, as a projection of a projection, or refuse it by name as `slice.not-yet`, but don't let it fall through to "cannot be named through a path".
4. **The bare-form fix-it with two candidates.** In `<T: Container, U: Container>`, a bare `Item` should list both `T.Item` and `U.Item` and pick neither. Pin it next to the single-parameter fix-it.

SL-453.p1 is up: `T.Item` names a type parameter's associated type (W4 (a), user, Oct 9). 1 commit, 34 files, +1,067/−164, on main 4ab871a7 (main has moved only in `.sawtracker`). It ran concurrently with U6c2, with no shared files. MIR is untouched and accepts projection types.

**Resolve** (`lookup.saw`, `walk.saw`):
- **`T.Item`:** a path headed by a type parameter binds to the associated type its bounds declare, or inherit through parent traits. It's a new binding kind, `Projection`, dumped `(projection T L:C MODULE.Trait.Item)`.
- **Your c2 pins:**
  1. **Ambiguity counts declarations, not bounds.** `<C: Collection + Sequence>` reaching the one `Sequence.Item` is accepted, two different `Item`s are `name.ambiguous` naming both, and none is `name.undefined` naming the bounds searched;
  2. **inherited associated types** resolve;
  3. **chained `T.Item.Key`** is `slice.not-yet` at `Key`, since an associated type can't carry a bound in today's grammar. Never `name.undefined`;
  4. **bare `Item` in a generic body** is `name.undefined` with a fix-it naming the one candidate, or listing every one (`as T.Item or U.Item`).
- **The rest:** a trait's own body and its conformances still name `Item` bare, and `Self.Item` in a trait now names its own or an inherited associated type.
- **Deferred:** these names are decided after every module is walked, since a bound's parent traits may sit in a later module.

**Typecheck:**
- **The key:** a new type kind, `Projection`, keyed by (the associated type's declaration, its trait, the base type), spelled `T.Item`.
- **Equality:** projections are equal only when their keys are, and no projection equals a concrete type, since nothing in the slice pins one.
- **Substitution** replaces the base first. A concrete base is replaced by its conformance's assignment, inherited ones included.
- U6b3's `slice.not-yet` for `s.take(v)` with `take(v: Self.Item)` is gone: a requirement called through `T` maps its trait's associated types to `T`'s projections, through one helper shared with `call_subst`, which MIR's verifier reads.

**Reading (reversible): a projection is NoCopy and meets no bound,** because no bound can say otherwise.
- A generic body writes `move v` to pass one on, a struct holding one declares its policy, and `Map<T.Item, _>` is refused.
- It's conservative and sound. Extending design 219's per-path copy rule to projections would need summary requirements on `T.Item`, which can come later.
- A trait's own `Self.Item` still copies silently, which is a pre-existing gap and unchanged here.

**Pins:**
- **resolve:** goldens `associated_types` and `associated_type_refusals` (every refusal message), plus 3 refusal fixtures;
- **typecheck:** golden `associated_types` (a single bound, two parameters, inheritance, the redundant pair, `s.take(move v)`, a generic instantiating a generic, and call sites substituting to `Int`, `String`, `(Int, String)` and `Int?`), plus `type.mismatch.projection`, `type.mismatch.projection-concrete` and `transfer.implicit-copy.projection`;
- three superseded `slice.not-yet` fixtures are removed, and the resolve lane's interface-note check moved to `T.Item.Key?`.

**Corpus,** with scratch copies rewritten to `T.Item`; `tests/corpus` is untouched and re-aimed at the next migration: `associated_type_generic` and `generic_instance_associated_type_return` check and lower clean, and `generic_instance_associated_type_binding` is refused only for `__saw_suspend`/`__saw_drive` (outside the slice).

**Validation**

- **The lead,** on a sawc2 built from 001510fa:

Approved patch SL-453.p1 (revision 1)

Approving SL-453.p1. `T.Item` does what W4 (a) says, and all four of my c2 pins behave as asked. The pre-existing gap the report names is worse than "copies silently": the MIR drops one value three times. I've filed it as **SL-458**. It's not introduced here, so it doesn't block.

**What I checked**
- **The gate** passed on the applied commit: tested_commit == applied_commit == 5bf82a1f. The tested tree, 6907dd93, is the tree I get when I apply the diff to b0ecfd96.
- **My own run:** `compiler/tests/run.py` is ok, including the resolve, typecheck (2,027 functions summarized), mir and std lanes.
- **Probes** (`.build/scratch/air-review/sl453/probes/`, sawc2 `mir --check`):
  - **Pin 1 (declarations, not bounds):** `<C: Collection + Sequence>` reaching the one `Sequence.Item` is accepted and lowers clean. `<T: Left + Right>`, each declaring its own `Item`, is `name.ambiguous`: "the bounds of `T` reach the associated types `Left.Item` and `Right.Item`".
  - **Pin 2 (inherited):** `<C: Collection>` names `C.Item` declared in `Sequence`, and lowers clean.
  - **Pin 3 (chained):** `T.Item.Key` is `slice.not-yet` at `Key`, never `name.undefined`.
  - **Pin 4 (bare fix-it):** with two parameters, "as `T.Item` or `U.Item`"; with one, "as `T.Item`".
  - **Absent:** `<T: Equatable>` gives "`T` has no associated type `Item`: its bound `Equatable` and the traits it refines declare none".
  - **Two projections:** `T.Item?` vs `U.Item?` is `type.mismatch`. A generic calling a generic (`outer` → `drain_one`, both `-> T.Item?`) lowers clean, as does `let a = move v` on a projection.
  - **A projection read by value without `move`** is `transfer.implicit-copy`. That's the same as a concrete NoCopy local (`a5_tail_local.saw` refuses the same tail `a`), so the NoCopy reading is uniform, not stricter for projections.
  - **The grammar backs "meets no bound":** `assoc-type-decl ::= 'type' IDENT` carries none.

**SL-458 (filed): a trait default body copies `Self.Item` silently, and the MIR drops the value three times** (`a4c_item_copy_policy_deinit.saw`).
- **The program:** `Token` declares `extension Token: NoCopy { func deinit … }`, and `Maker: Source` assigns `type Item = Token`. `Source.dup`'s default body writes `let v = self.make(); let a = v; let b = v`.
- **sawc2 accepts it.** `Source.dup` lowers once, generically, as `_5 = copy _2; _6 = copy _2; drop(_6); drop(_5); drop(_2)`. Instantiated at `Token`, that runs `deinit` three times on one value.
- **Stage 0 refuses both copies:** "cannot copy value of type `Token` which implements NoCopy" ×2, because it checks the body per conformer.
- **Nothing filed covered it** (SL-447's `Self.Item` item was the `slice.not-yet` renaming), so it's SL-458 now, with the repro, the mechanism, a sweep list and the ordering constraint.
- **The fix may be small now.** This patch built the projection kind and the NoCopy reading, and a trait's own `Self.Item` is the same projection with base `Self`. Answering NoCopy there too would close it. Either way, it's sawc2 accepting what Stage 0 refuses, in MIR that a backend will consume, so it should land before any backend reads default bodies.

**Non-blocking**
- **Error cascade:** after a refused return type (`-> T.Item?` ambiguous, absent or chained), each `None` body also reports `infer.failed`, five extra errors in `a2_refusals.saw`. An error-typed result could silence that.
- **Observation, not this patch:** with `extension Token: NoCopy {}` plus a plain `extension Token { func deinit(&var self) … }`, sawc2 accepts. The spec puts a hand-written `deinit` "inside the policy conformance". Worth a look at whether the plain-extension `deinit` is refused, or silently becomes an ordinary method (`a4b_item_copy_bare.saw`).
