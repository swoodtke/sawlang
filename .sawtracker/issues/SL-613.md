**F1. Two lane inputs the gate misses** (SL-606, bucket F, now). Findings: Tooling 5 and Tooling 2.

- **Tooling 5:** `SUITE_INPUTS["fixpoint"]` in `tools/patch_gate.py` lacks `tests/corpus/`, yet the replayed parse, eval, borrowck and drops lanes run sawc2 over it. So a corpus program that splits Stage 1 from Stage 2 never reaches the fixpoint. Add it.
- **Tooling 2:** `parse_lane.salt()` hashes only `GRAMMAR.md` and `grammar/*.py`. The records come from `recognize.check`, which lexes through `sawc2 lex`, so a lexer change leaves `.build/parse-lane/records.json` stale, and that can PASS a lexer change falsely. Key the salt on the lexer too: `compiler/lex/` and the sawc2 binary's identity, or whatever `build.py` already hashes for it.
- **Pins:** `./build.sh test --dry-run --diff tests/corpus/x.saw` names fixpoint, and a test shows that a change to a lexer source changes the salt.
- **Done when:** both hold.
