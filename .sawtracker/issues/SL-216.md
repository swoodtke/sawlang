A driven (coroutine-transformed) `match` over an OPTIONAL whose arm binds and USES the Some payload ICEs:

  internal compiler error ... (Identifier): Undefined variable: v

Minimal repro (pre-existing; reproduces on a clean tree with no SL-208 changes):

  import std.task.{yield_now}
  func maybe(x: Int) -> Int? { yield_now(); if x < 0 { None } else { x + 1 } }
  func pick(x: Int) -> Int {
      let r = match maybe(x) {
          case Some(v) -> v,        // <- ICE: Undefined variable: v
          case _ -> 0
      }
      r
  }
  func main() { print(__saw_drive(pick(4))) }

Both the let-bound and the tail-position spellings ICE at the arm; the scrutinee suspends (yield_now), so `maybe` is embedded and `pick`'s match is lowered into the resume state machine, where the `Some(v)` payload binding is not threaded into the arm body's scope.

NOT Optional-vs-Result-symmetric: the RESULT form `match f() { case Ok(v) -> v, case Err(_) -> ... }` with the same driving compiles and runs (verified). So the gap is the coro transform's handling of an OPTIONAL enum-pattern payload binding specifically (Some), where a driven Result Ok binding works.

Found while writing SL-208 regression tests; SL-208's match-arm acceptance cell uses the working Result form. Separate defect from SL-208's module-boundary divergence.
