## Description

Found while sweeping SL-640/SL-629 (agent t640testonly); not a test-only defect.

**Mechanism:** `static_call` (`compiler/typecheck/src/bodies.saw`) builds the owner with `named_owner`, which returns -1 for a generic type written with no type arguments (`G.f()`, `Box.make(...)`), and returns the error type after refusing an arity mismatch. `static_call` reads both the same way, `t < 0 || has_error(t)`, as "already refused", so the bare generic head is poisoned with no refusal: a sentinel that means two things. `typecheck --check` exits 0 and only the body verifier's INVARIANT lines show it; `sawc2 build` stops on them.

**Evidence** (`sawc2 typecheck --check --std-root std`, main at 65d3aba8b), a valid call:

```saw
struct G<T> {
    t: T
}

extension G {
    static func count() -> Int {
        3
    }
}

func main() {
    print("{}", G.count())
}
```

gives `INVARIANT p_static2 12:17 an expression's type is unresolved, but the module has no refusal` and `a call has no target`, rc=0. Stage 0 compiles and runs it. A missing static on the same bare head (`let b: Box<Int> = try! Box.new(1)`, `G.nope(1)`) gets the same INVARIANT lines instead of `member.unknown`; a non-generic `H.nope(1)` is refused `member.unknown` as it should be.

**Fix shape:** decide what a bare generic head means (Stage 0 accepts it: infer the arguments from the call and the expected type, as `init_call` does for a construction), and give "needs inference" its own answer instead of -1, so `static_call` either infers or refuses. Sweep the other `named_owner` callers for the same reading.

Pre-dispatch probes, on main (sawc2 built at 3d257ed12; nothing compiler- or std-side has landed since) and Stage 0. The probes are in `.build/scratch/air-review/sl657/` on the Air.

**Stage 0 is not a precedent for inference.** It accepts only the repro's shape, where a bare `extension G` never binds `T`. Every shape where inference would actually do something is refused or ICEs:

"INVARIANT" below means `typecheck --check` exits 0 and prints only the body verifier's INVARIANT lines, and `build` stops on them.

| shape | Stage 0 | sawc2 main |
|---|---|---|
| a. `extension G { static func count() -> Int }`, `G.count()` | runs, `3` | INVARIANT |
| f. same, under `extension G<T>` | ICE ``Undefined static method: G.count`` | INVARIANT |
| b. `extension G<T> { static func wrap(t: T) -> G<T> }`, `G.wrap(t: 5)` | ``argument `t` expects `T` but got `Int` `` | INVARIANT |
| c. `try! Set.of(5)` | the same refusal | INVARIANT |
| d. `let g: G<Int> = G.empty()`, `static func empty() -> G<T>` | ``cannot assign `G<T>` to variable of type `G<Int>` `` | INVARIANT |
| e. `G<Int>.count()` under a bare `extension G` | ICE ``Undefined static method: G$1$Int.count`` | runs, `3` |

**The spec decides a, b, c and f.**
- "Generic type-argument inference": inference applies to "generic free functions, methods, and constructors alike", and "Inference never guesses — a parameter no argument constrains (underdetermined) … is a clean error naming the parameter and suggesting explicit arguments."
- The spec writes a static on a bare generic head whose argument fixes `T` as the ordinary spelling: "spell empty/singleton collections `Map<K, V>()`, `Set<T>()`, `Set.of(x)`" (the `{ }` closure rule), and `Set.of(v)` again in Set's API list. So b and c should infer and run.
- So `G.count()` with nothing constraining `T` (a, f) should be refused, not accepted. That's sawc2's existing `infer.failed`, the refusal it already gives `Bag(n: 1)` and `pick()` for an unused `T`: ``cannot infer type argument `T` of `Bag`: nothing in the call determines it``. The issue calls (a) "a valid call"; under the spec it isn't. Accepting a static that names no type parameter would be a new rule, so it needs a ruling.

**d needs a ruling either way.** The declared slot at an initializer reaches "the constructor": the memberwise literal, a custom `init`, a generic enum's variant. A `static func` isn't on that list, so read literally, `let g: G<Int> = G.empty()` is underdetermined too. Extending the slot to a static call is the issue's "and the expected type", and that's a language change, not a fix.

**On the patch, I'll check:** b and c infer (c at typecheck level: `Set<Int>.of(5)` builds to `mono.not-yet` today, on the synthesized `Int` `hash`/`equals` slice, which is unrelated); a and f give `infer.failed` naming `T`; e still runs; `G.nope(1)` and `Box.new(1)` get `member.unknown`; no INVARIANT rows remain; and the sweep of the other `named_owner` callers has a row per caller.

**USER RULING (Oct 15): the spec reading, plus the expected type.**
- A static call on a bare generic head infers the type arguments from its arguments: `Set.of(5)` and `G.wrap(t: 5)` run (shapes b, c).
- With nothing constraining `T`, it is refused `infer.failed` naming `T`, as it is for `Bag(n: 1)`: `G.count()` under either extension form (shapes a, f).
- **Language change:** the declared type at an initializer also drives inference for a static call, so `let g: G<Int> = G.empty()` runs (shape d). The spec's list of what that slot reaches gains static calls, in the same patch.
- `G<Int>.count()` still runs (e); `G.nope(1)` and `Box.new(1)` get `member.unknown`; no INVARIANT rows remain; the sweep of `named_owner`'s callers has a row per caller (the Air's c1 checklist).
