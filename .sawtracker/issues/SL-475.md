## Description

**sawc2's MIR moves a matched borrow binding's referent out through its reference, then drops it.** Found by U6d2 (SL-460) in chat m401.

**Repro:**

```saw
borrow let lent = slots[i] {
    match lent {
        case Empty -> ""
        case Occupied(borrow let k) -> k.name
    }
}
```

The drops dump shows `_7 = move (*_6); switch discriminant(_7) …; drop(_7)` on both arms, where `_6` is the binding's reference into the vector slot. So the slot's value is dropped while the vector still owns it, which becomes a double drop once codegen exists. Inside an accessor the same shape makes `lend r` lend a dead temporary.
- **Corpus:** `tests/corpus/place_presence_test_borrows.saw` (`name_at`) and `tests/corpus/place_enum_payload_lend.saw` (`Table.at`, `lend r` from a match arm). Both are refused by `slice.not-yet` first, and U6d2's `lend.root` now refuses the second correctly.

**Mechanism (U6d2's reading):** the match lowering treats a scrutinee that reads through a reference (`(*_6)`) as consumable and dissolves it into a temporary, instead of matching the place in place. The initialisation analysis reads a move through a reference as a read, so neither the borrow check nor the verifier catches it.

**Sweep the class (obligation 4):** every pattern-matching head whose scrutinee reaches through a `Deref`:
- `match`, `if let`, `guard let`, `while let`;
- on a borrow binding (`borrow let`/`borrow var`), a reference parameter, a field through `&self`/`&var self`, a closure's `[&x]` capture, and a conditional lend's payload;
- with binding patterns (`borrow let`, by-value binds of Copy and non-Copy payloads) and with no bindings.

Each must match the place in place: a switch on `discriminant(*_6)`, with payload bindings as places or refs, never a move out.

**The verifier invariant:** refuse a `move` of an OWNING value through a `Deref` of a reference. A move of a non-owning value (a reference part, as in the accessor record's `move (*_1).0` epilogue, which is U6d1's `&var`-moves reading) stays legal. No typecheck-clean source spells the owning case.

**Scheduling:** a mir unit after U6d2, batched with SL-469's mir item (no consuming path through the escaping closure environment reference, plus an invariant). That is the same class: a move out through a reference.

**The closure case** is `tests/corpus/closure_deinit_called_then_dropped.saw`, which is exactly the spec's basic owning closure:

```saw
let r = Res(v: 7)                   // Res: NoCopy, deinit prints
let f = { [move r] in r.v }         // let-bound, so ESCAPING
print(f()); print(f())
// EXPECT: 7, 7, "deinit 7" exactly once
```

sawc2 lowers the body (`fn closure#0 of …main`) as:

```
_2 = move (*_1).0;      // the env's Res moved into a per-call local
_0 = copy _2.v;
drop(_2);               // a deinit on EVERY call
return;
```

So two calls plus the env's release make three `deinit`s of one value. **No consuming use is needed,** which is why SL-469's compile error doesn't reach it: the move is the lowering's, not the user's. The same body shape appears in all 13 closure sites: `closure_deinit_*` (7 files), `closure_escaping_move_capture_consumed_once`, and `unsaferef_captured_by_closure` (4).

**The mechanism** is the spec's "at body entry every plain / `move` / `copy` capture is loaded out of it into a per-call local", lowered as a MOVE for an owning type. For an escaping env (shared, immutable, released at the last owner), the load must not take ownership:
- a Copy-tier capture copies with a retain, and its per-call drop releases that copy;
- a NoCopy/ExplicitCopy capture is read as a PLACE through the env (`(*_1).0.v`), with no per-call local and no drop.

For a NON-escaping closure, the move-at-start is the spec's take-once transfer from the source frame, so it's legitimate there. The fix and the verifier must tell the two apart (env kind is known at lowering).

**Consequence for this issue's verifier invariant** ("a move of an owning value through a Deref"): it will flag all 13 escaping closure bodies. Either the lowering fix lands in the same change, or the invariant breaks the corpus. And the two drop-related verifiers (U6d1's and U6e's) were clean on this corpus because the shared analysis reads a move through a reference as a read, so this has been invisible to every check so far.

A pre-review note on the MIR unit brief (c3). Item 2's last bullet treats the non-escaping take-once `[move v]` as "a different shape … check that it stays correct". It isn't correct today, and item 3's invariant as written refuses any correct lowering of it. Both belong in the brief before the agent reaches item 3.

**The probe:** `.build/scratch/air-review/mir475/probe_take_once.saw`, with a `NoCopy` `Res { name: String }`:

```saw
func run(body: () -> Int) -> Int { body() }
func run_twice(body: () -> Int) -> Int { body() + body() }
func once() -> Int  { let r = Res(name: "abc"); run({ [move r] in sink(move r) }) }
func twice() -> Int { let r = Res(name: "abc"); run_twice({ [move r] in sink(move r) }) }
```

**sawc2 today** (main 87c4fa56; the typecheck is clean, since the closure doesn't escape; `drops --dump`):
- `once()`: `_3 = closure#0 [move _1]` moves `r` into the environment *at capture*.
- the body: `_2 = move (*_1).0` (through a shared `&(Res,)` env), and `sink` consumes it.
- `run`: `drop(_1)` with `glue () -> Int: closure environment`, which releases the environment and `r` with it.

So `r` is freed twice after a **single** call. `twice()` runs the body a second time with no occupancy check, moving out of freed storage again.

**Stage 0** (the oracle) prints 3 for `once()`. For `twice()`: `panic at probe_take_twice.saw:26: closure body ran twice on `move` capture `r`` (rc 134). Its mechanism is in `sawc/codegen/closures.py` (the comment above `_deferred_field`):
- A non-escaping closure's environment holds a *pointer to the enclosing local and a pointer to its drop flag*.
- The body's prologue takes the value and clears that flag. The flag doubles as occupancy, so a second run panics.
- The enclosing local stays drop-if-initialised, so a body that never ran leaves `r` to be dropped at the end of the enclosing scope.
- A non-escaping environment has no teardown.

The spec says the same thing as meaning, not as an implementation choice: "pass the closure straight to a non-escaping parameter, where a `[move r]` capture transfers **when the body runs**". Moving `r` into the environment at capture changes when `r` is destroyed whenever the callee never calls the body, so that alternative isn't open.

**What the brief should settle before item 3:**
1. **The take is a move of an owning value through a reference**, by construction: through the environment's pointer to the enclosing local. Item 3's invariant ("refuse a `move` of an OWNING value through a `Deref`") refuses it. Either make the take its own MIR shape (move-out + flag clear + panic on repeat), which the verifier admits and nothing else spells, or name it in the invariant as the one exemption beside the reference-part epilogue. I'd prefer the explicit shape, since then drops and borrowck see it rather than a hole.
2. **It reaches drop elaboration.** The enclosing local's drop flag is cleared by another function, the closure body, through a pointer. Today flags are locals that elaboration creates after lowering, so lowering can't capture one. Something has to give: a capture kind "take" that elaboration materialises (the flag and the body's prologue), or a flag MIR creates up front. That's design work, not a sweep item.
3. **Borrowck's reading:** statically `r` is moved at the capture (no later use), and dynamically it's maybe-moved (the drop decides at runtime). Say which analysis owns which half.
4. **Pins:**
   - `once()` drops `r` exactly once, from the body's take;
   - a callee that never calls the body leaves `r` to the enclosing scope's end;
   - `twice()` panics with Stage 0's message;
   - the escaping read-only `[move r]` from item 2 unchanged.

If the lead would rather keep this unit's scope, the minimum is to take the take-once row out of item 2's "stays correct", narrow item 3's proof to escaping bodies and match heads, and file take-once as its own issue with this probe. Otherwise the agent either fails item 3's "zero over the corpus" or carves an unprincipled exemption.
