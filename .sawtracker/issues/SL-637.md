**Symptom.** Any program that calls `__saw_suspend()` or `__saw_test_suspend()` fails MIR verification (sawc2 at 9734b1183, `--std-root std`):

```
func work() {
    __saw_suspend()
}
func main() {
    work()
}
```

`sawc2 mir --dump` prints `INVARIANT  a4_suspend  1:13 a4_suspend.work(): a call's suspension point disagrees with its callee's summary`, and so do `mono` and `coro`, since the stages before them run the verifier. One line per call: a function holding both intrinsics gets two.

**Mechanism: a bypassed funnel.** Every call constructor in `compiler/mir/src/lower.saw` sets the call's suspension flag through `build.saw:suspension(e, &var call)`, which asks typecheck's summaries (`eval_call` at the node). `builtin_call` (`MirCallKind.Builtin`) is the one constructor that never calls it, so a builtin call is always `MirSuspend.Never`. Since A2 (SL-553), typecheck summarizes the two test intrinsics as suspending (`summaries.saw:is_suspending_intrinsic`), and the verifier's `verify_suspension` evaluates the same summary and wants `Always`. The two disagree.

**Sweep.** The only builtins whose calls can suspend are the two test intrinsics (`res_test_intrinsics`). Under Stage 0's std (`--std-root sawc/std`), `sleep` is a builtin too, but typecheck refuses it first (`slice.not-yet`), so it never reaches MIR. Every other `blank_call(MirCallKind.Builtin, …)` site (`print`, `panic`, `assert`, `sizeof`, `alignof`, the builtin methods, the take-capture panic) never suspends. The class is these two, at one site.

**Fix.** `builtin_call` sets the flag through `self.suspension(e, &var call)`, as its siblings do. A MIR golden then shows `suspends` on both calls.

**Blocks:** SL-557 (A4a) lowering `__saw_suspend` as `park(ready)` and `__saw_test_suspend` as its effect-only no-op. coro never sees either call as a suspension, and the verifier stops the program before coro runs. A4a's own work avoids the file, since `compiler/mir/` is outside its list.
