**A3c. The `park` lowering for every reason** (back track; settled with the Air, t7).
- **Scope:** §3.9's "one lowering per case": one coro case per reason, each written and reviewed here, so "record before arm" is enforced per reason and A5's rule 4 checks each one.
  - *timer:* record the deadline;
  - *fd:* record `-1`, then call the executor's arm funnel `__saw_exec_io_register(fd, dir, token)`;
  - *channel:* record the readiness word's negated address;
  - *offload:* record `-1`, then arm the job's pipe through the same funnel;
  - *signal:* the fd case, reached through `SignalWatch.next`.

  Each case also reads its outcome on resume: ready, timed out, or cancelled. The std intrinsics name the reason and pass its operands; the executor functions each lowering calls are declared in std, and their bodies arrive with the std units (A11, A12a, A13a, A14b, A15). So the std units never touch `compiler/coro/`.
- **Depends on:** A3b.
- **Files:** `compiler/coro/src/lower.saw`, `compiler/tests/coro/golden/`.
- **Pins:** a lowered-MIR golden per reason, in which the record store precedes the arm.
- **Done when:** the five goldens are stable, and A5's rule 4 accepts them once it lands.
- **Estimate:** 1.

**Plan:** SL:coroutines §4, unit A3c (approved by the user, Oct 12). The plan text is authoritative; this issue is its tracker entry. Dependencies are named by unit id; see the epic's child list for their issues.

**For A3c's park operands, from the Air's review of A2 (SL-553 c11, finding 2).** `__saw_park_timer(nanos: Int)`, with `std/task.saw`'s `timer_nanos` saturating at `Int.max`, can't be observed only on a 64-bit target. On a 32-bit target, `Int.max` ns is about 2.1 s, so `sleep(Duration.seconds(5))` would silently return early. That is silent degradation, and kernels and embedded are first-class targets. The runtime seam under it is already `__saw_rt_sleep_ns(ns: UInt64)`.

So when A3c settles the operands, make the timer's operand `UInt64` nanoseconds, which costs nothing on 64-bit and removes the saturation. Delete `timer_nanos`'s saturation, or, if any narrowing is left, fix its comment's 'no observer can tell the two apart', which only holds on 64-bit.

**A3c stopped before any edit (agent:claude-sawlang/a3cpark), on a3c = A4b's tip 57270953c.** The unit as planned can't be built inside its file list (`compiler/coro/src/lower.saw`, `compiler/tests/coro/golden/`), and three of its contracts are unspecified. Nothing is committed.

**1. A park whose record and arm show in lowered MIR needs files outside the list.**
- `compiler/llvm/src/bodies.saw` `point_term` matches `CoroPointKind` exhaustively and emits the ready park's record itself (`store i64 0` through `%cx`). A golden "in which the record store precedes the arm", and A5's rule 4 over lowered MIR, need the record as a MIR statement. So MIR has to reach the root token: a local the resume entry loads from `%cx`'s first word, as it stores `%frame` into `_F` today. The backend's park point then only records the state and returns `Pending`. That's a backend change, plus `compiler/coro/src/{program,dump}.saw` for the new point kinds and their `--lowered` lines, and `compiler/tests/coro/README.md`, which specifies the lowering.
- **The arm has no callee.** The new std declares no `__saw_exec_io_register` (only Stage 0's `sawc/std/taskgroup.saw:542` does). And mono reaches an executor function only by name, per site kind (`compiler/mono/src/worklist.saw` `resolve_spawn`/`resolve_drive` → `exec_entry`). So the fd and offload arms need a declaration in `std/taskgroup.saw` and a mono rooting in `compiler/mono/src/{worklist,program}.saw`. c631attr holds mono's export roots, which may be in `worklist.saw`. The timer's "record the deadline" also needs a clock read (now + span), which is a call mono must root too.

**2. c2 (binding) crosses into the front track.** Changing the timer's operand to `UInt64` touches `std/task.saw` (`__saw_park_timer`, `timer_nanos`) and the role shape `ParkTimerFunction -> (params (nanos Int owned))` in `compiler/typecheck/src/lang.saw:193`, which `tc_check_lang_shapes` enforces.

**3. Unspecified contracts that need a ruling, or a reversible pick from the lead:**
- **Outcome on resume.** Every park role's shape returns `Void` (`typecheck/src/lang.saw:192-201`), so a "ready / timed out / cancelled" read has no destination. The executor also writes `PARK_UNSET` into the park word before every resume (`std/taskgroup.saw:471, 683`), so no channel exists from the executor back to the frame. Fixing this means one of two changes, each touching std plus typecheck's role shapes: an outcome return type with an encoding, or a context field.
- **The timer record on a 32-bit target.** The park word is `TaskContext.park: UnsafePointer<Int>`, with a timer recorded as a positive `Int` deadline. With c2's `UInt64` operand, a 32-bit target still can't record a nanosecond deadline in an `Int` word (about 2.1 s of range). So c2's goal isn't met unless the deadline gets a wider word: widen the park word, or add a deadline field to `TaskContext`. That's std's vocabulary, owned by A11.

**Air, on the three contracts (asked in m560):** no objection to any of them. Two of them carry constraints the patch should meet, and the third an obligation for a later unit. Read on main.

1. **The outcome deferred to A10/A11:** agreed. A7b's executor writes `PARK_UNSET` before every resume, and nothing produces a non-ready outcome before A10 and A11, so a read added now would have no writer.

2. **`TaskContext.deadline: UInt64`:** agreed, with three constraints.
   - **Append it after `task`.** The backend reaches the park word as `TaskContext`'s first field, with no offset: `point_term`'s `ParkReady` arm (`llvm/src/bodies.saw`) does `self.load("ptr", "%cx")` and stores through it. A field inserted ahead of `park` would silently make that read the wrong word. Better still, have the root-token local the amendment adds read `park` by its field offset rather than as offset 0.
   - **Every construction gets the field:** `new_cell` (`std/taskgroup.saw`), whose context sits inside the heap `TaskCell`, and A4b's `drive_frame`, which builds one on the driver's stack.
   - **Type the record store at `Int`, the target's width.** Today's `ParkReady` stores `i64` into the `Int` park word. That's right on every 64-bit target, but on the 32-bit target this contract is written for, it would also overwrite the `cancel` word after it in `TaskCell`. Moving the ready park's record into MIR, as the amendment does, should type it as `Int`. Worth a look in the golden.

3. **The token is `cx.park` as an `Int`:** agreed. For a spawned task that's `&cell[0].park` (`new_cell`), heap storage that lasts as long as the task. In a drive point it's `drive_frame`'s local, which lasts for the whole drive, and any non-ready park panics there (SL-645). In A3c each arm panics, naming its unit, so nothing registers yet. **Obligation for A12a/A13a:** once a registration is real, it must be withdrawn before its cell is freed (the task ends, or is cancelled), or the reactor will write a wake into freed memory. Their pins should include a task that ends or is cancelled while registered.

Approved patch SL-556.p1 (revision 1)

**Approved.** Each of the three contracts in c4, with my c5 constraints, is met, and the probes agree with main and Stage 0 wherever both lower. Two documentation notes, neither blocking, are at the end.

Probed with this patch's Stage 2 (applied with `--3way` to 093c2ed2f; compiler-wise that's main) against main's, at -O0 and -O2, and with Stage 0. The probes are in `.build/scratch/air-review/sl556/pr/` on the Air.

**The contracts:**
- **`deadline: UInt64` follows `task`, and nothing depends on the order any more.** The backend's `ParkReady` arm, which read the park word as `%cx`'s first word, is gone. Every record is a MIR place, `(*(*_C).park)` and `(*_C).deadline`, projected by field, so the layout supplies the offset. That's my first c5 constraint met in its stronger form. Both constructions, `new_cell` and `drive_frame`, set the field.
- **The record is typed at the target's `Int`.** `coro_record_word` stores a constant of `int_type()` through a place of that type: `const -1: Int` in the goldens, and the deadline is `UInt64`. sawc2 describes only LP64 targets so far (`mono/src/api.saw`), so there's no 32-bit build to probe. The typing holds by construction.
- **Record before arm, per reason.** In `park_fd.lowered`, the deadline (`const 0`, or the bound operand) is recorded, then the word `-1`, then the token `_t = cast(copy (*_C).park as Int)`, then `__saw_exec_io_register`, and only then the park call. The offload park records before both the pipe call and the arm. The timer computes its deadline, then records the deadline and the marker `1`. No arm in this unit registers anything: `__saw_exec_io_register` panics naming A12a, and `__saw_exec_offload_pipe` panics naming A14b. The withdrawal obligation (A12a/A13a) is written at the arm, where its implementer will see it.
- **c2's `UInt64` operand:** `sleep` passes `duration.as_nanos()` straight through, `timer_nanos` and its saturation are gone, and the role shapes match. `__saw_exec_timer_deadline` saturates only at `UInt64.max`, about 584 years.

**Runtime probes** (sawc2 at -O0 and -O2; NoCopy values with a printing `deinit`):

| probe | Stage 0 | main | patch |
|---|---|---|---|
| q1: `__saw_drive` of a frame and its child holding owning values across 3 ready parks | `drop 11, drop 1, drop 101, drive 113, end` | same | same |
| q2: `Task.spawn` of the same, joined from a suspending `main` holding a value | `drop 12, drop 2, drop 102, task 116, main holds 7, drop 7` | same | same |
| q3: a spawned task that sleeps holding a value | `before, drop 3, joined 3` | `coro.not-yet` at the `sleep` | `before`, then ``panic at taskgroup.saw:564: executor: a task is parked on a timer, which this executor does not wait on yet`` |

q3 moves a compile-time `coro.not-yet` to a run-time panic naming the reason, as c4 scoped it (SL-645, A11 pending). The clock seam links, since `clock.o` is in the runtime manifest, and the deadline call runs before the park.

**Gate checks:** `corpus.py` passes all 17 changed `.saw` files, and `astdiff` passes. Nothing else references the deleted `suspend_park_point.saw`: no `corpus_expected.tsv` row and no run-lane list.

**Notes, not blocking:**
1. `compiler/tests/run/README.md` (the paragraph that ends ``pin the refusals at a build``) still lists `suspend_park_point` among the due programs, as "a timer park". That program is deleted, and the timer park now builds. Fold the fix into the next edit of that sentence (A9 or A14 flips its other two members).
2. `TaskContext.deadline`'s doc says it's "0 when its park has none". Only the timer, fd and offload lowerings write it, so after a timer park, a ready or channel park leaves the old deadline in place. That's harmless today: the vocabulary reads the field only under the markers `1` and `-1`, and both lowerings write it. But A11, which owns the encoding, should either reword the doc or have every park write the field.
