## Description

**A long line written to a non-blocking standard error is cut silently: `__saw_rt_write_error` returns on the first write that would block.** Found by the reviewer while approving SL-1120.p1 (Nov 14); not caused by that patch, but that patch is what makes an `Err` line long enough to meet it.

**Run (the reviewer's, chat files f116 the driver and f117 the program; macOS arm64).** A `main` returning an error of 1,000,004 bytes, with standard error a pipe whose write end is `O_NONBLOCK`, read a second late: 65,536 bytes arrive, with no `…`, no line break, exit 1. An error of 3,004 bytes or less arrives whole (it fits the pipe).

**The mechanism (obligation 4).** `runtime/shim.c` has two sinks. Standard output's (`saw_writev_all`) treats `EAGAIN`/`EWOULDBLOCK` as "not a failure of the write": it waits for the descriptor (`saw_wait_writable`, a `poll` on fd 1) and goes on, with the comment "An inherited descriptor in non-blocking mode answers EAGAIN". Standard error's (`__saw_rt_write_error`) retries only on `EINTR` and returns on any other failed write, so once the pipe is full the rest of the line and its line break are dropped. It is the sink of a panic's message and of the entry's `error: ` line. So the class is: an output sink that does not wait on a descriptor that would block; the sweep is every `write`/`writev` to fd 1 or fd 2 in `runtime/` (and what `host_linux` and `host_macos` add), each listed with what it does on `EAGAIN`.

**The fix (lead's choice of the reviewer's two endings: the write waits).** `__saw_rt_write_error` waits for fd 2 when a write would block, as the standard-output sink does for fd 1: `saw_wait_writable` takes the descriptor, and both sinks call it. A reader that has gone away still ends the write (`EPIPE`), and a blocking descriptor behaves as today. For a panic this means the message is written whole before `abort`, where today a full pipe cuts it; a panic already waits on a blocking descriptor, so nothing new can hang that could not before.

**The spec** ("The entry point": "The error is written whole, however long its rendering is") is then true as written; no sentence is added.

**Pins.** A custom check in the run lane beside `check_main_error_bounded` (`compiler/tests/run/run_lane.py`): the reviewer's program with standard error a non-blocking pipe read late arrives whole with its line break, exit 1; the same for a panic's message longer than a pipe holds if one can be made (a panic's message is bounded at 508 bytes, so say whether any path writes more than a pipe's capacity through this sink: if none does, the entry's line is the only row). Linux: the lane's Linux run covers it when the VM is up; say whether a pipe's capacity differs there in a way that changes the row.

**Stops.** `saw_wait_writable` is used where a wait would be wrong (a signal handler, the crash path); the freestanding or provider builds compile `shim.c` without `poll`.

**Gate.** `compiler/tests/run.py --only seed,units,golden,subset,fixture_whitespace,std,comments,programs`; `tools/battery.sh citations abidoc` (the runtime's ABI document, if the seam's contract text changes).

**Files:** `runtime/shim.c`, `compiler/tests/run/run_lane.py` and its README, a probe under `compiler/tests/run/probes/`; `runtime/ABI.md` only if it states what the error sink does on a failed write.
