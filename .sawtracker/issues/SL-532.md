**Found by:** the lead flagged it in the SL-519 review, and the Air showed it to be a hazard (SL-519.p1 approval; repro in `.build/scratch/air-review/sl519/hijack/` in the Air's checkout). **Area:** sawc2's resolver, bare-import search (`compiler/resolve/src`, `res_find_beside`), and Stage 0's equivalent.

**The defect:** the spec's bare-import search is the importing file's own directory, then its package root (`src/`), then the configured search paths. sawc2, copying Stage 0, also searches the ENTRY file's directory, between the importing file's directory and the package root.

**Why it's a hazard, not just a divergence:** a library module `libpkg/src/sub/a.saw` writes `import util`. Its package root holds `libpkg/src/util.saw` (`tag()` returns 2), and the application beside the entry file holds `app/util.saw` (`tag()` returns 1).
- By the spec, the answer is 2.
- Both compilers give 1. sawc2's resolve dump binds `libpkg.sub.a`'s `util` to a module named plain `util`, the entry directory's file, and never loads `libpkg.util`.

So a dependency's bare import binds to whichever same-named file sits beside the program compiling it. A library's meaning depends on its client, and an application can replace a dependency's module without meaning to.

**Fix:**
1. **sawc2:** drop the entry-directory step, so the search follows the spec exactly. Sweep what relies on it: multi-file corpus programs, `compiler/tests/resolve` fixtures, and the compiler's own build, which uses `--module-path`, so it shouldn't. For each that breaks, decide whether it relied on the hijack (rewrite the program to a spelling the spec gives) or exposes a real gap (report it).
2. **Pins:** a resolve fixture reproducing the Air's shape, where the library's own `util` wins, plus an entry-adjacent `util` that a bare import from the ENTRY file itself still finds (its own directory).
3. **Stage 0 is frozen:** an SL:hazards entry (silent, since a different module binds), naming the shape and the safe spelling: inside a package, use the self-named `import <pkg>.x`, as Blade now does.

Pairs with SL-531, which records Stage 0's entry-file resolution as a hazard; one entry may cover both.
