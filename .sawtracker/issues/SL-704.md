**S5. Sweep Stage 0's std for everything the new std still lacks, and plan the ports** (unit of SL-596; Sonnet, read-only; user Oct 15: "we should do a sweep of the stage 0 stdlib too - and port anything which is suitable e.g. json, etc").

The new `std/` has 25 modules against Stage 0's 34 (`sawc/std/`). Missing on Oct 15: `arc` (S2), `cbor`, `channel` (A13a), `directory`, `fixedbuf`, `float`, `json`, `net` (A12a/A12b), `numeric`, `serde`, `signal` (A15?), `slab`, `time` (A11, submitted), plus `compiler/` (std.compiler.frame) and members missing from modules that exist (Vector: S3/S4; String, Data, Command).

**The sweep produces one table, posted on SL-596**, one row per missing module (and per module with missing members):
- **demand:** how many tracked programs import it or use its names, from `compiler/tests/corpusdiff/corpus_diff.tsv`'s refusal details (`no module std.X`, `cannot find X`, `has no method`) plus a grep of `blade/`, `libs/` and `tests/corpus/`;
- **dependencies:** what it needs from the language or other modules: traits (`Serialize`/`Deserialize`/`Encoder`/`Decoder` for serde, json and cbor), closures that capture owning values (SL-525), `LendingIterator` (S4), externs or runtime seams, statics, generics depth;
- **feasibility today**, probed, not guessed: copy the module (or its smallest self-contained part) into a scratch std root and build a small user of it with `sawc2 build`. Record the first refusal or ICE;
- **owner:** already a unit (name it), or a proposed new unit with its tier (Sonnet if it's a port of a clear Stage 0 reference with no compiler change; Opus if it needs a compiler feature first), and its order (what blocks what).

**Not in scope:** porting. The lead files the port units from the table. Nothing tracked changes.
