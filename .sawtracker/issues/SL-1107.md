## Description

Found by SL-457 U2b's agent (Nov 14) while probing cycles; it is older than that unit (the same on the compiler before its change). **Evidence** (probes under `.build/scratch/p457u2b/` in the lead's checkout): `enum E: UInt8 { case A = E.A }`, and two raw-backed enums each of whose case names a case of the other, make `sawc` exit 139 (a segfault, by its shape a recursion with no end) where a static's cycle is refused cleanly (`static.cycle`: `static X: Int = Y`, `static Y: Int = X`). **Expected:** the same refusal a static's cycle gets, naming the cases in the cycle. **The mechanism to confirm:** statics are evaluated under an in-flight marker (`static.cycle`); a raw case's value is folded by `evaluate_raw_case` / `fold_member` with no such marker, so a case that reads itself recurses. Since SL-457 U2b the pre-signature pass evaluates every raw case ahead, so this is met on every build of such a program, not only one that reads the case. **Sweep (obligation 4):** every other constant the fold evaluates on demand with no in-flight marker (an `@align` argument naming a static that names it, a const parameter's default, an alias construction over a cyclic static): one probe each. **Pins:** refusal fixtures for the self cycle, the two-enum cycle and a case-static-case cycle.

**Implementation detail (lead, Nov 14): a raw case whose value depends on itself is refused at its declaration, and nothing that reads it recurses.**

**The rule that exists.** A raw case's value is a constant expression that may name a case of its OWN enum and nothing else declared: a static or another enum's case is `static.not-constant` "it may not name a static or another enum's case, since an enum's cases are fixed by its own declaration, before either is known" (`constant_offender`, position `RawValue`; fixtures `static.not-constant.raw-case.saw`, `.raw-static.saw`). A sibling named either way round builds (`case A = E.B + 1; case B = 4`, and the reverse).

**The lead's probe, on the Stage 2 in the lead's checkout** (`.build/scratch/p1107/probe_cycles.py`, 26 shapes; `cycles_today.txt`). Exit 139 for every one of these:

| shape | today |
|---|---|
| `case A = E.A`; `= E.A as UInt8`; `= E.A + 1` | crash |
| two siblings naming each other; three in a ring | crash |
| `case A = 1; case B = E.A \| E.B` (a flag naming itself) | crash |
| two enums, each case naming the other's (`case A = F.B` / `case B = E.A`) | crash, where one direction alone is `static.not-constant` |
| a self-naming case USED in a length, a repeat count, a static's value, a `static_assert`, a generic argument (`B<E.A + 0>`) | crash |

The statics' twins are refused cleanly today: `static S: Int = S` and a pair are `static.cycle` "static `A` depends on itself: `A` -> `B` -> `A`; ..."; a cycle through a type (`static N: Int = sizeof<[UInt8; N]>()`, a const default naming a static that measures the struct) is `static.cycle` "depends on itself, through a type its own initializer names".

**The mechanism (obligation 4), by reading; step 0 confirms it.** The fold follows a declaration to its value at two places in `compiler/typecheck/src/fold.saw`. `fold_static` checks and extends `chain`, the declarations being folded, and answers `TcFault.Cycle`. `fold_member`'s raw-case branch does `self.fold_at(self.raw_value_node(c), &var chain)` with no entry in `chain`, so a case reached again is folded again without end. The ahead pass has its own guard (`evaluate_raw_case`'s `Typing` state), so the recursion is the fold's, not the pass's. The two-enum shape shows a second thing: something folds the foreign case BEFORE the rule that refuses naming it is asked. The siblings of the mechanism to sweep are every place that follows a name to another declaration's value: the fold's two branches; `adopt_lone_case`; the duplicate-value check (`check_raw_values`, `bodychecks.saw`); `E.from(raw:)`'s table; the evaluator stage's read of a case (`compiler/eval/`); the small folder (`build_const` or what SL-457's U3 leaves of it); whatever `sawc typecheck --dump` prints for a case's value. For each, say whether it reads a finished value or follows the node, with a run.

**The fix.**
1. A raw case is on the fold's chain exactly as a static is: `chain` holds declaration ids, so a case's id goes in the same list, and reaching one already there is `TcFault.Cycle`. One helper beside `fold_static` (its twin), used by every place the fold follows a case.
2. **The diagnostic is one error per case on a cycle, at that case's value, with the statics' rule id and shape:** `static.cycle`, "the raw value of `E.A` depends on itself: `E.A` -> `E.B` -> `E.A`; a raw value is fixed at compile time, so it may name only cases whose own values do not lead back to it". Read how a static's cycle is detected and worded (`statics.saw`, `evaluate_static`; the path print) and reuse its path-building; the wording above is the target, adjust it to the existing sentence's shape and quote what you chose. No new rule id.
3. **A USE of a case on a cycle adds no error and does not crash:** a length, a repeat count, a static's value, an assert, a generic argument, a match arm, `as`. The statics' rule is the model: "one already evaluated is on a cycle, which its own declaration refuses" (`statics.saw`). One program with one self-naming case used in all of those positions prints exactly one error.
4. **Two enums naming each other** print the existing `static.not-constant` once per offending case (two errors), no cycle message, no crash: the foreign name is refused before anything follows it.
5. The duplicate-value check says nothing about a case with no value.

**Not in scope:** the rule itself (what a raw value may name); `slice.not-yet` for a member inside a layout query's type (`case A = sizeof<[UInt8; E.A]>()`), which is SL-457's.
