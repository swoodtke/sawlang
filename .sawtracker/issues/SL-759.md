## Description

sawc2 refuses `==` on a fixed array (`operator.undefined`), while Stage 0 accepts it and sawc2 accepts an `Equatable` bound at the same array type. Found by p754 (SL-754): in `resolve_comparison` (`compiler/typecheck/src/bodies.saw`), the structural-Equatable fallback admits only Nominal and Tuple types, so an array is never routed through `structural_trait`'s Equatable grant. Fix: the fallback asks the same funnel the bound does. Probe the other kinds `structural_trait` covers (Optional `==` works; check `!=` and the array-of-tuples cases) per obligation 4.

Approved patch SL-759.p1 (revision 1)

**Air: SL-759.p1 r1 approved; arming it.** `compares_in_place` is now the one predicate that decides bit equality, shared by `resolve_comparison`, `builtin_comparable` and the backend's `memory_comparison`, with the backend's `comparable_bits` deleted. It compares part by part (`icmp`, Float `fcmp`), not as raw memory, so padding can't leak in. Only fieldless or raw-backed enums count as bits, and a type with its own `Equatable` or holding a String, array, closure or reference goes through `equals`.

**Probes** (`air-review/sl759/matrix.saw`; on d1ce9637d = main + r1, both stages rebuilt): byte-identical to Stage 0 at -O0 and -O2.
- **Optional:** a `None` reached by assigning `None` over `41`, compared with a fresh `None` (`true`/`false` for `==`/`!=`), and against `Some(41)` (`false`). A stale payload doesn't leak.
- **Signed zero:** `Pt { x: -0.0, y: 1 } == Pt { x: 0.0, … }`, `(-0.0, 2) == (0.0, 2)` and `Float?(-0.0) == Float?(0.0)` are all `true`.
- **A hand-written `equals` reached through a part:** a tuple `(Ci, Int)`, an array `[Ci; 2]`, and `Ci?` against `Ci?` and `None`, where `Ci` compares by length. All use `Ci.equals`.
- **Arrays:** `==` and `!=` on `[Int; 3]`, a struct holding one, `[(Int, String); 2]` equal and unequal, and generic `same` over `[Int; 2]` and `(Ci, [Int; 2])`.
- **`String?`:** Some against Some, Some against None, and None against None.
- **Still refused, as Stage 0 refuses:** a struct holding a String-carrying field with no `Equatable` (`operator.undefined`), and `Box<Int> == Box<Int>`. So the predicate doesn't make a pointer-holding type comparable by identity.

**Checks:** `run.py --only resolver,typechecker,mir,eval,borrowck,drops,mono,coro,programs,std,std_cone,subset` ok. `corpusdiff.py gate --no-build` holds all 2661, and none of the three rows moving to pass is in gmgate's lists.
