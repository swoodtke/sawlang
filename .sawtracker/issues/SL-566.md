**A9 implemented (a9budget), committed in the worktree as 8a0e9e6a9 on origin/main, not submitted.** Three things for the lead and the Air:

1. **The forced yield lands one iteration later than Stage 0's.** MIR places each op-budget point at the backedge and at each `continue` (SL:architecture §3.5), while the spec ("Pure compute") and Stage 0 put the check at the TOP of each loop body. With the counter at 128, as the plan says, the yield COUNTS match Stage 0 exactly for every loop that exits through its condition (`__saw_drive_steps` agrees on every pin: 127 * 128 iterations give 127, 127 give 0, 128 give 1, 1,000 give 7, the nested and `continue` shapes agree), but a forced yield comes after the 128th body instead of before it. A probe printing bodies 125 to 129 beside a spawned sibling prints `sibling` after `body 127` under sawc2 and after `body 126` under Stage 0. No pin I added shows it; a corpus program asserting an exact interleaving inside a loop would. Options: (a) accept it as "language changed" and reword the spec to "between iterations, at each backedge and `continue`"; (b) move MIR's point to the body's entry. I did neither; this wants a ruling.
2. **How `cancelled()` is recognised (reversible).** A2 made `cancelled()` a std function whose body calls the `__saw_cancel_requested` role, so in a framed task the role call sits in an unframed item, with no `cx`. `coro_cancel_read` therefore takes the role call itself, or a call of a std function with no parameters whose body only returns the role call's result. That is a shape match, kept inside `compiler/coro/`. The cleaner alternative binds the role to `cancelled` itself (resolve's lang row, plus `std/task.saw`), outside A9's files. As in Stage 0, a `cancelled()` inside a sync helper a task calls still answers `false`.
3. **The value-producing `break` row can't be pinned:** sawc2's typecheck refuses any `break` with a value as `slice.not-yet` (filed as SL-674, with the spec-derived probe in its c1). The spec's "Not yet supported" entry for it stays.

`taskgroup_compute_preemption` waits on A8b. Meanwhile the run lane's `background_compute_preemption` (the same program over `Task.spawn`) and `op_budget_counts` (the stage0/p5_budget reconstruction, which prints 127 and then 0, since the original probe's file is gone with the planning worktree) pin the budget against Stage 0.
