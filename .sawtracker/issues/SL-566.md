**A9 implemented (a9budget), committed in the worktree as 8a0e9e6a9 on origin/main, not submitted.** Three things for the lead and the Air:

1. **The forced yield lands one iteration later than Stage 0's.** MIR places each op-budget point at the backedge and at each `continue` (SL:architecture §3.5), while the spec ("Pure compute") and Stage 0 put the check at the TOP of each loop body. With the counter at 128, as the plan says, the yield COUNTS match Stage 0 exactly for every loop that exits through its condition (`__saw_drive_steps` agrees on every pin: 127 * 128 iterations give 127, 127 give 0, 128 give 1, 1,000 give 7, the nested and `continue` shapes agree), but a forced yield comes after the 128th body instead of before it. A probe printing bodies 125 to 129 beside a spawned sibling prints `sibling` after `body 127` under sawc2 and after `body 126` under Stage 0. No pin I added shows it; a corpus program asserting an exact interleaving inside a loop would. Options: (a) accept it as "language changed" and reword the spec to "between iterations, at each backedge and `continue`"; (b) move MIR's point to the body's entry. **1. Blocking: driving a `-> Never` body compiles and hangs** (conformance row D12, `b10_drive_never.saw`).

```saw
func halt() -> Never { while { yield_now() } }
func main() { __saw_drive(halt()); print("driven") }
```

- **Stage 0:** `a task body may not be \`Never\`: \`halt\` never returns, so \`__saw_drive\` would drive it for ever`.
- **Main:** refuses it, but only because the loop's budget point was `coro.not-yet`.
- **Patch:** builds it, and the binary was still running when killed at 5 s.

**Mechanism:** the typechecker's Never-body funnel (`refuse_never_task_body` in `compiler/typecheck/src/bodies.saw`) lists only `task_spawn` as an entry point. The drive forms bypass it, and the budget refusal was standing in for it.

D12 itself shows as `crash INVARIANT` in the differential only because its `halt(n: Int)` never reads `n` (item 2).

**Ask:** route `__saw_drive` and `__saw_drive_steps` through the funnel (add them to its ENTRY POINTS), with D12 as the pin. This patch removes the accidental refusal, so the row should not regress in it.

**2. Ask: fold in or file. Verifier rule 2 rejects a parameter the body never names.** Three programs (D12, `coro_done_path_releases_in_scope_order`, and my `b4_unused_param`) fail with:

> `verify rule 2 (teardown by state): …: _1 may be initialised at state 1 (bb…), but lives on the resume function's stack, which the suspension loses`

This predates the patch: main fails the same way with an explicit `yield_now()` and no loop (`b6_unused_yield`). Main compiles all of these correctly:
- a parameter read only before the suspension;
- a local written and never read;
- a local read only before it (`b11_dead_trivial`).

**Mechanism:** `coro_verify_residents` builds its slot map only from the places the body names. `frames.saw` lays out every parameter by kind, so a never-named parameter has a frame slot that the map shows as `-1`. Rule 2 then reports it as stack-resident.

**Why it matters now:** A9 makes every loop in a framed body a suspension, so `func worker(id: Int) { while … }` spawned with an unused id now fails with an internal-invariant error instead of building. The fix belongs in `verify.saw`, which this patch already edits: take a never-named parameter's (or result's) slot from the layout. Pin `b4`'s shape. If you'd rather not widen this patch, please file it.

**3. Existing faults, not this patch's.** Each is the same on main once the loop is out of the way:
- **Timer parks (7 programs):** the executor panics with `parked on a timer, which this executor does not wait on yet`. Main does the same for a driven `sleep` with no loop (`b9_sleep`). This is A11's, SL-568.
- **A shadowed binding's drop order (2 programs:** `conformance/K70_driven_scope_end_release_matrix`, `coro_frame_local_released_at_scope_end`**).**
  - sawc2 releases `let s = …; let s = derive(s)` at scope end, the second binding first. That's in sync code too (`b8_exposed`).
  - Stage 0 releases the first `s` at the rebind.
  - LANGUAGE_SPEC ("The compiler inserts `deinit()` calls at every scope exit", "Each scope releases its own bindings in reverse declaration order") reads as sawc2's order.
  - So these want a `stage0-wrong` annotation. That needs an id, so the lead files the issue or hazard first.
- **Refusal tests that now build (2 programs):**
  - `errors/coro_guarded_arm_owning_payload` is a Stage 0 limit (SL-283). With `sleep` swapped for `yield_now`, sawc2 prints the file's own intended output, `plain r0 / drop r0 / guarded r1 / drop r1 / plain r2 / drop r2 / 1` (`b7_guarded`).
  - `while_let_tuple_over_suspension_refused` is the limit this patch lifts in the spec.
  - corpusdiff has no annotation kind for "Stage 0 refuses what sawc2 lowers". Both could be `stage0-wrong` rows citing SL-283 and SL-566, or SL-666 adds a kind. Before SL-666 freezes the baseline, both need one or they stay `wrong` for good. Not blocking here.
