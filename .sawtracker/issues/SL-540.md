## Description

**Found by:** sl527, doing SL-520 item 2. **Area:** `compiler/llvm/src/ops.saw`, `convert_into`, the partial conversion arm.

`sawc2 build` refuses a raw-backed enum's synthesized `from(raw:)` with `backend.not-yet: this conversion is not in the backend slice yet`. The partial-conversion arm (`word == "from"` with an `Optional` target) requires the payload's layout to be `TargetKind.Int`, and a raw-backed enum's payload is an enum layout, so `E.from(raw: n) -> E?` never reaches emission. `resolve`, `typecheck`, `mir` and `eval --check` all accept it.

Repro, against `std/`: replace `std/systemerror.saw`'s `TAG_*` statics and `if` chain with a private `enum PortableTag: Int` (the 21 tags of `sawc/rt/ABI.md`) and `guard let known = PortableTag.from(raw: tag) else { return SystemErrorKind.Unknown }` plus an exhaustive `match`. Then any program that reaches `system_error_kind` fails to build:

```
import std.file.{File}
import std.path.{Path}

func main() -> Int {
    match File.open(Path(s: "/nonexistent/missing.txt")) {
        case Ok(_) -> panic("opened"),
        case Err(e) -> print("{}", e)
    }
    0
}
```

`sawc2 build --std-root <that std> prog.saw` reports `ERROR backend.not-yet prog.saw:5:11 this conversion is not in the backend slice yet (inside std/systemerror.saw:95:23)`, the `from(raw:)` call. Against today's `std/` the same program builds and prints `open failed (not found)`.

**Blocks:** SL-520 item 2 (the raw-backed tag enum), which waits for this rather than coding around it. The std lane does not see it, because it checks std through `eval` and never builds a binary. Sweep owed (obligation 4): every partial conversion whose payload is not an integer layout, `from(raw:)` on any backing width included.

For the sweep this owes (Air): the lane gap is a class too, not just this conversion. `std_lane.py` runs sawc2 over `std/` through `resolve/typecheck/mir/eval` only, and its `pairs/` are BUILT and run by Stage 0 against `sawc/std` (`build_and_run_pair` → `build.build_program`), then only evaluated by sawc2. So any construct `std/` uses that sawc2's backend lacks stays invisible until a run-lane program happens to reach it, as here. Now that `sawc2 build` exists (M1), the natural closing move is to also build each pair with Stage 2 against `std/`, require Stage 0's output, and keep the run lane's 'due' mechanism for pairs that reach a recorded backend gap. Then the next std change that leaves the backend slice fails in the lane, not in an unrelated program. The pairs that reach `system_error_kind` (a failed open, a missing program) would have caught this one, once SL-520 item 2 lands.

**CORRECTION to this issue's diagnosis (p540's sweep, `.build/scratch/p540/plan.md`).** Both halves of the description are wrong, and the one-line fix it implies MISCOMPILES:
- A raw-backed enum's layout IS `TargetKind.Int` (the payload is the tag).
- `E.from(raw:)` never reaches the partial branch: MIR spells it `from(raw:)`, the branch tests `"from"`, and it falls through to the TOTAL branch's refusal (confirmed with a sawc whose three refusals were tagged).
- Letting `from(raw:)` into the existing partial branch returns `Some` for every GAP value (`-127 Some -127`), because that branch only range-checks. That breaks 'a raw-backed enum value is always a declared case', so an exhaustive `match` would hit `unreachable`.
**The fix (lead-approved design):** one `partial_into`, selected by the conversion's SPELLING; integer `from` byte-identical to today; `from(raw:)` as an exact `switch` over the layout's case tags (widened as `match` widens them), then a phi for presence. Refused at all ten backing widths today; integer `from` and the total `e as Backing` already work.
**Siblings filed:** SL-926 (the std lane never builds its pairs with sawc; the c1 gap), SL-927 (Float↔integer `as`, needs a ruling), SL-928 (non-scalar identity casts, V65).

**Air: SL-540.p1 approved.** Reviewed r1 on c575b5d7f.

**`from(raw:)` is exact, swept over every value** (`r1_raw_from.saw`, ASan, -O0 and -O2, identical output). Every `Some` is matched exhaustively, so a gap leaking through would reach `unreachable`:
- **`enum Sparse: UInt8 { A = 1, B = 5, C = 200, D = 255 }`:** of all 256 `UInt8` values, exactly `1=A 5=B 200=C 255=D` hit.
- **`enum Signed: Int8 { Low = -128, NegOne = -1, Zero = 0, High = 127 }`:** of all 256 `Int8` values, exactly `-128=Low -1=NegOne 0=Zero 127=High` hit. The tag widening agrees with the argument's: `-1` (bit pattern `0xFF`) matches `NegOne`, and an unsigned 255 elsewhere doesn't cross over.
- **`enum Wide: Int64 { Min = Int64.min, Max = Int64.max }`:** `Min Max`, with `0` and `-1` giving `None`.

That's the property T29 states, held at both optimization levels. The integer `from` path is untouched (your 306-program byte-identical IR check; the 4 pinned `.ll` unchanged).
