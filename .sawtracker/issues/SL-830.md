## Description

**A generic default narrower than 64 bits is miscompiled: the helper returns the default's declaration-time `Int`, and the caller stores it into a 1-, 2- or 4-byte slot** (found by p822, SL-822 step 2, Oct 23; reproduced on main's build from Oct 19, so it predates SL-822).

`func plain<T>(x: T = 200)`:

| call | -O0 | -O2 |
|---|---|---|
| `plain<UInt8>()` | 200 | **0** |
| `plain<Int16>()` | 200 | **0** |
| `plain<Int32>()` | 200 | **0** |
| `plain<UInt64>()` | 200 | 200 |
| `plain()` | 200 | 200 |

**The IR at -O0:** the default's helper `saw default plain(x: T).x inst UInt8` is declared `-> i64` and stores `i64 200`. The caller then does:
```
%l1 = alloca i8, align 1
%t0 = call i64 @"saw default ….x inst UInt8"()
store i64 %t0, ptr %l1
```
That is an 8-byte store into a 1-byte stack slot. It is undefined behaviour, which -O2 exploits. It is a silent wrong value and a stack overwrite.

**Theory (UNVERIFIED):** the helper's return type (and its body's literal) is taken from the default's declaration-time typing (`Int`), not from the instantiation's `T`. It lives in the MIR or LLVM lowering of default helpers, or in mono's instantiation of them.

**Obligation 4:** every position where a generic default's value is materialized per instantiation:
- a parameter default;
- a struct field default;
- an `init` parameter default;
- a defaulted type parameter's value;
- the default of a const generic.

Each × `T` of widths 8, 16, 32 and 64, signed and unsigned; plus a `Float` `T` and a non-scalar `T` (a struct). Pin each at -O0 and -O2, and under ASan (the store overwrites the stack).

**Repro:** `.build/scratch/p822/gdef_widths.saw` and `gdef.ll` in the session scratchpad of the lead's Oct 22-23 session (`/private/tmp/claude-501/-Users-shawn-Projects-sawlang/66cd64ab-0743-4e62-9b39-b8db69ad7b60/scratchpad/p822/`).

**Air: reproduced, and the `init` face is wrong at -O0 too.** Built on SL-815.p1's tree (main as of Oct 23):

| probe | -O0 | -O2 | ASan (-O0, `detect_stack_use_after_return=1`) |
|---|---|---|---|
| `func plain<T: Printable>(x: T = 200)`, at `UInt8`, `Int16`, `Int32`, `UInt64` | `200 200 200 200` | `0 0 0 200` | stack-buffer-overflow |
| `extension Cell<T> { init(seed: T = 200, tag: Int) }`, `Cell<UInt8>(tag: 1)` / `Cell<Int16>(tag: 2)` | **`0 200`** | `0 0` | stack-buffer-overflow |

So the init-parameter row in the obligation-4 matrix isn't only an -O2 face. The wrong value reaches the program at -O0, so don't treat -O0 as the control for that row. Probes: `.build/scratch/air-review/sl830/p1_param_default.saw` and `p2_init_default.saw` on the Air.
