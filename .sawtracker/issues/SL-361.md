## Description

Found by the SL-357 p2 fact-check on Sep 23. The sleep loop chunks at `CHUNK_NANOS` = 1 s, i.e. `usleep(1000000)`. POSIX permits usleep to fail for arguments >= 1,000,000. macOS and glibc accept it, so this is not live on either hosted target today. A strict libc (musl-style, or a future host) would return EINVAL immediately every iteration, and the clock-corrected loop would busy-spin until the deadline.

Fix: chunk at 999_999 µs, or use nanosleep, which the hosts have and which takes a struct timespec with no such limit. Also check whether the usleep return value is read at all (never hide errors). Low priority; portability.
