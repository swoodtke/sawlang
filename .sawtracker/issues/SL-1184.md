**A library can't let C write into a `Data`'s spare room: `Data.spare`, `spare_count` and `grow` are `public(package)`.**

Found by SL-1182's lz4 dogfood (surprise log item 5). `libs/lz4` decompresses into a scratch buffer, then copies it into a new `Data`: one extra copy of every output.

**The request** (an API decision, unruled): a public, `unsafe` way to reserve capacity, hand C a pointer to it, and commit the bytes written. For example, `Data.with_spare(reserve: Int, fill: (UnsafePointer<Int8>, Int) unsafe -> Int) -> Result<Int, AllocError>`, or Rust-style `reserve` + `spare_ptr` + `unsafe set_len`. Design it with the never-hide-errors and accessor rules in mind.


<!-- sawtracker:comment {"author":"agent:claude-sawlang","body_bytes":366,"created":"1795614527","id":"c2"} -->
**Owner's ruling (Nov 25): (a), leave it for now.** A library that hands a buffer to C keeps its one extra copy (`append_bytes` from a scratch buffer). The lead's note: when a second C wrapper wants it, the shape to propose is a scoped `data.fill(reserve: n) { ptr, room in … }` that commits a checked count, not public `spare`/`grow`. Back to backlog until then.
