## Description

**Filed by the sawos lead for the sawlang lead.** The user asked that sawos's build tools be written in Saw, not Python, and that the gaps be filed here. Each was hit while designing sawos's image builder (SO-95, tracker doc `SO:images-and-packaging`, section 11). Run against sawlang 0.23.0 (`sawc-stage2` and its `blade`), hosted on macOS arm64, by the design's author; "reproduced" means it was run, "read" that only the source was read.

- **Tried.** A recursive walk that descended when
  `Directory.exists(entry)` was true counted 0 `.saw` files under
  `kernel/`. Reproduced.
- **What happened.** `Directory.exists` is documented as "whether a file or
  directory exists at `path`" (`std/directory.saw`), and there is no
  `is_dir`, `is_file` or metadata call.
- **Expected.** A way to ask whether a path is a directory (or a stat).
- **Why sawos needs it.** Walking package trees, finding sosimg outputs,
  and the arch-name scan the runner does over `kernel/core`.
- **How badly.** Has a workaround, which I ran: treat a path as a directory
  when `Directory.list` succeeds. It counted all 41 files. That costs an
  `opendir` per file. Nice to have.

Lead (Nov 14): a second consumer inside sawlang. `driver_make_directories` (`compiler/driver/src/main.saw`) asks `Directory.exists`, which is true for a regular file, so a `.build` (or a cache directory) that is a FILE reads as an existing directory and the build fails later with `open ... failed (other error, errno 20)` (found by SL-1052). When std can tell a directory from a file, that helper should ask, and refuse with the path and "exists and is not a directory". Blade's `remove_tree` and SL-1098's module-path walk use `Directory.list` as the test meanwhile.
