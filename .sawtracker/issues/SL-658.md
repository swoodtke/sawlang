**A diagnostic naming a type whose parts are shared is 2^depth bytes long** (SL-606, found in SL-639's sweep).

- **Mechanism:** a refusal message spells a type with `type_text` (`compiler/typecheck/src/spell.saw` `append_type`), which writes the structural type, with every alias expanded. Interned types share parts, so `type D0 = Int`, `type Dk = (D{k-1}, D{k-1})` spells as 2^k `Int`s. SL-639 made every walk over those parts answer once per part, so the message is now the only cost left: the walk is linear, the text it writes is not.
- **Repro:** `type Rk = Result<R{k-1}, R{k-1}>` with `let x: R24 = 5` (`type.ambiguous-result`), or a call `f(1, &w)` to `func f<T>(x: T, v: &D24)` with `w: &E24`, whose leaf differs (`type.mismatch`). `sawc2 typecheck --check` takes 2 s and 4 s at depth 24, each two levels 4x, and `sample` puts the time in `append_type` and `StringBuilder.append`. At depth 40 the message would be a terabyte. The dump has the same shape for a declaration whose type is such an alias.
- **Fix, a choice to make:** spell a type by the alias it was written with where one names it (which the interner does not keep today), or bound the spelling and elide the rest (`(…, …)`), or both. Stage 0's messages print the alias name for a written alias; the oracle for the elided form is open.
- **Not a correctness bug:** every answer is right; the refusal is the right refusal. It is a compile-time cliff on a pathological type, and a hazard for any diagnostic or dump that spells types.
