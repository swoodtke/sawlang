## Description

## Summary
An owned temporary in the head of an `if`, `while`, `match` or `for` is a receiver or an operator operand the head does not bind, as in `make_res("x").size() > 0` or `make_s(k) == "never"`. Stage 0 drops it late, and an early `return` skips the drop. The temporary leaks whether or not a `try` is involved. A temporary passed by value as an argument is dropped by the callee. An owned `match` or `if let` scrutinee that the pattern binds drops correctly.

Found by the SL-399 r5 checker agent (probes `heads.saw`, `heads_control.saw`). The lead reproduced it on main 2fa71814. `leaks --atExit` over 1000 calls counts:
- an operand: 2001 leaks (two heads per call);
- a receiver: 1001 leaks;
- a by-value argument: 1, the 48-byte baseline.

## Disposition
Leak-only. The user ruled on Sep 25 that leaks are tolerated in the bootstrap Stage 1 ("as long as the program generates the correct output, i'm fine with some leaks"), so there is no checker rule. It is ledgered as SL:hazards S23, and the new compiler's test corpus covers the shape.
