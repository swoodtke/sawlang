Found by SL-913's sawos sweep (p913, D2; reproduced by the lead on main 5393392b0).

A subscript declared with the old spelling, `subscript(i: Int) borrows -> Int`, is refused with `borrows.result`. That text explains what a `borrows` function may lend, but it doesn't offer the rewrite the spec's fixit describes: `-> &Int` or `-> &var Int`.

Worse, the refused accessor isn't recovered: every write through it is reported as `subscript.role` ("declares no `[]=`, and its `[]` lends no writable place"), and those errors sort BEFORE the declaration's own error. In sawos, one `Slab.[]` declaration produces 234 `subscript.role` errors across 8 files.

Repro: `.build/scratch/p913/probes/borrows_bare_t_cascade.saw`.

Fix shape: (1) the `borrows.result` text names the two rewrites for the declared `T`; (2) a refused `borrows` accessor is recovered as if it lent `&var T` (or its use sites are suppressed), so one bad declaration is one error. Doesn't block the sawos restart.

**SL-916.p1: a bare `borrows -> T` is one error with a real fixit** (found by the SL-913 sawos sweep: one `Slab.[]` declaration produced 234 errors)

- **The message** names both replacements and what each means, spelled as the source writes the type. It's the text the corpus program `errors/borrows_bare_return_type.saw` states in its four `EXPECT-ERROR-CONTAINS` lines, which now all match verbatim (corpusdiff doesn't read them: SL-918). A `borrows` with no result says so. A result that failed to resolve reports only its own error, not "lends `(error)`".
- **One predicate,** `lend_refused(d)` (declarations.saw), is shared by the declaration check and three use-site funnels. A use through a refused accessor reports nothing more:
  - `settle_subscript`'s three `subscript.role` refusals;
  - `refuse_not_a_place`, the single funnel for `type.not-a-place`;
  - `check_lend`'s `type.mismatch` against the bare result.

  This suppresses the cascade rather than recovering the accessor as `&var T`, which would invent a mode the author never wrote. `written_return` becomes public, and bodychecks.saw imports declarations.saw's extension.
- **Census:** 19 rows over every use position (`.build/scratch/p916/`): assign, compound, `&var` argument, `&` argument, a named `borrow var`/`let` block, method assign and read, a loop, a `&var self` receiver, no result, `-> Int?`, generic `-> T`, a struct result, a bare `[]` with a `[]=`, an unresolved result type, and a correct twin. After the change each row reports only its declaration's error; the twin builds.
- **Pins:**
  - fixtures `borrows.result.setitem`, `.writable-place`, `.method-place`, `.no-result` and `.struct-result`, each failing on main (its first error was the cascade) and passing now;
  - `borrows.result.saw` pins the fixit text;
  - K126 names the one-error fixtures, with 0 conformance-twin failures;
  - the typecheck README row follows.
- **Gates:**
  - `run.py --only seed,units,golden,subset,fixture_whitespace,std,typechecker,programs`: ok, with no golden moved;
  - corpusdiff: 2,677 hold.

  Only the message column of `corpus_diff.tsv`'s two `borrows.result` rows is stale, and the gate ignores it.

**Air: SL-916.p1, changes requested: the one-error rule breaks when the use is in another module, which is sawos's case.**

**What works.** These are on the patched compiler. The message text and the census rows I re-ran are right, and in one module:
- each refused declaration is exactly one error (`[]` with `@synthesize(shared)`, a named accessor returning an enum-selected field, `-> Nope` gives only its `name.undefined`);
- a correct `borrows -> &Int` written through, and a plain getitem used as a place, still get their `subscript.role` refusals;
- a bare requirement in a trait is still reported, with the conformer's `conformance.signature`, so a use through a bound can't slip through silently.

**The problem: the refused accessor is declared in one module and used from another.**
- **The test:** `lib/slab.saw` declares `public func [](&var self, i: Int) borrows -> Int`, and `main` writes `s[0] = 3`.
  - Base: `borrows.result` plus two `subscript.role` (the cascade).
  - Patched: `borrows.result` plus `INVARIANT  3:13 cross_module.main(): a call passes more arguments than its target has parameters`.
- **The other use forms** (one probe each, against a lib with two refused accessors, so 2 errors is right):

  | use in `main` | errors | INVARIANT |
  |---|---|---|
  | `s[0] = 3` | 2 | **1** |
  | `s[1] += 2` | 2 | 0 |
  | `print(s[0])` | 2 | 0 |
  | `bump(&var s[2])` | 2 | 0 |
  | `s.at(1) = 4` | **3** (`slice.not-yet`: "a `borrows` call lending a slice or a borrowing struct outside a `for` head…") | 0 |
  | `let n = s.at(0)` | **3** (same `slice.not-yet`) | 0 |

  The `slice.not-yet` rows match base, so they're an old cascade this patch doesn't reach. The `INVARIANT` is new.
- **The mechanism:** the quiet branches drop the refusal, so a module whose only problem is a use through a refused accessor has no errors of its own. The checks that run only on clean modules then see a call that typecheck left half-settled: the setitem with no setter and two arguments against a one-parameter `[]`, and the named lend classified as a struct lend.
- **Why the census missed it:** all 19 rows live in one module, which already has the declaration's error, so those checks never run there. sawos's `Slab.[]` is declared in `kernel/core/slab.saw` and used from other modules, so this is exactly the motivating case.
- **A fix that targets the mechanism:** a quieted use still marks its module or function as failed, printing nothing, so later checks skip it the way they skip a module with errors. Then add the cross-module rows to the census and a pin: the six use forms above, plus a generic bound if it applies.

**Steps:** `steps_for_paths` gives `fixture_whitespace`, `parallel_order`, `parser`, `programs`, `resolver`, `std`, `subset` and `typechecker`. Correct programs can't change behaviour, since every new branch needs a refused declaration, so no downstream stage step is owed. I'll run them on the revision.
