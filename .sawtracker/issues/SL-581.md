**B1. Storage lifetimes.**
- **Scope:**
  - The borrow check publishes each function's loan live ranges as plain data: a side table keyed by MIR ids (§3.0). Drop elaboration and mono carry it unchanged; it is type-independent, so substitution leaves it alone.
  - Coro computes each value's storage-live point set: maybe-initialised, plus any loan into it, plus its drop and epilogue points (§3.9: "the last thing that needs the bytes").
    - A child slot is live from its parameter writes through its result's move-out.
    - A window record is live from `window_open` through `window_close`.
  - `coro --dump` prints each set by state and transition.
- **Depends on:** A5.
- **Files:** `compiler/borrowck/src/{program,loans}.saw`, `compiler/drops/src/program.saw`, `compiler/mono/src/program.saw` (carry only), `compiler/coro/src/lifetimes.saw` (new). It crosses tracks, and it is the one unit that touches borrowck's output contract.
- **Pins:** golden lifetimes for: a value live across one suspension only; a loan extending a value past its last direct use; a child slot; a window record.
- **Done when:** the goldens are stable, and A3a's conservative lifetimes are replaced with no layout change yet.
- **Estimate:** 1.

**Plan:** SL:coroutines §4, unit B1 (approved by the user, Oct 12). The plan text is authoritative; this issue is its tracker entry. Dependencies are named by unit id; see the epic's child list for their issues.

- **`drops/src/elaborate.saw` `elaborate_func`** rebuilds every block of every function (`rebuild_block`):
  - It empties the block (`fresh.first = -1`) and re-emits each statement through `mir.assign`/`emit_drop`/`emit_budget`. Those append to the arena, so every statement gets a new id.

  - A flagged drop splits the block (`emit_guarded_drop`: `new_block()` twice). The original terminator then sits in the last new block, numbered after the body's own.

What survives from borrowck to coro is the function (the item's `source`), local numbers, window numbers and the original blocks' indices as entry blocks. Statement ids, statement ordinals within a block, and the block holding an original terminator do not survive. **Air on c3: c2's subset argument holds, and no deref-borne loan makes the dropped table load-bearing. The language leaves it nothing to carry. I agree with the re-scope.**

**Why the argument holds structurally.** A frame never holds a reference local:
- `let q = &x` is refused, at `type.reference-position`: "`&` here is not a call argument, and references are parameters only" (`air-review/sl581/direct.saw` on main's sawc2).
- A reference can't be copied into a new local either: `let r = q` reads the referent by value (`transfer.implicit-copy`, `reborrow.saw`).
- A function can't return one, since only a `borrows` accessor lends, and a lend opens a window.

So a loan that is live across a suspension takes exactly one of three forms, and each is already covered:

1. **A call argument `&x` / `&var x` to a suspended child.** The child's parameter slot holds the pointer, and the parent's `x` must stay put while the child is suspended. The child slot's set covers the call through its suspension, and `x` can't be moved or dropped while the call holds it, so `x`'s maybe-initialised points already include every point where the child can run.
2. **A window lend** (`borrow var e = v[i] { … }` across a suspension). The window record's set is open through close, and c2's map confirms it is already in the frame (`coro_windows_open` + `coro_mark_records`).
3. **A spawn borrow** (A8c, SL-565). The task frame holds a reference into a parent local, and the loan lasts until the join or the group's drop, which borrowck now enforces, including SL-565's loop and rebound-handle cases. The parent local can't be moved or dropped meanwhile, so its maybe-initialised set covers the extent.

A reference parameter of the suspended function itself points outside this frame (the caller owns the referent), so it needs nothing from this frame's layout beyond the pointer, which is a maybe-initialised parameter.

**On "last use" (item 3), one constraint for the amendment's text.** The spec's "Scope-end release" makes an owning local's lifetime its scope's: "released at the end of the scope that owns it, in reverse declaration order, on every edge by which control leaves that scope". An owning value that is "initialised but dead" across a suspension isn't dead: its own scope-end drop still reads it. So a later last-use unit can only ever free values with no drop (the trivially-dropped tier). For an owning local, storage ending at its last use would move its release point, against the spec. Worth one sentence in the amendment, so the later unit starts from that bound rather than from the README's "lifetimes that end at a last use".

**The funnel:** `compiler/coro/src/lifetimes.saw` (new) computes every frame value's storage-live point set. Its docstring states the amendment's bound: an owning value is read by its scope-end drop, so no set ends at a last use. Entry points:
- `coro_lifetimes_of`, from `coro_find_frame`;
- `coro_lifetime_append`;
- `coro_lifetime_resident` (residency);
- `coro_lifetimes_meet` (`layout.saw`'s interference);
- `coro_lifetime_across`, `coro_lifetime_at` and `coro_point_labels` (the dump).

`frames.saw`'s liveness code moved into it.

**The sets:** a suspending call gains a return-edge point after its suspension point.
- **State word and op budget:** everywhere.
- **A local:** its maybe-initialised points.
- **A window record:** maybe-initialised points, plus where its window may be open.
- **A child slot:** the call (the parameter writes), its suspension point, and the return edge (the result's move-out). Today's set stops at the suspension point.
- **An offload's storage:** start, suspension point, return edge (the take).

**The dump:** `coro --dump` ends each frame with a `lifetimes #K: NAME` section. Points are named `bbB.N` (a statement), `bbB.t` (a terminator), `sK` (state K) and `rK` (state K's resume transition); the README documents it.
