**The whole-corpus behavioural differential: every `tests/corpus/` program through sawc2, compared with Stage 0, bucketed and ranked** (SL-398 acceptance item 4; the user, Oct 15: "let's do the whole-corpus differential lane now … hopefully that will inform the gaps and give us a plan").

**Why:** removing `sawc/` needs sawc2 to build and run everything Stage 0 does, and nothing measures that today. The coroutine census covers 490 programs (93 pass), the run lane 95, and the drops lane gets 1,206 corpus programs through the front half. This lane is the progress meter, and its first report is the gap list the removal plan is built from.

**Shape, generalizing what exists rather than duplicating it:**
- **The Stage 0 side** is a snapshot, exactly as A0b did for the coroutine programs (`compiler/tests/coro/stage0/snapshot.py`, which compiles each program's `examples/` twin). Widen that mechanism, or factor it into one shared module, to cover every `tests/corpus/` program: exit status, stdout and stderr for a run, and the diagnostics for an expected-error test, on the host triple. A snapshot also preserves the oracle for when `sawc/` is gone (the removal needs one anyway).
- **The sawc2 side** builds and runs each `tests/corpus/` file, then compares it with its twin's snapshot.
- **Buckets per program:**
  - **pass:** same exit status and output, or, for an error test, a refusal whose rule matches the expectation, as the census decides;
  - **refused:** sawc2 refuses a program Stage 0 runs, keyed by the rule ID (`slice.not-yet`, `coro.not-yet`, `backend.not-yet`, …) and the stage;
  - **crash:** an INVARIANT, an internal error, a signal or a hang, keyed by its first line;
  - **wrong:** it builds and runs, but the output or exit status differs;
  - **link:** sawc2's IR fails in clang or the link;
  - **stage0-wrong:** a known Stage 0 bug (SL:hazards, the run lane's annotations); keep the existing annotation mechanisms.
- **The report:** a summary with counts per bucket, then each bucket's keys ranked by program count, with three example paths each. Also one `corpus_diff.tsv` row per program (path, bucket, key), so a later run diffs against it.
- **The coroutine census stays:** reuse its comparison code. If the two overlap entirely, say how they should merge, but don't merge them in this unit.

**How it runs (the user's instruction):** it isn't a per-patch gate step yet. Its full run is long, so it's a standalone tool plus a battery stage, run by hand.
- The measurement runs one program at a time (`--jobs 1` by default) and does NOT take the suite lock, so it can share the machine with the server's gate.
- Each program has a timeout, and a timed-out program is a crash ("hang").
- Building sawc2 itself still goes through `build.py` as usual.

**Done when:**
1. The tool and its README.
2. The Stage 0 snapshot is written for the whole corpus and checked in, whole, with a check like A0b's that it covers every corpus file.
3. The first full report is posted as a comment on this issue: the summary, the top keys per bucket, and a mechanism-grouped reading of the largest buckets (which stage, which missing feature, which unit or issue already owns it, where you can tell).

### What the numbers imply for removing `sawc/`

- **The blocker is coverage, not correctness.** 1009 of the 1684 run programs are refused, 13 differ and 14 crash.
- **The std port is the largest single lever.** About 600 programs wait on std surface: `TaskGroup`'s `init` (128 alone, and it also hides the coroutine programs behind it), `Arc`, `std.net`, `std.channel`, `std.json`, `std.mutex`, `std.time`, `Vector.iter`, `Data`.
- **Next comes the language slice.** That's 258 programs over about 40 features, led by `any Trait` method calls, `try` blocks, `?.`, `lends`, shorthand closure parameters and `Thread.spawn`.
- **After that, the backend.** That's 270 programs, led by the synthesized conformances beyond signed integers, collection literals and owning or escaping closure captures.
- **Driver flags are a small fixed list.** 39 programs need flags `sawc2 build` doesn't take yet; `--freestanding` matters most, since the freestanding suite is the cross-target gate.
- **Correctness defects to fix before trusting a pass:** the release-placement differences (5 programs, one mechanism), the copy-before-deinit on reassignment, and the 59 refusals sawc2 doesn't make yet. The last group is the checks a deletion of `sawc/` would silently lose: distinct aliases, visibility tiers, ambiguity, import cycles and unsafety.
- **Crash hygiene:** 14 of the 19 crashes are gaps that mono reports as INVARIANTs instead of `not-yet` refusals, and 5 are one typecheck cascade.
