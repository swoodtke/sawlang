## Description

**`panic("a literal")` reaches `String.deinit` and the `__saw_rt_dealloc` seam** (found by p843, SL-843 patch 2, Oct 23).

A bare `panic("plain literal message")` makes its program's cone reach `std.string` (a String literal, `String.copy`, `String.deinit`) and so the `__saw_rt_dealloc` extern, though nothing is allocated and a literal is immortal. A formatted `panic("… {}", n)` reaches further: `std.alloc`, `std.stringbuilder` and `std.float`, despite design 137's promise that format arguments render through stack scratch and allocate nothing. Measured with `compiler/tools/std_cone.py` on two scratch programs.

**Why it matters:** `SpinLock` is pinned to need no operating system and no allocator (SL-672's `spinlock.cone`), because a kernel takes it before any allocator exists. SL-843 patch 2 gives it a re-entry panic with a literal message, so its cone now names `__saw_rt_dealloc`. The lead admitted that reach in `std_lane.py`'s `SEAM_FREE_CONES`, pending this issue. The no-allocator check (no `std.alloc`, no `GlobalAllocator`) still holds.

**Scope:**
- a `panic` (and `assert`) whose message is a literal names no `String` value: the literal crosses to `__saw_rt_panic` as static bytes, the way compiler-inserted checks already do;
- the formatted form reaches no allocator (design 137);
- then remove the `__saw_rt_dealloc` admission from `SEAM_FREE_CONES["spinlock"]` and re-record `spinlock.cone`.

**Obligation 4:** every panic-shaped entry: `panic`, `assert`, `precondition` if one exists, a `!` force's message, and the format-argument forms.

**Implementation detail (lead, Nov 12): a literal `panic`/`assert` message crosses as static bytes; the formatted form's reach is measured and reported, not changed, in this unit.**

**Why it matters to sawos:** `SpinLock` must need no allocator (a kernel takes it before one exists). Its re-entry panic has a literal message, and today that makes its cone name `__saw_rt_dealloc`, which `compiler/tests/std/std_lane.py` admits by hand in `SEAM_FREE_CONES["spinlock"]`.

**How a panic is lowered today.**
- MIR (`compiler/mir/src/lower.saw`, `format_position`): the message of `print`, `panic` or `assert` is a FORMAT constant ("a constant of its own and never an interpolation") only when format arguments follow it or it holds `{}` slots. A plain literal with nothing after it is an ordinary `String` value: a literal built through the String literal role, passed, then dropped, which is what reaches `String.deinit` and `__saw_rt_dealloc`.
- The backend (`compiler/llvm/src/calls.saw` `builtin` → `panic_call`; `prims.saw` `fail_message`, `__saw_fail`, `__saw_fail_parts`) already knows how to emit a constant message's bytes after the site, as every compiler-inserted check does.

**Step 1, census (evidence first).** For each program below, record the std declarations and externs its cone reaches, with the std lane's cone machinery (read `std_lane.py` for how a `cone/*.cone` record is produced; write the outputs to the evidence directory):

| program | expected today |
|---|---|
| `panic("plain")` | reaches `std.string` (literal, copy, deinit) and `__saw_rt_dealloc` |
| `assert(c, "plain")` | the same |
| `assert(c)` with no message | no String |
| `panic("n = {}", n)` with an `Int` | reaches `std.stringbuilder`, `std.alloc`, `std.float` (the issue's claim) |
| `panic("s = {}", s)` with a `String`; with a user `Printable` | record |
| `panic("{n}")`, an interpolation | allocates by design (a hidden allocation `--no-hidden-alloc` refuses); record |
| `let v = o!` on `None`; `try! r` on an `Err`; an index out of range | no String (compiler-inserted) |
| `std/spinlock.saw`'s own cone (`spinlock.cone`) | names `__saw_rt_dealloc` |

**Step 2, the change: a plain literal message is a format constant with no slot.** In `format_position`, for `panic` and for `assert`'s message (NOT for `print`): when the message argument is a plain string literal (`Alt.Expr_String`) with nothing after it, answer its position, so it takes the same path as `panic("x = {}", x)` with zero arguments, and the backend writes its bytes as static data. A literal holding an escaped brace keeps its text (`\{` is a `{` in the output, as in the format path: check with a probe). A message that is any other expression (a `String` variable, a call) stays a `String` value: that panic owns a real String, and the report lists such sites in std (grep `panic(` in `std/` for non-literal messages) without changing them.
- If the format path's slot-count check, or any other consumer of `format_position` (typecheck's `{}` count rule), is keyed off the same answer and now misfires on a plain literal, STOP and report the function and the misfire; don't patch around it.
- `print("literal")` is deliberately out: it changes `compiler/tests/run/hello.ll` and every program's size, which is SL-790's question.
