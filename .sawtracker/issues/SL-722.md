**The Float backend plan is in `SL:float-backend` r1** (a read-only planning sweep, p722, at main 64f7f4caf). Summary:

- **Census:** 19 rows refuse first on Float (a constant, an operator, `Printable.format` ×10, `compare`, the missing `std.float`/numeric half), plus 2 hidden behind `std.net`; all 23 `std.json` rows wait on `std.float`. SL-722's other four refusals cover 41 rows, and NONE of them is Float: statics 24 (8 need only zero-init, SL-685), conversions 8 (`E.from(raw:)` ×6, alias projections ×2), the constant 9 (N ×8, SL-548; `#line` ×1), indexing 0 (landed with SL-710).
- **What works:** a Float value not born from a literal or an operator already matches Stage 0 bit for bit everywhere (fields, Vector, Optional, payloads, arrays, the C ABI).
- **Units:**
  - U1: typecheck parity;
  - U2: Float values in the backend (exact literal→bits with integer arithmetic, operators, equality);
  - U3: the Float row of the scalar hook table (`compare` as `<`, `>`, else Equal, so NaN isn't `Greater`);
  - U4: non-integer statics (fold in SL-685);
  - U5: port `std.float` and numeric's Float half, Float printing through it, `-lm` on Linux, the float vectors as run programs;
  - U6: Float↔integer conversions (blocked on Q1).
- **Questions for the user** (in the doc, each with a lean): Q1 (SL-69) Float↔integer conversion semantics; Q2 (SL-68) unrepresentable float literals; Q3 `<=`/`>=` on NaN in generic code (the spec contradicts itself); Q4 what a Float static's initializer may be.
- **Side findings, filed separately:** sawc2 accepts `&+ &- &*` on Float (the spec and Stage 0 refuse); sawc2 accepts Float↔integer `as` (Stage 0 refuses; the right answer depends on Q1); no `-lm` on Linux; an enum-case `as UInt8` of a 300-valued case builds and panics at run time where Stage 0 refuses at compile time.
- **The lead's dispatch order while Q1–Q4 wait:** U4 (statics plus SL-685, no Float rulings needed), U2 (the cells Q2 doesn't touch), U3 (its `compare` cell is independent of Q3's generic `<=`).
