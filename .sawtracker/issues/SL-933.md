Found by SL-865 U7/U8 (pplace): with exported statics built, the freestanding suite's `export_with_coroutine` case compiles and then FAILS TO LINK (`ld.lld`), leaving undefined:
- `__saw_rt_reactor_create`/`destroy`/`poll`, `__saw_rt_set_thread_executor`, `__saw_rt_thread_executor`, `__saw_rt_offload_done`, `__saw_rt_sleep_ns`, `__saw_rt_clock_monotonic_nanos`: executor and reactor seams the suite's `fsrt` provider doesn't supply;
- `pthread_mutex_lock`/`trylock`/`unlock`: called DIRECTLY from `std/taskgroup.saw`, not through a `__saw_rt_*` seam.

All are reached from `std/taskgroup.saw`. (The Air raised the TaskGroup half earlier, chat m616.)

**Two questions for the unit:**
1. **The pthread calls:** std must not name a host library on a freestanding target. Either the mutex goes through a seam (`__saw_rt_lock_*` already exists for SL-821's lock owner; check `runtime/ABI.md`), or a freestanding TaskGroup is refused with a clear `--freestanding` rule. "Kernels are first-class targets" argues for the seam.
2. **The executor and reactor seams:** which does a freestanding provider owe for a cooperative TaskGroup (no threads, no reactor)? Does the spec's freestanding profile allow TaskGroup at all (spawn is refused: `spawn.freestanding`)? The suite's fsrt then supplies the owed set, or the case is reshaped by the spec.

Until then, `export_with_coroutine` is `due`, citing this issue.

**User ruling (Oct 30): option (i).** A cooperative `TaskGroup` is ALLOWED under `--freestanding`. The freestanding runtime supplies the executor-word pair (`__saw_rt_thread_executor`/`__saw_rt_set_thread_executor`), the clock, `__saw_rt_sleep_ns` and `__saw_rt_reactor_create`/`_poll`/`_wake`/`_destroy` (plus `__saw_rt_lock_*` when the program uses channels). std makes the pool and offload code reachable only from `TaskGroup(threads:)`, so a cooperative image references no thread, pthread or offload seam.

Survey (p933, `.build/scratch/p933/plan.md`), the findings this ruling rests on:
- **The issue's case uses no TaskGroup.** `export_with_coroutine`'s `__saw_drive` reaches `this_executor()` and the scheduler sweep, so it needs the executor seams. Its header comment is wrong and gets rewritten with the fix.
- **std calls `pthread_*` directly.** taskgroup and channel make 7 calls that are not `__saw_rt_*` seams, so they slip past `provider.undefined-seam`, and `runtime/ABI.md` contradicts itself on them. The fix is seven thin `__saw_rt_pthread_*` seams. No seed bump is needed: sawc's std cone holds no taskgroup or channel.
- **Units, in order A, B, C, with D riding along:**
  - **A:** std's pthread calls go through the new seams (taskgroup, channel, the runtime bodies, ABI.md, the seam table).
  - **B:** pool and offload code becomes reachable only from `TaskGroup(threads:)`, through one funnel.
  - **C:** fsrt gains the owed seams, with a per-architecture clock in `boot.S`. `export_with_coroutine` drops its `due`, and new `cooperative_group` and `cooperative_deadlock` cases are added.
  - **D:** spec (freestanding section) and ABI prose.
