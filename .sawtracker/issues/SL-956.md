**A `match` on a place keeps its scrutinee's exclusive window across the arms, but closes a shared one before them.** Found by the sawos re-sweep (`.build/scratch/psos/report.md`, D1).

**Repro** (`.build/scratch/psos/probes/match_scrutinee_window.saw`): `match t[1].state { case Live -> { t[1].n = 7 } }` is refused with `loan.window-root … window of [] opened at 35:5 holds t exclusively` when the element type's subscript has only a `&var self` accessor. The same body is accepted when the subscript has a `@synthesize(shared)` twin. The control (`probes/shared_window_conflict.saw`) shows a live shared window does refuse an exclusive write, so the shared window closes before the arms and the exclusive one doesn't.

**The spec:** SL:borrowing rule 1 (LANGUAGE_SPEC.md, around line 4967) says a `match`-head lend "closes before the body runs, unless the lend is what the head binds", whatever the mode; it also says "a `match` on the place keeps its window" (around line 5025). Settle which holds (possibly a spec ambiguity), then make both modes agree. sawos hit this in `kernel/core/slab.saw`, where the workaround is adding the shared twin. Mechanism UNVERIFIED: perhaps near SL-906's `lend_mode` funnel.

**RULED (the user, Nov 8): (A), each arm decides.** In a `match` on a lent place, the head's borrow opens for the head and stays open through the pattern tests and the guards. Once an arm is chosen:
- an arm whose pattern binds nothing of the place runs with the borrow closed;
- an arm whose pattern binds a payload keeps it for its block.

This is spec rule 1 ("closes before the body runs, unless the lend is what the head binds"). The by-reference sentence "a `match` on the place keeps its window for that use" gets a clause saying the use is the pattern tests, the guards and the arms that bind. SL-838's "a `match` on a lent place stays by reference" was a lead note, not a ruling. Its probe `borrow_value_read_positions.saw` moves to the new order (`match place U / epi U / arm zero`), and the mir golden `borrow_reads` moves the same way.

Guards stay as they are: they run with the borrow open, so a guard reading the root through an exclusive-only accessor is still refused.

**SL-956.p1: a `match` on a lent place closes its window at an arm that binds nothing** (the user's ruling (A), Nov 8)

- **The rule** (spec rule 1, now stated in full): the head's window stays open through the pattern tests and guards. Then each arm decides:
  - an arm whose pattern binds a payload of the place keeps the window for its block;
  - an arm binding nothing (`case Live`, `case Some(_)`, `_`) runs with it closed, in both modes, so its body may use the root.

  The by-reference sentence in both places gains "for its pattern tests, its guards and an arm that binds of it". SL-838's "a `match` on a lent place stays by reference" was a lead note, not a ruling; the user ruled here.
- **The mechanism:** `lower_match` (mir/lower.saw) left the scrutinee's windows in the match's scope until each arm unwound it. At the entry of an arm that binds nothing, they're now closed and taken off the scope stack (`close_windows_from`), so a `return`, `break` or `continue` inside the arm doesn't close them again. They're restored for the next arm. This applies only when every entry since the scrutinee's mark is a window (`only_windows_since`).

  - with a printing accessor: the open and close order, `return`, `break`/`continue`, a bound arm keeping the window, mixed arms, `match` as a value, a suspending arm, a nested match.

**Air: SL-956.p1, changes requested: the per-arm close switches off when the scrutinee leaves a temporary.**

**What works,** at -O0 and -O2, all under `--sanitize address`. The table is backed by a `Vector`; its `[]` lends into the vector's storage and counts window opens and closes. Every arm that binds nothing grows the root past a reallocation:
- **A failing guard** (`case Live if flag`) falls through to `case _`, which grows the root;
- **`return`** from inside an arm that binds nothing, before and after the grow;
- **`continue` and `break`** out of such an arm in a loop;
- **A value `match`** whose chosen arm grows the root.

Every path gives opens == closes with no ASan report, so the window closes exactly once and the reallocation never meets an open lend. `mono` (downstream of MIR, which your run didn't cover) passes.

**The gap: `only_windows_since(mark)`.**
- **The mechanism:** the per-arm close runs only when every scope entry since the scrutinee's mark is a window. A scrutinee whose evaluation also leaves a non-window entry, such as an owning temporary with a drop, keeps the old rule. Its arms that bind nothing still run with the window open.
- **The probe** (`temp_scrutinee.saw`; `Table.[]` is `&var self … borrows -> &var Slot`):
  ```saw

      case Live -> { t[2].n = 9 },   // accepted (refused on base)
      case Dead -> {}
  ```

- **On base 20d767c66**, both writes are refused. **With the patch**, only the first is. Ruling (A) says each arm decides, and nothing in it depends on how the index was computed, so the first is a legal program refused. It fails safe, since it refuses rather than admits, but it's the rule's position matrix missing a row (obligation 1). The census has no scrutinee with a temporary.
- **The fix:** close just the window entries from the mark (and restore them for the next arm), leaving any temporary in scope until the match ends. Or, if the ordering makes that unsound, say why, file the limit, and pin it as a refusal with the reason.
