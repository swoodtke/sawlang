**A `match` on a place keeps its scrutinee's exclusive window across the arms, but closes a shared one before them.** Found by the sawos re-sweep (`.build/scratch/psos/report.md`, D1).

**Repro** (`.build/scratch/psos/probes/match_scrutinee_window.saw`): `match t[1].state { case Live -> { t[1].n = 7 } }` is refused with `loan.window-root … window of [] opened at 35:5 holds t exclusively` when the element type's subscript has only a `&var self` accessor. The same body is accepted when the subscript has a `@synthesize(shared)` twin. The control (`probes/shared_window_conflict.saw`) shows a live shared window does refuse an exclusive write, so the shared window closes before the arms and the exclusive one doesn't.

**The spec:** SL:borrowing rule 1 (LANGUAGE_SPEC.md, around line 4967) says a `match`-head lend "closes before the body runs, unless the lend is what the head binds", whatever the mode; it also says "a `match` on the place keeps its window" (around line 5025). Settle which holds (possibly a spec ambiguity), then make both modes agree. sawos hit this in `kernel/core/slab.saw`, where the workaround is adding the shared twin. Mechanism UNVERIFIED: perhaps near SL-906's `lend_mode` funnel.

**RULED (the user, Nov 8): (A), each arm decides.** In a `match` on a lent place, the head's borrow opens for the head and stays open through the pattern tests and the guards. Once an arm is chosen:
- an arm whose pattern binds nothing of the place runs with the borrow closed;
- an arm whose pattern binds a payload keeps it for its block.

This is spec rule 1 ("closes before the body runs, unless the lend is what the head binds"). The by-reference sentence "a `match` on the place keeps its window for that use" gets a clause saying the use is the pattern tests, the guards and the arms that bind. SL-838's "a `match` on a lent place stays by reference" was a lead note, not a ruling. Its probe `borrow_value_read_positions.saw` moves to the new order (`match place U / epi U / arm zero`), and the mir golden `borrow_reads` moves the same way.

Guards stay as they are: they run with the borrow open, so a guard reading the root through an exclusive-only accessor is still refused.

**Air pre-review for SL-956's patch (ruling (A): each arm decides).** These are the probes I'll run on it, listed now so the census can cover them. Each probe runs at -O0 and -O2, and under `--sanitize address` where an arm writes the root.

1. **Both accessor kinds, every binding form** (SL-897's lesson: a match-arm lend hid a use-after-free).
   - Take the original repro (`match t[1].state { case Live -> { t[1].n = 7 } }`) and its siblings over a `&var self`-only `[]` and over a `@synthesize(shared)` one.
   - In each arm, put an aliasing write to the root that would invalidate the place: a `push` that grows a Vector, or a reassignment of the element.
   - A non-binding arm must now accept that write on both kinds and stay clean under ASan. A binding arm must still refuse it while the binding is live.
2. **One window close on every path out of a match that mixes arms** (some bind, some don't). Cover: a guard that fails and falls through to the next arm; `return`, `break` and `continue` from inside a binding arm; `try`/`?` propagation and `catch` inside an arm; a diverging arm (`panic`, a `-> Never` call); and a value `match` whose arms yield the result. A drop-counting payload (a Deinit tag) or the mir golden's `epi` count shows a double or missing close.
3. **What counts as binding.** `case Some(_)` and `case Some(Pair(a: _, b: _))` bind nothing. `case Some(x)` with a Copy payload binds a copy, so is the borrow still "what the head binds"? The ruling says "binds a payload", and spec rule 1 says "unless the lend is what the head binds". Please pin the Copy-payload case either way. A NoCopy payload, which must be `move`d or borrowed, should keep the window.
4. **Guards** keep the borrow open (as ruled). A guard reading the root through an exclusive-only accessor is refused. A guard that's true for one arm, then a non-binding arm body writing the root, is allowed.
5. **Suspension.** A non-binding arm with a suspending call before a root write (the window already closed, so nothing spans the suspend). A binding arm whose binding is live across a suspend, under the existing "references span suspends" rule. Run both inside a task.
6. **Siblings of the same shape.** Do `if let` / `guard let` / `while let` on a lent place follow the same rule, the else branch running with the borrow closed? If they already do, say so in the brief. If not, it's the same rule at another position (obligation 1).
7. **The gates the ruling names:** `borrow_value_read_positions.saw`'s new order, the `borrow_reads` mir golden, any corpusdiff verdict move recorded with `--baseline`, and `gmgate` if a verdict moves (memory: a verdict move can turn it red).
