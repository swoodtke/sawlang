**A `match` on a place keeps its scrutinee's exclusive window across the arms, but closes a shared one before them.** Found by the sawos re-sweep (`.build/scratch/psos/report.md`, D1).

**Repro** (`.build/scratch/psos/probes/match_scrutinee_window.saw`): `match t[1].state { case Live -> { t[1].n = 7 } }` is refused with `loan.window-root … window of [] opened at 35:5 holds t exclusively` when the element type's subscript has only a `&var self` accessor. The same body is accepted when the subscript has a `@synthesize(shared)` twin. The control (`probes/shared_window_conflict.saw`) shows a live shared window does refuse an exclusive write, so the shared window closes before the arms and the exclusive one doesn't.

**The spec:** SL:borrowing rule 1 (LANGUAGE_SPEC.md, around line 4967) says a `match`-head lend "closes before the body runs, unless the lend is what the head binds", whatever the mode; it also says "a `match` on the place keeps its window" (around line 5025). Settle which holds (possibly a spec ambiguity), then make both modes agree. sawos hit this in `kernel/core/slab.saw`, where the workaround is adding the shared twin. Mechanism UNVERIFIED: perhaps near SL-906's `lend_mode` funnel.
