**2. Step 0: Stage 0's table and sawc2's final layouts don't correspond frame by frame.**

`sawc/sawc.py examples/task_backtrace_nest.saw --emit-bt-table`, decoded (darwin, word_bits 64): 4 frames, 10 states.

| frame | state_field | states (line, child, child_offset) |
|---|---|---|
| leaf | 8 | 0: (0, -, 0); 1: (24, leaf park) |
| middle | 72 | 0: (0); 1: (29, leaf at 16); 2: (0) |
| watcher | 0 | 0: (0); 1: (41, leaf park) |
| worker | 136 | 0: (0); 1: (34, middle at 16); 2: (0) |

`--emit-frame-layout` agrees: states 2/3/2/3, and `__sub0` is live in state 1 at offset 16.

sawc2 refuses the program as written: `sawc2 coro --layouts --std-root std tests/corpus/task_backtrace_nest.saw` gives `import.unknown-symbol ... dump_tasks is not defined in std.task`, because `dump_tasks` is A16b's. With only the `dump_tasks` import and call removed (`.build/scratch/p576/nest_nodump.saw` in my worktree), `coro --layouts` and `--lowered` give 5 frames, each with 2 states:

| frame | state word | state 1 |
|---|---|---|
| worker (task root) | 0 | drive middle at 8 |
| watcher (task root) | 0 | drive `std.task.sleep` at 8 |
| middle | 0 | drive leaf at 8 |
| leaf | 0 | drive `std.task.sleep` at 8 |
| `std.task.sleep` | 0 | `park timer` |

What has no counterpart:
- **Frame `std.task.sleep` has no Stage 0 counterpart.** Stage 0 inlines `sleep`, so `leaf` and `watcher` park themselves. In sawc2, `leaf` and `watcher` drive a `sleep` child, and the park is one frame deeper. Corpus EXPECT says the innermost dump line is `at task_backtrace_nest.saw:24 in leaf`. A table built from the final layouts as they stand leads the walker to a `sleep` frame in `std/task.saw`, unless the table or A16b's walker folds std park frames into their caller. The plan doesn't say which.
- **State 2 of Stage 0's `middle` and `worker` has no sawc2 counterpart.** Stage 0's state count is its block count (`coro_transform.py`: `'states': done_state = len(self._blocks)`). State 2 is the continuation block after a drive (`_emit_nested_call`'s `after`), which never parks: line 0, no child. sawc2 numbers only the entry and each suspension. So A0b's "frame and state counts" can't match by count. A per-suspension-state comparison would match: every sawc2 state 1 lines up with a Stage 0 state 1, apart from the leaf-park/drive difference above.

**3. Stage 0's exec descriptor can't be filled from the new std.** The blob's runtime descriptor (`sawc/backtrace_table.py`, 64 bytes) records `TaskGroup.tasks`/`done`/`gen` as parallel vectors, a `Box<any Resumable>?` element with a vtable word, and `__saw_bt_head`. lldb also needs `__saw_bt_vtables`, a vtable per frame. The new std's `TaskGroup` (`std/taskgroup.saw`) has `slots: Vector<TaskSlot>` (frame, cell, generation, done, active, …), `free`, and a `next` link, and it reaches a frame through the descriptor in its cell, not through a vtable. The format allows `exec_off = 0` ("absent"), so the frame half can keep Stage 0's format exactly. But then `tools/lldb_saw.py` can decode the table without finding any task, and `tools/test_bt_table.py`'s fixture check (`table["exec"] is None` fails) fails. "So `tools/lldb_saw.py` keeps working" needs either a new exec-descriptor layout (a format change: a version bump, with lldb_saw.py edited outside my file list) or a ruling that lldb's live walk waits.

**The decisions I need (each reversible):**
- (a) For the pin, a rebuilt `p3_dump` (and with what shape), or drop the pin and keep `task_backtrace_nest` alone.
- (b) Std park frames such as `sleep` and `yield_now`: kept in the table, with A16b's walker skipping them, or folded at table-build time, so a caller's drive into one is recorded as a leaf park on the caller's line.
- (c) The counts comparison: by suspension states (sawc2's numbering) rather than Stage 0's block count.
- (d) The exec descriptor: absent for now, or a new layout for the new std's `TaskGroup`, with the version bumped and `lldb_saw.py`/`test_bt_table.py` in scope.
