## Description

Found by design 275 U4's disagreement sweep (obligation 4), probed on main at
46d6db9c and unchanged by U4, which is behaviour-preserving.

`coro_transform._default_expr_suspends` (~:9351) answers "does this parameter
DEFAULT suspend?" by reading the BROAD bit — `node.suspends`, "might" — for
every free call it walks. Its one caller, `_arity_args._default_for`, uses the
answer to REFUSE, and the refusal it writes is about a FRAME:

    the default value of parameter `n` of `helper` suspends, and a suspending
    default cannot be materialized at a call that omits it — the expression would
    need a coroutine frame of its own at every such call

A body that suspends only by the conservative closure-call cause needs no frame,
which is exactly SL-306's rule. So a default whose expression calls any
closure-taking helper is refused although the expression never parks.

REPRO (main, 46d6db9c — `.build/scratch/probe_default_conservative.saw` in the
sl318u4 worktree):

    func apply(f: (Int) -> Int) -> Int { f(1) }
    func conservative() -> Int { apply({ n in n * 2 }) }
    func helper(n: Int = conservative()) -> Int { __saw_suspend()  n + 1 }
    func root() -> Int { helper() }
    func main() { print(__saw_drive(root())) }

    error: coroutine transform: the default value of parameter `n` of `helper`
    suspends, ...  -->  probe_default_conservative.saw:20:1

`conservative()` reaches no park; `helper()` is refused anyway. Passing the
argument explicitly compiles, which is the workaround the message names — and
which is the tell that the question asked was the wrong one, since an explicit
argument and a materialized default run the same expression.

MECHANISM (obligation 4): a consumer that must decide "is a FRAME owed here?"
reading the derivation that answers "is this provably suspension-free?". U4 makes
the two askable by name (`frame_boundary` vs `might_suspend`) and preserves every
consumer's current reading; this site keeps `might_suspend`.

SIBLINGS SWEPT, same mechanism, same sweep: `_find_suspending_cycle` reads the
broad bit too (`t.suspends`, ~:1732) and is NOT affected — `_analyze_nesting`
passes `is_built`, which narrows the walk to frames the closure walk actually
builds, so a conservative-only cycle is never reached (probed:
`.build/scratch/probe_conservative_cycle.saw` compiles and runs). The
`_suspending_methods_set` census reads the broad bit as a FIRST gate and then
asks `_own_suspending_methods_set`, so its final answer is the framing one. The
third sibling is design 260's consuming fences, filed separately.

FIX DIRECTION: `_default_expr_suspends` asks `frame_boundary` for its free-call
and method-call arms. It changes which programs compile (strictly more), so it
wants the ledger's reading rather than a point edit — SL-318 U1/U2.
