## Description

SL-260 found an uncontextualized integer outside platform Int's range silently truncated instead of rejected. Existing fixture prototypes/minivm/examples/numbers/reject_uncontextual_u64.saw:

```saw
func main() { print(18446744073709551615) }
```

Actual on arm64 macOS: compiler succeeds; executable prints -1. Expected: located integer literal range error. LANGUAGE_SPEC.md's integer literal rules say an uncontextualized bare literal defaults to platform Int and a value outside the target word range is a compile error. No UInt destination supplies a different expected type here. The prototype correctly rejects it.

Mechanism: visit_IntLiteral selects Int without enforcing that default type's range; lowering truncates the magnitude into signed i64. Add the range check after contextual typing has had its opportunity, preserving valid explicitly/contextually unsigned values. Sweep positive and negative boundaries, unary spelling, arguments/locals/tails, numeric bases and target word size. Do not merely special-case print or this maximum literal.
