Found by the SL-1049 spec review (F2). Appendix 0 says `-o` defaults to `.build/<source>`. In a directory with no `.build/`, `sawc build hello.saw` fails: "sawc: cannot create .build/hello.ll: open ".build/hello.ll" failed (not found)", and nothing is built. `-c` with no `-o` fails the same way (`.build/hello.o.ll`). After `mkdir .build`, the same command works. Probes: `.build/scratch/p1000o/cli1.sh`, `cli2.sh`.

**Expected:** a default output path works on its own, so sawc creates the `.build/` directory it chose (the doctrine that APIs do the expected thing). A path the user names with `-o` keeps today's behaviour, and a missing directory there is the user's error, reported as it is now.
