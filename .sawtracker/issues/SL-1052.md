**Implementation detail (lead, Nov 12): sawc makes the `.build/` directory it chose for a default output.**

**Today:** in a directory with no `.build/`, `sawc build hello.saw` (and `sawc hello.saw`, and `-c` with no `-o`) fails with `sawc: cannot create .build/hello.ll: open ".build/hello.ll" failed (not found)`. A first-time user's first command fails.

**Where.** `compiler/driver/src/main.saw`: the build command sets `out = driver_default_output(path)` when `-o` was not given (`driver_default_output` returns `.build/NAME`). `driver_make_directories(path)` already exists (it makes a directory and each missing one above it, returns "" or the reason, and treats a directory another build made meanwhile as success).

**The change.**
1. Where the build command falls back to `driver_default_output`, call `driver_make_directories(".build")` before anything is written. On a non-empty reason print `sawc build: {reason}, where the default output goes; name another place with -o` and return 1. Use the command's own name in the prefix as the neighbouring messages do (`command`).

3. Sweep (obligation 4): every other place the driver derives a path under `.build/` on its own when the user named none (grep `driver_default_output` and each literal `".build"` in `compiler/driver/src/`). **The lead's ruling on the stop at the pin's third case (Nov 14).** Agent p1052's fix works for the case the issue is about: with no `.build/`, `sawc build hello.saw`, `sawc hello.saw` and `sawc build -c hello.saw` each exit 0 and leave their output under a `.build/` sawc made (`.build/scratch/p1052/step0_after.txt` in the lead's checkout). The third case of the pin I specified cannot be met as written, and the reason is not this unit's.

**Why.** With `.build` a regular FILE, `driver_make_directories(".build")` answers "" (nothing to do): `Directory.exists` is true for a file as well as a directory (`std/directory.saw`: it delegates to `File.exists`), and std has no way to tell the two apart (SL-1094, filed by sawos on Nov 13). So the build goes on and fails where it always did: `sawc: cannot create .build/hello.ll: open ".build/hello.ll" failed (other error, errno 20)`, exit 1.

**Ruling.**
- `driver_make_directories` is not changed here. It has three other callers, and the right fix is for it to ask std whether a path is a directory once std can answer; listing a directory to find out (the workaround Blade uses) is not something to put on every build's path.
- The pin's third case stays, with what holds today: `.build` a regular file gives exit 1 and a message that names the path under `.build` it could not create, and no output is produced. It does not require the new "where the default output goes" text. The check's comment says in one sentence why (an existing file reads as an existing directory to the driver).
- The new refusal text stays in the code for the failures `driver_make_directories` can report (a `.build` it cannot create: a read-only directory, say). Add that as the check's third-and-a-half case if it can be made without root and cleaned up reliably (a parent directory with its write permission removed, restored in a `finally`); if it cannot be made reliable under the fixpoint twin and in the server's sandbox, leave it out and say so.
- The lead notes on SL-1094 that the driver's helper should use it.

**Then, as the brief has it:** the `LANGUAGE_SPEC.md` marker (read the sentence around line 17545 whole before editing; delete only what says the directory is not made yet, keep the rest true), the check on the std lane's driver cone and the pinned IR, the gate, one commit.
