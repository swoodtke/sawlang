## Description

# M19: canonical output and examples inventory

M18 (SL-301, under SL-300) supplies the indexed syntax tree. This next
increment adds a Saw canonical renderer and a reproducible inventory of the
examples corpus. It does not expand the grammar or change the production
compiler. Work starts stacked on M18; submission must identify that dependency.

## Canonical renderer

Add `prototypes/parser/src/canonical.saw`, assembled after the lexer and
parser. Public entry: `canonical_ast(tree: &AstTree) -> Result<String, AstError>`.
The input contract is a tree returned by `parse_ast`; arbitrary fabricated
arenas are not a serialization format. Return a complete string or a located
error, never partial output presented as success.

Match the parse-only `sawc/ast_dump.py` byte format (without IDs, typechecking,
stdlib, or trailing newline). `tools/dump_ast.py` adds one CLI newline; the
comparison adapter removes exactly that one byte. Preserve embedded newlines,
NUL, Unicode, and spaces in string payloads. The current StringLiteral writer
escapes double quotes only; do not substitute JSON escaping.

Use an explicit traversal/action stack, so valid depth-256 trees and long
shallow expression chains do not consume recursive VM call frames. Named
enums describe action kinds. Emit one shared indentation/line funnel.

Program emits `Program {`, an optional `functions: [` list, and closing lines.
Function emits ordered inline `name: Type` parameters and return type, braces,
then its block contents. Parameter/NamedType/Block are structural, not standalone
canonical headers. Let and Var both emit LetStatement with the mutability word
and optional annotation. Return, ExpressionStatement, FinalExpression map to
ReturnStatement, ExpressionStatement, and `final_expr:` respectively. Binary
children use `left:` and `right:`; Unary has a single indented operand.
Identifier, BooleanLiteral and string literals follow their Python arms exactly.

IntegerLiteral text retains normalized base notation plus suffix in M18.
Canonical IntLiteral uses the mathematical decimal value and the fixed `: Int`
label, as the existing dumper does. Strip only recognized suffixes; convert
base 2/8/16 to decimal with digit arithmetic rather than a machine-sized Int
accumulator. Test UInt64's maximum (beyond signed Int), each radix, and suffixes.
The unchanged lexer bounds admitted integer magnitudes; this milestone does
not expand those bounds. This is rendering, not range/type checking; preserve
the original AST text.

A Call whose callee is Identifier emits `FunctionCall name()` and ordered
`arg[i]: ` labels, including the existing trailing space. The canonical schema
cannot represent an arbitrary callee expression: return a located renderer
error for other callee kinds. Do not flatten, discard, or invent a schema for
them. Grouped identifier calls still have Identifier callees and can render;
Python's misparse of that syntax remains a differential failure (SL-73), not a
permission to copy the bug. This restriction belongs to the renderer, not the
parser grammar.

## Comparison and classification

Keep canonical fixtures separate from M18's arena oracle. Author exact expected
canonical bytes for every supported node and formatting boundary; compare Saw
output under VM, LLVM O0/O2, ASan and production-sawc execution. Independently
invoke the Python parse-only oracle on fixtures within its correct grammar.
Keep debt probes explicit and failing in a diagnostic comparison mode; never
introduce a known-divergence ledger or count debt as agreement.

Inventory every tracked `examples/**/*.saw` file, reporting top-level and
nested counts separately. Use sorted repository-relative paths and source
hashes, with no execution or typechecking of examples. Semantic EXPECT-error
directives do not decide parser eligibility. Record parser verdict, supported
syntax evidence, unsupported features, oracle failures and unresolved cases
separately. A Python AST whitelist alone cannot establish eligibility: it may
have discarded syntax (SL-73), and metadata such as modifiers must be checked.
The classification must not use the prototype's rejection to justify exclusion.

Run admitted examples through the Saw parser and canonical renderer using
bounded embedded-source batches (the VM has no file-reading API). Any unexpected
refusal, mismatch, timeout, crash or malformed protocol record is a failure.
Preserve source, both outputs, commands and diagnostics. Report the total census
and compared count explicitly; never call a partial sweep full parser parity.
Unknown classification stays visible and cannot silently become supported or
excluded. New examples must be reclassified rather than inherited by filename.

## Work and validation

The parent authors the design and reviews integrations. Sol source agent owns
the renderer; Sol harness agent owns canonical fixtures/harness; a separate
Sol agent owns census/classification. Use isolated worktrees. Serialize compiler
gates with the machine-wide suite lock. Focused Python tests cover classification
drift, semantic-negative eligibility, failure reporting and byte preservation.
No production compiler edits are included. File new production findings in
sawtracker, checking existing issues first.

The first checkpoint is the renderer and measured inventory. Any ambiguous
grammar classification is reported for review before a comparison scope is
frozen. Full grammar parity, file-reading CLI, parser integration into the VM,
and the complete design-259 port remain later milestones.
