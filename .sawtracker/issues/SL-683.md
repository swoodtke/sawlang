## Description

**Found by A8b (SL-564), a8bspawn.** A `group.spawn` handle can outlive its group, and its `join`, `cancel` and `detach` then read the group's dead storage. Safe code reaches it once `group.spawn` lowers (A8b); before A8b no safe code minted a handle into a group that can die, since `Task.spawn`'s background group lives to the process's end.

**Repro** (`sawc2 build --std-root std`, A8b's branch):

```saw
import std.task.*

func work(n: Int) -> Int {
    yield_now()
    n
}

func leak() -> Task<Int> {
    var g = TaskGroup()
    g.spawn(work(5))          // the group dies at `leak`'s return
}

func clobber(n: Int) -> Int {
    var a = n
    var b = n * 2
    var c = n * 3
    var d = n * 4
    a + b + c + d
}

func main() {
    let h = leak()
    print("clobber {}", clobber(9))
    print("joined {}", h.join())
}
```

- `-O0`: `panic at taskgroup.saw:821: Task.join: this task's result is gone` (the dead frame's slot vector happened to read as stale);
- `-O2`: `panic at vector.saw:71: Vector.[]: buffer is empty`: the handle read whatever the stack held;
- Stage 0: `panic at taskgroup.saw:1788: Task.join: this task's result was already joined`. Stage 0 has the same class; its message is also a read of storage the group no longer owns.

**Mechanism.** `Task<T>` and `VoidTask` hold the group as an `UnsafePointer<TaskGroup>` (and Stage 0's, raw pointers into the group-owned cell). `group.spawn` borrows the group only for the spawn statement, and nothing, static or run-time, bounds a handle's life by its group's. The spec gives a spawn *borrow* an extent the handle carries ("The borrow's extent is the task's life"), but says nothing of the handle's own reference to its group: the "Invariant (for future features)" paragraph of the Law of Exclusivity names exactly this kind of reference, one with no statically known extent.

**Escape routes** (each a way out of the group's scope): a handle returned from the function that owns the group (above); a handle assigned to a binding declared before the group, in an outer scope, then joined after the group's block ends; a handle moved into a struct or collection that outlives the group. A handle minted through a `&TaskGroup` parameter is sound only while the caller keeps the group alive, which the same rule would cover.

**Fix directions** (a ruling is needed):
- (a) static: the handle carries a shared loan of its group, as A8c's extents carry spawn borrows, so the borrow check refuses every escape past the group; it fits A8c's machinery (SL:coroutines A8c);
- (b) run-time: the handle reaches a cell that outlives the group (refcounted), and the group's teardown marks it, so a late `join` panics naming the cause rather than reading freed storage.

**Air, evidence for the SL-683 ruling.** Probes are in `.build/scratch/air-review/sl683/` on the Air, all run on Stage 0, since sawc2 has no spawn-borrow extents yet.

**1. A shared loan per handle conflicts only with the group's death.** The spec (TaskGroup, under Concurrency) says "`spawn` works through a shared reference to the group". `TaskGroup` is `NoMove`, and in the new std its only public `&var self` member is `deinit` (`count` takes `&self`). So under (a), more spawns, joins and counts while handles live all stay legal. The one use a handle's loan would refuse is the group dying first, which is exactly the escape.

**2. Stage 0 already reasons this way about spawn borrows.**
- **A loan survives the handle being stored** (`e1_stored_borrow`): with a handle holding `&var n` moved into a `Vector<Task<Int>>`, reading `n` is still refused ("the task spawned at line 16 holds `&var n` until `h.join()` releases it"), as with the handle in its own binding (`e2`).
- **Roots must outlive the group, by declaration order** (`e3_return_borrow`): a borrow root declared after its group is refused, because "destruction is LIFO — `n` is torn down BEFORE `group` joins its children".

(a) is the same declaration-order argument, applied to where the handle itself lives.

**3. Stage 0 has the class, confirming a8bspawn.** These build and panic with `Task.join: this task's result was already joined`:
- the returned handle (`e5_returned`, the issue's repro);
- the outer binding (`e4_outer_binding`: a `Task<Int>?` declared before the group, assigned inside its block, taken and joined after).

**4. What (a) must keep.** Seven corpus programs keep group handles in a `Vector<Task<…>>`:
- `taskgroup_slot_reuse_mt`, `taskgroup_threads_deinit_once`, `taskgroup_mt_live_pool_soak`, `taskgroup_threads_send_enum_field`, `taskgroup_threads_parallel_sum`;
- `errors/retired_task_handle_names`, `conformance/K53_mt_group_stays_live_across_spawns`.

Each declares the vector after its group, so it dies first. A rule letting the loan travel into any place that dies before the group (e1's behaviour) keeps all seven. K86's vector holds `Task.spawn` handles, whose background group never dies, so it's unaffected.

**5. Against (b):**
- A cell that outlives the group is an allocation no source construct names: one per group or per handle, which `--no-hidden-alloc` exists to refuse and a freestanding group would pay for.
- It also trades a static guarantee for a run-time panic. The Law of Exclusivity's "Invariant (for future features)" says a reference with no static extent must "either be given one or be kept out".

**6. One question for the ruling, if (a):** is the loan charged to the group's place, or to the group itself?
- Places charge their root, so a handle from `boxed.spawn(…)` on a `Box<TaskGroup>` would pin the `Box` against a move, even though the group, on the heap, doesn't move.
- The spec intends heap-owned groups ("the scope a group defines for its tasks is its ownership extent, not a lexical block").
- Refusing that move is sound but over-strict, and worth deciding on purpose.

**Sequencing:** Stage 0 has the same hole, so landing A8b with SL-683 open doesn't regress against the oracle. That's provided the hole is recorded: a hazards entry, plus a pin of `e5` citing SL-683, with an EXPECT of the intended refusal. The fix then lands with A8c, whose extent machinery it shares.
