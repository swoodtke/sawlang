## Description

**An extern taking or returning a struct by value is `backend.not-yet`; the spec rules it out, so it should be a typecheck error** (found by p848, SL-848 step 1, Oct 23).

The spec's FFI section says to "pass `UnsafePointer<CStruct>`, never a by-value struct". But an `extern "C"` parameter or result of a struct, tuple, tagged enum or `String` type compiles through typecheck and stops in the backend with `backend.not-yet` ("crosses the C convention as an aggregate … not in the backend slice yet"). "Not yet" promises a feature the spec says will never exist.

**Scope:** the extern signature whitelist refuses each by-value aggregate at the declaration, in typecheck, with a fixit naming the `UnsafePointer<T>` form (the way `export.c-abi` refuses `@export`). One funnel, shared with `export_class` if it fits. The backend's refusal becomes unreachable (keep it as an assertion). Pins: struct, tuple, tagged enum, `String`, `Int32?`, `UnsafePointer<any P>`, a double optional, in parameter and result positions.
