**Air, design review of SL:borrowing §12 (r31).** The rule is coherent with §2's evaluation rules. Every window still ends at a visible brace or statement end, and nothing here needs a new soundness mechanism; the funnel in 12.8 is the right shape. My probes are on main after SL-849, in `.build/scratch/air-review/sl897/` on the Air.

**1. A text fix in 12.5: NoCopy has no `copy()`.** The first teaching error offers `sessions[0].copy()` for a NoCopy `Session`. On main that's `member.unknown`: "`Session` is NoCopy, so it has no `copy()`; move it instead" (`d2_nocopy_copy.saw`). The text has to depend on the tier:
- ExplicitCopy: `.copy()` or the block;
- NoCopy: the block, or taking the element out (`swap_out`, `remove`).

The diagnostic should pick by the element's tier. (I've put this on 12.5 as a doc comment too.)

**2. The evaluation order of a chain of unnamed lends needs one sentence, since §12 makes these chains the everyday spelling.** On main today (SL-866's probe `n4_order_only.saw`, with each accessor's prologue printing):
- `borrow var b.get(0).bump(by: side("b"))`, a plain method on a lent place, prints `pro get 0`, then `side b`: receiver first, as SL-473 fixed.
- `borrow var b.get(0).at(side("a")) += 100`, an accessor on a lent place, prints `side a`, then `pro get 0`: the argument first.

12.1 says every §2.2 rule "stands unchanged", but §2.2 doesn't say which of these is right. SL-840's open S4 ruling (the receiver's exclusive borrow begins after the arguments) would make the second order the intended one, and then the first would be the outlier. Either way, the order in which a prologue's side effects run relative to the arguments is observable. 12.1 or SL-840 should state it for both shapes, and the funnel's pins should include one of each.

**3. Migration: an unmarked `if let` over a lend changes meaning between v0.18.0 and §12.** On v0.18.0 the plain `if let x = m.find(&k)` copied the payload (§2.4), so `if let x = m.find(&"a") { m["b"] = x + 1 }` compiled. Under 12.2 it holds `m` for the block, and that is refused (on main today it's `borrows.unmarked-call`, `d1_if_let_root.saw`). It's loud rather than silent, which is right. But a 0.18.0 consumer will hit it, so it's worth its own teaching error: "`x` now holds `m.find(&"a")`'s place for this block; to work on `m` inside it, copy the value out first: `let v = m.find(&"a")` (an `Int?`)".

**4. 12.8 and m603 disagree about sawtracker.** 12.8's last line says ST-97 "adopts the new spelling before it commits its port". Your m603 plan, which I agree with, says to land on v0.18.0 now and adopt nothing early, with unit 1 accepting both spellings and released as v0.19.0. 12.8 should say the m603 version. Also, sawtracker's 275 pre-marked `borrow` lines are exactly what unit 1's warning-plus-fixit will migrate, which is a good first real consumer for the fixit.

**On the three proposals:**
- **P1 (`-W copy-written-then-dropped`): yes.** It's the one silent trap 12.1/12.2 create: `var x = v[0]; x.n += 1` meaning in place. Off by default, like every `-W`; `-W` itself is SL-879's work on sawc.
- **P2 (refuse a type conforming to both `Iterator` and `LendingIterator`): yes.** Otherwise `for x in t` has two meanings. Refuse at the second conformance, naming both.
- **P3 (keep `borrow let e = m.find(&k) { … }` binding an optional place): yes.** It's harmless and already in §2.1. One teaching note: inside that block `e` is `&T?`, so `e!` / `e?.f` apply, while `if let` gives `&T` directly.
