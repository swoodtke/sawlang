## Description

**`Box<T>` is never `Send` or `Sync`, on either std.** Found by SL-675's sweep (agent u675unsafe).

**Evidence** (`need<T: Send>(x: &T) {}` then `need(&b)` with `b: &Box<Int>`):

| compiler | std | result |
|---|---|---|
| sawc2 `typecheck --check` | `sawc/` (default root) | `type.bound`: `std.box.Box<Int, std.alloc.GlobalAllocator>` does not satisfy `Send` |
| sawc2 `typecheck --check --std-root std` | `std/` | the same |
| Stage 0 `sawc/sawc.py -c` | `sawc/std` | "type `Box<Int, GlobalAllocator>` does not satisfy the `Send` bound" |

**Mechanism:** a std type that owns its storage through a raw pointer derives neither property, by design, and says what holds with a conditional assertion beside the type (`extension Vector<T: Send, A: Send>: UnsafeSend {}`, and `Map`'s, `Data`'s, `String`'s). `std/box.saw` and `sawc/std/box.saw` declare none, so `Box<T>` is never `Send`, whatever `T` is. The spec says it is: "`Arc`, `Mutex`, `Box` and a struct field are each `Send`/`Sync` exactly when their contents are" (Send and Sync, "Nothing upgrades a non-`Send` type"). Every type holding a `Box` inherits the gap: a recursive `struct Node { next: Box<Node>? }` can't cross a spawn.

**Sweep owed** (obligation 4): every std type whose fields hold an `UnsafePointer`, an `UnsafeMemory` or an interior cell, in both `std/` and `sawc/std/`, against its spec'd `Send`/`Sync` answer. The ones already asserting are `Vector`, `Map`, `Data`, `String`, `StringBuilder`, `Atomic`, `Mutex`, `SpinLock`, `Once` (new std) and `Arc`, `Channel`, `Thread`, `VoidThread`, `DataBuf` besides (Stage 0's). `Box` is the first found without one; `Set`, `Task`, `TaskGroup` and the `Channel` of the new std are the next to check.

**Fix shape:** `extension Box<T: Send, A: Send>: UnsafeSend {}` and the `Sync` twin beside the type, which SL-675's header check accepts (the pointer is the only blocker). Stage 0's std needs the same if Stage 0 should agree.
