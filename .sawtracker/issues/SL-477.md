## Description

**A non-escaping closure's take-once `[move v]` capture is lowered wrong in sawc2's MIR. The capture moves `v` into the environment at capture time, the body moves it out through the shared `&` environment, and the environment's glue frees it again.** So `v` is freed twice after a single call, and a second call moves out of freed storage with no occupancy check. Found by the Air pre-reviewing the SL-475 unit (SL-475 c3). Its probe is `.build/scratch/air-review/mir475/probe_take_once.saw` on the Air.

```saw
func run(body: () -> Int) -> Int { body() }
func run_twice(body: () -> Int) -> Int { body() + body() }
func once() -> Int  { let r = Res(name: "abc"); run({ [move r] in sink(move r) }) }
func twice() -> Int { let r = Res(name: "abc"); run_twice({ [move r] in sink(move r) }) }
```

**Stage 0 (the oracle):** `once()` prints 3, and `twice()` panics with "closure body ran twice on `move` capture `r`" (rc 134). Its mechanism (`sawc/codegen/closures.py`, `_deferred_field`):
- the non-escaping environment holds a pointer to the enclosing local and a pointer to its drop flag;
- the body's prologue takes the value and clears the flag, which doubles as occupancy, so a second run panics;
- the enclosing local stays drop-if-initialised, so a body that never runs leaves `r` to the enclosing scope's end;
- a non-escaping environment has no teardown.

The spec makes this meaning, not an implementation choice: "a `[move r]` capture transfers when the body runs".

**This is design work.** Settle each of these in the brief:
1. **A MIR shape for the take:** a move-out, a flag clear, and a panic on repeat. The verifier admits it, and nothing else spells it. That's preferred over an exemption in SL-475's "no owning move through a Deref" invariant.
2. **The drop flag.** The enclosing local's flag is cleared by another function, the closure body, through a pointer. Today drop elaboration creates flags after lowering. Choose either a "take" capture kind that elaboration materialises (the flag plus the body's prologue), or a flag that MIR creates up front.
3. **Borrowck's reading:** statically `r` is moved at the capture; dynamically it's maybe-moved. Say which analysis owns which half.
4. **Pins:**
   - `once()` drops `r` exactly once, from the body's take;
   - a callee that never calls the body leaves `r` to the enclosing scope's end;
   - `twice()` panics with Stage 0's message;
   - SL-475's escaping read-only row is unchanged.

It must land before any backend. It comes after SL-475's unit.

**Design for SL-477: the take-once `[move v]` in MIR** (agent:claude-sawlang/mir477). Implementing it now; the Air reviews it with the patch.

**Which captures take.** A capture takes when its closure does not escape, it is a `[move v]`, and its type owns something (MIR's `owns`). That is Stage 0's `deferred_moves`. A `[move n]` that owns nothing keeps its plain load.

## 1. The MIR shape

**The capture, in the enclosing function.** MIR creates a `Bool` take flag (local kind `Flag`, dump note `// flag r`), one per captured local per function. Two takes of one local share it. The environment entry is a new rvalue, `take(PLACE, FLAG)`, of type `(&var T, &var Bool)`: an exclusive reference to the local and one to its flag. This is Stage 0's `{ T*, i1* }`.

```
_5 = take(_1, _4);
_3 = closure#0 of take.once() [move _5];
```

**The body.** Environment element K is `(&var T, &var Bool)`, and the prologue is:

```
bb0: { switch copy (*(*_1).0.1) -> [true: bb2, false: bb1]; }
bb1: { call builtin panic [const "closure body ran twice on `move` capture `r`": String] -> !; }
bb2: { _2 = move (*(*_1).0.0);
       (*(*_1).0.1) = const false;
       ... }
```

- `_2` is an ordinary owned local of the body. A body that does not move it on drops it at its end.
- One helper, `load_take_capture`, is the only thing that emits this shape.
- The environment now holds only references, so its glue releases nothing. That closes the second free.

**The verifier.** `verify_moves` admits an owning move through a `Deref` in exactly this shape:
- the function is a closure;
- the place is exactly `(*(*_1).K.0)`, for a capture K the capture table makes a take;
- the next statement of the block clears `(*(*_1).K.1)`;
- the block's only predecessor ends in `switch copy (*(*_1).K.1)`, whose true arm enters it and whose false arm is a block holding nothing but a builtin `panic` that never returns.

The `take_once_capture` exemption is deleted. The epilogue's record-load exemption stays.

## 2. The drop flag: MIR creates it up front

**Why MIR creates it:**
- **Two functions share the flag.** The enclosing environment entry names it, and the body's prologue reads and clears it. Both are laid out at lowering: the environment's type and the body's blocks. If drop elaboration created the flag, it would have to retype an environment and rewrite another function's entry, after the borrow check had already checked both.
- **The flag is program meaning, not only drop bookkeeping.** It is the occupancy the repeat panic tests. So the verifier and the borrow check should see the whole take before elaboration runs.

**Drop elaboration still owns every write of the flag in the enclosing function:**
- It adopts the take flag as the captured path's drop flag. A path never gets a second flag. If two takes of one path named different flags, that is an `INVARIANT`.
- It sets the flag from the entry conditions, and at each assignment, by its ordinary transfer.
- It leaves the flag alone at the take, since its value passes to the closure.
- The drop of `v` at its scope end is labelled `flagged`, so it comes out as drop-if-flag: `switch copy _4 -> [true: bbD, false: bbC]`, then `drop(_1); _4 = const false` in bbD.

MIR leaves the flag unwritten, as it already does for an accessor record's flag field.

## 3. The borrow check's reading

One analysis owns both halves: the shared initialisation analysis. It gets a `Take` access, the place of a `take` rvalue. That access leaves the path, and every path inside it, `W M`, as an epilogue's resume does.

**The static half is the `M` bit.**
- `move.use-after` refuses any later read, borrow or move of `v`, exactly as after a move, and names the take as the move site.
- The take itself is a use, so taking a maybe-moved `v` is refused.
- The loan half reads the take as a move of `v`, so `loan.move-while-borrowed` applies. It makes no loan, since the `M` bit already leaves nothing able to reach `v`.

**The dynamic half is the `W` bit.**
- `W M` is maybe-initialised, so the drop at `v`'s scope end is labelled `flagged`, and elaboration guards it with the take flag.
- At the take, the flag's update is "keep": the closure decides it at run time.
- The drops verifier needs no new fact. Its false-edge refinement and its leak check already cover `W M`.

**In the body,** the take reaches through the environment reference, so the analysis reads it as a read of `_1`.

## Pins

These go in a new `takes` golden (mir and drops), plus the drops checker:
- `once()` drops `r` once, from the body's take.
- A callee that never calls the body leaves `r` to the guarded drop at the enclosing scope's end.
- `twice()` reaches the panic block with Stage 0's text.

SL-475's escaping read-only row and the `captures` and `generics` drops goldens stay unchanged.
