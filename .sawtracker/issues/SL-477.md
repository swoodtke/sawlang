## Description

**A non-escaping closure's take-once `[move v]` capture is lowered wrong in sawc2's MIR. The capture moves `v` into the environment at capture time, the body moves it out through the shared `&` environment, and the environment's glue frees it again.** So `v` is freed twice after a single call, and a second call moves out of freed storage with no occupancy check. Found by the Air pre-reviewing the SL-475 unit (SL-475 c3). Its probe is `.build/scratch/air-review/mir475/probe_take_once.saw` on the Air.

```saw
func run(body: () -> Int) -> Int { body() }
func run_twice(body: () -> Int) -> Int { body() + body() }
func once() -> Int  { let r = Res(name: "abc"); run({ [move r] in sink(move r) }) }
func twice() -> Int { let r = Res(name: "abc"); run_twice({ [move r] in sink(move r) }) }
```

**Stage 0 (the oracle):** `once()` prints 3, and `twice()` panics with "closure body ran twice on `move` capture `r`" (rc 134). Its mechanism (`sawc/codegen/closures.py`, `_deferred_field`):
- the non-escaping environment holds a pointer to the enclosing local and a pointer to its drop flag;
- the body's prologue takes the value and clears the flag, which doubles as occupancy, so a second run panics;
- the enclosing local stays drop-if-initialised, so a body that never runs leaves `r` to the enclosing scope's end;
- a non-escaping environment has no teardown.

The spec makes this meaning, not an implementation choice: "a `[move r]` capture transfers when the body runs".

**This is design work.** Settle each of these in the brief:
1. **A MIR shape for the take:** a move-out, a flag clear, and a panic on repeat. The verifier admits it, and nothing else spells it. That's preferred over an exemption in SL-475's "no owning move through a Deref" invariant.
2. **The drop flag.** The enclosing local's flag is cleared by another function, the closure body, through a pointer. Today drop elaboration creates flags after lowering. Choose either a "take" capture kind that elaboration materialises (the flag plus the body's prologue), or a flag that MIR creates up front.
3. **Borrowck's reading:** statically `r` is moved at the capture; dynamically it's maybe-moved. Say which analysis owns which half.
4. **Pins:**
   - `once()` drops `r` exactly once, from the body's take;
   - a callee that never calls the body leaves `r` to the enclosing scope's end;
   - `twice()` panics with Stage 0's message;
   - SL-475's escaping read-only row is unchanged.

It must land before any backend. It comes after SL-475's unit.
