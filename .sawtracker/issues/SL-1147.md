## Description

**A distinct alias of a generic instance cannot be constructed.** Found by SL-1129's U3 design pass (Nov 15): `type High = Mask<16>` then `High(x: 1)` is refused with `infer.failed`, where `Mask<16>(x: 1)` builds. Also check a plain generic type (`type Ints = Vector<Int>`, `Ints()`), a generic type with a type argument and a const one, and an alias of an alias. The spec's distinct-aliases section says what an alias's construction is: measure each against it, and refuse cleanly or build as it says.

Related: SL-1129.


## Comments

**Sweep done (lead, Nov 16; Sonnet, read-only): `.build/scratch/s1147/report.md` in the lead's checkout, ~140 probes beside it. SL-1147 is one cell of SL-1012 (alias identity) and is folded into SL-1012's design pass.**

- **Cause** (`init_call`, `compiler/typecheck/src/bodies.saw`): an alias head's type `Mask<16>` is reduced to its declaration (`nominal_decl`), dropping its arguments; only an alias of a primitive reaches `alias_construct` (the spec's `Alias(value)`), so a struct or instance target is constructed as its bare target and a generic one needs inference only an expected type supplies. Same cause as SL-744.
- **Worse than the title:** the alias's arguments are not used at all, so wrong instances build silently: `type PS = Pair<String>; PS(x: 1)` builds a `Pair<Int>`; `type PB = Pair<UInt8>; PB(x: 300)` builds and prints 300; `High<99>(x: 1)` builds a `Mask<99>`.
- **Siblings:** statics and enum cases through an alias (`member.unknown`, SL-1050); `extension High` reported as `slice.not-yet`; `as` on a struct alias `backend.not-yet`; an alias of a user generic enum accepted (the spec refuses it).
- **What decides the fix:** the owner's SL-1012 ruling (Nov 9: `type A = B` is DISTINCT; the spec kept): the spec's only construction into a distinct type is `Alias(value)`, one unlabeled argument checked against the underlying type. SL-1012's Opus design pass (owed since Nov 12) takes this sweep as input and settles construction, statics, extensions and `as` together; questions the spec leaves open go to the owner from it.
