Submitted patch SL-259.p1 (revision 1): M16: compile the unchanged lexer with the Saw prototype

The prototype now compiles the unchanged selfhost/lexer/src/lib.saw, with a generated driver, and runs the resulting complete lexer through the VM and textual LLVM/native backend. M16 supplies the gaps exposed by that integration: StringBuilder.clear(), bare while-break with owning cleanup, Void expression arms in statement matches, and repeatable nonbinding let _ declarations with immediate owned-result cleanup.

The new test_lexer.py compares complete tokens, suffixes, positions, doc trivia, interpolation segments and errors across VM, native O0/O2/ASan and the same source built by Python sawc. It includes exact independent golden records, an explicit lexical edge grid, configurable tracked-source sweeps and preserved failure artifacts.

COMPATIBILITY.md consolidates known semantic differences, unsupported features and runtime limits into a follow-up ledger. It explicitly distinguishes Vector snapshot reads from production borrowing places, Copy-only elements, bounded moves and the remaining generics/recursive-data/coroutine work. Lexer acceptance is not a claim of full Saw support or compiler self-compilation.
