SL-242's acceptance row. minivm compiles selfhost/lexer/src/lib.saw UNCHANGED (plus a small driver wrapper — the lexer has no imports, so no module loading needed), through BOTH engines; then a corpus sweep diffs its token stream against the sawc-built selfhost lexer — the first true self-hosting differential gate. Submitted patch SL-259.p1 (revision 1): M16: compile the unchanged lexer with the Saw prototype

The prototype now compiles the unchanged selfhost/lexer/src/lib.saw, with a generated driver, and runs the resulting complete lexer through the VM and textual LLVM/native backend. M16 supplies the gaps exposed by that integration: StringBuilder.clear(), bare while-break with owning cleanup, Void expression arms in statement matches, and repeatable nonbinding let _ declarations with immediate owned-result cleanup.

The new test_lexer.py compares complete tokens, suffixes, positions, doc trivia, interpolation segments and errors across VM, native O0/O2/ASan and the same source built by Python sawc. It includes exact independent golden records, an explicit lexical edge grid, configurable tracked-source sweeps and preserved failure artifacts.

COMPATIBILITY.md consolidates known semantic differences, unsupported features and runtime limits into a follow-up ledger. It explicitly distinguishes Vector snapshot reads from production borrowing places, Copy-only elements, bounded moves and the remaining generics/recursive-data/coroutine work. Lexer acceptance is not a claim of full Saw support or compiler self-compilation.

Validation passed:
- All 439 prototype regression cases; 15 focused completion cases, with all 13 selected sawc comparisons agreeing.
- 39 default lexer inputs plus 100 additional tracked Saw files, all compared through VM, native O0/O2/ASan and Python-sawc-built lexer.
- Five exact complete golden records covering empty input, ordinary tokens, error, doc trivia and interpolation.
- Independent BuilderClear verifier/runtime contract in VM and native O0/O2/ASan, including snapshots and allocation-failure-counter preservation.
- Citation and diff checks.

No production compiler or lexer source changes. Reproduction commands and precise limits are recorded in M16_LEXER_ACCEPTANCE.md and README.md. Follows merged SL-258.

Independently validated on a worktree at current main (c06b3200), patch applies clean: minivm builds (--module-path sawlex=selfhost/lexer), test_minivm.py 439/439, and test_lexer.py's default corpus 39/39 through VM, native O0/O2/ASan and the sawc-built lexer — including tracked/lexer (the lexer lexing its own source) and the five hand-authored golden records.

What makes this a real acceptance gate rather than a self-agreeing one: the goldens are authored independently of the Saw serializer; String values dump as byte counts + individual byte values so delimiters/NULs cannot hide differences; invalid UTF-8 survives the generated-source round trip via surrogateescape byte appends; failure artifacts are preserved under .build/scratch. The four M16 subset slices (BuilderClear through frontend/verify/vm/llvm; bare break with owning cleanup + patched jump lists; Void-call expression arms; repeatable let _ with immediate owned-result drops) each carry focused reject pins, and break-with-value/continue/labeled stay located rejections.

Process notes, both exemplary: production divergences became SL-284/SL-285 filings with the prototype deliberately NOT reproducing the incorrect acceptances (the differential's founding rule), and COMPATIBILITY.md separates semantic gaps from implementation limits without conformance overclaim — the "absence from this list is not evidence it works" close is the right posture.

One recorded observation, no change requested: VM BuilderClear allocates a fresh empty header rather than truncating in place; COMPATIBILITY.md's allocation-behavior row already flags the nonallocating-clear audit as future work, which is where it belongs.
