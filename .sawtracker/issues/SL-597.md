**S1. `Map` and `Set` in the new std** (unit 1 of SL-596).
- **Scope:**
  - **Port `sawc/std/map.saw` and `sawc/std/set.saw`** into `std/map.saw` and `std/set.saw`, in the bootstrap language: open addressing, linear probing, tombstones, power-of-two capacity, and the `ExplicitCopy` conformance when both `K` and `V` are.
  - **Load them** with two rows in `compiler/resolve/src/loader.saw`'s `load_new_std_modules`. The prelude already names `Map` and `Set` from `std.map`/`std.set` (`resolve/src/prelude.saw`), and typecheck already looks up `known.map`/`known.set`, so collection literals type once the modules exist.
- **API:** the current spec's, not Stage 0's leftovers.
  - Allocating ops return `Result<_, AllocError>`, all-or-nothing (design 234).
  - `get`-shaped ops return `Optional`; checked accessors panic.
  - `Map.[]` is a place (design 141/146).
  - Iteration order is unspecified.
  - The `try_copy` family stays pending DF-257b's naming ruling: port it as Stage 0 has it, and say so.

  Where Stage 0's std and the spec disagree, the spec wins, and the report lists each divergence.
- **Depends on:** nothing. `Hashable`, `Hasher` and `Equatable` are already in `std/prelude.saw`.
- **Files:** `std/map.saw` and `std/set.saw` (new), `compiler/resolve/src/loader.saw` (two rows), and `compiler/tests/std/` (the std lane's programs and fixtures). If `Hasher` or a primitive's `Hashable` is missing, `std/prelude.saw` and `std/scalar.saw` too; say so in the report.
- **Pins:**
  - std-lane programs for insert, lookup, update, remove, growth past several rehashes, the tombstone path, an owning key and an owning value each dropped exactly once, and `Set`'s operations;
  - `tests/corpus/map_literal.saw` and a `Set` literal under `--std-root std` type and run, which closes SL-547's Map and Set rows;
  - the count of corpus programs that newly pass the coroutine census, or get past their first refusal, reported before and after.
- **Done when:** the pins pass and the subset checker is clean on both files.
- **Estimate:** 1.5.
