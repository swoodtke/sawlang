**Review note (lead): SL-597.p1, std unit S1.**

**What landed:** `std/map.saw` and `std/set.saw`, loaded by two rows in `load_new_std_modules`.
- **Map:** open addressing over a raw slot buffer (the idiom the new `Vector` uses).
  - Growth counts occupied plus tombstone slots, at 3/4 load, and a same-size rehash clears tombstones, so a probe always ends at an empty slot. Stage 0 counted only live entries.
  - Replacing the value of a present key never allocates.
  - Keys are compared by reference, so no probe copies them: 43 keys made against Stage 0's 156.
  - `copy`/`try_copy` with `deinit` in the ExplicitCopy conformance.
- **Set** wraps `Map<T, Bool, A>`, since an empty marker struct is refused (L5). The full API is in the agent's report, below.

**Divergences from Stage 0, for the reviewer:**
1. `m[k]` is the spec's getitem: a read-only `(&self) borrows -> &V` lend, panicking on an absent key. There is NO `m[k] = v` yet, because the std profile's frozen parser refuses a setitem declaration (SL-600). The write is refused as `subscript.role`, and pinned so.
2. `get` is the spec's optional copy (`V: Copy`), and `find(&k)` is read-only for now (a writable payload lend needs `borrow var`, SL-600).
3. **Open question for the user:** NoCopy KEYS are accepted. The spec makes them a compile error because "the container probes keys BY COPY". This implementation probes by reference, so that reason no longer applies. The lead has put it to the user; it's either a spec relaxation or a restriction to add.

**Not done, and why:** iteration. The S1 rescope (c3) is blocked on:
- `lends self` (SL-461), so no `Vector.iter`;

On r2's spec text (Air): the ruling is implemented soundly, but one sentence overstates. LANGUAGE_SPEC now says 'The container hashes and compares keys through references and never copies one', and the skill says 'keys are compared by reference, never copied'. S1's probe binds the key by value: `bucket_of` uses `case Occupied(k, _) -> { if k == key …` (and `each_key` and `keys` do the same). So for a `Copy` or `ExplicitCopy` key, a probe DOES copy, or retain. S1's own `map_drops.saw` header says so: 'each copy a probe makes counts as one more key made'. A user who counts copies with a copy hook would see the spec contradicted. For a NoCopy key the same binding can't copy, and sawc2 compiles it as a borrow, which is why the ruling works.

Suggested wording: 'A key is any `Hashable + Equatable` type, in any copy tier. The container never needs a copy of a key: a NoCopy key is hashed and compared in place, and a copyable one may be copied by a probe as its tier allows.' For the skill: 'NoCopy keys included (compared in place; a by-value lookup consumes its key, so probe with `m.find(&k)`)', dropping 'never copied'.

The rest checks out. I probed `Map<Token, String>.keys()` with a NoCopy `Token`: it's a clean `type.bound` refusal ('declared where `K: Copy`'), so no API hands a key out of the table for a NoCopy key. A uniform by-reference probe needs the borrow payload pattern (SL-600, item 4), and could then make 'never copies' true. Until then the sentence should describe what the code does.

**r2 and r3, the NoCopy-key ruling:**
- The user's ruling ('if we can meaningfully use a NoCopy key in a Map then sure, relax the spec') is in LANGUAGE_SPEC and the skill, pinned by `std/calls/map_nocopy_key.saw`.
- r3 fixes the sentence I flagged (c8). The spec now says the container 'never needs a copy of a key: a NoCopy key is hashed and compared in place, and a copyable one may be copied by a probe as its tier allows', which matches `bucket_of`'s by-value binding and `map_drops.saw`'s copy count.
- I probed the one API that could hand a key out of the table: `Map<Token, String>.keys()` with a NoCopy `Token` is a clean `type.bound` refusal ('declared where `K: Copy`').

**The table's invariants, read:**
- **No duplicate keys.** `insert` asks `bucket_of` first, which walks past tombstones to the key or the first Empty slot, and only then takes an open slot. A key behind a tombstone is found, not shadowed.
- **Every probe ends.** `used` counts occupied slots plus tombstones (a tombstone reused by an insert doesn't increase it). The growth test `(used + 1) * 4 > capacity * 3` keeps at least a quarter of the slots Empty, so `open_bucket` always stops, and `bucket_of` is also capped at `capacity` probes.
- **Tombstones are reclaimed.** `rehash_target` doubles only when more than half the slots would be live, and otherwise rehashes at the same size, which clears the tombstones.
- **All-or-nothing growth.** `rehash` allocates and empties the new table before moving any entry, so a refusing `A` returns `false` with the map untouched, and `insert` reports `Err(AllocError)`. The entries move with `move`, so none is dropped or duplicated, and `used` resets to `live`.
- **Ownership.** A replaced entry hands its value back and destroys its old key. `remove` leaves a tombstone, destroys the key and hands the value back. `map_drops.saw` pins exactly-once destruction across replacement, removal, four rehashes and the map's own end.

**A churn probe beyond the pins** (String keys, since Int keys wait on SL-598): 50 rounds of 6 inserts and 5 removes. That piles up tombstones and forces same-size rehashes while the live count stays small.
