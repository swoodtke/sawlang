## Description

**corpusdiff's oracle can't take a refusal test's expected rule from anything but Stage 0's error text, so three lock rows sit in `wrong` while sawc2 is right.**

`oracle.plan_rule` maps a phrase of Stage 0's build error to the sawc2 rule a refusal test should get (`PLAN_RULES`). Stage 0 spells `Mutex.lock`/`SpinLock` bodies as `sync` closures, so its error is the generic `cannot suspend in a \`sync\` closure context`, which maps to `effect.sync`. The ruled mechanism is `borrows.sync-window`: the lock is a `borrows(sync)` accessor (SL:borrowing §2.5, §8), and sawc2 refuses with that rule. No phrase picks out the lock case, so `PLAN_RULES` can't fix it without moving every other `sync`-closure row too.

**Rows:** `errors/mutex_guarded_for_suspends`, `errors/mutex_lock_suspend`, `errors/spinlock_suspending_body`. All are `wrong` ("refused by another rule"), and sawc2's refusal is the correct one. The corpus copy of the first already states the ruled phrase in its `EXPECT-ERROR-CONTAINS`. (Found in SL-703 phase 2; the Air's SL-703 c4 proposed a PLAN_RULES entry, which the agent showed cannot match.)

**Wanted:** a per-path override of the expected rule for a refusal test: an `annotations.tsv` kind (e.g. `plan-rule`, with the rule and a citation), or a rule taken from the corpus copy's own directive when the copy differs from its twin. With it, these three rows pass. It must stay a regression gate: the override names one rule, and any other rule still reads `wrong`.
