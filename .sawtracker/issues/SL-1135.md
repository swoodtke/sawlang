## Description

**An Optional that is a conditional lend cannot be compared with a bare value when its payload does not copy silently: `vt.find(0) == w` is refused, though `vt.find(0) == None` builds.** Found by the reviewer on SL-1124.p2 (Nov 14); the same before and after that patch.

- `vt.find(0) == w`, where `find` is a `borrows -> T?` accessor and `T` is `NoCopy` (and `Equatable`): `borrows.optional-place-read` ("reading it whole copies it out as an Optional"), once for each such comparison in the program.
- `vt.find(0) == None` builds and is right: the `None` test reads the lend's tag in place (the spec's bullet for `None` names a conditional lend as working).
- Since SL-1124, a present comparison (`T? == T`) tests the tag and compares the payload in place through a reference, copying nothing. So nothing about its meaning needs the lend read whole: the refusal is the place-read rule not knowing this reader.

**What the fix is, as far as known:** typecheck's rule that refuses a whole read of a conditional lend's Optional gains the present comparison's Optional operand as a reader that reads in place, as it has the `None` test's (find where the `None` test is exempted: `presence_chain` in `compiler/typecheck/src/bodies.saw` is the same idea for a chain); the lowering's `present_comparison` then needs the lend's window open over the tag test and the payload comparison and closed after, on both paths. Sweep first: every reader of an Optional place that reads in place today, and each kind of lend (a `borrows` method, `v.get(i)`, `m[k]`, a chain ending in one).

**The spec** (Equality, the bullet SL-1124 adds) says this case is not built yet and cites this issue: the patch that fixes it removes that note (a citation of a closed issue fails the citations gate).

Related: SL-1124, SL-917 (a chain that ends in a `borrows` accessor).
