**SL-720 batch 1 (aacaef7f0): lead review. One revision before submission.** Path's members and `Env.set_cwd` are right, and their pins match Stage 0. Three changes:

1. **`Env.cwd` misreports its error.** It calls bare `getcwd` in a doubling loop, and std sees no errno after a bare libc call, so every failure is retried. A removed working directory ends as `ResourcesExhausted`, contradicting the doc comment (never hide errors). **Fix:** a status-carrying seam, `__saw_rt_fs_getcwd(status_out) -> i8*`, using `getcwd(NULL, 0)` and the `opendir` convention, in both runtime trees and ABI.md. `cwd` returns the real cause.
2. **LEAD RULING (reversible): `Path.as_string` becomes `public`.** A `Path` whose text user code can't read is the API not doing the expected thing. Stage 0's `as_str` was public, and the name follows the no-abbreviations doctrine.
3. **`join`/`join_path` drop the `unsafe` marker,** unless the compiler demands it.

The revision is queued as an Opus unit (brief `p720rev`). SL-737's sweep covers `set_cwd`/`chdir` as process-global state.
