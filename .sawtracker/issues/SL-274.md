## Description

Found while building design 272 unit 3 (Sep 12 2026). PRE-EXISTING and language-wide; unit 3 renamed its way out rather than coding around it.

SYMPTOM: a Saw FREE FUNCTION is emitted with its BARE name as the link symbol, so a free function whose name matches a libc symbol SILENTLY SHADOWS it for the whole program — including for C code inside the Saw runtime itself. There is no diagnostic at any stage.

HOW IT PRESENTED. std.signal grew a public free function `raise(which: Signal)` (POSIX's own name for "send a signal to this process"), whose body calls the shim seam `__saw_signal_raise`, whose body calls C `raise(3)`. The program segfaulted. `nm` on the binary:

  0000000100005164 T ___saw_signal_raise
  00000001000006fc T _raise            <- the SAW function, not libc's

so the shim's `raise((int)signo)` re-entered the Saw function, which called the shim, which called the Saw function: unbounded recursion, stack exhaustion, SIGSEGV. The reported failure is a segfault with no stack and nothing pointing at the name.

THE MECHANISM, probed rather than inferred. A user program at -O0 with two top-level free functions:

  func strlen(n: Int) -> Int { n + 1 }
  func getpid(n: Int) -> Int { n + 2 }

emits

  0000000100002080 T _strlen$OL$Int
  00000001000020cc T _getpid           <- UNMANGLED

So the rule is: a free function is emitted under its bare name UNLESS it participates in an overload set, in which case it picks up the `$OL$` suffix and is safe by accident. `getpid` is unmangled and would shadow libc's `getpid` for the entire process. METHODS are unaffected — they mangle as `Type_method` (`_IoError_format`, `_StringBuilder_append$OL$String`), which is why this has not been hit before: almost everything public in std is a method.

WHY IT IS A CLASS, not this one name. Every libc symbol is exposed: a user writing `func open(...)`, `func read(...)`, `func write(...)`, `func close(...)`, `func exit(...)`, `func malloc(...)`, `func free(...)` at top level shadows the C function of that name for the whole binary, and the Saw runtime calls most of those. The blast radius is worst for the ones the runtime uses on its own behalf (`write` is `__saw_rt_write`'s, `malloc`/`free` are the reactor's poll buffer, `close` is every fd path), where the failure surfaces far from the definition and looks like memory corruption rather than a name collision.

NOTE the asymmetry that makes it hard to notice: adding a SECOND overload of the offending name makes the symptom disappear, because both then mangle. So a program can be "fixed" by an unrelated edit and regress when it is undone.

POSSIBLE DIRECTIONS (not a ruling — design 249's module-keyed functions is the obvious home):
  1. Mangle every free function by module, as methods are mangled by type. Cleanest and matches the existing precedent; the cost is symbol churn and whatever depends on the bare names (`@export` is the sanctioned way to pin one, and already exists).
  2. Keep bare names but REFUSE a free function whose name collides with a symbol the runtime declares — a small, closed, checkable list, and a clean diagnostic at the definition. Narrower, but only covers the names the runtime happens to use, not the rest of libc.
  3. Emit free functions with internal linkage unless `@export`ed, so nothing outside the module can bind to them. This is likely the real answer and subsumes (1) for the collision question.

WORKAROUND for anyone hitting it now: rename, or make the function a method/static on a type. Design 272 unit 3 made its `raise` an extension method on `Signal` (`Signal.Terminate.send_to_self()`), which mangles and cannot collide.

### Why, exactly

SL-280's own diagnosis names the mechanism and this change feeds it. `coro_transform.py:11425-11428` builds the imported-callee splice table keyed by the UNMANGLED `_f.name`, while the effect graph keys a free function by `("fn", mangled_symbol or name)` (`typechecker/effects.py:431`). Today a `public` free function has `mangled_symbol=None`, so its edge key is the bare name, it matches the table, the body is spliced and a frame is built. Design 249 tags only MODULE-PRIVATE free functions, which is precisely why the private twin is the one that breaks today and the public twin works.

Unit 3 gives the public twin a `$m$` tag too. Its edge key becomes `helper_public$m$sl280mod`, the table still holds `helper_public`, the test at `coro_transform.py:11583-11592` is False, the splice is declined — **and nothing is said**. So the change does not merely coexist with SL-280; it moves every imported PUBLIC free-function helper from the working side of that bug to the broken side.

### What that would cost, if landed

SL-280's runtime face is the expensive one and it is not hypothetical — it is the bug's own filing. When the dropped suspension is a `std.net` park rather than a `yield_now`, the park lowers through the out-of-frame fallback in `codegen/calls.py:575-597`, which registers the fd and then BLOCKS THE OS THREAD — the cooperative executor's thread — so the whole process stops until that fd is ready. Today that is reachable only through a module-private imported helper, which is why sawtracker's server hit it by factoring a read into a helper. After unit 3 it would be reachable through ANY imported free function called from an imported body: the ordinary shape of every library that splits a suspending operation across two functions, `public` or not. std is exempt only because its suspending surface is methods.

### Re-sequencing

Unit 3 should land AFTER SL-280's fix, not before. ## The tag scheme chosen, and what it retires

ONE rule, `<name>$m$<module tag>`, on EVERY free function, with `module_tag(())` being `root` so the entry module's own functions carry one. `$m$` is DF-140f's delimiter, shared with design 144's type identities; on a free function it now means "the module that DEFINES it" rather than "private", because every free function carries one. An overload member appends its design-55 suffix to that base (`read$m$root$OL$Int`) and a generic's instantiations append their type arguments (`read$m$root$1$Int`), so both classes are module-tagged too.

**Design 249's `$M$` census is RETIRED outside std.** A per-module tag disambiguates two modules declaring one name by construction, so there is no whole-compilation census to take and no dependence on which module is checked first — `free_function_owner_census`, `_census_module_functions` and the `free_function_owners` plumbing they fed are deleted, and so is `_stamp_module_private_functions`, whose whole job the funnel now does at registration. std keeps a narrower per-FILE census (`std_free_function_owner_census`), for the reason below.

`typechecker/registration.py::_free_function_symbol_base` is the funnel; its docstring names its entry points (`_register_function`, plus `_stamp_overload_symbols` building on `symbol_base`). FOUR declarations keep the plain name, each because something reads the WRITTEN name as the symbol:

* the **ENTRY module's `main`** — the C entry, load-bearing at `codegen/core.py:3526`/`:3539`/`:3420`/`:2638`, `reachability.py:107`, `effects.py:1013` and the transform's seeds. A DEPENDENCY's `main` is ordinary, which is SL-305.
* an **`@export`ed** function — the sanctioned bare external name; codegen emits it under the requested C symbol whatever the funnel says, so leaving the plain name keeps one identity per seam.
* a **compiler-SYNTHESIZED** function (`is_synthesized`) or a **MONO INSTANCE** (`is_mono_instance`) — named by string where it is built and at every reference, exactly as design 204 records for a synthesized TYPE. The instance case is not cosmetic: an instance's name already carries the template's tag (`run$m$root$1$Fast`), and tagging it again detached the clone's effect node from the root the drive site had recorded. This is where 12 of the suite's 13 first-pass failures came from.
* a **STDLIB** declaration (`_checking_builtins`), which keeps design 249's rule unchanged. Not a convenience: codegen EMITS calls to `__saw_print_int`, `__saw_fmt_int`, `__saw_main_exit_code`, `__saw_bt_panic`, `__saw_string_*`, `__saw_atomic_*` and a dozen more by literal string, so std's free functions are the compiler/stdlib seam and are named the same way a synthesized function is. The linkage half internalizes every one of them anyway, and a USER declaration can never collide with one because the user's side is always tagged.

## Linkage — one funnel, three entries

`codegen/core.py::_apply_section_layout` is now THE place a definition's linkage is decided and its docstring names all three callers. The HOSTED profile internalizes on exactly the terms `--freestanding` and `--runtime-build` already did, keep-set `{@export'ed globals} ∪ {"main"}`, gated on `_strip_unreachable` (sawc's `whole_program`) so a plain hosted `-c` object — somebody else's to link — keeps external linkage. Sections stay design-168's ELF-only business.

`@section` without `@export` falls out with no extra rule: it is not in the keep-set. `examples/section_compose.saw` at -O0 goes from `S _hot` to `s _hot$m$root`, while its `@export("boot_double")` sibling stays `S`. LANGUAGE_SPEC's `@section` paragraph now says placement only, and a new "Link symbols and linkage" section states the rule.

## Two things the sweep did not predict

**D07_never_method_and_generic** (conformance) pinned `define void @Killer_die` in the OPTIMIZED IR sidecar, and that directive was only ever observable BECAUSE of external linkage: every call to those four `-> Never` declarations is on a path the fixture's constant arguments prove dead, so with internal linkage `globaldce` deletes all four and the sidecar holds nothing but `main`. That deletion is the point of internal linkage, and what the row is about is the `void` + `noreturn` a declaration is emitted WITH — so the directive moved to `-O0`, where a declaration is still a declaration, and now pins all three method slots (`define internal void @Killer_die`, `@Killer_halt`, `@"Killer_slay$1$Int"`).

**The `ircontract` lane** (second commit, `a690608d`) read each `-O` flag's size attributes as a SHARE over the module's attributed definitions. Its own comment records why a share and not a substring: LLVM stamps `cold minsize noinline noreturn` on the cold noreturn paths it forms at every level, and design 261's outlined panic routines are emitted `cold minsize noinline noreturn` by `_panic_helper` on purpose. As a fraction they were harmless while the fixture's hosted module carried ~90 definitions; internalization let globaldce cut it to FIVE attributed definitions, three of them those routines, so -O1 and -O2 read 60% `minsize` and the lane reported a level-table leak that is not there. A `noreturn` define is now excluded from the share, numerator and denominator alike — the share is over the definitions a level actually owns.

The other lanes the sweep flagged as at-risk came through untouched: `abidoc`, `bttable`, `stdtypes`, `reemit`, `irdet --all`, `gmgate`, `bootstrap`, `freestanding`.

## The encoding

`module_tag` renders the path's components ESCAPED and joins them with a bare `_`:

* a literal `_` inside a component -> `_0`
* any character outside `[A-Za-z0-9]` -> `_1<hex codepoint>_` (a non-ASCII identifier — the lexer's `isalnum()` is Unicode-aware — or a dot in a std leaf that is not a path separator); a LEADING `0`/`1` takes this escape too
* a component separator -> `_`
* the `("<std>", leaf)` head -> the component `std`, with the leaf's dots split into their real components; a USER path whose first component is `std` renders it `_173_td` instead, which reserves the marker's spelling

```
()                          -> ``                      the entry module
("dep",)                    -> `dep`                   unchanged
("a", "b")                  -> `a_b`                   unchanged
("a_b",)                    -> `a_0b`                  the finding
("<std>", "once")           -> `std_once`              unchanged
("<std>", "compiler.frame") -> `std_compiler_frame`    unchanged
("modules", "d144_pub_a")   -> `modules_d144_0pub_0a`  moved
("std", "once")             -> `_173_td_once`          a USER module `std.once`
```

INJECTIVITY ARGUMENT (the docstring carries it, and a test now checks it): decode left to right. A `_` followed by `0` is a literal underscore; a `_` followed by `1` opens a `_1<hex>_` escape whose hex digits run to the next `_`; any other `_` — including one at the end of the string or before another `_` — ends a component. The three cases are disjoint because the character after a separator is the first character of the next escaped component, and an escaped component never begins with `0` or `1`. So the decode is TOTAL and recovers the exact component tuple; two paths cannot share a rendering. The entry module is `()` and renders empty, which no non-empty path can render; the `<std>` head is the only producer of a leading `std`.

WHY THIS ONE and not length-prefixing or a longer separator: the escape is paid by the component that CONTAINS an underscore, not by the path that has several components. That is what keeps `("<std>", "once")` -> `std_once` and `("dep",)` -> `dep` reading exactly as before — std's tags (`State$m$std_once`, `Slot$m$std_compiler_frame`) are the ones the compiler, its tests and its prose name, and the one-component user tag is the everyday case. The price is `modules_d144_0pub_0a` for an underscore-bearing component, which the docstring states as the deliberate trade-off. Length-prefixing (`3dep`) or a multi-character separator would have moved every std tag and every readable one instead. `$` was not available (the mangling grammar's delimiter) and digits are the only characters an identifier cannot begin with, which is what makes the markers decidable.

`tools/test_module_tag.py` + a new `moduletag` battery stage: the pinned renderings, a generated grid (5276 paths, 5275 modules, 5275 tags — the one duplicate is `("<std>", "a.b")` vs `("<std>", "a", "b")`, which ARE one module), the `[A-Za-z0-9_]` alphabet, and the DECODER written from the docstring round-tripped over the whole grid.
