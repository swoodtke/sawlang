## Description

Found while building design 272 unit 3 (Sep 12 2026). PRE-EXISTING and language-wide; unit 3 renamed its way out rather than coding around it.

SYMPTOM: a Saw FREE FUNCTION is emitted with its BARE name as the link symbol, so a free function whose name matches a libc symbol SILENTLY SHADOWS it for the whole program — including for C code inside the Saw runtime itself. There is no diagnostic at any stage.

HOW IT PRESENTED. std.signal grew a public free function `raise(which: Signal)` (POSIX's own name for "send a signal to this process"), whose body calls the shim seam `__saw_signal_raise`, whose body calls C `raise(3)`. The program segfaulted. `nm` on the binary:

  0000000100005164 T ___saw_signal_raise
  00000001000006fc T _raise            <- the SAW function, not libc's

so the shim's `raise((int)signo)` re-entered the Saw function, which called the shim, which called the Saw function: unbounded recursion, stack exhaustion, SIGSEGV. The reported failure is a segfault with no stack and nothing pointing at the name.

THE MECHANISM, probed rather than inferred. A user program at -O0 with two top-level free functions:

  func strlen(n: Int) -> Int { n + 1 }
  func getpid(n: Int) -> Int { n + 2 }

emits

  0000000100002080 T _strlen$OL$Int
  00000001000020cc T _getpid           <- UNMANGLED

So the rule is: a free function is emitted under its bare name UNLESS it participates in an overload set, in which case it picks up the `$OL$` suffix and is safe by accident. `getpid` is unmangled and would shadow libc's `getpid` for the entire process. METHODS are unaffected — they mangle as `Type_method` (`_IoError_format`, `_StringBuilder_append$OL$String`), which is why this has not been hit before: almost everything public in std is a method.

WHY IT IS A CLASS, not this one name. Every libc symbol is exposed: a user writing `func open(...)`, `func read(...)`, `func write(...)`, `func close(...)`, `func exit(...)`, `func malloc(...)`, `func free(...)` at top level shadows the C function of that name for the whole binary, and the Saw runtime calls most of those. The blast radius is worst for the ones the runtime uses on its own behalf (`write` is `__saw_rt_write`'s, `malloc`/`free` are the reactor's poll buffer, `close` is every fd path), where the failure surfaces far from the definition and looks like memory corruption rather than a name collision.

NOTE the asymmetry that makes it hard to notice: adding a SECOND overload of the offending name makes the symptom disappear, because both then mangle. So a program can be "fixed" by an unrelated edit and regress when it is undone.

POSSIBLE DIRECTIONS (not a ruling — design 249's module-keyed functions is the obvious home):
  1. Mangle every free function by module, as methods are mangled by type. Cleanest and matches the existing precedent; the cost is symbol churn and whatever depends on the bare names (`@export` is the sanctioned way to pin one, and already exists).
  2. Keep bare names but REFUSE a free function whose name collides with a symbol the runtime declares — a small, closed, checkable list, and a clean diagnostic at the definition. Narrower, but only covers the names the runtime happens to use, not the rest of libc.
  3. Emit free functions with internal linkage unless `@export`ed, so nothing outside the module can bind to them. This is likely the real answer and subsumes (1) for the collision question.

WORKAROUND for anyone hitting it now: rename, or make the function a method/static on a type. Design 272 unit 3 made its `raise` an extension method on `Signal` (`Signal.Terminate.send_to_self()`), which mangles and cannot collide.

### The probe, and the measurement

### Why, exactly

SL-280's own diagnosis names the mechanism and this change feeds it. `coro_transform.py:11425-11428` builds the imported-callee splice table keyed by the UNMANGLED `_f.name`, while the effect graph keys a free function by `("fn", mangled_symbol or name)` (`typechecker/effects.py:431`). Today a `public` free function has `mangled_symbol=None`, so its edge key is the bare name, it matches the table, the body is spliced and a frame is built. Design 249 tags only MODULE-PRIVATE free functions, which is precisely why the private twin is the one that breaks today and the public twin works.

Unit 3 gives the public twin a `$m$` tag too. Its edge key becomes `helper_public$m$sl280mod`, the table still holds `helper_public`, the test at `coro_transform.py:11583-11592` is False, the splice is declined — **and nothing is said**. So the change does not merely coexist with SL-280; it moves every imported PUBLIC free-function helper from the working side of that bug to the broken side.

### What that would cost, if landed

SL-280's runtime face is the expensive one and it is not hypothetical — it is the bug's own filing. When the dropped suspension is a `std.net` park rather than a `yield_now`, the park lowers through the out-of-frame fallback in `codegen/calls.py:575-597`, which registers the fd and then BLOCKS THE OS THREAD — the cooperative executor's thread — so the whole process stops until that fd is ready. Today that is reachable only through a module-private imported helper, which is why sawtracker's server hit it by factoring a read into a helper. After unit 3 it would be reachable through ANY imported free function called from an imported body: the ordinary shape of every library that splits a suspending operation across two functions, `public` or not. std is exempt only because its suspending surface is methods.

### Re-sequencing

Unit 3 should land AFTER SL-280's fix, not before. SL-280's investigator already measured that the minimal keying fix does not hold on its own (an `internal compiler error` from a duplicated LLVM symbol when the spliced clone and the imported module's own emission collide, plus a latent `self`-in-spliced-body bug at reference parameters), and proposed the real shape: ONE `_callee_frame_key(...)` funnel whose docstring names its entry points, with the effect-graph edge, `imported_free_fns`, the splice registration, `_classify_call` and `_callee_fb` all routed through it, plus the `structurally_susp_fns` phase ordering. That funnel is exactly what makes unit 3 safe, because it makes the answer independent of whether a free function carries a tag — which is the property unit 3 needs and today's code does not have.

Worth noting for whoever sequences them: unit 3 is a good FORCING FUNCTION for that funnel. Once every free function is mangled, "what key names this callee's frame?" has one answer everywhere instead of two that happen to coincide for public functions, so the class of bug SL-280 represents stops being reachable rather than being fixed one site at a time.
