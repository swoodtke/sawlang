## Description

**A copy-only borrow's window lasts the whole statement in sawc2; the ruled extent ends when its value is read** (found by p686, SL-686 step 2, Oct 23).

**The ruling:** the user's Sep 24 doc-review ruling (SL:borrowing) says "a copy-only borrow closes as soon as its value is read; the right side is evaluated first". The spec says it too: "A borrow whose result is only copied closes as soon as the value is read".

**The defect:** in `print(borrow counted.at(0)!.label())`, the borrow's result is only read, so the accessor's epilogue must run BEFORE `print`. That is what `tests/corpus/place_enum_payload_lend.saw`'s `EXPECT-OUTPUT` and Stage 0 both show (`epilogue ran`, then `8`). sawc2 prints `8`, then `epilogue ran`: it closes the window at the statement's end. It isn't specific to conditional lends. A plain unconditional accessor shows the same order (p686's `order.saw`: `x` then `epilogue plain`). It surfaced only now because SL-686 let the row run.

**Obligation 4:** every position where a statement-form `borrow`'s result is only a value read:
- a call argument;
- an operand;
- an interpolation segment;
- a `let` initializer;
- a `return` value;
- a condition;
- a method chain ending in a value (`.label()`, `.len()`).

Each × an accessor with a printing epilogue, at -O0 and -O2. Contrast this with a borrow passed by reference (`f(borrow var x[i])`), whose window is the call.

**The corpus:** `place_enum_payload_lend` is recorded `wrong` in SL-686's baseline until this lands, and then moves to pass.

- **The fix (MIR only):** `prepare_borrow` closes the windows opened for a fresh result at its read, through `close_windows_since`, now THE value-read-close funnel. It's safe because a fresh result holds no borrow (only `borrows` returns a reference).
- **Rulings:** reconcile the spec sentence (a value copied out, or returned by a call on the place, closes at the read; uses by reference keep the window); a `match` on a lent place stays by reference.
