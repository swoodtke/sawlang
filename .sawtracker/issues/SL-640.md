## Description

Found by SL-630's sweep (agent c630hook). Wrong code from a test-only declaration, by a mechanism of its own.

**Mechanism:** typecheck's `written_member` (`compiler/typecheck/src/conform.saw`) finds the member that meets a conformance's requirement by scanning every extension of the type, test-only ones included. So a requirement of a production conformance can be met by a method a `@test extension` writes, and production code calling through the conformance runs test code. SL:testing ("Test code cannot change what production code means") requires production code to be checked as if no test-only declaration existed. SL-626 filtered the member tables and SL-629 is the test-only conformance itself; here the conformance is production and only the member is test-only. SL-630 refuses the one copy-family instance (a test-only `copy()` on a production type), so a copy hook can no longer come this way; every other trait still can.

**Evidence** (`sawc2 build --std-root std` at SL-630's tree, then run): prints `test-only name` and `99`. Expected: a refusal, since without the test-only body the production conformance is missing `name`.

```saw
struct Money {
    cents: Int
}

trait Named {
    func name(&self) -> Int
}

extension Money: Named {}

@test
extension Money {
    func name(&self) -> Int {
        print("test-only name")
        99
    }
}

func get<T: Named>(x: &T) -> Int {
    x.name()
}

func main() {
    let a = Money(cents: 1)
    print("{}", get(&a))
}
```

**Fix, proposed:** `written_member` skips a test-only extension's members when the conformance's own extension is production, so the production conformance is refused as missing the requirement (`conformance.missing` or the trait's equivalent). A test-only conformance may still be met by test-only members.

**Readings to confirm (each is reversible):**
1. SL:testing's "a test-only conformance that overlaps a production conformance is refused" counts an AUTOMATIC conformance (`Equatable`/`Hashable` of a trivially copyable struct, a payload-free enum) and a production REFINEMENT as production conformances. The spec says a trivially copyable struct is `Equatable` automatically, so this reading follows the text. Its cost is the golden change above: a test-only `@synthesize Equatable` on such a type is refused even though it would derive the same `equals`.
2. A test-only conformance takes the production answer for every requirement a production conformance also reaches, instead of being refused when the two disagree.
3. A side effect: a test-only method that shares a name with a production conformance's trait default makes a direct `a.hi()` in test code `call.ambiguous`.

If these hold, SL:testing owes clauses for 1 and 2, plus an explicit SL-640 clause: a production conformance's requirements are met as if no test-only member existed.
