Found by the reviewer on SL-1032. `Task.spawn(work())`, then `t.detach()`, then `t.join()` panics (rc 134) with "Task.join: this task's result was already joined". The result wasn't joined; the handle was detached. std's own doc comment on `Task.join` says a join after `detach` panics, so the panic is right but its message should name the detach ("Task.join: this handle was detached").
