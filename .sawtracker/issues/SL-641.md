## Description

Found by SL-630's sweep (agent c630hook), checking that MIR's `deinit_member` (`compiler/mir/src/build.saw`, the first `deinit` an extension writes) can find only one.

**Mechanism:** typecheck has no declaration-site check that two members of one type, written in different extensions, have indistinguishable signatures. Stage 0 refuses the second at its declaration ("method `deinit` is already defined for struct `Noisy` with an indistinguishable signature"). sawc2 accepts both. An ordinary method is caught later, at a call, as `call.ambiguous`; but the members no source call names, a hand-written `deinit` and a policy `copy()`, are never called by name, so nothing refuses them. `deinit_member` then takes the first in declaration order and the other body is dead.

**Evidence** (`sawc2 build --std-root std` at SL-630's tree, then run): prints `made 7` and `first deinit 7`; Stage 0 refuses at 16:5.

```saw
struct Noisy {
    id: Int
}

extension Noisy: NoCopy {
    func deinit(&var self) {
        print("first deinit {}", self.id)
    }
}

extension Noisy: ExplicitCopy {
    func copy(&self) -> Noisy {
        Noisy(id: self.id)
    }

    func deinit(&var self) {
        print("second deinit {}", self.id)
    }
}

func main() {
    let n = Noisy(id: 7)
    print("made {}", n.id)
}
```

**Fix, proposed:** refuse an indistinguishable redeclaration of a member across a type's extensions at its declaration, as Stage 0 does, so `deinit_member` and `policy_copy` each have one answer by construction.

**Related, needs a ruling:** this program also declares two copy policies on one type, `NoCopy` and `ExplicitCopy`. Both compilers accept two (the tier table lets `NoCopy` win), with or without the duplicate `deinit`. The spec says every type has exactly one tier ("Wrappers carry the tier of what they wrap"), which suggests a second policy conformance should be refused, but nothing states it.
