## Description

**`signal_concurrency_pins` no longer links under Stage 0** (found by SL-784's re-snapshot). The program builds `tools/signal_race_probe.c` together with `sawc/rt/shim.c`. Bisected by linking that pair at each commit that touched `shim.c`: the last that links is ca46db83a, and the first that fails is 71c71bcf1 (SL-765.p3):
```
Undefined symbols: ___saw_rt_last_syserror
```
`shim.c` now references a seam that the Saw-authored runtime defines, and the probe's build links the shim alone. The record's stdout is `varies` because the linker error names a random `shim-XXXX.o`.

**Fix:** link the probe against what the shim needs, i.e. the runtime objects that define `__saw_rt_last_syserror` (or a stub in the probe), through whatever builds `signal_race_probe.c`. Then the coro record re-snapshots to `meets_expect yes`. Check whether any other C test harness links `shim.c` alone (obligation 4: the mechanism is "a C harness links the shim without the Saw runtime it now depends on"; grep for `shim.c` in tools/ and tests/). Small; Sonnet-suitable.

**Air: SL-792.p1 approved.** Reviewed on origin/main 6fcdf856d plus r1.

**Reproduced:** Stage 0 builds `examples/signal_concurrency_pins.saw`, and its run prints "signal race probe: all cells hold", "signal in-flight probe: all cells hold" and "pins held", exit 0, which is the new record's stdout. The coro snapshot check (my `sl784p/probe_check.py`) passes with the updated record and index: 980 records, 0 failures.

**The sweep is complete:**
- The only harnesses that link `shim.c` are the two probes (`tools/signal_race_probe.c`, `tools/signal_inflight_probe.c`) and `signal_hook_shim.py`, which generates the shim the in-flight probe links.
- The probes' surface (`__saw_signal_watch`/`unwatch`/`raise`/`drain`) reports its own `-1`/`-2`/`-3` codes and never calls the mapper. In `shim.c` the mapper is reached only from `set_nonblocking` and the output seams, which neither probe calls. So the stub really is unreached today.

**Nit, not blocking:** the stub returns `0`. The shim reports failure as `-__saw_rt_last_syserror()`, so if a future probe ever reached a failing descriptor op through it, the failure would read as SUCCESS (`-0`), which is the opposite of what a test harness should do with an unexpected path. `fprintf(stderr, …); abort();` would turn a future reach into a loud probe failure for the same two lines.
