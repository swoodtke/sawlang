**A consuming body that replaces `self` after moving a field out reaches drop elaboration as an INVARIANT, not a refusal** (SL-606, bucket A; found by a5leak's SL-611 sweep).

- **Repro:** `let old = move self.first; self = Conn(...); move old` in a `consumes` body, `Conn` NoCopy with a hand-written `deinit`. `sawc2 drops --check` prints `INVARIANT … local _1 is dropped whole after a part of it moved out: a destructure does not dissolve it`; `sawc2 build` exits 1. The same INVARIANT comes when the field is assigned again before the replacement (`self.first = Tag(…); self = Conn(…)`).
- **Stage 0** refuses both: "`self = ...` and `move self.<field>` may not appear in one consuming body (design 260 v1): the replacement releases the OLD referent whole, including the field the move handed away".
- **Spec:** silent on the combination. "`self = v` inside a consuming body deinits the OLD referent whole, hand-written body included" assumes a whole referent, and a hand-written `deinit` reading a moved field is unsound, so Stage 0's fence is the oracle.
- **Mechanism:** a missing v1 fence, not SL-611's release rule. Nothing refuses the shape, so MIR lowers `self = v` as a whole `drop(_1)` of a partial receiver, and only the MIR verifier catches it. Not silent, but an INVARIANT is the wrong outcome for a user's program.
- **Related, same analysis:** the shared initialisation analysis keeps a parent partial after a moved field is written back ("a write to a part of a partial path leaves that path partial"). So after a refill, a whole use of `self` (`self.total()`) is refused as `move.use-after`, "used after a part of it may have been moved out". That's conservative and safe. Decide whether the fence above also covers it, or whether the analysis should restore a parent whose moved parts are all written back.
- **Fix:** a refusal at the fence's position (typecheck, or borrowck by the conditions at the `self = v`), with a fixture for each shape. Probes: `.build/scratch/a5_self.saw`, `a5_self2.saw` and `a5_whole_use.saw` in a5leak's worktree (`.claude/worktrees/agent-a2d779313b1ae821e`).

**a5self: fixed in worktree commit 5d10432dc (not submitted), on main a0d0c8cf4.**

- **Reproduced:** all three probes, rebuilt from the issue text. `self = v` after `move self.first`, and after the field was refilled, each printed `INVARIANT … local _1 is dropped whole after a part of it moved out`, and `sawc2 build` exited 1. The whole use after a refill was refused as `move.use-after`.
- **Fix, by the conditions at the replacement:**
  - `init_consumes_replacements` (mir/src/initialisation.saw) lists each statement that drops a consumed receiver whole while it may be `P`. That drop is always the old referent's drop before a `self = v`: once a field can leave, the release is field by field.
  - The borrow check refuses each one as the new rule **`consumes.replace-partial`**, in Stage 0's wording, naming the move.
  - The MIR verifier reads the same list to skip that body's move-path checks, as it does for `consumes.some-paths`, so a refused program prints the ERROR and no INVARIANT. This is a three-line edit to `mir/src/verify.saw`, approved by the lead.
  - `init_consumes_receiver` is the one test for "a consumes body owning local 1", and `init_consumes_partial` uses it too.
- **Decision (reversible): the analysis does not restore a parent whose moved parts are all written back.** So a replacement, or a whole use of `self`, after a refill stays refused. Why:
  1. The spec is silent on a whole use after a refill. "Releases what REMAINS" (V129) covers only the release, and Stage 0 refuses every such use, so Stage 0 is the oracle.
  2. Drop flags can't mirror a restore. Whether a write to a part makes the parent whole depends on the state of the other parts, but `drops_flag_effect` is a per-access constant. So a flagged parent restored to `W` would read a cleared flag and leak silently.
  3. Refusing is safe in direction.
- **Where sawc2 stays more permissive than Stage 0:** Stage 0 refuses any replacement in a body that moves a field, judged syntactically. sawc2 accepts a replacement *before* the move, and one after a trivially copyable field's `move`, which reads the field and leaves `self` whole. The run probe checks both drop correctly.

Approved patch SL-625.p1 (revision 1)

Approving SL-625.p1: `self = v` after a field may have left a consuming body is refused as `consumes.replace-partial`, naming the move, instead of reaching the MIR verifier as `INVARIANT … dropped whole after a part of it moved out`. Exact tree on 80e7c5e3f: 8107bd2a.

**The accepted shapes drop every value exactly once** (`sl625/replace_owning.saw`, owning `NoCopy` fields with a printing deinit, built by the patch at -O0 and at -O2, identical output):
- `self = v` before any move: `drop 2 drop 1` (the old referent, whole, at the replacement), then `drop 12 drop 11` at the release, `renew -> 0`.
- `move self.n` (an `Int`), then `self = v`: `drop 4 drop 3`, then `drop 14 drop 13`, `renew_after_int -> 6`.

These are the two places sawc2 is more permissive than Stage 0, and both are correct.

**Obligation 4, the mechanism's reach** (`sl625/siblings.saw`): the same shape outside a consuming receiver doesn't reach the borrow checker at all. A local `var p` with `move p.first` and then `p = …`, and a nested `move self.inner.first` in a consuming body, are both refused earlier, as `transfer.partial-move` at the `move`. Only a direct field of a consuming receiver can leave, so `init_consumes_replacements` covers the only position the INVARIANT could come from.

**The verifier carve-out is bounded:** `verify_flow` skips move-path checks only for a body that `init_consumes_replacements` lists, which is the same list borrowck refuses from. So the skip can't hide a problem in an accepted program; each listed body is an ERROR.

**The no-restore decision** (a refill doesn't make `self` whole again) is well argued: the drop flag is a per-access constant and can't follow "all moved parts written back", Stage 0 refuses every such use, and refusing is the safe direction. It's pinned by `move.use-after.refilled.saw`. The spec sentence is owed to bucket G, as the note says.
