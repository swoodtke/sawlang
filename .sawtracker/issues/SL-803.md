## Description

**`__saw_bt_table`'s exec descriptor for the new std, and lldb's live task walk** (split from A16b, SL-577 c7–c8). A16a ships the table with `exec_off = 0`, and A16b's in-process walker doesn't need a descriptor. A debugger does: `tools/lldb_saw.py` finds live tasks through the descriptor's offsets into the executor's types.

**Scope (A16b agent p577dump's proposal, SL-577 c7 item 3):**
- a v2 descriptor in `compiler/coro/src/bttable.saw`, all u32: the head symbol (`EXEC_RECORDS`' LLVM name, as a string-table offset); `ExecutorRecord.{groups, next}`; `TaskGroup` size and `.{slots, next, lock}`; a `Vector`'s element-pointer and length offsets; `TaskSlot` size and `.{frame, cell, generation, done, active}`; `TaskCell.{descriptor, park}`; `FrameDescriptor.backtrace`. The offsets come from mono's layouts of the std types;
- `CORO_BT_VERSION` 2, with `coro_bt_render` printing `exec=OFFSET`;
- `tools/lldb_saw.py` gains its own v2 decoder (Stage 0's decoder refuses any version but 1, and `sawc/` is frozen) and keeps v1 for Stage 0's binaries;
- `tools/test_bt_table.py` moves to `sawc2 coro --bt-table` (or stays on Stage 0's v1; decide).

**Golden moves:** the coro lane's `.bttable` records, and every `.ll` golden carrying the table's version byte (`hello.ll` included). **Pin:** lldb (or the decoder alone) lists a live task's frames from a stopped binary.
