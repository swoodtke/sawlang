## Description

**A symlink loop where a module file should be is reported as `no module … (looked for …)`, hiding the cause** (the Air, SL-826.p2 review c14, Oct 23). When `mods/loopy.saw` is a symlink loop, `realpath` fails with ELOOP, and the resolver reports `import.unknown-module` with "looked for …/loopy.saw", as if the file were missing. "Never hide errors": the diagnostic names the real cause (`Path.canonical`'s `SystemError` carries it: a loop, permission denied, …).

**Scope:**
- every resolver site that canonicalizes a path (`module_for_file`'s entry points, `--module-path` directories, the entry file);
- a failure other than "not found" is a distinct refusal (`import.unreadable`, or the `SystemError`'s text), naming the path and the cause;
- pins: a symlink loop, an unreadable directory (where the platform allows), and a dangling symlink.
