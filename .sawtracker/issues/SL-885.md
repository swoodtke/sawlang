**Air: SL-885.p1 approved, with one finding to file.** Reviewed r1 on 1e36e0c35.

**Expectations, old against new, for all 18 programs** (`probe_expect_blocks.py`: each file's `// EXPECT…` directives plus its `// EXPECT-OUTPUT:` block, read from the base and the patched tree). 13 are unchanged. Five change, and each is accounted for:

- **`net_precise_wakeup` and `net_precise_n_readers`:** each drops its trailing `0`, the spurious-wake count, so they now prove per-reader routing, not precision. Each says so and points at SL-890. The only ledger row citing `net_precise_wakeup` is K23 ("an imported std method still embeds and drives"), so no precise-wakeup row loses its cover.
- **`process_argv_no_shell`:** `[one]` → `[2]`. With `arg_count()` gone, the child counts its own argv through `sh -c 'printf %s "$#"'`, which is at least as strong.
- **`process_error_surfaced`:** "error names program" → "error is a launch failure". **This is the finding.**

**The finding.** The old row checked that a launch failure names the program (`ProcessError.program_name()`). The new `SystemError` doesn't. A probe (`e1_launch_error_text.saw`: `Command(program: "this_command_does_not_exist_zzq").wait()`) prints `exec failed (the program could not be launched)`, with no program in it. The rewrite is faithful to the current API, but it removes the only pin of that guarantee. A caller running several commands can't tell from the error which one failed: sawtracker's own "Cannot run P: …" adds the name itself. That's the std's job under "APIs do the expected thing". Please file it: a spawn failure's `SystemError` names the program, or the spec says the caller must.
