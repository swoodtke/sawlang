## Description

A `move` in the HEAD of a suspension-SPANNING container (`if`, `while`) is refused by the coroutine transform. Pre-existing; design 275 U3 makes it reachable from a collection `for`, because U3 charges the collection loop's back-edge (the design-127 skip at `_instrument_loop_backedges` went with SL-317's split) and an instrumented loop SPANS.

REPRO (fails on main too, with a RANGE `for` — the collection `for` was shielded only by the op-budget skip):

```saw
import std.task.*
struct Res { name: String }
extension Res: NoCopy { func deinit(&var self) { print("drop {}", self.name) } }
func note(r: &Res) -> Int { r.name.len() }
func consume_bool(r: Res) -> Bool { true }

func if_continue_range(n: Int) -> Int {
    yield_now()
    for i in 0..n {
        var r = Res(name: "old")
        if note(&r) + i < 0 { return -1 }
        if consume_bool(move r) { continue }     // REFUSED
    }
    5
}
```

    coroutine transform: `move` in the condition of a suspension-spanning `if` in `if_continue_range` is not supported

The `while` spelling gets the same refusal from `_split_while`.

MECHANISM (obligation 4). `_split_if` / `_split_while` call `_rewrite_hosting` on the head and REFUSE when it hands back `forgets` — the drop-flag clears a `move` of a frame local owes. There is nowhere to emit them: the condition is evaluated inside `_branch(cond, ...)`, so a forget emitted beside `cap_lets` would run BEFORE the condition rather than after it. SL-234 solved exactly this for a NON-split container (`_lower_inplace`'s `_hoist_head_and_relinquish`: bind the head to a temp, relinquish between the temp and the container) and SL-226 r1 corrected the `while` placement (the relinquish goes INSIDE the loop, because a `while` condition re-evaluates). Neither reaches the SPLIT path, so the class is "every container whose head may hold a `move` and whose lowering is a CFG split": `_split_if`, `_split_while`, and by inspection `_split_for`'s range endpoints (`_rewrite_hosting` on `iterable.start`/`.end`, which carries `lo_forgets`/`hi_forgets` and emits them AFTER the stores — so that one is already correct and is the shape the other two want).

FIX DIRECTION: give the split path the same head-hoist the non-split path has. `_hoist_container_heads` already owns the rewrite in both placements — `_head_lift` for a once-evaluated head, `_head_into_while_body` for a per-iteration one — so the fix is a third clause on `_head_must_move` ("the head contains a `move` and this container will be SPLIT") rather than new machinery. It needs the split decision to be known at head-hoist time; `_mark_ob_block`'s break/continue marking currently runs later, which is the sequencing question the fix has to answer.
