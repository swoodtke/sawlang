## Description

**Two pool waits hang silently, with no deadlock report, when a pool task waits forever** (found by p821, SL-821, Oct 23; pre-existing and unchanged by SL-821). In each, the waiting thread has no cooperative task, and a pool task waits forever (on a channel nothing sends to):
- a pool join made BY a pool's own task;
- a pool teardown from a plain `main`, a `blocking` `main`, or a pool's task.

"Never hide errors": a program that can never progress should get the deadlock report, not a silent hang.

**Mechanism (UNVERIFIED, p821's reading):**
- **The join:** the joining frame reads as "running on its worker", so the walk counts it as able to run.
- **The teardown:** it puts its workers back into `LIVE_THREADS` before reaping them, so the walk sees live threads.

**Scope:**
- confirm each mechanism with a probe and the walk's state at the hang;
- fix the walk's accounting through SL-808's walker funnel (and SL-809's `on_this_stack`), so a frame blocked in a pool wait, and workers being torn down, count as waiting;
- pin each cell (it reports the deadlock), at -O0 and -O2;
- soak SL-808's walkers to confirm no false report.

Also still open, from design 230: a `Thread.spawn` body blocked on a stuck cooperative task (`LIVE_THREADS` keeps it from reporting). Say whether the same fix reaches it.
