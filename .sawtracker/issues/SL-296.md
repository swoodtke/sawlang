## Description

SL-260's rejection corpus found a malformed Result type reaching codegen as an unbound type parameter. Existing fixture prototypes/minivm/examples/results/reject_type_arity.saw:

```saw
func bad() -> Result<Int> { 1 }
func main() { print(0) }
```

Actual: Python compiler exit 1, `error: internal compiler error: Unbound type parameter: E`. Expected: a clean located generic-arity diagnostic because Result requires both its value and error types. The prototype already rejects the malformed type normally.

Mechanism: incomplete generic application survives declaration/type resolution, leaving E unbound; sawc/codegen/types.py eventually raises the Unbound type parameter error. Validate arity before admitting instantiated types to lowering. Sweep too-few/too-many arguments on Result and other generic structs/enums at return, parameter, field and local annotation positions, respecting legitimate defaults and inference positions. A codegen catch that merely renames the internal error would not close the validation gap.
