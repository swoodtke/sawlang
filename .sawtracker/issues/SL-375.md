## Description

Found by the SL-355 implementer (Sep 23), not fixed there: it is the SL-138 class, and outside SL-355's scope.

The single-frame entry executor reads the frame's wake word once and then calls the reactor poll with no timeout. If a different poller (an MT worker or the ambient sweep) takes that frame's readiness event first and latches the word, this executor blocks in poll waiting for an event that has already been consumed.

**Sweep owed:** every executor loop that reads the wake word and then blocks in poll. Does each one re-read the word after a bounded poll, or have a wakeup path? Reproduce first; the reproduction likely needs a second poller active on the same reactor.
