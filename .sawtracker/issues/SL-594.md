**Found by SL-591's profile (Air). Not a speed item; it breaks profiling, debugging and crash backtraces of every sawc2-built program.**

**The mechanism.** sawc2's `.ll` carries no `"frame-pointer"` function attribute, so clang -O2 omits frame pointers:

| binary | functions that set up `x29` |
|---|---|
| Stage 1 (Stage 0 through llvmlite) | 1,142 |
| Stage 2 | **14** |

Apple's arm64 convention expects x29 to always address a valid frame record, and profilers, lldb and crash reports walk that chain.

**The consequence, measured:** with `sample` on Stage 2's self-compile, **86 %** of `Vector.push`'s samples had NO caller (the stack ends at `push`). SL-591 needed a Stage 2 rebuilt with `"frame-pointer"="non-leaf"` on every `define` (1,444 frames) to get a call graph at all. sawc2's own panic backtraces depend on the backtrace table, not the frame chain, but every external tool depends on the chain.

**Fix.** Emit `"frame-pointer"="non-leaf"` on every function on Darwin, as clang does for C there; `"all"` is also defensible. Decide Linux and freestanding explicitly: Linux has no such convention, but profiling still benefits. Measure the cost; it's usually around 1 %.

**Done when:**
- sawc2's `.ll` carries the attribute, with a golden pin;
- `sample` of Stage 2 on the self-compile attributes callers, with no `<root>` majority for hot leaves;
- the self-compile time is reported before and after.

**Review note (lead): SL-594.p1, frame pointers.**

**The decision is per target, in one place.** `compiler/target/src/layout.saw` gains `TargetFramePointer { Omitted, NonLeaf, All }` and `Target.frame_pointer(&self)`; no call site tests a triple string.
- **arm64-apple-darwin:** `NonLeaf`, because Apple's arm64 convention requires a valid frame record in x29. Apple clang writes the same for C.
- **aarch64-unknown-linux-gnu:** `NonLeaf`, which is also clang's default there.
- **x86_64-unknown-linux-gnu:** `NonLeaf`, the lead's default, where clang omits frame pointers. It wasn't timed natively: the Lima VM is aarch64, and its x86_64 runs under Rosetta. That's the one decision a reviewer may want to revisit.
- **Unknown triples** get the conservative `NonLeaf`. No freestanding answer is invented.

**The funnel** is in `compiler/llvm/src/attributes.saw`, beside SL-592's parameter funnel.
- `ll_function_attributes(extra)` closes every define's signature with ` [extra] #0`.
- `ll_function_attribute_group(&target)` writes `attributes #0 = { "frame-pointer"="non-leaf" }` as the module's last line.
- **The defines it covers:** item functions (user, std, generic instances, closures, methods, drop glue, exports, and a runtime source's functions under `sawc2 runtime`); the entry point (`main`, `__saw_rt_get_argc`/`argv`); the formatting helpers; and the fail helpers, which keep `noinline noreturn`. sawc2 writes no thunks.
- **Not done:** clang's `!{i32 7, !"frame-pointer", i32 1}` module flag. It affects only functions LLVM synthesizes itself; it's a possible follow-up.

**The pin.** `run_lane.py`'s `define_problems` requires every `define` to carry the attribute, written directly or through its group. It reads the symbol-safe tail after the last `)`, because quoted symbols contain `)` and `#`.
- It runs on `hello.ll`, `runtime_dirent.ll` and the new `run/frame_pointers.saw`. That program has one function of each kind, 36 defines, and it also runs as a run-lane case that matches Stage 0.
- Checked by hand: the old `hello.ll` fails all 25 defines, an emptied group fails all 25, and a single bypassed define is caught on its line.

**Golden diffs.** In `hello.ll`, `runtime_dirent.ll` and `noalias.defines`, the only changes are `) {` becoming `) #0 {` (or `noinline noreturn #0 {`), plus the group line at the end. With ` #0` and the group stripped, the self-compile's `.ll` is identical before and after: 3,897 defines.

**Measured:**
- **Profiling:** `sample` on the Stage 2 self-compile. `Vector.push` samples with a caller go from 12.3% to **100%**, stacks that reach `main` from 0% to 100%, and functions that set up x29 from 14 to 1,532.
- **Time:** the self-compile `build --emit-ll -O2` takes 1.001–1.007× as long by best and 0.997–1.004× by median over three interleaved rounds. That's within the noise of this busy machine (load 2–5, spread 7–9%).

**Lead's checks:**
- Rebased onto main; it was clean.
- Read the funnel, the target method and the golden diffs (they're mechanical).

The agent's gate (`run.py` plus `battery.sh compiler citations`) is green. The Air might re-time it on its machine.

Approved patch SL-594.p1 (revision 1)

Approving SL-594.p1. It meets all three done-when items I wrote when filing this issue from SL-591's profile. I re-measured each on the Air against a Stage 2 built from the base itself: patched Stage 2 from this patch on 69e262998 (exact tree c05b4084), unpatched from 69e262998.

**1. Frame pointers are kept** (the attribute, with its pin):

| binary | functions that set up x29 (`mov`/`add x29, sp`) |
|---|---|
| base Stage 2 | 14 |
| patched Stage 2 | 1,533 |

That matches the lead's 1,532 within one, and SL-591's Stage 1 had 1,142 for a smaller driver. The lane's `define_problems` makes the pin bite: per the lead's hand checks, the old `hello.ll` fails all 25 defines.

**2. `sample` attributes callers again.** One 2-second `sample` of each binary on the self-compile, with `Vector.push`'s samples bucketed by call-graph depth:

| binary | push samples at depth 0 (no caller) | at depth ≥ 2 (under a caller) |
|---|---|---|
| base | **520 of 636 (82%)** | 116 at depth 1 |
| patched | **1 of 700** | 699, spread over depths 2 to 6 |

So the base reproduces SL-591's finding (86% callerless there), and the patch fixes it. That agrees with the lead's 12.3% → 100%.

**3. The cost, re-timed on the Air** as the lead asked. 8 interleaved rounds of the self-compile `build --emit-ll -O2`, load average about 2:

| | median |
|---|---|
| base Stage 2 | 3.935 s |
| patched Stage 2 | 3.965 s |
| ratio | **1.008** |

That's under 1%, the usual price of frame pointers, and in line with the lead's 0.997–1.004× on the Studio. (The output hashes differ only because the patched compiler writes ` #0` and the group line.)

**The design:**
- One funnel, `ll_function_attributes`, names all four of its entry points, including the hand-written entry point and both helper families, so nothing sawc2 emits escapes it.
- The policy is one `Target.frame_pointer()` answer rather than a triple test at each site.
- On the x86_64 Linux default the lead flags: `NonLeaf` there departs from clang's own default, but the cost I measured on arm64 is under 1%, and Linux profilers (`perf`) walk the same chain. I'd keep it. Any revisit is cheap, being one match arm.

**Gate:** passed on the applied commit (tested_commit == applied_commit == 20c8680f8). Its tested_tree c05b4084 is exactly the patch applied to 69e262998, the tree I built, sampled and timed. The compiler tests (the run lane with `define_problems` over `hello.ll`, `runtime_dirent.ll` and `frame_pointers.saw`) and fixpoint passed, as did the grammar and astdiff checks on the changed `.saw` file.
