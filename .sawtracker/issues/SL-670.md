## Description

**sawc2's slice has no inline `catch`, no try block and no `?.` assignment** (found by a6flow on SL-559, A6).

SL:coroutines §3.3 assumes MIR already lowers these, so that A6 only pins them across a suspension: the `try { } catch { }` and inline `try EXPR catch { }` container rows, and two of the four lifted limits (a multi-hop `?.` assignment with a suspending right side; `coro_try_block_two_error_types`). None of them reaches MIR today, in a coroutine or not.

Probe (`.build/scratch/t1.saw` in the a6flow worktree), a plain `main` under `--std-root std`:

```
ERROR slice.not-yet  t1.saw:14:13  `syntax.expr.try.catch` is not in the bootstrap slice yet
ERROR slice.not-yet  t1.saw:16:5   `syntax.expr.try-block` is not in the bootstrap slice yet
ERROR slice.not-yet  t1.saw:23:5   `syntax.stmt.optional-assign.plain` is not in the bootstrap slice yet
ERROR slice.not-yet  t1.saw:24:5   `syntax.stmt.optional-assign.compound` is not in the bootstrap slice yet
```

The corpus pins refused at the same place: `coro_try_catch_suspending` (lines 42-43), `coro_suspending_call_in_inline_catch` (39), `coro_try_block_two_error_types` (48).

**Mechanism:** typecheck's expression dispatch (`compiler/typecheck/src/bodies.saw`, beside `Expr_Try_Propagate`/`Force`/`Optional` -> `try_expr`) has no case for `Expr_Try_Catch` or `Expr_TryBlock`, nor a statement case for `Stmt_OptionalAssign_*`, so each falls to `not_yet` with its syntax name; MIR (`compiler/mir/src/lower.saw`) has no lowering for any of them. Resolve already walks them (`walk.saw`, `kinds.saw`).

**The class**, by GRAMMAR.md's names: `syntax.expr.try.catch`, `syntax.expr.try-block`, and `syntax.stmt.optional-assign.{plain,compound,borrow-plain,borrow-compound}`, the four probed above refused as shown. `syntax.expr.try.route` (`try(as: E.Case) f()`) is in the same dispatch and likely the same; not probed.

**What it blocks:** A6's try/catch rows and two of its four lifted limits (SL-559), so those pins cannot be written yet.

**Fix scope:** front half: typecheck (the catch block's type joins the try's success type; a try block's error binding), MIR (the catch as a block every error edge of the try reaches; the optional chain's write as a branch per hop), and their goldens. Not coroutine work: once MIR lowers them, a suspension inside is ordinary blocks for coro.

**t670try: one piece stopped, the error union (two error types in one `try` block).**

- **What the spec and Stage 0 say:** a `try` block whose `try`s propagate more than one error type gives `error` a compiler-synthesized closed enum over exactly those types, matched by `case IoError(e) -> …` (LANGUAGE_SPEC, "The error union"). Stage 0 builds `_CatchError_A_B`, and does so for a concrete error beside `Box<any Error>` too (`<error union: IoError | Box>`); it does not erase. (The brief's "the erased error type when two error types meet" matches neither; I followed the spec.)
- **Why it stops here:** the union is a new type form. Typecheck can't add a declaration to resolve's program (SL:architecture §3.0, no stage mutates its input), so it needs its own type kind keyed by its members, and then mono's glue, the target's layout and the LLVM backend must lay out, drop, switch on and project it. Those stages are outside this unit.
- **What lands instead:** sawc2 refuses it where the block stands, `slice.not-yet` "a `try` block whose `try`s propagate more than one error type (`A`, `B`), which its `error` holds as their union", fixture `typecheck/refuse/slice.not-yet.error-union.saw`; the arm patterns naming error types add no cascade. One error type, however many `try`s propagate it, and `Box<any Error>` alone, are in.
- **Needs:** a decision on the representation (a `TcKind` for the union, its spelling, and the cross-stage work), as its own issue or unit. A6's lifted limit `coro_try_block_two_error_types` waits on that, not on SL-670.

Filed alongside: SL-676 (an argument moved into its call temporary leaks on an early exit from a later argument, pre-existing, reached by the new catch edges too) and SL-677 (a `try` over a binding is judged by the whole Result's tier, all four spellings).
