**A cast refuses a NoCopy raw-backed enum place as an implicit copy** (SL-606; found by SL-612's sweep).

- **The bug:** `t as UInt8` with `t: Tag`, where `Tag` is a raw-backed enum declared `NoCopy`, is refused by sawc2 with `transfer.implicit-copy`. The frozen `sawc` accepts it and prints the raw value, and the cast duplicates nothing: a run of the reference form, `r as UInt8` over `r: &Tag`, printed the value and one `drop`.
- **Mechanism:** `cast_expr` (`compiler/typecheck/src/bodies.saw`) reads its operand through `consume`, as a by-value read of the whole value, where a cast from a raw-backed enum reads only its backing. It calls `consume` before `through_refs`, so the reference form is accepted and the place form refused: the copy check sees `&Tag`, which copies, in one case and `Tag` in the other. SL-612 fixed that ordering at `??` and the cell constructor, where the read really is a copy; here the read is no copy at all, so the ordering is not the fix.
- **Fix:** record the cast's operand read as one that copies nothing when the cast is from a raw-backed enum, so neither form is refused, or rule otherwise. The numeric and pointer casts read trivially copyable values and are unaffected.
- **Probes:** `enum Tag: UInt8 { case A = 1, case B = 2 }` with `extension Tag: NoCopy { func deinit(&var self) { print("drop") } }`; `let t = Tag.A; print(t as UInt8)` is refused, while `func raw(t: &Tag) -> UInt8 { t as UInt8 }` is accepted and prints `1`, then one `drop`.
- **Pins:** the place form and the reference form, both accepted, in a typecheck golden, and a run-lane program that shows one drop.

Requested changes on patch SL-623.p1 (revision 1)

Requesting changes on SL-623.p1 for one reason: it makes a program reachable that main refuses, and that program reads uninitialised memory and runs a deinit on a value never written. Everything else checks out (below). Exact tree on ec446fc89: e2a528fd.

**The regression** (`.build/scratch/air-review/sl623/borrow_elem_main.saw`): a NoCopy raw-backed `Tag` whose deinit prints a constant, `var v = Vector<Tag>(); try! v.push(Tag.B); print("element {}", (borrow v[0]) as UInt8)`.

| build | result |
|---|---|
| main, -O0 and -O2 | refused, `transfer.implicit-copy` 17:26 ("reads a place of type `Tag`, which is NoCopy, by value") |
| patch, -O0 and -O2 | `element 0`, `drop tag`, `end`, `drop tag` |

The tag is 2, not 0, and the first `drop tag` is a deinit of a temporary that was never written. The vector's element drops once at the end, correctly. With the deinit printing `self as UInt8` (`forms_borrow.saw`), the patch prints `element 24`/`drop 24` at -O0 and `element 0`/`drop 0` at -O2. That's garbage, and it differs by optimisation level.

**Mechanism:** this is SL-642's second face, which the patch's own sibling report describes ("the glue for a NoCopy enum is defined `i8 (ptr)`, so the copy writes nothing"). It's reachable only because this patch makes the raw-enum cast a Borrow position. SL-642 lists "a cast (SL-623 makes the raw enum cast one)" among its positions. On main the cast consumes its operand, and a `borrow PLACE` operand is refused before MIR. Under CLAUDE.md's rule that a brief never leaves breakage it introduced, this has to close with this patch, not with SL-642.

**Either fix is enough:**
1. In `tag_read`, read a `borrow PLACE` operand's tag through the window's lent reference, the way a borrowed non-trivial place already arrives, instead of through `borrow_place_val`'s `prepared_val` copy. That's the right end state, and it doesn't depend on SL-642's general fix.
2. Or keep refusing a `borrow PLACE` operand at the cast in typecheck until SL-642 lands, with a pin naming SL-642.

Either way, pin `(borrow v[0]) as UInt8` with its real tag and one drop per value (a run program at -O0 and -O2), or as the refusal.

**What I checked and found right** (`forms_novec.saw`, `explicit.saw`, `use_after_move.saw`, -O0 and -O2 identical):
- `make(1) as UInt8`, `Tag.B as Int` and `(move m) as UInt8` each drop once at their statement. Main loses those deinits, and so does Stage 0.
- A place cast twice (`p as UInt8, p as Int`) stays usable and drops once at the end.
- An `ExplicitCopy` raw enum's cast reads the tag without running its `copy()`.
- A use after `(move t) as UInt8` is `move.use-after`.
- A plain `v[0] as UInt8` is refused, pointing to `borrow v[0]`. That refusal is correct, and it's the spelling that then breaks.
