**A cast refuses a NoCopy raw-backed enum place as an implicit copy** (SL-606; found by SL-612's sweep).

- **The bug:** `t as UInt8` with `t: Tag`, where `Tag` is a raw-backed enum declared `NoCopy`, is refused by sawc2 with `transfer.implicit-copy`. The frozen `sawc` accepts it and prints the raw value, and the cast duplicates nothing: a run of the reference form, `r as UInt8` over `r: &Tag`, printed the value and one `drop`.
- **Mechanism:** `cast_expr` (`compiler/typecheck/src/bodies.saw`) reads its operand through `consume`, as a by-value read of the whole value, where a cast from a raw-backed enum reads only its backing. It calls `consume` before `through_refs`, so the reference form is accepted and the place form refused: the copy check sees `&Tag`, which copies, in one case and `Tag` in the other. SL-612 fixed that ordering at `??` and the cell constructor, where the read really is a copy; here the read is no copy at all, so the ordering is not the fix.
- **Fix:** record the cast's operand read as one that copies nothing when the cast is from a raw-backed enum, so neither form is refused, or rule otherwise. The numeric and pointer casts read trivially copyable values and are unaffected.
- **Probes:** `enum Tag: UInt8 { case A = 1, case B = 2 }` with `extension Tag: NoCopy { func deinit(&var self) { print("drop") } }`; `let t = Tag.A; print(t as UInt8)` is refused, while `func raw(t: &Tag) -> UInt8 { t as UInt8 }` is accepted and prints `1`, then one `drop`.
- **Pins:** the place form and the reference form, both accepted, in a typecheck golden, and a run-lane program that shows one drop.

**c623cast: fixed in worktree commit 6b33463b5 (not submitted).**

- **Reproduced** on main 16137ccc1: `t as UInt8` of a NoCopy raw-backed `Tag` place is refused with `transfer.implicit-copy`, and `r as UInt8` over `&Tag` is accepted. The sweep found a third face: `make() as UInt8`, `Tag.A as Int` and `(move t) as UInt8` never run the value's deinit. The cast was handed the value and dropped nothing. The frozen `sawc` loses those deinits too.
- **Fix:**
  - **typecheck:** `cast_expr` records the operand as `Borrow` when the cast goes from a raw-backed enum to an integer (`casts_backing`, shared with `cast_allowed`) and the operand is a place, read through a reference or not. A temporary or a spelled `move` is still consumed. The same-type cast `t as Tag` is unchanged, a by-value read (V64).
  - **MIR (with the lead's approval):** `cast`'s new `tag_read` copies the tag through the shared reference a borrowed non-trivial place arrives as, and keeps a handed-off owned value in an owned temporary, so the statement drops it. No `copy()` runs for an ExplicitCopy enum.
- **Pins:** V131 and V132 in both ledgers; typecheck golden `raw_enum_cast`; refusal `transfer.implicit-copy.raw-enum-forwarding`; MIR golden `raw_enum_casts`; run program `raw_enum_cast.saw`, which matches Stage 0; and the sawc2-only probe `probes/raw_enum_cast_handoff.saw`, which states its output.
- **Siblings filed:** SL-642 (`borrow PLACE` at a Borrow position copies a NoCopy value out and drops it, a double drop, already on main) and SL-643 (a spelled `move` at a Borrow position moves nothing).
