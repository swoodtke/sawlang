## Description

**`cancelled()` is recognised by its shape, not by a role.** Found by A9 (SL-566, a9budget).

A2 made `cancelled()` a std wrapper around the `__saw_cancel_requested` intrinsic. Inside a task, that intrinsic call sits in an unframed item, which has no context to read. So A9 lowers a cancel-word read wherever coro sees either the intrinsic itself or a std function with no parameters whose body only returns the intrinsic's result. The shape match keeps A9 inside `compiler/coro/`, but it's a pattern, not a declaration.

**Fix:** bind the intrinsic's lang role to `cancelled` itself, in resolve and `std/task.saw`, so coro recognises it by role. Remove the shape match, and pin the role (a std function of the same shape but not `cancelled` is no longer treated as one).

**Also:** a comment in `compiler/llvm/src/bodies.saw` ("coroutine lowering lowers no frame that holds one") has been stale since A9; fix it here.

As in Stage 0, `cancelled()` inside a sync helper that a task calls still answers `false`. That's out of scope, and says nothing new.
