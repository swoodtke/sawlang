## Description

These come from the Air's review of SL-440.p1. They are small, and each is a naming or wording follow-up to grammar batch 4.

**1. Texts refused twice, once inside the refused form's reading, are unrecordable.** Two shapes reach reading 5's known edge:

| text | the lane's name | sawc2's name |
|---|---|---|
| `while { a } + (while { b } { }) { }` | `infinite-loop` at 2:17 | `block-tail` at 2:17 |
| `while { a } + (x as Int??) { }` | `cast-target-question` at 2:28 (step 1) | `block-tail` at 2:17 |

- **Why they disagree:** the recognizer's chart doesn't see filters, while sawc2's re-read of the condition obeys the rules. In the cast case, the brace-condition reading needs a second removed production.
- **The fix:** treat a text refused twice, once inside a removed form's reading, as unrecordable, the way a text between two rules already is. `cases.py` raises `Problem`, and the README's Refusals section says so.
- **Pin:** add a `cases.py` test that raises on both texts.
- **Scope:** neither shape is in the corpus today.

**2. §13's wording of `syntax.rule.infinite-loop`.**
- **The problem:** it says "a token on the line after the loop's `}` that the refused form would take is refused". In its own example, `let n = while { break 1 } + 2`, the refused form does take `+` and `2`; it just can't reach a body. Both implementations test that: the recognizer wants a `while-expr` from that `while` ending later, and sawc2 wants a clean re-read reaching a `{`.
- **Rewording:**
  - "…is refused at that token when the refused form, reading on through it, reaches a body…";
  - "A loop after which the refused form reaches no body is an operand as before."

**3. The doc-run refusal's message.**
- **The problem:** the second run is refused with "this doc comment documents no declaration". That is false: the run sits right above the declaration, but an earlier run already documents it.
- **The fix:** give it a message of its own in sawc2 and the recognizer, for example "this declaration already has a doc comment, at 1:1; a declaration takes one", with the hint "join the two runs, or make one a `//` comment".
- **Unchanged:** the rule id stays `syntax.lex.doc-attach`.
- **For reference:** the frozen parser refuses the blank-line and plain-comment shapes at the first run instead. §16 may want a row for that.
