## Description

**Import cycles are not refused under the new std** (found by p826, SL-826 step 1, Oct 23). `compiler/tests/resolve/refuse/import.cycle/main.saw` is refused with `--std-root sawc`, but passes `resolve --check` with `--std-root std`. A program with a real import cycle therefore builds.

**Mechanism (UNVERIFIED):** in `find_cycles` (`compiler/resolve/src/imports.saw`), each new root is pushed to the END of `stack`, with `top` reset to 1, but the walk reads `stack[top - 1]`, which is still the FIRST root. Under the new std, the std modules are walked before the entry, so the entry's subgraph is never walked. Reverting to `stack[0] = start` would confirm it.

**Obligation 4:**
- a cycle through the entry;
- a cycle among imported modules only;
- a cycle through a package module (`--module-path`);
- a cycle reached via a selective import (`import m.{X}`);
- self-import (allowed by the spec: "A module importing ITSELF is not a cycle");
- each under both std roots.

**Pins:** the existing `import.cycle` fixture under `--std-root std` (add `// flags: --std-root std`, or a twin), plus each sweep cell. Note SL-826's C7 cell: a two-module loop through the entry builds and prints today.

**Mechanism (read, not just inferred).** `find_cycles` seeds each root with `try! stack.push(start)` and `try! edge.push(0)`, then sets `top = 1`. From the second root on, the push appends at `stack.len()`, while the walk reads `stack[top - 1]` = `stack[0]`, the FIRST root:
- that root is already `state 2`, and its stale `edge[0]` is past its last import, so `next_import_of` returns -1;
- `top` drops to 0 and the walk ends at once;
- the new root stays `state 1` and its subgraph is never visited;
- every module it reaches becomes a later root, unwalked in the same way.

So only module 0's subgraph is checked. Under `sawc` the entry's cycle sits in that subgraph, while under the new std a std module is module 0.

**Sweep of the shape** (obligation 4): the other eight `var top = 1` stack walks in `compiler/`:
- `imports.saw`'s closure walk reseeds with `stack[0] = m`.
- `render_tree`, `bodyverify` ×3, `bodydump` and `bodies` ×2 are single-root with a fresh stack, and every push is guarded `if top < stack.len() { stack[top] = x } else { push }`.

`find_cycles`' per-root seed is the one unguarded push, so the fix is that seed taking the same guard (or `stack[0] = start` / `edge[0] = 0`), with no siblings.
