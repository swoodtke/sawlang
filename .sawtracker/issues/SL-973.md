## Description

**The unit program `mono/front_image_load` sits too close to run.py's 60 s unit timeout, and times out under load.** It failed the server's gate for SL-972.p1 revision 3 (`unit mono/front_image_load: timed out`), a change that doesn't touch it.

**Why:** SL-955 unit 4a2 split the image pins into two files because one took 37.7 s. `front_image_load.saw` then took about 23 s at low load. It runs load-equals-compute over five programs (hello, `ext_probe`, a nested suspending generic spawn, a refused program and Blade), each computing and loading std's cut and running the program's layer. Under the gate's load, with other agents' builds beside it, it passes 60 s.

**Direction:**
- Keep the pin's coverage and cut its time: one program per kind (keep Blade only if nothing smaller reaches the same paths), or run the programs as separate unit programs so each gets its own timeout.
- Do **not** raise the timeout to hide it.
- Report the before and after time, at low load and at load 20+.

**Related:** SL-955 unit 4b (in progress) adds layer images, so check its branch before changing this file, and land after it or fold this into it.
