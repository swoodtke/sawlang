## Description

**sawc2's default std root is the frozen std (`sawc`), not the new one (`std`).** In `compiler/driver/src/main.saw`, `var std_root = "sawc"`. A `sawc2 build FILE` with no `--std-root` therefore compiles against Stage 0's std. The new std's `std.numeric` never reaches MIR, and even `Int.abs` fails with "whose body this program does not lower". Found by p722u5 (SL-722 U5) on Oct 22.

Every lane and corpusdiff passes `--std-root std`, so the gates are unaffected. But a person or an agent running sawc2 by hand gets a surprising failure. Briefs have to say "pass `--std-root` on EVERY sawc2 command" because of it.

**The question:** CLAUDE.md says the fixpoint lane's std "is the one sawc2 compiles when no `--std-root` names another", so the default may be holding up the fixpoint lane. Is the frozen-std default still needed?
- If not, make `std` (relative to the sawlang root sawc2 runs from, or the root its runtime manifest names) the default.
- If it is, make the fixpoint lane pass its root explicitly, then flip the default.

Either way, update the briefs' boilerplate and `compiler/README.md`.
