## Description

**sawc2's default std root is the frozen std (`sawc`), not the new one (`std`).** In `compiler/driver/src/main.saw`, `var std_root = "sawc"`. A `sawc2 build FILE` with no `--std-root` therefore compiles against Stage 0's std. The new std's `std.numeric` never reaches MIR, and even `Int.abs` fails with "whose body this program does not lower". Found by p722u5 (SL-722 U5) on Oct 22.

Every lane and corpusdiff passes `--std-root std`, so the gates are unaffected. But a person or an agent running sawc2 by hand gets a surprising failure. Briefs have to say "pass `--std-root` on EVERY sawc2 command" because of it.

**The question:** CLAUDE.md says the fixpoint lane's std "is the one sawc2 compiles when no `--std-root` names another", so the default may be holding up the fixpoint lane. Is the frozen-std default still needed?
- If not, make `std` (relative to the sawlang root sawc2 runs from, or the root its runtime manifest names) the default.
- If it is, make the fixpoint lane pass its root explicitly, then flip the default.

Either way, update the briefs' boilerplate and `compiler/README.md`.

**The default follows the binary, through links** (`h1`, no `--std-root`):

| how sawc2 runs | result |
|---|---|
| Stage 2, from another working directory | builds, `hi 2` |
| through a symlink in another directory | builds, `hi 2`: `Env.executable_path` resolves links (`realpath` in the macOS body), so the root is the real tree's |
| a copy outside any sawlang tree | exit 2: `no std at …/std: the sawlang tree this binary was built in holds no std/prelude.saw; pass --std-root DIR` |
| `--std-root …/nope` | exit 2: `holds no std: neither prelude.saw (the new std) nor builtin.saw (Stage 0's frozen std) is there` |
| `--std-root sawc` (explicit frozen) | checks as before |

A missing std is no longer silent, either way.

**Gates:**
- `run.py --only borrowck,drops,eval,mir,parallel_order,programs,resolver,subset,typechecker,std,seed,units,golden,sanitize` passes. The six lanes' explicit `--std-root sawc` keeps every golden byte-identical, which is the proof the flip moves nothing.
- `patchgate`, `citations` and `docverify` are green.

**For SL-669, noted not blocking:** the default is `<binary>/../../std`, which holds for `.build/sawc2-stageN` in a checkout. When `bin/sawc` starts running the self-hosted compiler through the toolchain resolver's cached artifact, either the cache must keep a `std/` two levels above the binary, or the shim must pass `--std-root`. Otherwise an installed `sawc` refuses with exit 2. Today `bin/` holds only `blade` and Stage 0's `sawc`, so nothing depends on it yet.
