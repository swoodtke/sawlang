## Description

## U2b: the grammar's tools and the parser corpus

Epic SL-398, unit U2b. `GRAMMAR.md` (SL-400) is the single source for the grammar. U2b makes it executable: tools that read it, and a corpus derived from it, not from any parser. That corpus becomes the U4 to Un parser units' test-first target.

**Home:**
- Tools go in `compiler/tests/grammar/`: Python test tooling, the second tier until self-hosting (SL:architecture §5).
- The corpus goes in `compiler/tests/parse/`.

**Phases:** two, each landing as its own patch on this issue. Phase 2 is briefed in full on this issue when phase 1 lands.

### Phase 1: extract, lint, recognize, and wire into the gate
1. **Extractor (`extract.py`).** It reads `GRAMMAR.md` into one in-memory model:
   - productions (name, status, spec, node, ref);
   - alternatives with their `@names`;
   - the ebnf rules, the lexical rules, and the §10 refused forms with their rows;
   - the §12 context table (constructs × contexts, with each cell in Y/N/S/K/T), and the §13 rules with their constructs.

   It is deterministic, and has a `--json` dump for inspection. Nothing generated is committed.
2. **Lint (`lint.py`).** Every structural rule the document states about itself. At least:
   - production and alternative names are unique;
   - statuses and context cells come from their closed sets;
   - every `spec=` names an existing `LANGUAGE_SPEC.md` heading;
   - every nonterminal is defined and used;
   - every `syntax.*` name cited in prose, rules or tables exists;
   - every `removed` production has a §10 row;
   - every construct in §12 is a real production;
   - there is no trailing whitespace.

   It covers what `.build/scratch/u2a/check_grammar.py` checks, plus the Air's c4 points on SL-400. Each check has a fixture proving it fires (a small broken copy of the grammar), and the `icebreadcrumb` injection pattern applies: a check nobody has seen fail is not a check.
3. **Reference recognizer (`recognize.py`).** An Earley recognizer built from the fences, moved in from `.build/scratch/u2a/earley_check.py` and `r2_tree.py`.
   - It returns every parse tree of an input, and applies the §13 rules that the fences alone leave ambiguous (the generic-close split, head resets, the implicit-member line rule, and the rest).
   - For each parse it records which alternatives were used, and in which §12 context each construct appeared. That record is the coverage data phase 2 measures.
   - "More than one tree after §13" is a finding, not a pass.
   - Its corpus run over every tracked `.saw` must reproduce SL-400's result exactly: 3362 of 3451 accepted, 78 FAIL, 9 LEXERR, 1 SEGLEX and 1 SEGFAIL. Every refusal must be classified, as `.build/scratch/u2a/classify_*.py` do.
4. **Wiring.**
   - `compiler/tests/run.py` runs the lint and the recognizer's own unit tests (fast).
   - The full-corpus recognizer run (about a minute) is a battery lane, `grammarcorpus`. The path-aware per-patch gate (`tools/patch_gate.py`) runs it when `GRAMMAR.md`, `compiler/tests/grammar/` or `LANGUAGE_SPEC.md` changes, the last because `spec=` resolves against it.
5. **CLAUDE.md** (the Air's point on SL-400.p1):
   - "LANGUAGE_SPEC.md is authoritative for meaning, and GRAMMAR.md for spelling";
   - the repo map gains `compiler/tests/grammar/` and `compiler/tests/parse/`;
   - the battery list gains `grammarcorpus`.

### Phase 2: the corpus (outline; briefed in full after phase 1)
- **The canonical AST dump format.** An S-expression of the grammar's `node=` kinds and leaf tokens, byte-stable. It is the contract every parser unit must meet, and is documented in `compiler/tests/parse/README.md`.
- **The generator.** One snippet and its expected dump per alternative: optionals present and absent, repetitions of 0, 1 and many, each construct in each allowed §12 context, and pairwise option combinations, capped. It is deterministic and committed, and the lint checks that regeneration is byte-identical.
- **Golden cases** for:
  - the parser census (`designs/reviews/parser-census-sep1.md`, N1–N12);
  - design 259's R1–R8;
  - every §13 rule decision.
- **A negative corpus.** Mutations of the positives, every §12 N cell, and every removed form. Each carries its expected refusal: the rule name, or a parse error with its position. The recognizer confirms each one is refused.
- **The coverage lane.** It fails when any non-removed alternative lacks a positive, when a removed one lacks a negative, or when a §12 cell goes unhit. Its waiver list carries a reason for each entry.

### Gate policy (standing)
Run only what the change affects, and never the full suite or freestanding, since the server runs those. Before each commit, run `compiler/tests/run.py`. Before reporting, run the `compiler`, `citations` and `grammarcorpus` lanes under the suite lock.

Submitted SL-406.p1, phase 1. Your c1 points are in.

**What it adds**
- **`compiler/tests/grammar/extract.py`:** one model of GRAMMAR.md, with `--json`. It reads 277 productions, 421 named alternatives and 71 rules, every table sorted by schema, and every `syntax.*` mention.
- **`lint.py`:** 43 checks. GRAMMAR.md lints clean, and every check examines at least one item. It has 51 fixtures, each injecting one defect into a mini grammar and expecting exact (line, check) findings. An unedited control must lint clean, and a check without a fixture fails the test.
- **`recognize.py` and `contexts.py`:** the prototype's Earley recognizer. It has §13 tie-breakers and filters, so every accepted file has exactly one tree, and a second tree fails the lane. It also produces a coverage record per parse: alternative counts, and (construct, §12 context, parenthesized, position) cells. Unit tests pin SL-400's nine ruled trees, one fixture per §13 tree rule, and token-level verdicts.
- **Wiring:**
  - `run.py` runs the lint and the recognizer tests in under 0.5s.
  - The `grammarcorpus` lane takes about 22s.
  - `tools/patch_gate.py` runs the full corpus for GRAMMAR.md, LANGUAGE_SPEC.md, the grammar tools, or `sawc/`. The last is there because the recognizer still tokenizes with the frozen lexer.
  - Otherwise the gate checks each changed `.saw` file against `corpus_expected.tsv`. An unlisted file must parse, a listed one must match its verdict, and a deleted but still listed file fails.
- **CLAUDE.md:** meaning is the spec's and spelling is GRAMMAR.md's, and the repo map and battery prose are updated.
- **GRAMMAR.md, one line:** §16 cites the lexer tests at their `compiler/lex` path.

**Corpus**
- **At `2fa71814`,** the SL-400 base, the summary is `{'OK': 3362, 'FAIL': 78, 'SEGLEX': 1, 'LEXERR': 9, 'SEGFAIL': 1}`. All 89 refusal lines are byte-identical to the prototype's output, and all 89 are classified the same way.
- **On main,** `corpus_expected.tsv` records 3611 files: 3490 accepted and 121 refused (69 errors, 50 removed forms and 2 spec conflicts).
  - `parse.call-on-call` and `parse.parenthesized-callee` parse under the grammar and so are not listed.
  - The second spec conflict is `interpolation-line-break.saw`, which is S21 itself.

**Checks.** `run.py` passes. The `compiler`, `citations` and `grammarcorpus` lanes pass; the lead reran `grammarcorpus` after the GRAMMAR.md line. The output is identical under both hash seeds, `git diff --check` is clean, and the gate dry-runs match the design.

**Left for phase 2's brief**
- **The dump contract,** in two parts. §1's one-nonterminal pass-through, read literally, would drop `ExprStmt`, positional `Arg` and a const `Unary`; the prototype's shaping is kept. Assignment targets and `move` operands build flat hop lists, not the per-hop nesting that `syntax.rule.postfix-per-hop` describes.
- **§13's refusing rules** (head restriction, head reset, separators) are not yet modelled in acceptance, so `if a { b } { c }` is accepted. The negative corpus needs them modelled.
- **Tokenizing with the new Saw lexer** (`sawc2`) instead of the frozen one, to drop the `sawc/` dependency.
