**The subset checker's std profile cannot read the lockdown spellings the new std's API needs** (found by std1, SL-597).

**Mechanism.** `compiler/tools/subset_check.py` reads every std file with the frozen lexer and parser, so `std/` can only use what Stage 0's parser accepts. Its only workaround today is token rewriting for `@synthesize(shared)` (`_drop_shared_twins`) and `case None` (`_read_none_cases`). sawc2 accepts each spelling below; the profile refuses it as `parse` or `borrow-syntax`.

**The class**, each probed with `subset_check.py --std` on a scratch file:
1. **A getitem declaration**, `func [](&self, key: K) -> V` with no `borrows`: "a `[]` subscript must be `borrows`".
2. **A setitem declaration**, `func []=(&var self, key: K, value: V)`: "Expected LPAREN, got ASSIGN".
3. **`borrows` on a trait requirement**, `trait LendingIterator { type Item; func next(&var self) borrows -> &var Item? }` (the spec's "Two iterator traits"): "`borrows` may not appear on a trait requirement (design 141 v1)".
4. **A `borrow` payload pattern**, `case Occupied(_, borrow var v) -> { lend v }`, the spec's way to lend a slot enum's payload ("Lending an enum payload"): `borrow-syntax`.

**What it costs the std port (SL-597):**
- `Map` declares no getitem or setitem. A place accessor alone derives both, but the derived setitem REPLACES and panics on a missing key, where the spec's `m[k] = v` inserts. So `Map.[]` lends read-only (`(&self) borrows -> &V`), which derives the getitem (`m[k]` copies, panics if absent) and refuses `m[k] = v` with `subscript.role` rather than giving it the wrong meaning.
- `Map.find` lends read-only (`&V?`), since a writable lend of a slot's payload needs item 4. No `Map` API writes a value in place.
- `LendingIterator` cannot be declared in `std/prelude.saw` (item 3).

**Fix:** the profile reads std with sawc2's own parser, or grows token rewrites for these forms. Either way, the checker's own fixtures should pin each of the four.
