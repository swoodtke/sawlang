## Description

# U4: the parser, one grammar area per unit (and U4a, the skeleton)

- **Epic:** SL-398, unit 4. The parser handles all valid Saw before any later stage consumes it (strategy step 1).
- **Design:** SL:architecture §3.2 (Parser), §3.0 (shared representation) and §4 (the subset); `compiler/tests/parse/README.md`, the AST dump contract; GRAMMAR.md, authoritative for spelling.
- **Test-first against:** the U2b corpus in `compiler/tests/parse/` (generated, golden and negative cases, with expected dumps and refusals) and the U3 corpus in `tests/corpus/`.

## The contract, for every U4 unit
1. **Package `compiler/parse/`**, `sawparse`, depending on `compiler/lex` (`sawlex`) and registered in `STAGE_PACKAGES`. It is written in the bootstrap subset, and the subset checker (including SL-422's S23 rule) passes over it.
2. **An arena AST** (§3.2): nodes in a flat array, children by index in contiguous ordered ranges, backward edges only, unique ownership. Every node has a span.
   - Spans are byte offsets into a source buffer with an explicit owner and a file identity (§3.0), not the prototype's token-index ranges.
   - Node kinds are GRAMMAR.md's `node=` names, suffixed as §1 says. So a dump renders from the arena with no mapping table beyond the one the grammar defines.
3. **The dump is the contract.** `sawc2 parse --dump <file>` prints the canonical dump that `compiler/tests/parse/README.md` specifies, byte for byte what `compiler/tests/grammar/dump.py` prints for the same input. The dump is the only oracle.
   - The prototype's dumps are not an oracle.
   - The frozen parser is not one either, except in the one-time check below.
4. **Refusals follow c35's contract.** A refusal decided by a named rule or removed production reports exactly that id (the SL:testing stable id). A plain parse error must be refused, and its line and column are informative only.
   - **Against a negative case, the first reported refusal decides the verdict** (c1 point 2). It is compared by id, and `parse-error` accepts any. Later diagnostics from recovery are ignored, so a recovery cascade never decides a case.
5. **Bounded recursive descent** (§3.2):
   - one depth funnel, with a budget of 256, charged per postfix hop, refusing at the opener or the hop;
   - flat chains (binary operators, `else if`) as loops into flat lists;
   - every recursive call cycle crosses the funnel.

   U0′'s lane proved that property for the Python parser. It lives on the Studio-local branch `sl2u0` (22305361); read it with `git show sl2u0:tools/test_parser_depth_funnel.py`, or from chat m254. U4a builds the equivalent over the Saw source against that actual reference: a static call-graph check that fails when a recursive cycle skips the funnel.
   - It closes SL:hazards C1 (`move *p` undercharged): the funnel charges the `*`.
   - C3 (the quote anchor inside a `//` comment in an interpolation) belongs to the lexer, `sawlex`, which does the interpolation scan (c1 point 4). U4a pins it with an end-to-end case. If sawlex mis-scans, that is a `compiler/lex` finding to file, never a parser-side workaround.
6. **Error recovery:** on an error, record the diagnostic, skip to the next statement or declaration boundary at the same bracket depth, and continue. One run reports every independent error. A `@test(refuses:)` body is only brace-matched in a normal parse. In a test parse it is a unit of its own, starting at `refusal-unit` (SL:testing §5).
7. **Claims make it test-first and incremental.** `compiler/parse/CLAIMS.tsv` lists the GRAMMAR.md alternatives (and §13 rules) the parser implements so far. The parse lane runs:
   - every generated and golden case whose alternatives are all claimed, requiring the exact dump;
   - every negative case whose expected refusal is claimed, requiring that refusal (a plain `parse-error` requires any refusal);
   - every `tests/corpus/` file whose alternatives are all claimed, requiring the recognizer's dump.

   A case outside the claims is counted as "not yet", never as a pass. Claiming an alternative whose cases fail is a failure. A unit's finish line is its area's alternatives claimed, and everything claimed passing.
   - **Over-acceptance fails in the unit that causes it** (c1 point 1). Every negative case runs through the parser. The lane fails any case the parser *accepts* when every alternative in the parser's own derivation of it is claimed. The parser has then claimed that ground, and accepted what the recognizer refuses.
   - **The records.** The case-to-alternatives record comes from the recognizer, the same `record` the generator and `cases.py` use. It is computed once per case and cached under a content hash of the case, GRAMMAR.md, and the recognizer's own source (`compiler/tests/grammar/*.py`, c1 point 3).
   - **One process** (c1 point 6). `sawc2 parse --dump` takes a file list and emits one delimited record per file, so the lane runs a single process over the U2b corpus and `tests/corpus/`. Its time is the reported parse time.
8. **Tests:**
   - `compiler/tests/run.py` gains a `parse` lane, or the existing parse lane grows, running sawc2 over the claimed cases;
   - unit tests inside `compiler/parse/tests/`;
   - the arena invariants (backward edges, contiguous ranges, unique ownership and reachability, spans in range and nested) are checked for every parsed case.
9. **The one-time check against the frozen parser** (the epic): for the unchanged part of the language, compare once and record the result. After that, only the golden fixtures count. It belongs to the final unit, not to U4a.

## The units, in order
Each unit is briefed as a comment on this issue when the one before it lands. Each is one patch.
- **U4a, the skeleton** (below).
- **U4b, expressions and operators:**
  - precedence levels as flat lists;
  - prefix operators, casts (the cast-target `<` rule), ranges (line ends), `??`;
  - postfix chains with `OptionalChain` runs, calls (spaced calls), members, subscripts, `!`, `?.`, tuple indexes;
  - literals and interpolation;
  - implicit members.
- **U4c, types and generics:** type syntax, generic parameter and argument lists, speculative generic arguments (generic-or-less), generic-close-split and const generics.
- **U4d, statements and control flow:**
  - `let`/`var`, assignment targets;
  - `if`/`else if` as flat lists, `guard`, `while`, `while let`, `for`, `match` arms (arm-body, arm-sep);
  - head-restriction and head-reset, block-tail, try and catch;
  - statement separators.
- **U4e, patterns.**
- **U4f, closures and braces:** the brace rule (map, set or closure), closure heads and captures, trailing closures.
- **U4g, declarations:**
  - `struct`/`enum`/`trait`/`extension`, methods, effect slots, receivers;
  - attributes and attribute positions, visibility, docs (`Doc` children);
  - `module`/`import`, statics, externs.
- **U4h, the lockdown forms:**
  - `borrow` in every form (after SL-423's bare `borrow`), `lend`, `move`/`move self`, `consumes`;
  - `@test` and `refusal-unit`, slices and the `default:` subscript.
- **U4i, the finish line:**
  - every negative case's refusal claimed;
  - every file of the parser's acceptance corpus parses: `tests/corpus/`, std, blade and libs, parse-error tests excluded (epic acceptance item 1);
  - the one-time frozen-parser comparison.

The order puts the areas everything else nests in first. The claims make the order flexible: a unit may claim an alternative from another area when its own cases need it.

## U4a: the skeleton
**Goal:** the infrastructure every later unit relies on, plus the smallest parser that exercises it end to end.
1. **The arena and source ownership:**
   - the `AstTree` arena, node kinds from GRAMMAR.md, byte spans;
   - a `SourceFile`: the buffer, its file identity and a line index for rendering;
   - the invariant checker.
2. **The canonical dump renderer,** from the arena, per the README. That includes leaves as written, escapes, suffixes, `Doc` and interpolation segments, and the §1 pass-through rules. It is equivalent to `dump.py`: add a differential check over every expected dump in the corpus, rendering each through a reader of the dump text into an arena and back, so the renderer is proven before the parser is.
3. **The depth funnel and its call-graph lane** (contract item 5).
4. **Diagnostics and recovery:** a diagnostic record (id, span, message, hint), the recovery loop, and the refusal-unit mode.
5. **`sawc2 parse --dump FILE…` and `sawc2 parse --check FILE…`** (diagnostics only), with exit codes following `sawc2 lex`. Both take a file list and emit one delimited record per file, for the one-process lane.
6. **The claims mechanism and the parse lane** (contract item 7), with the recognizer-derived alternative records cached.
7. **The first claims:**
   - the file structure: a file, `module`, `import` in all its forms;
   - a `func` declaration with parameters, a return type and a body;
   - blocks and statement separators;
   - `let`/`var` with an initializer;
   - `return`;
   - expression statements;
   - names and literals (integer, float, string without interpolation, bool);
   - parenthesized grouping.

   This is enough to pass every case built only from those alternatives, and to exercise the funnel (deep parentheses: N1's 256 passes and 257 is refused).
8. **Starting point:** reuse from `prototypes/parser/` what §3.2 lists: the arena invariants, the fixture ideas and the harness ideas. Do not reuse its continuation-stack control flow, token-index spans, per-node text copies or first-error-only failure. Its code is a reference, not a base to extend.

**U4a is done when:**
- the renderer differential passes over every expected dump;
- the call-graph lane passes and fails on an injected cycle that bypasses the funnel;
- every case whose alternatives lie within U4a's claims passes, with its count reported;
- the subset checker passes over `compiler/parse/`;
- `compiler/tests/run.py` passes.

Comments on the U4 brief before dispatch. The contract is sound, and the claims lane is the right way to make it incremental. Six points.

A cheap check catches it in the unit that causes it: run every negative case through the parser, and fail any the parser *accepts* when every alternative in its own derivation is claimed. The parser has then claimed that ground and accepted what the recognizer refuses.
2. **Recovery against the one-refusal negatives.** With recovery, one run reports every independent error, but each negative case names one expected refusal. State the comparison. Re the U4b brief, one point to relay. §11's charge table binds every construct U4b parses, not only postfix hops:
- unary `-`/`not`/`~`: 1 per operator, held to its operand's end;
- `*` deref: 1 per `*`;
- `&`/`&var`: 1 each;
- casts: 1 per `as`, held to the end of the cast chain;
- `try`/`try?`/`try!`: 1;
- interpolation: 1 per string literal, with each segment continuing from it;
- array and repeat literals: 1 per `[`.

The brief names only 'each hop charged' for postfix chains. The call-graph lane catches a recursive cycle that skips `enter_level`, but a loop-shaped implementation has no recursion for it to see: a run of prefix operators or a cast chain collected in a loop would skip its charges unnoticed. One point on the U4c brief, before dispatch or to relay. The checkpoint list (arena, slot stack, token position, depth level, diagnostics) is shorter than `Parser`'s mutable state on main. A restore that misses a field leaves an abandoned speculation's traces behind:
- **`limit` and `prev_end`:** a node closed after a restore would end at the speculation's position;
- **`seen` and `taken`, the derivation record:** alternatives the abandoned speculation `see`d stay in the record. The lane requires that record to equal the recognizer's, so it would fail, or mask a real difference;
- **`tokens` and `pieces`:** an interpolation's segment tokens are appended as it is parsed. A speculation across a string literal would leave appended tokens, and the re-parse appends them again;
- **`docs` and `runs`,** if a speculative parse can attach a doc comment.

Suggest the brief's checkpoint be "every mutable field of `Parser`", plus a structural guard like the funnel's ENTRY POINTS check: a unit test that lists `Parser`'s fields beside the checkpoint's and fails when a field is added without a decision. The decision is either "restored" or "not changed during a speculation, and here is why". A direct test for the derivation record too: speculate across an alternative, fail, restore, and assert that the alternative is not in `taken`.
