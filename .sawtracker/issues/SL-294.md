## Description

SL-260's shared-source comparison found Python sawc accepting three calls rejected by the prototype's whole-call access checks (6f307c11; unchanged source at 6a6d57bd):

* references/reject_later_read.saw: `consume(&var value, value)` reads the exclusively borrowed root in a later value argument.
* references/reject_later_write.saw: `consume(&value, if true { value = 7; value } else { 0 })` writes the shared-borrowed root during later argument evaluation (the fixture uses Saw newlines, not semicolons).
* references/reject_outer_borrow_preserved.saw: `consume(&var held, read(&other), held)` has the same later read after an unrelated nested call.

All three compile and execute successfully with no output. Expected: located exclusivity refusals. LANGUAGE_SPEC.md Law of Exclusivity and Nested calls say the argument's borrow extends over the whole call expression; an exclusive borrow excludes other reads and writes, and shared access excludes writes. The prototype should retain its stronger checks.

Mechanism to address: production's call access-set comparison covers reference/move arguments and nested reference arguments, but does not account for these ordinary value reads and inline writes while an outer explicit argument borrow is active. SL-284 is adjacent but covers a different omitted source (implicit method receivers inside nested calls); here the original explicit reference is already present.

Audit argument order, shared/exclusive roots, nested calls, inline value-control writes, fields and reference forwarding. Preserve disjoint-root/field and shared-read controls. The prototype fixtures above are the three minimal regression cells; avoid fixing only the bare two-argument spelling.
