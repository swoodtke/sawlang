**A `borrow PLACE` read at a Borrow position copies a NoCopy value bitwise into a temporary its statement drops** (SL-606; found by SL-623's sweep).

- **The bug:** `print("element {}", borrow v[0])`, where `v: Vector<Res>` holds a NoCopy `Res` that has a printing `deinit`, prints `drop 5` twice from safe code: once at the end of the statement and once when `v` dies. `drops --check` accepts it. It reproduces on main at 16137ccc1, without SL-623's change.
- **Mechanism:** MIR's `borrow_place_val` (`compiler/mir/src/lower.saw`) handles a use other than `Copy` with `prepared_val(e)`. Inside the window, that copies the lent referent into a fresh temporary (`_12 = copy (*_13)`). `transfer` then sees `v.fresh && u == Borrow` and calls `own_temp`, so the statement owns a bitwise duplicate of an element the vector still owns, and drops it. A Borrow position must pass the lent place by reference while its window is open, not copy it out.
- **A second face:** for a NoCopy raw-backed enum element, `(borrow v[0]) as UInt8` prints `0` and then `drop 0`. The backend emits that copy as `call void @"saw copy glue T"(ptr dst, ptr src)`, but the glue for a NoCopy enum is defined `i8 (ptr)`, so the copy writes nothing. A NoCopy type should never reach copy glue at all.
- **Positions to sweep:** every Borrow-use position whose operand can be a `borrow PLACE`: format arguments, interpolation, comparison operands, a `??` subject and a cast (SL-623 makes the raw enum cast one).
- **Probe:** `.build/scratch/c623/borrowfmt.saw` in agent worktree `agent-a6601eb0884059b7f`:
  `struct Res { n: Int }`, `extension Res: NoCopy { func deinit(&var self) { print("drop {}", self.n) } }`, a `Printable` that appends `self.n`, then `var v = Vector<Res>(); try! v.push(Res(n: 5)); print("element {}", borrow v[0])`. It prints `element res 5 / drop 5 / end / drop 5`.
- **Pins:** a run program for each position above that prints exactly one drop per value, and a raw enum element whose cast prints its real tag.

**b642borrow: fixed in worktree commit fa05325b4 (branch `b642borrow`, on origin/main 24d9db172; not submitted).**

- **Reproduced** on main: `print("element {}", borrow v[0])` printed `drop 5` twice.
- **Mechanism (corrected from c1):** the copy is not made in `borrow_place_val`'s window. Typecheck's `settle_call` settles the subscript under a `borrow` expression as a derived **getitem**, because the subscript's own use is `Project`. MIR's `prepare_subscript` then runs `getitem`, whose `copy_out` copies the element bitwise (no hook, since NoCopy) and closes the window, and `transfer`'s `fresh && Borrow` makes the statement own that copy.
- **Fix:**
  - **typecheck** (crossing approved by the lead): `settle_call` settles the subscript as a Place when its projection ends in a lending position. The test is `lent_in_place`, a funnel shared with `check_plain_subscript_reads`, as SL:borrowing §5.1 says ("`borrow` subscripts are places"). The element is read through the open window, which closes at the statement's end, or once a part is copied out.
  - **cast:** `lent_by_borrow_place` is removed. The two guard fixtures `transfer.implicit-copy.raw-enum-cast-borrow` and `-projected` are deleted and are now rows of the run probe, which prints the real tag and one drop at -O0 and -O2.
  - **INVARIANT, not `drops --check`:** the MIR verifier refuses a `copy` operand of an owning type that does not copy silently. Typecheck refuses every such copy the source spells, and a `copy()` hook runs as a call, so a copy that reaches MIR is always the lowering's defect, which is what an INVARIANT reports. The MIR verifier also runs on every function before the backend, where the copy glue was miscompiled. One shape is admitted (`reads_tag`): the operand of a raw-backed enum's cast to an integer, which reads only the tag. On the unfixed typecheck, the check catches every row of the sweep.
- **Sweep** (main → fixed). Double drop: format argument, interpolation, both comparison operands, a scrutinee with and without a payload binding, `borrow var` in a format argument. Bitwise copy leaked: a field read in a format argument, in a `let` or in arithmetic, and `borrow v[0].n == r.n`. Refused by mono or by `lend.root`: a nested chain, a receiver (`borrow bags[0].items.len()`), a range bound, and an accessor's `lend self.bags[0].items[0].n`. In place, unchanged: an ExplicitCopy element and a `borrows` method lend. The cast's whole, field and lend forms were guarded on main and are now read in place. `??` consumes its subject: a NoCopy payload is still refused with `transfer.implicit-copy`, and a Copy payload is unchanged. Every one is now one drop per value.
