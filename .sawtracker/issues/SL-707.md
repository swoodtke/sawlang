## Description

**sawc2 never checks the spec's entry-point rule** (LANGUAGE_SPEC.md "The entry point": `main` is a top-level function taking no parameters, and returns one of four types, or it's a compile error at the declaration). Found by SL-698's sweep (agent m698main).

**Mechanism:** no stage owns the rule. Mono's `add_roots` picks `main` by name, the newest declaration of that name in the entry module, and the backend reports whatever is left as a broken invariant rather than as a refusal with a rule ID.

**Evidence** (`sawc2 build --std-root std`, Stage 2 at c4ea336a3):

| program | sawc2 | expected |
|---|---|---|
| `func main(x: Int) { print("main {}", x) }` | rc 0; prints `main 1` (argc, read as `x`); at -O2 a test-only twin printed `0` | refused at the declaration |
| `func main() { … }` then `func main(x: Int) { … }` | rc 0; runs the newer one, `main(x:)` | refused: `main` takes no parameters, and there is one `main` |
| `func main() -> String { "s" }` | `INVARIANT mono a main returning anything but Void or Int is not in the backend slice yet` | the spec's error at the declaration, "`main` must return `Void`, `Int`, `Result<Void, E>` or `Result<Int, E>`" |
| no `main` at all | `INVARIANT mono the entry module declares no \`main\` with a body` | a refusal. Stage 0 says `no \`main\` function found`, with the hint to add one |

An `INVARIANT` line claims the compiler broke its own invariant. Each of these rows is a user error, and none has a rule ID that a fixture or `@test(refuses:)` could cite.

**Fix:** one typecheck check of the entry module's `main`: no parameters, one declaration, one of the four return types. A program with no production `main` is refused there too. A test-only `main` doesn't count, since SL-698 made a normal build pass test-only declarations over. `Result` returns stay a backend not-yet until they are lowered. The rule names need choosing, e.g. `entry.missing` and `entry.signature`. Pins: a refusal fixture per row, and, once it is a refusal, SL-698's "only `main` is test-only" case in both spellings.
