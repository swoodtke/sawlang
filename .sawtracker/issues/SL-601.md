**sawc2 cannot walk a lending iterator with `for`** (found by std1 on SL-597's new step 1, the iteration protocol).

Probe (`.build/scratch/probe_lendfor.saw` in the std1 worktree): a trait `Lending { type Item; func next(&var self) borrows -> &var Item? }`, a `Countdown: Lending` whose `next` lends `self.value`, then `for x in c { ... }` and `for borrow var y in d { ... }`:

```
ERROR type.mismatch    probe_lendfor.saw:27:14 `for` walks an iterator, and `probe_lendfor.Countdown` has no `next` that hands out an Optional
ERROR slice.not-yet    probe_lendfor.saw:31:5  `syntax.expr.for.borrow` is not in the bootstrap slice yet
```

And a shared lend, `func next(&var self) borrows -> &Int?`, does not meet the requirement `-> &var Item?`:

```
ERROR conformance.signature ... `BagIterator.next` does not meet `Lending.next` ...: its result type differs
```

The spec allows it ("`func next(&var self) borrows -> &var Item?`, or `&Item?` for a shared one").

**Mechanism:**
- `for_expr`/`iterator_item` (`compiler/typecheck/src/bodies.saw`) accept a `next` only when its result is an Optional VALUE. A lending `next`'s result is a reference to an Optional, so it is refused.
- `Expr_For_Borrow` has no typecheck case, so it falls to `not_yet`.
- MIR's `lower_for` calls `next` as a plain call. A lending `next` needs a window per iteration, opened before the body and closed before the next `next` ("each iteration is one nested borrow").
- The conformance check compares the result types exactly, so it has no rule for the shared-lend variant.

**What it blocks:** `LendingIterator` in the prelude (with SL-600, the std profile), every collection iterator the spec has collections implement, and A6's (SL-559) collection `for` across a suspension, which consumes the same trait. Together with SL-461 (`lends`, for `Vector.iter`'s borrowing struct), it is why SL-597's iteration steps stopped.

**Fix scope:** typecheck (`for` over a lending `next`; `for borrow let/var`, which requires one; the shared-lend conformance rule), MIR (`lower_for`'s per-iteration window), and borrowck's charge of the head for the loop.
