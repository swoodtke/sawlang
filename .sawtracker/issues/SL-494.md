## Description

Found by SL-459's misc459 agent while pinning item 7's static_assert matrix.

**Defect.** A statement-position `static_assert` inside a function body is never evaluated by sawc2, so a false one, a faulting one and a non-constant one are all accepted silently:

```saw
func main() {
    let n = 3
    static_assert(n > 2, "a local")        // not a constant: accepted
    static_assert(1 << 64 == 0, "a fault") // shift out of range: accepted
    static_assert(1 > 2, "false")          // false: accepted
    print(n)
}
```

`sawc2 typecheck`, `mir` and `eval` print no refusal. Stage 0 refuses the false one ("static assertion failed: in a body"), and LANGUAGE_SPEC (Compile-Time Evaluation) says `static_assert` "is legal at top level and in statement position", with a false result a compile error.

**Mechanism.** Only a top-level `static_assert` item gets a constant-position MIR function (`static_assert MODULE L:C`), which the evaluator runs. In a block, typecheck checks only that the condition is a `Bool` (bodies.saw, the `Decl_StaticAssert` statement arm: `check_condition`), and lowering emits nothing for it (lower.saw `lower_statement`: `case Decl_StaticAssert -> {}`). So no constant position exists for the evaluator to reach. Every body kind is affected: a function, a method, an `init`, a closure body, a trait default body, a test case.

**Fix.** Either lower a statement-position `static_assert` as a constant position of its own, as the item form is (MIR `static_assert` function, evaluated by eval and held to the fold by the agreement check), or report it in typecheck through SL-493's constant-position funnel. The condition may not name a local, so it is a constant over module scope either way. Sites: lower.saw (mir, not op_move) and bodies.saw (typecheck, tcb2b's lane). Pin: a golden row per body kind.

Probe: misc459 worktree `.build/scratch/body_sa2.saw`.
