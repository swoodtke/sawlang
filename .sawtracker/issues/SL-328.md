## Description

# M21: iterative control-flow parsing

Under SL-300, following merged M20 (SL-303). User authorized September 19:
build this milestone in parallel with Claude's SL-2 Python parser alignment.
The final parity gate depends on that alignment; independent implementation
and arena validation do not. This milestone changes the prototype only.

## Scope

Replace expression/block recursion with explicit continuations before admitting
ordinary `if condition { ... }`, optional `else { ... }`, and `else if` chains.
An if is an expression, usable in a binding, return, assignment RHS, argument,
operator operand, condition, or block tail; the existing block statement/tail
rules still apply. Branches contain the existing M20 statements and nested ifs.
Optional binding (`if let`/`if var`), loops, match, closures, bare block
expressions, and other grammar remain cleanly refused.

Preserve the existing expression grammar and precedence, newline continuation,
assignment-only-at-statement-head rule, spans, and first-error funnel. Do not
copy Python's known grammar defects or silently consume adjacent expressions.
In particular, branch/else lookahead must not consume the newline needed to
separate the next statement. A leading minus after a newline following a closed
if belongs to the next statement under design 259 R2. No production parser,
mini-VM resource limit, lexer, or canonical schema changes belong here.

## Representation and execution

Add an `If` arena node with empty text and ordered children: condition, then
Block, optional else Block. Anchor at `if`; span through its last branch.
Represent `else if` as an else Block containing a FinalExpression wrapping the
nested If, matching Python's canonical shape; the synthetic block is anchored
at the nested `if` and spans that nested expression. Existing arena invariants
remain: backward edges, contiguous child ranges, unique child ownership,
complete reachability, and parent span containment.

Use one explicit parser work/continuation stack for suspended expression and
block work. Parsing syntactically nested ifs must not recurse through Saw/VM
call frames. Preserve the depth-256 expression contract and extend the same
budget to active nested if expressions: each active if adds one; groups,
unary operators and argument delimiters retain their existing contributions.
The function body and the required branch braces do not add another charge
for the same if. Sequential siblings must release their budget. Pin 256/257
for pure if, else-if, and mixed if/group/call/unary paths, plus long shallow
blocks/chains. Reconcile any conflict with SL-2's eventual depth convention
explicitly before final parity approval; never quietly change existing pins.

Canonical rendering uses the existing IfExpr format: condition:, then:, and
optional else: sections, normal Block rendering, using the renderer's iterative
work stack. Syntax-only acceptance must include semantically invalid conditions
and branch value types; semantic rejection is not parser rejection.

## Ownership and validation

Sol source agent owns `prototypes/parser/src/{lib,canonical}.saw`. Sol tests
agent independently authors fixtures and harness checks. Sol inventory agent
owns fresh eligibility analysis, classifier coverage and its tests. Each works
in an isolated worktree. Parent owns this brief, review, integration, gates,
tracker submission, and reconciliation with Claude's oracle work.

Test ordinary/else-if/nested forms in every expression position; empty branches,
statement/tail distinctions, assignments and returns inside branches; operator
precedence and newline behavior; missing conditions/braces/else bodies and
unsupported binding forms; exact spans, anchors, child order and invariants;
depth boundaries and long shallow inputs. Independently authored expectations
must not be generated from the new implementation's output.

Run arena and canonical gates across VM, LLVM O0/O2, ASan, and production sawc;
all harness tests; inventory regeneration/check; and the fresh eligible corpus
differential. Report counts by verdict and compare newly eligible complete
files. Existing Python disagreement remains a strict, visible debt probe, not
a tolerated divergence. Final M21 approval requires rebasing onto aligned
Python, debt probes green, and canonical parity. If alignment has not landed,
submit only as explicitly dependency-blocked work with validation limits clear.
