The user ruled (Nov 9) on spec review F6 (SL-1003): add the site. LANGUAGE_SPEC "Variables and Mutability" says the diagnostic names the shadowed binding's exact declaration site. sawc's message (compiler/resolve/src/lookup.saw check_shadow) names none. The corpus programs tests/corpus/errors/shadow_*.saw already expect `x` shadows the binding declared at FILE:L:C.

The three messages become:
- **non-derived:** "`x` shadows the binding declared at FILE:L:C without deriving from it; pick another name, or mention `x` in the initializer";
- **flat** (a pattern, parameter or closure parameter): "`x` shadows the binding declared at FILE:L:C, which a pattern, a parameter or a closure parameter may not do; pick another name";
- **same scope:** "`x` is already defined in this scope, at FILE:L:C; a redefinition must derive from it, as `let x = f(x)` does".

FILE:L:C comes from module_file plus position_text, as append_res_diag renders. A local's site is its binding.node, in the current module. A static's is decls[d].leaf. The brief follows.

**Air: SL-1027.p1, approved.** I built sawc from b7cf9596f + p1 and probed every shadowing position. Each diagnostic names the shadowed binding's own name leaf as `FILE:L:C`:

| shadowing position | site named |
|---|---|
| nested `let n` | `…:2:9` |
| same-scope redefinition ("already defined in this scope, at …") | `2:9` |
| a `for i` over a local | `2:9` |
| a closure parameter | `3:9` |
| a match payload binding | `2:9` |
| an `if let` | `2:9` |
| a local over a module `static` (`decl.leaf`) | `1:8` |
| a local over a parameter | `1:8` |

`check_shadow` sets `site_node` on both paths that find a shadowed binding (a local's `binding.node`, a static's `leaf`) and returns before `binding_site` when neither does. `let self` is a parse error before resolution, so no reachable path formats node −1. The spec's two quoted messages match.

Nit, not this patch's: the for-loop and `if let` shadow messages end "or mention `i` in the initializer", but a loop variable has no initializer. It's a candidate for SL-1020's message pass.
