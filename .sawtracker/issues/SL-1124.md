## Description

**`String? == String` with a right side that is not a literal reads and frees memory it does not own: the comparison wraps a REFERENCE to the bare operand as the Optional's payload.** Found by the reviewer while probing SL-1119.p1 (Nov 14); it is on main and not caused by that patch. Safe code, no `unsafe` anywhere.

**Run (lead, main at d10d83f4e, macOS arm64; `.build/scratch/poptcmp/` in the lead's checkout: the program is `dl/optional_equals_string.saw`, the reviewer's chat file f96).**
```saw
func same_binding(id: Int) -> Bool {
    let s: String? = "i{id}"
    let want = "i{id}"
    s == want
}
```
- `-O0`: prints `binding false` for two equal strings, exit 0.
- `-O2`: dies on a signal (exit -5) at that line.
- `--sanitize address`: `stack-buffer-overflow ... READ of size 8` in `std.string.String.len()`, called from `string_equals`.
- `s == "i7"` (a literal on the right) is right, and so is `Int? == Int`.

**The mechanism, read from `sawc mir --dump` (`main.mir`, `fn optional_equals_string.same_binding`).**
```
_7 = ref(shared, _2);            // &String?   the left operand
_8 = ref(shared, _5);            // &String    the right operand, borrowed
_9 = String?::Some(move _8);     // a REFERENCE moved in as a String? payload
_10 = ref(shared, _9);
_11 = call Equatable.equals(other: &Self) (owner String?) [move _7, move _10]
...
drop(_9);                        // then dropped as if it owned a String
```
The comparison lowers each operand by reference, and the adjust that makes the bare side an Optional (`T` to `T?`) is applied to the borrowed operand, so the `Some` holds a pointer where a `String` is expected. `equals` then reads the pointer's bytes as a `String` (the wrong answer, or a read out of bounds), and the `drop` releases a `String` that was never there. It is one of the compiler-made call constructions (a comparison becomes a call of `Equatable.equals`), and the class is: **an auto-wrap adjust meeting an operand the construction has already taken by reference.**

**To do first (obligation 4): the sweep, each cell built at `-O0` and under `--sanitize address` and run, with the MIR line that makes the `Some` quoted.**
- The bare side: a local binding, a parameter, a `&String` parameter, a field place (`p.name`), an index (`v[0]`), a call's result, an interpolation, a literal (the control).
- The payload type: `String`; a struct of the automatic Copy tier that holds a `String`; an enum with a payload; an `ExplicitCopy` type (`Vector<Int>`); a `NoCopy` type that is `Equatable`; `Int` and `Bool` (controls); a nested Optional (`String??` against `String?`).
- The operator and the side: `==` and `!=`, the Optional on the left and on the right; the ordering operators if `Optional` takes them.
- **The other constructions that take an operand by reference and may meet the same adjust:** `match` on an Optional against a bare pattern value, `contains`-style calls where a `T?` parameter takes a bare `T` argument by reference, `assert(a == b)`'s operands, `??` and `if let` are NOT comparisons but list what each does with the same operands as controls. Find where the adjust is applied (`payload_adjust`, `TcAdjustKind` and the comparison's lowering in `compiler/mir/src/lower.saw`; the typechecker's side in `compiler/typecheck/src/bodies.saw` where a comparison's operands are unified) and name every caller.

**What right is.** The bare operand compared with the payload in place: either the Optional's tag is tested and the payload compared by reference with the bare operand (no wrapper is made, which is the only form that works for a type that cannot be copied), or, for a type of the Copy tier, the wrapper holds a copy with its retain. The fix takes ONE of these for every type, decided from the sweep: a `NoCopy` payload has to work or be a clean error, never an ill-typed MIR.

**Also from this finding: the MIR verifier accepted `String?::Some(move _8)` with `_8: &String`.** An aggregate whose operand's type is not its field's type should be an INVARIANT. Add that check (`compiler/mir/src/verify.saw`), and report whether anything on main trips it (run it over the corpus and std: every hit is a sibling of this defect).

**Ledger.** This is a safety guarantee (safe code read out of bounds): its `tests/corpus/conformance/` row is written first (obligation 3), with its twin where the ledgers need one.

**Pins.** A run probe with the reviewer's four functions at `-O0`, `-O2` and under the ownership oracle (`gmgate`); the sweep's cells that built wrong; a MIR golden of `same_binding`.

**Workaround until it lands:** compare through the payload (`if let x = s { x == want } else { false }`) or wrap the right side yourself (`let w: String? = want` then `s == w`: check that this spelling is right in the sweep before recommending it).

- `if let x = s { return x == want }` is right.
- `let w: String? = want` and then `s == w` is right (the wrapper made by a binding holds a copy, not a reference).
- **Only an Optional on the LEFT wraps the right side:** `want == s` (the bare side on the left) is refused, `type.mismatch`: "expected `String`, the type of the other operand, and found `String?`". So the sweep's "Optional on the right" cells are expected refusals, and the defect is the right operand of a comparison whose left is an Optional.
