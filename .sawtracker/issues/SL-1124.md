## Description

**`String? == String` with a right side that is not a literal reads and frees memory it does not own: the comparison wraps a REFERENCE to the bare operand as the Optional's payload.** Found by the reviewer while probing SL-1119.p1 (Nov 14); it is on main and not caused by that patch. Safe code, no `unsafe` anywhere.

**Run (lead, main at d10d83f4e, macOS arm64; `.build/scratch/poptcmp/` in the lead's checkout: the program is `dl/optional_equals_string.saw`, the reviewer's chat file f96).**
```saw
func same_binding(id: Int) -> Bool {
    let s: String? = "i{id}"
    let want = "i{id}"
    s == want
}
```
- `-O0`: prints `binding false` for two equal strings, exit 0.
- `-O2`: dies on a signal (exit -5) at that line.
- `--sanitize address`: `stack-buffer-overflow ... READ of size 8` in `std.string.String.len()`, called from `string_equals`.
- `s == "i7"` (a literal on the right) is right, and so is `Int? == Int`.

**The mechanism, read from `sawc mir --dump` (`main.mir`, `fn optional_equals_string.same_binding`).**
```
_7 = ref(shared, _2);            // &String?   the left operand
_8 = ref(shared, _5);            // &String    the right operand, borrowed
_9 = String?::Some(move _8);     // a REFERENCE moved in as a String? payload
_10 = ref(shared, _9);
_11 = call Equatable.equals(other: &Self) (owner String?) [move _7, move _10]
...
drop(_9);                        // then dropped as if it owned a String
```
The comparison lowers each operand by reference, and the adjust that makes the bare side an Optional (`T` to `T?`) is applied to the borrowed operand, so the `Some` holds a pointer where a `String` is expected. `equals` then reads the pointer's bytes as a `String` (the wrong answer, or a read out of bounds), and the `drop` releases a `String` that was never there. It is one of the compiler-made call constructions (a comparison becomes a call of `Equatable.equals`), and the class is: **an auto-wrap adjust meeting an operand the construction has already taken by reference.**

**To do first (obligation 4): the sweep, each cell built at `-O0` and under `--sanitize address` and run, with the MIR line that makes the `Some` quoted.**
- The bare side: a local binding, a parameter, a `&String` parameter, a field place (`p.name`), an index (`v[0]`), a call's result, an interpolation, a literal (the control).
- The payload type: `String`; a struct of the automatic Copy tier that holds a `String`; an enum with a payload; an `ExplicitCopy` type (`Vector<Int>`); a `NoCopy` type that is `Equatable`; `Int` and `Bool` (controls); a nested Optional (`String??` against `String?`).
- The operator and the side: `==` and `!=`, the Optional on the left and on the right; the ordering operators if `Optional` takes them.
- **The other constructions that take an operand by reference and may meet the same adjust:** `match` on an Optional against a bare pattern value, `contains`-style calls where a `T?` parameter takes a bare `T` argument by reference, `assert(a == b)`'s operands, `??` and `if let` are NOT comparisons but list what each does with the same operands as controls. Find where the adjust is applied (`payload_adjust`, `TcAdjustKind` and the comparison's lowering in `compiler/mir/src/lower.saw`; the typechecker's side in `compiler/typecheck/src/bodies.saw` where a comparison's operands are unified) and name every caller.

**What right is.** The bare operand compared with the payload in place: either the Optional's tag is tested and the payload compared by reference with the bare operand (no wrapper is made, which is the only form that works for a type that cannot be copied), or, for a type of the Copy tier, the wrapper holds a copy with its retain. The fix takes ONE of these for every type, decided from the sweep: a `NoCopy` payload has to work or be a clean error, never an ill-typed MIR.

**Also from this finding: the MIR verifier accepted `String?::Some(move _8)` with `_8: &String`.** An aggregate whose operand's type is not its field's type should be an INVARIANT. Add that check (`compiler/mir/src/verify.saw`), and report whether anything on main trips it (run it over the corpus and std: every hit is a sibling of this defect).

**Ledger.** This is a safety guarantee (safe code read out of bounds): its `tests/corpus/conformance/` row is written first (obligation 3), with its twin where the ledgers need one.

**Pins.** A run probe with the reviewer's four functions at `-O0`, `-O2` and under the ownership oracle (`gmgate`); the sweep's cells that built wrong; a MIR golden of `same_binding`.

**Workaround until it lands:** compare through the payload (`if let x = s { x == want } else { false }`) or wrap the right side yourself (`let w: String? = want` then `s == w`: check that this spelling is right in the sweep before recommending it).

**The mechanism.** Only a comparison's right operand ever carries the `T` to `T?` adjust under a borrowing use (typecheck: `compare_expr` and `check_compared`). What a program may write does not change.

## 1. Where the "present and equal" test is made

### 1.1 The choice: typecheck resolves at the payload and names the Optional operand; MIR lowers the tag test

- **Typecheck** (`compare_expr`, `compiler/typecheck/src/bodies.saw`): the
  operand checked against the other operand's type (`check_compared`, the
  funnel's mixed-operand entry) is the only one that can carry a wrap. When
  that operand's adjustment chain ends in `Some`, the comparison is `==` or
  `!=`, and two values of the payload type compare (`payload_compares`: a
  builtin comparison, or `satisfies(P, Equatable)`), typecheck removes that
  last `Some` step (`unwrap_compared`, `adjust.saw`), resolves the comparison
  at the payload type `P` through the unchanged `resolve_comparison`, and
  records on the comparison's call record which operand is the Optional
  (`TcCall.optional_operand`, `model.saw`).
- **MIR** (`comparison` -> `present_comparison`, `compiler/mir/src/lower.saw`):
  a record with `optional_operand >= 0` lowers to: both operands read exactly
  as the resolved payload comparison reads its operands (a builtin's borrowed
  values, or a declared `equals`'s two shared references), left to right;
  the Optional operand's place (read through any reference) switched on its
  tag; on `Some`, the payload place (`payload_place`) read as the comparison
  reads an operand (`borrowed_value` for a builtin, `shared_ref` for a call)
  and compared with the bare operand, in source order; on `None`, `false`;
  the two edges join; the operands' windows close after the join; `!=` is
  `not` of the joined answer.

Every stage after MIR sees only constructs it already handles: a `switch
discriminant`, a payload projection under its switch, shared references, a
builtin `Eq` or a call of `P`'s `equals`. Nothing new is taught to borrowck,
drops, mono, coro or the backend (section 2).

### 1.2 Why this place, and why it cannot be bypassed

- `compare_expr` is the one place a comparison's operand is typed against the
  other's type (`check_compared` is called only there), and `comparison` is
  the one place a comparison lowers (`Expr_Compare_Pair` -> `comparison`,
  `lower.saw`). Every spelling the sweep listed reaches both: `assert(s == w)`,
  `if`, `return`, `not (...)`, parentheses, a guard, a field place, a
  generic body.
- The wrong lowering is unrepresentable at three levels, each a check that
  fires on any construct, not only comparisons:
  1. **typecheck's body verifier** (`bodyverify.saw` `verify_typed`): a `Some`,
     `Ok` or `Err` adjustment on an expression whose use is `Borrow` is an
     INVARIANT ("a borrowed value is wrapped in a case"). After the fix no
     position records one: no INVARIANT of any kind over the corpus
     (`final/corpus_check_summary.txt`), all of std (`final/allstd_check.txt`)
     or the compiler driver's whole program (`proto/driver_check.txt`, and the
     stage builds, which run every verifier: `build_u1*.log`).
  2. **typecheck's body verifier** (`verify_call` -> `verify_optional_operand`):
     a record's `optional_operand` is one of the comparison's own two operands,
     and its type, read through references, is the Optional of the other's.
  3. **the MIR verifier** (`verify.saw` `verify_aggregate`, U2): an aggregate
     whose operand's type is not its slot's. It flagged every wrong cell on
     main and nothing else (section 3).
- The lowering never decides the form from types: it reads the record. A
  record without `optional_operand` lowers exactly as before (the builtin
  branch or `operator_call`), and a comparison whose operand still carried a
  `Some` would be reported by check 1 (and its MIR by check 3) as an
  INVARIANT, which blocks the build before drop elaboration and codegen
  (`drops_layer_front` stops on any verifier's INVARIANT; `u2/forms_build.txt`
  shows `sawc build` refusing on check 3).

### 1.3 The alternatives, and why they lose

- **(i) Typecheck keeps the comparison at `P?` and the lowering makes the
  right operand an Optional "without a wrapper".** There is no such value: a
  `&P?` must point at storage laid out as a `P?` (tag, then payload), and a
  bare `P` has no tag beside it. Making one is a bitwise copy of `P` into a
  `Some` that must then never be dropped, i.e. a wrapper and a copy, which the
  ruling rejects; MIR has no non-owning aggregate to express it, and the new
  aggregate check (U2) would rightly refuse the `Some(move &P)` it would need.
  It also keeps every comparison of a String payload going through the
  `String?` member glue instead of the builtin String equality.
- **(ii) The test lives in mono's equality glue** (`glue.saw`
  `build_parts_equals`), with a second entry taking `(&P?, &P)`. That needs:
  a callee identity no declaration writes (typecheck would record a call to a
  synthetic target, which `verify_call`, the summaries, `instantiate` and
  mono's worklist all key on a declaration), a new `MonoGlueKind`, its
  worklist registration and its LLVM emission; and the builtin payloads
  (`String`, `Int`) would either lose their builtin comparison or need the
  MIR branch anyway. It touches three stages (typecheck, mono, llvm) instead
  of two, puts the presence test where borrowck and the MIR verifier cannot
  see it, and inherits the Optional glue's suspension summary, which drops the
  payload's condition (section 2.6, UNVERIFIED as a defect).
- **(iii) Keep `Int? == Int` (a builtin Optional comparison) on its old path**
  and route only the non-builtin payloads through the new form. It would
  leave a `Some` adjust under a `Borrow` use legal for trivial payloads, so
  check 1 would need a type carve-out, and two shapes would answer one
  meaning. Rejected; see 2.7.
- **(a) as chosen** is the smallest: typecheck gains one branch in
  `compare_expr` and one record field, MIR gains one function beside
  `operator_call`, and both reuse their existing funnels (`resolve_comparison`,
  `switch_cases`, `payload_place`, `borrowed_value`/`shared_ref`, the call
  construction of `operator_call`). Prototype size: `proto.diff`, 7 source
  files.

### 1.4 What typecheck records

For `s == want` (`same_binding`), before and after, from `typecheck --dump`
(`main/forms/typecheck.txt` and `proto/forms/typecheck.txt`, node 29):

```
before: (29:5-29:14 Binary.pair Bool value temp (operator Equatable.equals(other: &Self) == (owner String?)))
        (29:5-29:6 Name String? place borrow)
        (29:10-29:14 Name String (some String?) place borrow))
after:  (29:5-29:14 Binary.pair Bool value temp (op == (optional left)))
        (29:5-29:6 Name String? place borrow)
        (29:10-29:14 Name String place borrow))
```

Exactly:
- **The comparison** (`call_at[e]`): the record `resolve_comparison` makes at
  the PAYLOAD type `P`, unchanged in every other field: a `BuiltinOperator`
  with the operator's spelling (and, for a String payload, the
  `string_position` the builtin String comparison owes), or an `Operator`
  call of `P`'s `equals` (owner `P`: a member, the `Equatable` requirement
  through `record_structural_equals`, or the bound's requirement for a type
  parameter), plus `optional_operand` = the node of the operand whose type is
  the Optional. The dump prints it `(optional left)` / `(optional right)`.
- **The Optional operand**: its own type (`P?`, or a reference to it), use
  `Borrow`, no adjustment added (it was typed first, with no expectation).
- **The bare operand**: its own type (`P`, or a `&P` it reads through), use
  `Borrow`, and its adjustment chain WITHOUT the final `Some` step; any earlier
  step stays (an `Adopt` of a literal, a `Deref`). `final_type` is `P` (or its
  reference).
- The comparison's type is `Bool`, as before.

How the lowering knows the form: `self.tc.calls[at].optional_operand >= 0`.
Which payload comparison: the record's `role` (`Operator` -> call, else
builtin), exactly as for any comparison.

### 1.5 The two corners a user extension on `Optional` opens

`resolve_comparison` looks for a method member named `equals`/`compare` on the
compared type before it asks `Equatable`. A user can write
`extension Optional { func compare(&self, other: &Self) -> Ordering }` (or
`equals`), and on main that makes `s < want` (and `s == want`) resolve at `P?`
through the user's member with the wrapped-by-reference operand, so it is
memory-unsafe (`main/ext_compare/runs.txt`).

The prototype:
- **Equality**: the present-and-equal form applies whenever the payload
  compares (`payload_compares`), so the user's `Optional.equals` is not
  consulted for a mixed comparison; `ext_equals.saw` now prints `cell false`
  at `-O0`, `-O2` and asan (`"i7"` vs `"j7"`), where the user's member would
  have said `true` (`final/ext_equals/runs.txt`). This follows the ruling's
  text ("means present and equal") but changes which code answers; see
  Questions.
- **Ordering, or an equality whose payload does not compare**: after
  `resolve_comparison` at `P?`, a comparison that still carries the `Some`
  and was resolved (a member found on `Optional`) is refused,
  `operator.undefined` at the comparison (`refuse_wrapped_comparison`):
  - ordering: "`<` compares a `String?` with a bare `String`: only `==` and
    `!=` compare an Optional with a bare value; test the Optional with
    `if let` first" (`final/ext_compare/runs.txt`,
    `final/refuse_fixtures.txt`);
  - equality: "`==` compares a `Name?` with a bare `Name`, which tests that
    the Optional is present and its payload equals the value, and `Name` is
    not `Equatable`" (module prefixes elided; `final/refuse_fixtures.txt`).
  A comparison refused by `resolve_comparison` itself (no member) keeps its
  old diagnostic: `s < want` with std alone still reads "`<` compares two
  `String?`, which is not `Comparable`", and `Vector<Int>? == Vector<Int>`
  "`==` compares two `Vector<Int, ...>?`, which is not `Equatable`"
  (section 4: every refusal byte-identical). That is why `payload_compares`
  is asked BEFORE resolving at the payload: resolving at `P` first would
  refuse a non-`Equatable` payload in `P`'s words, not `P?`'s.

### 2.3 Borrowck: the loans each side holds

`proto/forms/borrowck.txt`, `fn forms.same_binding`:
```
loan L0: shared _2;  // ref at 29:5
loan L1: shared _5;  // ref at 29:10
loan L2: shared ((*_7) as Some).0;  // ref at 29:5
bb0: ... {L0} _8 = ref(shared, _5); {L0 L1} switch discriminant((*_7)) ...
bb1: {L0 L1} _10 = ref(...); {L0 L1 L2} _9 = Eq(move _10, move _8); {} goto -> bb3;
bb2: {} _9 = const false ...
bb3: {} ...
```
The Optional side holds one shared loan of its place (L0) from before the
right operand is evaluated until the compare; the bare side one shared loan
(L1); the payload a shared reborrow through L0 (L2) in the present edge only.
Every loan is dead at both edges' `goto` (`{}` on bb1's goto and all of bb2):
none outlives the comparison. These are the loans `operator_call` takes today
(L0, L1), less the loan of the bogus wrapper. The builtin form holds what the
builtin branch holds today: a trivial Optional is copied (`int_builtin`:
`_5 = copy _2`), so no loan and the right operand may still write the
Optional's place (the `snapshot` rule kept, 2.7).

## 3. The verifier check (U2)

### 3.1 The rule

`compiler/mir/src/verify.saw`, `verify_aggregate`, called from
`verify_block` for every `Assign` whose rvalue is an `Aggregate`:

- Slots by aggregate kind (`aggregate_slots`):
  - `Case` (`decl` the case): the case's payload field types
    (`cand_param_type` of a `TcCand` of kind `Case`), each substituted with
    the aggregate type's own arguments (`TcSubst(owner: the enum, args:
    nominal_args(rv.ty))`), as `lower.saw` `payload_types` computes them.
  - `Struct`: `struct_fields(rv.ty)` (`build.saw`), the stored fields at the
    type's arguments.
  - `Tuple`: the tuple type's element types.
  - `Array`: the element type, once per operand. `Repeat`: the element type
    for the value, the count unchecked.
  - `Vector`, `Set`: the first type argument per operand; `Map`: the first
    and second in turn.
  - `Closure` and `Plain`: no declared slots; not checked (a closure's
    operands are its captures, whose by-reference captures are references
    by design).
- The operand count must equal the slot count ("builds a `T` from N operands
  where it has M parts"), and each operand's type must be EXACTLY its slot's
  type ("bbN builds a `T` from a `X` where its part K is a `Y`").
- "The same type": type-id equality in typecheck's interned type table after
  the substitution. For a type parameter that means the same parameter (the
  slot `T` of `Optional<T>` at `T?` in a generic body is the body's `T`, and
  an operand `&T` is not it); a reference is never its referent; an erased
  value is its erased type (`any Trait`, `Box<any Error>`: the `Erase`
  adjustment has already produced that type before the aggregate); a
  `sendable` function and the plain function type are made one by the
  `ForgetSendable` conversion before the aggregate, so they compare equal.
  A constant operand is typed by its `Adopt`. No other leniency was needed:
  nothing on main trips it (3.3).
