## Description

Unit C of SL-209 (ownership uniformity). Plan step 5. Depends on Units A/B. SEQUENCE AFTER SL-208 lands (see note).

## Preserve the contract through compiler transformations
Place lowering, generic specialization, closure conversion, and coroutine lowering change expression shapes. Each transformation must EITHER:
- preserve an existing ownership decision and remap its source identity; OR
- introduce a new transfer that goes through the same checking operation.

Use design 266's `admit_declarations` path (`sawc/sawc.py:1183`) for generated declarations, while VERIFYING that it also covers newly generated transfers. Rechecking must not consume a source twice or add a second retain. Generic specialization must RESOLVE deferred requirements (Unit A's "generic copy requirement awaiting specialization") rather than blindly reuse decisions tied to an abstract type or another instance.

## Acceptance
Sync and suspending versions have equivalent ownership behavior; repeated compilation does not accumulate ownership annotations or cleanup actions (ties directly to the irdet/reemit determinism gates — a decision that is re-stamped per compile would break byte-identity).

## Sequencing note
This unit touches the coroutine-transform lowering path, which is exactly where SL-208 (DF-300e, cross-module frame materialization / token propagation) is being fixed right now. Land SL-208 first, then build this unit on top so the two do not fight over the same frame-materialization seam.

Requested changes on patch SL-212.p1 (revision 1)

Review of SL-212.p1 revision 1 (base ee3c0f16, applied ee8438fc): request changes.

Two demonstrated false negatives remain in the preservation engine. These concern what the optional audit proves today, not SL-214's later decision to make it mandatory.

P2 — Check preservation per cloned occurrence, not only per instance body (preservation.py:257-258).

P1a skips an instance as soon as ANY decision remains in it. P3 then iterates only over surviving decisions. Consequently, losing an individual unstamped transfer decision is invisible. The independent review compiled V91, restored the untouched AST, then removed ALL records for one live NoneLiteral in a monomorphized `init`: its action was `take`, destination `struct field`, and its origin still had a template decision in the ledger. Other decisions in that instance remained. The audit still returned ok=True with zero findings; live decisions fell 10230→10229, antecedents 2214→2213, and all 40 stamps remained reconciled. This is exactly a cloned occurrence whose re-derived decision was lost, despite the whole-instance zero-decision test passing.

Please reconcile each live cloned occurrence with its judged origin, requiring its own decision or an explicit legitimate discharge. Add a negative test deleting a single unstamped take/move decision while leaving its sibling decisions intact; dropping an entire instance's records is insufficient coverage.

P2 — Reconcile required annotations in the reverse direction too (preservation.py:274-278).

The audit only considers annotations that are still true. Clearing a required annotation makes the obligation disappear from its input set even though the ledger still requires it. I independently compiled this source through a run_codegen spy:

```saw
struct Counted { n: Int }
extension Counted: Copy {
    func copy(&self) -> Counted { print("copy {}", self.n) Counted(n: self.n) }
}
enum Bad { case Nope }
extension Bad: NoCopy {}
func make() -> Result<Counted, Bad> { Counted(n: 7) }
func main() {
    let r = make()
    let got = try! r
    print("got {}", got.n)
}
```

Immediately before codegen, main's TryExpr has payload_needs_copy=True and a `copy`/`retain-source`/`let binding` decision. The audit is clean. Clearing ONLY payload_needs_copy and auditing again still returns ok=True with zero findings, but the emitted program now prints only `got 7`; the unchanged control prints `copy 7` then `got 7`. The audit certifies a program that no longer executes the checker's copy obligation. This is the required Ok-path retain from SL-211, not a speculative annotation.

Please check that live decisions requiring a retain still have their appropriate lowering representation, or an explicitly verified replacement. Pin loss of payload_needs_copy and needs_copy separately; a nonzero aggregate stamp count cannot catch a single dropped obligation.
