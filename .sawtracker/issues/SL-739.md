**sawc2 has no lowering for `lends` (`syntax.expr.lends`), the borrowing-struct initializer argument.** This is the one blocker for `Vector.iter` (SL-703; 33 corpus programs, Blade's `for x in v.iter()` loops among them).

**Evidence (SL-703's second probe, scratch `.build/scratch/s703iter/`).** A user copy of Stage 0's `Vector.iter` design: a `borrows struct BagIterator` with a shared `&Bag` field and an index, a plain `Iterator` with `Item = Int`, and `for x in bag.iter()` (with `iter` building `BagIterator(source: lends self, index: 0)`). Stage 0 builds and runs it (`total = 10`), plain and with `yield_now()` inside the loop. sawc2 (`--std-root std`) gives exactly one error, at the initializer: `slice.not-yet: syntax.expr.lends is not in the bootstrap slice yet`. The `borrows struct`, the conformance and the `for` head all pass.

**Scope (Opus):**
- Lower `lends self` (and `lends <place>`, if the spec allows other operands) in a borrowing struct's initializer, with the loan it creates: shared, rooted at the lent place, and live as long as the borrowing struct value. Tie it into borrowck's existing borrowing-struct rules and into the coroutine frame, since a borrowing struct can live across a suspension, as probe (e) does.
- One funnel that names its entry points; the position matrix: the operand (self, a local, a field), the holder (local, returned, passed), and suspension (none, inside the loop, across the loop).
- Pins: the probe pair as run programs matching Stage 0, plus refusal fixtures for an exclusive use of the root while the iterator is live.
- Then SL-703 phase 2 ports Stage 0's `Vector.iter`/`enumerated` as they are (`T: Copy`, which is Stage 0's bound).

Separate from SL-738, which is the spec-planned `LendingIterator`/`for borrow`, not on the parity path.
