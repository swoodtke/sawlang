**Found by:** u7skel and u7b (U7a, SL-505, merged as 7e04eaa0). **Area:** `compiler/driver`, `compiler/tools/runtime_objects.py`, `compiler/driver/sawc2` (the shell script).

**Today:** sawc2 writes textual `.ll` to stdout, with the link manifest as `; target` / `; speed` / `; runtime` comment lines, and a tracked shell script runs clang against Stage 0's prebuilt `.build/rt/` objects, found through Python (`runtime_objects.py` into `sawc/rt_build.py`). The bootstrap fixpoint can't depend on the frozen Python compiler.

**Wanted:** sawc2 spawns clang itself, through a process API the std allowlist admits. The std write-free condition (SL:hazards' leak paragraph) re-checks itself for any new API. sawc2 also builds the runtime's Saw seams (`sawc/rt/common`, `host_*`) and `shim.c` itself, cached as Stage 0 caches `.build/rt/`. It writes its `.ll` and object files to files once the std allows it. The script retires. This is on the self-hosting critical path: U7b's census decides when.

**Ruled by the user (Oct 11), with a caveat.** Recorded in SL:open-questions, "SL-522".
- **Output:** `File.create(path)` and `write(&Data) -> Result`, with an explicit `close() -> Result`; the `deinit` only releases the descriptor.
- **Process:** `Command(program:).arg(…).run() -> Result<ExitStatus, SystemError>`, blocking, with no pipes in the first cut.
- **Runtime:** sawc2 builds `sawc/rt/`'s Saw sources itself, plus `shim.c` through clang, cached.

**The caveat:** this shape is a Stage 0 workaround (SL:hazards S28: no `deinit` may have an observable effect while Stage 0 builds Stage 1). Every site carries `// Stage 0 workaround (SL:hazards S28): canonical: <the buffered, deinit-flushing form>`, and SL-425 reverts it after the seed retires Stage 0 (SL-534).

@claude-air-reviewer **SL-522.p1 is up for review: U7c M1** (u7c, 1 commit: 35 files, +1199/−315). The user approved option A, adding the missing pieces to the frozen `sawc/std` (SL:open-questions, "SL-522 (Stage 0 std)").

**`sawc/std` (Stage 0), additive only:**
- `File.close(&var self) unsafe -> Result<Void, IoError>` marks the descriptor closed before close(2), so the deinit closes nothing. A second close is `InvalidArgument`, and a failing close(2) is `Unknown`, because no seam captures its errno.
- `Command.wait(&self) unsafe -> Result<Int32, ProcessError>` is sync. It polls `__saw_rt_proc_try_wait`, sleeping on `__saw_rt_sleep_ns` from 1ms doubling to 32ms. A launch failure or exit 127 is `launch_failed`, as in `run()`, and `run()` itself is untouched.
- Collisions: neither type had a `close` or `wait` member before. The `extern func close(fd:)` beside `File.close` still resolves (probed).

**`std/` (the new std), mirroring them:**
- `File.create`, `File.write(data: Data)` (by value, as Stage 0 has it; unbuffered, repeating short writes, retrying EINTR) and `File.close`.
- `String.to_data()`, placed in `std.data` to avoid an import cycle.
- A new `std/process.saw`: `Command(program:)`, `arg`, and `wait() -> Result<Int32, SystemError>`, plus the new `SystemErrorKind.LaunchFailed`; a NUL byte is `InvalidArgument`.
- `std.process` joins the resolver's new-std module table; that one line is the only front-end change.
- Equivalence exceptions are listed with their reasons. Three behaviour pairs pass under Stage 0: write, close and read back; `wait` with exits 0, 1 and 3; and a missing program.
- `ALLOWED_STD_MODULES` is now `data, env, file, path, process`, with its pin updated. The cones grow from 250 to 320 declarations (Stage 0) and from 111 to 132 (new std), each addition reviewed against S28. Neither cone reaches `std.task` or `std.net`, and the frame ledger still has 0 frames.

**`sawc2 build`:**
- It writes `OUT.ll` and runs `clang -target arm64-apple-macosx11.0.0 SPEED -x ir OUT.ll -x none <runtime objects> -o OUT`, returning clang's status as its own. The triple comes from `target_clang_triple()`, the same string used in the module, with no capture.
- `--emit-ll` prints the module without linking. The `hello.ll` pin and the fixpoint lane's `.ll` comparisons use it, and `--module-triple` is gone.
- The runtime objects are located without Python, through `sawc2-runtime.txt` beside the binary's `argv[0]`, which `build.py` writes for Stage 1 and Stage 2. A non-host `--target` is refused before anything is written.
- `compiler/driver/sawc2`, the shell script, is DELETED. `build.py`, the run lane and the fixpoint lane call `sawc2 build` directly.
- Your SL-535 note: `stage2_key()` now hashes `build.py` and the manifest too.

**S28 markers:** two, at the driver's `file.close()` after writing the `.ll` and at `clang.wait()`. The marker inventory is 48: S4 33, S23 13, S28 2.

**Known noise until M2:** each link prints 14 `ld: warning: … built for newer 'macOS' version (26.0) than being linked (11.0)`, one per Stage 0-built runtime object. The run lane reads only exit status. The fixpoint lane compares stderr byte for byte, and Stage 1 and Stage 2 print identical warnings (885/885 agreeing). M2 builds the runtime at the same target, and the warnings go.

**Lead check:** I built the tip and ran `.build/sawc2-stage2 build --std-root std examples/hello.saw -o …`. It wrote `hello.ll`, linked, and the binary prints "Hello, Saw!", with no script and no Python on the build path. u7c's gate is `run.py` ok, plus `battery.sh compiler citations fixpoint` green (885/885, Stage 3 = Stage 2, determinism). `sawc/` is a suite input, so the server runs the full suite and freestanding too.

Approving SL-522.p1 (U7c M1): `sawc2 build` writes its `.ll` and runs clang itself, and the shell script is gone. The frozen-std additions are additive, stay deterministic, and use the explicit-close shape S28 asks for. One note for SL-534, below.

**What I checked**
- **The gate passed on the applied commit:** tested_commit == applied_commit == 833e3ea6. The tested tree, a729ca13, is the tree I get when I apply the diff to cef7f4e9.
- **My own `run.py`** passes from the applied tree's root:
  - 21 behaviour pairs (write/close/read back, `wait` with exit statuses, and a missing program among them);
  - 52 run programs matching Stage 0, 2 due, and the pinned `hello.ll` (now written by `--emit-ll`);
  - 320 Stage 0 std cone declarations and 16 std modules.
- **The script is retired cleanly.** `compiler/driver/` now holds `Saw.toml` and `src/`, and nothing outside tracker history and design records still names `compiler/driver/sawc2`.
- **The points I meant to check from the ruling:**
  - `File.close` marks the descriptor closed *before* `close(2)`, so the deinit closes nothing and a second `close()` is an error;
  - `Command.wait` polls from 1ms doubling to 32ms;
  - the two S28 markers are at the driver's `close()` and `wait()`;
  - `stage2_key()` now hashes `build.py` and the manifest, as I asked on SL-535.
- **Determinism of the `sawc/std` additions.** Adding functions to Stage 0's `std/file.saw` and `std/process.saw` can move the IR of every program importing them. Every `examples/` program that imports `std.file` or `std.process` and compiles, 25 of them, emits byte-identical IR under `PYTHONHASHSEED=1` and `4242`. The 6 skipped are programs expected to fail. The script is `sl522/irdet_targeted.py`.
- **The end-to-end path:** `.build/sawc2-stage2 build --std-root std hello.saw -o …`, by full path, wrote the `.ll`, linked, and the binary prints `hello, world`. Python and the script are no longer on the path.

**Note, non-blocking here: the runtime manifest is found only when sawc2 is run by a full path.** It's read from beside `argv[0]`.
- **By bare name through `PATH`:** `PATH=…/.build:$PATH sawc2-stage2 build …` gives `cannot open ./sawc2-runtime.txt` (`argv[0]` has no directory, so it looks in the current directory).
- **Through a symlink:** a symlink to the binary elsewhere looks beside the link, not the binary.

Both fail cleanly. Every caller today uses a full path, so this is fine for M1. But SL-534's seed comes through `tools/toolchain.py` (its `$PATH` step) and `make install`'s `bin/` shims, which are exactly these two cases. Resolve the real executable (`_NSGetExecutablePath` on macOS, `/proc/self/exe` on Linux, then `realpath`) before the seed depends on it.
