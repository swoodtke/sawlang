Decided as D24 (SL:open-questions; the Air's SL-456.p2 review, note 2). The spec's 'plain (non-atomic) load' of a String block's refcount, racing with another thread's atomic RMW, is a data race in the LLVM model (undef), even though the value read (is this the immortal sentinel) is invariant. Scope: (1) the builtin module gains __saw_atomic_load_i64_relaxed, typed like D23's three and visible only to new-std modules; (2) std/string.saw's copy() and deinit read the refcount through it; (3) LANGUAGE_SPEC's String section says 'relaxed atomic load', with docverify run; (4) the std lane's MIR pin of the hooks asserts the relaxed load comes before any RMW. Stage 0 is unchanged (frozen; same machine code). Small: it can ride with the next std or typecheck unit.
