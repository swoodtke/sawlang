**Implementation detail (lead, Nov 12; a stretch item this week): half done; the open half, `$0`, gets a short design pass (Opus) and is then one or two Sonnet units.**

**Status.**
- **`FuncPointer` (L3): DONE** by SL-940 and SL-848 (the freestanding suite's `func_pointer_table.saw` runs). Step 1 of the unit re-runs this issue's four acceptance cells (c1: a `FuncPointer` taking and returning `UnsafePointer<T>?`, `FuncPointer<F>?` as an `extern "C"` parameter and result) and ticks or re-files each.
- **Shorthand closure parameters, `$0` (L2): OPEN.** GRAMMAR.md keeps the production (`syntax.expr.shorthand-param`, status current, spec "Functions"), resolve refuses it as `slice.not-yet` (`compiler/resolve/src/walk.saw`, the `Expr_ShorthandParam` arm), and 23 corpus programs are refused on it, the largest single refusal group in `corpus_diff.tsv`.

**Why a design pass.** A shorthand parameter makes a closure's parameter LIST implicit: the count is the highest `$n` used, discovered from the body, before the closure's type is known. The pass decides:
1. **Where the parameters come from:** resolve synthesizes the closure's parameter declarations when it meets the closure (it must scan the body for `$n`, not descending into nested closures, which own their own); what an unused lower index means (`{ $1 }` has two parameters); mixing a written parameter list with `$n` (refused: which rule); `$n` outside any closure (refused).
2. **Typing:** each `$n` takes its type from the expected function type, exactly as an unannotated written parameter does; with no expected type the refusal is the existing one for an unannotated parameter.
3. **Known hazard positions** (SL:hazards L2; SL-38 and SL-41 are Stage 0's bugs there): a `$n` inside a `try` operand, inside a trailing closure, inside an interpolation hole, as a call's receiver, under `&`/`&var` (is `&var $0` legal? the spec says), captured by a nested closure (refused or allowed? the spec says).
4. **Everything after resolve:** if resolve presents a shorthand closure exactly as a closure with written, unannotated parameters named `$0`…`$n`, typecheck, MIR and later stages need no change. Prove it or list what does.

**Census first** (`.build/scratch/p828d/` of the main checkout): the 23 refused corpus programs, each with the `$n` positions it uses and what else it would be refused on next; the spec's "Functions" text on shorthand parameters quoted in full, with OPEN where it is silent.

**Deliverable:** one comment here with the design, the position matrix with fixtures (`compiler/tests/resolve/` and `compiler/tests/typecheck/`), the corpus rows expected to move to `pass` and those that will meet another gap, and the cut into Sonnet units.
