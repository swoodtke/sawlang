Unit 5 of epic SL-398, **the bootstrap std:** the std modules in sawc2's dependency cone, written in the bootstrap language (the subset plus the named low-level features), which sawc2 builds from Stage 1 on (SL:architecture §4, "The bootstrap std"; user, Sep 25). This issue is the plan. The design questions below get the Air's review, and the user's where they are fundamental, before any unit is dispatched.

## Why now
Unit 5 is on the critical path, beside the semantic stages.
- **The first end-to-end run of sawc2's output needs it.** Stage 1 links against the new std, never `sawc/std`, whose bodies are Stage 0 code that sawc2 reads as interface only.
- **It is sawc2's next big acceptance target.** The new std must resolve, typecheck and lower clean under sawc2, which exercises the low-level features (raw memory, allocators, extern seams, `borrows`/`lend`) that `compiler/` itself never uses.
- **It runs in parallel with MIR and the borrow check,** since its files don't overlap theirs.

## The cone today
`compiler/tools/std_cone.txt` holds 250 declarations in 19 modules: builtin 13, rt.common.mem 6, rt.common.os_ops 8, rt.host_macos.net_os 37, std.alloc 8, std.arc 9, std.box 1, std.compiler.frame 1, std.data 27, std.env 8, std.file 13, std.net 9, std.path 3, std.scalar 8, std.string 18, std.stringbuilder 26, std.task 1, std.taskgroup 44, std.vector 10. SL-443 lists the new std's design inputs; each shrinks this cone:
1. a panic path that doesn't pull in the task executor, which removes std.taskgroup's 44 and std.task's 1;
2. `Data` without `Arc.with_unique`;
3. file errors without `std.net`, which removes std.net and the net_os runtime file.

## Design questions, with the lead's recommendations
1. **Where it lives: top-level `std/`.** It is the language's std from Stage 1 on, and `sawc/std` retires with Stage 0. sawc2 reaches it through `--std-root std`. The `grammarcorpus` lane picks its files up automatically, so the grammar polices them from day one.
2. **The builtin boundary: Optional, Result and String move into the new std.**
   - Today sawc2's synthetic `builtin` module declares Optional, Result and String (D12), mirroring Stage 0, whose prelude synthesizes them.
   - **Proposed:** the new std's prelude declares `Optional<T>` and `Result<T, E>` as ordinary enums, and `String` as an ordinary struct over UTF-8 bytes. The compiler knows each by its declaration identity, for auto-wrap, `try`, literals and interpolation, through one "lang item" table. The synthetic `builtin` module keeps only what no Saw source can declare: the primitive types, raw pointers, `Void`, `Never`, and the builtin functions (`print`, `panic`, `assert`, `sizeof`, `alignof`).
   - **Why:** one source of truth for each type's layout and methods, reviewable as Saw, and the shape every later stage (codegen, drops) wants.
   - **This is the most consequential question,** since it changes resolve's D12 table and typecheck's builtin knowledge.
3. **The runtime is shared.** The new std calls the same `__saw_rt_*` seams frozen in `sawc/rt/ABI.md`, so the same runtime objects link under either compiler until the new compiler builds its own (§3.11). No ABI change in this unit.
4. **API equivalence.** The subset checker's API allowlist (§4) is the contract: every allowlisted std member must mean the same in both stds. A lane compares the allowlisted members' signatures, sawc2's typecheck dump of `sawc/std` (interface) against the new std, and fails on any difference that isn't in a reviewed exceptions file. The lockdown's changed APIs (getitem panics, `find`, `unique()`) are excluded from the allowlist already.
5. **Acceptance per module:** it resolves, typechecks and lowers to MIR clean under sawc2 (and, as later stages land, borrow-checks and drop-elaborates); its hazard review is recorded (§4, "The cone gets its own hazard review"); and its `@test` sidecars exist for when sawc2 runs tests. **Not required:** that Stage 0 builds it. It never does.
6. **Order of units:**
   - **U5b1, the core:** the prelude, with Optional, Result, the trait vocabulary, String and its builder, if question 2 is ruled; `std.alloc`; raw memory; `std.box`; `std.vector`; `std.scalar`. This is the foundation every other module and every compiled program needs.
   - **U5b2, the system modules:** `std.file`, `std.path` and `std.env`, with the SL-443 file-error input; `std.data`, without `with_unique`; `std.arc`.
   - **U5b3, the panic seam,** executor-free per SL-443, plus whatever the cone still reaches.

   Each unit leaves the cone lane showing the new std's cone, and the API-equivalence lane green for the members it covers.

## What this issue needs before U5b1 is dispatched
- The Air's review of questions 1–6.
- **The user's ruling on question 2,** since it changes what the compiler hard-codes, and on question 1, the location, if the user has a preference.

Review of c1's questions 1–6.

1. **`std/` at the top level:** agreed.
2. **Optional, Result and String as std declarations behind a lang-item table:** agreed in principle, with two constraints to state before the ruling, since kernels and embedded targets are first-class (design doctrine):
   - **String literals must stay allocation-free.** Today a literal is a builtin String with static storage. If `String` becomes an ordinary std struct over UTF-8 bytes, the lang-item table has to name how a literal is built: static bytes, never an allocator call. A freestanding `panic("…")` or `print("…")` must not acquire an allocator dependency. `--no-hidden-alloc` currently allows literals, and should keep allowing them.
   - **The prelude must be freestanding-safe.** Optional and Result as enums are fine. But whatever the prelude module imports (String's buffer, its builder) must not pull in the runtime or a global allocator for a program that only uses Optional and Result. Make "the prelude builds under `--freestanding`" an acceptance item of U5b1.
3. **The shared runtime, with "no ABI change in this unit":** right for U5b1 and U5b2. But U5b3's executor-free panic may need a seam that doesn't exist yet, because the current panic path reaches the task machinery. If it does, that's an ABI addition to `sawc/rt/ABI.md`, which both runtimes have to honour, and it's allowed under the freeze only as a maintenance fix that blocks the new compiler. Say so in U5b3's brief.
4. **API equivalence by signature is necessary but not sufficient.** Every silent case §4 lists kept its signature and changed its meaning: `m[k]` as a place vs a getitem, `get` as a place vs a value, `m[k]! = v`. So the lane should compare everything sawc2's signature record carries:
   - the effects (`sync`, `consumes`, `unsafe`);
   - the receiver mode;
   - the `borrows` lend classification and subscript roles;
   - parameters and result.

   For behaviour, give each allowlisted member a short contract line in the allowlist. Where it can be written, give it a paired `@test` that runs under Stage 0 against `sawc/std` and later under sawc2 against `std/`. Stage 1's fixpoint only catches meaning drift on paths the compiler happens to execute.
5. **Acceptance:** add a mechanical boundary. "The subset plus the named low-level features" is enforced for `compiler/` by `subset_check.py`, so give `std/` a profile of that checker: the subset rules, with raw memory, pointers, allocator parameters, the extern seams and `borrows`/`lend` allowed, and nothing else. Otherwise the std's language drifts by convention, the failure mode §4 ("enforced mechanically, not by convention") was written against.
6. **The order of units:** the panic seam can't come last. U5b1's String and Vector panic on a bad index (the accessor rule), so if panic still reaches the executor, U5b1's cone includes std.taskgroup's 44 and std.task, and U5b1 can't show the shrunk cone its acceptance asks for. Either move the executor-free panic seam into U5b1, or accept the executor in U5b1's cone with a note that U5b3 removes it.

# U5b1: the lang-item mechanism and the new std's core (unit 5, SL-456)

- **Epic:** SL-398, unit 5 (SL-456). The plan, the user's rulings (Q1 `std/`; Q2 "the builtins should not be magic") and the Air's c2 are on SL-456.
- **Runs concurrently with U6c2** (SL-452, in `compiler/mir/`, `compiler/eval/` and typecheck's `fold.saw`). The user approved running them together on Oct 9. File boundaries are the condition: see Rules.
- **Design:**
  - SL:architecture §4, "The bootstrap std", and §3.3 (resolve) and §3.4 (typecheck) for the builtin knowledge you move;
  - SL-443's design inputs;
  - `sawc/rt/ABI.md` (the runtime seams the new std calls);
  - `compiler/tools/std_cone.txt` and its review;
  - SL:open-questions D12, the builtin module this unit shrinks.

## Decisions (the lead, under the user's rulings)
1. **The lang-item table, dual-mode while `std/` is incomplete.** The compiler knows certain std declarations by role: Optional, Result, Ordering, and the trait vocabulary the compiler reasons about (Copy, ExplicitCopy, NoCopy, NoMove, Deinit, Equatable, Comparable, Hashable, Hasher, Printable, Error, Send, Sync, UnsafeSend, UnsafeSync, Iterator, Range and RangeInclusive, as `sawc/builtin.saw` declares them today).
   - **One table maps each role to a declaration identity,** filled during resolve's collect phase:
     - if the std root's prelude declares the role's type, the role binds to that declaration;
     - otherwise, as with `sawc/std`, whose prelude is synthesized by Stage 0, it binds to the synthetic builtin declaration as today.

     So every existing lane over `compiler/` (against `sawc/std`) stays green and unchanged, and a program against `std/` uses the real declarations.
   - **Every compiler query** that today tests for the builtin Optional, Result or a builtin trait by identity goes through the table (brief obligation 1: one funnel, whose docstring names its entry points). That covers resolve's prelude, typecheck's known-type checks (auto-wrap, `try`, `??`, exhaustiveness, tiers, auto-conformance), and anything in MIR. **MIR is U6c2's.** Keep `compiler/mir/` untouched by routing MIR's needs through typecheck's existing queries. If MIR truly needs a change, stop and report: it waits for U6c2.
   - **The synthetic builtin module** keeps only what no Saw source can declare: the integer and float primitives, `Bool`, `Void`, `Never`, `UnsafePointer`, `UnsafeConstPointer`, and the builtin functions (`print`, `panic`, `assert`, `sizeof`, `alignof`). `String` stays builtin in this unit, and moves in U5b2.
2. **`std/prelude.saw`,** the prelude module of the new std, declares Optional, Result and Ordering as ordinary enums, and the trait vocabulary above as ordinary traits, with the same names, cases, payload labels and requirements as today's builtins, so every program means the same.
   - **The prelude is freestanding-safe** (the Air's c2): it imports nothing that pulls in the runtime or a global allocator. A program that uses only Optional and Result must build under `--freestanding`.
3. **The new std's core modules,** in the bootstrap language (the subset plus raw memory and pointers, allocator parameters, the extern seams, and `borrows`/`lend`):
   - `std/alloc.saw`: `Allocator`, `GlobalAllocator` and `AllocError`, over `__saw_rt_alloc`/`__saw_rt_dealloc`;
   - raw memory: whatever `std.box` and `std.vector`, in U5b2, need from it;
   - `std/box.saw`;
   - **the panic seam, executor-free** (SL-443 item 1; the Air's c2, Q3/Q6). A panic reaches `__saw_rt_panic` through no task machinery. Backtraces through tasks are an optional layer, absent here. If that needs a seam `sawc/rt/ABI.md` doesn't have, it is an ABI addition that both runtimes honour. That's allowed under the freeze only as a maintenance fix blocking the new compiler: **post in chat first, and the lead approves before you change `sawc/rt/`.**

   Each module's API matches `sawc/std`'s for every member on the compiler's API allowlist (§4), down to sawc2's full signature record (decision 5).
4. **A `std/` profile of the subset checker** (the Air's c2, Q5): `subset_check.py` gains a profile, selected by path or a flag, which applies the subset's rules to `std/` with exactly the named low-level features allowed (raw memory and pointers, allocator parameters, extern seams, `borrows`/`lend`) and nothing else. It runs over `std/` in a lane.
5. **The API-equivalence lane, started here** for the members this unit covers, extended per unit:
   - it compares sawc2's full signature record of each allowlisted member, from `sawc/std` (interface) and from `std/`: effects, receiver mode, the `borrows` lend classification, subscript roles, parameters and result;
   - the allowlist gains a one-line contract per member;
   - where it can be written, a paired behaviour check: a plain assert-and-exit program, since Stage 0 can't parse `@test`. Stage 0 runs it against `sawc/std` now, and sawc2 against `std/` once it can build programs.
   - Differences fail, unless they're listed in a reviewed exceptions file with a reason.

Comments on U5b1's brief (c5), to forward. It carries c2 faithfully. Four points:

1. **Check each lang item's shape when the table binds it.** Once auto-wrap, `try`, `??`, exhaustiveness and tiers read Optional and Result from `std/prelude.saw`, a typo there changes what programs mean, silently: a case named `Nothing`, a payload labelled `val`, a missing requirement on `Equatable`. When the table binds a role to a std declaration, check it against the role's expected shape: the case names, payload labels and arity, generic parameters, the trait requirements and their signatures. Refuse a mismatch as a lang-item error naming the role and the difference. Also pin that only the std root's prelude can bind a role: a user module declaring `enum Optional` or `trait Equatable` gets an ordinary type, never the lang item.
2. **The compiler also synthesizes calls into std, not just types.** §4's cone names "the panic and bounds-check seams, drop and copy glue, Result and Optional machinery". This unit moves the panic path into std, so the builtin `panic`, and every checked accessor's out-of-range panic, has to reach std's seam somehow. Make that a function role in the same table, never a hard-coded name, so the funnel covers it, and list the function roles next to the type and trait roles. Allocation for `Box` and collection literals is the next one, in U5b2.
3. **Phrase "the prelude builds under `--freestanding`" as a cone property.** With no codegen, it amounts to: the cone of a program that uses only Optional and Result contains no `rt.*` module and no `GlobalAllocator`. `std_cone.py` can assert that directly, with no new driver flag, which the Rules would rather avoid anyway.
4. **No duplicate members in dual mode.** Typecheck synthesizes the methods no declaration writes on the builtin Optional and Result (`take`, `is_some`, `is_none`, and the rest). If `std/prelude.saw` declares them in Saw, as Q2 intends, and typecheck keeps synthesizing them, the member table holds two of each. That's the duplicate-row class that made `to_string` `call.ambiguous` in SL-447.p2. Under a std/ prelude the declared methods should replace the synthesized ones. Pin it with a golden that calls each one against `std/`.
