## Description

A shift count that names a static declared AFTER the shift (`x << LATE`, with `static LATE: Int = 64` below the use) builds and panics at run time, where it should be refused (`constant.shift-range`). The count folds before `LATE` is typed. Found by p757 (SL-757), which deferred the constant-cast check to after every body is typed for the same reason. Fix: defer the shift/divide funnel's constant judgment the same way, then sweep its other constant checks (divide by zero, `[T; N]` length, `static_assert` through a later static) per obligation 4.

**SL-760.p1: one pending-constant funnel. Summary for review.**
- **The mechanism:** SL-757's cast list is generalized into `TcPendingConstant` (`model.saw`: Cast, CertainFault, SlotRange and Position entries), judged in order by `judge_pending_constants` once every body is typed. The funnel is `defer_constant`, with entry points `cast_expr`, `check_certain_fault`, `check_constant_range` and `check_constant_position`. Casts are always held. The others are held only when the fold stops at a node no body has typed yet (`awaits_typing`), so no existing refusal or golden moves.
- **Now refused when the operand is declared later** (each built before, and ran, panicked or printed a wrong value):
  - the shift count;
  - a divisor;
  - an integer slot or argument (`Late.Big` at `UInt8` printed 44);
  - a flag combination;
  - a default parameter value;
  - a body `static_assert` (which was ignored);
  - a top-level `static_assert` over a static in a module checked later.
- **Already correct, or order-free:** a same-file top-level `static_assert`, the integer cast, and `[T; N]`/repeat/const-generic (refused for any static).
- **Not deferred, on purpose:** a static's initializer naming a later static. That is the spec's forward-reference rule, which sawc2 lacks (`errors/static_forward_reference`, already `wrong`). Side effect: `static A = 1 << B`, with `B = 64` declared later, is refused as a shift fault.
- **Fixtures:** six `*.declared-later` refusals (one is a two-module case) and the control golden `constant_declared_later_controls`.

Approved patch SL-760.p1 (revision 1)

**Air: SL-760.p1 r1 approved; arming it.** `defer_constant` is one held list for the four constant judgments: Cast always, and CertainFault, SlotRange and Position only when the fold `awaits_typing`. It is judged once every body is typed, each judgment in its own module, so a check met before its static or case is typed no longer slips through. A static's initializer is rightly left out, since it names only the statics above it.

**Probes** (`air-review/sl760/`; on b45a88d5c = main + r1, both stages rebuilt):
- **A later mutable static isn't folded:** `1 << SHIFT` with `unsafe static var SHIFT: Int = 70` declared after the use, lowered to 3 at run time, prints `8` in both compilers.
- **Controls, all declared later:** generic `1 << SMALL`, a closure `{ 1 << SMALL }`, a passing body `static_assert(SMALL < 8)`, `Code.Mid as UInt8` (200 at a `UInt16` backing) and `100 / DIV` print `8 8 200` / `14`, identical to Stage 0.
- **Refused when declared later:** a body `static_assert(LIMIT < 10)` with `LIMIT = 12` (`static_assert.failed`, as Stage 0); generic `1 << BIG` with `BIG = 64` (`constant.shift-range`); and a closure `{ 10 / NONE }` with `NONE = 0` (`constant.divide-by-zero`).
- **A later static whose own initializer is refused** (`static WIDE: UInt8 = 300`, then `1 << WIDE`): one refusal at the initializer (`type.mismatch`, as Stage 0), with no second one at the use site.

**Where sawc2 is stricter than Stage 0, by the spec:** Stage 0 builds the generic-body shift and the closure-body divide and panics at run time, and it does so with the statics declared EARLIER too (`generic_early.saw`). sawc2 refuses both in both orders, which is the spec's rule ("a shift count that is a literal, a `static`, or a constant expression over those … is refused beside a run-time value", Integer Arithmetic → Constants). The patch only made that order-independent.
