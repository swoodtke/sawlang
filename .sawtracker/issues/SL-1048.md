**User ruling (Nov 10, SL-1044 F1):** the executor's frame seam is std-internal, not public API. `std.taskgroup` declares `public enum Poll`, `public struct TaskContext` (the task's park and cancel words as `UnsafePointer` fields) and `public struct FrameDescriptor` (a frame's size and alignment plus `unsafe sync` resume and drop function pointers). User code can import all three today. `.build/scratch/probe_poll_import.saw` builds `import std.taskgroup.{Poll, TaskContext, FrameDescriptor}` and runs, and the struct-tier rule makes the fields public too.

Exposing them would freeze the frame layout and the resume signature as an ABI that nothing is designed around. A custom-executor story (a kernel or embedded runtime driving frames itself) would be a design of its own that decides what to expose.

**Expected:** the three types are unreachable from user code (`public(package)` within std, or the equivalent), while the compiler-emitted frames and std's executor keep using them. Sweep first:
- every std module and every runtime package (`[package] runtime = true`) that names them;
- whether the compiler resolves them by name in a way a narrower tier breaks;
- `tests/corpus/user_enum_poll_coexists.saw`.
