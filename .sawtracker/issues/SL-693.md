## Description

**A seed bump no longer fits sawtracker's 8 MiB patch request.** Found on SL-662.p2.

A seed bump replaces all three targets' compressed IR, about 1.85 MB per driver `.ll.xz`, and none of it deltas. `git diff --binary` writes a changed binary twice, once forward and once reversed, so SL-662.p2's full diff was 14.36 MB. It went up forward-only (7.27 MB, verified to apply exactly), with under 1 MB of headroom. The compiler's IR grows with every unit, so a future bump won't fit even forward-only. SL-663 fit only because its files were new.

**Options, to decide with the user:**
1. **Binary hosting** (SL-663's deferred option A): seeds as release artifacts fetched by `tools/toolchain.py`; the repo commits only the pin and a hash.
2. **Raise sawtracker's cap,** or let a patch carry binary attachments: a sawtracker feature, for the sawtracker lead.
3. **Shrink the seed:** strip debug metadata and names from the seed IR, emit the seed at a smaller optimization level, or use a stronger xz preset or dictionary. Measure each and check the self-reproduction check still holds.
4. **Split a bump across patches:** not per target (the seed check needs every target to match one pin), but perhaps files first and pin second. That needs the check to tolerate it.

**Owed now:** measure option 3's savings. It's cheap and may buy several bumps of headroom.
