**The remote test worker can't fetch the seed once SL-694 lands.** Found by SL-694's consumer sweep (agent s694seed), unverified by a worker run.

SL-694 moves the seed's `.ll.xz` files out of git; `compiler/tools/build.py` fetches them from https://blobs.sawlang.com/ by SHA-256 into `.build/blobs/`. The remote worker (`tools/remote_battery.py`, design 160) runs each job in a fresh directory under `tools/test_worker.sb`, whose profile allows outbound connections only to localhost. A job that builds sawc2 (`compiler/tests/run.py`) then fails at the fetch.

**Two fixes:**
1. **Carry `.build/blobs/` in the job snapshot (recommended).** It keeps the sandbox closed, and it's safe because the funnel re-hashes every cached blob on each read, so a wrong or stale copy is refetched or refused, never used.
2. Open outbound HTTPS to blobs.sawlang.com in the profile.

**Done when:** a remote job builds sawc2 from a fresh directory with no network.

SL-696.p1 submitted (the recommended option; the worker's sandbox stays closed).

- **`build_snapshot`** (`tools/worker_proto.py`): after packing the tree, it reads the snapshot root's `compiler/seed/manifest.tsv` through `build.seed_manifest`, gets every named blob through `build.seed_blob` (so a blob the client lacks is fetched, and a corrupt cached one is refetched, by the one funnel), and adds exactly those as `.build/blobs/<sha256>` with normalized metadata. Nothing else under `.build/` travels. A blob the client can't produce raises `SeedError` naming the file, which `worker_client.snapshot` turns into `(None, why)`, so no snapshot goes out without its seed. The worker side is unchanged: the funnel re-hashes every cached blob on read.
- **A fix found on the way:** snapshots were not byte-identical. `tarfile`'s own `w:gz` mode stamps the current time into the gzip header (the old comment claiming `mtime=0` was wrong), so the existing self-test passed only when both snapshots fell in the same second. The `GzipFile` is now built with `mtime=0`.
- **Pins** (`tools/test_worker_snapshot.py`): exactly the manifest's blobs and nothing else under `.build/`; a missing blob with no network gives `(None, why)` naming a seed file; a corrupt cached blob is never carried; two snapshots 1.1 s apart are identical; a tree with no manifest carries no blobs.
- **Gate in the worktree:** the pins; `tools/remote_worker_selftest.py` in full (loopback); `run.py --only seed`; `battery.sh citations`. All green.
- **Size:** this tree's snapshot goes from 16.9 MB to 22.7 MB (the 43 seed blobs, 5.7 MB).
