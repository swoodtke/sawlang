## Description

`tests/corpus/spinlock_basic.saw` (K10) is the last flagged file in tests/corpus. It is carried over from SL-438, item 4.

**Why it is still flagged.** Under SL:borrowing §8, a nested `try_lock()` or `is_locked()` inside the lock's own window is a compile error (re-entry through the same name). §9.1 moves that pin to an `@test(refuses: …)` case, but refusal cases name a rule id, and semantic diagnostics have no stable ids yet. The runtime half, re-entry through another name, which panics, has no spelling on a `static SpinLock`. Splitting the file also needs a new corpus file, which the migrate tool can't create.

**When to do it:** once the checker's semantic diagnostics get rule ids, around the resolution and typecheck units of SL-398.
1. Split K10 into the compile-time refusal case, with its rule id, and a runtime test of re-entry through a second name.
2. Clear the flag.
3. Re-text K10's conformance row.

Also, for the same later sweep: the notes on K142, K143 and K144 in `tests/corpus/conformance/INDEX.md` still describe the frozen compiler's internals (the Air, SL-438.p1 review).
