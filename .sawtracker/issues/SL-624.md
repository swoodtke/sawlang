**Stage 1 and Stage 2 word a file-open failure differently.** Found by gateperf while pinning SL-618's batched lex, Oct 14.

- **What differs:** `sawc2 lex MISSING_FILE`
  - Stage 1 (built by Stage 0 against `sawc/std`) prints `sawc2: cannot open …: io error: open failed (not found)`;
  - Stage 2 (built by sawc2 against the new `std/`) prints `… open failed (not found)`, without `io error:`.
- **Mechanism:** the two stds render the file-open error differently. Stage 0's std `Printable` for the error kind is not the new std's. The same probably holds for every std error type the driver prints through `{e}`.
- **Why it matters:** the fixpoint compares Stage 1 against Stage 2 output. Nothing it replays reaches a failure path today, so the difference is latent, but any lane that ever lists a missing or unreadable file would fail on it. SL-618's pin lists only existing files for that reason.
- **Fix:** decide the wording, by the spec or the saw-docs style, and make the new std's `Printable` for its io errors print it. Then sweep the other std error types the driver interpolates, and add a fixpoint case that reaches one error path.
