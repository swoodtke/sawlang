# Saw Package Manager Design (Blade)

`blade` is the official package manager and build tool for the Saw programming language. It is written in Saw, serving as a flagship example of the language's capabilities.

## 1. Core Philosophy

*   **Zero-Config by Default:** A simple `new` command should produce a compiling project.
*   **Reproducible:** `Saw.lock` guarantees that builds are identical across machines.
*   **Fast:** utilizing Saw's lack of GC and efficient machine code generation.
*   **Unified:** Handles dependency management, building, testing, and publishing.

## 2. Project Structure

A standard Saw package follows this layout:

```text
my-project/
├── Saw.toml           # Manifest file (metadata, dependencies)
├── Saw.lock           # Exact version resolution (autogenerated)
├── src/
│   ├── main.saw       # Entry point for binary packages
│   └── lib.saw        # Entry point for library packages
├── tests/             # Integration tests
│   └── some_test.saw
└── target/            # Build artifacts (gitignored)
    ├── debug/
    └── release/
```

## 3. The Manifest: `Saw.toml`

Based on TOML (Tom's Obvious, Minimal Language), similar to Rust's `Cargo.toml`.

```toml
[package]
name = "my-project"
version = "0.1.0"
authors = ["Jane Doe <jane@example.com>"]
edition = "2025"
description = "A sample Saw project"
license = "MIT"

[dependencies]
# Semver compatible (equivalent to ^1.0.0)
serde = "1.0"

# Exact version
files = { version = "=1.2.3" }

# Git dependency
utils = { git = "https://github.com/example/utils.git", branch = "main" }

# Local path dependency
local-lib = { path = "../local-lib" }

[dev-dependencies]
test-utils = "0.2"
```

## 4. CLI Commands

The `blade` binary provides the following interface:

### Project Creation
*   `blade new <name>`: Create a new binary project in directory `<name>`.
    *   `--lib`: Create a library project instead.

### Build & Run
*   `blade build`: Compile the project and dependencies.
    *   `--release`: Build with optimizations.
*   `blade run`: Build and execute the binary.
    *   `-- <args>`: Pass arguments to the binary.
*   `blade check`: Analyze code for errors without generating binary (faster).
*   `blade clean`: Remove the `target/` directory.

### Dependency Management
*   `blade add <dep>`: Add a dependency to `Saw.toml`.
*   `blade remove <dep>`: Remove a dependency.
*   `blade update`: Update dependencies in `Saw.lock` to latest compatible versions.
*   `blade tree`: Display dependency graph.

### Testing
*   `blade test`: Run unit tests (in `src/`) and integration tests (in `tests/`).

### Publishing
*   `blade login`: Authenticate with the registry.
*   `blade publish`: Upload the package to the registry.

## 5. Architecture (Internal Modules)

Since `blade` is written in Saw, it will be structured as follows:

### `blade::cli`
Handles command-line argument parsing (using a sub-command structure).

### `blade::manifest`
Responsible for parsing `Saw.toml`. Requires a TOML parser implementation.

### `blade::resolver`
The heart of the package manager.
1.  Reads `Saw.toml`.
2.  Fetches dependency metadata (from Registry or Git).
3.  Performs Version Sat solver (SemVer) to find compatible versions.
4.  Writes/Reads `Saw.lock`.

### `blade::fetcher`
Handles downloading source code.
*   **Git:** wrappers around system `git` or libgit2 bindings.
*   **Registry:** HTTP client to download tarballs (`.tar.gz`).

### `blade::builder`
Orchestrates the build process.
1.  Topological sort of the dependency graph.
2.  Invokes `sawc` for each crate, passing library paths (`-L`).
3.  Handles incremental compilation (checking file hashes/mtime).
4.  Links final binary.

## 6. Registry Protocol (v1)

Initially, the registry can be a static HTTP index or a Git repository.
*   `GET /api/v1/crates/{name}`: JSON metadata and available versions.
*   `GET /api/v1/crates/{name}/{version}/download`: Returns the `.tar.gz`.

## 7. Implementation Strategy (Bootstrapping)

1.  **Stage 0 (Python/Shell wrapper):** A simple script to compile `blade` using `sawc`.
2.  **Stage 1 (Minimal `blade`):** Can only build itself and local path dependencies.
3.  **Stage 2 (Full `blade`):** Can fetch from network, handle locks, and build arbitrary projects.
