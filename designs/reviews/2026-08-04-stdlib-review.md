# Standard library review — 2026-08-04

Review of the public std surface at `main` = `f764b75`: `sawc/std/*.saw` (22
modules, design 82 = one module per file) plus the built-in traits in
`sawc/builtin.saw`. `sawc/rt/` was read only where it shapes the std surface.

Two parts:

- **Part 1** audits the surface against the project's API bar — *expected not
  easy*, *never hide errors*, cross-module consistency, and prelude discipline.
- **Part 2** compares std's *content* against Rust core/std, Swift
  stdlib/Foundation-lite and Zig std, weighted for Saw's stated targets:
  **kernels + embedded first, freestanding as a first-class profile.**

Every "PROVEN" claim below was settled by a probe, not by reading. Probes live
in `.build/scratch/srev_*.saw` (gitignored); each finding names the one that
settles it. The full test suite was not run (out of scope for this review).

Severity ladder:

| Severity | Meaning |
|---|---|
| **critical** | memory unsafety or command execution reachable from ordinary safe code, with no `unsafe` marker and no diagnostic |
| **high** | silent wrong answers, swallowed failures, or a stated house rule (design 92 / never-hide-errors) violated on the public surface |
| **medium** | surprising-but-honest behaviour, cross-module inconsistency, leaked internals |
| **low** | naming, style, cosmetics |

## Part 1 — Findings

### Summary

| Severity | Count |
|---|---|
| critical | 5 |
| high | 11 |
| medium | 18 |
| low | 8 |
| **total** | **42** |

The three worst, in one line each:

1. **`Vector.push` writes past the end of the buffer when `grow()` fails to
   allocate** — silent heap corruption in the most-used API in the language,
   and the same code shape is repeated in `StringBuilder`, `Data` and `Command`.
2. **`Vector.iter()` over an owning element type double-frees** — `for r in
   v.iter()` hands out a bitwise duplicate of a `NoCopy` element; safe code,
   no `unsafe`, no diagnostic.
3. **`std.process.Command` is a shell-injection API wearing an argv costume** —
   `arg()` concatenates into a `system()` string with no quoting, so
   `c.arg("; rm -rf ~")` runs.

### critical

| # | Site | Issue | Severity | Suggested shape of the fix |
|---|---|---|---|---|
| C1 | `sawc/std/vector.saw:153-170` (with `grow`, `:249-271`) | **Heap buffer overflow on allocation failure.** `push` calls `grow()`, which on allocator failure leaves `capacity` unchanged and returns silently. `push` then re-enters `if let buf = self.buffer` — which still succeeds — and stores at `buf[self.length]` where `length == capacity`, past the end, then bumps `length`. Every later `get`/`iter`/`deinit` reads and frees out of bounds. **PROVEN** (`srev_e.saw`, a 2-element `Vector<Int, FailAlloc>` whose grow is denied: `[alloc DENIED size=32]`, then `len after failed-grow push = 3`, `get(2) = 30` read back from past the buffer). On the *first*-allocation path the failure is different but also wrong: `buffer` stays `None`, the `if let` fails, and the element — already consumed by the transfer checkpoint — is dropped on the floor (leaked for an owning `T`). | critical | `grow` must report success (`-> Bool` or `Result<Void, AllocError>`), and `push` must act on it. Given the design-19 three-tier model the honest v1 is: `push` is the infallible tier → **panic** on OOM (matching `Box.make`), plus a fallible `try_push(value) -> Result<Void, AllocError>` for the tier-2 callers. Silently succeeding is not one of the three tiers. |
| C2 | `sawc/std/vector.saw:274-276` + `:505-527` | **`Vector.iter()` double-frees owning elements.** `iter()` is declared on the *unbounded* extension (no `T: Copy`), and `VectorIterator.next()` returns `buf[idx]` — a raw pointer read, i.e. a bitwise duplicate of the slot. For a `NoCopy`/owning `T` the loop variable and the vector both own the same payload and both run its deinit. **PROVEN** (`srev_c.saw`: a `Vector<Res>` with one element prints `deinit a` twice — once at the end of the loop body, once when the vector drops). This is a use-after-free/refcount-underflow generator for `Vector<String>`, `Vector<Vector<..>>`, `Vector<File>`. | critical | Bound `iter()`/`VectorIterator` to `T: Copy` (matching `each`/`map`/`enumerated`, which already carry it) and have `next()` return an explicit `.copy()`. Reaching `NoCopy` elements stays `with_ref`/`with_var_ref`. A by-reference iteration form is the follow-on design. |
| C3 | `sawc/std/process.saw:126-176`, `:179-210`, `:222-234`, `:238` | **Shell injection by construction.** `Command`/`arg` present a Rust-`Command`-shaped argv builder, but `append_arg` space-concatenates raw argument bytes into one string and `run`/`output` hand it to `system()`/`popen()`. No quoting, no escaping. **PROVEN** (`srev_i.saw`: `c.arg("one two")` is silently split into two shell words, and `c.arg("; echo INJECTED")` executes a second command — output `one two` / `INJECTED` / `exit 0`). Any program that puts user input, a filename with a space, or a path with a quote into `arg` is exploitable or simply wrong. | critical | Two independent fixes. (a) Stop going through the shell: `posix_spawn`/`fork`+`execvp` with a real `char**` argv (this is the "expected" behaviour the name promises and removes the injection class outright). (b) If a shell string must survive as a separate API, name it that (`Command.shell(line:)`) and single-quote-escape every `arg` in the meantime. `append_arg` additionally repeats the C1 overflow: when the `realloc`/`malloc` at `:145-156` fails, `args_cap` stays short and `:170` writes past it. |
| C4 | `sawc/std/string.saw:39-42` | **`String.byte_at` is an unchecked out-of-bounds read in a signature that carries nothing unsafe.** `public func byte_at(&self, index: Int) -> Int8` — comment says "no bounds checking" — is a plain `&self` method on a safe type, so design 81 requires no `unsafe` at the call site and gives the caller no signal. **PROVEN** (`srev_d.saw`: `"hello".byte_at(99)` returns `6104361712`, arbitrary heap memory, and the value is not even inside `Int8`'s range). It is the workhorse of `starts_with`/`contains`/`split`/`replace`/`Path`, so it cannot simply become Optional without a cost, but it must not be *public*. | critical | Make the unchecked form private (`_byte_at`) and publish a checked `byte_at(index) -> Int8?` (or `UInt8?`, see M4) alongside. std's own internal hot loops keep the private one; user code cannot reach past the end from safe code. |
| C5 | `sawc/std/vector.saw:505-527`; `sawc/std/data.saw:283-285`, `:425-457` | **Vector/Data iterators escape the borrow they were created under.** `iter()` takes `&self` but returns a struct holding a raw `UnsafePointer<T>` + a length snapshot, with no retain and no borrow tracking. Mutating the container during iteration reallocates and frees the buffer the live iterator points into. **PROVEN** (`srev_f.saw`: `for s in v.iter() { v.push("grown") }` compiles clean and runs — the push at `len == cap` reallocs and frees the buffer the iterator is walking; `for x in make().iter()` over a temporary also compiles). `data.saw:22-25` already documents the flaw against itself ("iterators can become invalid if source Data is deallocated"). Note the contrast: `StringBytes`/`StringChars` (`string.saw:993-1036`) get this **right** — they hold an owning `String` field, so the retain keeps the bytes alive. | critical | Adopt the `StringBytes` shape: have `VectorIterator`/`DataIterator` hold an owning handle (a `Data` refcount bump is free; `Vector` needs either the `T: Copy` snapshot of C2 or an exclusivity rule that rejects mutation while an iterator derived from the container is live). At minimum, `Data.iter()` should bump the refcount today — the buffer is already refcounted, so it is a two-line fix. |

**Same-shape as C1, not independently probed (code is identical in structure):**
`StringBuilder.append` / `append_char` (`stringbuilder.saw:73-82`, `:100-104`
after a failed `grow` at `:179-201`); `Data.push` / `append` / `append_bytes`
(`data.saw:145-149`, `:180-189`, `:201-205` after a failed `ensure_capacity` at
`:309-334`). All four write at `length` into a buffer whose capacity never grew.

### high

| # | Site | Issue | Severity | Suggested shape of the fix |
|---|---|---|---|---|
| H1 | `sawc/std/vector.saw:144-150` | **`Vector.set` leaks the element it overwrites.** `buf[index] = value` is the *placement-move* primitive — it stores without releasing the prior occupant. `push`'s own comment (`:158-165`) states the rule: "Writing into a slot `< length` this way would leak the live element there". `set` writes exactly there. **PROVEN** (`srev_a.saw`: `v.set(0, Res(name:"new"))` over a live `Res(name:"old")` never prints `deinit old`; only `deinit new` runs at drop). Every `Vector<String>`/`Vector<Vector<..>>`/`Vector<Box<..>>` element overwritten with `set` leaks. Secondary: out-of-bounds `set` is a **silent no-op** that also consumes and drops the argument. | high | `set` should be `swap_out(index, value)` semantics with the old value released — i.e. move the old element out and deinit it in place before the placement write — and out-of-bounds should either panic (bug signal, like `swap_out`) or return `Bool`/`Result`, not vanish. |
| H2 | `sawc/std/string.saw:856-860` | **`String.fromBytes` returns `Ok("")` when allocation fails.** The function's whole point is to be the *validating* constructor with a `Result<String, Utf8Error>` surface, and its failure path hands back a successful empty string with the comment "an empty String is the only value we can hand back here". A caller that checks the `Result` is told the parse succeeded. | high | Widen the error to carry OOM (`Result<String, StringError>` with `Utf8(offset)` / `Alloc(AllocError)` cases), or panic on the infallible tier like `Box.make`. A `Result` that reports success on failure is the exact shape design 92 exists to forbid. |
| H3 | `string.saw:178-180`, `:205`, `:231`, `:308`, `:964`; `path.saw:190-193` | **Allocation failure degrades to a plausible-looking wrong answer, six times.** `_substring` → `""`; `to_uppercase`/`to_lowercase` → `self` (the *un*-cased string); `replace` → `self` (the *un*-replaced string); `Vector<String>.join` → `""`; `Path.join` → `self` (the *un*-joined path). Each is a sentinel that collides with a completely legal result, so no caller can detect it. | high | One policy, applied uniformly: these are infallible-tier APIs, so **panic** on allocator failure (`Box.make` precedent, `__saw_rt_panic` lets a kernel choose). Where a fallible twin is genuinely wanted, add `try_*` returning `Result<_, AllocError>` — the `Vector.try_with_capacity` precedent already exists in-tree. |
| H4 | `sawc/std/data.saw:292-302` | **`Data.to_string()` mints invalid-UTF-8 `String`s.** It byte-copies into a `StringBuilder` with no validation, next door to a `String.fromBytes` that validates. `string.saw:876-880` states the invariant this breaks: "String contents are always valid UTF-8 … so a decode error is unreachable". **PROVEN** (`srev_c.saw`: `Data` of `[0x68, 0xC8, 0x69]` → `to_string()` gives a `len()==3` String whose `chars()` yields **1** scalar and then stops). So the language's own iterator silently truncates data because a std method broke the type invariant. | high | Either make `to_string()` return `Result<String, Utf8Error>` (delegating to `fromBytes`), or keep an unvalidated path under an honest name (`to_string_lossy()` with U+FFFD replacement, Rust's `from_utf8_lossy` shape). It must not be the short, obvious name. |
| H5 | `sawc/std/directory.saw:59-60` | **`Directory.list` hardcodes the macOS `dirent` layout.** `let name_ptr = unsafe entry + 21` — 21 is macOS (`d_ino`8 + `d_seekoff`8 + `d_reclen`2 + `d_namlen`2 + `d_type`1). On glibc it is **19** (`d_ino`8 + `d_off`8 + `d_reclen`2 + `d_type`1), so every listed filename on Linux is offset by two bytes. The repo ships `sawc/rt/host_linux/`, so Linux is a supported host. It also violates the house rule the skill states: "For a KNOWN C struct, declare a typed Saw struct … never a raw byte blob". | high | Declare the two `dirent` layouts as Saw structs (declaration-order natural ABI, design 58) and select per host, or push a `__saw_rt_fs_readdir_name(dirp) -> UnsafePointer<Int8>?` seam into `sawc/rt/host_*` where the divergence already lives (the `SysError`/`clock` precedent). |
| H6 | `sawc/std/data.saw:383`, `:415` | **`sizeof(DataBuffer)` is hardcoded as `24` with alignment `16`.** `let buffer_struct_size = 24 // sizeof(UnsafePointer) + sizeof(Int) + sizeof(Int)` and the matching `dealloc(inner_raw, 24, 16)`. On a 32-bit target — **riscv32, the live SOS target** — `DataBuffer` is 12 bytes, so the allocation is oversized and the dealloc size is a lie to the allocator. `sizeof<T>()`/`alignof<T>()` are builtins; there is no reason for the literal. | high | `sizeof<DataBuffer>()` / `alignof<DataBuffer>()`. Same sweep applies to `mutex.saw` (`64` in five places), `channel.saw` (`160/128/136/144/152`), `arc.saw` (`16`, `8`), `task.saw` (`16`) — see M13. |
| H7 | `sawc/std/mutex.saw:52-62` | **`Mutex.lock` returns `false` for "the mutex was never allocated", colliding with the body's own `false`.** The result is documented as "the closure's result", but the `else` branch on the inert/OOM path returns `false` **without running the body at all**. A caller cannot distinguish "my critical section ran and answered no" from "my critical section never ran". | high | Fold into M1 (make `lock` generic over the body result). The inert-mutex case then has to be surfaced honestly — `lock` should panic on a mutex whose construction OOM'd, since a `Mutex` that silently never locks is worse than a crash. |
| H8 | `sawc/std/channel.saw:69-94`, `:141-151`, `:155-180` | **`Channel.send` silently drops the value on OOM; `recv`/`receive` on an inert channel panic or hang.** `send` returns `Void` and wraps the whole enqueue in `if let node = GlobalAllocator().alloc(...)` with no `else` — allocation failure means the value is consumed, deinit'd, and never delivered, with no signal to either side. On the receive side, `recv` on a `block: None` channel does `empty!` (force-unwrap of `None` → panic), and `receive` loops `try_receive` + `yield_now` forever. | high | `send` should be `Result<Void, AllocError>` (or panic on the infallible tier); the inert channel state should not exist — `Channel()` should panic on OOM rather than construct a channel that eats messages. |
| H9 | `sawc/std/file.saw:44-79`, `:87-129`, `:136-163`, `:169-187`; `sawc/std/directory.saw:50-91`, `:130-144` | **Design 92 was applied to half of `std.file`/`std.directory`.** In the *same files*, `File.remove`/`rename` and `Directory.create`/`remove`/`set_current` return `Result<Void, IoError>` with the errno cause — while `File.open`/`create`/`open_append`/`read`/`write`/`seek_*`/`position` and `Directory.list`/`current` return bare Optionals. "File not found", "permission denied", "too many open files" and "is a directory" are all `None`. `IoError.of(syscall:tag:)` is already public and already used two functions away. | high | Convert the Optional-returning fallible ops to `Result<T, IoError>`. The design-92 note in the skill already lists the converted set; this is the unconverted remainder of the same sweep. |
| H10 | `sawc/std/file.saw:87-129`, `:136-163` | **`File.read`/`File.write` silently do less than their names promise.** `read` issues a *single* `read(2)` and returns whatever arrived — a short read from a pipe/socket/signal-interrupted call is indistinguishable from a complete one, and there is no EOF/error distinction (`None` = error, empty `Data` = EOF *or* empty file *or* short read). `write` returns a byte count and does not loop, so a partial write silently succeeds. This directly contradicts the convention design 92 established next door in `std.net`, where `write(bytes:)` writes the **whole** buffer and returns `Result<Void, IoError>` and `read` distinguishes `Ok(empty)`=EOF from `Err`. | high | Mirror net exactly: `read() -> Result<Data, IoError>` with `Ok(empty)` = EOF, a `read_into(&var Data) -> Result<Int, IoError>` twin, and `write(Data) -> Result<Void, IoError>` that loops until the buffer is drained. Add `read_to_end`/`read_to_string` on top. |
| H11 | `sawc/std/numeric.saw:13-21`; `sawc/sawc.py:50` | **`std.numeric` leaks libm into the freestanding profile.** `HOSTED_STD_MODULES = {"file","process","env","directory","time","net"}` does not include `numeric`, so `numeric.saw` — and its `extern "C" { fabs floor ceil round sqrt fmin fmax }` — is compiled into `--freestanding` builds and its `Float` methods are prelude-visible in a kernel. The comment at `sawc.py:47-49` claims the non-hosted set "depend only on the runtime seams"; `numeric` does not. A kernel calling `x.sqrt()` gets a link failure against a libm that is not there, with no compiler diagnostic. | high | Split the file: `Int`'s methods (pure, freestanding-safe) stay prelude; the libm-backed `Float` methods move to a hosted-only `std.math` (or the `Float` extension becomes seam-backed via `__saw_rt_*`). Given "kernels + embedded first", the seam route is the better long-run answer — see gap G16. |

## Part 2 — Gap analysis vs Rust core/std, Swift stdlib, Zig std

### How this list is weighted

Saw's stated targets are **kernels + embedded first**, with freestanding as a
first-class profile, and the near-term dogfooding load is the compiler-in-Saw
rewrite. So the ranking is *not* "what a general-purpose stdlib is missing". It
applies these multipliers:

| Category | Weight | Rationale |
|---|---|---|
| Bit twiddling, checked arithmetic, alignment/layout, volatile/atomics | **×3** | this *is* kernel code; a driver or page-table walker cannot be written without it |
| Slices/views, fixed-capacity collections, `mem` utilities | **×3** | the freestanding profile forbids allocating on every substring/subslice |
| Formatting (radix/padding), error plumbing, iterator adaptors | **×2** | equally kernel logging and daily compiler-rewrite ergonomics |
| Collection/string API completeness, sorting | **×1.5** | dogfooding weight, some kernel weight |
| Buffered IO, hashing policy, RNG, encodings | **×0.5** | hosted convenience |
| HTTP/TLS/JSON/date-time formatting | **×0** | explicitly out of scope |

Sizes are rough implementation effort: **S** ≈ one focused unit, **M** ≈ a
design brief with several units, **L** ≈ a language-level design plus library.

## Cross-cutting observation

Three of the five critical findings and most of the high ones share one root:
**std has no single answer to "the allocator said no".** `Box.make` panics,
`Vector.try_with_capacity` returns `Err`, `Vector.init(capacity:)` degrades to
empty, `Vector.push` corrupts the heap, `String.fromBytes` returns `Ok("")`,
`Path.join` returns the un-joined path, `Channel.send` drops the message,
`Mutex.lock` returns `false`, and `Arc`/`Channel`/`Mutex` each construct an
"inert" object that fails silently forever afterwards.

Design 19's three-tier model already names the right answers (panic / `Err` /
propagate). What is missing is the sweep that applies it. That sweep is
probably the highest-value single brief coming out of this review, and it
subsumes C1, H2, H3, H7, H8 and the inert-object pattern in one pass.
