# corodiff's XFAIL ledger (design 218 unit 0).
#
# A signature listed here is a twin-parity finding that has been FILED as a DF
# and is not yet fixed. corodiff still reports every hit — with its DF number
# and the first combo that reached it — but does not fail the run for it, so
# the battery's corodiff lane stays a signal rather than a wall.
#
# READ IT AS A MATRIX, not as a list of excuses. A runtime signature is
# `<kind>: <binding>/<placement> @ <context class>`, which names one testable
# cell of the axis grammar, and a mechanism's full set of cells is exactly the
# position matrix obligations 1 and 4 ask a fix brief to carry. The DF-217h and
# DF-217p blocks below ARE those matrices, generated from a full `--all`
# run rather than guessed.
#
# The rules are the suite's XFAIL rules:
#   - an entry MUST cite a DF, and a numbered DF MUST have a pin in examples/
#   - an entry that no longer fires is STALE — delete it in the landing that
#     fixes the bug, exactly as you delete the XFAIL marker
#   - `--ignore-known` re-reports everything here, which is how you check
#
# (The landing run's `DF-pending-*` entries were numbered DF-217n/o/p by the
# lead at integration; their examples/ pins ride the pin-promotion batch.)
#
# Format: DF <TAB> signature   (the signature corodiff prints for it)

# DF-217o (reported 2026-08-13) — NEW. A SPAWNED task body that contains
# no suspension point cannot destructure a tuple:
#
#     func worker() -> Int { let (a, b) = (mk(1), mk(2))  ...  0 }
#     g.spawn(worker())        // error: struct `__Frame_worker` has no field `a`
#
# A spawn root is always frame-transformed, but with no suspension the pass
# that gives a destructuring `let`'s bindings their frame fields does not run,
# while the read rewrite still does. Adding one `yield_now()` to the same body
# makes it compile and run — which is why the DRIVEN twin is the one that works
# and the oracle reports this as BOGUS-ACCEPT.
# Standalone repro: .build/scratch/probe_spawntuple.saw
DF-217o-2026-08-13	BOGUS-ACCEPT: error: struct `X` has no field `X`

# DF-217p (reported 2026-08-13) — NEW, and the widest thing in this file:
# 61 cells of ONE mechanism. A frame-resident local in a driven body is
# released at FRAME TEARDOWN rather than at the end of the scope that owns it.
# Deterministic destruction is a language guarantee, so a resource held past
# its scope is a real behavioral difference and not a cosmetic one — the counts
# always balance, which is why this is DEINIT-ORDER and never LEAK.
#
# Two faces, both from the same cause:
#   - @ loop — a loop-body local survives into the NEXT iteration (and the last
#     iteration's survives the whole loop). Reaches essentially every binding
#     construct, which is what makes it a mechanism rather than a construct bug.
#   - @ linear — a scope that ends INSIDE the body: the replaced binding of a
#     same-scope redefinition (design 107 drops it AT the redefinition point),
#     an `if let`/`guard let` body's end, a `match` arm's end.
#

#     while i < 2 { yield_now()  let a = Res(name: "a{i}")  print(...) }
