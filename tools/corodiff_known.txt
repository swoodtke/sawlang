# corodiff's XFAIL ledger (design 218 unit 0).
#
# A signature listed here is a twin-parity finding that has been FILED as a DF
# and is not yet fixed. corodiff still reports every hit — with its DF number
# and the first combo that reached it — but does not fail the run for it, so
# the battery's corodiff lane stays a signal rather than a wall.
#
# READ IT AS A MATRIX, not as a list of excuses. A runtime signature is
# `<kind>: <binding>/<placement> @ <context class>`, which names one testable
# cell of the axis grammar, and a mechanism's full set of cells is exactly the
# position matrix obligations 1 and 4 ask a fix brief to carry. The DF-217h and
# DF-217p blocks below ARE those matrices, generated from a full `--all`
# run rather than guessed.
#
# The rules are the suite's XFAIL rules:
#   - an entry MUST cite a DF, and a numbered DF MUST have a pin in examples/
#   - an entry that no longer fires is STALE — delete it in the landing that
#     fixes the bug, exactly as you delete the XFAIL marker
#   - `--ignore-known` re-reports everything here, which is how you check
#
# (The landing run's `DF-pending-*` entries were numbered DF-217n/o/p by the
# lead at integration; their examples/ pins ride the pin-promotion batch.)
#
# Format: DF <TAB> signature   (the signature corodiff prints for it)

# DF-217f's row is GONE, removed by design 237 unit 2 (the ledger sweep that
# unit's fix owed). The finding — a suspending call as an enum-constructor
# argument that is itself a `match` scrutinee — was CLOSED by design 224's
# container-HEAD hoist on Aug 15: a scrutinee is a head, `_hoist_container_heads`
# lifts it, and the ctor's own arguments then linearize through the funnel. The
# entry outlived its fix by six days; design 237's census re-probed every cell
# (`match Sig.One(v: s(7))`, the struct-init sibling, both `&&`/`||` LHS, the
# `if`/`while` conditions and the `for`-range bounds) and found them all working.
#
# DF-217g's row is GONE too, removed by the fix (design 237 unit 2): a
# destructuring `let` was the one LEAF statement class missing from the ANF
# hoist's entry set, and it is now a row of `_ANF_STMT_ENTRIES` with
# `examples/coro_destructuring_let_suspending_rhs.saw` as its matrix.

# DF-217h's seventeen rows are GONE, removed by design 218 stage 2 (Aug 14) in
# the landing that fixed them, exactly as an XPASS marker is. The ANF hoist's
# temp is a `Slot` now and its one read is `take()`, so a value consumed by the
# parent cannot also be dropped at teardown — the three argument positions the
# matrix carried (`v.set(i, f())`, `v.swap_out(i, f())`, `none() ?? f()`) and
# every oracle class they reached (linear, loop, cancel, teardown, MT) are
# clean on a full `--all` run.

# DF-216g RETIRED (fixed Aug 14 by design 218 stage 3 — `[&self]` capture +
# the second minted handle; the ledger row outlived the fix until the 218b
# spec's probe found it stale, 0 hits on both filters. Same miss shape as
# DF-217n's.)

# DF-217n RETIRED (fixed Aug 18 — `case Has(_)` drops its payload; the ten
# LEAK/STDOUT-PARITY match_nobinding rows that lived here are gone with the
# fix). What REMAINED at the in_rhs cells is the DRIVEN twin's half of the old
# composite: it always released late (frame teardown — DF-217p's mechanism,
# as the old STDOUT-PARITY comment already recorded), and with the control
# twin correct the divergence MORPHED from LEAK into DEINIT-ORDER. Those rows
# were filed under the mechanism that owns them and went with its fix; the
# after/before/between cells never forced the scrutinee frame-resident, so
# they reached parity and needed no rows.

# DF-217p's sixty-eight rows are GONE, removed by design 218 unit 2 (Aug 21) in
# the landing that fixed them, exactly as an XPASS marker is. A frame-resident
# local in a driven body is released at the end of the scope that owns it now,
# not at frame teardown: the transform keeps the scope map `_uniq_walk_block`
# already built, and ONE funnel (`_scope_release_seq`) emits a release at every
# edge by which control leaves a scope — fallthrough, `break`, `continue`, the
# done path, and a design-107 redefinition. Both faces of the matrix are clean
# on a full `--all` run: the `@ loop` cells (the iteration's locals dying before
# the backedge) and the `@ linear` cells (a scope that ends inside the body — an
# `if let` body, a `match` arm, a same-scope rebind).
#
# The `match_consume/in_rhs` cells went with the statement-end edge, stage D
# (218b section 2c): the scrutinee temp a suspending `match` HEAD is hoisted
# into is a statement's temporary, not a scope's binding, so it releases at the
# construct's merge point — an idempotent tag-drop, paired with the DF-210f
# forget that survives on the consuming arms.
#
# DF-218w's two rows are GONE, removed by the landing that fixed them (Aug 21,
# branch `df-218s-218w`). They were the `_`-arm cells, whose residual divergence
# was intra-statement TIMING: sync drops a discarded payload INLINE at
# extraction (it is registered in no cleanup scope, so no scope exit could reach
# it), and the driven twin — with no consume mode to be in, its scrutinee being
# the frame temp the container-head hoist made — dropped the whole temp at the
# statement's end.
#
# E-ARM is the edge that closed them: an arm that claims NOTHING of the
# scrutinee by name releases the hoisted temp at the arm's START, because the
# payload is then owned by the temp and aliased by nobody. The merge-point
# release survives behind it as the idempotent tag-drop — a no-op once the arm
# has released, and still the edge for an arm that DOES bind. Both lowerings
# take it: `_split_match`'s arm entry state and `_lower_inplace`'s MatchExpr,
# which is where corodiff's `in_rhs` placement lands (the head is the only
# suspending part, so the construct spans nothing once it is hoisted).
#
# FAM_SCRUTINEE_TEMP is narrowed again, not retired, and the DF-210f forget is
# untouched. What DF-218w still names is the MIXED `case Both(v, _)` shape,
# which corodiff does not generate (`st_match_nobinding` builds the single-field
# `case Has(_)`) and which is pinned in examples/ instead:
# examples/coro_mixed_match_payload_released_at_extraction.saw, plus
# examples/coro_discarded_match_payload_field_drop_order.saw for DF-218y.

# DF-218e's row is GONE, removed by design 218 unit 2 stage E (Aug 21) in the
# landing that fixed it. CONSUMPTION SYMMETRY: a suspending callee is consumed
# at the splice, and so now is a generic TEMPLATE whose body names one — on the
# free-function side and, through design 223's one strip funnel, on the method
# side. The re-check has no body left in which the name is dangling, and the
# instantiations were checked concrete, which is where the checking belongs.
# One guard: a template nothing surviving still CALLS, so the shape where
# `_promote_nested_generic_calls` declines keeps its old diagnostic instead of
# trading it for a codegen one.
